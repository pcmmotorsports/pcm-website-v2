## 🔴 訂正一(2026-08-24 稍後,回頭比我方時發現;第一個 bug)

**解析腳本原本沒有先剝掉 CSS 註解就在數 `{` `}` 巢狀層級。** 這份稿裡的中文說明註解常常**直接引用
CSS 片段當例子**(例如註解裡寫 `.rail-collapsed #nav-rail{width:56px}` 這種文字),
註解裡就藏了 **20 個**不成對的大括號(`grep` 數過:225 段註解裡合計 20 個 `{`/`}`),
足以讓沒剝註解的巢狀計數器在局部走歪,漏抓到夾在corrupted區段裡的宣告。

```
影響範圍:9 筆宣告在原始掃描中被漏掉(407 → 416)
實際改變贏家的:只有 2 個變數
  --border      原判贏家 :5046(FIX-27)#ccd5e2  →  訂正後 :5316(FIX-38)#e3e9f0
  --border-soft 原判贏家 :4858(FIX-10)#e8ecf2  →  訂正後 :5317(FIX-38)#f1f5f9
```
修法:重新解析前先把 `/\*.*?\*/`(含跨行)整段替換成等長空白再交給巢狀計數器,行號因此不漂。

## 🔴🔴 訂正二(2026-08-24 更後,1b 複驗時再抓到;第二個 bug——與訂正一不同族)

**解析腳本沒有處理「規則區塊裡最後一個宣告沒有結尾分號就直接接 `}`」這種合法 CSS 寫法。**
例:`:root{--pcm-pill-w:62px;--pcm-three-w:198px}` —— 第二個宣告 `--pcm-three-w:198px` 後面
直接是 `}`,原本的解析器只在遇到 `;` 時才收一筆宣告,遇到 `}` 就直接跳過,**這個沒有分號的
最後一筆會被靜默丟掉**(不報錯,表面上看起來一切正常)。

```
全檔用同一個樣式(--變數:值}, 缺分號直接接右括號)掃了一次, 共 11 處命中:
  :4829  --font-sans   = system-ui,-apple-system,"Segoe UI","Noto Sans TC","PingFang TC","Microsoft JhengHei",sans-serif
  :4836  --od-fs-sm    = 13px
  :4837  --od-fs-sm    = 13px
  :4838  --od-fs-sm    = 12px
  :5042  --od-fs-sm    = 13px
  :5045  --fg-2        = #333e4e     ← 影響下方第⑤節主表
  :5054  --od-fs-sm    = 14px
  :5055  --od-fs-sm    = 14px
  :5066  --pcm-three-w = 198px       ← 影響下方第⑤節主表(新增列)
  :5334  --od-row-h    = 48px
  :5404  --od-fs-sm    = 13px
```
```
實際改變贏家的:2 個變數(都在下方第⑤節主表裡)
  --fg-2         原判贏家 :4853(FIX-10)#3c4757  →  訂正後 :5045(FIX-27)#333e4e
                 🔴 訂正後的值與我方 globals.css:128 現值 #333e4e 相同 ⇒ 這格其實【沒有差異】,
                    不是需要照稿改的堆甲。1b 原本要我改成 #3c4757 反而是錯的方向,已擋下未執行。
  --pcm-three-w  原本整筆漏掉  →  新增 :5066(FIX-28)198px(我方 globals.css:1626 現值 128px)
其餘 9 處(--font-sans / --od-fs-sm ×6 / --od-row-h)只影響下方「密度條件式」與 font-mono/
  font-sans 那個「工具限制」附注, 不在核心 28 列表裡, 已一併更新於對應段落。
```
修法:解析器在遇到 `}` 收合區塊時,除了原本的 pop 堆疊,**也要把 `}` 之前尚未被 `;` 收掉的
殘留文字當成最後一筆宣告嘗試解析一次**,兩處收合入口(`;` 與 `}`)共用同一個 flush 函式。

⚠️ **這是這份表出現的第二個獨立解析器 bug,不是同一個坑犯兩次** ——訂正一是「沒剝註解」,
訂正二是「沒處理缺分號的最後宣告」,兩者互不相關,分開記錄。

```

## 用法

對稿時,先查這張表有沒有你要比對的變數;有 ⇒ 直接用「最後贏家」那欄的值,不要自己重 grep
第一個出現的值。表裡沒有的變數 ⇒ 代表它在稿裡只宣告一次,你 grep 到的值就是生效值。

```

⚠️ **這支工具在我方 `apps/admin/src/app/globals.css` 上有盲區,不能直接拿去比我方那一側**:
我方檔案開頭是 `@import 'tailwindcss'; @import 'tw-animate-css';
@custom-variant dark (&:is(.dark *)); :root {…}` ——三個沒有 `{}` 的陳述句黏在
第一個真正選擇器 `:root` 前面。這支工具的 `walk()` 把「第一個 `{` 之前的全部文字」當一整塊
prelude 來判斷是不是 `@media`/`@supports`,判不是就整段丟棄——**連黏在最後面的 `:root`
也一起被丟掉**,導致我方最大的那個 `:root` 主區塊完全消失(只剩後面一個獨立小 `:root` 區塊)。
OD 稿的 `<style>` 沒有這種「多個陳述句 + 選擇器黏一起」的開頭,所以稿那一側沒事、只有我方這一側
會踩到。回比我方的 27 列交件(`~/pcm-mailbox/06-交件-27列回比我方-20260824.md`)改用另一支
已剝註解修正過的解析器,單尺 + `grep` 抽驗,沒有假裝雙尺驗過我方那一側。

# OD 稿(`orders-admin-v2.html`)裡「哪一條真的贏」

> 🔴 **為什麼要有這份檔**:`orders-admin-v2.html` 是一份會**層疊**的程式(39 個 `<style>` 區塊,
> 含多個 `data-od-fix="FIX-N"` 後補修正塊),不是一份宣告文件。同一個 CSS 變數常常被宣告
> 超過一次,**只看第一次出現的值會拿到錯的答案**——2026-08-24 夜這條線自己就踩過一次
> (誤判 `--primary` 有差異,實際是漏看了後面的 `FIX-10` 覆蓋)。
> 這份表把「稿裡宣告超過一次的變數,最後誰贏」算完一次,供之後每次對稿直接查,不用重算。
> 產生方式:唯讀解析(程式追蹤 `{ }` 巢狀與 selector/at-rule 堆疊,不是肉眼掃行號),
> 過程與腳本存於本次任務的 scratchpad,原始交件見 `~/pcm-mailbox/06-交件-稿的實際生效值表-20260824.md`。

## ① 區塊數(當場印,不用信裡的數字)

```
grep -c "<style" 那支稿  ⇒ 40
```
🔴 其中 1 個是假的:`:6378` 那個 `<style>` 字樣其實是 `<script>` 裡的 JS 字串字面
(`function styles(){ return "<style>"+s.textContent+"</style>" }`),不是真的 style 標籤
⇒ **真正的 `<style>` 區塊 = 39 個**。前 3 個起始行:`9-4561`(base)、`4562-4565`、`4566-4595`;
其餘 36 個各自帶 `data-od-fix="FIX-N"` 標籤(FIX-08 起跳到 FIX-80,非連號)。

```

```

## ③ 正對照 / 負對照(方法先驗過,再信結果)

```

  程式跑出來:第一筆 :3560『:root』#0066b1 → 贏家 :4858『:root』(FIX-10)#1a5c96
  ⇒ 與已知答案一致, 方法沒有壞

負對照 挑一個只宣告一次的變數(--tw-translate-z,:16,值 0)
  ⇒ 正確地【沒有】被列進「出現超過一次」那批
```

## ④ 特異性:同特異性才是「後面贏」,不同特異性另列

```
83 個裡, 排除掉「只在 .dark / prefers-color-scheme:dark 條件下重複」的(明暗兩套各自的值,
不互相競爭)之後,剩 78 個在 light 模式下有 ≥2 筆宣告。
其中 25 個是 Tailwind 內部工具變數(--tw-* 開頭)——一條全域 reset 給預設值, 再由各自的
  utility class 在該 class 存在時覆蓋, 兩者是分工不是衝突, 排除。
另外 21 個是 --color-* 開頭的 Tailwind 主題色階——差異是同一個顏色的 hex 版 + lab() 精確版
  (@supports 漸進增強), 不是值真的改了, 排除。
```
⇒ 排除完雜訊,剩 **32 個**是真正跟後台設計代幣有關的變數。

**再拆這 32 個**:
```
3 個(--od-fs / --od-fs-sm / --od-row-h)是【密度模式】的條件式變體, 不是衝突, 另列不進主表。
2 個(--font-mono / --font-sans)是特異性計算工具在【逗號分隔選擇器】(`:root, :host {...}`)
  上的已知限制:`:host` 在一般網頁不會命中, 真正比較基準應與純 `:root` 同級 ⇒ 後面那組具體
  字體堆疊(`ui-sans-serif, system-ui, …`)才是真正生效值, 已手動訂正, 不是程式原始輸出。
```

## 用法

對稿時,先查這張表有沒有你要比對的變數;有 ⇒ 直接用「最後贏家」那欄的值,不要自己重 grep
第一個出現的值。表裡沒有的變數 ⇒ 代表它在稿裡只宣告一次,你 grep 到的值就是生效值。

## 已知限制(未涵蓋的部分)

```
· 只涵蓋 CSS 自訂屬性(--變數), 不含一般屬性(color/background-color 等直接寫值、不走變數的宣告)
· 只做了「哪個 :root 級變數贏」, 沒有做「我們自己 globals.css 的同款表」——那份已有人數過,
  見 260e51fd 附的盤點檔(69 處宣告 / 38 個選擇器)
· payload(:4608 gzip+base64)與 <style> 內容是否一致, 未驗
```

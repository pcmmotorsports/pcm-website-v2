## 0. 現況基準線(**改之前的樣子,附量法**)

```
色票        54 個（grep -cE '^\s*--[a-z0-9-]+: oklch' globals.css）
            其中 chroma=0 純灰 52 個 ⇒ 有彩度的只有 --destructive 亮/暗兩版

圓角        --radius: 0.5rem = 8px，sm/md/lg/xl 四階全由它推導（:106-109）
字級        Tailwind 五階，實際 94% 只用兩階（text-sm 214 + text-xs 200 = 414/441）
            另有 5 處在 CSS 直接寫死字級繞過階梯
互動        active: 九支原件只有 sidebar 有 ／ input 零 hover ／ transition 只有 5/9 支
原件        9 支：breadcrumb button input separator sheet sidebar skeleton spinner tooltip
            ⚠️ admin 不使用 packages/ui（@pcm/ui 零命中；正向對照 from '@pcm…' = 98）
```
🔴 **改 token + 這 9 支 ⇒ 84 個元件與約 11 個畫面大部分會跟著變。**
**不要一頁一頁改** —— 一個一個改做不完,而且會不一致。

| token | 現況 | 應該 | 來源 |

| 主文字 | `oklch(0 0 0)` | `#111827` | **【抄】** `:15` |
| **強調色** | **無**(`--primary` 是純黑) | **`#0066b1`** BMW 藍 | **【抄】** `:21` |
| hover / active | **無推導** | `color-mix(in oklab, var(--accent), black 8%)` / `black 14%` | **【抄】** `:23-24` |
| 危險 | `oklch(0.63 0.19 23.03)` | `#e4002b` | **【抄】** `:27` |
| 次要文字 | `oklch(0.44 0 0)` | ~~`#64748b`~~ → **`#64738a`** | **【改】** `:17` |
| 成功 | **無** | ~~`#16a34a`~~ → **`#12883e`** | **【改】** `:25` |

### 🔴 三處【改】的理由與量法(WCAG AA 正文 4.5:1)
```
次要文字  #64748b on #f7f8fa  4.48 → #64738a 4.53   色相 215° 不變
成功      #16a34a on #ffffff  3.30 → #12883e 4.55   色相 142° 不變
警告      #f59e0b on #ffffff  2.15 → #a56a07 4.50   色相  38° 不變
```
**改法紀律:保色相、只調明度到剛好過標。** 依據 = Sean 逐字「**有不適合我們或者我們需要再依照類似風格建置上去**」。
⚠️ **警告色動最多**(明度 0.502→0.338)—— 橘色在白底上先天難達標,**這是標準的物理限制,不是 OD 選錯色。**

### 🔴🔴 三階邊框 —— **【長】,BMW M 沒有這個分法**

**依據的原則**(稿裡的):**無陰影、以 hairline 分隔**(`--elev-flat: none` `:57`;OD 自己有兩階 `--border` `:19` / `--border-soft`)。

| 角色 | 用在哪 | 對比要求 | 值 |
|---|---|---|---|
| `--border-interactive` | **輸入框、可聚焦元件的邊界** | 🔴 **必須 ≥3.0**(WCAG 1.4.11) | 待定 |
| `--border` | 卡片、區塊邊界 | 視覺用,無硬要求 | `#d7dee8` **【抄】** `:19` |
| `--border-soft` | **表格 hairline、裝飾性分隔** | **無**(裝飾性不受 1.4.11 管) | `#edf1f6` **【抄】** |

**🔴 判別句(下一個人照這個分,不要憑感覺)**:
> **「使用者需不需要靠這條線才知道【這裡可以點/這裡是一個控制項】?」**
> **需要 ⇒ `border-interactive`(必須達 3.0)。不需要 ⇒ 另外兩階。**

⚠️ **為什麼不把所有邊框拉到 3.0**:實算 `#d7dee8` 要達 3.0 得變成 **`#7a91b3`**(對比 3.03)——
**那是中灰藍的明顯線條,不是 hairline。**
🔴 **WCAG 1.4.11 管的是「識別 UI 元件與狀態所需」的視覺資訊,不管裝飾性分隔線。**
**硬拉會同時毀掉設計語言、又誤讀標準** —— 做出來的東西已經不是「達標的 BMW M」,是別的東西。

## 5. 互動與動態 —— **這一整段是純新增**

| | 現況 | 應該 | 來源 |
|---|---|---|---|
| 快 / 慢 | **無** | `130ms` / `220ms` | **【抄】** `:61-62` |
| 緩動 | **無** | `cubic-bezier(0.16, 1, 0.3, 1)` | **【抄】** `:63` |
| focus 環 | 各元件自寫 | 🔴 **不可照抄,見下** | **【改】** `:60` |
| 陰影 | **無** | `none` / `0 0 0 1px var(--border)` / raised | **【抄】** `:57-59` |
| `active:` | 🔴 **只有 sidebar 有** | accent 壓深 14% | **【抄】** `:24` |
| `input` hover | 🔴 **零** | 需補 | **【長】**,依據 = 契約 `requiredStates` 九態含 `hover` |

### 🔴🔴 focus 環:**OD 那個值不合格,不要照抄**(`accessibility-review` 跑出來的)

```
--focus-ring: 0 0 0 4px rgba(0, 102, 177, 0.24)     ← OD :60

24% alpha 疊在底色上的【實際顏色】與對比：
  疊在 #f7f8fa ⇒ #bcd5e8   對比 1.43     需要 3.0   🔴 不過
  疊在 #ffffff ⇒ #c2daec   對比 1.44     需要 3.0   🔴 不過

對照（不透明的 accent 當焦點環）：
  #0066b1 on #f7f8fa ⇒ 5.59  ✅        #0066b1 on #ffffff ⇒ 5.94  ✅
```
🔴 **WCAG 2.4.7(可見焦點)+ 1.4.11(非文字對比 3.0)** ⇒ **24% 的藍在淺底上幾乎看不見。**
⚠️ **這條特別值得記**:我原本把它標成 **【抄】直接照搬** ——
**因為它「看起來就是個 focus 環」,而我沒有把 alpha 疊算回底色。**
**半透明色的對比不能看它宣告的顏色,要看它疊在底上的【實際顏色】。**

**⇒ 改法(保持 BMW M 的視覺意圖:細環、不搶眼)**:**降低透明度或改用不透明的 accent 描邊**,
**值待定,但硬要求是疊算後 ≥3.0。** 依據 = 契約 `requiredStates` 含 `focus` + WCAG 2.4.7。

### ⬜ 觸控目標(順帶量到,**不是這一輪要解的**)
```
ADMIN_INPUT_CLASS 的 h-9 = 36px
  WCAG 2.2 AA  (2.5.8) 需 24×24  ⇒ ✅ 過
  WCAG 2.1 AAA (2.5.5) 需 44×44  ⇒ 🔴 不過（36 < 44）
```
⚠️ **標清楚哪一級**:**AA 過、AAA 不過。** 不要寫成「違反 WCAG」——
**那會讓下一個人以為我們現在不合規,而 AA 才是我們的門檻。**

🔴 **`color-mix` / `elev-ring` 要保留成【運算式】,不要求值成靜態色**:
求值之後,**未來改主色時互動色不會跟著動,而沒有任何守門會紅。**
⚠️ **`color-mix(in oklab,…)` 我們的建置鏈一次都沒用過**(`grep -c 'color-mix' globals.css` ⇒ **0**)
⇒ **先拿一顆 token 實測再整批換。標【未實測】。**

## 6. 驗收契約(來自 `DESIGN-MANIFEST.json`,**這半才是那份 JSON 的價值**)

⚠️ **那份 JSON 沒有 token 值** —— `tokens.source: ["index.html"]`、`tokens.required` 是 **11 個類別名**、
`note` 逐字要求 "Extract/freeze tokens before framework implementation"。**它明文把值委派給 HTML。**

**九種狀態**:`default / hover / focus / active / disabled / loading / empty / error / success`
⚠️ **我們現況大概只穩定做到 `default` 與部分 `hover`**;`empty / error / success / loading` **完全沒量過,不要當成「有」。**

**九個斷點,每一個都 `mustAvoidHorizontalScroll: true`**:
| 斷點 | 視窗 | 我方容器 | 表格 | 溢出 | |
|---|---:|---:|---:|---:|---|
| tablet-landscape | 1024 | 830 | 716 | 0 | ✅ |
| **laptop** | **1366** | 1172 | 1412 | **240px** | 🔴 **違反契約** |
| **desktop** | **1440** | 1246 | 1412 | **166px** | 🔴 **違反契約** |
| wide | 1920 | 1726 | 1412 | 0 | ✅ |
| mobile ×3 / foldable / tablet-portrait | 360–820 | — | — | — | ⚠️ **未量** |

(公式 `容器 = 視窗 − 194`,五筆實測驗證:1024/1280/1440/1600/1920。)
🔴 **`laptop 1366` 與 `desktop 1440` 是員工最可能用的兩台機器,而它們正是過不了的兩格。**
**根因與 `#519` 相同:14 欄固定寬相加 1412,而 `@container` 在 900 就把欄全放出來。**
⚠️ **OD 的 `--container-max: 1220px`** `:64` **比我們的表格還窄** ⇒ **不要照抄那個上限,先解決欄寬。**

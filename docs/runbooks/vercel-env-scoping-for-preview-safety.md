## 🔴🔴 先讀這一段(比第一步怎麼做重要)

### **不要只做一半。**

最直覺的做法是「把預覽版的 `TAPPAY_ENV` 改成 `sandbox`」。**那一步單獨做會製造一個新問題:**

```
只改 TAPPAY_ENV → sandbox,而資料庫那格不動
⇒ 預覽版變成【沙盒的刷卡設定 + 正式的資料庫】
⇒ 而那正是我們後台程式碼【明文判定為不該存在】的組合
   (apps/admin/src/lib/payment/composition.ts:99-100 逐字:sandbox × 正式帳本 ⇒ 擋)
⇒ 你會親手做出一個「我們自己的系統認為不該存在」的狀態
```

**⇒ 所以下面的做法【不是】把它改成 sandbox,是【讓預覽版連刷卡功能都起不來】。**
那樣就不會產生那個組合。

---

## 現在的狀況(一句白話)

你在 Vercel 設的那些值是**全部環境共用一組**。
而 Vercel 預設「每推一個分支就自動產生一個預覽版網站」。
⇒ 那些預覽版拿到的是**正式的刷卡設定 + 正式的資料庫**。

🔴 **這不是最近才壞的,是一直都這樣。**
而它剛好解釋了為什麼「本機刷沙盒卡,訂單會躺進正式站後台」—— 同一個根源。

## 🔴 這件事【做不完整】,而我先講缺的是什麼

有兩個洞,而下面的步驟**只堵得住第一個**:

| 洞 | 下面的步驟堵得住嗎 | 需要什麼才堵得住 |
|---|---|---|
| 預覽版可以**刷真的信用卡** | ✅ **堵得住** | 只要改 Vercel 設定,不需要別的 |
| 預覽版會**寫進正式資料庫**(訂單、購物車、會員) | 🔴 **堵不住** | 要有**第二個 Supabase 專案** |

**為什麼第二個堵不住**:預覽版要能打開網站就得連得到資料庫,而我們(據我所知)只有一個。
把它指向別的地方就得先有別的地方。

🔴 **而「我們只有一個 Supabase 專案」這件事我沒有查證** —— 那要看你的 Supabase 面板。
**如果你其實有第二個,告訴我,那第二個洞也能一起堵。**

**你要另外決定的三條路(我不替你決定,而我會給推薦)**:
```
路 1  維持現狀 + 只堵錢那個洞(= 下面的步驟)
      成本 最低,今天就做得完
      代價 預覽版還是會寫進正式資料庫(而寫進去的是【沒付款的】訂單/購物車,不是錢)
      👍 我推薦先做這條,因為它把【最貴的那個洞】今天就關掉

路 2  新開一個 Supabase 專案給預覽版用
      🔴 我答不出成本 —— 要搬 schema、搬測試資料,而它自己就是一片工程
      而「Supabase 方案開不開得了第二個」我也要你在面板上看一眼

路 3  直接關掉預覽版部署
      成本 最低
      代價 你會失去「推一個分支就有一個網址可以先看」這件事
      ⚠️ 而我不知道你們平常有沒有在用預覽版 —— 有在用就不要選這條
```
⛔ **我刻意不列第四條「約定大家不要推分支」** —— 那是提醒不是機制,而提醒治不好這種事。

## 步驟(路 1;三步,順序不可換)

### 第 1 步 · 讓預覽版拿不到 `TAPPAY_ENV`

```
按哪裡  Vercel → 選 storefront 那個專案 → 上方 Settings → 左邊 Environment Variables
        在清單裡找到 TAPPAY_ENV → 點它右邊的編輯(鉛筆或「⋯」)
填什麼  🔴 值【不要改】。只改「哪些環境要用它」:
        把 Production 留著打勾,把 Preview 與 Development 的勾【取消】
        存檔
怎麼確認生效  這一步先只確認一件事:
        那一列顯示的環境標籤只剩「Production」一個
        🔴 而【真正的生效確認在第 3 步】—— 面板改了不等於網站變了
```

### 第 2 步 · 同樣處理那兩把金鑰

```
按哪裡  同上那個清單
填什麼  找到 TAPPAY_PARTNER_KEY 與 TAPPAY_MERCHANT_ID
        同樣改成【只勾 Production】,值都不要改
為什麼  少了第 1 步的 TAPPAY_ENV,刷卡功能就已經起不來了
        這一步是【不要把鑰匙放在不需要它的地方】—— 少一個地方放,就少一個地方漏
```

⚠️ **`NEXT_PUBLIC_SUPABASE_URL` 這一格【不要動】。**
預覽版還是要連得到資料庫才打得開網站。這條路的安全性來自「刷不了卡」,不是「連不到資料庫」。

### 第 3 步 · 確認它真的生效(**這一步不能省**)

```
🔴 改完設定之後,舊的預覽版還帶著舊設定 —— 要重新部署才會換
按哪裡  Vercel → 同一個專案 → 上方 Deployments
        找一個 Preview 的部署(那一列會標 Preview,不是 Production)
        點右邊「⋯」→ Redeploy → 確認
        等它跑完(通常幾分鐘)
怎麼看  跑完之後點開那個預覽版網址,走到結帳、按下付款
預期    🔴 它應該【做不下去】或【出現錯誤】
        如果它還能正常刷卡 ⇒ 🔴 設定沒生效,停下來告訴我,不要繼續
📌 判別句:我看到的是【面板上的字】,還是【那個網站的行為】?
          只有後者算生效。
```

⚠️ **第 3 步為什麼不能省**:第 1、2 步只改了「以後新部署會拿到什麼」。
**現在正掛著的那些預覽版,還是舊的。** 不重新部署,它們照樣能刷真卡。

## 1. 最常撞的一句:「這張單已取消,但供應商的貨到了」

登錄會回 **`EXCEEDS_ROOM_AFTER_CANCELLATION`**:這張單被取消掉的份額,**不能再登錄到貨**。

- ✅ **這不是壞掉,是設計**(Sean Q9=A)。貨變成自家庫存,**不掛回那張單**。
- 部分取消也會撞:原本 3 件、取消 2 件,第 1 件登錄得進去,第 2 件就回這個碼。

### 這批貨要記到哪裡去:**登記溢收**

**資料庫層的出口已經有了** —— 用「**到貨 0 件、溢收 N 件**」登記(`quantity=0 / surplus=N`)。
a1 migration `20260810230000:82` 逐字寫了這個用法:「訂單已收滿之後才到的貨 = `quantity=0 / surplus=N`」。

- 兩道額度守門(採購列層 `:193`、品項層 `:245`)**都只看「到貨件數」、不看溢收件數** ⇒
  到貨填 0 就不會再撞 `EXCEEDS_ROOM_AFTER_CANCELLATION`。
- 溢收的語意(Sean Q1=A):**有紀錄查得到,但不能自動拿去出別單** —— 它不加進可出量。
- 🔴 **不要**改小取消數量、改大訂購量,或自己新開一筆採購列來硬塞 ——
  那會讓客人的取消紀錄與退款對不上,而且額度是**品項層**的
  (`quantity − Σ已取消 − Σ已到貨`,`20260811010000_..._item_level_room_guard.sql:231-241`),
  換一筆採購列**在同一張單上一樣會被擋**。

⚠️ **#352-b 上線時要確認畫面真的給得出這條路**(backlog **#386**):
被擋當下員工要能直接把「到貨件數」改成 0 並填溢收,而不是自己去猜。
溢收之後那批貨怎麼變成可以賣的庫存 = backlog **#374**(Phase 2、獨立庫存、要跟報價單整合);
在 #374 之前,溢收紀錄只是**查得到的帳**,不是能出貨的庫存。

## 3. 其餘回傳碼一覽(逐字取自 migration)

**登錄** `admin_record_item_receipt`:

| 碼 | 意思 | 值班怎麼做 |
| --- | --- | --- |
| `RECORDED` | 登錄成功 | 正常 |
| `DUPLICATE_REQUEST` | 同一張單同一個請求碼重送 | 正常,**不要再按一次**;第一次已經記進去了 |
| `EXCEEDS_ROOM_AFTER_CANCELLATION` | 這張單被取消掉的份額不能再登錄到貨 | 見 §1 —— 到貨填 0、多的登記**溢收** |
| `QUANTITY_EXCEEDS_ALLOCATED` | 超過這筆採購**訂了幾件** | 先對供應商出貨單;確實多送就到貨填 0、多的登記**溢收** |
| `PROCUREMENT_NOT_FOUND` | 找不到那筆採購 | 畫面重整;仍舊回報給工程 |
| `INVALID_QUANTITY` | 數量不是正整數 | 改輸入 |
| `NOTE_TOO_LONG` | 備註超長 | 縮短 |
| `RECEIVED_AT_REQUIRED` / `RECEIVED_AT_OUT_OF_RANGE` / `RECEIVED_AT_IN_FUTURE` | 到貨日空白 / 超出合理範圍 / 填到未來 | 改日期 |

`ALREADY_DELETED` = 已經刪過(重按無害)/ `RECEIPT_NOT_FOUND` = 找不到該筆收據。

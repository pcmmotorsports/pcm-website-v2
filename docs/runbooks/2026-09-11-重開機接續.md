## §1 重開前:存檔 + 「做到哪」卡片(主視窗統一廣播,施工窗照做)

**廣播原文(主視窗整段發給每一個施工窗):**

```
【重開前存檔 —— Sean 2026-09-11 拍】

存檔 = ① 在【你自己的分支】commit(git add 精確路徑, 禁 -A / .)
       ② 做到一半照存 —— 閘沒過就在 commit message 寫「閘 X 未過, 停在 Y」, 不要為了存檔去硬跑完
存檔 ≠ ❌ push   ❌ 併進 dev   ❌ 刪任何東西

然後回我這張卡片, 六行, 不要多:
  1. 我是誰      <ListAgents 印的本 session 名字>
  2. 樹 / 分支   <git rev-parse --show-toplevel> · <git branch --show-current>
  3. 做到哪      <一句話, 哪一題/哪一列, 做完幾成>
  4. 下一步      <重開後第一件要做的事, 具體到檔名>
  5. 卡在什麼    <沒有就寫「無」>
  6. 未推        <git rev-list --count dev..HEAD> 顆 · 最後一顆 <sha>
```

🔴 **卡片第 6 行用 `dev..HEAD` 不用 `origin/dev..HEAD`** —— merge 過 dev 之後,後者會把別人的算進你頭上
(§C-坑 第 8 行,2026-09-08 實例:它印 72,而那個窗自己的只有 6)。

### 🔴 收工的定義:東西在 dev 上,不是「我 commit 了」

別的 worktree 的 commit **等於沒 commit** —— 沒有人會去那棵樹推它。
🔬 2026-09-11 實量:`~/pcm-mob`(`agent/mob`)**領先 15 顆、髒 2 檔** —— 那 15 顆不在 dev 上。
> ✅ **[主視窗 11:35 訂正]** `a2` 已逐檔盤點:那 15 顆動過的 10 支檔 **全部已在主樹、逐檔 diff 一致**(`-c core.quotepath=false` 重跑 10/10);2 支髒檔的內容也已在主樹。⇒ **甲/乙都不用選 —— 內容已經在 dev 上,`agent/mob` 只是一條過期分支。**

⇒ **重開前主視窗要對每一棵「領先 > 0」的樹決定一件事:**
```
甲 併進 dev 再重開(乾淨, 而要跑三綠 + 預告)
乙 留在那棵樹的分支上, 重開後由接手的窗在同一棵樹接著做(卡片第 4 行要寫清楚)
```
**不可以是第三種:沒人決定。**

你是 PCM 網站重做的【施工窗 〈A 前台 / B 後台〉】。

   缺的那幾份 ⇒ 要跑 dev server / 測試前回報主視窗, 不要自己複製(.env 不在對話裡碰)

你在這棵樹 commit ≠ 做完。回報時寫「未推 N 顆, 最後一顆 sha」, 由主視窗決定併進 dev。
🛑 不 push。

## §5 哨兵 + 不停機,實際怎麼跑

```
主視窗派工那一發   SendMessage(to=施工窗, message=交辦, notify_when_idle: true)
                  ⇒ 同一發既派工又訂閱
施工窗做完         回報主視窗(它自己發)⇒ 主視窗【立刻】派下一件
施工窗結束沒講     哨兵通知抵達 ⇒ 主視窗去 ListAgents 看它還在不在
回報 Sean 之前     主視窗先跑 ListAgents, 對照窗表數一次窗
```

🛑 **哨兵的已知限制**(CLAUDE.md〈多窗:哨兵〉逐字):
「**每一則 idle 通知抵達時,那個窗自己的訊息都早就到了 ⇒ 通知是過期的。**」
⇒ 它**不是**「有人在盯著」。它只抓「窗結束了而它沒發訊息」那一種缺席。

🔵 **「不停機」與「窗可以停下」不衝突:**
```
不停機   = 主視窗的責任:手上永遠有下一件可以派, 窗一回報就派, 不先等 Sean
窗停下   = 施工窗的權利:判斷不對就停, 講理由, 同步主視窗
🔴 而【不可逆 / 對外 / 寄信 / 正式庫寫入】仍然等 Sean —— 那是安全線不是節奏(Sean 0910 原文)
```

# 艦隊:不停滯 + 不跑題(2026-09-08 Sean 兩次喊停之後立的)

> 🔴 **本檔記的是【機制】不是【心法】** —— 心法今天證明無效:同一件事校正過很多次,而它每次都回來。
> 📌 常載只放判別句與指標;為什麼、實錘、當天的讀數在這裡。

---

## 一、跑題:那個判別句(取代所有討論)

Sean 2026-09-08 **同一天問了兩次**:
```
① 「確定一下你跟每一個施工視窗是不是又一直在修裡沒意義的事情喔?」
② 「你們是否又開始檢查自己的檢查?」
③ 而他接著問:「怎麼這麼容易往這個方向跑, 我們校正超級多次, 總是會變成這樣..」
```
🔬 **量到的**:那天 `dev` 上 **128 顆 commit ⇒ docs 88 顆(69%)**,真動到產品 23 顆;
而板上 **125 件掛著 ⟨擋⟩,一件都沒碰**。

### 🛑 每一件動手之前問這一句
> ## **這一件做完了,【客人的體驗】或【Sean 的操作】會不一樣嗎?**
> **不會 ⇒ 那不是現在該做的。** 不管它多有道理、多值得記、多可複製。

### 🔵 唯一的例外
```
它【擋住別人做事】(閘 rc=1 / 板紅 / commit 過不了)
⇒ ✅ 修掉
⇒ 🛑 而【只修不研究】—— 不寫落板文字、不寫 traps、不分析「為什麼第一把尺沒看到」
```

### 🔴 為什麼會跑題 —— 成因不是紀律,是獎勵結構
| | 量具/教訓那條路 | 關擋上線的列 |
|---|---|---|
| 找得到嗎 | **永遠找得到** —— 任何工具都有盲區 | 要讀陌生的碼、判斷模糊的東西 |
| 多久有成果 | **五分鐘,而且是真的** | 幾小時,而且可能做完發現不對 |
| 產出 | 一句漂亮的話 + 一顆 commit | 一列變成 `done` |

🔴 **而最關鍵的:主視窗一直在發獎品。** 每次有窗交出量測發現就說「那條要落 traps」「那句最值錢」
⇒ 📌 **八個窗都在對主視窗的反應學習** ⇒ **不是它們往那邊跑,是主視窗一直在那邊發糖。**
🛑 **⇒ 主視窗的義務:不再稱讚那個方向。** 而那比寫規則有效,因為**規則本身也是那個形狀**
(2026-09-08 實錘:第一次喊停之後,主視窗做的事是**寫了一條新規則說不要再寫規則**)。

## 二、停滯:三種,而它們的修法不同

Sean 逐字:「我發現 account, auth, db, mail 會有停滯的習慣,剛剛 refund 也是發現說他回了『繼續』然後就明擺了」
以及(看了四個窗的截圖之後)**「在我眼中他們就是停住了」**。

### 甲型:回一句沒有受詞的話,然後等
`-refund` 自陳:「我寫『繼續』**然後就停下來等** —— 是 Sean 敲我才動的。」
📌 **「繼續」是一個【回報】不是一個【動作】。**
🔴 **而在主視窗那一端,「窗在做事」與「窗停了」是同一個訊號:什麼都沒有。**

```
① ⛔ 禁止只回「繼續」「我接著做」「往下領」「沒有題要你決定」—— 沒有受詞的句子
② ✅ 每則回報的【最後一行】必須是「⏭ 下一件:<具體的錨 / 檔名 / 那一列的行為>」, 寫完【直接做】
③ 🔴 找不到下一件 ⇒ 不要寫「手上空了」, 寫出你問過 R7 三題的【答案】
🛑 判別句:我這一則的最後一行, 是【名詞】還是【動詞】? 動詞 ⇒ 你在等人
```

### 乙型:等主視窗發下一批 —— **而那是主視窗的設計問題**
2026-09-08 四個窗最後一行都是「跟主視窗要下一批」。
🔴 **成因**:主視窗一整天都在替它們挑 ⇒ **它們學會了「主視窗會發」**。

✅ **修法是機制不是規則:認領板**
```
📄 ~/pcm-mailbox/認領板-<日期>.md   ← 從 python3 scripts/launch-dispatch-table.py 的
                                     【無主】+【已不存在的線】兩節產生
① 挑一列 ② 【當場】把線名寫進「誰領」欄並存檔 ③ 才開始做
🛑 誰領欄有名字的不要碰。寫了名字就必須做完或明說卡在哪, 不可以放著
✅ 做完把「結果」欄填一句(done / 卡在哪 / 不成立)⇒ 直接挑下一列
📌 全部領完了才回主視窗 —— 那時附「我做了幾列 / 幾列卡住 / 卡在誰」
🔴 卡住【不是】回報主視窗的理由 ⇒ 結果欄寫「卡在 X」⇒ 挑下一列
```

### 丙型:**一直被主視窗岔開** —— 這一型最難看見
`-db` 自陳:「我宣告了三次『下一件是 X』,**三次都沒動到它**
⇒ 📌 **不是停著,是【一直在被岔開】**。」
🔴 **岔開它的是主視窗** —— 每個窗交一件就回一長則,**而那則裡通常還帶著新的東西**。

```
🛑 主視窗的義務:
   · 少回、短回, 【不要在回覆裡夾帶新東西】
   · 一個窗宣告了「下一件是 X」之後, 到它交出 X 為止【不再寄東西給它】
     例外只有兩種:① Sean 拍板改變它手上那件 ② 別條線的讀數推翻它正在做的前提
```

## 三、主視窗不是唯一的路口

```
① 連做 2-3 件再回報 —— 不要做一件停一件
   🛑 三種【立刻回報】的例外:
      · 要 Sean 拍板的(壓成一個字回得完, 走 Q:/A:)
      · 撞到授權邊界(不可逆 / 對外 / 平台設定 / 角色憑證)
      · 你的讀數【推翻別條線已經交出去的東西】—— 那會擴散, 越晚越貴
② 不需要主視窗的, 窗對窗直接寄
   落板文字 ⇒ ship · traps 實例 ⇒ 正在寫那一節的人 · 複量別人的讀數 ⇒ 當事人
   🔴 而【推翻別人的裁定】仍然經主視窗 —— 那不是效率問題, 是那個人有權先看到
③ 手上空了 = 自己領, 不是回報「我手上空了」
```

### 主視窗保留的只有四件
```
1. Sean 的題(端出去 / 收回來 / 落檔)
2. 收割與合併(碰 dev)
3. apply-paste-board(那支腳本自己寫著「跑它的是主視窗」)
4. 跨線衝突與推翻裁定的仲裁
```
📌 **代價明寫:主視窗會比較晚知道事情** ⇒ 所以①那三種例外不可以省。

## 四、推之前一定要發預告

2026-09-08 主視窗推了 215 顆而**沒有發預告** ⇒ **七個窗各自來問**。
📌 而七個都做對了同一件事:回「我沒推」、**把「我沒推」與「我證不出是誰推的」分開**、**不自己查 reflog**。
🔵 **而它們做對是因為那道警示裡有一句解釋**:「reflog 不記錄執行者 ⇒ 自己去查只會得到這個答案」
⇒ 🎯 **一道會解釋自己為什麼存在的守門,比一道只會擋人的有用。**

```
✅ 預告的形狀:「origin/dev 會從 <X> 走到 <Y>, 共 N 顆」⇒ 推之前廣播全線
🔴 而「沒有預告」與「預告沒送到」在收訊那一端是【同一個空白】
```

## 五、Sean 隨時可以查的那個數

```bash
git log --since=today --format='%s' origin/dev..dev \
  | awk '{n++; if($0 ~ /^docs/) d++} END {print "文件 " d+0 " / 總共 " n+0}'
```
🛑 **回「文件 0 / 總共 0」⇒ 那一發不算數**(剛推完, 分母是 0)——
📌 **「都沒有寫文件」與「一顆 commit 都還沒有」印同一個 0。**
🔵 而更省事:**直接問主視窗「現在幾比幾」**。答不出來或數字又跑高 ⇒ 又跑掉了。
🔬 2026-09-08 推之前那一批:**88 / 128(69%)**。

## 你需要準備的三樣東西

**① 連線字串 `D1_DB_URL`** —— 🔴 **形狀要求比 D1a2 那次嚴**,因為這支 CLI 走離散欄位守門:

- host 必須是 session pooler:`aws-<數字>-<區域>.pooler.supabase.com`
- **port 必須是 5432(或省略)。`6543` 會被當場拒收** —— transaction pooler 的 host 與帳號
  跟 session pooler**一模一樣、只差 port**,而 D1 全程靠 session 級 advisory lock 擋雙執行,
  誤用會讓那道防護靜默歸零。
- 帳號必須是 `postgres.bmpnplmnldofgaohnaok`,資料庫 `postgres`
- 連線字串裡的 `?sslmode=...` 一律**被忽略**(CLI 自己強制帶 CA 驗證),不用管

不符上面任一條,你會看到 `D1:連線目標不符 production;拒絕執行`(訊息刻意不含連線字串)。

**② TapPay 正式商戶的 merchant id** —— 從商家後台抄。它會跟 Vercel env 裡的
`TAPPAY_MERCHANT_ID` 比對,**兩個獨立系統對得上才放行**(這就是 Q2=A 的雙輸入斷言)。

**③ `age` 加密密碼**(1Password 裡那組,跟匯出檔同一組) —— 步驟 5 保存證據包時要用。

**預期**:`D1-OUTCOME: readback-ok`,exit 0。

**貼回給我這三段就好**(都不含機敏值):

```bash
python3 -c "

e=json.load(open(p))
print('outcome=',e['outcome'])
for r in e['readback']:
    print(r['displayId'], r['verdict'], r['evidenceLevel'], 'status=',r['recordStatus'], 'amt=',r['amount'], 'refunded=',r['refundedAmount'])
print('shapes=',{k:v['topLevelKeys'] for k,v in e.get('responseShapes',{}).items()})
"
```

### 看到 `readback-aborted` 怎麼辦

**不要重跑、不要改參數。** 證據檔照樣有落盤(這是刻意的),把上面那段輸出貼給我,
我讀 `error` 那欄判斷。最可能的兩種:

- **某張 pending 單回 `record_status = 0`(AUTH)或 `4`(PENDING)** —— 規格明文:
  這兩個值**不自動放行**,要保留 cohort、停下等你決定。這不是程式壞了,是預期分支。
- **`0102` 或 `0104` 查無** —— 正式站真刷過必有紀錄,查無代表事實與假設不符,必須停。
- (`0052` 查無是**合法出口**:它會走「保持原值」,不擋其餘。)

## 步驟 4 · D1c apply(🔴 不可逆)

```bash
cd /Users/sean_1/pcm-website-v2 && \
npx tsx scripts/d1-orchestrator-cli.ts apply \
  --target production \
  --merchant-id '<同上>' \
  --confirm DELETE-26-ORDERS \
  --audit "$HOME/.pcm-d1/d1c-audit-20260730.json"
```

`--confirm DELETE-26-ORDERS` 是**防誤觸**用的,不是批准本身(批准 = 步驟 3 你親口說的那句)。

**它會做的事,依序**:停用結帳掃描排程器 → 等在途請求排空 → 等 70 秒沉降(這段會停在那裡,
是正常的)→ 開交易 → 三道守門 → 鎖列 → **再跑一次 read-back** → 刪 26 張 → 3 張改號 →
狀態對齊 → 驗收矩陣 → 先落 audit → COMMIT → 恢復排程器。整段約 3-4 分鐘。

**預期**:`D1-OUTCOME: completed`,exit 0,訊息含「sweeper 已恢復」。

### 🔴 出現以下任何一種:立刻停手,把訊息貼給我,不要重跑

| `D1-OUTCOME` | 意思 | 可以重跑嗎 |
|---|---|---|
| `completed` | 全部做完、排程器已恢復 | 已完成 |
| `not_committed` | 沒提交、資料一動未動 | 可以(先看原因) |
| `not_committed_recovery_required` | 沒提交,但排程器沒恢復回來 | **先跑 `--recover-sweeper` 再重跑** |
| `commit_outcome_unknown` | **COMMIT 送出了但結果不明** | 🔴 **絕對不可重跑** |
| `committed_recovery_required` | **資料已刪**,收尾失敗 | 🔴 **不可重跑**,只跑 `--recover-sweeper` |
| `recovery_only` | 只做了收尾 | 看訊息裡的對帳那句 |

**排程器復原指令**(任何時候都可以單獨跑,它只讀自己留下的狀態檔):

```bash
cd /Users/sean_1/pcm-website-v2 && \
npx tsx scripts/d1-orchestrator-cli.ts recover-sweeper \
  --target production --audit "$HOME/.pcm-d1/d1c-recover-20260730.json"
```

**如果程式在中途被 Ctrl-C 或整台機器死掉**:結帳掃描排程器可能還停著。
**一定要跑上面那道 `--recover-sweeper` 並確認回報「sweeper 已恢復」** ——
它停著的期間,已授權但未入帳的刷卡不會被自動對帳。

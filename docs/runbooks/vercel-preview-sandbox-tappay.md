## 步驟(四步,順序不可換)

### 第 1 步 · 先去 TapPay 拿沙盒那組金鑰
```
要拿兩個值:Partner Key、Merchant ID —— 沙盒那組
🔴 沙盒與正式是【兩套不同的值】,不能共用
⚠️ 在 TapPay 商戶後台,**確切在哪一頁我沒查證**(未確認)
```

### 第 2 步 · Vercel 新增四個變數(Project → Settings → Environment Variables)
**每一個都只勾 `Preview`,不要勾 `Production`。**(`Development` 勾不勾都可以,那是本機。)

| 變數名 | 填什麼 | 🔴 格式不可以錯 |
|---|---|---|
| `TAPPAY_ENV` | `sandbox` | **只認 `sandbox` 或 `production`** 兩個字。不是 `1`、不是 `true`、不是 `SANDBOX` |
| `TAPPAY_PARTNER_KEY` | 第 1 步拿的沙盒 partner key | — |
| `TAPPAY_MERCHANT_ID` | 第 1 步拿的沙盒 merchant id | — |
| `TAPPAY_3DS_ENABLED` | `true` | 🔴 **只認小寫 `true` 這五個字母**。`TRUE` / `1` / `yes` 一律當成關閉,而**它不會報錯,只是靜靜地不跳 3D 驗證** |

> 🔴 **貼值不要帶到多餘的空白。** 顧客站那側**不會**幫你把空白去掉(後台那側會)⇒ 同一個帶空白的值,後台正常、顧客站報錯。
> (依據:`apps/admin/.../composition.ts:137` 有 `.trim()`,`apps/storefront/.../composition.ts:70` 沒有。)

### 第 3 步 · **重新部署一個 preview(這一步不能省)**
環境變數是在**建置的時候**讀進去的 ⇒ **只改設定、不重新部署,舊的預覽版還是舊的值。**
做法:進那個 preview deployment → `Redeploy`。

### 第 4 步 · 確認它真的生效(**看到東西才算,不是「沒報錯」**)
```
1. 開那個 preview 網址,走到結帳
2. 用這張測試卡:4242 4242 4242 4242 / CVV 123 / 有效期限填【任何未來的年月】
   (官方公開測試卡,正本 docs/reference/tappay-sandbox-test-cards.md)
3. ✅ **成立的樣子 = 跳出 3DS 驗證頁。**
```
🔴 **為什麼要看「跳出來」而不是看「刷成功」**:你上次量到的失敗長相就是**沒跳 3D 驗證**。
⇒ **這次要看到它跳,才代表設定真的換過去了** —— 「刷失敗」與「設定沒生效」在畫面上長得一樣。

---

## 失敗長什麼樣 ⇒ 看到這些字就停下來,不要自己改

| 你看到 | 意思 | 怎麼辦 |
|---|---|---|
| `TAPPAY_ENV 須為 'sandbox' 或 'production'(got 'xxx')` | 值打錯了 | 回第 2 步,照表格重填 |
| 頁面直接掛掉 / `requireEnv` 之類的錯 | 三個變數有沒填的,或**忘了勾 Preview** | 回第 2 步,確認四個都在、都勾了 Preview |
| 刷了但**沒跳 3DS** | `TAPPAY_3DS_ENABLED` 不是小寫 `true`,或**沒重新部署** | 先確認第 3 步做了,再回第 2 步看那個值 |
| 後台按退款,說「TapPay 環境與帳本 DB 配對不成立」 | ✅ **預期的,不是壞掉**(見上面 ②) | 不用處理 |

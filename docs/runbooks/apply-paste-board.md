## 2. 它會在哪裡停(每一道停的意思不同)

| 停在 | 意思 | 你該做什麼 |
|---|---|---|
| ① 貼板編號命中 ≠ 1 支 | 編號給錯 / 貼板有重號 | 對編號 |
| ③ 檔名取不出 14 位版本號 | 貼板檔名不合格式 | 改檔名或問寫的人 |
| ④ repo 裡那個版本 ≠ 1 支 | migration 沒進版控 / 重號 | 先處理版控 |
| ⑤ **兩個 sha 不同** | 貼板那份與 repo 那份**不是同一份內容** | 看 diff,決定哪一份才對 |
| ⑥ 版本已在 `APPLIED.tsv` | 已經記過帳 | 不要重貼 |
| ⑥ **`APPLIED.tsv` 有而平台帳本沒有** | 貼過了而沒 repair | **只補 repair**,不要重貼 |
| ⑦ **平台帳本上已經有這個版本** | `supabase_migrations.schema_migrations` 有此 version ⇒ **貼過了** | 不要重貼;若 `APPLIED.tsv` 沒記,只補那一行 |
| ⑦ **查不動(連不上 / 沒權限)** | 🔴 fail-closed ——「沒有查」不是「查無」 | 看它印的 psql 錯誤 |
| ⑦ **含 psql meta-command(任何反斜線指令)** | 🔴 `\include` 可跑不在 SHA 裡的 SQL · `\c` 可換庫(**而 A/B 驗證看不到**)· `\!` 執行任意 shell · 關掉 `ON_ERROR_STOP` 讓錯誤後照跑而 rc=0 | 那支要人判 |
| ⑦ **會在 apply 當下寫資料而檔頭沒宣告冪等** | 🔴 兩本帳證的是「**沒有人記過**」,不是「**跑第二次是安全的**」 | 確認重跑安全後,在檔頭加 `-- pcm:idempotent: yes` |
| ⑦ **交易形狀 messy** | 中途 `COMMIT` / 只有一半 ⇒ `-1` 帶或不帶都不對 | 那支要人判 |
| ⑦ **檔在前置與 apply 之間被改過** | SHA 回核不符 ⇒ **我不知道 DB 跑的是哪一份** | 不記帳,交給人判 |
| ⑦ **那張表不存在** | 🔴 fail-closed —— 表不存在時 `count` 也會回 0,**那個 0 是尺的 0** | 確認寫入身分讀得到 `supabase_migrations` |

## 3. 🔴 貼完之後出事怎麼辦

| 情況 | 狀態 | 怎麼辦 |
|---|---|---|
| psql 印 ERROR · 檔案**自帶** `BEGIN…COMMIT`(shape=clean) | 🔴 **本工具【不帶 `-1`】** —— 原子性由**檔案自己**保證;錯在 COMMIT 之前 ⇒ 連線關閉時回滾 | 看 log 的 ERROR |
| psql 印 ERROR · 檔案**零交易控制**(shape=none) | 本工具帶 `-1` ⇒ 整支回滾 | 看 log 的 ERROR |
| **psql rc=2(連線中斷)** | 🔴🔴 **這一種不能斷言 DB 未變** —— 若在 COMMIT 的回應之前斷線, 可能已經提交 | **先唯讀查再決定**,不要重跑 |
| **psql 成功而 `repair` 失敗** | 🔴🔴 **半套:DB 變了而平台帳本沒記** | 工具會把**要手補的兩行印出來** —— 照著補 |
| 全成功,事後發現貼錯 | 🔴 **沒有自動 rollback** | 要那支 migration 自己的 down;**沒有 down 就沒有回頭路** |

🛑 **⇒ 所以「一次一支 + Sean 逐支點名」不是流程繁瑣,它是這片唯一的 rollback。**
📌 而「半套」那一格在 `rc` 上與「什麼都沒做」長得一樣 —— 所以工具**不會靜靜結束**,它會印紅。

## 4-b. 冪等宣告閘(⟦db-APPLYIDEMPOTENT⟧)

🔴 **它擋什麼**:一支**會在 apply 當下寫資料**、而檔頭沒有 `-- pcm:idempotent: yes` 的 migration。
理由:**兩本帳證的是「沒有人記過」,不是「跑第二次是安全的」** —— 一支純 `INSERT` 的片子重貼會**加倍**,而兩本帳在它第一次貼完沒被記到時**都會說「沒有」**。

🔬 **射程是量出來的**(用**同一支碼**數,不是另寫一支):
```bash
for f in supabase/migrations/*.sql; do
  bash scripts/apply-paste-board.sh --check-dml "$f" >/dev/null 2>&1
  [ $? = 1 ] && echo "$f"
done | wc -l
```
⇒ 分母 **335** 支 · **會被擋 55 支**(2026-09-06 opus R3 折完後重量,與折前同數)。

🔴 **`[ $? = 1 ]` 不可以寫成 `||`**(codex R2 抓到):`--check-dml` 的離場碼是**三態** ——
**0 = 過 · 1 = 擋 · ≥2 = 掃描器自己壞了**。
⛔ ~~`|| echo`~~ 會把「掃描器壞掉」也算成「有 DML」⇒ **在掃不動的環境它會假報 335**。
📌 **一條為了證明數字而寫的指令,自己把兩種世界壓成同一個。**

🔵 **三個分母(當場量,`-f8` 2026-09-06 要求寫進來)**:
| 位置 | 支數 | 算不算 | 為什麼 |
|---|---|---|---|
| **頂層** | **26** | ✅ 算 | apply 當下就執行 |
| **`DO $$…$$` 區塊內** | **26**(其中頂層沒有的 24) | ✅ 算 | 🔴 **DO 在 apply 當下會執行** |
| **`AS $fn$…$fn$` 函式體內** | **125** | ⛔ 不算 | 🔵 **函式體只有被呼叫時才跑** |

📌 **把函式體也算進去的話,這道閘會對 42%(125 支)的 migration 叫,而那些幾乎全是誤報。**
🛑 而**只算頂層**會漏掉 24 支 —— 那 24 支的 `DO` 區塊**真的會寫資料**。

## 4-c. 🛑 這道閘【證不到】什麼(codex R1/R2 逐條指名,照實列)

· 🔴 **`SELECT write_fn()` / `PERFORM write_fn()` 抓不到** —— 一個函式呼叫**看不出來它會不會寫**。
  這是**文字比對的天花板**,不是可以補的樣式。⇒ **貼含函式呼叫的片子時,那一格靠人。**
· 🔴 **`EXECUTE format(...)` / 字串拼接的動態 SQL 抓不到** —— 同一個天花板。
· 🔵 **`TEMP … ON COMMIT DROP` 的 CTAS 被放行,而那是【已知的放寬】** ——
  即使表會 DROP,查詢裡的 `nextval()` 或寫入型函式**仍留永久副作用**。
· 🔴 **「`.env.local` 設 `APB_SELFTEST=1`」那個世界 selftest 造不出來**(要一份真的主樹 `.env.local`)
  ⇒ 那條路今天靠**讀碼**,不是靠**跑過**。📌 **未覆蓋不是通過。**
· ⛔ ~~只有上面那一格未覆蓋~~ —— **2026-09-06 opus R3 訂正**:當時**整個 `.env.local` 載入區塊
  都是零覆蓋**(把它整塊換成 `die`,selftest 仍 110/0)⇒ 讀的人會以為「其餘部分跑過了」。

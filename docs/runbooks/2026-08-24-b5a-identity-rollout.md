## 2. 三件東西的順序(這是問題的本體)

```
① 這份碼部署到【全部】節點   (能收 v:1 與 v:2;仍簽 v:1, 因為上游沒送 sub)
② 上游開始送 sub             (⇒ 我們開始【簽】v:2)
③ ADMIN_REQUIRE_REAL_IDENTITY=1 (⇒ 開始【拒】v:1)
```
**硬約束:① 全部完成 → ② → ③**,而且 ③ 之前要讓在外的 v:1 票自然汰換。

| 顛倒 | 後果 | 有沒有機制在擋 |
|---|---|---|
| ③ 先於 ② | 每次登入簽 v:1 ⇒ 下一個請求被自己拒 ⇒ **登入無限迴圈** | ✅ **有**(見 §4) |
| ② 早於 ① 完成 | 新節點簽 v:2、舊節點拒 v:2 ⇒ **間歇登出** | 🔴 **沒有**(只有 §3 的事後偵測) |
| revert(② 之後) | 在外的 v:2 票被舊碼 `v!==1` 全拒 | 🔴 **沒有**(見 §5) |

📏 **量到的**:HEAD(= 現在線上的 admin)的守衛是 `if (o.v !== 1) return false`
⇒ **舊碼拒 v:2**。量法:`git show HEAD:apps/admin/src/lib/session/session.ts | grep 'o.v'`

📏 **而今天有一件事對我們有利**:這份碼**今天不簽 v:2**(上游沒送 `sub`)
⇒ **這一次部署本身是安全的**(純「開始收 v:2」的擴充階段)。
⇒ 🔴 **危險窗不是現在,是【上游翻開關】那一天。**

## 3. 🧮 偵測器:還有沒有舊節點在跑(② 之後才有用)

```sql
-- 🔴 這一發【沒有在正式庫跑過】。它要 migration 20260824030000 先 apply 才有資料。
SELECT actor_kind IS NULL AS looks_like_old_node, count(*)
  FROM public.admin_sso_login_events
 WHERE outcome = 'success' AND occurred_at > now() - interval '15 min'
 GROUP BY 1;
```
**怎麼讀**:② 之後,新節點簽的票會帶身分 ⇒ `actor_kind` 非 NULL。
若同時仍有**大量** `actor_kind IS NULL` 的成功列 ⇒ 🧮 **推測**還有舊節點在簽 v:1。

⚠️ **它的天花板(照實寫,不要放大)。這一節有兩個方向,兩個都要讀:**

### 方向一:**看到 NULL** 不等於有舊節點
- `actor_kind IS NULL` 的**第二個來源**:上游對**那一次登入**本來就沒送 sub(例如 fallback 登入路徑)
  ⇒ 🔴 **非零不等於有舊節點。** 要配合部署時間點一起看。

### 方向二 🔴🔴:**看不到舊節點** 更不等於舊節點已經清空(2026-08-24 codex R2-5)
```
「這個查詢裡沒有舊節點的列」有【三個來源】, 而它們印出來的東西一模一樣:
  ① 真的沒有舊節點了                      ← 你想要的那個
  ② 舊節點還在, 但這 15 分鐘【沒有人從它登入】
  ③ 舊節點還在也有人登入, 但它那一發【best-effort 的 DB 寫入失敗了】⇒ 那一列不存在
```
🔴 ③ **正是這本帳一開始要修的那個病**(`login-event.ts` 的失敗路徑設計上是靜默的)——
   ⇒ **用一本「會靜默漏列」的帳去證明「某個東西不存在」,那個推論本身就不成立。**
⇒ **這個查詢只能拿來【確認舊節點還在】(看到就是有),不能拿來【宣告舊節點已清空】。**
   要宣告清空,證據必須來自部署平台(Vercel 的 rollout 狀態),不是這張表。

### 兩個方向共用的紀律
- **事後偵測,不是預防。** 它看得到「已經發生了」,看不到「即將發生」。
- 沒有正對照就下結論 = 假綠。**先確認同一個窗口裡有非 NULL 的列**(證明鏈是活的),再看 NULL 那一格。

## 4. ✅ 唯一一個真的機制:③ 先於 ② 會被當場擋下

**碼**:`apps/admin/src/app/api/sso/callback/route.ts`(`requireRealIdentity() && !result.sub`)

## 5. 🔴 revert 這一包:**沒有機制,而且處置與直覺相反**

```
❌ 不要只做:「先把 env 拿掉」—— 那救不了已經簽出去的票
✅ 要做:revert 這片 = 必須配一個【讓所有現存票一起失效】的動作
        = 換 ADMIN_SESSION_SECRET ⇒ 全員重登一次
        (或等它們自然過期, 而那段期間部分員工登不進來)
```
理由:碼 revert 回去 ⇒ 舊碼守衛是 `v === 1` ⇒ **還沒過期的 v:2 票全部被拒**,
而它們已經在使用者的瀏覽器裡 —— **env 動不到它們。**

⚠️🔴 **沒有任何機制在執行這一條。它靠 revert 的人讀到這段字。**
**已知的失敗方式**:有人用 `git revert` 而沒有先 `git show` 那顆 commit
(`git revert` 產生的訊息**預設只帶 subject、不帶 body**)。

📌 唯一一個**會被強制經過**的時點 = **B7 的 plan 必須先答「退場路徑」** ——
而**那也不是機制,是流程**:它靠「B7 那片會照規矩提 plan」。

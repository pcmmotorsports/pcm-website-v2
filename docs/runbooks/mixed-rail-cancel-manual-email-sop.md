# 告警說「有取消單要人工寄信」—— 怎麼辦

> **這一份給客服。** 技術錨在最後一節,客服不必讀。
> 建立:2026-09-06 線【信】`-mail`(⟦b4-CANCELMAILMIXEDRAIL⟧ 的「提醒那半」)。

## 症狀

早上那封告警信裡出現一段:
```
【有取消單要人工寄信】
🔵 N 張混合退款的取消單【系統刻意不寄】, 而客人還沒收到通知。
```

## 一句話:為什麼系統不寄

那些單的錢是**分兩條路退的** —— 一部分退回信用卡、一部分是現金或匯款。

🔴 **而系統只算得出【退回卡上】的那一半** ⇒ 它寫得出來的信會**少講一半的錢**。
⇒ 📌 **主視窗 2026-09-05 裁:這種單【整張不寄】,等人工。**(`Q2 = 乙`)
🛑 **所以這【不是故障】** —— 是刻意的,而告警只是在提醒你去補那一封。

## 你要做什麼

1. **從告警那段拿到張數**;要拿到是哪幾張單,請工程跑一發唯讀查詢(見技術錨)。
2. **打開那張單的後台明細**,看兩個數:**退回卡上多少**、**另外用現金/匯款退了多少**。
3. **手動寄一封**給客人,而信裡**兩筆都要講**。
   🔴 **不要只講卡片那筆** —— 那正是系統不敢自己寄的原因。
4. 寄完**在那張單留一則備註**寫「已人工寄出取消通知 + 日期」。
   📌 **為什麼要留**:今天**沒有任何東西**會記錄你寄過了 ⇒ 下一次告警**還會把它算進去**,
   而看到的人分不出「還沒寄」與「寄過了而系統不知道」。

## 🔴 我們查不出來的那一格 —— 請先讀完再回覆

- **系統不知道你寄過沒**(上面第 4 點)⇒ **那個數字會重複出現**,直到那張單離開條件。
- **客人有沒有收到**:人工寄的信不經過我們的寄信紀錄 ⇒ **後台的「通知信」那一區不會有它**。
  ⇒ 客人若說沒收到,**不要說「系統顯示寄過了」** —— 系統不顯示。

## ⚠️ 而有一種情況不是這一格

**純刷卡、而只退了一部分**的單 —— 那是**另一道閘**(`refund_kind`)擋下來的,不是本檔講的混合軌。
📌 兩者的差別:**本檔這種是「錢走了兩條路」;那一種是「錢只走卡,而沒退滿」。**

# 步驟 1 · 先照一張「動之前長什麼樣」的相

**在 Supabase → SQL Editor,貼這一段、按執行:**

```sql
SELECT
  coalesce(
    (SELECT string_agg(x, ' | ' ORDER BY x) FROM (
       SELECT DISTINCT d.defaclrole::regrole::text || ' 建的新表 → ' || a.grantee::regrole::text AS x
         FROM pg_default_acl d
         JOIN pg_namespace n ON n.oid = d.defaclnamespace,
              LATERAL aclexplode(d.defaclacl) a
        WHERE n.nspname = 'public' AND d.defaclobjtype = 'r'
          AND a.grantee <> 0
          AND a.grantee::regrole::text NOT IN ('postgres', 'service_role')
     ) s),
    '乾淨')
    AS "①殘留_應為乾淨",
  (SELECT CASE WHEN to_regclass('public.sweeper_heartbeat') IS NULL
               THEN '沒有這張表' ELSE '表在' END)
    AS "②表_應為表在",
  (SELECT CASE
     WHEN to_regclass('public.sweeper_heartbeat') IS NULL
       THEN '量不到(表不存在)'
     WHEN (SELECT relacl FROM pg_class
            WHERE oid = to_regclass('public.sweeper_heartbeat')) IS NULL
       THEN '0(ACL 為 NULL = 零顯式授權)'
     ELSE (SELECT count(*)::text
             FROM pg_class c, LATERAL aclexplode(c.relacl) a
            WHERE c.oid = to_regclass('public.sweeper_heartbeat')
              AND a.grantee IN ('anon'::regrole, 'authenticated'::regrole))
   END)
    AS "③訪客權限_應為0";
```

### 你應該看到什麼

第 ① 格**大概會列出一串東西** —— 那正是我們要收掉的。

# 步驟 5 · 最後一段(問「以後新建的表真的乾淨了嗎」)

**整段貼進去、按執行:**

```sql
DO $$
DECLARE v text;
BEGIN
  CREATE TABLE public.pcm_acl_probe_tmp(x int);
  SELECT CASE
    WHEN (SELECT relacl FROM pg_class
           WHERE oid = 'public.pcm_acl_probe_tmp'::regclass) IS NULL
      THEN '乾淨(新表零顯式授權)'
    ELSE coalesce((SELECT string_agg(DISTINCT a.grantee::regrole::text, ', ')
                     FROM pg_class c, LATERAL aclexplode(c.relacl) a
                    WHERE c.oid = 'public.pcm_acl_probe_tmp'::regclass
                      AND a.grantee <> 0
                      AND a.grantee::regrole::text NOT IN ('postgres','service_role')),
                  '乾淨(只有 owner / service_role)')
  END INTO v;
  RAISE EXCEPTION '探測結果(這一行是正常的,不是出事):%', v;
END $$;
```

### 你應該看到什麼
**一行紅色的 ERROR,而它的內容就是答案:**
```
ERROR: 探測結果(這一行是正常的,不是出事):乾淨(新表零顯式授權)
   ⇒ ✅ 成功（限於【你這個帳號】建的表 —— 見下方限定）

ERROR: 探測結果(這一行是正常的,不是出事):anon
   ⇒ 🔴 洞還在。停下來貼回來。

看到【別的】錯誤（例如 syntax error / unterminated）
   ⇒ 你可能只貼到一半。整段重貼一次即可 —— 🔴 而這種情況【不會留下任何東西】
```

⚠️ **這一段只量得到「你這個帳號建表時會發生什麼」** ——
若還有別的身分在建表,這一段量不到那條。**那條靠步驟 4 的第 ① 格看,兩個要一起讀。**

## 你應該看到什麼 —— **四種,而它們的意思完全不同**

```
① {"code":"42501","message":"permission denied for table sweeper_heartbeat"}
   ⇒ ✅✅ 這是【最好的結果】，而且它一次證明兩件事：
        (a) 那張表【存在】而且中間那層看得到它
        (b) 訪客【真的被擋住了】= 你按的第 ① 支生效了
   ⇒ 看到這個就完成了。

② {"code":"PGRST205","message":"Could not find the table … in the schema cache"}
   ⇒ 🔴 【不要】讀成「表沒建起來」——步驟 4 已經證明它建起來了
   ⇒ 這句話的意思是【中間那層還不知道有它】
   ⇒ 做法：等一兩分鐘再打一次。還是一樣 ⇒ 停下來貼回來。

③ 一個【正常的結果】（例如 `[]`）而不是錯誤
   ⇒ 🔴🔴 這是【最壞的】：訪客打得進去 ⇒ REVOKE 沒生效
   ⇒ 停。不要繼續。貼回來。

④ {"code":"42703","message":"column … does not exist"}
   ⇒ 網址打錯了（欄位名寫錯）。用上面那個 `select=*` 就不會遇到。
```

🔴 **② 與 ③ 最容易被搞混,而它們一個是「再等等」、一個是「立刻停」。**
⚠️ 而 ① 那個「permission denied」**看起來像出事,其實是我們要的答案** ——
這是整份單子第二個「紅色的東西是好消息」的地方。

### 📎 上面四種我在拋棄式 PostgreSQL + PostgREST 上各跑過一次(2026-08-18)
```
表在、訪客有權         ⇒ [] / HTTP 200          ← ③ 那種（在這裡是壞消息）
假表名                 ⇒ PGRST205 / HTTP 404
表剛建、cache 未更新   ⇒ PGRST205 / HTTP 404    ← 🔴 與假表名【一字不差】
cache 更新後、訪客無權 ⇒ 42501   / HTTP 401     ← ① 我們要的
欄位名打錯             ⇒ 42703   / HTTP 400     ← ④（我自己先踩到才發現要寫）
```
🔴 **第三行是重點**:「表沒建」與「建了但那層還不知道」**回一模一樣的東西**
⇒ 這就是為什麼 ② 的下一步是「再等等」而不是「停」。

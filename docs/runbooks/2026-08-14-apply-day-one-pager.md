## 🔴 最重要的三句(其餘可以慢慢看)

1. **看到紅字就停。** 兩個更新都包在「一個交易」裡 ⇒ **失敗會自己整個退回去,資料不會做一半。**
2. **不要自己判斷「應該沒關係」。** 停下、把**整段訊息原封複製**傳出來就好。
3. **一次只做一個。** 做完、驗完,再做下一個。

## 先做哪個?—— **無所謂,但別同時做**

兩個更新**互不相干**:一個動「採購」那塊的兩支程式,一個新增一張「訂單貨品」檢視表,兩者讀寫的東西**零重疊**(已逐字比對)。

## A. 採購那個更新

**① 做之前:先問一句話。** Dashboard → SQL Editor 貼這段(**只是問,不會改任何東西**):

```sql
select count(*) as 已作廢的採購筆數
  from public.order_item_procurement where voided_at is not null;
```

- **是 `0`** ⇒ 往下做。
- **不是 `0`** ⇒ 🔴 **停,不要做這個更新**,把數字傳出來。
  意思是:有人在這之前**手動撤過採購**,而這個更新的安全性建立在「還沒有人撤過」上。
- ⚠️ **今天問過是 `0`,但那不算數** —— 中間任何人動過資料就會變。**當天要重問一次。**

**② 怎麼做。** 照平常做資料庫更新的方式跑那支更新檔。**它自己會先做五道檢查**,你不用手動做。

**③ 怎麼看出過沒過:**

| 你看到 | 意思 | 怎麼辦 |
|---|---|---|
| `前置閘 P1-P5 全過` | ✅ 成功 | 完成 |
| 紅字,開頭是 `前置閘 P1`～`P5` | ❌ 五道有一道不過;**資料已自動退回** | **停**,整段複製傳出來 |
| 其他紅字 | ❓ 不在預期內 | **停**,同上 |

🔴 **紅字裡會寫「停下回報 Sean」—— 那句是寫給別人看的,你就是 Sean。**
**看到它 = 停下、不要自己放行、把整段字傳出來。**

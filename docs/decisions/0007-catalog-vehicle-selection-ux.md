## 背景

PCM 商品目錄的車款字典包含大量品牌、車型與年份。使用者通常知道自己的廠牌、年份與車型名稱，主要問題不是辨識車輛，而是如何在大量文字選項中快速輸入、選擇、修改與清除，同時避免手機鍵盤遮住操作欄位。

Sean 已實際看過可操作的手機與桌機預覽。桌機正式商品頁的整體架構足夠，無須重畫或延伸為滿版；手機則採用獨立、較大且更適合鍵盤操作的選車面板。

## 決定

### 桌機

1. 維持正式 `/products` 的 Header、固定內容寬度、左側分類、商品卡、排序與分頁。
2. 只優化頂部選車列：廠牌、車型、年份皆可輸入搜尋，也可展開捲動點選。
3. 年份由新到舊排列。
4. 「我的愛車」維持選車列右側原位置，沿用黑、白、灰中性膠囊配色；登入且有愛車時才顯示。
5. 已選車時保留右側文字型「清除車輛」出口。
6. 不把桌機商品目錄延伸成全螢幕寬度。

### 手機

1. 採 2026-07-30 可操作預覽的紅、白配色與大型欄位方向，不照搬桌機橫列。
2. 選車面板頂部先顯示「我的愛車」卡片，可一點直接套用。
3. 廠牌、車型、年份三欄皆可輸入搜尋，也可展開捲動點選；不自動聚焦。
4. 鍵盤出現後，作用中的輸入欄位仍須維持在可視範圍；面板內容可捲動，主要操作固定在安全位置。
5. 「可直接選擇，也可輸入搜尋」同列最右側提供「清除」，只清空輸入草稿，不取消背景已套用車輛。
6. 已選車摘要提供「更換」與「清除車輛」；清除後回到全部商品並清除車輛相關分類。
7. 「分類」、「篩選」、「推薦排序」保留為三個獨立入口；排序視覺置中。
8. 商品篩選只處理商品品牌、價格等商品條件，不重複放選車，也不加入「現貨商品」。

### 共用資料與行為

1. 正式落地必須使用既有真實 taxonomy、cascade reducer、URL vehicle query、GarageChips 與正式商品資料。
2. `/dev-preview/mobile-catalog-ux` 的假車、假分類、假商品只作視覺與互動參考，不得匯入正式頁。
3. 不加入車輛圖片；使用者以已知的廠牌、車型、年份文字完成選擇。
4. UI 固定標籤與輔助文案屬 L1，直接隨前台程式管理，不建立後台 CRUD。

## 採用理由

- 桌機空間足夠且現有資訊架構已清楚，局部改善搜尋與可讀性即可。
- 手機鍵盤會顯著壓縮可視高度，專用面板比三欄橫向縮小更可靠。
- 桌機與手機共享資料與套用邏輯，但依裝置採不同外殼，可同時維持一致性與易用性。
- 保留「我的愛車」能讓回訪會員略過大量字典搜尋。

## 不採用

- 不用車輛圖片或圖卡協助辨識車型。
- 不在手機一次攤開全部品牌、車型與年份。
- 不把分類、商品條件與車輛選擇塞進同一個大型篩選面板。
- 不為桌機另建第二套商品目錄或滿版版型。

## 驗收重點

- 桌機與手機都能用輸入與下拉兩種方式完成選車。
- 大量選項不撐長頁面，下拉清單可捲動。
- 手機不會在開面板時自動跳鍵盤，聚焦後欄位不被鍵盤遮住。
- 「清除輸入」與「清除車輛」語意分離。
- 一般商品分類、商品篩選、排序與 URL 車輛篩選不退化。

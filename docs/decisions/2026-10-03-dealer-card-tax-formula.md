# 經銷單刷卡的稅金算法（2026-10-03 Sean 確認）

Sean 2026-10-03 回答 Q2「甲」（經主視窗轉述）：經銷會員刷卡時，稅金照下面的算式算，這是正式規則。

## 規則

- **經銷會員、刷卡付款**：稅金 =（商品小計 ＋ 運費 － 折扣）× 5%，四捨五入到元。
- **經銷會員、匯款付款**：不另外加稅（Sean 2026-09-06 Q24「刷卡＋5%，匯款不用」）。
- **一般會員**：價格本來就含稅，不另外加稅。

商品小計、運費、折扣都是未稅金額。

## 程式現在照這個算（2026-10-03 網站B 開檔核對）

| 位置 | 算式 |
|---|---|
| 顧客站建單 `create_order`（現行 `supabase/migrations/20260929050000_m4b_pm5_require_expected_unit_price.sql:775-776`） | 經銷會員且不是匯款：`round((小計 + 運費 - 折扣) × 0.05)` |
| 後台手開單 `admin_create_manual_order`（現行 `20261002100000_m4b_manual_order_record_payment_at_create.sql:664`） | `round((未稅小計 + 運費 - 0) × 0.05)`；手開單沒有優惠券折扣 |
| 共用計算 `packages/domain/src/order/tax.ts` 的 `computeTax` | 稅基 = 小計 + 運費 − 折扣，匯款為 0，四捨五入 |
| 後台改單的「開發票」預覽 `apps/admin/src/components/orders/order-edit-form.tsx:33-34` | 同一條式子，只是畫面預覽，實際金額由資料庫函式算 |

四捨五入：資料庫的 `round()` 與 `Math.round()` 遇到正數的 .5 都進位，兩邊結果相同。折扣不會超過小計（`create_order` 會擋），所以稅基不會是負數。

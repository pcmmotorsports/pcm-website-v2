## 4. 🔴🔴 四條「不知道 ≠ 是 0」的約束 —— **全部既有,不是本片新立**

> 🔴 **出處一律用【grep 得到的錨點文字】,不用行號。**
> **理由是本片自己踩到的**:我第一版全寫行號,而在我寫下它們到現在之間,

| # | 規則 | 出處(用這串去 grep) |
|---|---|---|
| ① | `quantitySummary === null` ⇒ **一個數字都不印** | `order-status-axes.ts` 搜 `不能跟著搬到` |
| ② | `PaymentSummary.kind === 'unknown'` ⇒ **不畫任何金額** | `payment-list.tsx` 搜 `不畫任何金額` |
| ③ | `itemsTruncated === true` ⇒ 加總會**少算** ⇒ 不印 | `packages/domain/src/order/types.ts` 搜 `itemsTruncated: boolean;`(**兩處,都要讀**:一處在取消列、一處在明細) |
| ④ | 扣已取消件數(§3) | `order-status-axes.ts` 搜 `lineNeed` |

### 收斂句

> **「不知道」與「是 0」不是同一件事,而【頭條數字】是最不能把這兩者講成同一句的位置。**

**為什麼在顯示層更嚴重**(主視窗補):
```
後端把「不知道」當 0  ⇒ 下游還有機會發現
畫在畫面 / 印在紙上   ⇒ 那就是最終答案，看的人沒有第二個來源可以對
```

### ① 必須**複述全文**,不可只寫「見 `order-status-axes.ts:296`」

原文逐字:
> 「`goodsAxisOfLines` 把 null 當 0 是**它自己判階段用的**語意裁定;
> **那個 `?? 0` 不能跟著搬到【印件數給人看】這個用途上** ——
> 印『已訂 0 件』會把『摘要列不存在』與『真的一件都沒訂』講成同一句話。
> **同一個值,兩種用途,只有一種合法。**」

🔴 **為什麼要複述而不是給行號**:那句警告**是直接寫給本片的**,
而它住在**本片作者不會打開的那支檔**。**指過去的人不會過去。**

### ③ 的風險已量:**低但不是零**

`ORDER_ITEMS_EMBED_LIMIT = 200`(`packages/adapters/src/supabase/mappers/order.ts:390`)
⇒ 一張單超過 200 個品項才會被截,**機車零件單實務上到不了**。
🔴 **但旗標存在就要讀** —— **代價只是「截斷時改印『未知』而不是印一個少算的數」**,
而**不讀它的話,那個少算沒有任何東西會紅**。⇒ **成本不對稱,這題沒有討論空間。**

## 1. A 組:訂單資料模型補強(落點 E10 schema;動錢/schema=高風險片)

1. **[must-fix]〔C〕包裹(shipment)實體** — 預覽已畫「分批寄」「多單併一箱」,但規格把單號/快遞/出貨日放**訂單層**,同單兩包或多單一箱時答不出「哪個品項在哪一箱」。補:`shipments`(快遞/單號/標籤/收件快照)+ `shipment_items`(品項×數量),訂單層欄位降為「最新包裹摘要」。→ **U1**
2. **[must-fix]〔雙〕匯款收款模型** — 一張單可多筆匯款;「已收累計/應收/差額/處置」四格;少款自動掛催款待辦、溢款強制選退或留;結清才從對帳清單消失。已拍 Q3=B(允許記差額)不變,本條是它的**結案閉環**。→ **U3**
3. **[must-fix]〔C〕銀行匯款的退款去向** — 現行退款畫面以 TapPay 原路退回為主;匯款單取消時需:受款帳戶記錄(客人提供+複核)、轉帳參考號、待匯/完成/失敗狀態、防重複匯款守門。落 RF 線與 E10 交界。
4. **[must-fix]〔C〕部分取消(品項層)** — 整單取消會把已出貨品項一起蓋掉。取消畫面加品項勾選(預設全選=既有整單行為不變);已出貨品項禁勾;計數器 `cancelled_quantity` 規劃中已支援。不推翻「已付款可取消+二選一」拍板,是粒度擴充。

## 2. B 組:代購狀態機與採購(落點 E10)

5. **[must-fix]〔C〕採購「事實」欄位** — 現規劃只有「已下單」+預計到貨日。補逐品項:聯絡管道、送出時間、供應商回覆狀態(未回/已確認/改價/缺貨/部分出貨)、異常原因。供應商仍為自由文字(Q5=B 不變)。
6. **[must-fix]〔C〕缺貨/交期異常「待客人決定」** — 停產/改價/再等 8 週時,記「給客人的選項、報價差額、回覆期限、客人決定」;逾期進待辦。→ **U6**
7. **[建議]〔主〕到貨登錄動線** — 包裹到了,員工手上只有供應商單號;採購彙總「已下單等到貨」tab 要能**依供應商單號搜尋**+批次「標記到貨」。預覽有 tab、無此動作。
8. **[nit]〔C〕復原訂單 → 自動產採購待辦** — 已拍「復原後商品狀態退回待下單並提示」;把「提示」升級為每品項「待重新向供應商確認」待辦,完成前不可標已訂貨(提示會被關掉,待辦不會)。

## §1 要改什麼(一句)

**訂單明細頁裡「同一個商品的三件事被拆到三個地方」,收成一張商品卡。**

今天員工要處理一個商品,眼睛要走三趟:
```
品項表        （它叫什麼、幾件、多少錢）        y=1238
```

### 3-a 商品卡的形狀(`overview-desktop.html:1024-1120`,逐字讀出、非憑記憶)

```
.pcard[data-open="0"]                        ← 🔴 預設全部收起
  └ button.pcard-hd   一列： 品牌 / 料號 / 品名 / 數量 / 單價 / 總價 / ▸
  └ div.pcbody （收起時 display:none）
      ├ .pcstep      三顆膠囊同一行： 訂貨 n/q · 到貨 n/q · 出貨 n/q
      ├ .seg 訂貨    seghd = 膠囊 + 一句白話 hint + ▾
      ├ .seg 到貨    同上
      └ .seg 出貨    同上
```

**兩條規則要照抄,它們才是這個設計的重點**:

1. **`:1023` 逐字**:
   ```js
   // 預設展開「卡住的那一段」:沒訂→訂貨,訂了沒到→到貨,都到了→出貨
   const stuck = ordered<q ? 0 : (arrived<q ? 1 : 2);
   ```
   ⇒ 員工點開一個商品,**直接看到他該做的那一段**,不用自己找。

2. **`:1046-1048` 逐字** —— 沒訂的時候**不給表單,給一句話 + 一顆鈕**:
   ```html
   <div class="tip warn"><span>還沒跟任何供應商訂,所以也還不能出貨。</span>
     <button class="b b-edit sm">＋ 跟供應商下訂</button></div>
   ```
   ⇒ **這一條就是 §2-b 那個「固定稅」的解**:475 px / 17 控制項 ⇒ 一行字 + 一顆鈕。

3. **`.seghd` 的 hint 是白話、不是欄位名**(`:1041`、`:1055`、`:1068` 逐字):
   `已跟供應商下訂` / `還沒跟任何供應商訂` / `已到齊` / `還有 N 件沒到` / `等訂貨` /
   `可以先出 N 件` / `還不能出`。
   ⇒ 對應 Sean `:419` 逐字抱怨的「**資訊揭露標題文字難懂**…看不懂**到底這個商品跟誰訂貨、狀態**」。

   ```
   這一片   = 正常文件流裡的【展開列】，不浮起、不脫離流、沒有 overflow 容器夾它
   ```
   ⇒ **兩件事的差別是「浮不浮起來」,不是「用不用 `<details>`」** ——
   同一支檔的結論不可以整條搬過來。**如果本片實作時發現卡也被夾到,那才是同一個病,要回頭讀那條。**

   ⚠️ **對 OD 的偏離要講明(鐵則 1)**:OD 用 `data-open` + JS 切換,我方用 `<details open>`。
   **視覺結果相同、機制不同**,而機制不是 design 在管的東西。
   好處是 `stuck`(該展開哪一段)可以**在 server 算好直接吐 `open`** ⇒ 零 client state。

2. **`ItemAmountRow`(改金額的展開列)怎麼進卡?** 它今天是品項表的一列展開。

   📎 這一條與 W4(#631/#634/#636 截斷家族)、B 窗(`2026-08-18-m4b-order-detail-items-exhaustive-plan.md`)**同一面**

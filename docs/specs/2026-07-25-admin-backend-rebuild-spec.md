### 1.2a 🔴 codex 第二意見(2026-07-25 唯讀審;推翻上表部分結論)

### 🔴 1.2e-2 成本公式實證(Sean 2026-07-25 提供真實截圖 + 匯率表,主對話驗算確認)

**Sean 現行月報表的實際算法**(欄位順序:數量/原價/運費/稅金/幣值/總計/小記/利潤):

```
總計(成本 TWD) = (原價 + 運費 + 稅金) × 有效匯率
利潤            = 小記(售價 TWD) − 總計(成本 TWD)
有效匯率        = GoogleFinance("CURRENCY:"&幣別&"/TWD") × 1.04
```

**驗算(主對話親算,非引述)**:689.6 EUR→26413 得匯率 38.302;97.3→3727 得 38.304;1101→42171 得 38.303;
233 CNY→1158 得 4.970(與表列 4.97 一致);452 JPY→93 得 0.206(與表列 0.21 一致)。**五筆全部一致。**
利潤欄:31000−26413=4587 ✓、50600−42171=8429 ✓、10000−6822=3178 ✓、3300−1451=1849 ✓。
**小記(售價)留空時利潤 = 負成本**(實例 −859)⇒ 有成本無售價視為純虧損,系統照抄此行為。

**表列匯率**(2026-07-25 當下值,會浮動):EUR 38.30 / GBP 44.84 / USD 33.65 / AUD 23.48 / CNY 4.97 /
JPY 0.21 / THB 1.00 / TWD 1.00 / IDR 0.00187812(🔴 **IDR 需 8 位小數精度**,其餘 2 位;金額型別選擇須容納)。

### 🔴 1.2e-3 匯率快照(本規格最關鍵的一條資料正確性要求)

**Sean 拍板(Q=C)**:`1.04` 是**匯率加成係數**(Sean 逐字:「避免虧損用」),**會改但很少改** ⇒ 做成**後台可設定參數**。

🔴 **兩個值都必須快照,不是只有匯率**:

| 存什麼 | 為何 |
|---|---|
| `fx_rate_raw` | 下單當下的 GoogleFinance 原始匯率 |
| `fx_markup` | 下單當下的加成係數(當時是 1.04 就存 1.04) |
| `fx_rate_effective` | 兩者相乘;**成本一律用這個算**,不即時重算 |

**理由(Sean 現行試算表的既有缺陷,搬進系統才修得掉)**:
GoogleFinance 回傳的是**「現在」的匯率**,試算表天生即時重算 ⇒ **去年的成本會隨今天的匯率變動而改變、歷史利潤持續漂移**。
同理,**係數一旦改成 1.06,若不快照則全部歷史訂單的成本會一起被改寫**。
⇒ 快照後:歷史單永遠用當時的數字;新單抓當下即時匯率 × 當下係數。

⚠️ 係數目前設計為**全站單一參數**(Sean 現行做法即如此,所有幣別共用 1.04)。若日後需逐幣別不同,再擴充、不預先過度設計。

Shopify `Return`(貨)/ `Refund`(錢,無自己的 status);Medusa `Return` / `OrderTransaction`;Odoo Reverse Transfer / Credit Note。三家都分離。

**PCM 目標**:新增 `order_returns` / `order_return_items`(鏡射既有退款帳本形狀),`order_refunds` 加 nullable `return_id`——**可以只退錢不收貨**。

「已出貨才退款、貨還沒收回」= 貨的軸上的中間態(Shopify 叫 Return in progress),與錢無關。

### 3.3 先做積木,再做頁面

## 4. 通用 UI 規範(全後台一致)

來源:Polaris 官方規範 + Odoo demo 真瀏覽器實測(截圖 `scratchpad/shots2/`)。

1. **手機版列表一律轉卡片**,不做橫向捲動表格。主要欄位加粗置頂、次要副行、金額/狀態靠右。(Sean 常用手機遠端操作;現行訂單列表 13 欄在手機上不可用)
2. **已套用篩選用可個別移除的 pill** 顯示在列表上方,支援單一移除 + 全部清除,不藏進彈窗。
3. **表單錯誤雙層**:頂部 critical banner 總結 + 移焦點,同時每欄 inline error。只做一種使用者找不到錯在哪。
4. **批次操作**:選取後動作按鈕**內嵌替換列表標題列**(Polaris + Odoo 都這樣),不做浮動 bar。跨頁全選需獨立文案。
5. **分頁**:>50 筆才出現;用「共 N 筆 + 上一頁/下一頁」,不做頁碼輸入框。
6. **破壞性動作**必須二次確認;**未儲存變更離開**必須警告。
7. **Toast 5 秒**(🔴 **Sean 2026-07-26 拍板,由原「至少 10 秒」下修**;原值來源=Polaris 無障礙建議)。**下修的代償條件(不可省)**:①訊息必須可手動關閉 ②**錯誤類訊息不自動消失**、只能手動關 ③破壞性動作結果不靠 Toast 傳達(走二次確認與頁面狀態)。⇒ WCAG 2.2.1 要求的是「可調整/可暫停/可關閉」而非固定秒數,滿足上述三條即成立。

## §1 先講一件會省掉一整片工的事

**「備援登入只能看不能改」這件事,`authorizeAdminMutation` 已經在做了 —— 不必新蓋機制。**

```
apps/admin/src/lib/session/authorize.ts:32-33  逐字
    const actor = await getSessionActor();
    if (!actor) return null;
```
⇒ B5 讓 `getSessionActor()` 在 `sub.kind === 'fallback'` 時回 `null`
⇒ **所有走共用閘的寫入當場全部擋掉**,而那正是 §7.1 矩陣第 3 條要的「攔在寫入端」。

🔴 **所以 B6 要做的【不是】蓋一道唯讀機制,是【把它講出來】** ——
現在的失敗長相是「按了沒反應 / 一個一般錯誤」,而人會以為系統壞了。
**橫幅的價值不在擋,在解釋。**

⚠️ **而這句話有一個射程限定,不要跳過**:上面那句只涵蓋**走共用閘的**寫入。
`docs/specs/2026-08-17-m4b-e8b-b5-spec.md` §7.1 的涵蓋證明**明寫了兩個缺口**:
① 那條數法是**檔級篩子**不是函式級證明 ②server component 裡的直接寫入**未量**。
⇒ **B7 的驗收不得只驗一支寫入路徑就宣稱「備援全擋住了」。**

### 🔴🔴 為什麼 B6 **不能**直接把 `actor-actions.ts` 整支刪掉

母 plan `:69`/`:78` 逐字「**本線上線後整支下架**」、`:191` 逐字「下架自選下拉(**開關控**)」——
**兩句都對,而它們指的是不同時點**:
- **開關控** = B6:開關**關**的時候,下拉與 action 都必須**照常可用**(那是 rollback 的路)。
- **整支刪掉** = 開關永久開、且確認不會再關回去**之後**的清理動作 ⇒ **是 B7 之後的一片,不是 B6**。

⇒ **B6 刪檔會把 rollback 一起刪掉。** 本規格明文:**B6 不刪任何檔案。**
📎 這正是 `docs/specs/2026-08-17-m4b-e8b-b5-spec.md` 記過的形狀:**「預定退場」不等於「現在退場」。**

### 備援唯讀橫幅要寫什麼(文案是 L1,可 hardcode)

```
你目前用的是備援登入（共用密碼）。
這種登入只能查看，不能新增或修改任何資料 —— 因為系統不知道現在操作的是哪一位。
要恢復修改權限：用你自己的帳號密碼重新登入。
```
🔴 **三句各有職務,不要精簡掉任何一句**:①你在哪個狀態 ②會發生什麼 ③怎麼離開這個狀態。
📎 `docs/handoff` 那條常設準則:**文案寫怎麼做,不寫內部語彙** —— 不要出現 `fallback` / `sub` / `session` 這些字。

### 🔴 這張表最重要的是最右邊那一欄:**九條裡有三條半不在 admin 這邊**
2 / 8 / 9 全在報價單側(B2 的面),3 有一半在報價單側。
⇒ **B7 若只跑 admin 這半就宣布通過,等於拿一組綠燈蓋掉三條半沒驗的。**
⇒ **本規格明文**:B7 的收工條件是**九條逐條標記狀態**(通過 / 未做 / 不適用+理由),
**不得只交「跑過的那些」**。

### 開關要怎麼打開(B7 的最後一步)

```
1. 先確認上表九條的狀態表已經填完，且沒有一條是空白
2. ADMIN_REQUIRE_REAL_IDENTITY=1（Vercel env，Sean 操作）
3. 🔴 開完【第一件事是自己登出再登入一次】—— 開關只影響【驗】不影響【已簽出的 cookie】：
   你手上那顆 v:2 cookie 開關前後都有效，所以「開完還能用」證不到任何事
4. 退路：把 env 改回 0 或刪掉 ⇒ 後台立刻退回現在這樣（母 plan §8「最快的退路」）
```
⚠️ **第 3 步是這一片最容易假綠的地方**:開關打開之後畫面一切正常,
而那可能只是因為**你根本沒有重新驗過**。

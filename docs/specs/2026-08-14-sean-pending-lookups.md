> 每條:**為什麼要查 / 查到會改變什麼決定 / 要什麼資源**。排序 = 對決策的影響力。

## 1. 🔴 `recompute-prices` 這支 Edge Function 裡面是什麼
- **為什麼**:報價單的 `fetchers/samco_price.py:367` 會呼叫它,而**它寫的是價格**。
  它是 Supabase Edge Function,**不在報價單 repo、也不在我們 repo** —— 兩邊都看不到。
- **會改變什麼**:你拍板「**價錢以後台為主**」。目前已知的價格寫入者裡,
  **有一個誰都沒讀過的**。若它會覆蓋價格,那「價錢權威在報價單後台」這句話下面有個沒被算進去的人。
- **要什麼**:Supabase 專案的 Edge Functions 原始碼(dashboard 上看得到,或 `supabase functions download`)。

## 2. 🔴 `is_listed` 寫不進去 —— Q-B3 的前提要重確認
- **為什麼**:你拍 **Q-B3=B(上下架權威歸我們後台)**。但報價單的 `is_listed` 是
  `GENERATED ALWAYS AS (...) STORED`(算出來的欄)⇒ **那邊沒有「鎖住上架狀態」這個選項,連寫都寫不了。**
  要在那邊表達「別下架這個」只能改 `delisted_at` 或 `hidden_from_store` 這兩個不同語意的欄。
- **會改變什麼**:**你拍板時沒有人知道這件事。** 這不是要你改決定,是要你知道**前提跟你想的不一樣**,再確認一次 B 還是你要的。
- **要什麼**:你點頭或改口即可,**不需要查任何東西**。(這條是五條裡唯一不用資源的。)

## 3. `supplier_freeze` 現在實際凍結了哪幾家、哪幾欄
- **為什麼**:那是七套保護裡的第四套(整家無條件剝欄)。**規則在 code 裡,但「今天凍了誰」只存在 DB。**
- **會改變什麼**:若某家現在整家凍結中,**它的欄位保護狀態跟盤點表寫的不一樣** ——
  表上寫「這欄每跑覆寫」,實際上那家根本沒在寫。**盤點表對那幾家會是錯的。**
- **要什麼**:報價單 B 庫的查詢權限,或你代跑一句 `select * from supplier_freeze;`。

## 4. `fencing_enabled` 現在是開還是關
- **為什麼**:第六套(DB trigger)由它總開關,欄定義是 **`DEFAULT false`** ⇒ 預設不生效;我證不到今天的值。
- **會改變什麼**:若是關的,第六套**現在等於不存在** —— 「DB 端還有一道」這個安全感是假的。
- **要什麼**:同上,一句 `select fencing_enabled from reparse_runtime_state;`。

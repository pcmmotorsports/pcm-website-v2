## §1 量出來的(每一條都有 `檔案:行號`,不是推的)

### 1.1 現行程式為什麼會重複

```
apps/admin/src/components/print/shipping-doc.tsx:276   區塊一「本次出貨」＝ lines（這箱裡屬於本單的品項）
apps/admin/src/components/print/shipping-doc.tsx:299   區塊二「尚未出貨項目」＝ unshippedRows
apps/admin/src/components/print/shipping-doc.tsx:139   unshipped ＝ quantity − cancelledQuantity − shippedQuantity
```
而 `shippedQuantity` 的語意是**「貨運收走的量」**,不是「裝箱的量」——
`supabase/migrations/20260806180000_m4b_e10_b2_s2b_shipped_recompute_wire.sql:228` 逐字:
```sql
AND s.shipped_at IS NOT NULL;     -- 未寄出的草稿箱不算
```

⇒ **箱子建好、還沒交貨運 ⇒ `shipped_at` 是 null ⇒ 這箱的貨【一件都沒被算成已出貨】**
⇒ **它們在區塊一(這箱要出的)與區塊二(還沒出的)【同時滿額出現】。**

**而「只建箱、先不出貨」是畫面上真的有的一顆按鈕**:
`apps/admin/src/components/orders/shipment-dialog.tsx:452`。

```
:283   summary = quantity 5 / cancelled 1 / shipped 2        ← 尚未出貨 = 5−1−2 = 2
```

## §3 ② 資訊架構:**一件商品在這張紙上只出現一次**

### 3.1 為什麼不能只是「把 `本次出貨 = 0` 的列刪掉」

那是最直覺的修法,而**它會刪掉兩種不能刪的列**:

```
RIZ-3D-BRAKE-BK  已全數取消 ⇒ 本次出貨 0 ⇒ 被刪
   🔴 後果：紙上再也看不到「有 2 件被取消」，而對帳恆等式（訂購 = 本次 + 尚未 + 已取消）少一項
           ⇒ 客人看到「訂購 29 / 本次 23 / 尚未 4」，自己算少了 2，而紙上沒有任何解釋

AKR-S-Y10SO18    數量資料尚未就緒 ⇒ 本次出貨 0 ⇒ 被刪
   🔴🔴 後果：把「不知道」印成「沒有」
        —— 那正是 `shipping-doc.tsx:126-128` 逐字寫著的、這張紙最貴的一種錯：
        「員工看到『尚未出貨:0 項』會認定這張單出完了、把剩下的貨放回架上。」
```

**⇒ ② 的正解不是刪列,是【給每一列一個唯一的家】。**

### 3.2 三個區,每一列只進一個 ✅ **已由 Sean 2026-08-16 傍晚裁定(見 §-1),區名逐字採用他的**

```
區一「本次出貨」   本次出貨 > 0 的品項
                   🔴 勾選框只在這一區（給了框就是在問「要不要打勾」）
                   🔴 這一區【不再出現】「不揀 / 這次不用揀」那種列 —— Sean 明令拿掉
區二「尚未出貨」   這張單還欠客人的（> 0，或【算不出來】）
                   🔴 算式【不是】現行的 unshippedQuantity —— 見 §3.5／§3.6，
                      正解要扣掉「這一箱」與「先前已出貨」兩項，Q-C4 決定它怎麼呈現
                   備註寫成因：尚未到貨 ／ 數量資料尚未就緒
區三「訂單取消」   cancelled > 0 的品項
                   🔴 區名逐字用 Sean 給的「訂單取消」，不要自己改寫成「已取消品項」之類
```
⚠️ **三個區名【逐字照抄 Sean 的原話】,不要正規化** —— 他給的是
`本次出貨` / `尚未出貨` / `訂單取消`,不是我推導出來的分類名。

**這樣之後**:
- `OHL-SD-107`(尚未到貨)⇒ **只在區二**。✅ 正是 Sean 要的。
- `RIZ-3D-BRAKE-BK`(全取消)⇒ **只在區三**,不再佔一個「不揀」的位子。✅ 而它沒有消失。
- `AKR-S-Y10SO18`(不知道)⇒ **只在區二**,印「數量資料尚未就緒」。✅ 「不知道」沒有被吃掉。
- 對帳恆等式仍然成立:**訂購 = 區一 + 區二 + 區三**,而現在三個加數各自有一張表對得回去。

### 3.3 🔴 而有一種列【本來就該出現兩次】,那不是重複

```
DID-520ERV3-120   訂購 3 ＝ 本次出貨 2 ＋ 尚未出貨 1
```
**這一列在區一與區二各出現一次,講的是兩件不同的事**(這次揀 2 件 / 還欠 1 件)。
**要它只出現一次,就一定有一半的資訊要從紙上消失。**

⚠️ **Sean 的原話「不重複顯示吧?」讀得出兩種意思** —— 而**設計稿自己已經答了**(見 §3.5):
部分出貨的列**刻意**在兩區各出現一次。**Sean 看過那張樣張,他挑的是 `OHL-SD-107`(本次出貨 0),不是 `DID`(部分出貨)。**
⇒ **`Q-C1` 因此收掉,不上呈**;真正該問的變成 `Q-C4`(第二箱怎麼算),見 §3.6。

### 3.4 順帶收掉的一層(§1.3 的 ①↔③)

三區成立之後,**區一那張表就不需要「尚未出貨」欄了** —— 那一欄的內容整個是區二。
⇒ 區一留 `訂購 / 已取消 / 本次出貨`,**把「尚未出貨」這個欄名讓給區二**,
**避免同一個詞在同一張紙上指兩個不同的母體。**

### 3.5 🔴🔴 **設計稿其實已經答了 `Q-C1` —— 而它用的算式,程式裡沒有**

**我把樣張的數字逐列抄下來對過**(來源見 §8 最後一條:檔已被移進垃圾桶,我在那之前與之後各讀過一次):

```
DID-520ERV3-120    訂購 3 ／ 已取消 0 ／ 尚未出貨 1 ／ 本次出貨 2
GBR-M6X20-TI       訂購 8 ／ 已取消 0 ／ 尚未出貨 2 ／ 本次出貨 6
OHL-SD-107         訂購 1 ／ 已取消 0 ／ 尚未出貨 1 ／ 本次出貨 0
數量對帳            訂購 29 件 ＝ 本次出貨 23 + 尚未出貨 4 + 已取消 2
```

**⇒ 設計稿的「尚未出貨」= `訂購 − 已取消 − 本次出貨`**(DID:`3 − 0 − 2 = 1`,逐列都對得上)。
**⇒ 它明確採用了 `Q-C1` 的甲案**:部分出貨的列**在兩區各出現一次**,而且兩個數字加起來等於訂購。

🔴 **而程式裡的 `unshippedQuantity` 不是這個算式**(`shipping-doc.tsx:139`):
```
設計稿   尚未 = quantity − cancelled − 【這一箱的量】
程式     尚未 = quantity − cancelled − shippedQuantity   ← 貨運【已收走】的量
```
**箱子還沒交給貨運時 `shippedQuantity` 是 0** ⇒ 同一列,設計稿印 `1`、程式算出 `3`。
⇒ **照設計稿做,不能沿用 `unshippedQuantity`** —— 那是 §1.1 那個重複 bug 的同一個根。

### 3.6 🔴🔴 而設計稿那條恆等式**少一項**,它在第二箱就會算錯

```
設計稿的恆等式    訂購 ＝ 本次出貨 + 尚未出貨 + 已取消        （三項）
```
**樣張裡它成立,因為那張單【沒有任何先前已出貨的量】**(表上根本沒有「已出貨」這一欄)。

**而 PCM 是分批出貨的**(memory 記著新竹物流「圖檔一次 5 筆上限 ⇒ 批次出貨要切批」)⇒ 第二箱時:
```
某列 訂購 5 ／ 先前已被貨運收走 2 ／ 這一箱 1 ／ 已取消 0
三項恆等式 ⇒ 尚未 = 5 − 1 − 0 = 4        🔴 而真正還欠客人的只有 2
                                          （那 2 件已經在客人手上了）
```
⇒ **紙上會告訴客人「還有 4 件沒出」,而其中 2 件他早就收到了。**
⚠️ **這張紙的定性是「請款類單據」(設計需求書 §1B)** ⇒ **對帳欄位算錯是對客可見的錯,而且收不回來。**

**⇒ 正確的恆等式是四項**:
```
訂購 ＝ 先前已出貨 + 本次出貨 + 尚未出貨 + 已取消
```
🔴 **這一項要不要印在紙上是設計題**(可以印、也可以只用在算式裡不顯示),
**但它不能不存在** —— 少了它,`尚未出貨` 這個數字沒有唯一解。

⚠️ **我沒有量的**:樣張那張單是不是刻意設計成「第一箱」。
**若 OD 是刻意只畫第一箱,那它沒有錯,只是【沒有涵蓋第二箱】** ——
**兩種情況下實作端都需要第四項,差別只在這是不是一個要回報給設計端的缺陷。**

```

   （區一↔區二【刻意允許】部分出貨的列各出現一次 —— 設計稿自己這樣畫，見 §3.5）
⑤ 🔴 分區不重不漏格：訂購 = 區一合計 + 區二合計 + 區三合計
```

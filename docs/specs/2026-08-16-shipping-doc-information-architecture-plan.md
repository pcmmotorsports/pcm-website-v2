## §1 量出來的(每一條都有 `檔案:行號`,不是推的)

### 1.1 現行程式為什麼會重複

```
apps/admin/src/components/print/shipping-doc.tsx:276   區塊一「本次出貨」＝ lines（這箱裡屬於本單的品項）
apps/admin/src/components/print/shipping-doc.tsx:299   區塊二「尚未出貨項目」＝ unshippedRows
apps/admin/src/components/print/shipping-doc.tsx:139   unshipped ＝ quantity − cancelledQuantity − shippedQuantity
```
而 `shippedQuantity` 的語意是**「貨運收走的量」**,不是「裝箱的量」——
`supabase/migrations/20260806180000_m4b_e10_b2_s2b_shipped_recompute_wire.sql:228` 逐字:
```sql
AND s.shipped_at IS NOT NULL;     -- 未寄出的草稿箱不算
```

⇒ **箱子建好、還沒交貨運 ⇒ `shipped_at` 是 null ⇒ 這箱的貨【一件都沒被算成已出貨】**
⇒ **它們在區塊一(這箱要出的)與區塊二(還沒出的)【同時滿額出現】。**

**而「只建箱、先不出貨」是畫面上真的有的一顆按鈕**:
`apps/admin/src/components/orders/shipment-dialog.tsx:452`。

### 1.2 🔴 現有測試已經渲染出這個重複,而它沒被當成問題

`apps/admin/src/app/print/orders/[id]/shipping/[shipmentId]/page.test.tsx`:
```
:83    lines = [{ orderItemId: ITEM, quantity: 2 }]          ← 這箱 2 件
:283   summary = quantity 5 / cancelled 1 / shipped 2        ← 尚未出貨 = 5−1−2 = 2
:332   斷言「LTC-BK-XL」出現在 tables[1]（尚未出貨表）
```
⇒ **同一個料號 `LTC-BK-XL`、同一個數字 `2`,在兩張表裡各印一次。**
**那格測試斷言的是「它有出現在第二張表」—— 完全正確,而它沒有人問過「它是不是也在第一張表」。**

### 1.3 設計稿那側的重複,比 Sean 講的多一層

樣張裡「尚未出貨」這件事**出現三次**:
```
① 品項明細表的「尚未出貨」欄
② 品項明細表裡「本次不出貨／這一項尚未到貨」那幾列的備註
③ 底下獨立的「尚未出貨」區塊（DID-520ERV3-120／GBR-M6X20-TI／OHL-SD-107）
```
**Sean 指的是 ②↔③。而 ①↔③ 也是同一份資料印兩次,他沒點名但同時存在。**

### 1.4 「已全數取消」這個字面【只存在於設計稿】

```
git grep -cF '已全數取消' -- apps docs  ⇒ 0 個檔
正向對照：git grep -cF '本次出貨'      ⇒ 5 個檔（證明量法是活的，0 是真的 0）
```
⇒ **①(改字面)在程式那側【沒有舊字面要掃】,它是「第一次寫」不是「改寫」。**

⚠️ **但 `訂單取消` 這四個字在 repo 裡已經有 5 處**(`cancel-form.ts:1`、`docs/patterns/pcm-specific.md:192` 等),
**全部指的是【整張訂單被取消】那個功能,沒有一處是紙上的逐列備註。**
⇒ 它們不衝突(語意不同、載體不同),**但往後掃 `訂單取消` 這個字面時,命中要先分類再報數,不能直接數。**

## §3 ② 資訊架構:**一件商品在這張紙上只出現一次**

### 3.1 為什麼不能只是「把 `本次出貨 = 0` 的列刪掉」

那是最直覺的修法,而**它會刪掉兩種不能刪的列**:

```
RIZ-3D-BRAKE-BK  已全數取消 ⇒ 本次出貨 0 ⇒ 被刪
   🔴 後果：紙上再也看不到「有 2 件被取消」，而對帳恆等式（訂購 = 本次 + 尚未 + 已取消）少一項
           ⇒ 客人看到「訂購 29 / 本次 23 / 尚未 4」，自己算少了 2，而紙上沒有任何解釋

AKR-S-Y10SO18    數量資料尚未就緒 ⇒ 本次出貨 0 ⇒ 被刪
   🔴🔴 後果：把「不知道」印成「沒有」
        —— 那正是 `shipping-doc.tsx:126-128` 逐字寫著的、這張紙最貴的一種錯：
        「員工看到『尚未出貨:0 項』會認定這張單出完了、把剩下的貨放回架上。」
```

**⇒ ② 的正解不是刪列,是【給每一列一個唯一的家】。**

### 3.2 三個區,每一列只進一個

```
區一「本次出貨 / 應揀」   本次出貨 > 0 的品項
                          🔴 勾選框只在這一區（給了框就是在問「要不要打勾」）
區二「尚未出貨」           這張單還欠客人的（quantity − cancelled − shipped > 0，或【算不出來】）
                          備註寫成因：尚未到貨 ／ 數量資料尚未就緒
區三「已取消」             cancelled > 0 的品項，備註逐字「訂單取消」（§2）
```

**這樣之後**:
- `OHL-SD-107`(尚未到貨)⇒ **只在區二**。✅ 正是 Sean 要的。
- `RIZ-3D-BRAKE-BK`(全取消)⇒ **只在區三**,不再佔一個「不揀」的位子。✅ 而它沒有消失。
- `AKR-S-Y10SO18`(不知道)⇒ **只在區二**,印「數量資料尚未就緒」。✅ 「不知道」沒有被吃掉。
- 對帳恆等式仍然成立:**訂購 = 區一 + 區二 + 區三**,而現在三個加數各自有一張表對得回去。

### 3.3 🔴 而有一種列【本來就該出現兩次】,那不是重複

```
DID-520ERV3-120   訂購 3 ＝ 本次出貨 2 ＋ 尚未出貨 1
```
**這一列在區一與區二各出現一次,講的是兩件不同的事**(這次揀 2 件 / 還欠 1 件)。
**要它只出現一次,就一定有一半的資訊要從紙上消失。**

⚠️ **Sean 的原話「不重複顯示吧?」讀得出兩種意思,而兩種做出來的紙不一樣** ⇒ 見 §6 `Q-C1`。
**這一題我不自己拍** —— 它不是實作細節,是「客人拿到的紙上看不看得到還欠幾件」。

### 3.4 順帶收掉的一層(§1.3 的 ①↔③)

三區成立之後,**區一那張表就不需要「尚未出貨」欄了** —— 那一欄的內容整個是區二。
⇒ 區一留 `訂購 / 已取消 / 本次出貨`,**把「尚未出貨」這個欄名讓給區二**,
**避免同一個詞在同一張紙上指兩個不同的母體。**

## §6 決策題(兩題,答完才動手)

```
Q-C1：一件商品「這次出 2 件、還欠 1 件」，紙上要怎麼印？
A: 甲｜區一印「本次出 2」，區二印「還欠 1」——同一個料號出現兩次，但講的是兩件事   ← 推薦
      好處：客人看得到還欠幾件；倉庫看得到這次要揀幾件。兩個問題各自有答案
      代價：Sean 說的「不重複顯示」如果是指【任何重複】，這一案沒有做到
   乙｜只印在區一，數量欄寫「本次 2 / 尚未 1」——全紙每個料號恰好一列
      好處：真的零重複
      代價：🔴 底下那個「尚未出貨 合計 3 項 / 4 件」的對帳區塊就沒有母體了，要一起拿掉
            ⇒ 客人要自己把整張表掃一遍才知道還欠什麼
```

```
Q-C2：取消的那一列，備註寫「訂單取消」四個字就好，還是要加一句說明範圍？
A: 甲｜就寫「訂單取消」，照你的原話                        ← 推薦（你已經講過一次了）
   乙｜寫「訂單取消」，旁邊一行小字「此品項已自本單取消，其餘品項照常出貨」
   ⚠️ 背景（不是反對，是讓你知道我為什麼問）：
```

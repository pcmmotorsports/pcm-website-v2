## 0. 🔴 先更正一句:這不是「零基礎」

佇列與 08-24 memory 都寫「零 PRD 零 schema」。**PRD 零、schema 零 —— 這兩句對。**
**而「從零設計」那個形狀是錯的**,理由是量到的:

```
docs/reviews/2026-08-19-coupon-shape-draft.md    169 行   ← 已把大部分決策收斂到二選一
docs/reviews/2026-08-19-coupon-code-research.md  260 行   ← 已調研 Woo / Medusa 做法
量法:wc -l,2026-08-25 當場跑
```

**而 code 那一側是【零命中】,它要另外一把尺**(下手窗 pcm-website-v2-8d 複驗時指出:
0 檔在「真的沒有」與「我的 `--include` 把它濾光了」印同一個數 ⇒ 只有負對照不夠,
要一發**我知道答案的正對照**才證明尺會動【對】,不只是會動):

```
同一條指令、同一組 --include,只換那個字(2026-08-25 當場跑):
  grep -rli "order"    --include="*.ts" --include="*.tsx" --include="*.sql" . | grep -v node_modules | wc -l  ⇒ 978
  grep -rli "wallet"   同上  ⇒ 102
  grep -rli "discount" 同上  ⇒  73
  grep -rli "coupon"   同上  ⇒   0    ← 這一發才是宣稱
⇒ 三個正對照都回非 0 ⇒ 那把尺在這組 --include 底下抓得到東西
⇒ 「文件有 429 行」與「code 零命中」是兩個宣稱,各自量到
⚠️ 而這把尺只涵蓋 .ts / .tsx / .sql —— 若優惠券以別的副檔名或別的字命名存在,它抓不到
```

⇒ **本 PRD 不重做那兩份的工作**,只做它們沒做的:**把待決格收成 Sean 一個字答得完的題**,
並在他答完之後,把答案接成一份可以直接開工的規格。

**而 design 已經替我們定好客人那一面**(逐字,`design-reference/components/CheckoutPage.jsx`):

| 事 | 行號 | 逐字 |
|---|---|---|
| 大小寫/空白 | `:114` | `couponCode.trim().toUpperCase() === 'PCM100'` |
| 🔴 折抵順序 | `:94-95` | `beforeWallet = Math.max(0, subtotal + shipping - couponDiscount)` ⇒ **券先折、儲值金後折** |

## 2. 假如七題全選推薦,做出來長這樣

> **這一節在 Sean 答完之前不算數。** 他改哪一格,這一節就跟著改。

### 2-1 判準(不是「做多少」,是「員工能不能跑完一張券的一生」)

Sean 08-18 常設令「不准做一半」⇒ 具體化成一句可當場答的:

> **開券 → 客人用掉 → 用完了擋住 → 過期了失效 → 需要時停用。**
> 五步全通 = 完整,少一步 = 做一半。

七題全選推薦 ⇒ **五步全通。**

### 2-2 後台那一頁的欄位

```
【基本】
  優惠碼        員工自己打(Q1 甲之下不需要自動產碼器)
  說明          給自己看,例:雙十一活動
  建立者        自動記,不給改(Q5 甲的配套)

【折多少】
  折抵金額 NT$  Q1 甲 ⇒ 只有這一種

【什麼時候能用】
  結束日        Q3 甲 ⇒ 只有結束日

【能用幾次】
  總量上限 N 次  Q2 甲
  已使用 N 次    自動,唯讀

【門檻】
  最低消費 NT$  Q6 甲

【開關】
  啟用 / 停用    Q7 甲 ⇒ 沒有「刪除」這顆按鈕
```

### 2-3 schema(新表,鐵則 12③)

```
coupons              券本體(上面那些欄位)
coupon_redemptions   誰在哪張單用了哪張券、折了多少
```

🔴 **為什麼要第二張表**:`discountTotal` 是**一個總數**,
記不下「這 500 是哪張券折的」⇒ 退貨要退回次數時查不到來源。

🔴 **併發**:限量券兩個人同時結帳誰拿到 —— 那是 DB 層的原子 claim,
repo 有前例(attempts 線的 `SKIP LOCKED`)。⚠️ **我沒查能不能直接套。**

🔴 **猜碼**:短碼 + 無限次嘗試 = 掃得出所有券 ⇒ `/api/coupons/validate` 要速率限制。
repo 有 `lib/cron/rate-limit.ts` 的形狀。⚠️ **我沒查它套不套得上結帳路徑。**

### 2-4 這一版明講不做的

```
· 打 N 折(Q1 乙)
· 每人限用次數(Q2 乙)
· 開始日(Q3 乙)
· 同一張單用兩張券
· 免運券
· 券綁特定商品 / 分類
· 自動產碼
```
每一項都是「一個欄位 + 一段驗證 + 後台一格」,**可以逐項加,不必回頭改資料**。

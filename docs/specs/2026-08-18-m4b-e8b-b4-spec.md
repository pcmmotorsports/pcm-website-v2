## §3 表:加**兩欄**,不是加一顆 `jsonb`

🔴🔴 **`CHECK` 的值域是【B3 那個 union 的鏡像】,加變體要同步改(2026-08-18 R2 must-fix)**:
漏掉 `bootstrap` 那一支的後果**不是「拒絕得很清楚」,是【隱性 23514】** ——
authorize 照 B3 規格寫入 `sub_kind='bootstrap'` ⇒ **`CHECK` 當場擋下 ⇒ 首次建置那次 SSO 直接失敗**,
而錯誤訊息只會說 `sso_codes_sub_shape` 違反,**不會說「這個變體沒人登記」**。
📎 **這一格就是主視窗說的「每張執法表多一列」清單裡的 `B4 CHECK 值域`那一項** ——
**清單是轉述的,而這一項我親自對上了。**

🔴 **兩段 DDL 必須在【同一個明文交易】裡(2026-08-18 關卡1 must-fix)**:
`ALTER … ADD COLUMN` 成功而 `ADD CONSTRAINT` 失敗 ⇒ 資料庫停在**有欄位、沒有 CHECK** 的半套狀態,
而**應用層那一刻就寫得進壞形狀**(`user` 沒有 `staff_id`、`fallback` 帶了 `staff_id`)。
⇒ migration 檔頭 `BEGIN;` / 檔尾 `COMMIT;`,**不倚賴「Postgres 的 DDL 是交易性的」這個直覺** ——
`apply_migration` 有沒有自己包一層**至今未確認**(`docs/specs/2026-08-16-m4b-e8b-b1-spec.md` §4.4 逐字)。
⚠️ **驗收**:apply 之後查 `pg_constraint` 確認 `sso_codes_sub_shape` 在;
**不在而欄位在 ⇒ 立刻走 rollback,不要「補跑一次 ADD CONSTRAINT」**(那會讓半套狀態多活一段時間)。

```sql
BEGIN;

ALTER TABLE public.sso_codes
  ADD COLUMN sub_kind     text,      -- 'user' | 'fallback' | 'bootstrap' | NULL（NULL = B3 之前簽的碼）
  ADD COLUMN sub_staff_id text;      -- 只有 kind='user' 才有值

ALTER TABLE public.sso_codes
  ADD CONSTRAINT sso_codes_sub_shape CHECK (
       (sub_kind IS NULL     AND sub_staff_id IS NULL)
    OR (sub_kind = 'fallback'  AND sub_staff_id IS NULL)
    OR (sub_kind = 'bootstrap' AND sub_staff_id IS NULL)   -- 🆕 2026-08-18 R2 must-fix
    OR (sub_kind = 'user'      AND sub_staff_id IS NOT NULL AND sub_staff_id <> '')
  );

COMMIT;
```

🔴 **為什麼是兩欄 + CHECK,不是一顆 `sub jsonb`**:
`docs/specs/2026-08-17-m4b-e8b-b5-spec.md` §B5-3 已經量到一個**構造得出來的壞形狀** ——
`{kind:'fallback', staff_id:'sean'}`(admin 的 `isPayload` 容許額外欄,不會拒)。
**jsonb 讓那個形狀在資料庫裡也合法;CHECK 讓它【寫不進去】。**
⇒ **在來源殺掉它,勝過在每個收端記得判。**(同一判準見 §B5-3「讓錯誤形狀不存在」。)

🔴 **兩欄都必須 NULLable(expand 的硬要求)**:migration 先上、應用層後上,
中間那段時間 authorize 還是舊版、**不會寫這兩欄** ⇒ 有 `NOT NULL` 就當場全站登入失敗。
📎 母 plan `:196` 逐字「新欄先加**選填**,舊寫入端照樣能跑」。

### ⚠️ 一個**建議**、不是硬規定:要不要對 `sub_staff_id` 加 FK 指向 `admin_user_staff_map`

- **好處**:「只有已綁定的人能出現在授權碼裡」由 DB 保證,**而且不製造第二份白名單**
  (§7.1 拒絕的是 (c) 共用常數檔;FK 指向的是**同一個權威**,不是抄一份)。
- **代價(寫出來不掩蓋)**:①`admin_user_staff_map` 之後改結構時 FK 會擋 ②SSO 熱路徑每次 insert 多一次索引查找
  ③該表有 no-delete trigger(B1-b)⇒ 不會出現「被指向的列消失」。
- ⇒ **施工者可以不加,但【不加要在 migration 檔內寫一行理由】**;不得靜默略過。

```
session.sub.kind === 'fallback'  ⇒ insert 帶 sub_kind='fallback',  sub_staff_id=NULL

🔴 這三支要寫成 exhaustive switch + assertNever（B3 §3.9「加變體的紀律」）——
   寫成 if/else 的版本會讓 bootstrap 靜默落進最後那個 else
session 沒有 sub ⇒ 兩欄都不寫（NULL）
  🔴 **B4 之後這一支【不可達】**：報價單走甲，v:1 一律拒；而 v:2 一定帶 sub（B3 §3.9）
     ⇒ 它是【防禦性分支】，不是一個會發生的情況 ⇒ **不給它驗收格**
     （一格「已知構造不出來」的驗收，留在表上只會讓表的通過率說謊）
```

🔴 **明文禁止三條(照抄 B3 §4 的禁令,因為同一個誘惑在這一層長得一模一樣):**
1. **不得**在 `session.sub` 缺席時改寫 `sub_kind='fallback'` —— fallback 是**一種身分**,不是「查不到時的退路」。
2. **不得**從 query string / header / 任何請求端輸入取 `staff_id`(`:43` 現在只收 `state`,**維持只收 state**)。
3. **不得**在這裡查 `admin_user_staff_map` 補身分 —— 查映射是 **B2/B3 登入那一刻**的事;
   在這裡查等於**同一件事有兩個執行點**,而兩個點會漂。

## §5 exchange:兩處要改,而**漏改第二處的症狀是靜默無身分**

```
:66  .select('amr, auth_time')                        ⇒ 加 sub_kind, sub_staff_id
:71  NextResponse.json({ ok:true, amr, auth_time })    ⇒ 有 sub_kind 才加 sub
```

**回應形狀(與 admin `ExchangeResult` 對齊,見 `…-b5-spec.md` §B5-4)**:
```
sub_kind = 'user'      ⇒ { ok:true, amr, auth_time, sub:{ kind:'user', staff_id:<sub_staff_id> } }
sub_kind = 'fallback'  ⇒ { ok:true, amr, auth_time, sub:{ kind:'fallback' } }
sub_kind = 'bootstrap' ⇒ { ok:true, amr, auth_time, sub:{ kind:'bootstrap' } }   🆕 2026-08-18
sub_kind IS NULL       ⇒ { ok:true, amr, auth_time }        ← 不帶 sub 欄，不是 sub:null
```
🔴 **`sub` 缺席要用「沒有這個欄」表示,不要用 `sub:null`** ——
admin 那端(§B5-4 (2))把「沒有」與「形狀壞」分成兩條路,而 `null` 會掉進**形狀壞 ⇒ 整包拒**那一條。

🔴🔴 **這一片最容易出的錯,就是只改 `:71` 而忘了 `:66`。**
症狀:`data.sub_kind` 恆為 `undefined` ⇒ 回應永遠不帶 `sub` ⇒ **admin 永遠拿不到身分,而每一層都「正常」**
(碼換得到、登入成功、沒有任何錯誤)。**typecheck / lint / 現有測試全部看不到**(`.select()` 吃的是字串)。
⇒ **§6 第 3 格就是為了這一行存在的。**

⚠️ **`exchange` 不做任何白名單過濾** —— admin 端 `apps/admin/src/lib/sso/exchange.ts:11` 檔頭逐字
「報價單 exchange **直透 DB 值、無白名單**」。**`sub` 沿用同一個分工**:
報價單這端擋在**寫入**(§3 的 CHECK),admin 那端擋在**收取**(§B5-4 的 `sanitizeSub`)。
🔴 **兩端都要有,不是二選一** —— DB 裡若有 CHECK 之前寫進去的舊列,CHECK 管不到它。

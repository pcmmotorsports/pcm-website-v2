## §3 要印哪些數字(每一個都附出處,`Q-D-7` 驗收條款)

| 紙上的字 | 值 | 出處 / 運算 |
|---|---|---|
| 品項「金額」 | `unitPrice.amount × 本區數量` | `types.ts` 錨點 `unitPrice: Money`;**整數 × 整數** |
| 本次出貨小計 | Σ(上一列,本區) | 本區各列相加,**不跨區** |
| 尚未出貨小計 | Σ(上一列,本區) | 同上 |
| 商品小計 | `detail.subtotal` | **直接印,零運算**(契約 `subtotal = Σ lineTotal`) |
| 運費 | `detail.shippingFee` | 直接印 |
| 折扣 | `detail.discountTotal` | 直接印,前面加負號;🔴 **`amount === 0` 時整行隱藏** |
| 付款金額 | `detail.total` | **直接印,零運算** |

> 🔴 **折扣 0 要隱藏,不是印 `−0`**(關卡1 findings ⑤)。
> **照抄既有行為,不自創**:`apps/admin/src/components/orders/order-detail-items-table.tsx:207`
> 逐字 `detail.discountTotal.amount > 0 &&` ⇒ 訂單頁零折扣時**那一行不存在**。
> ⚠️ 紙上與訂單頁不一致 = 客人拿兩邊對照時會以為有一邊壞了。

🔴 **結算四行全部直接印權威欄,零推算、零湊數。**
不變式(`types.ts` 錨點 `total = subtotal + shippingFee`)保證它們加得起來,
**而我不在紙上重算來「驗證」它** —— 重算等於在紙上多一個可能與權威值不符的數字。

🔴 **兩區小計【不等於】商品小計,而那是對的**:小計的母體是整張訂單(全下單量),
兩區的母體是「這一箱」與「還欠的」。**紙上不得出現任何跨區等式**(同 `#10` 片2b 已有的紀律)。
⚠️ 這一點要在紙上用一句人話講清楚,否則客人會自己相加然後發現對不起來。

## 🔴🔴 §6.5 對外紙本的通則:**每一個數字要能回答「它是不是它的標籤說的那個東西」**

```
Q-C8   結算區「取消/退款」那一行 ⇒ 用減的湊出來，數學上恆等於【折扣】，與取消無關

       而實際退款金額走退款流程、可能不同
Q-C12  結算區「付款金額」取 detail.total ⇒ 那是【契約算出來的訂單總額】不是實收
       （types.ts:158 vs :206「對帳/實收一律走 payment_method + payment_status」；
         同檔 grep -c 'paidAmount|amountPaid|actualPaid' ⇒ 0，這型別根本沒有實收欄）
         🔴 2026-08-31:那條 grep 少了 `-E` ⇒ 它對什麼都回 0(死尺)。加 `-E` 今天【也是 0】(🔵 正對照 同檔 `grep -c total` ⇒ 21)⇒ **結論碰巧是對的,而「碰巧」兩個字要留著。**

🔴 **三個的共同形狀**:數字**算得出來、印得出來、四綠不會紅**,

**落地動作(不是決心)**:
> 紙上每加一個數字,當場寫下**兩句**:
> ① 它的值從哪個欄位/運算來 ② **它的標籤向客人宣稱了什麼**
> **兩句對不起來就不要印。** ⇒ 這比 `Q-D-7`「寫明出處」多要一半 ——
> 出處只答①,而**三次出事的都是②**。

  而 `redirectWith` 只帶 **`?r=<六碼之一>`**。**query string 裝不下 RPC 的訊息。**
- **最近的前例走的是另一條路**:`item-procurement-form.tsx:4` 用 `useActionState`,

### 7-1 缺陷(我從 code 撈到,主視窗用瀏覽器量到數字)

`order-detail.tsx:145` 逐字:
```tsx
<td className={`${TD} text-right tabular-nums whitespace-nowrap`}>
```
而我塞進去的是:`AdminFormField`(帶 label)+ 輸入框 + checkbox + **「我確認這個品項要改成 0 元」14 個中文字**。

**主視窗 2026-08-16 實測(視窗 1440、未開側邊面板、正式站現況=沒有本片的版本)**:
```
訂單明細頁共 4 張表；品項表是第 [1] 張（6 欄，表寬 1150）
欄寬  品項 289 / SKU 175 / 數量 102 / 單價 155 / 小計 175 / 訂貨·到貨·取消 255
```
🔴 **單價欄 155px**,而那句中文估約 200px(≈14px/字 × 14 字)再加 checkbox。
⇒ `whitespace-nowrap` 會讓它**一行到底**,那一欄至少要撐到 220px 以上;
而表寬 1150 已接近容器 ⇒ **撐開只能從別欄擠(品項欄 289 最肥,會先被壓)或整張表出現橫向捲軸。兩種都不好。**

⚠️ **量測的作用域**:那是**正式站現況**(還沒有本片的表單)的欄寬,**不是加上表單之後的實際渲染**。
它證的是「**這一欄本來就只有 155px**」,不是「加上去之後會變成幾 px」。
📌 **主視窗上一份量測抓錯表**(`document.querySelector('table')` 只回第一張,而這頁有 4 張)——
**上面這組是重量過的那份。** 🔴 舊那組(5 欄 / 表頭全空 / 1118)**作廢,不要引用。**

### 7-2 三個選項與裁決

| | 做法 | 為什麼不選 |
|---|---|---|
| ② | 拿掉 `whitespace-nowrap` | 中文會在一個 `text-right tabular-nums` 的**數字欄**裡折行 ⇒ 那格變成一團,**而且會把其他列的數字對齊拉歪** |
| ③ | 收進 sheet / 展開抽屜 | 多一層互動,而員工要做的事只是**改個數字** ⇒ 違反「操作直覺化」常設準則 |
| **①(採用)** | **表單移出那格,獨立成一列** | 見下 |

**①額外解掉一件**:編輯區有自己的橫向空間
⇒ **確認句、錯誤提示、原因欄以後都放得下,不必為每個新欄位再打一次版面仗。**

### 7-3 ①的代價與對策(主視窗指定)

**代價**:一個品項變兩列 ⇒ **品項多的訂單會變很長。**
**對策**:🔴 **只有「正在編輯的那一項」展開那一列,其餘不展開。**
⚠️ 那表示要有一個「哪一列在編輯」的狀態 —— **而它是 client state**;
**表格本體仍是 server component**(`grep -c "use client" order-detail.tsx` ⇒ **0**),
⇒ 展開狀態要放在**新的 client 島**裡,不要把整張表變成 client component。

### 7-4 ⚠️ 這一節沒驗的

1. **「14px/字 × 14 字 ≈ 200px」是估的**,沒有量過實際渲染寬度。
2. **加上表單之後的欄寬沒有人量過**(那需要先部署或本機起站)。
3. **展開列的實作形狀沒設計** —— 只定了「只展開正在編輯的那一項」這個約束。

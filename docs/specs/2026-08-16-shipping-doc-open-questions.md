## 🔴🔴 `Q-C8` · 出貨單「取消/退款」那一行,錢從哪裡來?

**照 `Q-D-11 = 甲`(付款金額用權威值、取消/退款用減的湊)實作,那一行會印出【折扣】,不是取消。**

我自己開檔驗過的三條(不是轉述 `D-027`):
```
① 兩支取消 RPC 都【只】動 cancelled_at / cancelled_reason / updated_at
   20260805100000_…a8a2_partial_cancel.sql（錨點 SET cancelled_at = pg_catalog.now()）
   20260804180000_…a8a1_admin_cancel_order.sql
   數法：grep -rc "UPDATE public.orders" 兩檔 ⇒ 各 1 處，逐處開檔看過
② grep -rn "SET total|total =" supabase/migrations/*cancel*.sql
   ⇒ 唯一命中是 a8c2_confirm_cancel_guard.sql 的 v_order.total = p_amount ——【讀取比對】不是寫入
③ 不變式：packages/domain/src/order/types.ts（錨點 `total = subtotal + shippingFee`）
```
⇒ `小記 + 運費 − 付款金額` = `subtotal + shippingFee − total` **代進不變式 ⇒ 恆等於 `discountTotal`**。
而 `discountTotal` 的 docstring 逐字「**Phase 1 多為 0**」
⇒ **客人退了 3000 塊,那一行會印 0。**

```
A：不印那一行 —— 取消只用「訂單取消」那一區的【件數】表達，紙上不出現取消金額
B：從 order_cancellation_items 自己算 —— 但那是【紙上新增一種金額算法】，
   而 Q-D-7 只放行過「unitPrice × 本區數量」
C：取消時讓 RPC 真的改 total —— 🔴 動的是金流寫入鏈，跟本片完全不同量級
```
**C 窗推薦 = A**(紙上零新增金額算法、也不動寫入鏈;客人要金額對帳走退款通知/訂單頁)。
⚠️ **同時命中鐵則 12 ①錢 + ⑤對外不可回收 ⇒ 這題我不自己拍。**

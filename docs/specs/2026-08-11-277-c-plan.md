## 2 view 形狀

```sql
CREATE OR REPLACE VIEW public.vehicle_taxonomy_public
  WITH (security_invoker = false) AS
SELECT DISTINCT moto_brand, model_code, year_start, year_end
FROM public.product_fitments
UNION ALL   -- 兩半依建構互斥(下半的 NOT EXISTS 保證該 brand/model 不在上半)⇒ 外層去重是白工
SELECT DISTINCT e.moto_brand, e.model_code, NULL::int, NULL::int
FROM public.product_fitments_effective e
WHERE NOT EXISTS (
  SELECT 1 FROM public.product_fitments d
  WHERE d.moto_brand = e.moto_brand AND d.model_code = e.model_code);
```

- **上半**=年份的唯一來源(direct,不受報價單年份 bug 影響)。
- **下半**=只補「direct 完全沒有的車型」,年份刻意寫 NULL ⇒ 下拉顯示「不限年份」
  (`VehicleSelect.tsx:418-419` 既有狀態,不用新做 UI)。
- 🔴 **anti-join 用嚴格字面比對是刻意的,代價已量**:兩表有 **3 組**同一台車字面不同
  (`Ducati/"Panigale V4"` vs `"panigale v4"`、`Honda/"Forza 250 "`(尾端空格)vs `"Forza 250"`)
  ⇒ 嚴格比對會多補 **1 列**(`added_strict = 198` vs `added_normalized = 197`)。
  改用 `lower(btrim(...))` 比對可消掉它,但**實測 413ms → 1,170ms(2.8 倍)**,
  而且兩側 sort 都 `external merge Disk`(溢出磁碟)⇒ anon 3s 的餘裕從 7 倍掉到 2.6 倍、
  且磁碟排序在並行負載下變異大。**取捨:留嚴格比對。**
  🔴 那多出來的 1 列**由下游吸收**:`buildVehicleTaxonomy` 以 `normalizeVehicleQuery`
  (NFKC+trim+lower)為節點鍵去重 ⇒ 兩個字面併成同一個車型節點、年份取聯集。
  ⚠️ **這是對下游行為的依賴,必須有守門**(見 §7-4),不能只寫在註解裡。
- 🔴 **`security_invoker = false` 必須保留**,理由與前一版同(`20260811020000` §2):
  invoker 版會把底表 RLS 的下架 join 套進來 ⇒ 實測 3,047ms,而 **anon 的 statement_timeout 是 3s**。
  本 view 仍**零 `product_id`、零價格、零供應商** —— ⛔ 不得加任何商品欄。

⚠️ **`lost_models_normalized` 用的是 SQL 的 `lower(btrim(...))`,不完全等於 app 的
`NFKC + trim + toLowerCase`(關卡2 指出,屬實)**:全形/半形字面 SQL 這邊不會折,app 會。
實查 view 有 **2 列含非 ASCII 字元** ⇒ 那 2 列的口徑差**未逐字驗**。
所以「消失 0 / 新增 200」這兩個數字的精確度以 ASCII 部分為準,非 ASCII 那 2 列標為未確認。

```sql
WITH c_view AS (
  SELECT DISTINCT moto_brand b, model_code m, year_start ys, year_end ye FROM product_fitments
  UNION ALL
  SELECT DISTINCT e.moto_brand, e.model_code, NULL::int, NULL::int
  FROM product_fitments_effective e
  WHERE NOT EXISTS (SELECT 1 FROM product_fitments d
                    WHERE d.moto_brand=e.moto_brand AND d.model_code=e.model_code)
), old_path AS (
  SELECT DISTINCT trim(e->>'motoBrand') b, trim(e->>'modelCode') m,
    CASE WHEN (e->>'yearStart') ~ '^[0-9]{4}$' THEN (e->>'yearStart')::int END ys,
    CASE WHEN (e->>'yearStart') ~ '^[0-9]{4}$' AND (e->>'yearEnd') ~ '^[0-9]{4}$'
         THEN (e->>'yearEnd')::int END ye
  FROM products p, jsonb_array_elements(p.fitments) e
  WHERE p.delisted_at IS NULL AND jsonb_typeof(p.fitments)='array'
    AND nullif(trim(e->>'motoBrand'),'') IS NOT NULL AND nullif(trim(e->>'modelCode'),'') IS NOT NULL
)
SELECT
  (SELECT count(*) FROM (SELECT b,m,ys,ye FROM old_path EXCEPT SELECT b,m,ys,ye FROM c_view) x) AS lost_4col,
  -- 🔴 使用者可見的損失看這個:整台車不見(normalize 後比對,與 app 的節點鍵一致)
  (SELECT count(*) FROM (
     SELECT DISTINCT lower(btrim(b)) b, lower(btrim(m)) m FROM old_path
     EXCEPT SELECT DISTINCT lower(btrim(b)), lower(btrim(m)) FROM c_view) x) AS lost_models_normalized;
-- 2026-08-11:lost_4col = 1(空白字面差)、lost_models_normalized = 0
```

## §2 現況事實(這一節推翻了本片的直覺前提,務必先讀)

### 2.1 `AdminDataTable` **早就有完整的手機卡片模式**

`apps/admin/src/components/shared/admin-data-table.tsx`(163 行)。不是要從零做卡片:

- `:101` 桌機 `hidden overflow-x-auto … md:block` / `:135` 手機 `<ul … md:hidden>`
  —— **純 CSS 斷點、零 JS、零視窗偵測、server component 直出**(`:14-15`)。
- 槽位語彙 `AdminColumn.mobile?: 'title' | 'trailing' | 'sub' | 'meta'`(`:33-40`),
  外加 `renderMobileActions`(`:75-76`,固定放卡片最下方)。
- `:86-93` 對「`title` 恰好 1 個」有 dev-only `console.warn` 自檢。

### 2.2 🔴 但 `AdminDataTable` 是**扁平列模型**,`orders-table` 是**兩層模型**

這是本片片界的**唯一硬約束**:

| | `AdminDataTable` | `orders-table` |
|---|---|---|
| 資料 | `rows: readonly T[]`(`:70`)| 訂單 → 品項兩層(`:64` `order.lines`)|
| DOM | 一列一個 `<tr>`(`:113-114`)| **一張訂單一個 `<tbody>`**(`:69`)、每品項一列(`:70`)|
| 訂單層欄 | 無此概念 | **`rowSpan` 合併**(`:76`/`:110`/`:136`/`:162`,金額另依 `:123` 條件合併)|

⇒ **`orders-table` 今天接不上 `AdminDataTable`**,除非改後者的列模型(= 共用元件行為改動)。
歷史紀錄早就指出過同一件事:`docs/handoff/CURRENT.md:856` 逐字
「**不從 `orders-table.tsx`(210 行、rowSpan)下手**」。

### 2.3 手機卡片的自然單位是「一張訂單」,不是「一個品項」

順著 §4-1「主要欄位加粗置頂」推:主標 = 訂單編號 ⇒ **一張訂單一張卡**。
若改成一品項一張卡,3 品項的單會把單號 / 日期 / 客戶**重複三次** —— 比現在的橫捲表更糟。
⇒ **手機卡片本身就是兩層結構**(卡頭 = 訂單層、卡內清單 = 品項層),
與桌機 rowSpan 是同一個資訊結構的兩種畫法。這正是 §2.2 那條約束會咬人的地方。

### 2.4 既有測試不會被雙 markup 誤傷(實查)

`orders-table.test.tsx`(484 行):**`getByText` 系零次**、`container.querySelector*` **24 次**,
且選擇器全鎖在 `thead th` / `tbody tr td`(抽樣 `:116`/`:123`/`:139`/`:142-144`)。
⇒ 卡片版若是 `<ul><li>`(非 `<table>`),**既有斷言一格都不會誤命中**,桌機回歸套件保持有效。
⚠️ 反面:既有測試對卡片版**零覆蓋**,新格要自己寫(§6)。

### 2.5 九碼前置已解除

`A11a` plan `:320` 逐字「A11c(手機卡片版)若也渲染九碼,A9v 就還不能跑 ⇒ 開 A11c 時要一併確認」。
**實查:已解除。** `orders-table.tsx:17-18` 記載九碼三群已於 A11a-1 下架、
「這是**列表側最後一個九碼消費端**」;`order-list-view.ts:34-35` 記載查詢鍵與哨兵亦已下架。
全檔僅存歷史註解,**零渲染面** ⇒ 卡片版拿不到九碼,A9v 不被本片擋。

## §4 ⛔ 片界決策題(要主視窗/Sean 拍,拍完才動工)

`E-129-A` 的內文說「手機卡片版**蓋在 `AdminDataTable` 上**」,但同一句的括號寫的是

```

A) orders-table 自己長出卡片版(桌機表格 hidden md:block + 手機卡片 md:hidden),
   AdminDataTable 完全不動;槽位語彙刻意照抄 title/trailing/sub/meta,讓 A12a 遷移是機械工。

   —— 一次到位、零重工;但這是共用元件的**列模型**改動(3 個既有消費端全在射程內),
```

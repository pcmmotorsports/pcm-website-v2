| # | 現在問的 | 為什麼在 Supabase 上答不了 | 證據 |

| 1 | 「有沒有角色切得進 `service_role`」 | 🔴 **恆為真** —— `authenticator` 必須切得過去,否則 Data API 不會動 | 本機重建正式庫拓樸實測:三個角色全中;repo runbook `:140` 逐字 |

而「壞事」與「正常運作」在那個快照上**長得一樣** —— 分辨它們需要的是**變化**,不是**狀態**。

## ④ 片二那批敘述:**修文字,還是本體才是對的?**

**先判這個 —— 兩者的處置完全相反。**

```
敘述說：「有人看過了 ⇒ 那一列離開主告警述詞 ⇒ 計數 1→0」
本體做：那一列【留在】主告警計數裡，同時進入一個 unknown 存量
```

🔴 **我判:【本體是對的,敘述是舊的】。依據是本體自己帶的理由(`:143-152` 逐字)**:
> 「`unknown` 是唯一會通過的路,而它不要求任何對帳證據 ⇒ 讓它退出主告警
>   = 把『真扣款但本地仍 pending/unpaid』的單,沿**阻力最小的路**送出視線之外。
>   ⇒ **在『證據』這道要求存在之前,退出主告警這件事本身就是那個洞。**」

⇒ 那個推理**與這支檔要守的丙(那一列不會從視線裡消失)一致**,而舊敘述**與它矛盾**。
⇒ **處置 = 修敘述**(而 🔴 其中 **2 處是 `COMMENT ON`,會寫進 `pg_description`、逃出 repo** ⇒ 優先)。

⚠️ **而有第三種可能我不排除,只是不選**:「R2 反轉本身是錯的、應該再反轉回去」。
**那是 Sean/主視窗的題,不是我的** —— 而若真要走那條,**這整份 plan 的 ④ 要重寫**。

# 台灣電子發票研究(供 PCM 後台發票記錄功能參考)

> 研究時間:2026-07-25。⚠️ 本文件只陳述法規字面與常見實務,不構成稅務建議;凡涉及「PCM 該怎麼申報/該選哪種身分」的判斷,標明「需會計師確認」。

## 1. 法規與主管機關

**母法**:加值型及非加值型營業稅法 第32條之1(law.moj.gov.tw)
> 第一項:「營業人銷售貨物或勞務,依前條第四項規定以網際網路或其他電子方式開立、傳輸電子發票者,應依規定時限將其開立電子發票及相關必要資訊傳輸至財政部電子發票整合服務平台存證;買受人以財政部核准載具索取電子發票者,營業人應將載具識別資訊併同存證。」
> 第二項定義「載具」= ①身分證統一編號/自然人憑證卡片號碼/電話號碼/會員號碼 ②信用卡/轉帳卡/儲值卡/電子支付帳戶等支付工具號碼 ③其他得記載或連結電子發票資訊之號碼。
來源:https://law.moj.gov.tw/LawClass/LawSingle.aspx?pcode=G0340080&flno=32-1 (WebFetch 讀取,非逐字 PDF 比對,建議正式寫規則前再親自開網頁核對一次條文標點)

**子法/辦法**:統一發票使用辦法(law.moj.gov.tw pcode=G0340082)— 全文 https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=G0340082
- 第7條:電子發票種類、應有存根檔/收執檔/存證檔。
- 第7-1條:定義**雲端發票**=使用財政部核准載具、或指定捐贈碼捐贈,且**未列印電子發票證明聯**。
- 第8條:電子發票得以條列方式列印名稱/地址/統編於統一發票專用章欄,免蓋章。
- 第9條:雲端發票記載事項得以外文為之,交易日期得用西元。
- 第20條:銷貨退回/掉換/折讓應於事實發生時依規定辦理。
- 第20-1條:電子發票的銷貨退回、進貨退出或折讓證明單,應以網際網路或電子方式開立/傳輸/接收,具存根檔/收執檔/存證檔。
- 第24-1條:機器故障時得人工開立替代。

**執行要點**:電子發票實施作業要點(law-out.mof.gov.tw id=FL041411)
- 第2條:定義「載具」「共通性載具」「捐贈碼」。
- 第3條:折讓證明單須以電子方式開立/傳輸/接收,並依時限傳輸至整合服務平台存證。
- 第7條:字軌配號**預設按期配賦**;符合條件(自印收銀機發票者/無欠稅且符合會計師查核/連鎖加盟/公用事業等)可申請**按年配賦**。
- 第22-23條:平台以**每兩個月一期**處理捐贈發票;捐贈碼每一機關團體限一組,買受人變更捐贈對象**每機關團體以三次為限、設定或變更後三個月內不得再變更**。

**主管機關/平台角色**:財政部電子發票整合服務平台(「大平台」,https://www.einvoice.nat.gov.tw/)是全國電子發票資料**集中存證與查詢中樞**,提供:①營業人 web 介面直接開立發票 ②Turnkey 傳輸軟體 + MIG 資料交換格式介接 ③載具歸戶/捐贈碼查詢/中獎兌獎/開放資料 API。稅務入口網(etax.nat.gov.tw)是申報/帳號登入入口,兩者資料互通。
來源:https://www.einvoice.nat.gov.tw/、https://www.etax.nat.gov.tw/etwmain/tax-info/innotative-tax-e-reference/startup/invoice/VOpWrNx

**114年(2025)新規**:自 114/1/1 起,電子發票銷貨退回/進貨退出/折讓證明單,經買賣雙方合意,賣方應**依限據實傳輸**至大平台存證,否則受罰。存證時限:**買受人為非營業人者 2 日、買受人為營業人者 7 日**(自事實發生日起算)。
來源:https://www.mof.gov.tw/singlehtml/384fb3077bb349ea973e7fc6f13b6974?cntId=de15ed4416dd4b91891b6cf72bd0bb8b

## 2. B2C vs B2B 差別

| | B2C(買方為一般消費者) | B2B(買方為營業人/要求記載統編) |
|---|---|---|
| 型態 | 二聯式(舊制對應)/雲端發票或電子發票證明聯 | 三聯式(舊制對應)/需記載買方統編、名稱 |
| 統編/抬頭 | 非必填 | **統一編號、買受人名稱必填** |
| 紙本裁切 | 明細自二維條碼以下**裁切** | 二維條碼下方**接續列印交易明細,不裁切** |
| 對獎 | **電子發票證明聯**可對統一發票中獎(每兩個月開獎一次) | 通常不涉及對獎 |
| 存證時限 | 2 日 | 7 日 |

**雲端發票 vs 電子發票證明聯**:雲端發票=買受人使用財政部核准載具(或指定捐贈)、**不列印紙本**,存於大平台雲端;電子發票證明聯=**列印紙本**(需感熱紙、僅一張不得重製)可參加對獎。兩者在系統設計上互斥(有載具就不印證明聯)。
來源:https://www.etax.nat.gov.tw/etwmain/tax-info/innotative-tax-e-reference/startup/invoice/E8BBvKQ、https://gateweb.com.tw/電子發票、統一發票使用辦法第7-1條

## 3. 載具與捐贈(格式規則,將寫進 DB CHECK,已交叉驗證)

**手機條碼**:共 8 碼,**第 1 碼固定為 `/`**,後 7 碼為數字(0-9)、大寫英文字母(A-Z)、及特殊符號(`.` `-` `+`)組成。
Regex:`^/[0-9A-Z.+-]{7}$`(兩個獨立來源一致:https://invoice.amego.tw/info_detail?mid=74 、 https://www.ecpay.com.tw/CascadeFAQ/CascadeFAQ_Qa?nID=3531)。條碼採 Code39 編碼。官方 PDF(財政部,手機條碼申請使用注意事項)在 https://www.einvoice.nat.gov.tw/static/ptl/ein_upload/download/2142.pdf 及 https://www.einvoice.nat.gov.tw/static/ptl/ein_upload/html/ESQ/Download/802_moblicebarcode.pdf,**本次 WebFetch 未能解析出 PDF 逐字文字**(binary/超過 fetch 大小限制),上述 regex 為**二手來源交叉驗證、非官方 PDF 原文比對**——寫 DB CHECK 前建議 Sean 或工程師手動開一次官方 PDF 核對逐字規則。
**真實性驗證**:格式合法≠真的存在,財政部有提供手機條碼查詢 API 可驗證條碼是否確實已註冊。

**自然人憑證條碼**:共 16 碼,前 2 碼**大寫英文字母**,後 14 碼**數字**。
Regex:`^[A-Z]{2}[0-9]{14}$`。來源(二手,未找到官方逐字 PDF):https://tw.help.yahoo.com/kb/SLN22635.html、多篇整合說明頁一致。**標「未完全確認官方逐字」**,建議正式寫 CHECK 前再查一次財政部原文。

**會員載具(非共通性載具)**:由個別企業(如超商、電商平台)自建的會員卡/APP 帳號號碼,**格式由該企業自訂、不受財政部統一格式限制**,僅需向財政部申請核准使用。PCM 目前 `orders.invoice.carrier` 若指的是手機條碼/自然人憑證(共通性載具),應套用上述兩種 regex;若做「PCM 自己的會員載具」則屬非共通性載具、格式自訂但需另外申請。

**愛心碼(捐贈碼)**:由受捐贈機關/團體向財政部申請設定,**每一機關團體限一組**,買受人於結帳時輸入捐贈碼即可把發票捐出。可於大平台「捐贈碼查詢」頁(https://www.einvoice.nat.gov.tw/portal/btc/btc603w)以捐贈碼/統編/名稱/簡稱查詢核對。捐贈碼**格式未見統一長度規範**(依各團體核配,常見為數字碼,但長度不定)——標「未確認」,若 PCM 要做前台捐贈碼輸入驗證,應改走「呼叫查詢 API 核對是否存在」而非自訂 regex。

## 4. 字軌與號碼

- **字軌組成**:2 個大寫英文字母 + 8 位數字(例如 AB12345678)。
- **配號方式**:預設**按期**(雙月一期)配賦;符合條件(自印收銀機發票、無欠稅且會計師查核簽證、連鎖加盟、公用事業等)可申請**按年**配賦。首次使用前需向所在地主管稽徵機關申請、核准後於大平台依需用數量取號。
- **期別**:與統一發票相同,**雙月**為一期(1-2月、3-4月...11-12月)。配號方式選「期配」者,若字軌用量估算偏差,須於**雙月 18 日前**至大平台調整下期取用本數。
- **作廢**:發票開立後如需作廢,須聯繫買受人並經雙方合意才可辦理(電子發票已傳輸存證,不可片面作廢)。
- **折讓/退貨**:透過「銷貨退回、進貨退出或折讓證明單」電子化開立,**經買賣雙方合意**由賣方依限據實傳輸存證(自 114/1/1 起強制);存證時限=買受人非營業人 2 日、營業人 7 日。**這塊 PCM 有退款需求要對齊**:任何退款流程若已開立電子發票,理論上須同步走折讓證明單流程(不能只在 PCM 內部資料庫標記退款、不留稅務痕跡)——**此為稅務合規判斷,需會計師確認實際 SOP(尤其是尚未串接電子發票、目前手開階段該怎麼處理退貨折讓)**。
來源:https://www.ntbna.gov.tw/download/4f02901de52d4d81aac6f7cdebc5b029、https://law-out.mof.gov.tw/LawContent.aspx?id=FL041411(電子發票實施作業要點第7/22/23條)、https://www.ntbt.gov.tw/singlehtml/41ae3594197f4f69b47753ce08188516

## 6. 進項發票(供應商開給 PCM)

**應記欄位**(依「進項憑證整理與編號」實務指引):憑證類別代號(例如格式代號21=三聯式/電子計算機統一發票、22=二聯式收銀機統一發票等)、期月、發票字軌號碼、金額、稅額、供應商統編。
**歸檔規則**:進項稅額**逾 500 元**者需按**期月分類**裝訂(白色封面;二手車用淺綠色);逾 500 元以下免按期月分類、僅按類別分類(藍色封面)。**每 100 張裝訂 1 冊、每張右下角依序編號 00-99**;超過百張時第一冊封面需填總張數/金額/稅額合計。
**保存年限**:會計憑證(含進項發票)除永久保存或未結會計事項外,**至少保存 5 年**(商業會計法第38條、稅捐稽徵機關管理營利事業會計帳簿憑證辦法);帳簿則保存 10 年。經核准可用電子方式儲存媒體保存。
**與 401 申報的關係**:進項發票是「營業人銷售額與稅額申報書(401)」進項稅額扣抵的憑證來源,需依上述分類裝訂留存供稽徵機關查核,但**PCM 具體該怎麼歸檔、哪些供應商發票可扣抵——需會計師確認**,本研究只陳述法規字面。
來源:https://www.etax.nat.gov.tw/etwmain/tax-info/understanding/tax-q-and-a/national/business-tax/collection-prcedure/nBpMV6Y(最後更新民國112年4月25日)、https://accounting.sme.gov.tw/run.php?name=forum&file=post&p=536421

## PCM 發票功能最該先做的 3 件事 + 建議串接方案

1. **先把「開票需求」欄位(`orders.invoice`)的格式驗證補齊**:`carrier` 若允許手機條碼/自然人憑證,現在應該用上面兩條 regex 做前端+後端雙重驗證(目前很可能沒驗證、任何字串都能存進去),`taxId` 統編應加 8 碼數字+財政部檢查碼演算法驗證(本次未研究統編檢查碼公式,需另查)。這是最低成本、立刻能做、風險最小的一步。
2. **把「折讓/退款」流程與發票狀態機串起來**:目前 `invoice_status` 只有 not_issued/issued/voided 三態,沒有對應「已折讓」;PCM 有退款需求,一旦真的開始開立正式發票(電子或手開),退款時如何處理發票(補開折讓證明單 vs 純作廢)必須先問會計師定案,再回頭設計狀態機——**不要先寫死邏輯、再發現稅務對不上**。
3. **串接選型先小規模驗證 ECPay,不要碰 Turnkey/MIG**:ECPay 有完整公開文件、測試環境、REST API,是目前唯一同時滿足「文件公開」+「有測試環境」+「費用可預期」三條件的選項;Node.js 沒有堪用的開源 SDK,直接自寫 REST client 反而比套一個 5 年沒更新的套件安全。過渡期(現在混合手開)可以先把後台的「發票記錄」欄位設計成能同時容納「手開發票號碼」與「未來 ECPay 回傳的電子發票號碼/QR code」,不用等串接才動 schema。

（以上 3 點是研究員基於法規與生態現況的建議排序,不是稅務建議;實際定案仍需 Sean + 會計師拍板。）

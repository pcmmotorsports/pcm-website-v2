## 0. 掃描範圍與方法
- 兩條 Apps Script 唯讀通道(見 `~/.claude/skills/pcm-monthly-report/SKILL.md`),`&meta=1` 取分頁清單、`&rows=1&gid=` 逐頁抓值,只做 GET,沒有任何寫入。
- **月份範圍:2025/07 ~ 2026/07,共 13 個月**(兩通道皆同一範圍;更早月份分頁存在但本次未掃,見底部「未取得」)。
- 訂單/車行通道(key 見 skill,不重複貼):W 欄(用途)、X 欄(費用金額)。逐頁確認資料實際只落在該月分頁前段(每頁約列 5~21 列就結束,沒有拖到後面幾百列的訂單明細區),不是靠猜的範圍界線、是直接看資料自然斷點,所以下面加總沒有跨月污染風險。
- 成本/月報表通道:X 欄(用途)、Y 欄(原幣金額)、AA 欄(台幣換算,採用 AA;若 AA 缺值退回 Y)。同樣每頁資料只落在前段(約列 5~21 列),自然斷點,無跨月污染。
- 逐字保留原始字串,大小寫、全形半形、空白都原樣照抄,不做任何合併/翻譯。

## 3. 收入分類

- **B2(本月營業額)只有單一總額,沒有任何收入子分類**(沒有「零件銷售/運費收入/安裝服務」這種拆法)。
- 唯一找到的「收入側」分類是訂單通道 **L欄「客戶型態」**,只有兩種值:`車行`(206 筆,2026/07 單月)、`直客`(86 筆,2026/07 單月)——這是通路別(批發/零售),不是會計科目意義的收入分類。
- 結論:**收入面沒有既有分類可抄,只有客戶型態(車行/直客)這個維度可用。**

## 4. 用途字串髒亂程度評估 → 結論:必須做下拉選單、不能沿用自由輸入

具體重複/變體證據(逐字對照,原樣抄):
- 快遞商同名多寫法:`FedEx` / `Fedex` / `fedex`(訂單通道三種大小寫都出現);`FEDEX` / `Fedex` / `FEDEX運費` / `FEDEX運費/5`(月報表通道)。
- 物流商多寫法:`新竹` / `新竹物流` / `新竹貨運` / `新竹5月` / `05月新竹物流`(同一家拆成 5 種字串)。
- 供應商多寫法:`WRS` / `WRS稅金` / `WRS DHL` / `WRS+EX稅金` / `WRS fee`;`MATERYA` / `Materya` / `materya` / `Materya稅金`。
- 純粹空白/大小寫差異視為不同字串:`711寄件` vs `711 寄件`(中間多一個空白);`DHL` vs `DHL `(尾隨空白);`Gbracing 稅金` vs `GBracing稅金`(大小寫+空白都不同,同月出現兩次視為兩筆)。
- **用途欄位混用「品牌名/供應商名」「動作說明」「金額調整原因」三種語意**,不是單一維度(例如訂單通道同時有 `補`、`補錢`、`校正`、`修正` 這種調整類字眼,也有 `Sean`、`sean` 這種人名當用途)。
- **沒有任何既存欄位標示「這是退款/補款/一般支出」**,全靠金額正負號隱含判斷。

結論:同義異寫、大小寫、空白、品牌名當分類混雜科目性質,人工歸類成本高且容易漏。**後台應該做「用途」下拉選單(建議一組 8-12 類粗分類,如:海外運費/國內物流/關稅報關/供應商進貨/水電雜支/電信/保險稅務/退款校正/其他)+ 保留一個「備註」自由欄位承接舊資料的細節**,不建議直接沿用現有字串當選項(選項會爆炸到 158 個以上且持續長出新變體)。

## 5. 成本欄位怎麼存的

成本/月報表通道每個月分頁的**主表(逐筆訂單明細)**,每一列(=一筆訂購項目)有明確欄位(表頭在該分頁第 3 列,對照抓到 2026/06 分頁的實際欄名):
- E欄=原價、F欄=運費、G欄=稅金、H欄=幣值(幣別代碼,如 GBP/USD/THB)、I欄=總計。
- 這是**逐筆記**(每筆訂購項目自己一行原價/運費/稅金,I 欄總計看起來是這三者加總後的金額),不是月底一次性估算公式。

**公式字面:未取得。** 本次唯讀 API(`getDataRange().getValues()`)只回傳算好的數值,不含儲存格公式文字,我沒有管道另外呼叫 `getFormula()`。SKILL.md 裡引用過「B2 範例公式 `sum($J$5:$J156)`」是既有文件記載、非本次任務重新查證取得,我沒有獨立驗證這條公式在其他月份是否成立,列在下面「未取得」。

另外,同一分頁還有一組**完全獨立的「公司支出/物流費用」清單**(就是本報告第2節掃的 X/Y/AA 三欄),跟上面主表的 E/F/G 逐筆成本是兩回事——這組是「這個月付給物流商/報關行的實際帳單」,X=用途(物流商或稅務說明)、Y=原幣金額、Z=幣別、AA=換算台幣。

## 6. 月報表現有的彙總欄位

除了 SKILL 文件已知的 B2(本月營業額)、C2(本月利潤)外,實測還看到:
- **D2 = 淨利率**(逐月核對 = C2/B2,數值上完全吻合,判斷是比率;公式文字同樣未取得)。
- **A2 = 一個整數**(152、156、182、197…量級,推測是「本月訂單/項目筆數」,但沒有欄位標籤可佐證,未確認)。
- **第4列(row4)有一組小型摘要:X4標籤「訂單上運費」、Z4標籤「本月支出運費」、AA4=一個數字、AC4=幣別「TWD」**。實測這個 AA4 數字**跟本節掃描出的 X/Y/AA 清單加總對不上**(例如 2025/07:AA4=11,833,但我掃到的清單加總是 88,782)。追查後判斷這是兩個不同的東西:AA4 摘要可能是引用另一個範圍或口徑(未確認是什麼),不是「本節 X/Y/AA 用途清單」的自動加總。**這點是本次唯一數字對不上的地方,如果後台要做「本月運費」這個指標,建議用第2節逐筆清單自己加總、不要直接抄 AA4 這格數字,除非先跟 Sean 確認 AA4 的實際定義。**
- 老闆實際在看的數字,依 SKILL/方法文件記載=每月 B2/C2/淨利率,以及品牌毛利、客戶集中度(這些是月報分析 skill 算出來的衍生指標,不是表格本身自帶的彙總欄位)。

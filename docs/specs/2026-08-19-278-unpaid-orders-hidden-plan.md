## 3. 🔴 丙【要什麼才做得到】—— 這是主視窗指定我要答的那題

丙要分「孤兒」與「等匯款」,而**今天的資料裡沒有任何欄位分得出來**。要做,得先有下面之一:

```
① 一個【付款方式/意圖】欄
   建單當下就標「這筆要走 TapPay 即時刷」還是「這筆等匯款」
   ⇒ 最乾淨,而它是 schema 改動(鐵則 12③)
   ⚠️ 而它**答不了既有單**(今天 0 筆 ⇒ 這個缺點現在為零,以後不是)

② 一個【時間】判準:「建立超過 N 小時仍 unpaid ⇒ 當孤兒」
   ⇒ 零 schema,而它是**猜的**:等匯款的客人可能三天後才匯
   🔴 而 N 是誰定的?那又是一題 ⇒ **不建議,除非 Sean 明確要一個便宜解**

③ 一個【誰標的】判準:員工在後台把某筆標成「等匯款中」
   ⇒ 語意最準(人知道實情),而它要一個新的欄位 + 一片後台 UI
   ⚠️ 而它有個安靜的失敗形狀:**沒有人去標的單,行為與乙相同** ——
      也就是「忘了標」= 客人看不到,而沒有任何訊號。

**三案共同的前置**:都要先決定 §2 那題。**丙不是 §2 的第四個選項,它是「甲」的一個精緻版本。**
```

## 4. ④ Rollback

```
零 migration ⇒ rollback = 把那 10-11 檔的改動 revert
🔴 而【已經寫進去的更正紀錄不會被 revert 掉】—— order_refund_manual_corrections 是 append-only
⇒ 回退後那些更正**仍然生效**（remaining 仍照更正後算）
```

### 🔴 4a. 而 R1 抓到的洞:**回退之後, 「再更正一次」的入口也一起消失了**
```
更正是【人的判斷】⇒ 而人也會判錯 ⇒ 撤銷一筆更正的正規路徑是**再更正一次**
⇒ 而那條路徑就住在這片的 UI 裡 ⇒ **回退 = 連撤銷的能力一起收走**
⇒ 而那時 remaining 停在最後一次更正算出來的值，**沒有人改得動**
```
**⇒ 所以回退【不是免費的】。回退前必做兩件, 寫進本片檔尾的 rollback 段本身**:
```
🔴 ① 盤點本片期間寫進去的所有更正列
   ⛔ ~~v2 寫「依本片上線後的 seq」~~ **作廢(R2 must-fix)** ——
      `seq` 是**每個 refund 各自從 1 遞增**的（`order_refund_manual_corrections_refund_seq_key
      UNIQUE (refund_id, seq)`）⇒ **它不是全域部署水位** ⇒ 那個盤點【做不到】。
   ✅ 改成：**部署當下記一個 UTC cutoff**，盤點 `created_at >= cutoff`
      （該表有 `created_at timestamptz NOT NULL DEFAULT now()`，已開檔確認）
      + 用 audit 的 action 交叉比對
   **怎麼證明這個盤點是完整的**：拿 cutoff 之前刻意寫一列 ⇒ 它**不得**出現在清單裡（負對照）；
   cutoff 之後寫一列 ⇒ 它**必須**出現（正對照）。
② 逐列確認判斷正確；有錯的先在回退【之前】用 UI 更正回來
⚠️ 而若回退是緊急的、來不及做 ①② ⇒ **明寫「remaining 停在某個未複核的值」並開條目**，
   不要讓它安靜地留在那裡
```

#### 🔴 v4 折 A7(原 R3-8):**整個 §4a 建在「撤銷 = 再更正一次」上,而【沒有一格會紅】**

```
🔴 R3 的證明：no_money_moved 在 remaining 上「完全不被消費」（migration :423 只吃 money_moved）
✅ 而 -0b 開檔複驗後**收窄了這句**（:418-425）：
   精確說是【靠缺席被消費】—— 翻成 no_money_moved ⇒ 那一列掉出 sum ⇒ remaining **回升**
   ⇒ 📌 **機制是對的。migration 一個字都不用改。缺的只是【觀測兩個方向】的測試。**
   ⇒ 🔴 所以這一條比 finding 字面**便宜很多** —— 而讀 finding 字面會以為要改 DB
```
**⇒ v4 的折法:三拍差分(一發、三次量,而中間每次只改一個變因)**
```
第 1 拍  未更正                ⇒ 量 remaining = R0
第 2 拍  更正為 money_moved     ⇒ 量 remaining = R1   斷言 **R1 < R0**
第 3 拍  再更正為 no_money_moved ⇒ 量 remaining = R2   斷言 **R2 = R0**（回到原值）
🔴 第 3 拍那格才是 §4a 的驗收 —— 前兩拍任何一片既有測試都可能已經涵蓋
✅ 而三拍要**讀同一支** pcm_order_refundable_remaining，不得中途換來源
```
⚠️ **而 `-0b` 加的那個 caveat 要跟著搬(它會讓這一發安靜地假綠)**:
```
若三拍是**經由 TS repository** 讀 remaining ⇒
  🔴 必須**顯式斷言 remaining !== null**，且**不得用 falsy 判**
  （`0` 是合法值 = 已無可退；refund-repository.ts:172-180 逐字）
  ⇒ 寫 `if (!remaining)` ⇒ **R2 = 0 與 R2 = null 走同一條路** ⇒ 那一發永遠不會紅
✅ **建議走 SQL 函式直讀** —— 它**免疫這個坑**（沒有 TS 那層的 0-vs-null 轉換）
```

## 10. 🔴 我三輪的失敗形狀(**這一節不在任何 findings 裡, 而它是下一個人最可能重蹈的**)

**一句話:每一輪的折法, 都製造了下一輪的洞。**
```
R1 → R2：R2 打中的 6 條裡，**有 2 條是我折 R1 時新寫的**
   · §4a 我用了一個【我沒查過語意的欄位】（seq 是 per-refund，不是全域水位）

   · 我補的是「這個 oracle 完不完整」，**沒補「這個 oracle 量的是不是本片」**
```

### 那個病的形狀(同一個, 四次)
> **折 finding 時【換了一個說法】, 而沒有給出【怎麼證明它】。**

**⇒ 而處置(主視窗 2026-08-29 指定, v3 起照做)**:
```
✅ 每一條驗收旁邊要寫【它怎麼被證明】，而不是它宣稱什麼：
   · 這一格能演哪兩個世界？· 那兩個世界只差一個變因嗎？【差在哪】要指名
   · 【誰讀那個變因】？
🛑 而寫不出「怎麼證明」的 ⇒ **不要折它**，列成「這一格我證不了」+ 缺的是哪一道檢查
📌 一條標明「我證不了」的驗收，不會在下一輪被打；一條換了說法的會。
```

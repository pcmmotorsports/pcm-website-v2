## 1. 🔴 先更正我自己(#27 plan §4 有一句話的機制是錯的)

我在 `2026-08-14-27-audit-log-viewer-plan.md` §4 寫:
> 「必須新開一支 migration…並**同時把上面兩條斷言的終態改寫**,否則新舊斷言互相矛盾。」

**「互相矛盾」不成立,而且「改寫」是錯的做法。**
migration 是 **forward-only、只跑一次**(`20260712210000:140` 逐字「Rollback(Supabase **forward-only**、僅供參考…)」)⇒
`:113-117`、`:127-133` 那兩個 `DO $$` 是**當時 apply 那一刻的檢查**,**不會再跑**,所以**執行期不存在矛盾**。
而去編輯一支**已經 apply 過的** migration = 改歷史,是明文禁止的。

**正確做法(house pattern,有先例)**:D0 寫**自己的**新斷言、陳述**新的終態**,並在檔頭寫明「本支取代 `20260712210000` §4 的最小權限意圖」。
先例 = `20260807120000`(A9v,撤 `order_status_options` 寫權):
- `:10` 逐字「**REVOKE,不是 DROP**:函式與表都留著…可逆、留回滾餘地」。
- `:118` 斷言的是**攤平後的完整授權字串**(`service_role:SELECT:false`),不是只數筆數。
- `:106` 有一條**誤殺正控**:「`admin_update_order_workflow` 的 service_role EXECUTE 不見了(合法改單會死);拒繼續」。
- `:77-80` 甚至**誠實標註某條斷言在本檔內恆真** —— 恆綠格自己先講出來。

⇒ **D0 的斷言清單(寫進 plan)**:①`service_role` 終態恰 `INSERT` + `SELECT`,其餘 5 權限零 ②`anon`/`authenticated` 7 權限仍全零 ③**誤參正控:`INSERT` 仍在**(寫入路徑是 19 支 writer 的命脈,誤殺它等於後台所有寫入操作連帶死)④欄級 ACL 零殘留。

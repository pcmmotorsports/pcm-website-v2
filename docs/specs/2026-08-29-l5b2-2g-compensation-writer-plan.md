**建一支新的 SECDEF 函式,它是 `payment_refunds` 這本帳【唯一】的寫入端。**

## 1. ① 改什麼

**一支 migration,一個新函式。不動任何既有物件。**

| 項 | 內容 |
|---|---|
| 新增 | `public` 的補償寫入 RPC(函式名於實作時定,**定了要同步做第 ⑤ 節**) |
| 動既有 | **零**。不 `ALTER`、不 `DROP`、不 `CREATE OR REPLACE` 任何既有函式或表 |
| 寫入的表 | `payment_refunds`(父列)+ `payment_refund_events`(`sent` 事件) |
| 讀取 | `payment_charge_attempts`(`superseded_at` / `settle_attempt_count`)、`orders`(**只鎖,不改**) |

**本體順序(母 plan 片表 `:576` 逐字)**:
```
advisory lock → 否決條件 → 開父列 + `sent`（一次一列）
→ 鍵沿用既有式子（含 `extensions.`）→ `sent` 前持久化 `refunded_amount` baseline
→ SECDEF 全套（search_path='' / REVOKE PUBLIC / GRANT / owner / COMMENT）
```

### 🔴 1a. 鎖的形狀是**照抄**,不是重新設計 —— 而它有一個實錘
`20260812170000:711` COMMENT 逐字(**這是 2f 上線時釘下的三方契約**):
> ①步 2 後、步 3 前取 order 級 advisory(三方共用序列化點);
> 鍵式子 = `pg_advisory_xact_lock((''x''||substr(replace(order_id::text,''-'',''''),1,16))::bit(64)::bigint)`,
> **三方必須逐字相同**,不經 `hashtext` = 避 32-bit 碰撞讓不相干訂單共用隊伍;
> **必須早於步 3**,否則持 orders 列鎖等 advisory × close 持 advisory 等 orders = **AB-BA 40P01**。

🔴 **而列鎖的型別也是釘死的**:`:567` 逐字「**`FOR NO KEY UPDATE`** —— `FOR UPDATE` 與 FK RI KEY SHARE **死結 40P01 實錘**」。
⇒ **本片不得自行選鎖**。三方(`close_released_attempt` / `admin_initiate_order_refund` / 本片)**逐字相同**。

### 1b. 否決條件 = 母 plan 核心點 2 的十三條合取
1 `superseded_at IS NOT NULL` · 2 `queryStatus ∈ {0,2}` · **3a** `numberOfTransactionsReported === true` ·
**3b** 兩個計數各為 1 · 4 `recTradeId` 等於目標 · 5 幣別 TWD **且必須有值** · 6 `record_status ∈ {0,1,2}` ·
7 `refunded_amount` 欄存在(**嚴禁 `?? 0`**) · 8 `record.amount !== 0` · 9 強識別可得 ·
10 **無未結案 refund** · **11** `orderNumber` 等於 `order_id` · **12** `bankTransactionId` 相符 ·
**13** `originalAmount` 等於應收(**缺欄不得放行**)

⚠️ **這十三條的【實作】在 `2i`,不在本片。** 本片只做**在鎖下重驗**那幾條與資料庫狀態有關的(1 / 10 / lease token 當前性)。
🔴 **而本片開工前必須先做一件母 plan 指定、而【沒有人做過】的事** —— 見 §6。

## 4. ④ Rollback

**本片是「新增一支不存在的函式」⇒ rollback = `DROP FUNCTION`,而它比聽起來安全。**

```
BEGIN;
  -- 閘：本函式若已經寫過任何一列 payment_refunds ⇒ **abort，不准 DROP**
  --     （已經寫了 sent = 錢可能已經在外面動了 ⇒ 見母 plan §4b「應用層 rollback 的不可逆邊界」）
  DROP FUNCTION public.<2g writer>(...);
COMMIT;
```
🔴 **必須是【單一交易腳本】** —— 母 plan v8 定案(`:718`),理由是實測:
本 repo 的 rollback 慣例是「檔尾座標 + 逆序手動執行」= `psql -f` 逐句 autocommit、**無 `ON_ERROR_STOP`**
⇒ `DO … RAISE` 之後**後續每一句照跑**,閘等於被滾過去。
⇒ **禁止只抄座標逐句手跑。這句要寫進本片檔尾的 rollback 段本身。**

### ⚠️ 4a. 而「rollback 掉本片」**不等於回到原狀**
母 plan §4b 逐字:已寫 `sent`、或落 `result_unknown` 的 refund,**錢可能已經在外面動了**。
⇒ **回退後仍必須有人對帳。**而承接它的「人工佇列四件」是 **2d 的驗收條件** —— 而 2d 已 apply。
⚠️ **那四件到底做完沒,本檔【未驗】。**

## 5. 🔴 ⑤ 那個空陣列 —— **它是本片的一部分,不是後續**

```
scripts/l5b2-2e-rollback.sql:68    p.proname = ANY (ARRAY[]::text[])
scripts/l5b2-2f-rollback.sql:136   p.proname = ANY (ARRAY[]::text[])   -- 顯式名單：2g 必填
```
`l5b2-2e-rollback.sql:49-51` 逐字:
> 🔴 **加一份顯式函式名單**…**2g 實作時必須把自己的函式名填進去**,那才是真正的不變量。
> ⇒ 這條是**寫給 2g 作者的前置義務**;正規式只是它沒被履行時的網子。

**那道閘的職務** = 「2g 的 writer 在庫時,阻止 `2e` 或 `2f` 被單獨 rollback」。
現在只剩**啟發式文字掃描**那一半,而它**自陳**會靜默放行 5 種形狀
(動態 SQL / owner 在 psql 直接 DML / 其他 schema / 只 `UPDATE` 不新增列 / 關鍵字拆開)。

> 🔴 **2g 一落地,那個不變量【當場】從「無所謂」變成「必須成立」。**

📌 **⇒ 而那一秒不會有任何東西提醒任何人** —— 這是一個**條件式的洞**:
**它的觸發條件是本片的落地,而觸發者(本片的作者)不會知道自己是觸發者。**
⇒ **所以它寫在本 plan 的正文,不在附註。**

**驗收**:填完之後跑一發突變 —— 把 2g 的函式名從陣列裡拿掉、庫裡留著那支 writer
⇒ 兩支 rollback 都必須 **abort**。**沒跑這發,那兩行等於沒填。**

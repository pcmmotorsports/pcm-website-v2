## §1 兩張紙的使用者與場景 —— **不同的人、不同的地方、不同的失敗代價**

## §5 失敗態 —— 🔴 **設計稿不處理這些,實作時就會自己亂長**

| 態 | 現行行為 | 設計端要給什麼 |
|---|---|---|
| **整張不能印**(訂單已取消 / 箱已作廢 / 清單沒載完 / 箱單對不上 / 收件資料缺 / **訂單零品項**) | 印一段警告、**不印品項表** | 那段警告的版面位置與份量。**它比內容重要** —— 印出一張看起來正常的紙,員工就會照做 |
| **數量「不知道」** | 印文字「數量資料尚未就緒 / 這一項不要揀」,**絕不補 0** | 文字比數字長很多 ⇒ 那一欄要容得下一句話 |
| **這次不用揀(數量 0)** | 用**字**說,不放大的 `0`,且**不給勾選框** | 同上,且要與「有數量」那列在視覺上分得開 |

| 🔴 **一箱多單** | `shipments` **沒有 order_id**,一箱可含多張訂單 | 紙上只列**本單**在這箱裡的品項 ⇒ **要有一句話講明「同一箱可能還裝著別單的東西」**,否則客人以為少寄 |

## §6 🔴🔴 「一張紙兩用」的取捨 —— **兩案的代價都寫出來,讓設計端選,不要讓它猜**

Sean 拍板合併、且接受後果。**但「操作上一樣」不等於「內容一樣」** ——
同一張紙既在倉庫被翻、也進客人的箱子。**兩種版面各自的代價**:

```
甲案 一張紙、一種版面，兩用
  倉庫看到：金額、公司抬頭、客人公司名與統編
  客人看到：勾選框、應揀數量、內部箱號，而且那張紙【被人用筆勾過】
  🔴 代價：寄給客人的是一張塗改過的單據；而倉庫桌上有金額
  ✅ 好處：只有一種紙、一套版面、員工不會拿錯

乙案 一支元件、兩個 variant（同資料源，印兩次）
  倉庫版：無金額、無抬頭、有勾選框與應揀量
  客人版：有金額、有抬頭、無勾選框
  ✅ 好處：「絕不出現金額」那道守門可以【保留在倉庫版上】⇒ §2 那個對立消失
  🔴 代價：多一個 variant 維度 ⇒ 每一道擋法都要標「哪個 variant 適用」；
          且 Sean 說的是「兩者是一樣的東西」，兩種樣子可能不是他要的
```
⚠️ **這一題不是設計偏好,是營運題** —— **列印線判「不由設計端單方面決定」**,
但**設計端要在提案裡明說自己假設了哪一案**,否則實作端會照另一案接。

## 0. 一句話總結

新竹提供**兩組獨立服務**:①**查貨**(物流追蹤)②**出貨/託運單列印**。
兩者**分開申請、分開認證**,都要找「配合站所的電腦負責人」拿申請表單。

**標籤有兩條路**:用新竹回傳的圖(省事、一次上限 5 張)、或自己照規格畫(無張數限制、需多叫一支到著碼 API、且**做好要送新竹資訊處確認**)。

## 2. 服務一覽

### 2.1 查貨(物流追蹤)

| 模式 | URL | 說明 |
|---|---|---|
| 網頁串接 | `https://hctapiweb.hct.com.tw/phone/searchGoods_Main.aspx?no=<加密字串>&v=xxxxxx` | 產生加密網址,**可直接放我們網頁供客人點**,由新竹顯示貨況。最省事 |
| 多筆 XML | `https://hctapiweb.hct.com.tw/phone/searchGoods_Main_Xml.ashx?no=<加密XML>&v=xx` | **請求類型須 POST**。回傳加密 XML,解密後自行呈現 |

**加解密方式與金鑰:文件未載明,「申請後提供」;C# sample code 亦於申請後提供。**

**限制(逐條抄自文件 §2.1.4):**
1. 一般貨況**僅供查詢 30 天內**資料;歷史查詢須聯繫原申請營業所
2. **訂單編號與 10 碼貨號只能擇一查詢**,申請時即選定,要改須聯繫營業所
3. 用訂單編號查詢須綁定特約客戶帳號及客戶代號
4. XML 多筆查詢**單次上限 100 筆**,且須等結果回傳後才可再次提交
5. **每日凌晨 03:40–04:30 系統維護**,期間無貨況更新
6. 異常聯絡電話:文件載 `02-2837-1122 #5123 許先生`(⚠️ 未驗證是否仍有效)

**貨況對照表:** 文件 §2.1.5 有完整中文貨況對應(集貨 / 卸集貨 / 發送 / 到著 / 配達 / 持回 / 客戶不在 / 地址錯誤 / 查無此人 / 拒收退回 / 委外配送中 …),實作時逐字抄,不自行改寫文案。

### 2.2 出貨 / 託運單列印

**服務 URL:** `https://Hctrt.hct.com.tw/EDI_WebService2/Service1.asmx`(SOAP)
**🔴 每支服務都有 `_Json` 與 `_XML` 變體 ⇒ 可走 JSON,不必處理 SOAP envelope。**

| 服務 | 用途 |
|---|---|
| `TransData()` | 上傳託運資料 → 取得**貨號、到著站、標籤圖片字串** |
| `UpdData()` | 修改重量(傳新竹貨號 + 訂單編號) |
| `TransReport()` | 確認當日出貨、列印託運總表(文件註「18 時間上傳」) |
| `QueryEDELNO()` | 用訂單編號查已配發的貨號 |
| `R_TransData()` | **逆物流**:派員到客人處收退貨 |

**認證:** `Company` + `password` 兩個字串參數。
**測試帳號(文件明載):** 公司名稱 `test` / 密碼 `test1`。

## 3. `TransData` 欄位(出貨主力)

### 傳入

| 欄位 | 說明 | 長度 | 備註 |
|---|---|---|---|
| `epino` | 訂單編號 | Char(30) | **必要** |
| `ercsig` | 收貨人名稱 | Char(40) | **必要** |
| `ertel1` | 收貨人電話 1 | Char(15) | **必要** |
| `ertel2` | 收貨人電話 2 | Char(15) | |
| `eraddr` | 收貨人地址 | Char(100) | **必要** |
| `ejamt` | 件數 | Char(4) | **必要,最小 1** |
| `eqamt` | 重量 | Char(5) | **必要,小數進位到整數** |
| `esdate` | 出貨日期 | Char(8) | 預設今天 `YYYYMMDD` |
| `escsno` | 客代 | Char(11) | 預設值 |
| `esstno` | 出貨站 | Char(4) | 預設值 |
| `edelno` | 新竹貨號 | Char(10) | 不給則系統自行配號 |
| `etcsig` / `ettel1` / `ettel2` / `etaddr` | 出貨人名稱 / 電話 1 / 電話 2 / 地址 | 40/15/15/100 | 預設值 |
| `eddate` | 指定日期 | Char(8) | 預設空白;**小於今日視為空白** |
| `eqmny` | 代收貨款 | Char(5)〔Json 版為 Char(8)〕 | 預設 0 |
| `eprdct` | 傳票類別 | Char(2) | 預設月結 `11`;到付 `21`、現收 `31` |
| `emark` | 備註 | Char(100) | |
| `eprdcl2` | 商品種類 | Char(3) | 預設 `001` |
| `egamt` | 報值金額 | Char(5) | 保值貨物應報值,**加收報值金額 1% 為報值費** |

> ⚠️ **文件內部不一致**:`eqmny` 在 DataSet 版寫 Char(5)、Json/XML 版寫 Char(8)。實作前以測試環境實跑為準。

### 回傳

`Num`(傳送序號)/ `success`(**新增 `Y` · 修改 `R` · 失敗 `N`**)/ `edelno`(新竹貨號)/ `epino`(訂單編號)/ `erstno`(到著站號碼)/ `eqamt`(重量)/ **`image`(標籤圖片字串)** / `ErrMsg`

> ⚠️ **文件表格有筆誤**:DataSet 版回傳欄位表把「到著站號碼」也寫成 `epino`,但 Json/XML 版寫 `erstno`,範例亦為 `erstno`。**以 `erstno` 為準。**

**`image` 格式:** hex 字串 → byte[] → Bitmap(文件附 C# 轉換範例)。文件註明轉為 1bpp 索引色(黑白單色)。

### 🔴 批次限制(直接影響 UI 設計)

- 「傳送一批資料請不要超過 **30 筆**」
- 「**若使用回傳圖檔,一次上限為 5 筆**」← **後台批次出貨必須自動切批**
- SOAP 版需調大 `maxBufferSize` / `maxReceivedMessageSize`;JSON 版需調大 `maxStringContentLength`(一張圖轉字串約 2 萬多字元)

### 🔴 唯一性規則

| 鍵 | 規則 |
|---|---|
| 新竹貨號 + 訂單編號 | 當日重複上傳 = **視同更正資料內容**(不是報錯) |
| 訂單編號 | **同一個 `esdate` 內不可重複** |
| 新竹貨號 | **100 天內不可重複** |
| 逆物流貨號 | **3 個月內不可重複**;且**貨號必須 2 開頭** |

> **對 PCM 的影響(2026-07-28 定案,取代舊「訂單編號+後綴」構想):** 送 `epino` 的是**包裹自身的 `shipment_reference`**(6 碼、全表唯一、與 PCM 訂單編號完全脫鉤;產號合約見 E10 總規劃 v2 §8.5)。
> 全表唯一嚴格強於「同一 esdate 不可重複」⇒ 分批出貨每批各自有 reference,**不會撞**;
> ✅ **後綴 `-1/-2` 已由 Sean 拍 Q19=A 正式作廢**(reference 本身唯一,後綴要解決的問題不存在)。
> 🟡 唯一殘餘:`epino` 的**允許字元**本文件未載 —— Sean 申請 API 時問新竹站所。

## 4. 其他服務欄位

| 服務 | 傳入 | 回傳 |
|---|---|---|
| `UpdData` | `epino` + `edelno` + `eqamt`(三者皆必要) | `Num` / `success`(修改 `R` 失敗 `N`)/ `edelno` / `epino` / `eqamt` / `ErrMsg` |
| `TransReport` | `epino` + `edelno` | `Num` / `success` / `edelno` / `epino` / `ErrMsg` —— **無 `image`,故總表須自行排版** |
| `QueryEDELNO` | 訂單編號,多筆以 `,` 分隔(**訂單編號中不可含逗號**) | `success` / `edelno` / `epino` / `ErrMsg` |

### 逆物流 `R_TransData`

語意反轉:`ercsig`/`ertel1`/`eraddr` = **退貨人**(去跟誰收),`etcsig`/`ettel1`/`etaddr` = **收貨人**(退回到我們)。
額外欄位 `edelno2` = 原正物流出貨查貨號碼。
限制:件數只能 1(總長運費);重量若用總長只能 `60/90/120/150/151-999`。

## 5. 自己畫標籤(路線乙)

### 5.1 需要的第三支 API:集貨註區比對

**URL:** `http://is1fax.hct.com.tw/Webedi_Erstno_NEW2/WS_addrCompare1.asmx`
**測試帳號:** `TEST2`
**服務:** `addrCompare_string`(單筆)/ `addrCompare_Json`(多筆)
另有 URL 直呼版本 `Addr_Compare.aspx`,**傳入中文需使用 Big5 編碼**。

**傳入:** `USER` / `ADDR`(100)/ `ESDATE` / `TEL` / `TEL2` / `EPRDCL` / `EMARK` / `ESCSNO` / `EJAMT` / `EQAMT` / `EQAMTTYPE` / `ELAMTTYPE`

**回傳關鍵欄位(標籤必印):** `CODE1` 類別 / `CODE2` 到著簡碼(3 碼,靠右)/ `CODE3` 衛星區(1 碼)/ `CODE4` 註區(3 碼,**印黑底白字**,無值留空)/ `CODE5` 疊區(1 碼)/ `CODE6` **QRcode 內容** / `MDCODE1-3` MD 到著碼 / `AREAS`(`*` = 有聯運區)

**電話格式要求:** 區碼前一定要帶 0、不可填分機。
**站所自取:** `ADDR` 填「站所名稱 + 站止」(例:台北站止、大園站止)。
**超商店取:** `EMARK` 填關鍵字(全家 / 萊爾富 / OK / 7-11),位置不拘。

### 5.2 標籤欄位(共 24 項)

到著碼四段(簡碼 / 衛星區 / 註區 / 疊區)、物流單號條碼、物流單號數字、商品種類、收貨人名稱電話地址、備註、訂單編號、出貨站所簡碼、寄件人名稱電話地址、件數、重量、代收貨款或元付到付、指配日期(MMDD)、QRcode、MD 到著碼三段。

**代收貨款欄邏輯:** 代收貨款 > 0 → 印「代收」+ 金額;否則依付運費別印「元付」或「到付」。

### 5.3 條碼規格(硬性)

| 項目 | 規格 |
|---|---|
| 一維條碼 | **CODABAR**,純數字 10 碼,**前後用 `D` 包起來** |
| 物流單號 | 10 碼 = 單號 9 碼 + 檢查碼 1 碼;**檢查碼 = `MOD(前 9 碼, 7)`** |
| QRcode | Version 1 / 21×21 modules / ECC Level **M** / 密度 0.8mm / 16.8×16.8mm / **淨空區 3.2mm** |

> 🔴 **檢查碼規則公開 ⇒ 我們可在送出前自行驗證貨號正確性**,不必等 API 退件。

### 5.4 設備與送審

- 建議設備:**雷射印表機或熱感標籤機**
- 🔴 **標籤做好要送新竹資訊處確認內容**(文件 §2.1 與 §2.2 兩處明寫)

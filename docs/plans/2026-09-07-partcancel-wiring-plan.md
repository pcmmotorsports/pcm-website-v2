## §2 我提的第三條路:**在 `order_cancellation_items` 上加 statement-level AFTER INSERT trigger**

### 🔬 它成立的三個事實(全部是開檔量到的, 附行號)
1. **部分取消【一定】會寫那張表**:`admin_cancel_order` 最新代
   (`20260830020000:115` 起)`:502` 逐字
   `INSERT INTO public.order_cancellation_items (cancellation_id, order_id, order_item_id, cancelled_quantity) SELECT …`
2. **一次取消 = 一發 INSERT**(不是逐列):部分那支 `:502-505` 與整單那支 `:507-513` **都是單一 `INSERT … SELECT`**
   ⇒ 🔵 **statement-level trigger 每次取消【恰好】醒一次** —— 不必自己去重, 也不會 N 列跑 N 遍。
3. **寫入順序是量到的**:`:497` 先寫 `order_cancellations` ⇒ `:502/:507` 寫品項
   ⇒ `:525` 才算 `v_closed` ⇒ `:532-533` 才 `UPDATE public.orders SET cancelled_at = pg_catalog.now()`。
   ⚠️ **行號的一個自踩, 記在這裡**:我第一版寫的是 `:383 / :388 / :411 / :418`——
   那是我用 `awk 'NR>=115 && NR<=560'` 切出來之後**視窗內的相對行號**, 不是檔案行號(差 114)。
   ⇒ 📌 **一個相對行號長得跟絕對行號一模一樣, 而它會把下一個人送到錯的地方。**
   ⇒ 已用 `grep -n <整支檔>` 重量一次訂正。

### ✅ 它比 09-05 §5 提的「在 A8a2 裡明呼一次」好在哪
09-05 §5 的接法要 **`CREATE OR REPLACE` 那支 445 行的 `admin_cancel_order`**。
🔴 **而【不要那樣做】是 `20260901080000:50-56` 自己寫下的理由**,逐字:
「`CREATE OR REPLACE` 整支 = 回捲風險(把後幾代的行為整個倒回去,**而三綠不會紅**)」。
⇒ 📌 **兩份 plan 在這一點上是牴觸的, 而牴觸點沒有被任何一份指出來。** 本檔指出來。
✅ 另外:掛 trigger 就自帶 `20260901080000:57-58` 想要的那個開關 ——
`ALTER TABLE public.order_cancellation_items DISABLE TRIGGER …`,**不必重新部署**。

### 🛑 它的代價(先講, 不要等審查抓)
1. **整單取消會走到兩條路** —— 新 trigger(在 `:502`)先醒, 既有 trigger(在 `:533`)後醒。
   ⇒ **必須先答:第二次進來時 `ON CONFLICT (order_id, rail) WHERE voided_at IS NULL AND settled_at IS NULL`
   (`20260901080000:449`)是 `DO NOTHING` 還是 `DO UPDATE`?** 兩者的行為完全不同, 而**我還沒讀那一段**。
   ⇒ 這是 §3 第一題。
2. **新 trigger 醒的那一刻 `orders.cancelled_at` 還是 NULL**(順序見上, `:533` 在 `:502` 之後)
   ⇒ **金額函式若讀 `cancelled_at` 判「是不是整單」就會判錯** ⇒ 它必須改用
   「剩餘未取消數量 = 0」當判準。⚠️ 這一條要與 09-05 plan `§2b` 的式子對一次, **我還沒對**。

## §3c 🔴 codex `gpt-6-astra` plan 層 R1:**三條 must-fix,全部把 §3b 的結論往回收**

> 三條我都逐字複驗過(附行號),**全部成立**。⇒ 📌 **§3b 那句「①已答」要降級成「①答了一半」。**

### MF1 🔴🔴 `cancellation_id` 對部分取消會寫成 **NULL**,不是「最新那筆」
`pcm_pending_refund_open_for` 找取消單的方式(`20260905070000:211-213` 逐字):
```
SELECT count(*), (array_agg(c.id))[1] INTO v_n, v_cid
  FROM public.order_cancellations c
 WHERE c.order_id = p_order_id AND c.created_at = v_cancelled_at;
```
而部分取消 `orders.cancelled_at` 是 **NULL** ⇒ `c.created_at = NULL` **永遠不成立** ⇒ `v_n = 0`
⇒ 同段 `:222` `v_cid := NULL`。
🛑 **⇒ 我在 §3b 寫的「`cancellation_id` 跟著換成最新那筆是已定義的行為」對【部分取消】不成立** ——
那句話描述的是 `DO UPDATE SET cancellation_id = EXCLUDED.cancellation_id`(`:241`),
**而 `EXCLUDED.cancellation_id` 本身就是 NULL。**
⇒ 📌 **我核對了那一行在做什麼, 而沒有核對餵給它的那個值從哪裡來。**
✅ **修法要明定**:接線那一側**把這次的 `cancellation_id` 直接傳進去**
(新參數 / 或由新 trigger 自己寫), **不能只改入口閘 + 傳 `true`。**

### MF2 🔴🔴 重算之後**消失的那一軌**,舊的待退款列會**留著**
反例(codex 給的, 我照抄不改寫):收款 5,051 ⇒ 先取消 51 ⇒ 待退 51;
再取消 1 ⇒ 剩餘應收 4,999 + 補收運費 100 = 5,099 ⇒ 應退 `max(0, 5051−5099)` = **0**
⇒ `pcm_pending_refund_amounts` **回零列** ⇒ `open_for` 那個 `INSERT … SELECT … ON CONFLICT` 
**一列都沒有 ⇒ upsert 整段不執行** ⇒ 🛑 **舊的那筆「待退 51」原封不動留在表上。**
📌 **`ON CONFLICT DO UPDATE` 只管【還在的那幾軌】—— 它對【不見了的那一軌】零作用。**
✅ **要定義「怎麼收尾」**:把該軌現存那一列 `voided_at` 標掉(還是別的作法)——
而那是一個**行為決定**, 本 plan **不猜**, 列進 §3 的必答題。

### MF3 🔴 整單判準**不可以**換成「剩餘件數 = 0」,要保留 `cancelled_at IS NOT NULL` **或**
逾期取消那條路(`20260809160000:173` / `20260828060000:234`)**只 `UPDATE orders SET cancelled_at`,
一列 `order_cancellations` / `order_cancellation_items` 都不寫**
(`pcm_pending_refund_on_cancel` 的 COMMENT 早就記過這件事)。
⇒ 那種單的「剩餘件數」是**原本的件數, 不是 0** ⇒ 若判準只看剩餘件數,
取消後晚收 1,000 時仍會扣掉原單應收 ⇒ 🛑 **漏開全額退款。**
✅ 判準必須是 **`cancelled_at IS NOT NULL` 或 剩餘件數 = 0**,兩條**都要**。
📌 **這一條的形狀**:我把一個判準**換掉**而不是**擴充**, 而被換掉的那一條涵蓋著一條我沒想到的路。

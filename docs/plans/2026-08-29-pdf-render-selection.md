## 二、🔴 先講一件會改變選法的事:**字型問題有【兩半】, 而選型只決定其中一半**

板 `⟦b4-PRINTFONT1⟧` 講的是「Vercel 是 Linux 容器、沒有中文字型」。當場量:
```
apps/admin/src/app/print/print-a4.css:278-280
  --pd-body: 'Noto Sans TC', 'PingFang TC', 'Microsoft JhengHei', 'Helvetica Neue', sans-serif;
  --pd-disp: 'Helvetica Neue', 'Helvetica', 'PingFang TC', 'Noto Sans TC', sans-serif;
  --pd-mono: 'SF Mono', 'Menlo', 'Consolas', 'DejaVu Sans Mono', monospace;

真正的 @font-face 宣告（git grep '@font-face' -- '*.css'）           ⇒ 零命中（負對照 'zzzface' ⇒ 0）
⚠️ 板 207 記的「@font-face 命中 1 檔」＝ page-measure.test.tsx:110 的【註解字面】，不是宣告
```
⇒ **那四個字型名一個都沒有隨檔案送出去 —— 它們全靠「跑的那台機器剛好裝了」。**

**兩半是這樣分的**:
```
下半（容器）  伺服器自己開一個瀏覽器去畫  ⇒ 容器四種字型都沒有 ⇒ 🔴 豆腐字
上半（客戶端）客人／員工自己的瀏覽器去畫  ⇒ Mac 命中 PingFang TC、Windows 命中 Microsoft JhengHei
                                          ⇒ ✅ 兩大平台都接得住
```
🔴🔴 **⇒ 選「伺服器畫」= 把一個【現在不存在的問題】買進來;選「客人自己畫」= 下半整個消失。**
⚠️ **而上半沒有完全消失**:Linux 桌機客人、或裝了怪字型的機器仍可能落到 `sans-serif`。
**未量**:客人端 OS 分佈(我們沒有這個數字)。

## 三、三個選項(照「最懶的先試」爬)

### 甲 · **不產檔 —— 給客人一頁列印版, 他自己按「儲存成 PDF」** ⭐ 建議
```
做什麼  新增 /account/orders/<id>/print 一頁（沿用 print-a4.css）＋一顆呼叫 window.print() 的鈕
新相依  0
新字型  0
容器    完全不參與 ⇒ 字型下半消失
版面    922 行 CSS 直接復用，不重畫
```
- ✅ 「另存 PDF」是**瀏覽器內建**:macOS/Windows/Chrome/Safari/Edge 都有;iOS 與 Android 也走得通(分享→列印→儲存 PDF)。
- 🔴 **代價要明寫**:客人拿到的**不是一個 `.pdf` 下載**,是一個**列印對話框**。多按一到兩下。
- ⚠️ **未量**:手機上那條路實際幾步、長輩客人會不會卡住 —— **我沒有量過, 不要把它寫成「一樣好用」。**

### 乙 · **伺服器開無頭瀏覽器印成真 PDF**(`@sparticuz/chromium` + `puppeteer-core`,或 Playwright)
```
做什麼  一支 route 打開自己的列印頁、呼叫 printToPDF、回 application/pdf
新相依  2（其中一支是壓過的 Chromium binary）
新字型  🔴 必須把中文字型檔一起塞進去，否則就是豆腐字
版面    同樣復用 922 行 CSS
```
- ✅ 客人點一下就下載到一個 `.pdf`。**寄信附件**也只有這條路做得到。
- 🔴 **買進三個新問題**:部署體積、冷啟動、以及**字型下半**。
- 🔴🔴 **而最貴的一格是量測**:本機一定看得到正確中文 ⇒ **本機驗證、三綠、截圖對這一格全部零判別力**,只有真實部署分得開。

### 丙 · **用 PDF 函式庫自己排版**(`pdf-lib` / `@react-pdf`)
```
🛑 不建議。那 922 行 CSS 與已對標 OD 稿的版面【全部作廢、重畫一次】，
   而重畫出來的東西與 Sean 在 OD 上調過的那份會不一樣，且沒有機械訊號分得出來。
```


🔴 **而有一件事會直接推翻這個順序**:**如果出貨/付款信要【夾帶】明細附件**,那非乙不可 —— 信裡塞不了列印對話框。
⇒ **這是唯一一個問 Sean 才知道的前提。**

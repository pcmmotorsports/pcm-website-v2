## §1 🔴 上限與砍法 —— 而這一格是本檔最硬的一節

`HCT_MAX.remark = 100`(`hct-trans-data.ts:95`),而截斷走 `clip()`:

```ts
function clip(v: string, max: number): string {
  return v.length <= max ? v : v.slice(0, max);   // hct-trans-data.ts:204-206
}
```

### 1-a 🛑 `v.length` 是 **UTF-16 單位**,不是 byte,也不是「看得見的字」

| 內容 | `v.length` | UTF-8 bytes | 看得見幾個字 |
| --- | --- | --- | --- |
| `ABC` | 3 | 3 | 3 |
| `派達有限` | 4 | 12 | 4 |
| 一個 emoji(如 🚚) | **2** | 4 | 1 |

🔴 **⇒ 而 `slice(0, 100)` 可能把一個【代理對】切成兩半** ⇒ 產生一個孤兒 surrogate。
⚠️ 而 `xmlEscape` **不剝它**(它只剝 C0 控制字元與 `U+FFFE/FFFF` —— `hct-client.ts` 逐字)
⇒ 📌 **一個 not-well-formed 的信封 ⇒ 新竹回 `soap:Fault` 或直接斷 ⇒ 那一箱卡成 `unknown`。**
🔵 **今天觸發不到**:料號與訂單編號都是 ASCII,而商品名今天沒有 emoji。
🛑 **而「今天沒有」不是「不會有」** —— 本片自己組字串 ⇒ **本片要負責不產生那個形狀。**

### 1-b ✅ 砍的順序 —— ⛔ **第一版是錯的,codex R1 抓到,主視窗同日改裁**

⛔ ~~骨架 = `[PCM] ` + 訂單編號 + 料號 + 後綴,而**後綴在尾巴**~~
🔴 **出事輸入(codex 舉的,我複驗成立)**:料號 90 個字元 · `itemCount: 3`
```
⇒ 紙上只剩 [PCM] CH6D75 + 88 個 S    ⇒ 📌「等共 3 項」【整個消失】
```
⚠️ **而手動建單那條路【不限制料號長度】** ⇒ 那個輸入真的進得來,不是理論。

✅ **三層,而分層的判準是【司機要什麼】**:
```
🔒 骨架(不可砍)   [PCM] + 訂單編號 + 「等共 N 項」/「等 N 單」
🔵 有固定上限      料號 —— 24 碼點, 超過【砍它自己】, 不吃別人的額度
🟡 吃剩下的        商品名 —— 額度用完砍到 0 也不動上面兩層
```
📌 **判別句**:**這一格的讀者是司機。他要的是【這箱是誰的 · 有幾項】** ——
那兩件都在骨架裡;**料號與品名是【方便】不是【憑據】**,所以它們才是可砍的那一邊。
🔴 而砍字一律**用「碼點」不是 `v.length`** ⇒ 代理對不會被切半。

**實際輸出(2026-09-10 實跑)**:
```
正常            [PCM] CH6D75 前叉油封 SKU-1234                         34 byte
多品項          [PCM] CH6D75 前叉油封 SKU-1234 等共 3 項                47 byte
料號 90 字      [PCM] CH6D75 前叉油封 SSSSSSSSSSSSSSSSSSSSSSSS 等共 3 項  63 byte  ← 後綴活著
超長品名        [PCM] CH6D75 前前前…前 SKU-1234 等共 3 項                98 byte
多單            [PCM] CH6D75 等 2 單 前叉油封 SKU-1234 等共 2 項         57 byte
```

### 1-c 🛑 而【真正的上限是不是 100 個中文字】—— **量不出來**

規格寫 `String(100)`。而那是 **100 個字元**還是 **100 個 byte**,PDF 沒說。
```
🔴 若是 100 byte ⇒ 33 個中文字就爆
⇒ 而爆的時候新竹回什麼, 我們沒有看過
```
⚠️ **而 `emark` 那一欄【一次都沒有被真的送出去驗過】** ——
2026-09-10 第一箱送的是 `emark: ""`(空字串,實測)。
⇒ 📌 **⇒ 本檔對「100 是什麼單位」不下結論。第一發送出去要有人看它回什麼。**
✅ **而保守做法**:先按 **UTF-8 byte 算,上限抓 100 byte**(≈33 個中文字)——
🎯 兩種世界它都不會爆,而代價只是**中文商品名被多砍一些**。

## §2 🔴 一箱多個品項 / 多張訂單 —— 兩個做法,要 Sean 挑

Sean 寫的是單數「**該商品**」。而**一箱可以裝多樣,也可以跨多張訂單**:
```
shipment-repository.ts:857 逐字:「回傳的箱子**可能還裝著別單的品項** —— **箱子掛客人不掛訂單**」
```

### 2-a 今天的實數(唯讀正式庫 2026-09-10)
```
4 箱 · 每一箱【1 個品項】· 每一箱【1 張訂單】
🛑 而分母是 4 ⇒ 那是「還沒發生過」, 不是「不可能」
🔵 而其中兩箱(XS6XVY · ZN2HDP)【對到同一張訂單 C8MYDB】
   ⇒ 📌 「一單多箱」已經發生了, 而「一箱多單」還沒有
```

### 2-b 兩個做法,各自長什麼樣

**甲:只帶第一項 + 總數**
```
[PCM] CH6D75 前叉油封 SKU-1234 等共 3 項
單品項時 ⇒ [PCM] CH6D75 前叉油封 SKU-1234
```
· ✅ 短,絕大多數情況下不會爆 100
· 🔴 而司機看到的品名**可能不是他手上那箱最重的東西**
· 🔴 跨多張訂單時,那個訂單編號**只是其中一張**

**乙:全部帶,砍到滿為止**
```
[PCM] CH6D75 前叉油封 SKU-1234 / 煞車皮 SKU-5678 / …
```
· ✅ 資訊完整
· 🔴 **幾乎一定會被砍**,而砍在哪裡看不出來
· 🔴 100 字元裝不下三樣中文商品名

**🔵 我推薦甲**,而理由是**這一格的讀者是司機**:
📌 **他要的是「這箱是誰的」,不是「這箱有什麼」** —— 後者他手上那張紙印不下,而系統裡查得到。
🛑 **而多張訂單那一格,甲要補一句**:訂單超過一張時印 `CH6D75 等 2 單`。

## §3 ✅ 不蓋掉人打的字(主視窗已裁)

```
carrier_note 有字   ⇒ 原樣送, 本片一個字都不加
carrier_note 是空的 ⇒ 才用預填的那一串
```
🔴 **而預填【不寫回 DB】** —— 它只在「組送給新竹的那一包」那一刻算出來。
📌 理由:寫回去會讓那一格從「員工填的」變成「有時候是系統填的」,
而下一個人看到 `carrier_note` 有值時**分不出是誰填的**。
🔵 **而畫面上要看得見**:送出前那個確認畫面要印出「備註會送:`[PCM] …`」,
否則員工不知道紙上會多一行字。

## §3-b 🔴 同一箱兩次呼叫, 備註可能不一樣(codex R1 must-fix 二)

**出事流程**(codex 舉的,我複驗成立):
```
箱子只有一項 ⇒ 送新竹逾時成 unknown ⇒ 有人【加了第二項】
⇒ 再按 ⇒ 走 QueryEDELNO 查回來(recovered)
⇒ 那一發【沒有送新的一包】, 而現算會變成「等共 2 項」
⇒ 📌 我們回報的與新竹紙上印的【不一樣】
```
🎯 **病根不是「算得不夠小心」,是【那串字被算了兩次,而兩次之間世界變了】。**

✅ **修法:不要宣稱我們沒做過的事** —— `recovered` 回 `remark: null`。
🛑 **而「把送出去那一串記下來」我【沒有做】**,理由是它要動 schema:
```
唯讀正式庫 2026-09-10 逐欄看過:
  shipments 十八欄 ⇒ 【沒有一欄】存著送出去的請求
  hct_raw_response 存的是【回應】, 而回應二十欄裡【沒有 emark】
⇒ 要真的存下來 = 加一個欄位 ⇒ 那是另一片
```
🔵 而兩者不衝突,因為它們是**兩個不同的東西**:
```
carrier_note      = 員工的【意圖】 ⇒ 不動它, 不寫回
實際送出的 emark  = 發生過的【事實】 ⇒ 要記才留得住, 而今天沒有地方記
```

## §3-c 🔴 料號不准被當成【指令】(codex R2 must-fix)

**出事輸入**:料號 = `SKU-$&`

⚠️ **而手動建單【允許】那種料號** ⇒ 那是一個真的會送出去的錯字。

✅ **修法不是把第二參數換成回呼, 是【整段不要用 `replace`】** ——
📌 **一個「把資料當成指令」的 API, 換一個安全的用法只是把坑挪遠一點**;
而這裡本來就只要**接字串**, 不需要搜尋與替換。

---

## §3-d 🔴 回報的與送出的要是同一串(codex R3 must-fix)

`hct-client.ts` 的 `xmlEscape` 在組 SOAP 信封時會**丟掉** C0 控制字元與 `U+FFFE/FFFF`。
⇒ 出事輸入:料號含 `U+FFFF`,而**手動建單沒有禁止那個字元**

🎯 **這與 §3-b 是【同一族】**:那一次是「同一串字被**算了兩次**」,
這一次是「同一串字被**兩層各自處理**」—— **兩次都讓回報與事實分岔。**

✅ **修法:在組的那一刻就剝掉** ⇒ 預填 = 送出 = 回報**同一串**。
🔴 **而順序是承重的:先剝、再砍** —— 剝完的長度才是真的長度。
🛑 **而它不是重寫一份 `xmlEscape`**:字集逐字抄那一支,而**兩邊漂開時以 `hct-client` 為準**
(它才是真的送出去的那一層)。

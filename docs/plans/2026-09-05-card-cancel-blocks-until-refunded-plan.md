## §0-a 三件量到的事(它們一起決定這一片的形狀)

述詞在 `supabase/migrations/20260903093000_…sql:421-429`(**不是註解, 是 `IF`**)。
⚠️ **下面這段是【摘錄】不是逐字** —— 我剝掉了 enum cast 與 `public.` 前綴讓它讀得懂。
**要拿它當證據的人請自己開那 9 行。**(codex R2 #1:寫「逐字」而不逐字, 會讓 source drift 永遠不被發現。)
```sql
IF (v_order.payment_status <> 'unpaid'
     AND NOT (v_order.payment_status = 'paid'
              AND EXISTS (SELECT 1 FROM order_payments WHERE order_id = p_order_id)
              AND NOT EXISTS (SELECT 1 FROM order_payments WHERE order_id = p_order_id AND rail = 'card')))
   OR EXISTS (SELECT 1 FROM payment_charge_attempts WHERE order_id = p_order_id AND status <> 'failed')
THEN RAISE EXCEPTION '%', v_generic_msg;
```

**① 刷卡已付款單 ⇒ 擋。** 有 `rail='card'` 的收款列 ⇒ 第三個 AND 為 false ⇒ `NOT(false)` ⇒ 擋。
**② 🔴 而【全額退完】的單 ⇒ 也擋。** `payment_status='refunded'` ⇒ `= 'paid'` 為 false ⇒ 同樣 `NOT(false)` ⇒ 擋。
  ⇒ 📌 **所以「把鈕解鎖」不夠 —— 解鎖之後送出【還是會失敗】。**
**③ 而該走的那條路【已經在正式庫上, 而沒有人接】**:
  `admin_mark_order_cancelled`(同檔 `:604`,2 代,帳本已記)——
  `grep` 全 repo:**admin 這一側零呼叫端**(命中 5 處全是註解)。
  它的閘(同檔 `:604+`):**「這期只開放刷卡的單」** · **「🔴 只認 `refunded`(全額)—— `partiallyRefunded` 不算」** · 已取消過會擋。

⇒ 🎯 **這一片 = ①UI 擋 + 說清楚 ②全退之後把 `admin_mark_order_cancelled` 接上去。**
⇒ 🔵 **不動任何一支金流 RPC。**

## §2 判準(每一格寫「錯了會怎樣」)

**讀的帳本 = `order_refunds`**(不是 `payment_refunds` —— 那是補償退款帳)。

| 狀態 | 取消鈕 | 錯了會怎樣 |
|---|---|---|
| 有 card 收款列、`payment_status` 不是 `refunded` | **停用** + 指路 | 放行 ⇒ 送出必失敗,員工看到看不懂的話 |
| `payment_status = 'refunded'` **且** `payment_method='tappay'` **且**「沒有既存的部分取消」 | **可按** ⇒ 走 `admin_mark_order_cancelled` | 停用 ⇒ **退完了還是取消不了**(今天就是這樣) |
| `refunded` 而**不滿足**上面那兩個附加條件 | **停用** + 說「這張單要工程處理」 | 🔴 **codex R2 #4**:只看 `refunded` 就解鎖 ⇒ 匯款退款單 / 曾部分取消的單**送出照樣失敗**(那支 RPC 還有這兩道閘, `:729-750`) |
| `payment_status = 'partiallyRefunded'` | **停用** + 說「還沒退完」 | 見 §3 |
| 🔴 **退款還在路上** | **停用** + 說「退款處理中,先等它結束」 | ⚠️ **codex R1 #4**:當成「退款額 0」⇒ **畫面會叫員工【再退一次】** |
| ⛔ **而「還在路上」怎麼判, 這一格【是空的】** | — | 🔴 **codex R2 #3:我只是把 R1 #4 換了位置, 沒有解掉它。**⇒ **動手前第一件事是量它**, 不是實作 |

```

```

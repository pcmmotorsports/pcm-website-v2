## §1 它現在有什麼(先講這個, 因為它比大多數腳本成熟)

`scripts/check-anon-grants-prod.sh`(197 行)對**正式庫**查 `anon` / `authenticated` 的權限現值。
它**已經有**下面這些, 而這些正是我們平常要求別人補的:

```
✅ rc 是【三態以上】不是布林:0 / 1(工具問題)/ 2(用法錯)/ 6(沒校準表)/ 7(校準不符=發現)/ 8(net 兩表不存在)
✅ 檔頭逐字寫「rc=1 / 6 都不是【查無】—— 不要當成權限已經收乾淨了」
✅ 正向 + 負向【兩個】對照, 而且檔頭寫了**為什麼負向不能單獨用**:
   「admin_audit_log × anon ⇒ 0」在【表被鎖好了】與【表根本不存在】兩個世界印同一個東西
✅ 連線字串走 env 不走 argv(不進 ps / 不進 shell history)
✅ information_schema 會依連線角色過濾而 pg_catalog 不會 —— 第 ④ 段因此改走 relacl/attacl
```

## §2 它缺什麼:**沒有 `--selftest`**

🔬 量到的(P1-1 盤點):
```
內文 --selftest / --self-check ⇒ 0 次
lint-staged 指名它的 glob      ⇒ 0 條(只被 scripts/*.{sh,py} 那四道【形狀閘】掃到)
.husky / CI 接線               ⇒ 查無
⚪ 負對照 現造 scripts/zq7fh3k2m9x-nope.sh ⇒ 同樣 0(⇒ 上面那些 0 不是尺壞掉)
```
⇒ 📌 **它的【行為】沒有任何自動化在守** —— 四道通用閘守的是形狀(shell 方言 / 隱藏 helper / selftest 隔離),
不是「它判得對不對」。

## §3 難處:**它的本體要連正式庫, 而 selftest 絕不能連**

🛑🛑 **紅線(不可協商)**:`--selftest` **在任何情況下都不得連正式庫**。
理由不只是「唯讀所以安全」—— 而是:
```
· 它會被【lint-staged 每次 commit】叫 ⇒ 那等於每次 commit 都對正式庫發查詢
· 而它讀的是【權限現值】⇒ 那是最不該被自動化高頻拉取的東西
· 🔴 且本 repo 今天剛量到:lint-staged 會把 staged 檔名附加到命令後面
  ⇒ 一支「參數解析不嚴」的腳本可能把那個路徑吃成別的意思
```
🛑🛑 **而危險不只是慢(主視窗 `-1a` 2026-09-08 補的理由, 逐字收)**:
> 那條連線會住在一個**每個人每天跑幾十次**的位置, 而**沒有人會再去看它**。
> **一條沒有人在看的正式庫連線, 是最容易被下一次改動悄悄擴權的東西。**

📌 ⇒ 所以紅線的判準**不是「它現在唯讀所以安全」** —— 是**「它會待在一個沒有人看的位置」**。

### 它的七個離場點分三層, 而**只有前兩層不用 DB**

| 層 | 離場點 | 要造什麼世界 | 要不要 DB |
|---|---|---|---|
| A 參數/env | `rc=2` ×2(收到參數 / 沒有 `PGURL`) | 直接呼叫 | ❌ 不用 |
| B 工具 | `rc=1` ×3(`psql` 不在 / `python3` 不在 / `PGURL` 解析失敗) | `PATH` 遮蔽 + 餵壞字串 | ❌ 不用 |
| C 判準 | `rc=0 / 6 / 7 / 8` | 要一個**有表、有 GRANT** 的庫 | ✅ 要 |

## §4 兩個方案 —— **而我判不出高低, 要 `-1a` 拍**

### 甲:只做 A + B 兩層(**不起 PG**)
```
✅ 快(毫秒級)· 零 DB 依賴 · 掛 lint-staged 沒有任何速度風險
🛑 而它【證不到那支腳本判得對不對】—— 它只證「參數與工具那幾條路會照預期離場」
🔴 誠實的標籤要寫死在 selftest 的**輸出**裡:
   「本 selftest 沒有驗任何一條【判準】—— rc 0/6/7/8 四條路一格都沒有跑到」
   🛑🛑 **寫進【輸出】不是【註解】** —— 註解只有讀碼的人看得到,
      而**盤點的尺看的是輸出**(`-1a` 2026-09-08 明點)。
   🎯 **⇒ 而這正是本片 ① 那件的鏡像**:`rollback-drill.sh` 有 4 個 selftest 旗標,
      **而它從來沒真的跑過** —— 盤點看到旗標就把它算成「有守門」。
      ⇒ 📌 **一個只驗參數的 selftest, 會讓下次盤點以為它的判準也被守著。**
```

### 乙:A + B + C(**起一台拋棄式 PG**, 照 `scripts/rollback-drill.sh` 的形狀)
```
✅ 真的驗得到判準:造一張 anon 有權限的表 + 一張沒有的 ⇒ 四個 rc 各跑一次
✅ repo 裡已經有現成的形狀可抄(rollback-drill 的第二層就是這樣做的)
🛑 代價 = 時間, 而那個時間【變異很大】:
   🔬 rollback-drill --selftest 今天四發實測 **2 / 3 / 12 / >120 秒**(load 7.5~10.4)
   ⇒ 📌 變異 60 倍, 而我沒查清楚差在哪
🔴 而 `.husky/pre-push` 檔頭記過那個代價:
   「閘死於誤報與死於太慢一樣常見, 而被關掉的閘等於沒有。」
```

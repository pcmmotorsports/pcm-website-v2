## 2. Q-a:② 那 8 件放在商品頁哪裡 —— **實體版本**

**位置:接在「適用車款」那張表的正下方、`.pd-fit-note` 那句話之前**(同一個 `<section>` 內)。
理由:客人已經在那裡讀相容性,**不必再往下找**;而那一段本來就是條件渲染(`fitments` 空就整段不畫)。

```
┌─ FITMENTS · 適用車款 ─────────────────────────────┐
│ 這款部品適用的車型與年式        下單前請先聊聊確認…  │
│                                                   │
│  HONDA                                            │
│    CBR1000RR-R          2020–2023                 │
│                                                   │
│ ┌───────────────────────────────────────────────┐ │
│ │ ⚠ 這些情況裝不上                              │ │   ← 🔴 新增的就是這一塊
│ │  · 2025 年以後的車型                          │ │
│ │  · 配原廠排氣管時                             │ │
│ └───────────────────────────────────────────────┘ │
│                                                   │
│ 列表為主要適用車款;同系列其他年式 / 配備如需確認… │
└───────────────────────────────────────────────────┘
```

**規則(寫死,免得做出一個空框)**:
```
沒有排除條款的商品 ⇒ 這一塊【整個不存在】
  🛑 不是畫一個空框、也不是印一句「無」
  ⇒ 做法與既有慣例一致:`ProductFitments.tsx:143` 那句 `if (!fitments…) return null` 的同一個形狀
```
🔵 **視覺沿用既有 token**,不另起風格:底用 `surface-2`、sharp corner、薄線(同 `.pd-fit-year` chip 那一族)。
🛑 **本片不新增顏色、不新增字級** —— 要 design 對稿的話,這一塊要先過 `design-reference/`(鐵則 1),**而我還沒對過,那是動手前的第一步。**

## 3. Q-b:內容從哪裡來 —— **一份來源,兩個消費者**

🔴 **主視窗擋的那件事我同意:兩套來源 = 兩份真相。所以只做一份。**

```
packages/domain/src/catalog/fitment-exclusions.ts   ← 🎯 唯一的來源
  key = (supplier_slug, external_id)
  {
    years?:    年式修正(給 ① 那 5 件)
    excludes?: 一句一條的中文「裝不上的情況」(給 ② 那 8 件)
    source:    那句英文原文逐字(留證,讓下一個人核得動)
  }
```
**兩個消費者,而來源只有一個:**
```
① rpm-import   讀 years    ⇒ 寫進 product_fitments(匯入時套用 ⇒ 沖不掉)
② 前台元件     讀 excludes ⇒ 畫那一塊(不進 DB ⇒ 🟢 零 schema 變更、零 migration、不用貼板)
```
🔵 **為什麼 ② 不走 DB**:走 DB 要加欄位 ⇒ migration + 貼板 + 部署時序閘。
   而這裡只有 8 筆、內容是人寫的中文 ⇒ **放在 repo 裡看得到、進得了 code review、改了會出現在 diff**。
   🛑 **而代價要寫明**:它**不能由員工自己維護**(要改碼)。量大了就得走鐵則 9 的後台 CRUD —— **那是另一件。**

### 🔴 3-b 那道對帳(硬要件,不是選配)

> 我自己寫過:**只有例外表而沒有對帳,就是「今天對、三個月後靜靜過期」那種東西。**

```
對帳內容:例外表裡的每一個 (supplier_slug, external_id)
  ① 在來源目錄裡還在不在?          不在 ⇒ 這條例外已經沒有對象
  ② 那句 source 原文還在不在描述裡? 不在 ⇒ 供應商改了條款, 這條例外可能已經錯
```
**🔴 對帳不過會怎樣(主視窗點名要寫死)**:
```
· rpm-import 那一側 ⇒ 🛑【擋住匯入】, 不是印警告
    理由:印一行沒人看的警告不算防線 —— 而匯入紅了一定有人處理。
· 測試那一側     ⇒ 🔴 一格會紅的測試(不是 console.warn)
    🔵 而它要能燒負對照:把例外表裡任一筆的料號改成不存在的 ⇒ 必須紅、而且指名是哪一筆
```

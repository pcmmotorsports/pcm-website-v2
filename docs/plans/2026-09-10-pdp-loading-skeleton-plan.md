# Plan:商品詳情頁不要再借用「商品目錄」的載入骨架

> 2026-09-10 窗 D。**只寫不做,等 Sean 批。**
> 觸發:對正式站跑 `audit-website`(squirrelscan)報 `a11y/landmark-one-main`;
> 而它與 2026-09-09 那份 SEO 盤點裡「PDP 有 2 個 h1」是**同一個東西**。

## 1. 病(量到的,不是推的)

`app/products/loading.tsx` 是 Next App Router 的 route-level loading UI,而它會套用到
**該 segment 與底下所有子路由** ⇒ `/products/[slug]`(商品詳情)繼承了 `/products`(商品目錄)的骨架。

**兩個世界各量一次(2026-09-10,正式站 `shop.pcmmotorsports.com/products/dbk-gr06`):**

| | `<main>` | `<h1>` | `pp-loading` |
|---|---|---|---|
| **原始 HTML**(`curl`,沒跑 JS) | **2** `pp-main` / `pd-page` | **2**「全部商品」「鋁合金油冷護網」 | 出現 208 次 |
| **執行 JS 之後**(真瀏覽器) | 1 `pd-page` | 1「鋁合金油冷護網」 | 0 |

⇒ 🔴 **重複只存在於未執行 JS 的原始 HTML。**

## 2. 受害者只有一種 —— 而這一格我們兩個先前都講錯

- ❌ **讀屏使用者不受影響**:他們的瀏覽器跑 JS ⇒ 拿到乾淨的 1 個 `main`。
  ⇒ **這不是 a11y 問題**,雖然是 a11y 掃描器報出來的。
- ❌ **Google 不受影響**:Googlebot 會 render。
- ✅ **不跑 JS 的爬蟲受影響**:`GPTBot` / `ClaudeBot` / `CCBot` 那一族多半不 render
  ⇒ 它們在**每一個商品頁**上讀到一個假的 `<h1>全部商品</h1>`。

🔴 **而這正好接回 2026-09-09 那批 GEO 工作**(`llms.txt`、robots 具名允許 AI 爬蟲):
**我們才剛把 AI 爬蟲請進來,而它們進來看到的每一個商品頁標題都是「全部商品」。**
⇒ 那讓這一片的優先度**往上**,不是往下。

🔵 而 squirrel 報得出來、我手工掃 a11y 卻沒報,是因為**它掃的是原始 HTML** ——
📌 **罐頭工具的價值不在它比人聰明,在它站在一個人不會站的位置上。**

## 3. 改什麼(甲案)

新增 `app/products/[slug]/loading.tsx`。
Next 的規則:**子 segment 的 `loading.tsx` 覆蓋父層的** ⇒ PDP 載入時顯示商品頁自己的骨架。

**不動的:** 路由網址、`app/products/loading.tsx`(目錄頁那支照舊)、任何既有元件。

## 4. 為什麼不是乙(只把 `<main>` 改成 `<div>`)

- 🔴 **乙把一個【說錯話】的問題改成【說得小聲一點】** ——
  「全部商品」那四個字**仍然會出現在 PDP 的原始 HTML 裡**,只是不再是 `h1`。
  爬蟲仍然會在商品頁上讀到「全部商品」。
- 🔴 第二個代價:`/products` **真的在載入時**,那一刻沒有 `main` 地標、也沒有 `h1`
  —— 那是把一個真實使用者看得到的狀態弄差,去換一個爬蟲看得到的狀態變好。

## 5. 🔴 骨架長什麼樣 —— 這是設計題,要 Sean 拍

**查證結果(2026-09-10):**
- `design-reference/` 底下掃 `load|skeleton|placeholder` ⇒ **零命中**。
- `design-reference/styles` 掃 `skeleton|loading` ⇒ **零命中**。
- 而既有那支 `app/products/loading.tsx` 的檔頭逐字寫著:
  「**design-reference 未定義資料等待態;依 Sean 選定的 C 方向**,保留既有型錄外殼」

⇒ 📌 **等待態這一整類本來就沒有稿,而現有那支是 Sean 自己拍的方向。**
⇒ 所以 PDP 骨架也**只能問他**,不能照鐵則 1 去搬(沒有東西可以搬)。

```
Q:商品詳情頁在載入時要顯示什麼?
   甲(推薦)= 照現有那支的作法,換成【商品頁的外殼】——
              頁首 + 一塊圖的位置 + 標題/價格的灰條 + 買鈕的位置。
              好處:與目錄頁那支同一種語言(灰條骨架),客人一眼知道「在載商品頁」。
              代價:要做一份新的骨架版面(我做,約一片)。
   乙 = 只放頁首 + 一條進度條,不畫骨架。
              好處:最省、也不會有「骨架與真頁對不起來」的問題。
              代價:載入那一刻畫面幾乎是空的。
   A: 甲|乙
```

## 6. 驗收(🔴 這一節是本 plan 最要緊的一行)

```
a11y   squirrel 的 landmark-one-main 那格必須綠
SEO    PDP【原始 HTML】的 h1 數必須從 2 變 1、且第一個 h1 是商品名
```

🔴 **一定要量【原始 HTML(`curl`)】,不能量瀏覽器** ——
**瀏覽器那份現在就已經是 1 個了,用它驗會【永遠是綠的】,不管修沒修。**

📌 那描述的是一把**自己會變綠**的尺 —— 而那是最毒的一種:
**不是量錯世界,是量了一個【問題不存在的世界】。**

## 7. 影響與 rollback

- **影響面**:只有 `/products/[slug]` 的載入那一瞬間。不動資料、不動路由網址、不碰金流權限 schema。
- **rollback**:刪掉新增的那一支 `loading.tsx` ⇒ 行為回到現在這樣(PDP 繼承父層骨架)。**一個檔案的事。**
- **不需要 codex**:不碰錢 / 權限 / schema / migration / next.config / vercel.json / 寄信 / `packages/ui`。

## 8. 這份 plan 沒有做的事

- 沒有動任何碼。
- 沒有決定骨架長相(§5 那題要 Sean 答)。
- 沒有處理同一份掃描報告裡的其他項(圖片過大、`label-content-name-mismatch`)—— 那些各自獨立。

## 4. 修法:三個選項,而**只有一個是工程可以自己決定的**

```
甲  丙(DB CHECK 只收嚴 name)  ⇒ 🔧 工程可做。今天 0 列被擋(§2)。
    · 改什麼:ALTER TABLE public.shipments ADD CONSTRAINT shipments_recipient_name_not_blank
              CHECK (NOT pcm_b2_is_blank(recipient_snapshot->>'name'))
      🔵 用既有的 pcm_b2_is_blank —— 同一張表已經有 5 條約束在用它, 不自己發明一套
      🔬 那支的本體我唯讀讀出來了(讀 pg_proc.prosrc, 沒呼叫它 —— pcm_readonly 對它沒有 EXECUTE):
           btrim(translate(COALESCE(t,''), E'\t\n\r\v\f' || U&'\00A0' || U&'\3000', '       ')) = ''
         ⇒ NULL 與【7 種空白字元】都算空(含 NBSP U+00A0 與全形空格 U+3000)
         🟢 正式庫本體與 repo `20260805170000:56-70` 逐字相同 ⇒ 兩邊沒有漂移
      🛑 而那支的 COMMENT 自己警告:「改這支等於同時改那四條守門的語意」
         ⇒ 📌 **本片【只新增第 5 個消費端, 一個字都不改那支函式】** —— 不碰既有四條的語意
    · 為什麼:今天擋 name 的是【應用層兩處】, 而 DB 是最後一道。繞過應用層的寫入路徑
              (未來的 RPC / 手動 SQL / 別的窗)不會有任何東西紅。
    · 影響:既有 4 列全過(實量)。新寫入若 name 空白 ⇒ 23514, 而應用層已經先擋掉了
              ⇒ 📌 正常路徑上任何人都不會看到它。
    · rollback:ALTER TABLE public.shipments DROP CONSTRAINT shipments_recipient_name_not_blank;
              (純新增約束、零資料改動 ⇒ 可逆, 且 drop 之後與今天逐位元組相同)

乙  §3 那個相反 ⇒ 🧑 **這是 Sean 的題, 不是工程判斷。**
    問題只有一句:「一箱【自取、沒有地址】或【客人沒有電話】的貨,
                   它的出貨明細單應該【印出來(地址欄留白)】還是【不准印】?」
    · 印  ⇒ 改列印層:phone/line 空從「阻印」降成「紙上標注」, 與建箱層對齊
    · 不印 ⇒ 改建箱層:phone/line 空從「放行/警告」升成「擋」, 與列印層對齊
            🛑 而這一支會退掉沒有電話的既有客人(建箱層檔頭逐字警告過)⇒ 代價要他知道

丙  什麼都不做 ⇒ 也是一個合法選項:今天曝險 0, 而 #39(自取)還沒落地。
    🔴 而它的代價是:Sean 第一次遇到會是在【按下列印那一刻】, 而那時他手上有貨。
```

**我的推薦:甲現在做(便宜、可逆、今天 0 列被擋);乙端 Sean 一句話;丙不採。**

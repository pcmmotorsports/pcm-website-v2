而 repo 裡有**兩道明文守門**擋著金額, 其中一道**用突變驗過**:
```
(a) picking-doc.tsx:9  「本檔不得出現任何金額」
    驗收條件在 page.test.tsx:151 格② —— 檔頭逐字寫著「那格用突變驗過
    （故意塞金額進去 ⇒ 該格必紅）」
(b) shipping/[shipmentId]/page.test.tsx:461 「金額區塊還沒做 ⇒ 紙上不得出現任何金額」
    ⚠️ 該檔自己寫著「金額真的落地時要【改寫這格, 不是刪掉】」
```

🛑 **所以這一片會【反轉一道突變驗過的守門】。**
一般情況下「想動驗證本身」是立即停止訊號(R4)。**這一次不是** ——
那道守門對**揀貨單**是正確的, 而**那顆按鈕已經不是揀貨單了**(Sean 08-23 拍板)。
🔴 **但這個區別只有 Sean 分得出來, 所以它必須由他說。**

```
Q-DETAIL-MONEY:訂單明細那張紙, 要不要印金額？
A: 甲 要（它是「完整的一張訂單」⇒ 沒有金額不成立）
   乙 不要（那張紙也會被拿到倉庫 / 被客人瞄到）
```
**推薦甲** —— 依據:①「完整的一張訂單」是他自己的逐字 ②8/16 brief 已把「倉庫桌上那張有金額」
列為合併的**固有代價**而他選了甲 ⇒ 他已經買過這個代價一次。
⚠️ **而外洩顧慮沒有消失、是搬家到出貨單那張** —— 兩張都印, 就是接受它兩次。

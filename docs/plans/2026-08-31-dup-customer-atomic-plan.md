## 1. 🔴 而這一片最重要的一段是【不能做什麼】

板上那條**原始關掉條件已作廢**(`5f00d26b`,codex R7 抓、主視窗裁),而理由要抄下來:
```
⛔ ~~加一條「manual + 正規化電話 + 姓名」的唯一約束~~
🔴 它與一個**合法的世界**矛盾:**同名、共用市話的第二個人(一家人)** ⇒ 那個人**永遠建不進去**。
📌 ⇒ 原病是「同一個人被建成兩個帳號」,而那個修法會變成
   「**兩個不同的人只能有一個帳號**」—— **它做出了自己要修的那個病的反面。**
```
🛑 **而板上那句「為什麼它會被照著做」我要原樣帶進本 plan**:
> 那條關掉條件**讀起來完全合理**,而且它是一個**機械的、可驗收的、寫得出 `grep` 的**條件。
> 📌 **一個可以 `grep` 的關掉條件,比一個模糊的更容易被照著做 —— 而那正是它錯的時候傷害最大的原因。**

⇒ 🔴 **本 plan 因此不提任何「用欄位組合當身分鍵」的方案。**
**系統判不出「是不是同一個人」;判得出來的是【人】。**

## 2. 現行關掉條件(板上訂正後那一版)= 三件事

```
① DB 鎖(advisory lock 或等價)
② 拿到鎖之後【重新檢查】一次
③ 撞到疑似重複 ⇒ **要求員工明確選擇**(而不是替他決定)
```
🔵 **而 ① 有現成成例可抄,不必自己發明**:
```
supabase/migrations/20260613130000_m3_3ds_0b_cart_session_dedup.sql
與 20260612150000 / 20260613140000 ——
形狀 `PERFORM pg_catalog.pg_advisory_xact_lock(pg_catalog.hashtextextended(<key>::text, 0));`
(實例見 …0c…sql:389,對 `customer_user_id` 上交易級鎖)
```
📌 **⇒ 交易級(`_xact_`)⇒ 交易結束自動放,不需要人記得解鎖。**

## 3. 分片

### 片 1 · migration:一支受控的「建客人」RPC(**本片的全部**)
```
· 交易內:先 `pg_advisory_xact_lock(hashtextextended(<正規化電話>, 0))`
  🛑 **鎖的是【電話】而不是【姓名+電話】** —— 鎖只需要讓「同一支電話的兩個請求排隊」,
    它**不決定他們是不是同一個人**。⇒ 📌 **鎖是排隊機制, 不是身分判準。**
· 拿到鎖後【重新查一次】現有 manual 客人
· 命中 ⇒ **回一個「疑似重複 + 那一筆的識別」給呼叫端, 而【不建】**
  ⇒ 由 UI 去問員工(② 與 ③)
· 沒命中 ⇒ 建
```
🔴 **而它答不出的那一格要寫在碼裡**:`auth` 帳號的建立在另一個系統(Supabase Auth),
**本 RPC 的交易涵蓋不到它** —— 那正是 `manual-customer.ts:443` 自陳的那一句。
⇒ **⇒ 所以本片把窗口【縮小】到鎖住的那一段,而不是宣稱它消失了。**

### 🛑🛑 片 1 上面那個設計【是錯的】—— 我實跑量掉了它, 不是推理

> 拋棄式 PG 17.10 @ `/tmp/pg-ship1e` · 2026-08-31 16:3x · 兩個世界各印不同的東西

```
世界 A(逐字照我上面那個形狀:RPC 裡 pg_advisory_xact_lock, 而 PostgREST 一發就是一個交易)
  A1  SELECT rpc_check('0912345678')       ⇒ 'no-dup, go create'   ← 這一發已經 COMMIT
  A2  另一條連線 pg_try_advisory_xact_lock(同一把鑰匙) ⇒ 🔴 **搶到了**
🟢 正對照 B:同一把鑰匙、交易【還開著】時去搶 ⇒ **擋住了** ⇒ 尺是活的, 它分得出兩個世界
```
🔴 **⇒ `_xact_` 鎖在 RPC 回傳的那一刻就放掉了, 而 `createUser` 在那【之後】才發生。**
```
時間軸(這才是真的流程, 我開檔核過, 不是想像):
  ① admin_search_customers  ← 一趟往返(一個交易)
  ② createManualCustomer → client.auth.admin.createUser  ← 另一趟往返, 走 Supabase Auth, 【不是 DB 交易】
⇒ 把鎖放在 ① 裡面, 它在 ① 結束時就沒了 ⇒ A 與 B 兩個請求會【雙雙】拿到「沒有重複, 去建吧」
⇒ 📌 **窗口一格都沒有變小。**
```
📌 **⇒ 我寫的關掉條件「交易級 ⇒ 交易結束自動放, 不需要人記得解鎖」是對的 ——
而我把那句【優點】抄進了一個它變成【致命傷】的位置。**
🔴 **同一個事實, 在成例那支 migration 裡是優點(那裡整段工作都在同一個交易內),
在這裡是失效原因(這裡的工作跨了一趟 HTTP)。而兩邊的碼長得一模一樣。**

### 🔵 那什麼形狀跨得過那一趟往返 ⇒ **佔位列 + UNIQUE**(同一發實跑量的)

```
世界 C  claims(phone_norm PRIMARY KEY)
  C1  A INSERT 佔住 0912345678, **COMMIT**(交易結束了)
  C2  B INSERT 同一支      ⇒ ✅ duplicate key 擋下   ← 佔位列【活過了 commit】
🟢 負對照 D:B 換一支不同電話 ⇒ 放行 ⇒ 尺不是恆擋
```
🛑 **而它的代價同一發一起量了, 不放到「之後再說」**:
```
E  A 若在【佔住之後、建完之前】掛掉 ⇒ 那支電話被卡住, 而**沒有任何東西會放掉它**
⇒ 這個形狀【必須】自帶過期規則, 否則一次當機 = 那位客人永遠建不進去
⇒ 📌 而那正是本 plan §1 明令禁止的那個病的**變形**:讓一個合法的人建不進來。
```

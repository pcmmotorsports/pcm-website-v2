## 1-c 兩支並排 —— **而選官方的理由是量出來的**

| | 官方 | g0v 社群 |
|---|---|---|
| 回應時間 | **0.085 s** | 0.484 s(**5.7 倍**) |
| 回傳大小 | **75 B** | 3,801 B(**50 倍**) |
| 回傳內容 | **只有統編 + 公司名稱** | 含**代表人姓名 · 住址 · 董監事名單**(個資) |
| 誰維護 | 政府機關 | 社群志工 |
| 查不到 | 200 + 空陣列 | (未測) |

🎯 **⇒ 而「回傳只有兩個欄位」在這一片是【優點不是缺點】**:我們只要抬頭。
🔴 **拿 g0v 那支等於把【代表人姓名與住址】也抓回來** —— 我們不需要,而**抓回來就有保管責任**。
📌 **⇒ 這一格比速度重要:選官方不只是快,是【它給的剛好是我們要的】。**

## 1-d 🛑 金鑰 / 申請 / 流量 —— **這一格有矛盾,我照實寫**

**開發指引逐字**(`https://data.gcis.nat.gov.tw/od/rule`):
> 「本平臺**系統介接 API** 係透過**來源 IP 進行白名單管控**,請告知者務必於告知書內填寫外部 IP,而非內部 IP。」
> 申請程序:填「經濟部商工行政資料開放平臺資料介接使用告知書」⇒ 遞件 `opendata.gcis@gmail.com` ⇒ 平臺設定後發信通知。
> 流量:表格有「**介接使用者每日最大介接次數**」,超出回「**超出本日最大介接次數。**」(**每分鐘的數字未標**)

🔴 **而我今天【沒有申請、沒有白名單】,那一發照樣 200。**
```
⇒ 兩種解釋, 我分不出:
   ① 白名單只管「系統介接 API」那一族, 而我打的這支 OData 端點不在那一族
   ② 它有限制而我今天沒撞到
🛑 ⇒ 所以【不要把「我打通了」讀成「不用申請」】。
📌 一發成功不等於沒有限制 —— 而那正是今晚一直在講的:一個 0 要先問它的分母, 一個 200 要先問它的次數。
```
✅ **⇒ 而 fail-open 讓這一格【不擋上線】**:哪天真的被擋,畫面的行為與「查不到」一模一樣,員工照樣自己打。
🔵 **⇒ 建議:先上,而把「要不要遞使用告知書」當成一件【上線後的事】排進去,不要卡在這裡。**
🛑 **金鑰:這支不需要金鑰 ⇒ 沒有任何值要進 `.env.local`。** 若日後申請白名單,要設的是**來源 IP**,那不是一顆 env。

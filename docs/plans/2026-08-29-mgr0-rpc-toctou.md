# Plan · 把「管理者查核」與「員工資料寫入」包進同一支 SECDEF RPC(`⟦b4-MGR0-RPC⟧`)

> **狀態:等 Sean 批(鐵則 8 —— 新建 DB 物件;且命中鐵則 12②權限 ③schema)。批准前不動任何檔。**
> 提案 `-b9` · 2026-08-29 · 主視窗 `-48` 裁**甲** · 量測全文 `~/pcm-mailbox/de-b9-TOCTOU窗口量測-20260829.md`

## 0. 要解的是什麼(**兩件, 而板子只寫了第一件**)

```
① 機制:管理者查核與寫入分屬【兩次 DB 往返】⇒ 中間那段沒有東西在看
🔴 ② 後果:稽核紀錄會說一句【不真的話】——
     audit 帶的是 authorization.actorId，而那是【降級之前】那次查核的結果
   ⇒ 稽核上看到「管理者 A 做了這件事」，而事發當下 A 已經不是管理者
```
📌 **⇒ ②才是這一片的重量。而「補上限擋得住【誤填】, 擋不住【否認】」——**
**這一格是 `⟦b4-AUTOREFUND⟧` 那條根因的【第二個現場】。**

## 1. 要改什麼(**三個窗口, 不是一個**)

`apps/admin/src/lib/staff-actions.ts` 有 **3 處** `await authorizeManagerMutation()`, 各自一個窗口:

| 查核 | 寫入 | 隔 | 寫什麼 |
|---|---|---|---|
| `:105` | `:123` `insertStaffRow` | 17 行 | 新增員工 |
| `:156` | `:197` `updateStaffProfileRow` | 40 行 | 改員工資料 |
| `:230` | `:284` `setStaffActiveRow` | 53 行 | 停用 / 啟用 |

🔴 **而每一段中間都有 `await getRequestId()`** ⇒ **窗口 = 兩次 DB 往返 + 一個 await。**
⚠️ **單位刻意是【往返】不是毫秒** —— **那個數字不會因為機器快而消失。**

### 🛑 而【只搬一支】會讓板子看起來像關了
```
若只把 :105 那條包進 RPC ⇒ :156 / :230 的窗口【還開著】
⇒ 而板子那一列會被標 done ⇒ 下一個人不會回來看
✅ ⇒ 所以本片的驗收條是【三處都搬】，或明寫「只搬了哪一處、其餘為什麼還開著」
```

## 2. 為什麼是甲(包進 RPC), 不是乙(寫入前再驗一次)

```
乙 把窗口【縮小】：第二次查核與寫入之間仍然是兩次往返
   ⇒ 🔴 而縮小之後，下一個人【量不出來它還剩多寬】
   ⇒ ⚠️ 而它會讓「已經驗過了」出現在兩處 ⇒ 下一個人要問「哪一次算數」
✅ 甲 把窗口【關掉】，而關掉它的是 FOR SHARE：
   它鎖住 staff 那一列直到交易結束 ⇒ 並行的降級會【被擋住等】，不是【搶先寫進去】
```

### ✅ 而甲有現成範本 —— 成本比看起來低
```
supabase/migrations/20260828090000_m4b_b4views1a_request_id_gate.sql
  :52  admin_create_saved_order_view   :89  FOR SHARE
  :203 admin_update_saved_order_view   :241 FOR SHARE
  :371 admin_delete_saved_order_view   :401 FOR SHARE
⇒ 同一個形狀：SELECT … FOR SHARE → IF NOT FOUND THEN RAISE → 檢查 → 寫入，全在一個 plpgsql 函式裡
  （-b9 複驗:函式邊界 :52..:197 · LANGUAGE plpgsql · COMMIT 0 ⇒ 同一個交易）
```

## 3. 🔴 而**稽核那一格不會自己好** —— 這一句要明寫, 不得當成順便的

```
把查核與寫入包進 RPC ⇒ 解掉的是【寫得進去】那一半
🔴 而 audit 寫的仍然是【呼叫端傳進來的 actorId】
⇒ 除非 RPC 裡【重讀一次身分】並用那一次的結果寫 audit
⇒ 📌 而那要明寫在驗收條裡，否則它會變成「包進去了而稽核還是記錯人」
```
⚠️ **⇒ 而那是一個【要決定】的事**:RPC 要不要拒絕「呼叫端傳的 actor 與它自己讀到的不一致」?
**⇒ `-b9` 不預設, 這一格請 Sean 或主視窗裁。**

## 4. 影響面 / rollback

- **影響面**:三個後台員工管理動作(新增 / 改資料 / 停用啟用)。**客人端零影響。**
- **新建 DB 物件** ⇒ 鐵則 8 + 12③;**權限** ⇒ 12②。⇒ **要 plan 批准 + codex 對抗審查(不降級)。**
- **rollback**:migration 走 forward-only;應用層那半單顆 `git revert`。
  ⚠️ **而 RPC 建了之後即使應用層回退, 那支 RPC 仍在** ⇒ **rollback 不對稱, 要明說。**

## 5. 我沒做 / 沒量的(射程)

```
🔴 ① 沒有量那個窗口的【毫秒數】—— 而那要真的跑，且毫秒會隨網路變
🔴 ② 沒有構造過一次真的並發 —— 而那是【刻意】的：
     構造並發只能證明「我這一次搶到了」，搶不到【不代表窗口不存在】
     ⇒ 那是一發【只能證有、不能證無】的實驗，而窗口在不在靜態就答完了
⚠️ ③ 沒有查【現在線上有幾個管理者】—— 那要正式庫
     ⇒ 而它決定這件事的觸發率，不決定它成不成立
```

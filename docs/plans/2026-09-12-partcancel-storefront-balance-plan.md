## 2. 正確的數該怎麼算 · 那支 view 是不是單一來源

```
pcm_order_effective_amounts_v(20260907210000:60-100)
  effective_subtotal     = Σ((quantity − 已取消) × unit_price)
  effective_shipping_fee = store ⇒ 0 · subtotal >= 5000 ⇒ 0 · 否則 100(逐字沿用 create_order:226)
  effective_total        = effective_subtotal + effective_shipping_fee
  effective_balance_due  = effective_total − (o.total − bal.balance_due)   ← 減的是【已付】
  🔵 bal.balance_due 為 NULL(有退款那一族)⇒ 整條為 NULL ⇒ 自動落回「不給數字」那條路。
  🔵 20260909100000 另外讓它在【未稅單算不出來】時回 NULL(Sean 2026-09-10 拍甲)。
```

🔴🔴 **它是不是單一來源 —— 答案要分兩半講,而第二半是本題的關鍵**
```
✅ 是:它自己的 COMMENT 逐字「**只有匯款通知信那兩支 view 接它** —— 單一來源、兩層共用,
   兩邊不可能算出兩個數」⇒ 「客人現在該付多少」這個問題, 今天只有它一個答案。
🛑 而同一句 COMMENT 的下一行逐字:「**它【不是】對帳用的權威金額**:orders.total 仍然是
   那一列上的字面, 本 view 只答『**若照 Q39(券作廢算原價)與運費規則重算**, 客人現在該付多少』。」
⇒ 🔴🔴 **所以 effective_total ≠ 「訂單金額扣掉取消的件」** —— 它還做了兩件事:
     ① **券整張作廢、算回原價**(Sean Q39 逐字「那優惠卷就不能使用, 這樣最簡單, 算回原價」)
     ② **運費照規則重算**(Sean 09-05 拍乙:跌破門檻要補收)
   ⇒ 📌 **一張用過券的單, effective_total 可能【比原本的訂單金額還高】。**
     (板列 ⟦auth-PAIDAMOUNTNOTFROZEN⟧ 記著 Sean 2026-09-07 為此單獨答過 `Q82 = 照寄`。)
⚠️ 而那兩條拍板的**原情境都是「已付款後退錢」**, 用在未付款的匯款單屬【延伸】——
   主視窗 B 2026-09-07 判「照做並標明」, **Sean 沒有被單獨問過這一格**。
```

🎯 **⇒ 本題真正的難處不是「算不出正確的數」,是:**
**把扣好的餘額放進顧客頁,那一頁上的「訂單金額」就得一起換成 `effective_total`
—— 而那個數會【含券作廢的加回】** ⇒ 客人看到的訂單金額比他下單時看到的高。
📌 **不換的話更糟:訂單金額 10,000、應付餘額 4,950,兩個數對不起來,而客人會自己去減。**

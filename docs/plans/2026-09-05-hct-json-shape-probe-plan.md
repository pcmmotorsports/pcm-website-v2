## 1. 為什麼要發(而它不是「試試看」)

`TransData_Json` 的第三個參數是 **`string json`** —— 一段 JSON 字串。
**而【那段字串的外層長什麼樣】沒有任何文件說。**
```
PDF 第 13 頁  給了 20 個欄位名與長度(epino / ercsig / ertel1 / eraddr / ejamt / eqamt …)
PDF 全文      含 `{"` 的行 = 0  ⇒ 一個 JSON 範例都沒有
線上服務描述  只說型別是 string
```
⇒ 🔴 **我們今天送的外層 `{"data":[{…}]}` 是【猜的】。**
⇒ 而猜錯的後果**不是報錯**:`hct-client.ts:155` 把非 2xx 判成 `unknown`(「它可能收了」)⇒ **那一箱卡死, 而出口還沒做**。

## 3. 發幾發、順序、每一發怎麼判

### 🟢 第 0 發(主視窗 2026-09-05 批「甲」)—— **故意讓它失敗**
```
帳號     test
密碼     (故意留空)
json     {"data":[<一筆最小合法欄位>]}
```
**為什麼要有它**:它把**兩個問題拆開**。
```
沒有第 0 發   一發失敗 ⇒ 「信封組錯了」與「外層形狀錯了」分不出來
有第 0 發     它拒絕的理由是【帳密】⇒ 證明信封、SOAPAction、namespace、參數名【全對】
              ⇒ 之後三發的失敗, 就只可能是外層形狀
```
🛑 **判準寫出來**:
· 回 `soap:Fault` **且訊息與帳密無關**(例如 XML 解析錯)⇒ **信封還沒對 ⇒ 停, 不發後面三發。**
· 回 **HTTP 200 + 一個業務層的失敗**(`success=N` 或帳密相關 `ErrMsg`)⇒ ✅ **信封對了, 可以往下。**
· 回 **HTTP 200 + `success=Y`** ⇒ 🔴🔴 **立刻停** —— 空密碼竟然建單成功, 那代表這個端點的行為與我們理解的完全不同。

### 🟢 第 0 發【已送出, 2026-09-05 16:5x】—— 結果:信封全對
```
HTTP 200 · 819 bytes · text/xml; charset=utf-8 · 0.042 秒 · curl rc=0
success = "N"   ErrMsg = "公司名稱或密碼錯誤"   edelno = null
```
✅ 照上面判準第二條 ⇒ **信封 / SOAPAction / namespace / 參數名(`company` `password` `json` 全小寫)全對。**
🔵 **順便量到三件**:①它回 SOAP 而 body 裡是一段 JSON 字串 ②**空密碼建不了單, 已實證**
   ③回傳欄位表 **20 欄**(機械數的):`Num success edelno epino erstno eqamt image ErrMsg NewOutArea eqmny
   CODE1 CODE2 CODE3 CODE4 CODE5 CODE7 AREAS MDCODE1 MDCODE2 MDCODE3`
   🔴 **`CODE6` 不在裡面** ⇒ 未查, 不猜 ⇒ **寫消費端時不要假設 CODE 是連續的。**
🛑 **而它是在【帳密關卡】被擋下來的 ⇒ 沒有走到解析 `json` 那一步 ⇒ 外層形狀一格都還沒被回答。**

### 🔵 第 1-3 發 —— 三種外層形狀

#### 🛑 **而我把它們改輕了 —— 這是【往安全側偏離授權】, 所以要寫在這裡**
```
本 plan 原本   三發各送【20 個完整欄位】
實際做法       只送【1 個欄位】(epino)
理由           形狀對 ⇒ 回「欄位不足」;形狀錯 ⇒ 回「格式錯」
               ⇒ 兩個世界照樣分得開, 而【建單成功】那個世界幾乎被關掉
```
📌 **Sean 批的是「可能建單」那一版, 我做的比他批的輕 ⇒ 輕的那一側也要說。**
🔴 **而它買到的代價要一起寫**:「**形狀①在【完整欄位】下會不會成功**」⇒ **這一版測不到。**
   ⇒ 下一個人不要把「形狀①通過」讀成「我們碼裡那個外層是對的」——
     它只證到「那個外層沒有在解析階段被拒」。

```
形狀①  {"data":[ {…20 欄} ]}      ← 我們今天碼裡送的(`hct-client.ts:145`)
形狀②  [ {…20 欄} ]               ← 純陣列
形狀③  {…20 欄}                   ← 純物件
```
**順序 = ①②③**, 理由:**①是我們碼裡現在的形狀** ⇒ 它若成功, 後面兩發**不必發** ⇒ **不可回收的動作少兩發。**
🛑 **一次只發一發, 每發之後停下來讀回應再決定要不要發下一發。** 禁止一次發三發。

**每一發的判準**(照 runbook `:165` 的回傳值表):
```
success = Y  新增成功       ⇒ 🔴 立刻走 §4 取消
success = R  修改成功       ⇒ 🔴 立刻走 §4 取消(而且要記:它把某張既有單改掉了)
success = N  失敗           ⇒ ✅ 讀 ErrMsg。若 ErrMsg 指向「格式/欄位」⇒ 這個外層被拒 ⇒ 換下一個形狀
其他 / 非 2xx / 不是 JSON   ⇒ 🛑 unknown ⇒ **停**, 不要換形狀再發
                              (我們不知道它收了沒 ⇒ 再發一發可能變成兩張單)
```

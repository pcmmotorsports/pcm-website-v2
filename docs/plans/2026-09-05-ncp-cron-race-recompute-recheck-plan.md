## 3. 做法(一句)

**在 `pcm_noncard_settle_recompute` 拿到 advisory 之後、算任何東西之前,重讀 `orders.cancelled_at`;
已取消 ⇒ 不翻 `payment_status`,改呼叫 `pcm_pending_refund_open_for` 開一筆待退款。**

```
現況(:201 起)          v2
  advisory                advisory
  讀 payment_status       讀 payment_status + cancelled_at      ← 加這一欄
  算 verdict              IF cancelled_at IS NOT NULL THEN
  翻 payment_status         開待退款 + RETURN                    ← 加這一段
                          END IF
                          (以下不變)
```
🔵 **為什麼放在 advisory 之後**:advisory 之前讀到的是舊世界;而 A 的 UPDATE 一旦 COMMIT,
　 B 在自己的 snapshot 裡就看得到(B 的 INSERT 已經被列鎖擋到 A COMMIT 之後才開始)。
🛑 **而這一句成立要靠一個前提:B 真的會被擋到 A COMMIT 之後。**
　 那正是 §1 那個機制 —— ⚠️ **而它是 codex 給的,我沒有自己量過。** 見 §6①。

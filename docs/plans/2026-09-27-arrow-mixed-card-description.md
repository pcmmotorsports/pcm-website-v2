# 計畫：Arrow 混合卡的商品說明（2026-09-27，窗「進度 a0」）

> 狀態：**09-27 Sean Q1 甲**（經主視窗轉達）⇒ 已照「甲的細節」實作，見第六節。
> 「混合卡」＝一張商品卡底下有好幾款（例如 GP2 和 GP2 Dark），而且各款的說明不一樣。

## 一、現在怎麼挑說明

- 位置：`scripts/rpm-transform.ts:498`
  `const description = variants.find((v) => (v.description ?? '').trim() !== '')?.description ?? null;`
- 款式的順序來自讀報價單時的 `order('sku')`（`scripts/rpm-fetch.ts` 的 `fetchPageWithRetry`），分卡時照原順序放進去（`scripts/rpm-import.ts` 分群段）。
- 所以：**整張卡的說明＝料號字母排最前面、而且有說明的那一款**。其他款的說明客人看不到。
- 同一個挑法也用在「賣點」（`rpm-transform.ts:500`，第一個非空的 highlights）。
- 卡片的標題和價格則是用**最便宜的那一款**（`rpm-transform.ts` 的 `basis`）。兩者可能不是同一款。

### 為什麼今晚會換

Arrow 有一條只有它有的規則（`supplier-config.ts` 的 `requireListingContent: true`）：缺說明或分類的款式先不上架。今晚報價單替 63 列新款補上說明，這些款式第一次被放進卡裡。如果新款的料號字母排在舊款前面，卡片說明就換成新款那段。

### 「優先挑主料號那段」對 Arrow 沒有用

Arrow 的主料號長這樣：`ARROW-71556-SILENCERS`，而各款料號是 `71556GP`、`71556GPI`。**283 張多款卡裡，沒有任何一張有料號剛好等於主料號**（下面第二節的預測腳本算的）。所以那條規則在 Arrow 永遠挑不到東西。

## 三、問題不只今晚這 20 張

225 張混合卡，客人都只看得到其中一款的說明。例如 GP2 尾段排氣管組：

- 71556GPI（GP2 Dark，17,800 元）：「黑鋼罐身搭配不鏽鋼尾蓋…通過 ECE 認證」
- 71556GP（GP2，22,400 元）：「尾段外殼材質為鈦合金…具道路合法認證」

卡片價格顯示的是便宜的 GP2 Dark（17,800），而今晚之後說明寫的是鈦合金那款。客人選 GP2 Dark 時讀到的材質是錯的。
Sean 09-26 Q14 甲要求「一款一套」的卡，新款也逐款寫 WRS 說明；照現在的挑法，那些逐款寫好的說明大多不會出現在網站上。

## 四、修法選項

| | 做法 | 改哪裡 | 影響 |
|---|---|---|---|
| 甲（推薦） | 卡片說明改成「分款列出」：各款說明不同時，每段前面加上款式名稱（規格欄 `spec.style`，例如「GP2 Dark」）；各款說明相同就照舊只放一段 | `scripts/rpm-transform.ts` 挑說明那一行改成一個小函式＋測試；只對 Arrow 開（`supplier-config.ts` 加一個設定） | 只影響 Arrow。約 225 張卡的說明會變長，下一次每日同步生效。不動資料庫結構、不動商品頁 |
| 乙 | 每款各自顯示說明：客人在商品頁選哪一款，就顯示那一款的說明 | 資料庫 `product_variants` 加說明欄（migration）、匯入寫入、商品頁元件 | 畫面最正確，但要動 schema、匯入、前台三處，工作量大很多，要另寫完整 plan |
| 丙 | 只讓說明固定不換：卡片已上架的說明，只要還屬於某一款就保留 | 匯入程式要先讀網站現有說明再比較 | 只解決「換來換去」，不解決「其他款看不到」；今晚已經換掉的 20 張會維持新的 |

推薦甲的理由：成本最低（一支檔＋設定＋測試），就能讓 225 張卡的每一款說明都出現在網站上，Q14 逐款寫的說明也看得到。缺點是說明比較長、不像乙那樣跟著選項切換。

### 甲的細節（Sean 批了才做）

- 標題：用 `spec.style`；沒有 style 時退回料號。
- 順序：沿用現在的料號順序，讓每天同步的結果一樣，不會每天換來換去。
- 各段之間空一行。每段結尾那句「適用車款與年式以本頁標示為準」重複時只留最後一次。
- 賣點（highlights）不改，仍取第一款（另案）。
- 其他 21 家供應商行為不變（設定預設關閉），測試裡釘一格「沒開設定的供應商說明逐字不變」。

## 五、影響與退回

- 影響範圍：只有 Arrow 的商品說明文字；價格、庫存、分類、款式不受影響。
- 生效時間：合併並推上 dev 之後的下一次每日同步。
- 退回：revert 那一顆 commit（或把 Arrow 的設定關掉），下一次每日同步就回到現在的挑法。不需要動資料庫。
- 驗證：單元測試（混合卡／同說明卡／沒開設定的供應商三格，先寫會紅的）＋乾跑印出前後差異筆數＋同步後在正式站打開 GP2 尾段排氣管組那張卡看。

**下一個讀的人第一個問題會是「有重現嗎」—— 答案是【沒有,而且不需要】。**


**那個不變式,是那道柵欄自己的 docstring 寫的**(`SupabaseEmailOutboxAdapter.ts:14-15` 逐字):
> 「`claimedAttempts` 世代柵欄:**lease 回收 + 他人再認領後(attempts 已 +1)**,舊持有者延遲到達的標記 `.eq('attempts', 舊世代)` 必 0 列 → 不覆寫別人的在途列(ABA 擋掉)」

🎯 **⇒ 它的前提是「`attempts` 只會往上走」。而救援 RPC 把它歸零 —— 前提不成立。**
📌 **一個 ABA 防護,被一個【合法的業務動作】從背後打開。而兩邊各自都對:**
救援**必須**歸零(不歸零它還是死信,`:366` 逐字拒絕未燒完的列);柵欄**必須**用單調值(不單調就擋不住 ABA)。
🛑 **⇒ 要修的不是誰做錯了,是【一個欄位兼兩職】。**

## 2. 🎯 分母:離開 `sending` 的路有幾條,各自的柵欄狀態

**🔴 而第一件要更正的是那句話本身**:docstring `:17` 逐字寫「**mark\* 三出口**皆帶柵欄」——
🔬 今天實數:`return this.leaveSending(` 呼叫點 **15 個**(🔵 負對照 `leaveZzq` ⇒ 0)。
⇒ 📌 **「三」這個數字已經過期了。而重點不是它變成 15,是【它被引用了三次當成分母】。**

| # | 路 | 帶世代柵欄? | 落點 |
|---|---|---|---|
| 1 | `leaveSending` 的 15 個呼叫點 | ✅ 帶(helper 強制吃 `claimedAttempts`) | `SupabaseEmailOutboxAdapter.ts`(15 處) |
| 2 | `markSentWithProviderId` 那條自訂路 | ✅ 帶(`:1242` 兩個述詞都留) | 同檔 `:1217-1242` |
| 3 | `reclaimStaleLeases` | 🔴 **不帶(帶不了)** —— 回收器不是持有者、無此值;靠 `claimed_at < staleBefore` 判所有權 | 同檔 `:1461-1485` |
| 4 | `admin_requeue_dead_email`(人工救援) | 🔴 **不帶,而且它【把世代歸零】** | `20260915040000:374-380` |

**把 `attempts` 一個欄兼兩職拆開。三個候選,我排序並說明取捨 —— 不替 Sean 選。**

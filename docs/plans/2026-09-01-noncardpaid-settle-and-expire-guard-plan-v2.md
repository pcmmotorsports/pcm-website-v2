## 2. 🔴 #3(券)—— 而它今天【不可能發生】,那改變了它的處置

codex 說:我引入的 `partiallyPaid` 中間態,會讓券的兌換 trigger(只接受 `OLD.payment_status = unpaid`)在第二次翻 `paid` 時不觸發

### ✅ 而我實查正式庫 ⇒ **那個 trigger 今天不存在**

```

  🟢 正對照 全庫非內部 trigger 總數 ⇒ 62(尺會動)
函式名含 coupon 的 ⇒ (none)
```
🔵 **⇒ 券那一整片(`20260901030000` 等)【還沒 apply】。**

### 🛑 ⇒ 所以 #3 的形狀是【順序】不是【設計錯】

```
今天貼本片    ⇒ 券 trigger 不存在 ⇒ 不會壞
之後貼券片    ⇒ 🔴 券 trigger 上線, 而它的前提 OLD.payment_status = unpaid 與本片的中間態相撞
先貼券片再貼本片 ⇒ 同上
```
📌 **⇒ 兩片各自都對, 而【誰後貼誰踩到】。⇒ 那是今晚同一個母題的第五個實例。**
🔴 **⇒ 而最危險的是:今天測本片會全綠, 而那個綠【不涵蓋券片上線之後的世界】。**

**兩個選項,代價都要寫出來:**
```
甲 不引入 partiallyPaid 中間態(underpaid 也不翻)
   ⇒ 券那一格安全, 而【少收的單】沒有任何狀態標示 ⇒ 它靠 cron 那條腿活著
   ⇒ 而那讓「不翻」的那一堆變大 ⇒ 更依賴 cron 那道兜底
乙 改券 trigger 的前提(接受 partiallyPaid → paid)
   🛑 而那是【券那條線的檔】, 不是本片能改的 ⇒ 要跨線協調, 而它還沒 apply ⇒ 現在改最便宜
```
🔵 **我推乙, 而理由是時機**:券片還沒 apply ⇒ **現在改它的前提,成本是零;等它上線再改,就是改正式庫上的 trigger。**
🎯 **而那要跨線 ⇒ 已交主視窗 `-0a` 協調(2026-09-01 21:xx,它逐字回「券那條線的協調我接」)。**

📌 **⇒ 一句沒有錨的「已交出去」,與一句「我打算交出去」在事後長得一樣。**

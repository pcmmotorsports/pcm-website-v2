## 1. 通用款的判定(逐字出處)

只有一條:`p.fitments = '[]'::jsonb`,下在 view `products_list_public` 上。

## 2. 🔴 分區要改哪裡 —— 兩條路,我選 B,理由是分頁

### 現況已經有的東西(不用新造)
- RPC 內部**已經有 `fit_rank`**(0 專用 / 1 通用),而且**已經是第一順位排序鍵** ⇒ 專用一定排在通用前面
- 回傳的 `item` jsonb **已經帶 `fitments` 與 `fits`** 兩欄;`fits` 逐字就是現成標籤:
  空的 ⇒ `"通用款"`(Sean 截圖看到的「適用 通用款」就是這一欄)、有車款 ⇒ `"Aprilia Tuono V4"`

### 路 A:前端分組,**零 DB 改動**
前端照 `fitments.length === 0` 切兩區。
- ✅ 不碰 RPC、不碰 migration、不碰鐵則 12
- 🔴 **錯判上限已量**:全站 21 件(`fitments` 空、但在 `product_fitments_effective` 有繼承車款)會被前端判成通用,而 RPC 算它專用。CB1000 Hornet 2026 這台是 **0/135**。
- 🛑 **致命的是分頁,不是錯判**:一頁 25 筆,專用 135 件 ⇒ 第 1-6 頁全是專用,**第二區從第 6 頁才開始、橫跨 226 頁**。
  ⇒ **Sean 拍的「第二區預設收合」在這條路上做不到** —— 收合一個橫跨 226 頁的東西沒有意義。
  📌 這正是「照批准的字面做下去,交出一個空的」那一族。

### 路 B:RPC 加一個範圍參數(**推薦**)
`search_catalog_by_vehicle` 加 `p_fit_scope text DEFAULT 'all'`(`all` / `fit` / `universal`),只在 `cand` 那一段多一個 WHERE。
- 主清單傳 `fit` ⇒ 只有 135 件、自己分頁;第二區傳 `universal` ⇒ 5,657 件、自己分頁、預設收合
- ✅ 這條路「預設收合」是真的做得到的
- ✅ 順手解掉錯判 21 件(fit_rank 是 DB 算的,前端不再自己判)

**🔴 風險與做法(CLAUDE.md 那條 2026-09-16 板 199 的帳)**
加參數 = **簽章改變**。`CREATE OR REPLACE` 不會取代舊的,會**新建一支** ⇒ 兩支同名多載 ⇒ PostgREST 依參數名解析,舊呼叫仍打得到舊那支。
⇒ 做法:**同一支 migration 裡 `DROP FUNCTION` 舊簽章 + `CREATE` 新簽章**,並且**貼板與推碼當成同一次動作**,中間時間壓到最短。
⇒ 影響面:`search_catalog_by_vehicle` 與 `search_catalog_by_vehicle_dealer` **兩支都要改**(經銷側同形)。

## 3. 🔴 側欄件數:分區之後那些數字代表什麼

現況 `catalog_facet_counts` 算的是 `專用 ∪ 通用` ⇒ 側欄「維修零件 1,380」點進去確實有 1,380 件。
分區之後**不改它就會說謊**:側欄叫你點 1,380,而主清單那一區是 0 件,1,380 全在收合的第二區裡。
📌 這是「亮法宣告的狀態,跟清單真正的母體對不起來」那一族(與 chip 互相干擾同族)。

⇒ **側欄要跟主清單同一個母體**:`catalog_facet_counts` 也吃 `p_fit_scope`,選車時算 `fit`。
⇒ 那 Hornet 的側欄會變成:拉桿 29 · 外觀 41 · 腳踏 17 · 維修零件 **不出現**。**這才是他的車真正有的東西。**
⚠️ 第二區自己要不要側欄,是另一題,**這一版不做**。

## 4. 四輪 ATV/UTV 那 44 件 —— 🔴 這不是同一個問題,不要一起修

```
四輪 ATV/UTV 全櫃 44 件 · 其中沒車款 44 件(100%)· 供應商 1 家(samco)· 全部是矽膠水管
```
它們不是「通用機車零件」,是**四輪車的零件**。放進「通用配件」區仍然是錯的。

### 4.1 「五櫃不進」我不建議做 —— 兩條路我都反對

- **寫死分類清單會過期**:哪天維修零件真的有專用件就錯了。而且 **ATV 那櫃是永遠該擋、進氣那櫃只是這台車剛好 0** —— 性質不同,寫死會把兩件事混成一件。
- **用「專用 0」動態判定是錯的尺**:它會連 1,380 件真的通用維修零件一起藏掉,而那些是 Sean 可能想留的。

### 4.2 動態判定真的做下去會怎樣(實測,不是推論)

規則 =「大類至少有 1 件專用,它的通用件才准進第二區」。`Honda CB1000 Hornet 2026`:

```
第一區 專用        135
第二區 通用(套規則後) 3,792
被擋掉                1,865
  維修零件 1380 · 進氣系統 277 · 碳纖維部品 138 · 四輪 ATV/UTV 44 · 懸吊與車架 25 · 服務與其他 1
```

🔴 **而它會隨資料抖動**:這 1,865 件被擋掉,只因為這台車在那幾櫃剛好 0 件專用。
**換一台車就換一組**(`Honda CB500 Hornet`:專用 48、有專用的櫃 8 櫃、通用區 1,995)
⇒ **同樣 1,380 件維修零件,在某台車看得到、在另一台車消失** —— 而消失的理由跟那 1,380 件本身無關。

🔴 **⛔ ~~碳纖維部品那櫃是最好的反例:它現在「專用 0」是那 117 群被削光的影子~~**
**2026-09-16 我自己複量,這句對 Hornet 這台【是錯的】,逐字更正**(詳見 §8):
- 碳纖維部品全櫃 **2,789 件,其中 2,651 件是有車款的** ⇒ 對 Hornet 的 0 **是真的**,只是沒有一件碳纖維是為 Hornet 做的
- 那 117 群的料號前綴指向 **Kawasaki / Yamaha / Harley / Suzuki / Ducati / BMW / Aprilia**,**沒有一個看起來是 Honda**
⇒ **修好那個 bug,Hornet 的碳纖維大機率仍然是「專用 0」。**

🔵 **而反例本身仍然成立,只是換一台車**:那 117 群是**某些車**的專用件(YAMT 24 群看起來是 Yamaha MT、KAH 34 群看起來是 Kawasaki)。
⇒ 對**那些車**,這一櫃的件數會在 bug 修好的那一天改變。
📌 **⇒ 規則的輸出會隨著另一個 bug 的修好而改變,而沒有任何一層會叫。那才是不該拿它當規則輸入的理由。**

**44 件、1 家供應商 = 這是資料問題,不是程式問題。** 為 44 件蓋一道以後沒人看得懂的閘,是今天一直在抓的形狀。

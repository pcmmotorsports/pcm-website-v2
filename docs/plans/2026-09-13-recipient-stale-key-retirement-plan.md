## 0. 一句話結論(先講,因為它與派工時的預期相反)

**建議:維持現狀 —— 收件地址重驗那條路【繼續無條件退休鍵】。**

📌 ③ 確實給了第三條路(按「有沒有交給過 provider」分流),**而那條路在這一族是錯的方向** ——
理由在 §3:**這一族的「第二封」寄給的是【另一個地址】,不是同一個人再收一次。**

⇒ 本檔要 Sean 批的,是**「這個不做」**,不是一個改動(§8)。

## 1. 為什麼這份 plan 現在才寫得出來

我當初開 ② 的時候,手上只有兩條路,**而兩條都有人受害**:
```
退休鍵   ⇒ 那一列可能已經送過 ⇒ 重排 ⇒ 新的 outbox id = 新的 provider 冪等鍵 ⇒ 寄第二封
不退休鍵 ⇒ 五族的鍵不含地址 ⇒ 每輪算出同一把鍵 ⇒ 撞唯一鍵、永遠插不進去 ⇒ 永久漏寄
```
⇒ 🎯 **一個做不出來的取捨,常常是因為缺一個問不出來的事實。**
③ 之後那個事實變成可問的(`handedToProviderAt`),所以這份 plan 才寫得出來。

> 🔵 而 ③ 的判準值得照抄進來,因為 ② 會再次面對「這一列到底怎樣」這種問題:
> codex R2 打掉我第二版時,真正的發現是 —— 一列「送過、死掉、被救回來」的舊列,
> **在每一個欄位上都與全新的一模一樣**。📌 **它身上沒有證據,而我兩次都在找一個不存在的證據。**
> ⇒ ✅ 修法是把問題從「**找證據**」換成「**定義一個可證的世界**」
>   (判準從「證明它送過」換成「**證明不了它沒送過**」)—— 那不是變寬鬆,是**換掉一個不可判定的述詞**。

## 3. 🔴🔴 核心:失敗方向是**不對稱**的 —— 而那正是第三條路在這裡錯的原因

**③ 的分流在 `bank_order_amount_changed` 那一格是對的,它的世界長這樣**:
```
同一個地址 · 同一個人 · 兩封信 · 而且【金額不同】
⇒ 客人可能照錯的數字匯款, 或匯兩次 ⇒ 📌 第二封是【有害的】
⇒ 所以「可能送過 ⇒ 不重排」是對的。
```

**收件地址重驗那一格的世界【不一樣】**:
```
地址 A → B。那一列是排給 A 的, 而它【可能已經寄到 A 了】。
· 退休鍵    ⇒ B 也收到一封(內容由下一輪掃描面【重算】, 是一封正確的信)
              ⇒ A 那一封已經寄出去了(外洩已經發生, 退不退鍵都改變不了)
· 不退休鍵  ⇒ 🔴 **B 永遠收不到** —— 而 B 才是現在那張單的收件人。
```
⇒ 🎯 **「第二封」在這一族不是同一個人多收一次,是【另一個地址】的人第一次收到。**
⇒ 📌 **所以兩邊的代價不是「重複 vs 漏寄」,是「一封已外洩的信 + 正確的人收到」
   vs「一封已外洩的信 + 正確的人永遠收不到」。** 後者嚴格更糟。

🛑 **而外洩那一半不在本題的射程內**:A 收到那封信,是在**地址改掉之前**就送出去的
⇒ 退休鍵這個決定**發生在它之後**,救不到它。
⇒ 這條路治的病本來就是「**之後**不要再寄到 A」,而它已經做到了(那一列被標終態、不寄)。

---

## 4. 那 ③ 那個事實在這裡完全沒用嗎 —— 有一格,而它很窄

`bank_order_amount_changed` **同時**會走這兩條路(它是七族之一)。
⇒ 一列 amc 若「已送到 A、地址改成 B」⇒ 退休鍵 ⇒ 重排 ⇒ **B 收到一封金額正確的新信**。
🔵 **而那不是 §3 講的那個有害情境** —— 有害的是**同一個地址收到兩個金額**,
這裡是兩個地址各收到一封,而**後面那封的金額是重算的、正確的**。
⇒ ✅ **結論不變:這一格也不該改。**

## 7. 🔴 什麼會讓這個答案翻過來(寫出來,免得下一個人以為它是永久的)

```
① 哪天有一族的信【內容含金額而且會被重算】, 同時它的 dedup_key 不含地址
   ⇒ 地址沒改而「重排」被別的路徑觸發時, 那個有害情境就回來了。
   🔵 今天 amc 的重排是【重算】⇒ 它出的是正確的新數字, 所以不成立。
② 哪天 `getCurrentRecipient` 開始回「同一個人的第二個信箱」而不是「換人了」
   ⇒ 「另一個地址」這個前提變了 ⇒ §3 的不對稱要重算。
③ 哪天有人把「已外洩那一封」也算進本題的射程(例如要做召回 / 通知)
   ⇒ 那是另一件事, 不是退不退鍵。
```

## 8. 🛑 這支 plan 證不到什麼

- **我沒有量正式庫** —— 本檔每個座標都是 repo 內的檔與行號(我逐條開檔對過)。
  「正式庫有幾列 `recipient_stale_at_send`」這種數字**本檔一個都沒有**。
  🔵 而那個數字**不影響結論**:§3 是方向的論證,不是頻率的論證。
- **它沒有驗「A 那一封真的寄到了」** —— 那要 provider 端的資料,而本欄位族只記到「交出去了」。
- **它不處理外洩本身**(§3 最後一段):那一封已經出去了,本題的任何選擇都救不到它。

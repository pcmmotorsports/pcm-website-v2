## 1. 要改什麼

**一句**:`pcm_pending_refund_on_cancel` 今天只在**整單取消**那一刻開待退款;**部分取消不開** ⇒ 那些單收了的錢**沒有任何東西提醒要退**,而**它不會叫**。

## 2. 為什麼(而它為什麼不是「漏做」)

板列逐字:部分取消不開待退款**是刻意的** —— 因為「部分取消該退多少」曾被當成沒有人答過的口徑題。
🟢 **而那個前提已經不成立**:Sean 在 `Q13` 自己給了公式(原話抄在
`supabase/migrations/20260810100000_m4b_e10_op1_order_payments_m.sql:25-26`):

> 「保留,看剩下訂單總金額多少,退掉多餘部分,不足的話也不用退款,就當作是先收多餘部分」

⇒ **退款額 = `max(0, 已收未退總額 − 取消後訂單剩餘應收總額)`**

## 3. 🔴 算式的每個名詞指到哪一欄(主視窗指定;**這一節是本 plan 的重點**)

| 名詞 | 來源 | 狀態 |

**一個看起來對的金流算式,錯的地方通常在「那個欄位到底裝什麼」,不在算式本身。**

## 4. 🔴 觸發集合的前後差(兩張清單並列)

**現在**(`20260901080000_m4b_autorefund_pending_refunds.sql:495-496`):
```
CREATE TRIGGER order_pending_refund_open_au
  AFTER UPDATE OF cancelled_at ON public.orders
```
⇒ 只在 `orders.cancelled_at` **由 NULL 變非 NULL** 那一刻(`:377` 逐字「只在【由無變有】那一刻發火」)。
⇒ 涵蓋:整單取消 · 一連串部分取消**把最後一件也取消掉**(那時 `cancelled_at` 才變)。

**加完之後**(待定,**本 plan 不預設形狀**):要涵蓋「**訂單仍有未取消品項,而某些品項被取消**」那一刻。

## 1. 改什麼

**選【A:整段刪掉】,不選【B:把門檻改成一個大到不會觸發的數】。**

· A = 刪掉兩個分支的 `new_batch_days` CTE、兩處 `NOT EXISTS(… new_batch_days …)`、以及 `:365` 的門檻常數。
· B = `c_batch_day_threshold` 改成 `2147483647`。

**為什麼選 A**:
1. B 留下一段**每次新品查詢都會跑、而永遠回 0 列的聚合** —— 它掃的是 7 天窗內整批列。
   那是白付的成本,而且**下一個人看到那段碼會以為規則還在**。
2. B 的「rollback 比較簡單」在這裡**不成立** —— 兩種做法都得 `CREATE OR REPLACE` 重貼**整支函式**
   (PostgreSQL 不能只改函式裡的一行)⇒ 📌 **兩者的 rollback 是同一件事:把舊的函式體整支貼回去。**
   ⇒ 既然代價相同,選讓碼誠實的那一個。

⚠️ **`:226` 那個字串字面**:它是前一段 migration 用來斷言「上一代長這樣」的自我檢查。
本次**不刪它、也不改它** —— 它描述的是**歷史上那一代**,不是現在這一代。
🛑 而**要在新 migration 裡寫一句話說明**,否則下一個人會拿它去對現況然後以為漏改了。

## 4. rollback —— 一支可執行的檔,不是散文

⚠️ 板列 `⟦db-NOROLLBACKARTIFACT⟧`:351 支 migration 裡寫在檔內的可執行反向 SQL = **0 支**。
**本次不再加一支符合那個描述的。**

產出 `supabase/rollbacks/<新版本號>-rollback.sql`,內容 = **把改動前那一版函式體原樣貼回去**:

```sql
-- supabase/rollbacks/<新版本號>-rollback.sql
-- 一句話就跑得完:把 search_catalog_by_vehicle 還原成 20260909010000 那一版(批次日規則還在)。
-- 🔴 直接從 supabase/migrations/20260909010000_m4b_search_catalog_keyword_terms.sql 的
--    :333 起那整支 CREATE OR REPLACE 逐字複製過來(含 p_terms),不是重寫。
BEGIN;
SET LOCAL lock_timeout = '5s';
CREATE OR REPLACE FUNCTION public.search_catalog_by_vehicle(...13 參數...)
  ... 逐字 = 20260909010000 的函式體 ...
COMMIT;
```

**驗收 rollback 真的可執行**(不是宣稱):在鑽機上(`bash scripts/storefront-probe/up.sh`)
套 forward ⇒ 套 rollback,而**驗收要直接打那支 13 參數 RPC,不要只看 `?filter=new` 的件數**。

🔴🔴 **[唯讀對抗審查 R1 must-fix ③ —— 我原本那道驗收【證不到 p_terms】]**
⛔ ~~「`?filter=new` 件數要回到『批次日被擋』那個數」~~
🛑 那個數字**對關鍵字功能完全沒有判別力**:rollback 就算把 `p_terms` 整段濾除邏輯漏掉、
只保留參數簽章,新品件數**照樣完全正確** ⇒ 📌 **一道量不到自己要保護的東西的驗收。**
⚠️ 而 `lib/products.ts:497-512` 的呼叫端**今天不傳 `p_terms`** ⇒ **走頁面永遠驗不到它**;
頁面還有 60s 快取,可能讀到舊結果。

✅ **改成直接呼叫 RPC 的四格**(同一批資料、同一個時間窗,forward 與 rollback 各跑一次):

| 格 | 打法 | forward 期望 | rollback 期望 |
|---|---|---|---|
| ① `p_brand IS NULL` 分支 · 無關鍵字 | `p_new_since=7 天前, p_terms=NULL` | 批次日商品**回來** | 批次日商品**再被擋掉** |
| ② `p_brand` 有值分支 · 無關鍵字 | 同上加 `p_brand` | 同上 | 同上 |
| ③ 兩個分支 · **關鍵字有命中** | `p_terms='{碳纖維}'` | 回得出東西 | **與 forward 相同** |
| ④ 兩個分支 · **關鍵字無命中** | `p_terms='{zzz_bogus}'` | 0 列 | **0 列** |

🟢 ③④ 是這道驗收的**判別力來源** —— 少了它們,一個把 `p_terms` 濾除整段弄丟的 rollback 會全綠。
🔵 再加一格靜態比對:rollback 套完之後 `pg_get_functiondef` 與基底 `20260909010000` 的函式體**逐字相同**。

**這一步在 plan 批准後、貼正式庫前做。**

## 4. 改什麼 —— 照 `⟦b4-CANCELMAILMIXEDRAIL⟧` 那一族的現成形狀,不發明新的

### 4-1 DB:一支 `get_*_gap_counts` 風格的函式
```
public.get_paid_after_cancel_gap_counts() RETURNS jsonb
  { "drift_count": <先寄付款信才被取消的張數>,
    "total_count": <分母:已取消而身上有【任何】信的張數>,
    "oldest":      <最舊那張的 cancelled_at, 沒有就 null> }
```
- 述詞(2026-09-10 已在正式庫唯讀跑過,回 0):
  `orders.cancelled_at IS NOT NULL AND email_outbox.sent_at IS NOT NULL AND email_outbox.sent_at < orders.cancelled_at`
  ⚠️ **而「付款信」那一格要收窄到 `eventType = 'order_created'`** —— 上面那一發我沒有收窄,
  它算的是**任何信**。⇒ 實作時要把 `event_type` 條件加上,並在 plan 驗收裡分開驗兩種。
- `SECURITY DEFINER` + `SET search_path TO ''` + 兩道 REVOKE + `GRANT EXECUTE TO service_role`
  (照 `docs/patterns/revoking-function-execute-in-supabase.md`;告警只由後端排程叫)
- 🔴 **`total_count` 是分母,不可省** —— 現成的那一族逐字寫著理由:
  「`Pending = 0` 而分母也 0 ⇒ 那是『今天沒有這種單』;分母 > 0 而 Pending = 0 才是
  『有這種單而都寄完了』。**兩者不可印成同一句。**」
- migration 號段 **`…07xxxx`**(我的);實作時**當場重跑撞號閘**,不沿用本 plan 猜的號碼。

### 4-2 adapter:`PgAnomalyAlertReaderAdapter`
照同檔 `cancelledMixedRail*` 那三格逐字複製形狀:
- 函式查不到(沒 apply / 沒授權)⇒ `undefined` ⇒ 三格回 **`null` 不是 0**
  (逐字理由:「**讀不到**」與「**一切正常**」在裸數字上長得一模一樣)
- 回了但不是物件 ⇒ `throw AnomalyAlertReaderParseError`

  傳參的話它只看得到 1 個 ⇒ 📌 **那一族的契約保護會縮水,而它照樣印綠。**
  🔬 該檔逐字記著這道閘 2026-09-07 當場咬過人。

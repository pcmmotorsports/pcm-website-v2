# 怎麼判一個帳號是測試的 —— 判準 · 2026-09-10(唯讀;板檔零改動)

> 🔴 **這一份的由來是我自己犯的錯**:我寫「15 個客戶裡有 **1 個**是測試帳號」而答案是 **3 個**。
> **成因不是算錯,是【我只問了我知道名字的那一個】** —— 我的尺只找得到我已經知道的東西。
> 🛑 **所以這一次照交代:先建判準,再去找。** 底下 §三 那個「有沒有第四個」是**用判準跑出來的**,不是憑印象。
> 🛑 **PII**:全程**不印完整信箱與姓名** —— 只印遮罩後的識別。真客人的資料不落地在這份檔裡。

# §三 · 「有沒有第四個?」—— **這一次先建判準再找**

## 🟢 用判準跑出來的答案:**在【今天這 15 個】裡,沒有第四個。**

**依據**:第 2 層與第 3 層把「機器不會叫的 12 個」逐個看過 —— 7 個是合成信箱(有 migration 逐字證據)、4 個是外部真網域、1 個要人看。**沒有第四個「我們自己造的帳號」。**

## 🔴 而這個「沒有」有三個明確的洞,我寫出來不遮

| 洞 | 為什麼 | 要補得做什麼 |
|---|---|---|
| **① 三條機器規則都在「找我們留下的痕跡」** | 一個用 `mytest2026@gmail.com` 註冊、姓名填「王小明」的測試帳號,**三條都不會叫** | 要看**行為**(下單 1 元 / 建完就全退 / 同一個 IP)—— 而那要訂單層的查詢 |
| **② `uitest` 的 M3 是【後來才成立的】** | `2026-08-08` 之前它姓名是空的 ⇒ **M3 對它 `false`** | 📌 **⇒ 判準不能只看「現在長什麼樣」,它會隨著有人手動改資料而改變** |
| **③ 我只看了 `public.customers`** | `auth.users` **我沒權限讀**(逐字 `ERROR: permission denied for schema auth`)⇒ **一個【註冊了但沒有 customers 列】的測試帳號,我這把尺完全看不到** | 要有 `auth` 讀權限的人跑一發 |

🎯 **⇒ 所以正確的說法是**:
```
✅ 「在 public.customers 這 15 列裡, 沒有第四個測試帳號」—— 這句我證得出來
🛑 「全站沒有第四個測試帳號」—— 這句我證不出來, 而且【我這把尺結構上證不到】
📌 而那正是我上一次犯錯的同一個形狀:【我的尺的射程被我的已知圈住】。
   這一次我把射程寫出來, 而不是把它讀成一個 0。
```

## 🔵 建議的判準寫法(可以直接抄進碼或閘)

```
一個帳號【疑似測試】 ⇔
   ① 信箱網域 = pcmmotorsports.com          (不含 *.pcmmotorsports.local)
   ∨ ② 信箱 local part 命中 test|sandbox|preview|demo|qa|staging|dummy|fake
   ∨ ③ 姓名命中 測試|沙盒|test|sandbox|UX|demo
   ∧ ¬ isSyntheticEmailDomain(email)        ← 🔴 這一條是【必要的】, 它擋掉 7 個真客人
⇒ 命中者【不自動排除】, 只進一份【給 Sean 過目的名單】
```
🛑 **而它刻意【不是】一個 `is_test` 欄位** —— 窗A 今天證過:加旗子的成本在「**每個聚合都要記得帶條件**」,而**忘記帶條件不會紅**。
✅ **⇒ 一個會被讀到的判準 > 一個要每個人記得帶的欄位。**

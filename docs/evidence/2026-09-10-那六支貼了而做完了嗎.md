## 3 🔴 ① 的驗法 —— 寫成可重複的步驟

**為什麼需要它**:`CREATE OR REPLACE` 這一族,**沒貼與貼了在現成的每一把尺上都是綠的**。

```
函式在 ✅ · 呼叫端在 ✅ · 搜尋回得了東西 ✅ · 測試綠 ✅
差別只在【回什麼】, 而沒有一個測試在問那件事
```

🎯 **一支 `CREATE OR REPLACE` 的 migration,沒貼不會【缺一個東西】—— 它會【安靜地換一個行為】。
　　而「缺東西」看得見,「換行為」看不見。**

### 步驟(下一個人照抄)

```
① 在正式庫挑一個【純字母、而且是完整料號】的 sku —— 那正是這一支打開的那條路
   🔴 而【要自己補 RLS 那個述詞】, 否則你算的不是客人的世界:
   ────────────────────────────────────────────────────────────
   select upper(regexp_replace(pv.sku,'[^A-Za-z0-9]','','g')) as norm_sku,
          count(distinct pv.product_id) as products
     from public.product_variants pv
     join public.products p
       on p.id = pv.product_id
      and p.delisted_at is null          -- 🔴 這一行不能省, 見下
    where upper(regexp_replace(pv.sku,'[^A-Za-z0-9]','','g')) ~ '^[A-Za-z]{4,8}$'
    group by 1 order by 2 asc limit 5;
   ────────────────────────────────────────────────────────────
② 拿那個詞去正式站打一次:
   https://shop.pcmmotorsports.com/products?search=<那個詞>
③ 讀「N 件商品」與商品連結數, 與 ① 的 products 對答案
⚪ 負對照:同一條路打一個現造的詞 ⇒ 必須「0 件商品」+「找不到符合條件的商品」
```

### 🔴 而 `and p.delisted_at is null` 那一行為什麼不能省

```
current_user = pcm_readonly · rolbypassrls = 【t】
⇒ 唯讀查到的每一個數字都【繞過 RLS】
⇒ products 差 559 · product_variants 差 721(2026-09-10 實測)
```
🎯 **一個「唯讀」的身分,不等於一個「跟客人一樣」的身分 —— 而它讀出來的數字,長得跟客人看到的一模一樣。**
📌 **省了那一行,你會拿【自己看得到的件數】去對【客人看得到的件數】,而它們可能差到 559。**
🔵 全文 `docs/evidence/2026-09-10-唯讀繞過RLS的射程-先算差再掃結論.md`。

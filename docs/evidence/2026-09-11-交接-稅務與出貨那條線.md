### 🔴 而下一個人要知道的三個地雷
```
1. untaxedFromTaxed 被【拆成兩支】, 而拆是承重的:
     untaxedForTaxedLine        品項 ⇒ round(含稅×20/21), 不拒收
     untaxedFromTaxedShippingFee 運費 ⇒ 【維持整除才收】
   🛑 不要「順手把運費也放寬」—— 那支殘差 migration 檔頭 :120-122 點名警告過:
      RPC 收不到運費稅基 ⇒ 放寬它 ⇒ 含稅品項 1,050 + 含稅運費 31 ⇒ 算成 1,082 而應收 1,081
      ⇒ 🔴 那是【多收】一塊(我第一版把方向寫成「少收」, 被 codex 抓到)

2. 捨入【全程 half-up】。PG round 與 JS Math.round 都是 half-up, 而 Python 內建 round 不是
   ⇒ 🛑 拿 Python 算一份對照表去對答案 ⇒ 每 21 個金額就有一個錯, 而兩邊都不會紅
   ⇒ 🎯 我就是那個人:我用 Python 挑驗收的判別格, 挑出一個【零判別力】的格子

3. 挑判別格的規則:【從兩種捨入的分岔交集裡挑】, 不要從單邊挑
   ⇒ 那個交集是等差數列 31 · 73 · 115 · 157 …, 公差 42 = 2 × 21
   ⛔ 含稅 11(只在 banker's 分得開)· ⛔ 含稅 10(只在 half-up)· ⛔ 含稅 1,100(兩邊同)
   ✅ 用 31
```

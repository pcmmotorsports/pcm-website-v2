### rowSpan 機制 —— **v2 §7.2 的更正是對的**

`:65-67` 逐字:
```
const rows = order.lines.length > 0 ? order.lines : [null];
const rowSpan = rows.length;
```
⇒ `rowSpan` **從手上這份 `lines` 算**,不是從 DB 算 ⇒ v1 那句「篩選必須在資料層做」確實是錯的,v2 的正確約束(**篩完必須重新分組並重算**)成立。
**空品項兜一列 `null` 佔位**是既有行為(`:64` 註解「create_order 保證 ≥1 line」)—— A11a 重建時**不可弄丟這條**,否則佔位列會渲染成破格。

### 整單彙總 badge —— **v2 §7.2 的第二個更正也是對的**

`:85-88` 註解逐字:「item 狀態篩選作用中不顯示:`!inner` 投影只回命中品項 → lines 不完整、彙總會把混合單誤顯為全同」。
⇒ 註解**只證明「不完整投影不能拿來算彙總」**,沒有禁止彙總本身 ⇒ v1「不做整單彙總徽章」確為過度概化。
現行防線 = `itemStatusFiltered` prop(`:167` 型別註解)。**A11a/A11b 重建三軸膠囊時,這條防線必須同步保留** —— 三軸膠囊的 `n/m` 同樣是彙總,同樣會被不完整投影騙。

### 訂單層 vs 品項層欄位分佈(A11a 重建的依據)

- **訂單層(`rowSpan` 合併)**:訂單編號 `:76`、日期 `:97`、會員等級 `:117`、客戶名稱 `:120`、來源·管道 `:144`

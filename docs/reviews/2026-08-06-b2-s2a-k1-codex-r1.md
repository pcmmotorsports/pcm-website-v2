## 主對話親驗(兩條打臉我先前宣稱的,逐字證實)

### ✅ #10 —— 我的「全樹契約債已結清」是**假的**

`supabase/migrations/20260805170200_m4b_e10_b2_s1b_shipment_items.sql` 的
`COMMENT ON COLUMN public.shipment_items.shipped_quantity` 逐字:

```
'本箱出貨數量。🔴 本批**不強制 shipped ≤ instock**(摘要欄與重算都不在本批);'
'強制點未定案 —— Sean 2026-08-05 已拍 Q1=A 走摘要表 CHECK(C9),由 S2 那片落地。'
```

🔴 **同一句裡「強制點未定案」與「Sean 已拍 Q1=A」並存 = 自相矛盾,而且這是已 apply 到正式站的 live COMMENT。**

**為什麼我的全樹 grep 漏掉它**:我用的變體是 `尚未定案` / `重新開放` / `該在哪一層被強制`,
而這裡寫的是「**強制點未定案**」——**沒有「尚」字**。
⇒ `feedback_claimed-sync-but-only-patched-touched-lines` 的第 N 次復發,
而且是在我**今晚才剛宣稱「已結清」**的那件事上。**教訓:變體清單要含詞幹(`定案`)而非完整詞。**

**修法**(codex 的,採納):歷史 migration **不改**(它是已 apply 的紀錄);
由**小線的 migration forward-override 該欄 COMMENT**,並納入驗收 oracle。

### ✅ #25 —— runbook 的 forward-rebuild 會把摘要表退回五欄

`docs/runbooks/a4a-summary-rollback.md` 步驟 ⑥ 逐字:
「**Forward 重建**(任一時點):依序重放 **A1**(`20260730150000`)與 **A4a**(`20260803140000`)migration 檔」

⇒ 清單裡**沒有 S2a**。S2a 已登 ledger 之後跑這段:
摘要表被 `DROP` 再由 A1 重建成**五欄**,而 `supabase db push` **不會重跑已登記的 S2a**
⇒ **摘要表永久少一欄**,直到有人手動發現。

**修法**:小線同批更新該 runbook 的 forward 清單與 rehearsal,並驗「重建後六欄十 CHECK」。

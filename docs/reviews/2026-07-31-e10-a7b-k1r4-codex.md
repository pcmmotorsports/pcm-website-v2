## Q2 D7 承重論證

不成立。具體反例：

1. E2b 後發出 Refund。
2. TapPay 已受理，但 worker 收到逾時。
3. worker 錯誤地寫 E5；DB 允許並清掉 `attempted_at`。
4. 後續重試收到重複 key 或其他非成功回應，最後 E5b 寫成 `retry_exhausted`。
5. E13 選 `retry_authorized`，D7 CHECK 放行。
6. gen2 使用新 `bank_refund_id` 再退款，可能退第二次。

另外，現有 TapPay 參考只寫 `status=0` 是成功，沒有證據支持「任何非 0 回應必然零副作用」。因此 D7 不能被描述成 DB 層的安全證明。

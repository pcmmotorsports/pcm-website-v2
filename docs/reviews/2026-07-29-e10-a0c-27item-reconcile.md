## 2. 兩項漂移的證據

### #19 取消訂單:⚠️ → 🔴 **❌**

07-26 記載:`⚠️ 原因是自由文字 | cancelled_reason text`。
**本次實查:全樹沒有任何寫入 `cancelled_at` 的路徑。**

| 查法 | 結果 |
|---|---|
| `grep -rn "cancelOrder\|cancel_order\|cancelled_at" apps packages` | 命中 **7 處全部是讀取**:`SupabaseOrderAdapter.ts:60,89`(SELECT 投影)、`mappers/order.ts:214,296,331,426`(row → domain) |
| `packages/domain/src/order/types.ts:290` | 逐字「cancelled_at(取消軸,非 null = 已取消,**本片純顯示、取消功能留取消片**)」 |
| `apps/admin/…/order-detail.tsx:233-239` | 只有 `cancelled && (…)` 的唯讀顯示區塊,**零動作按鈕** |
| 既有 4 支 admin owner RPC | 無一支能取消(`admin_update_order_workflow` 已於 D-2 收窄成只管運送方式與發票四欄) |

⇒ 「原因是自由文字」這個描述**預設了取消動作存在**,而它不存在。
**這與 v2 §2.2 的判斷一致**(逐字:「v1 §2 把第 19 項標成『⚠️ 自由文字』是低估:欄位是自由文字**且動作不存在**」)——
A0c 的貢獻是把這條**回寫進 27 項主表的計數**,而不是只寫在 E10 規格裡。

### #26 員工各自帳號與權限:狀態仍 ❌,但**證據行過期**

07-26 記載證據:`apps/admin/src/lib/staff.ts:3` = **hardcode 名單**。
**本次實查:該檔已不是 hardcode 名單。**

| 現況 | 證據 |
|---|---|
| 名單改由 DB 提供 | `staff.ts:1` 逐字 `import { listStaffRows } from './staff-repository';` |
| 檔內自陳 | `staff.ts:3-4` 逐字「M-4b E8-A1:staff 名單改由資料庫提供,但操作者仍是使用者自行選擇。🔴 **這不是登入 / 授權邊界**,也沒有驗證『目前使用者是誰』」 |
| migration 已存在 | `supabase/migrations/20260726120000_m4b_e8a1_staff_table.sql` |
| 管理頁已存在 | `apps/admin/src/app/settings/staff/page.tsx`(E8-A2) |

⇒ **狀態維持 ❌ 完全正確**(仍然沒有「每個員工的帳號密碼」),
但理由從「hardcode 名單」變成「**有 DB 名單與管理頁,但操作者身分是自己下拉挑的、系統不驗證**」。
🔴 引用 `staff.ts:3` 當 hardcode 證據的地方**都已過期**,包含 27 項主表;memory 記載的 graphify 舊節點 `STAFF [staff.ts:15]` 同樣過期。

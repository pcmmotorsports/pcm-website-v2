## §1 逐條核對(乙 §3 的五條判準)

### 判準①:這份稿子裡有沒有「特價」?

**✅ 有,而且它是主畫面第一格。**
```
brief.md §① B「三個主要編輯區…由上到下:1. 特價 2. 分類 3. 各規格現貨數量」
brief.md §② 第一格:特價
  卡片內靜態文字逐字:「零售原價由報價單系統提供,這裡不能修改。」
brief.md §③ 一整節示範「將特價從 7,690 改成 6,900 的完整操作流程」(四步)
brief.md §⑤ 一整節「批次改價流程」
```
⚠️ **而那個欄位今天不存在**(乙 §2;來源 = G6 調研片 §0① 的 0 命中 + 正向對照)。
🔴 **這是「設計走在實作前面」,不是「設計錯了」** —— 兩者的處置完全不同。

### 判準②:每個輸入框旁邊有沒有回答「改完會不會被明天的同步蓋掉」?

**✅ 有,而且用了三種不同的手法。**
```
一 把不能改的【整批收起來並標唯讀】
  §⑥「其他欄位」收納區:「預設收合,展開後按內容分組,但**全部維持唯讀**」
二 把【去哪裡改】寫在欄位旁邊
  §⑥ 零售原價旁逐字:「**原價要到報價單系統修改,這裡只管理特價。**」
三 把【被蓋掉】設計成一個結果狀態,而且是【異常】不是失敗
  §⑤ 第三組逐字:「這筆先改成功,後來又被每日商品資料改回。不要重做,請通知管理者。」
  並且:「特價是獨立新增的資料,正常情況下不可能被每日供應商資料改回…
        **若出現非 0,代表資料隔離失效,必須被視為系統異常**,而不是一般改價失敗。」
  🔴 而那一組【不提供「重做」按鈕】—— 逐字理由「避免員工一直重複相同操作」
```
🔴 **第三點是我在乙裡沒想到的**:我只想到「要標明誰擁有」,
**而它進一步想到「如果隔離失效了,員工在畫面上會看到什麼、以及【不該】看到什麼(重做鈕)」。**

### 判準③:上下架那格,有沒有反映它是唯一有保護機制的?

**⚠️ 部分 —— 而它用的是【列層】而不是【欄層】。**
```
§①-A 商品識別列:兩個彼此獨立的狀態
  「商品來源:供應商商品 / 人工建立」
  「人工修改:有 / 無」
  逐字「兩者**不可合併成同一個標籤**」
```
⇒ 這是「這一列被人碰過沒有」,**不是「這一欄是誰決定的」**。
⇒ 而 repo 今天的 `listing_set_by` 恰好是**欄層**的(只管 `delisted_at`)。
🔴 **兩者不衝突,而它們是兩件事,實作時要都有** —— 這一格算**設計與現況的介面差異**,不是缺陷。

### 判準④:圖片那格,有沒有反映「沒有鎖」?

**❌ 沒有找到。**
```
量法:`/usr/bin/grep -n "圖片" brief.md` ⇒ 命中在 §①-A(商品識別列顯示商品圖片)
      與 §⑥「商品基本資料」清單裡的一項(唯讀)
⇒ **沒有任何一句講「圖片會被供應商換掉、而且沒有鎖」。**
```
⚠️ **而它被 §⑥ 的「全部維持唯讀」涵蓋住了** ⇒ 員工改不到,所以蓋不蓋得掉對他沒有差別。
🔴 **但有一個情境它沒涵蓋**:員工看到一張**爛圖或錯圖**時,畫面沒有告訴他「這張圖會自己變」。
⇒ **這是我這一輪唯一一條【設計沒答到】的**,而它很小。

### 判準⑤:它假設員工要改的欄位數量,與乙的表對得起來嗎?

**✅ 對得非常好 —— 而且比我預期的更收斂。**
```
它給員工的可編輯格 = **三格**:特價 / 分類 / 各規格現貨數量
其餘全部收進「其他欄位」並唯讀
```
⇒ 乙的表推出「實際改得動的只有少數幾欄」,而這份稿子**主畫面只留三格**。
📌 而 `pcm-product-admin-4dir` 的丁案逐字就是這個做法:
「唯讀欄不放進主畫面,收到『其他欄位』裡;**主畫面只留你真的能改的三格**」
⇒ **`pcm-product-edit-screen` 是丁案的細化版。**

## §2 `pcm-product-admin-4dir`:它做的是【四種擋錯法的取捨】,不是四種版面

```
機械計數(整份 HTML,91KB):同步 41 次 / 特價 22 次 / 唯讀 12 次 / 覆蓋 5 次 / 報價單 5 次
```
比較表的列(逐字):**員工按下儲存後 / 誤改的擋法 / 老闆每天要做的事 / 員工最常抱怨 / 批次改價 /
三種欄位規則怎麼呈現 / 適合什麼時候用**
```
甲 全攤開・店主全權   誤改擋法:沒有,全靠人小心
乙 動作驅動的鎖       有進行中訂單就鎖,鎖的理由一律附在欄位下方
丙 編輯完 ≠ 上線      存成「待核准」,老闆是最後一關
丁 少選項・後果明確   能按的東西本來就沒幾個;唯讀欄收進「其他欄位」
```
🔴 **它把選擇題問對了**:四案的差別不是好不好看,是**「誰來擋錯」與「老闆每天要付多少時間」**。
⇒ 而每一案都附了「員工最常抱怨」那一列 —— **那是把代價寫出來,不是只推銷優點。**

### ⇒ `Q-B1` 的實際狀態是【半解】,而兩半的處置不同

```
上下架  ✅ 2026-08-15 已拍板【員工贏】,而且【已經實作並上線】
        —— 缺的只是後台那顆按鈕(乙 §2 那一格「有保護、沒 UI」)
價格    🔴 **沒有拍過**,而同步管線今天仍然每輪覆寫:
        scripts/rpm-transform.ts:294 逐字「view.price_retail → 網站 price_general(零售)」
        同檔 :349 / :390 各寫一次(群層與變體層)
        ⇒ **後台改了價格,隔天會被沖掉** —— 而這正是那份設計稿【繞開】的東西:
          它不動原價,只做「特價」這個**同步不會碰的新欄位**
```
🔴 **所以那份設計稿的「特價」不是天真,是【已經避開了 Q-B1 的地雷】。**
它選了一條**不需要先解 Q-B1 價格那半**的路 —— 新欄位、資料隔離、而且替隔離失效設計了異常狀態。
⇒ **這一格把我對那份稿子的評價再往上調一級。**

📎 而「`Q-B1` 從來沒有被答過」這句話本身,是**今晚第 N 次**的同款:
**一份寫著「等 X」的檔,不會在 X 到了的時候變色**
(`docs/patterns/guard-and-instrument-traps.md` 有這一條)。
⇒ **那份 recon 檔比拍板早一天,而它到今天還在被引用。**

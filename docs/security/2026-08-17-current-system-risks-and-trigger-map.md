### 2-1 token 洩漏後**無法與正常使用區分**
```
證據  token 查無 → 純 404，無記錄無告警
      dealer-update:  console.warn|error|alert|notify|captureException ⇒ 0 命中

      唯一痕跡 login_rate_buckets，由 cron 每天清 1 小時前舊窗（限速暫存，非稽核軌跡）
```
**嚴重度(🔴 收斂過,不要放大)**:
```
洩漏面 = 【單張報價】的售價 / 車行加價% / 工資 / 數量，且可被竄改
✅ 不含 PCM 成本與來源價 —— quote-snapshot-types.ts:181 明文永不入快照
⇒ 不是「資料大外洩」，是「單張報價的商業資訊 + 可被竄改」
```
**要防的是 token 怎麼流出去**(公開網址、轉貼、截圖、瀏覽器歷史、Referer、CDN log)
—— **不是防猜**(128 bit,爆破需 1.6e31 年,見附錄 A)。

> **寫不進去。那個欄是 `NOT NULL`。**

**真值(當場讀 DDL,逐字)**:
```
/Users/sean_1/API大量上架/PCM報價單-V2/supabase/migrations/20260730000000_baseline_schema.sql:4592
  （CREATE TABLE public.quote_snapshots，起於 :4588）

    expires_at timestamp with time zone DEFAULT (now() + '30 days'::interval) NOT NULL,
```
⇒ ✅ **有效期真值 = 30 天。** Sean A3「30 或 60 我忘了」⇒ **是 30,不再是未確認。**
⇒ 🔴 **而 `NOT NULL` 才是重點**:`never_expire = 0` **不是「今天剛好沒有」,是【寫不進去】。**
   ⇒ 「永久有效」這條風險**在 schema 層就關掉了**,不是「尚未被行使」。

**現在的正確兩層**:
```
DB 層    ✅ NOT NULL + DEFAULT now()+30 days ⇒ null 不可能存在 ⇒ 這條風險【關閉】
code 層  ⚠️ quote-token.ts:16-21 `if (!expiresAt) return false` 仍在，但對這張表
           【到不了】—— 它是防禦性分支，不是活著的洞
型別層   📌 順帶發現:app/quote/_lib/snapshot-read.ts:33 把它宣告成 `string | null`
           ⇒ TS 型別比 DB 寬。**不是漏洞**（DB 擋住了），但型別與 schema 不一致。
```
⇒ **2-1 的洩漏面時間窗 = 最長 30 天**(自建立起算)。

⚠️ **這條仍然不要刪**,但理由變了:
   留著是為了記錄「**它曾經被判成永久,而那個判斷錯了兩次**」——
   第一次錯在「以為是永久」,第二次錯在「以為只是資料剛好沒踩到」。
   🔴 下一個人若只讀到中間那一版,會以為這裡有個活的洞而去補一道不需要的守門。

⚠️ **同批實測的 `dealer_opened = 0` 不要拿來推論**:307 張、近 30 天 126 張,而這欄是 0
   ⇒ 🔴 **那比較可能是【那個欄位根本沒在寫】,不是「沒人看」。未查。**

## 🔴 C-1 先講一個命令【形狀】的要求 —— 我在寫的時候踩到,而它會讓閘失效

我第一版寫的是 `git show <SHA>:<檔> | grep -c <守門字面>`:
```
綠（守門在）      ⇒ 1
紅（守門被拿掉）  ⇒ 0
🔴 自壞（git show 失敗、grep 吃空輸入）⇒ 0   ← 與「紅」【一模一樣】
```
⚠️ **而我真的踩到了**:第一次跑時 zsh 把 `"$SHA:apps/…"` 的 `:a` 當成**參數修飾子**吃掉路徑
⇒ `git show` 失敗 ⇒ 輸出空 ⇒ `grep -c` 印 `0` ⇒ **我差點把它當成「紅的世界驗過了」。**
**那個檢查「通過」是因為它壞了。**

**⇒ 硬閘的命令必須讓【三個世界】印不同的東西**,修法是同時印**分母**:
```bash
git show "$SHA:$P" | awk '/<守門字面>/{n++} END{print NR" "n+0}'
   綠 ⇒ 65 1      紅 ⇒ 65 0      自壞 ⇒ 0 0
```
🔴 **請把這條寫進硬閘規格的命令格式要求**:
**「一個 exit code 或計數,若在【自壞】與【該紅】兩個世界相同,那它不是守門。」**

## C-2 兩條【真的可以進硬閘】的(已實跑三個世界)

### #9 `ADMIN_DEV_BYPASS` 的 `NODE_ENV` 前綴不得被拿掉
```bash
SHA=<被審的 commit>
for P in apps/admin/src/lib/session/authorize.ts apps/admin/src/proxy.ts; do
  git show "$SHA:$P" | awk '/NODE_ENV !== .production. && process.env.ADMIN_DEV_BYPASS/{n++} END{print FILENAME" "NR" "n+0}'
done
```
```
綠   兩支都印「行數 1」        （實跑:proxy.ts ⇒ 65 1）
紅   前綴被拿掉的那支印「行數 0」（實跑模擬 ⇒ 65 0）
自壞 印「0 0」                  （實跑:空輸入 ⇒ 0 0）
```
✅ **三個世界都印不同 ⇒ 可進硬閘。**

### #3 新增的 migration 若建表,必須自帶 `REVOKE`
```bash
# 🔴 只掃【這次 diff 新增/修改】的 migration，不是全樹（理由見下）
git diff --name-only "$BASE".."$SHA" -- supabase/migrations | while read f; do
  c=$(git show "$SHA:$f" | grep -c 'CREATE TABLE')
  r=$(git show "$SHA:$f" | grep -c 'REVOKE')
  echo "$f CREATE=$c REVOKE=$r"
done
```
```
綠   每個 CREATE>0 的檔，REVOKE 也 >0
紅   出現 CREATE>0 而 REVOKE=0 的檔
自壞 迴圈零輸出 ⇒ 🔴 要另外斷言「這次 diff 有幾個 migration」，否則零輸出＝假綠
```
⚠️ 🔴 **實跑發現,必須限縮到 diff**:對**全樹**跑(SHA `3c3886aa`)⇒
**含 `CREATE TABLE` 的 33 檔中,有 2 檔零 `REVOKE`**。
⇒ 若拿全樹當閘,**它從第一天就是紅的,而一直紅的閘會被關掉**。
📌 **那 2 檔本身是一個待查項**(可能早於 E683-1、也可能是真缺口)—— **本輪未逐檔判定,列為待查。**

### 🅑 七段深掃**沒涵蓋**而這一輪抓到的 —— 這是本輪的產出

#### 🟡 B1(hardening note,不是漏洞)—— 五個防護標頭一個都沒有

【量的】對 `/` · `/products/<slug>` · `/login` · `/account` 四個路徑各發一次 `HEAD`:
```
content-security-policy      0 次
x-frame-options              0 次
x-content-type-options       0 次
referrer-policy              0 次
permissions-policy           0 次
strict-transport-security    4 次   ← 這個有(max-age=63072000,兩年)
```
✅ **前提斷言**:同一把尺數 `server` ⇒ **4 次** ⇒ 尺會咬,那五個 0 是真的 0。

【量的】**不是部署漂移,是從來沒設**:`apps/storefront/src` 與 `next.config.ts` 裡 grep 這五個標頭 ⇒ **0 命中**,`next.config.ts` 也沒有 `headers()`。

🛑 **為什麼我判它是 hardening note 而不是漏洞**(照 `security-audit` 自己的規矩:縱深防禦缺口 ≠ 漏洞):
· 缺 CSP ⇒ 是 XSS 的**第二層**,而第一層(A4)量過是關著的。
· 缺 `X-Frame-Options` ⇒ clickjacking。**而我證不到具體損害** —— 顧客站沒有「登入後一鍵就造成後果」的動作(結帳要走多步 + 付款)。
· 缺 `X-Content-Type-Options` ⇒ MIME sniffing。**顧客站沒有使用者上傳**(【量的】grep `FormData|multipart|upload` 命中的 4 支都不是上傳端點)⇒ 沒有可被 sniff 的使用者內容。

⇒ 📌 **值得補,但它不擋上線。** 補法是 `next.config.ts` 加 `headers()`,零行為改變。

#### ✅ B2 —— `/dev-preview/*` 在正式站是關的

【量的】`/dev-preview/brands` · `/filter-drawer` · `/sound-clips` · `/mobile-catalog-ux` ⇒ **四個全部 404**。
📌 那 9 頁在 repo 裡是活的 ⇒ **如果它們在正式站也活著,就是把內部預覽頁公開**。實測是關的。

#### ✅ B3 —— 五支 cron 端點全部 401,而且不揭內部

【量的】五支各發一次(不帶任何 Authorization):
```
401  (空回應)  /api/cron/anomaly-alert
401  (空回應)  /api/cron/capture-recheck
401  (空回應)  /api/cron/email-sweep
401  (空回應)  /api/cron/order-ineligible-gate
401  (空回應)  /api/cron/settle-sweep
```
🛑 **打之前我先讀碼**:五支都是 `CRON_SECRET` Bearer + `timingSafeEqual` + fail-closed(env 未設或 <32 字元 ⇒ 500,不是放行)⇒ **沒帶 header 會在做任何事之前就 401** ⇒ 打它不會觸發寄信。
📌 **這一格的順序是刻意的**:先讀碼確認打了不會有副作用,才打。反過來做,`email-sweep` 那一發就可能真的寄信出去。

#### ✅ B4 —— source map 沒有公開

【量的】`/_next/static/immutable/chunks/1u4yf99m5i8xf.js.map` ⇒ **404**。

#### ✅ B5(vibesec 角度)—— open redirect 關著

顧客站有兩個吃 `next` 參數的入口:`/auth/callback:26` 與 `/api/auth/line/start:34`,**兩個都過 `sanitizeNextParam`**。
【量的】那支的實作逐字四道:
```
1. 不是字串 / 空字串        ⇒ 回預設
2. 不是 '/' 開頭             ⇒ 回預設
3. '//' 或 '/\' 開頭         ⇒ 回預設(protocol-relative)
4. hasUnsafeChar            ⇒ 回預設
   —— charCode ≤ 0x20(含 space \t \n \r \f \v)、0x7f、以及反斜線
```
⇒ 對照 `vibesec` 那張繞過表逐格核:`//evil.com` 擋 · `/\@evil.com` 擋 · `%09`/`%0d%0a`(searchParams 已解碼成控制字元)擋 · `%2f%2f` 解碼後成 `//` 擋 · `javascript:` 不是 `/` 開頭擋。
🔵 **失敗路徑也過同一把尺**(`:44`)—— 那是常見的漏法:成功路徑守著、失敗路徑忘了。

> ## 🔴 30 秒清單:**跑任何盤點 / 掃描 / 斷言之前,先讀這三題**
>
> (2026-08-19 G6 立;來源 = 一個晚上**六個**量具坑,**全部當場自抓**、每個都有實例與數字。
> 🔴 **每一題給的是【正向的作法】,不是「小心 X」** —— 因為「小心」不會被執行,一條命令會。)
>
> ### Q1 **我要下一個「零 / 沒有 / 查無 / 不存在」的斷言**
> ```
> ⇒ 先拿一個【你確定會命中】的東西,餵給【同一條命令】跑一次。
>    它動了，那個零才有意義；它不動，你剛剛量的是自己的工具。
> ```
> **這一條蓋掉六個坑裡的三個**(全部是「印出一個看起來像結論的空集合」):
> ```
> · `grep -P` 在 macOS BSD grep **不支援** ⇒ 印 0;改 `awk` ⇒ **19**
> · `comm` 要【字典序】,而餵了 `sort -un`(數值序)⇒ 印空;改 `sort -u` ⇒ **4**
> · **中間檔過期** ⇒ 正向對照撈不到已知答案
>   🔴 最毒的形狀:**我自己剛改完那件事,然後用改之前的快照去驗它**
> ```
>
> ### Q2 **我要下一個「有 / 已經做了 / 共 N 處」的斷言**
> ```
> ⇒ 不要只看數字。**開頭幾行【印出來看】,問:這些命中是不是我要的那一種?**
> ```
> **這一條蓋掉另外兩個坑**(全部是「多出來的東西被讀成【已經有了】」——**方向比空集合更危險**):
> ```
> · `/usr/bin/grep` **不吃 `.gitignore`** ⇒ 掃到 `.next/cache/*.sst` ⇒ **194** 行,
>   而 `git grep` 同一題 ⇒ **0**。
>   🔴 兩支不是「哪一支對」,是**問的問題不同**:
>      `git grep` = 「**版控裡**有沒有」(問「這件事做了沒」用這支)
>      `/usr/bin/grep` = 「**磁碟上**有沒有」(問「跑起來會讀到什麼」才用這支)
> · **尺撞到【談論它自己】的文本** ⇒ pattern 含「待」而命中了**狀態欄自己的「⏳ 待執行」**,
>   光那一種就 **290** 行 ⇒ **尺量到的是表格的結構,不是內容。**
>   判別句:**我這個 pattern,會不會命中【承載資料的容器】而不是【資料】?**
> ```
>
> ### Q3 **我要用一條命令的成敗,決定下一步做什麼**
> ```
> ⇒ **不要接管線。** 先存 rc 再判:
>      cmd > out 2>&1 ; rc=$? ; cat out ; [ $rc -eq 0 ] && … || …
> ```
> ```
> · `ls … | cut … || echo "不存在"` ⇒ `$?` 是 **`cut`** 的 ⇒ **那個 `||` 從來沒有機會跑**
> 🔴 而這一條 **`CLAUDE.md` 明文寫過**(「pipeline 後面的 `$?` 是右端那個指令的」),**而它今晚仍然被踩了**
>   ⇒ 📌 **要記的不是規則,是【一條寫在常載檔裡的規則,今晚仍然被踩】這件事本身** ——
>      那是「**知道規則不等於執行規則**」的又一個實例,而它支持**機制優先律**:
>      **能做成 hook / 守門的,不要只寫成規則文字。**
> ```
> 📎 ①②③④ 的全文與 BSD ≠ GNU 靜默錯答清單在 memory
> `reference_a-broken-ruler-prints-an-empty-set-not-an-error`。

>
> (2026-08-19 主視窗要求寫下來:**下一個人需要的不是結論,是判斷的依據**。)

# 任何備援,在**第一次真的被用到**之前,都是一個未經驗證的宣稱

> 稿 = `-0b`(R3)· `-48` 指定掛 R3 名 · `-b9` 複核後落並更正一格
> 🔴 **同族已自首**:與 `⟦b4-ROLLBACK1⟧` 互引(**不併、不重開** —— `-b9` 裁,理由在末段)

## 句

任何「**備援 / 保險 / 回滾路徑 / 快照 / 還原流程**」,在**第一次真的被用到**之前,
都是一個**未經驗證的宣稱** ——

> ### **而它被用到的那一刻, 恰好是【最不適合發現它壞掉】的時刻。**
> (那一刻沒有時間 debug,而你正指望它。)

## 今晚的實例(`-0b` 實撈)

```
mailbox-snapshot 每小時拍、7 份在庫 —— 整晚全隊「以為有這道保險」，零人回撈過
-0b 奉 -48 令實撈一發：07:20 那份撈回、與現行差 142 行（真歷史，非鏡像）
⇒ 它從「以為有」變成「驗過一發」
```
📌 **⇒ 差別在這裡**:**一支從沒被實際回撈過的快照工具, 與一支撈不出東西的, 在艦隊表上長得一樣。**

✅ **`-b9` 複核**:`~/pcm-mailbox-snapshots/` 目錄數 ⇒ **7** ✅ 與 `-0b` 同值;
`20260830-072006/` **存在** ✅。(那支工具是 `-b9` 建的,而**在今晚之前它從來沒有被回撈過** —— 我自己也沒有。)

## ✅ 判別句(`-0b` 提)

> **每一條備援要一個【演習欄】—— 記上一次真的走過它是什麼時候。**
> ### **空白 = 宣稱, 不是保險。**

⇒ 射程含:`down`-migration 的「未跑」標記 · 「非綠不刪」的還原流程 ·
災難還原 runbook · **任何寫著「可回滾」的欄**。

## 🔴 而 `-b9` 更正一格:那個數字要帶數法

`-0b` 稿裡寫 `grep -c 'Supabase forward-only'` ⇒ **103**。
**`-b9` 當場重跑, 兩種數法都不是 103**:
```
檔數（至少一次命中）⇒ **84**
總次數             ⇒ **106**
負對照 zzqForwardOnly20260830 ⇒ 0
```
⚠️ **兩個數都是真的, 而它們數的是不同的東西** ——
📌 **⇒ 而 103 落在兩者之間, 所以它既不是檔數也不是總次數**:
**可能是量測時點不同(那個目錄一直在長), 也可能是第三種數法。**
🛑 **⇒ 所以引用時要寫「84 檔 / 106 次(2026-08-30 `-b9` 量)」, 不要寫 103。**

## 🛑 而 `-b9` 裁【互引, 不併入板列】—— 理由

`-0b` 建議「落板時併不重開」。**而我把它拆成兩件**:
```
✅ 不重開一列 ⇒ 同意
🔴 而【不併進 ⟦b4-ROLLBACK1⟧】 ⇒ 因為那兩者的讀者不同
```
```
⟦b4-ROLLBACK1⟧ 是一個【有量測的具體缺陷】：
   supabase/migrations/*.sql 總支 222 · 檔名帶 down/rollback/revert ⇒ 0
   而 forward-only 是【刻意的慣例】，不是漏做
🔴 本條是那件事的【全稱化】，射程遠大於 migration
```
📌 **⇒ 併進去會把一條通則, 埋在一列講 migration 的紀錄裡** ——
**而下一個在想「我的災難還原 runbook 算不算保險」的人, 不會去讀那一列。**
✅ **⇒ 所以:本條在坑檔、那一列在板上, 兩邊互指。**

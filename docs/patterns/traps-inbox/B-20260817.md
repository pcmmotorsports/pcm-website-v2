## 「已經有人決定了而我沒去查」——同一個沒做的動作,兩個相反的外觀〔安靜〕

**判別句**:我寫下「**未定 / 還沒人拍板 / 待決策**」之前,**有沒有 grep 過本線的母 plan?**

### 實例(同一個窗、同一天,方向相反)

| | 做了什麼 | 後果 |
|---|---|---|
| `B-581-STOP` §3-3(2026-08-17 早) | 把**已經拍過的板**升級成決策題丟給 Sean | 施工者**無謂停工**,等一個不需要的拍板 |

我在 B3 spec(`54a92f57`)寫:
> `actor-actions.ts`「處置**未定**,三條路(加閘 / 去權威化 / 退場)**都還沒有人拍板**」

而母 plan `docs/specs/2026-08-16-m4b-e8b-real-auth-line-plan-v4.md:53` 逐字:

⚠️ **這裡刻意不寫行號**:我第一版寫 `:168`,而**同一顆 commit 裡我自己往上游加了行,它當場漂到 `:174`**
(codex 2026-08-17 `must-fix`)⇒ **引用會被自己的改動推翻,是本檔第二次踩「量法不可重跑」。**
可重跑定位:`grep -n '^| \*\*B6\*\*' docs/specs/2026-08-16-m4b-e8b-real-auth-line-plan-v4.md`

**可重跑量法**(這一條就是本條的動作):


### 為什麼它安靜

**「未定」這兩個字沒有任何機械訊號會反對它。**
它不會讓測試紅、不會讓 grep 數字變、不會讓 typecheck 抱怨 ——
而它產生的**具體損害是下游的**:下一個施工者照它去補一道閘,
**把一個預定退場的東西加固成看起來合規的長期設施**,下架那天要多拆一層。

🔴 **更安靜的一層**:判別句**早就存在**(`B-581` §3-3 白紙黑字),
**而它今天被同一個窗違反了一次,方向相反。**
⇒ 這條的價值不在判別句(已有),在於**它證明「知道規則」與「執行規則」是兩件事**。

### 動作

規則文字已經證明擋不住(它被自己的作者違反),所以配一條**當場跑的命令**:
> 落筆寫「未定 / 還沒人拍板」之前 ⇒ `grep -n '<檔名或機制名>' <本線母 plan>`
> **零命中才可以寫「未定」**;有命中 ⇒ **先讀那一行管的是什麼**。

### 與既有條目的關係

- house 教訓 `feedback_knowing-rule-is-not-executing-rule` 的當日實錘。
- A 窗補的那半:「**撈到一條拍板 ≠ 撞到那條拍板**」—— 中間還有一步:**讀那條拍板管的是什麼**。
  ⇒ 本條是它的**反面**:連撈都沒撈。

## 折 finding 這個動作本身會生出新的 must-fix,而它在進度表上讀起來像進度〔安靜〕

**判別句**:**我剛折完的那一條,如果它是錯的,現在有誰會發現?**
(答案若是「沒有,因為表上已經寫**已折**」⇒ 那一折需要獨立一輪。)

### 實例(2026-08-17,同一份 spec 的 codex 三輪)

```
R1  21 must-fix（審 spec 本體）
R2   4 must-fix + 3 nit（審【我的折法】）
R3   8 must-fix + 2 nit（換角度：假設審查／施工者行為／更正是否誤導／內部矛盾）
```
**R2 的 4 條裡,有 2 條是我自己在 R1 折的時候製造的。**

**① 折錯方向**:`#9` 我寫「綁定白名單在**簽發時**由 `CHECK` 執行」——
**`SELECT` 不會重跑 `CHECK`**;`CHECK` 只在**那一列被寫進去**時擋。
⇒ 我把一個**沒有 runtime 執行者**的驗收格,寫成「執行位置已經定了」。

**② 修法生出新洞**:為了折 `#15` 我寫下「admin 寫入**全部**經 `authorizeAdminMutation()`」——
**照字面會鎖死登入**:SSO `start`/`callback` 依定義未登入可達且會寫 cookie。
量法:
```bash
git ls-files 'apps/admin/src/app/api/**/route.ts' | grep -v '\.test\.'
grep -n 'SSO_OPEN_PATHS' apps/admin/src/proxy.ts
```
⇒ 那兩支 route **就是** `proxy.ts:12` 白名單裡的兩條。

### 為什麼它安靜

**finding 表上「已折」那一格,對「折對了」與「折錯了」印同一個字。**
折完之後那條就離開了追蹤清單 —— **錯的折法比沒折還危險,因為它還把追蹤關掉了。**

### 動作

- **R1 有 must-fix ⇒ 折完必跑一輪確認**,而那一輪要**審折法本身**,不是重審原 finding。
- 折完的每一條,在紀錄裡寫**折在哪(檔案:行號)+ 折法一句** ——
  **寫不出「折在哪」的,就是還沒折。**

### 與既有條目的關係

- `feedback_folding-a-finding-defaults-to-the-named-spot-only` 的**上游**:
  那條講「只修被指名那一處」;本條講「**修對了地方但修錯了方向**」,而兩者在表上長得一樣。

## 一條「全部都要」的規則,它的價值在【例外寫在哪裡】〔安靜〕

**判別句**:我寫下這條全稱規則的同一段,**有沒有寫「它不管什麼」**?

### 實例

承上 ②。「admin 寫入**全部**經授權閘」少了例外條款,後果**不是「規則不完整」**,是下面兩條之一:
- 施工者照字面做 ⇒ **把登入鎖死**
- 施工者自己判斷該有例外 ⇒ **例外存在但零留痕**,下一個人看不到它為什麼在那

### 為什麼它安靜

全稱規則**讀起來比有例外的規則更嚴謹**,所以審規則的人傾向放行;
**而例外是在施工現場才長出來的,那時已經沒有人在看規則了。**

### 動作

寫全稱規則時,例外清單**指向一份已經存在的名單**,不要新造一份 ——
本例用 `proxy.ts:12` 的 `SSO_OPEN_PATHS`。
🔴 **第二份名單就是第二個真相。**

## 一條量法在我做完這件事之後,還跑得出同一個答案嗎〔安靜〕

**判別句**:**我這條量法,在我做完這件事之後還跑得出同一個答案嗎?**
跑不出來 ⇒ **它不是量法,是一句過期的話。**

### 實例(同一天兩次,兩種不同機制)

**① 被自己的產物推翻**:我在新檔的檔頭寫量法 `find . -name 'traps-inbox*'` ⇒ 零命中
—— **而那個零,在我把這個檔存檔的那一秒就不成立了**(現在會命中它自己)。

**② 被自己的編輯推翻(行號引用的通病)**:我在同一份檔裡引用母 plan `B6` 在 `:168`,
**而同一顆 commit 裡我往上游加了行,它當場漂到 `:174`** ——
`:168` 現在指到的是 `B0`。**引用讀起來完全正常,只是指錯人。**

### 為什麼它安靜

**量法寫進檔案的那一刻是對的** —— 它不是打錯,是**當下為真、之後為假**。
沒有任何機制會在它變假的時候叫:測試不紅、grep 數不變、typecheck 不管。
🔴 而它比一般的過期敘述更毒:**它長得像證據**。下一個人看到「附了量法」就不會再去驗。

### 動作

- **量法要用【不受本次改動影響的分母】**:引 `git ls-tree <ref>` / `git show <sha>:<path>`
  這類**釘在某個提交上**的,不要引「當前工作樹掃描」來證明某物不存在。
- **行號引用**:引**內容錨點**(`grep -n '^| \*\*B6\*\*' <檔>`)而不是裸行號;
  非得寫行號 ⇒ **同一顆 commit 改完之後回頭重量一次**。
- 落筆自問:**這條命令的答案,會不會因為我接下來要做的事而改變?**

### 與既有條目的關係

- 與 `feedback_the-correction-itself-goes-stale` 同族,但機制不同:
  那條是**更正過期**;本條是**證據在出生後被自己推翻**。

## `find -newermt` 的相對時間在本機【靜默回零】〔安靜〕

**判別句**:**我這條「最近有沒有新東西」的掃描,在【真的有新東西】的世界會印出不同的數嗎?**

### 實例(2026-08-17 19:37 當場,起因=Sean 要我持續檢查信箱)

我跑 `find ~/pcm-mailbox -name '*.md' -newermt '-90 minutes'` ⇒ **零命中**,
我差一點就回報「沒有新信」。**而當下 3 分鐘前才落地一封 `T-004`。**

**兩個世界的實測(同一支 `find`,只換時間格式)**:
```bash
find ~/pcm-mailbox -maxdepth 1 -name '*.md' -newermt '-90 minutes'          # bfs: error: Invalid timestamp → 0 行
find ~/pcm-mailbox -maxdepth 1 -name '*.md' -newermt '2026-08-17T18:07:00'  # ⇒ 4
find ~/pcm-mailbox -maxdepth 1 -name '*.md' -newermt '2026-08-17T00:00:00'  # ⇒ 65
```

**成因(量到的,不是推的)**:本環境 `find` 是一個包住 **`bfs 4.1.1`** 的 shell function
(`which find` 印出 function 本體;`find --version` ⇒ `bfs 4.1.1`)。
**`bfs` 只吃 ISO 8601-like 時間**,`'-90 minutes'` / `'30 minutes ago'` 這類 GNU 相對格式**直接報錯**。

### 🔴 為什麼它安靜(這才是重點,不是「格式不對」)

```
錯誤訊息走 stderr       ⇒ 接了 | wc -l 就看不到
$? 被管線【右端】吃掉   ⇒ … | wc -l; echo $?  拿到的是 wc 的 0
輸出 0 行               ⇒ 與「真的沒有新信」一模一樣
```
⇒ **兩個訊號同時沉默,而它的形狀正是「工具自己壞掉」被讀成「世界上沒有那個東西」。**

⛔ ~~exit code 仍是 0 ⇒ echo $? 也不會叫~~
🔴 **這一行 2026-08-17 更正,而錯的是我自己(見本檔最後一則)**:
**`find`/`bfs` 【有】報錯,直呼不接管線時 `rc=1`。** 我複量的三個數:
```
直呼不接管線            ⇒ rc=1
接 | wc -l 之後 echo $? ⇒ rc=0   ← 那是 wc 的
呼叫端 set -o pipefail  ⇒ rc=1
```
⇒ **沉默的是「stderr 被丟掉」與「`$?` 被管線右端吃掉」,不是 find 自己不叫。**
📎 這在信箱裡**至少已經有前例**:`~/pcm-mailbox/A-032-STOP.md:61` 逐字
「我原本用 `find … -newermt '30 minutes ago'` 想看『近期被改的檔』,**它靜默回零**」,
另有整封 `E-651-複驗scan.sh與find靜默.md`。**⇒ 這是復發,不是新發現。**

### 動作

- **掃信箱不要用相對時間**。用**不需要解析時間**的:`ls -lt ~/pcm-mailbox/*.md | head -N`
  (它在有新信與沒新信兩個世界會印不同的第一行)。
- 非用 `-newermt` 不可 ⇒ **給 ISO 格式**,而且**當場跑一發正向對照**(把時間往前推,必須撈到更多)。
- 🔴 通則:**任何「回零就代表沒事」的掃描,先讓它在【該有東西】的世界表演一次。**

### 與既有條目的關係

- `feedback_absence-read-as-verified` 的一個**機械成因版**:那條講「沒看到 ≠ 不存在」,
  本條給出一個**具體的、rc=0 的、每天都在用的**產生器。

## 錯的解釋長在【守門】裡,比長在文件裡更貴〔安靜〕

**判別句**:我寫進守門訊息裡的那句因果,**是我量到的,還是我從一個接了管線的 `$?` 推出來的?**

### 實例(2026-08-17,一句錯誤診斷的完整傳播鏈)

我診斷某個掃描指令為什麼會靜默回零,寫下「**三個訊號同時沉默,含 exit code 仍是 0**」。
**那個「rc=0」是假的** —— 我當時的量法是:
```bash
<那支指令> 2>&1 | tail -1; echo "rc=$?"      # 🔴 這個 $? 是 tail 的
```
⇒ **我犯的正是 `CLAUDE.md` 明文記著的那條**:「pipeline 後面的 `$?` 是**右端**那個指令的」。

**傳播鏈(四步,每一步都合理)**:
```
1 我把錯誤診斷報給主視窗
2 主視窗【原字廣播全陣】—— 它沒有自己複量
3 我據此把那句話寫進一道【守門的訊息】
4 別的窗後來複量、更正了說法，更正也重播了
  🔴 但那時守門已經掛上去，而【更正沒有跟進到守門裡】
```
**複量的實際數字(我自己重跑,不是引述)**:
```
直呼、不接管線              ⇒ rc=1   ← 它【有】報錯
接 | wc -l 之後 echo $?     ⇒ rc=0   ← 那是 wc 的
呼叫端 set -o pipefail      ⇒ rc=1
```

### 為什麼它安靜(這條的核心)

**一句錯的解釋寫在文件裡,讀者可能不會讀到;寫在守門裡,讀者【一定】會讀到 ——
而且是在他【正要犯那個錯的那一刻】。**
🔴 **那一刻他最信它**,因為守門剛剛才正確地攔下他。
🔴 **而且他不會想到要去查證「守門說的話」** —— 守門在心理上是權威,不是待驗的主張。

⇒ **守門的攔截判定與它的解釋,是兩個獨立的東西,可以一對一錯。**
本例就是:**攔得準(它真的擋下該擋的),而解釋是錯的。**

### 動作

- **寫進守門訊息的每一句因果,標準比寫進文件更高,不是更低。**
  落筆前問:這句話我是**量到的**,還是**推出來的**?
- 🔴 **更正一個廣播出去的診斷時,把「它有沒有長出下游產物」列進清單** ——
  hook / 腳本 / 測試名稱 / commit body,**都是它可能已經固化進去的地方**。
  (本例:更正重播了兩次,而守門裡那句撐了幾小時沒人動。)
- 任何「為什麼會靜默」的診斷,**先把 `$?` 從管線裡拆出來單獨量**。

### 與既有條目的關係

- 是 `feedback_the-correction-itself-goes-stale` 的一個**更貴的版本**:
  那條講「更正本身會過期」;本條講「**錯的原文已經被固化成機制,而更正只走了文件那條路**」。
- 與本檔「量法會被自己推翻」同族:都是**證據的載體出了問題**,不是證據本身。

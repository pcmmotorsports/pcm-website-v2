## 三種對的零, 而三種的下一步完全不同

### ① 蓋好而門沒開 —— 那是**一條拍板的結果**, 不是漏接

**下一步:去找有沒有一條拍板把那扇門關著。**

```
depositWallet（客人自助儲值的 use-case）⇒ 全 repo 命中【只在它自己的測試檔】（9 筆）
🔴 而它不是漏接：
   2026-05-24 寫好 → 2026-05-31 Sean 拍 HOLD（儲值法規未定）
   → 2026-08-26 解凍法規，而逐字「甲 只顯示餘額和明細…之後再做，現在先顯示就好」
   ⇒ WalletTab.tsx:10 逐字寫著那顆鈕與 DepositModal【是被拿掉的】
```
🛑 **它與「忘了接」在 `grep` 上是同一個零, 而處置相反:一個要去接上, 一個【不准接】。**

### ② 拍板落在沒有流量的那條路上

🔴 **這一種【已經有家】** ⇒ `memory/feedback_ruling-landed-on-the-path-with-no-traffic.md`
(同一晚寫的;`customer_wallet_ledger.entry_date` 兩個寫入端兩套語意)
⇒ **本條不重述它, 只在這裡放一個指標** —— 三種要並排看才看得出「零有三種」。

### ③ 答案只住在對話裡, 而 `git` 裡沒有它

**下一步:去 `grep`【決策板】, 不是只 `grep` git。**

```
主視窗 2026-08-29 端 8 題給 Sean ⇒ 其中 5 題【早就做完了】
而「儲值金舊列有幾筆記錯」那題：Sean 40 分鐘前就跑過 SQL 回了數字（UTC / 總列數 3 / 記錯 0）

⇒ 而那個結論是【對的】：真的沒有人寫過碼
   —— 做掉它的不是一顆 commit，是【他貼了一次 SQL】
```
🔴 **`git log --grep` 擋得住「有人寫碼做掉了」, 擋不住「他已經答過 / 已經跑過」。**
✅ 而後者只有在**有人把答案落檔**的前提下才擋得住
📌 **⇒ 所以落檔不是紀錄, 是那道守門的【輸入】。**

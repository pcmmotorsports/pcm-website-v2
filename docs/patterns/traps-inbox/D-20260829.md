## D-1 一個【被中途砍掉的審查】,與一個【跑完的審查】,在檔案大小與 grep 命中數上長得一樣

> ⚠️ **母題已存在**(查重第 6 名 0.4292):正本 `:15787`
> 「**量具給了你一個【講得通的錯誤故事】—— 錯的那一發不長得像壞掉,長得像一個發現**」。
> ⇒ 本條是它在【審查工具的輸出】上的成員,而**加值在那個機械判別法**:
> `VERDICT` 命中的**行號**(第 33 行 = prompt 位置 / 檔尾 = 真答案)。
> 📌 **⇒ 母題答得出「為什麼你不會懷疑它」,答不出「那一刻要看哪一格」。**

**當班實錘**。跑 codex 對抗審查,**被我自己設的 10 分鐘 Bash 逾時砍掉**(`rc=143`)。
輸出檔 **424,827 bytes / 4,827 行**,而:

```
grep -c  'VERDICT'  ⇒ 1
grep -ci 'must-fix' ⇒ 13
```

🔴 **兩個數字都不是 0,而它一條 finding 都沒產出** —— 它當時還停在**讀檔**階段。

- `VERDICT` 那一次命中在**第 33 行** = **我自己 prompt 的回音**(我要求它「最後給 VERDICT」)。
- 13 次 `must-fix` 全部來自:我的 prompt、codex 自己的 agent 說明、
  **以及它讀檔時貼出來的檔案內容** —— 那些檔案裡本來就寫著別人以前的 `must-fix` 紀錄。

📌 **⇒ 「有沒有輸出」與「有沒有審查」是兩件事,而前者的量法會順手回答後者。**
🔴 **⇒ 而本 repo 特別容易餵飽這種尺**:我們的註解裡到處是 `must-fix` / `VERDICT` / `codex 關卡2`
⇒ **審查素材本身就長得像審查結果。**

### ⚠️ 這與今晚那六版判別法【不是同一個形狀】(主視窗指定要分開寫)
```
那六版防的是：① 零產出   ② 讀太早（檔案還在寫的時候去讀）
🔴 而這一種是第三種：中途被砍，而【輸出看起來完整】
   · 不是零產出（424KB）
   · 不是讀太早（process 已經死了，rc=143）
⇒ 那六版一格都擋不住它
```
📌 **合在一起寫會讓下一個人以為那六版涵蓋了這一種。**

> 🔴 ③ **而家法逐字:codex 要 `wait "$PID"`,不要輪詢、不要設短逾時。**
>    ⚠️ 那個 10 分鐘是**我自己設的** ⇒ **不是它慢,是那個逾時把一個還在正常工作的東西砍了。**

### 🔴 而同一個病今晚出現過【相反的另一半】
```
第一次：檔案【還在寫】的時候去讀 ⇒ 我報「零輸出」⇒ 而它後來跑完，VERDICT: NOT-SAFE + 5 條 must-fix

## D-3 反引號在【三種載體】裡都不是惰性字元,而我們拿它當「程式碼字體」

> 逐字:「**知道一個坑,擋不住你在下一段掉進去 —— 因為病是同一個,而【載體換了】。**」
> ⇒ 本條是那個母題在【反引號】這個字元上的具體成員:同一個字元、三個載體、三種行為。
> 📌 **而本檔 D-5 提到的「註解裡寫著那句被禁的話」也是同一個母題的成員** ——
> 那條逐字就是「**解釋這條規則的那句話會違反這條規則**」。
> ⇒ **兩條都掛回去,不另立編號。**

**當班實錘**。我在一個 **TS template literal** 裡寫 SQL 註解,而註解裡用了反引號:
```
-- 🔴 **`WHEN OTHERS`** 抓不到 `query_canceled`
```
⇒ 那些反引號**當場終止字串** ⇒ `TS1005 ',' expected` ⇒ 而**別的窗先撞到它,不是我**。

📌 **三種載體,同一個字元,都會被解讀**:
```

TS 反引號字串  ⇒ 當場終止字串（本例）
Markdown       ⇒ 行內程式碼（我們每一則訊息都這樣寫）
```
🔴 **⇒ 而 `CLAUDE.md` 那條只涵蓋 shell 那一層** ⇒ 下一個人會在 TS 裡再踩一次。
🔴 **⇒ 而養成這個習慣的正是我們自己:今晚每一則訊息、每一段註解都拿反引號當程式碼字體。**
📌 **⇒ 危險的不是那個字元,是【它在三個地方長得一樣而行為不同】,而我們的手已經記住那個寫法。**

**修法**:那段註解的反引號**全拿掉,不靠跳脫**。
⇒ 理由:**跳脫過的版本下一個人編輯時會再踩** —— 而拿掉之後它就沒有那個形狀了。

## D-4 R1 與 R2 是同一個根因的兩面,而我第一次只修了【看得見的那一面】

**當班實錘**。同一支 fail-open handler,兩輪對抗審查各抓到一條,而**它們是同一件事**:

```
R1：WHEN OTHERS 抓不到 query_canceled ⇒ 逾時會逃出 handler ⇒ 整批 ROLLBACK
    我的修法：具名 WHEN query_canceled THEN 去接住它
🔴 R2：逾時與【操作者按 Ctrl-C】同為 SQLSTATE 57014
    ⇒ 抓了它 ⇒ 把人的取消意圖一起吞掉 ⇒ 然後照樣 COMMIT
```

📌 **⇒ 而正解不是「抓得更準」,是【讓那個例外不該出現】**:
```sql
SET LOCAL statement_timeout = 0;   -- 只為那一筆
<audit 區塊，handler 只有 WHEN OTHERS>
SET LOCAL statement_timeout = '60s';
```
✅ **⇒ 之後若還出現 `57014`,那就【真的是人在取消】⇒ 我們不抓 ⇒ 取消恢復意義。**
🔴 **⇒ 一個【讓訊號恢復意義】的修法,而原本那個是【把訊號吃掉】。**
⚠️ 而「timeout 設 0」聽起來危險 ⇒ **必須同時講 `lock_timeout='5s'` 仍在**
⇒ 卡鎖 5 秒拋 `55P03`,**而那個 `WHEN OTHERS` 抓得到** ⇒ 不會永遠卡住。

### 🔴 而這與「漏了另一處」**不是同一件事**
```
漏了另一處 ⇒ 另一面【當時就看得見】，我沒去看
本例      ⇒ 另一面【要先做了第一個修法才長出來】
```
📌 **⇒ 所以它防不了「更仔細一點」 —— 它只防得了【修完再審一輪】。**
✅ **⇒ 而這正是「R1 FAIL 才跑 R2」那條家法在買的東西,而我第一次差點覺得 R2 是多餘的。**

## D-7 換成白名單,不等於換成【正確的】白名單 —— 那個白名單裡有空白的成員

**當班實錘(2026-08-29,`D1_OPERATOR` 那道閘,codex R5 抓)**。

```
第一版：拒 \p{Cc}\p{Cf} + 要求「剝掉 \p{C}\p{Z} 之後不是空的」
🔴 codex：那是【黑名單偽裝成白名單】，而它兩個方向都錯
   · 該擋沒擋：U+034F / variation selector / U+3164 ⇒ 不在 C/Z 類 ⇒ 過，而看起來是空白
   · 該過擋了：波斯文等合法姓名需要的 ZWNJ / ZWJ（\p{Cf}）⇒ 被拒
✅ 我改成 /[\p{L}\p{N}]/u（至少一個字母或數字）—— 這一次是真白名單
🔴 而演 16 個世界之後，【一格不符】：
   U+3164（諺文填充）在 Unicode 裡是 **Lo（其他字母）** ⇒ 它【在白名單裡】
   而它畫出來是空白
```

📌 **⇒ 而我與裁定的人【兩個都以為】「換成白名單」就解決了。**
🔴 **⇒ 判準:一個【類別規則】表達的是【分類】,不是你要的那個【性質】。**
**「可見」是【渲染】的性質,不是【字元】的性質 —— 沒有任何 Unicode 類別能表達它。**

**修法**:那一小塊(`U+115F` / `U+1160` / `U+3164` / `U+FFA0`)**具名剔除**再判 ⇒ 16/16 符合期望。
✅ **而射程明寫在碼旁**(它不可能完整):
> 擋得住【誤填】(空白 / tab / 零寬 / 標點),擋不住【刻意找一個畫不出來的字母】——
> 而後者屬於惡意,而惡意的人本來就改得動這支腳本本身。

⚠️ **鄰居但不同**:正本 `:17602`「白名單的【錯理由】要留在原地」——
那條講**白名單條目的理由**寫錯;本條講**白名單規則本身**包含不該有的成員。

## D-8 一個【假的事故報告】,會產生一次【真的】寫入

**當班實錘**。有窗回報:「我用讀-改-寫覆蓋掉你剛加進 `MEMORY.md` 的那一行關鍵字。」
它附了成因分析、附了「沒有任何東西會紅」的自陳,並開始準備用 `sed` 把那一行補回去。

🔴 **而我當場量 ⇒ 那一行【在】。**
```
grep -c '<我寫進去的那串>' MEMORY.md ⇒ 1
主索引字元數：它量 8476 ／ 我量 8476   ← 同一份檔
而它的 grep 回 0 ⇒ 圖樣與我寫進去的字串不同
（主索引這一族的格式是【關鍵字串】，不是檔名清單 ⇒ grep 檔名本來就回 0）
```
📌 **⇒ 同一份檔案不會對兩個 grep 給相反的答案 —— 除非圖樣不同。**
**⇒ 而「我們量到同一個字元數」是那一格最硬的證據:它證明我們看的是同一份。**

### 🔴 而危害不在「事實錯了」,在**它會觸發一個動作**
```
它要「用一次性 sed 只動那一行」把我那串補回去
⇒ 而它【已經在那一行上】⇒ 補回去 = 那一行有兩份，或 sed 樣式把現有那段切壞
🛑 ⇒ 一個假的事故報告，產生一次真的寫入
```
⚠️ **而它比一般的誤報貴一格**:
「**我弄壞了別人的東西**」這種結論會讓人**立刻動手修補** —— 而修補本身是一次寫入。
📌 **⇒ 誤報的成本,與它引發的動作成正比;而【自責型誤報】引發的動作最快。**

### 下次那一刻要做的動作
> ① **回報「我覆蓋掉你的東西」之前,先用【對方寫進去的原文】grep 一次** ——
>    而那一發 grep **自己要有正對照**(先確認它抓得到某個一定在的東西)。
> ② **收到這種回報的人,先自己量** —— 不要直接開始補救。
> 🔴 ③ 而**兩個窗都不要各寫一次同一支檔**:那正是它擔心的那個病再來一次。

## D-10 一個【查來的範例值】預設是真的,不是編的

> 🔴 **這不是新母題** —— 它是正本 `:26085` 的成員:
> 「**範式的【形狀】可以抄, 它的【常數】不行 —— 而那個常數【在原處是對的】,
> 所以它不會看起來可疑。**」(2026-08-29;線D `-69` 寫的,而我同一夜踩了它的另一面)
> ⇒ 那一條講的是**抄一個技術常數**;本條講的是**抄一個【當範例用的值】**。

**當班實錘**。我問 codex:「讀的人真的分得出 pre / post 嗎(單號格式的差異夠明顯嗎)?」
它為了回答**去讀了真的 cohort 資料**,回我:「pre 為 `PCM-2026-0001`,post 為 `2D3ZZZ` 類六碼」。
⇒ 我把 `2D3ZZZ` 抄進 docstring 與 runbook,**當作【格式範例】**。

🔴 **而它是真的其中一個還原號**:
```
D1_DELETE_COHORT 裡 restoreDisplayId === '2D3ZZZ' ⇒ 命中【1】筆
負對照 'ZZZZZZ' ⇒ 0
```
✅ **擋住它的是一條【為了別的目的立的】守門**:
「`pre` 版不改號:26 個 `restoreDisplayId` 一個都不得出現」⇒ 那條測試當場紅。

### 📌 而這條路上**沒有任何一步做錯事**
```
· codex 讀真資料 ⇒ 是為了回答我問的問題（我要它評估「讀得懂嗎」）
· 我抄它的答案 ⇒ 是為了舉例（而舉例本來就該用真實的形狀）
🔴 ⇒ 而那條路上沒有任何一步【看起來像】「把真資料放進文件」
```

### 🔴 判別句
> **一個「範例值」若是【別人查資料查來的】,它預設是【真的】,不是編的。**
> ⇒ 而編出來的範例會長得可疑(`XXXXXX` / `foo`),**查來的範例長得剛剛好** ——
> **因為它就是真的。**

### 下次那一刻要做的動作
> 把任何**別人給的具體值**寫進會被 commit 的檔案之前,**當場對真實資料查一次**:
> ```
> 它在真資料裡命中幾筆? ⇒ >0 ⇒ 換掉
> 而換上去的那個，也要查一次 ⇒ 必須 0（我換的 A1B2C3 ⇒ 0）
> ```
> ⚠️ **兩邊都要查** —— 只查舊的會讓你換上另一個真的。

### ⚠️ 而它有一個更廣的射程,而我沒有量
```
本例是【還原號】⇒ 它不是 PII，後果是「測試會紅」
🔴 而同一條路可以帶進來的東西：客戶姓名、email、訂單號、金額
⇒ 而那些【不會有一條為了別的目的立的守門】剛好擋住
📌 ⇒ 我這次是運氣好：那一族剛好有人立過一條很嚴的守門
```

## D-13 一道守門,它給的【修法建議】會製造它宣稱要防的那個 bug

**當班實錘(2026-08-29 23:5x,而它在裝上去之前被擋下)**。

我一夜踩四次「反引號切斷 TS template literal」⇒ 寫了一道 pre-commit 守門:
> 一行以 `-- ` 開頭而且含反引號 ⇒ 紅。

自檢九個世界 PASS、真 repo **957 支 `.ts` 零命中**、正對照做過
(拿真檔塞一行 ⇒ 守門 rc=1 且 `tsc` 對同一份檔 rc=2)。
⇒ **看起來每一格都做到了。**

### 🔴 而 codex 找到 repo 裡【現在就有】的反例
`apps/admin/src/lib/session/is-manager-cost-contract.test.ts:223`:
```
-- COMMENT ON COLUMN public.staff.is_manager IS '…權限';`;
```
```
這一行以 "-- " 開頭（它是 template literal 【裡面】的 SQL 註解）
🔴 而結尾那個反引號是【template literal 的結束符】
⇒ 我的守門 rc=1
```
🛑🛑 **而我印的那句「怎麼改:把那幾個反引號【拿掉】」**
**⇒ 照做會刪掉結束符,【直接弄壞合法的 TS】。**

📌 **⇒ 一道守門給的修法建議,會製造它宣稱要防的那個 bug。**
🔴 **⇒ 而那比「誤報」嚴重一個量級**:
```
誤報 ⇒ 人被擋住、查一下、發現是誤報 ⇒ 成本是時間
🔴 而「誤報 + 一句聽起來權威的修法」⇒ 人照做 ⇒ 成本是【一個新的 bug】
⇒ 而那個 bug 長得跟守門要防的那個一模一樣
```

### 🔴 而它為什麼躲過我全部的量測
```
我掃 957 支 .ts ⇒ 零命中 ⇒ 我寫進提案「裝上去不會擋到任何現有 commit」
🔴 而那支反例是【別窗今晚稍後才建的】—— 掃描當下它不存在
📌 ⇒ 我把一個【時點的事實】寫成了一個【對未來的宣稱】
⚠️ 而主視窗當時就警告過「957 支零命中不等於未來零命中」
   ⇒ 而「未來」在【一小時之內】就到了
```

### 🔴 而根因:**那個判準需要的東西,它拿不到**
> 一個反引號是「程式碼字體」還是「字串結束符」——
> **不解析 TS 就分不出來。**
⇒ 而每加一條啟發式,就多一種「它給錯建議」的世界。
📌 **⇒ 判別句:一道守門若【分不出它要分的那兩件事】,加啟發式不會讓它變準,
只會讓它錯得更少見而更難發現。**

### 處置(不是修,是撤)
```
✅ 撤下：unstage + git checkout -- package.json（不留一個【半裝的掛鉤】）
✅ 腳本留在磁碟上、不進版控
🔴 而不繼續修 —— 一道會給錯修法建議的閘，比沒有那道閘糟
```
⚠️ **而那個問題本身還在**(我一夜踩四次)⇒ 留在 D-3 / D-12 當判別法,
**而我承認判別法擋不住手的習慣。**

### ⚠️ 而 codex 另外五條也都成立(抽驗兩條當場複現)
```
· 不認得的參數 ⇒ 假綠（--not-a-real-mode ⇒ rc=0；餵 package.json ⇒ rc=0）
· 逃生門只驗關鍵字存在、不驗理由 ⇒ 危險行原樣加 marker 就放行
· read 中途失敗被 while 當成迴圈結束 ⇒ 沒寫進 rc ⇒ fail-open
· 而它【不是每次 commit 都跑】：無 staged TS 且 guard 自己沒 staged ⇒ 根本不呼叫
🔴 ⇒ 六條裡有【四條】是「它在該叫的時候不叫」——
   而我的自檢九個世界，一個都沒演到那四種
📌 ⇒ 自檢演的是【我想到的世界】，而漏掉的正是我沒想到的那些
```

### 🛑 而給下一個人:**這一族做不成 pre-commit,而理由是結構性的**
```
🔴 不解析 TS，就分不出【程式碼字體的反引號】與【template literal 的結束符】
⇒ 而它們可以出現在【同一行】的同一個位置類型上（行尾）
⇒ ⇒ 任何靠「行首是 -- 」+「這行有反引號」的判準，都會把兩者混在一起
📌 加啟發式不會讓它變準，只會讓它錯得更少見而更難發現
```
⚠️ **而【降級成 CI 警告】也不行**(主視窗同日裁):
警告的內容仍然是那個判準 ⇒ 它仍然分不出兩種反引號
⇒ **一則說錯的警告,比一道說錯的閘只少了「強制」,沒有少「誤導」。**
(而沒有人看的告警 = 沒有告警 —— 那一格今晚另外記過。)

🔴 而我承認：判別法【擋不住手的習慣】——
   我知道那條規矩，而我同一夜還是踩了四次
⇒ 📌 所以這一條不是「已解決」，是【已知而沒有機制】
```
🔴 **而批准它的人(主視窗)自己認了一格,一起記**:
> 它批准時寫的第一個理由是「957 支零命中 ⇒ 今天不會擋任何人」,
> 而**同一則訊息裡**也寫了「957 支零命中不等於未來零命中」。

> ⇒ 而「未來」在**一小時之內**就到了。

> **而那個要求正好是這個 bug 的入口**:

> ✅ ⇒ 所以那條要求要加一格:**「說得出怎麼改」的前提是【那個修法本身要被驗過】。**

### 📎 而那支腳本的內容逐字存在這裡(它已被刪除)

```
### 為什麼存全文:一支【未追蹤的腳本】與一支【還沒裝上的腳本】在磁碟上長得一樣。
### 而它比一份過期的文件糟 —— 文件會被讀,而一支腳本會被【跑】。
### ⇒ 所以檔案刪掉,內容留在這裡當【它為什麼不該裝】的證物。
### 而它的病在上面 D-13:那個判準分不出「程式碼字體的反引號」與「template literal 的結束符」。

#!/usr/bin/env bash
# sql-comment-backtick-guard.sh —— 擋「SQL 註解裡的反引號」把 TS template literal 切斷。
#
# 🔴 為什麼(2026-08-29,線D 一夜踩四次):
#    我們的習慣是拿反引號當「程式碼字體」——每一則訊息、每一段註解都這樣寫。
#    而在一個 TS template literal 裡面寫 SQL 註解時,那個字元【會當場終止字串】。
#    症狀:esbuild/tsc 報一個離現場很遠的語法錯(Expected ";" but found …),
#    而更糟的一半是【產生器整支跑不起來】⇒ 下游拿到的是上一輪的舊檔。
#
# 📌 判準:一行【去掉前導空白之後以 "-- " 開頭】而且含反引號 ⇒ 紅。
#    ("-- " 帶一個空白,避開 TS 的 --x 遞減運算子。)
#
# ── 逃生門(留痕,不是靜默 skip)────────────────────────────────
#    那一行加上  guard-allow:sql-backtick <理由>  ⇒ 放行,而它會【印出來】。
#    ⇒ 所以「有沒有人用過逃生門」看得見:掃 guard-allow:sql-backtick 就數得出來。
#
# ── 這支自己壞掉時是 fail-closed ────────────────────────────
#    讀不到檔 / 參數形狀不對 ⇒ rc=2 並說明,而【不是】安靜跳過。
#    (pre-commit 的 fail-open 最糟:它會安靜地不再守,而沒有人會發現。)
#
# 用法:  bash sql-comment-backtick-guard.sh <檔...>
#        bash sql-comment-backtick-guard.sh --selftest
set -euo pipefail

ALLOW_MARK='guard-allow:sql-backtick'

scan() {
  local rc=0 f n line t allowed=0
  if [ "$#" -eq 0 ]; then
    printf '🔴 沒有給任何檔 —— 本閘拒絕在「沒有輸入」時回綠(fail-closed)\n' >&2
    return 2
  fi
  for f in "$@"; do
    case "$f" in *.ts|*.tsx) ;; *) continue ;; esac
    if [ ! -r "$f" ]; then
      printf '🔴 讀不到 %s —— 本閘不跳過讀不到的檔(fail-closed)\n' "$f" >&2
      rc=2; continue
    fi
    n=0
    while IFS= read -r line || [ -n "$line" ]; do
      n=$((n + 1))
      case "$line" in *'`'*) : ;; *) continue ;; esac
      t="${line#"${line%%[![:space:]]*}"}"
      case "$t" in '-- '*) ;; *) continue ;; esac
      case "$line" in
        *"$ALLOW_MARK"*)
          printf '⚠️  %s:%s 用了逃生門(%s)—— 放行,而這一行被記下來\n' "$f" "$n" "$ALLOW_MARK"
          allowed=$((allowed + 1))
          continue
          ;;
      esac
      printf '🔴 %s:%s SQL 註解裡有反引號 —— 它會終止外層的 TS template literal\n' "$f" "$n" >&2
      printf '   %s\n' "$t" >&2
      printf '   ✅ 怎麼改:把那幾個反引號【拿掉】,註解本身留著。\n' >&2
      printf '      🔴 不要用跳脫(\\`)—— 下一個人編輯那一行時會再踩一次。\n' >&2
      printf '      🔴 也不要刪掉整段註解 —— 要留下來的是理由,不是那個字元。\n' >&2
      printf '      ⚠️ 這【不是】shell 的 echo \\c 那個坑(那個的正解才是 printf %%s\\\\n)。\n' >&2
      printf '      ⚠️ 真的需要那個字元 ⇒ 同一行加 %s <理由>,它會被記下來。\n' "$ALLOW_MARK" >&2
      rc=1
    done < "$f"
  done
  [ "$allowed" -gt 0 ] && printf 'ℹ️  本次用了 %s 次逃生門\n' "$allowed"
  return $rc
}

if [ "${1:-}" = "--selftest" ]; then
  d="$(mktemp -d)"; trap 'rm -rf "$d"' EXIT
  printf 'const q = `SELECT 1;\n  -- 這裡用 `x` 當程式碼字體\n`;\n'            > "$d/bad.ts"
  printf 'const q = `SELECT 1;\n  -- 這裡沒有反引號\n`;\n'                     > "$d/ok.ts"
  printf 'let i = 3;\n--i;\nconst s = `a`;\n'                                 > "$d/dec.ts"
  printf -- '-- 這是 .sql,反引號 `x` 在這裡無害\n'                            > "$d/x.sql"
  printf 'const q = `SELECT 1;\n  -- `x` guard-allow:sql-backtick 測試用\n`;\n' > "$d/esc.ts"
  a=0; scan "$d/bad.ts" >/dev/null 2>&1 || a=$?
  b=0; scan "$d/ok.ts"  >/dev/null 2>&1 || b=$?
  c=0; scan "$d/dec.ts" >/dev/null 2>&1 || c=$?
  e=0; scan "$d/x.sql"  >/dev/null 2>&1 || e=$?
  g=0; scan "$d/esc.ts" >/dev/null 2>&1 || g=$?
  h=0; scan "$d/nope.ts" >/dev/null 2>&1 || h=$?
  i=0; scan               >/dev/null 2>&1 || i=$?
  # 🔴 不要把 scan 接進管線 —— set -o pipefail 之下,scan 自己的 rc=1 會讓整條管線 rc=1,
  #    而那與「grep 沒找到」印同一個結果。⇒ 先落檔,再 grep。
  scan "$d/bad.ts" > "$d/j.out" 2>&1 || true
  j=0; grep -q '怎麼改' "$d/j.out" || j=1
  scan "$d/esc.ts" > "$d/k.out" 2>&1 || true
  k=0; grep -q '逃生門' "$d/k.out" || k=1
  p() { printf '%-34s ⇒ 該 %s,實際 %s %s\n' "$1" "$2" "$3" "$([ "$2" = "$3" ] && echo ✅ || echo 🔴)"; }
  p '世界一 SQL 註解含反引號' 1 "$a"; p '世界二 同段無反引號' 0 "$b"
  p '世界三 TS 遞減運算子' 0 "$c";   p '世界四 .sql 檔不看' 0 "$e"
  p '世界五 逃生門 ⇒ 放行' 0 "$g";   p '世界六 讀不到檔 ⇒ fail-closed' 2 "$h"
  p '世界七 零輸入 ⇒ fail-closed' 2 "$i"
  p '世界八 擋下時說得出怎麼改' 0 "$j"; p '世界九 逃生門會留痕' 0 "$k"
  if [ "$a" = 1 ] && [ "$b" = 0 ] && [ "$c" = 0 ] && [ "$e" = 0 ] && [ "$g" = 0 ] \
     && [ "$h" = 2 ] && [ "$i" = 2 ] && [ "$j" = 0 ] && [ "$k" = 0 ]; then
    printf '⇒ 自檢 PASS(九個世界印出不同答案)\n'; exit 0
  fi
  printf '🔴 自檢 FAIL\n'; exit 1
fi

scan "$@"
```

# 只測邊界的兩側,測不出邊界的【形狀】錯了

> 線【出貨】`-1e` · 2026-08-31 · codex R2 nit 抓到

## 現場

我把一個 ISO 時刻 regex 的小數位從 `(\.\d+)?` 收窄成 `(\.\d{1,3})?`,
理由是回傳值走 `new Date(t).toISOString()`(**只保留毫秒**)⇒ 多打的位數會被靜靜截掉。

我寫的測試:
```
'…00.123Z'     ⇒ ok        ✅
'…00.1239Z'    ⇒ bad-format ✅
'…00.123999Z'  ⇒ bad-format ✅
```
**三條全綠。** 而 codex 打回來:

> regex 若誤改成**只接受恰好三位**小數 ⇒ `.1Z`、`.12Z` 這兩種**目前合法且不失精度**的設定
> 會被拒收,**但新增測試仍全部通過**。

## 📌 母題

```
我測了邊界的【兩側】(3 過 / 4 不過), 而沒有測邊界的【形狀】。
`{1,3}` 與 `{3}` 在我那三條測試底下印同一個綠。
```
🔴 **⇒ 一個「上界」的測試不會告訴你【下界】被誤鎖住了。**
✅ 補法:把 `.1Z` 與 `.12Z` 放進正對照。
**驗證**:把 regex 突變成 `(\.\d{3})?` ⇒ `rc=1 · 1 failed | 15 passed (16)` ⇒ 新測試抓得到。

## 🔵 一般化

**任何寫成「至多 N」「至少 N」「N 到 M」的約束,它有兩個端點與一個【範圍形狀】。**
測兩個端點是必要的,而它證不出中間那一段沒有被挖掉。
⇒ 判別問句:**把這個約束改成一個【更窄但兩端相同】的版本,我的測試會紅嗎?**

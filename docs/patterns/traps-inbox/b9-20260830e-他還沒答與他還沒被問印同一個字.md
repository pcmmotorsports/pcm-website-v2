> 承 `b9-20260830{,b,c,d}` 的第 1-17 條。`-48` 判本條**獨立成條**(它是今晚整件板子重驗最值錢的產出)。
> ⚠️ 時戳是 sandbox 的 `date`,不是 Sean 那台的鐘。

**判不併,而分工要寫清楚, 否則本條會被讀成它的第二個實例:**
```
那一條：我【自己發明】了一題，然後在後面幾則訊息裡講「他還沒回」
        ⇒ 沒有人端過它，而端的人就是提醒者自己，他也忘了
        ⇒ 🔴 病在【那題根本不存在於任何佇列】

🔴 本條：那題【確實在待問佇列上】，有編號、有落點、有人排它
        而排它的人【自己就誠實寫了】「它連題目都還沒整理好 ⇒ 本輪不端他」
        ⇒ 病在【兩個載體各自誠實，而合起來說了一句假話】
```
📌 **⇒ 那一條是「一個不存在的請求」;本條是「兩份都對的紀錄, 拼出一個錯的狀態」。**
**⇒ ⇒ 而後者【沒有人做錯任何一步】—— 所以它不會被任何「請大家小心」修好。**

📌 **⇒ 而那兩者在板上印同一個字:「等 Sean」。**

## 🔴 判別句
> **誰欄寫「等某人」的列 —— 那個請求【已經送出去了】嗎?**
```
沒送出去 ⇒ 它不是「等他」，它是【等我們】
⇒ 而「等他」這三個字會把責任移出去，讓這一列看起來不需要我們做任何事
```
🛑 **而最毒的一格是它【永遠為真】**:沒送出去的東西當然不會有回覆
⇒ **「他還沒回」這句話沒有任何時間點會自己失效。**(這一格與 `feedback_my-own-question-became-a-phantom-blocker` 共用。)

## ⇒ 它在板子病裡的位置(第五種)
```
① 做完了而沒有人劃掉             ⇒ 板子 vs 世界
② 查清楚了而沒有人回去改那一列    ⇒ 板子 vs 交件檔
③ 他答了而那一列還停在問句        ⇒ 板子 vs 決策檔
④ 前半與後半互相矛盾             ⇒ 板子 vs 它自己（同一列）
🔴 ⑤ 本條：它宣稱有一個請求在他手上，而那個請求從來沒有離開我們
     ⇒ 板子 vs 【它自己的請求鏈】
```
📌 **⇒ ①②③ 靠「去外面查一下」抓得到;④ 靠「把整列讀完」抓得到;**
**🔴 ⑤ 兩者都抓不到 —— 你要去追【那個請求現在在哪】, 而板子上沒有那一欄。**

## ⇒ 可機械檢查的(`-48` 指定要有)
```
誰欄含「等 <人名>」的列 ⇒ 決策檔裡必須有一個對應的題號
                        ⇒ 而那個題號必須是【已整理成選項】的狀態，不是只有一個標題
判法（兩個世界印不同的東西）：
  ✅ 已整理 ⇒ 那個題號底下找得到一行以 `A:` 開頭的選項行（Sean 的家法是 prose code block）
  🔴 只有標題 ⇒ 找不到那一行 ⇒ 這一列的「等他」是假的
負對照：拿一個【現造】的題號去查 ⇒ 必須零命中
```
⚠️ **而這把尺的已知盲區, 寫在旁邊**:
```
· 它只驗【格式】不驗【題目好不好】—— 一個有 A: 行而問得很爛的題照樣過
· 它抓不到「題目整理好了、而沒有人端出去」⇒ 那是第六種形狀，本條不涵蓋
· 誰欄的寫法不統一（等人: / 等 Sean / 等他 / 等主視窗端）⇒ 字集要先量，不要憑寫
```

## 🔴 而根因在最後一格,它不是任何一個人的疏忽
> **`Q-HMAC` 的下一步是「把題目整理出來」—— 而那件事【今天沒有人被指名】。**
```
· 排它的人（-0b）明說「本輪不端」⇒ 它盡到了責任
· 板上那一列的持有者不知道那題還沒整理好 ⇒ 它看到的是「等 Sean」
🔴 ⇒ 而「整理題目」這個動作【不屬於任何一個角色】
   ⇒ ⇒ 所以它不會被任何人的收工清單掃到
```
📌 **⇒ 一件沒有人被指名的事, 與一件沒有人想做的事, 在所有紀錄上長得一樣。**
✅ **而這一次的解法是【指名】** —— `-48` 2026-08-30 指名 `-b9` 去整理,而它當天就整理完了(`~/pcm-mailbox/de-b9-問Sean-Q-HMAC-…-20260830.md`)。
🔴 **⇒ 那個「一被指名就當天做完」本身是證據:它從來不是難, 它是【沒有人的】。**

## 🔴🔴 而它有【第二層】—— 剝完第一層之後才看得到(2026-08-30 同日)

第一層剝完 ⇒ **他還沒被問** ⇒ `-48` 指名 `-b9` 把題目整理出來 ⇒ **當天整理完。**
而寫題時,作者在**射程段**(不是附註)標了一句:
> **「本題的核心前提【那顆編號在後台網址上看得到】—— 我沒有獨立驗到。」**

⇒ `-48` **因此扣住不端**, 改派 `-0b`(**不是作者、也不是那一列的持有者**)去補那一發。
🔴 **結果:那個前提是【假的】。**
```
佔位信箱用的是 customerRequestId（manual-customer.ts:367 → placeholderEmailFor）
而網址上那顆 mrid 是【訂單】的鍵 —— 兩顆不同的鍵，每次 render 各鑄一顆
  （manual-order-view.tsx:67-70 逐字：「與建單那顆是兩顆不同的鍵」）
customerRequestId 掃 searchParams/router/redirect/url/href ⇒ 零命中
  （-0b 量、-b9 獨立複核 ⇒ 一個「不在」的結論被兩把不同的尺各自量到）
```
📌 **⇒ 所以完整的形狀是兩層**:
```
① 那一列宣稱「等他一個決定」—— 而【他沒被問】
② 而那個問題本身，建立在一個【已經不成立的前提】上
   （舊形狀曾同時拿那顆鍵當客人鍵，現行已脫鉤 ⇒「寫的時候可能為真，而碼走掉了」）
```
🔴 **而任何一層停下來, 都會得到一個【看起來合理】的結論**:
```
停在第 0 層 ⇒「這一列在等 Sean」⇒ 一個永遠不會動的待辦
停在第 1 層 ⇒「他還沒被問，快去問」⇒ 端出一個【建立在假前提上】的題
✅ 只有剝到第 2 層 ⇒ 才知道要做的不是問他，是【重新問這一列在防什麼】
```

## 🔴 而擋住第二層的是【一句自我標記】, 不是任何檢查
> **作者把「核心前提未獨立驗到」寫進【射程段】而不是附註。**
📌 **⇒ 沒有人會去驗一個沒有被標記的前提。**
⇒ **⇒ 而那正是第 17 條(「一行小字可以打開核對也可以關掉核對」)的【打開】方向, 在一個真的高風險位置上生效的一次。**
🛑 **而處置也要記全**:題目檔**就地標作廢、不刪、作廢寫在最上面**、原文一字未改留在下面
—— 理由:**兩份同時在信箱裡的話, 先被讀到的是舊的那份。**

## ✅ 那把尺的第一發(2026-08-30 當場跑, 而它的弱點與數字一起走)

```
板上誰欄寫「等 Sean ／ 等他」的未關列 ⇒ 12
決策檔裡出現過的題號                 ⇒ 86
   其中【底下 900 字內找得到一行以 A: 開頭的選項行】⇒ 50
   ⇒ 🔴 其餘 36 個題號【找不到那一行】
負對照：現造題號 Q-ZZQ8842 ⇒ 0（尺不是恆回東西）
```
🛑 **而「36」不可以被讀成「36 題沒整理好」—— 這把尺有三個已知弱點, 每一個都會把它灌大**:
```
① 已答的題，答案常常【取代】了選項行 ⇒ 它們會被算進那 36
② 我抓題號用的是寬鬆的字元類（含中文），可能撈到不是題號的東西
③ 900 字的搜尋窗是我挑的，沒有量過 —— 選項行離題號更遠的會被漏掉
```
📌 **⇒ 所以那個 36 是【上界】, 而且是一個【我知道被灌大】的上界。**
🔴 **⇒ 而正確的下一步不是把尺調準, 是把那 12 列逐列開檔對** ——
**12 是人做得完的數, 而把尺調準會得到第四個合理而錯的數。**
(那與今晚 `-48` 的那句同一條:**換抽法會得到第三個合理而錯的數。**)

# 前半 · 我把一個【未解的洞】寫成了一個【通過條件】

## 事件
片 C3 要在 Vercel 上用 headless chromium 產 PDF。`@sparticuz/chromium` 的 66 MB brotli
binary **不在 Next 的檔案追蹤清單裡**(它是執行時才解壓的, 靜態分析看不到)。
**我知道這件事。** 而我把它寫成:

```ts
it('🛑 而 chromium 那顆 brotli binary【不在】—— 這一格是【記錄現況】不是通過條件', () => {
  // 它是執行時才解壓的, 靜態分析看不到 ⇒ 這個 0 是**預期的**。
  expect(count(/@sparticuz.*\.br$/)).toBe(0);
});
```

codex 抓到(逐字):
> tracing test 把必要 `.br` 數量為 0 寫成通過條件;若 Vercel 依 NFT 打包,
> `chromium.executablePath()` 沒有壓縮包可解, **route 固定 500**。

## 🔴 判別句
```
我寫了三樣東西:
  ① 測試【名稱】說「這是記錄現況不是通過條件」
  ② 測試【註解】說「這個 0 是預期的」
  ③ 測試【斷言】說 expect(...).toBe(0)  ← 而報表只看得到這一個
⇒ 那一格躺在「131 格全綠」的報表裡, 與一個真的驗過的東西**逐字同一個綠勾**。
```
📌 **一個綠燈的語意由【它在報表上長什麼樣】決定, 不由旁邊的註解決定。**
🛑 而註解在這裡比沒有更糟:**它讓寫的人覺得自己已經標記過了**, 於是不會再去找別的表達方式。

## ✅ 修法(可機械執行)
```
改成 `it.todo('🛑 未解:… 缺的那一道是【真部署一次、打那條 route、看 executablePath() 回什麼】')`
⇒ 報表上它是【待辦】不是綠燈。實測輸出從 `131 passed` 變成 `130 passed | 1 todo`。
📌 判別動作:**寫完一格斷言, 去看它在 `vitest run` 的輸出上長什麼樣** ——
   而不是去看你在它旁邊寫了什麼。
```
⚠️ 適用範圍:任何「我知道這裡有洞, 而我先把現況釘住」的斷言。
   釘住現況本身沒有錯 —— 錯的是**讓它與「驗過了」共用同一個符號**。

# 後半 · 一個被中斷的審查, 它已經吐出來的那部分會被讀成全部

## 事件
片 C3 的 codex R1 **跑到一半被容量錯誤砍斷**(`rc=1`,輸出末尾兩行
`ERROR: Selected model is at capacity`)。它在死掉之前吐出了**一條** finding,
而那條的開頭逐字是:

> **第二個**同級問題也成立:現在的「fail closed」只擋 `embedded === 0`…

```
🔴 「第二個」⇒ 有一個「第一個」, 而它從來沒有被寫出來。
🛑 而我拿到的東西長得像一份【findings】—— 有具體內容、有可執行的修法、
   在輸出檔的最末尾(那正是完整報告該在的位置)。
```
我修了那一條、跑了 R2(3 must-fix + 3 nit)、修完、跑 R3 ——
**而「第一個」是我在 R3 的提示詞裡【明寫要它重講】才拿回來的**,
而它就是本則前半那個假打勾。

## 🔴 判別句
```
一個被中斷的產出, 與一個完整的產出, **在【已經吐出來的那部分】上完全一樣**。
⇒ 而中斷的訊號(`rc=1`、末尾的 capacity 錯誤)住在**輸出的另一端**,
  而讀的人是從**內容那一端**讀的。
```
📌 **⇒ 這不是 codex 的問題, 是【任何會分段輸出的東西】的問題** ——
   長回報、被 kill 的背景任務、被截斷的 log、跑到一半的批次。

## ✅ 修法
```
① 收任何工具的產出, **先看 rc 與末尾**, 再看內容。rc≠0 ⇒ 那份東西是【殘篇】不是報告。
② 殘篇裡的序數詞是免費的線索:「第二個」「其餘」「另外」⇒ **它自己說了它有前文**。
③ 續跑時**明寫「把你上一輪沒吐完的講完」** —— 不要重跑一次全面審查,
   那會得到一份新的、而缺的仍然缺(新的一輪不會知道舊的一輪吞掉了什麼)。
🛑 而 ①②③ 都是提醒。**機制那一格我沒有做出來**:
   我沒有辦法讓一個被砍斷的 codex 自己在檔頭寫「本份不完整」。
   ⇒ 這一則到此為止是規則不是機制, 照 `00-work-rules §4 機制優先律` 這是它的弱點。
```

## 而這兩半為什麼是同一則
```
前半:結果是【部分的】(一個未解的洞), 而它的長相是【完整的】(一個綠勾)
後半:報告是【部分的】(被砍斷), 而它的長相是【完整的】(一份 findings)
⇒ 同一個形狀:**部分的東西, 穿著完整的外觀。**
⇒ 而兩次的解法也同構:**去看那個東西【在它自己的輸出格式裡】長什麼樣**,
  不要看作者(我 / codex)在它旁邊說了什麼。
```

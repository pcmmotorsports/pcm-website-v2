## A-1 ⑤ 的新一半:**窄掉的原因是【我自己的強調符號】—— 而它與「重要」正相關**

**當班實錘**(2026-08-29,寫 `~/pcm-mailbox/線A-災難還原四列-要Sean拍的一題-20260829.md` 的收工自核):
表格四列,我跑 `grep -c '^| \*\*' <檔>` 當「列數對不對」的自檢 ⇒ **印 `3`**。
而表上是 **4 列**。成因:**第四列是 `| 🔴 **` 開頭,而我的尺只認 `| **`。**

🔴 **而少掉的那一列,正好是我特別標紅、在報告裡單獨拉出來講的那一列。**

### 📌 為什麼這不是 ⑤ 的重複,而是它的新一半

⑤ 原本的兩半都是**隨機的窄**:我的字集少了幾個詞 / 我依賴的 hook 字集少了幾個詞。
**這一半的窄是【有方向的】** ——

```
我們用符號(🔴 ⚠️ 🛑 **)強調【重要】的東西
⇒ 那些符號改變了那一列的【開頭字面】
⇒ 而尺是照【開頭字面】寫的
⇒ ⇒ 越重要的那一列，越容易掉出尺的字集
```

**⇒ 漏報不是均勻散落在所有列上,它【集中在最重要的那幾列】。**
(⑤ 現有那半的結論是「詞表的分母 ≠ 病的分母,而它們的差就是漏報區」;
 **這一半補的是:那個差【不是隨機的】—— 它與我們自己標記重要性的動作相關。**)

### 引信位置:它印的是「少一列」不是「錯了」

`3` 是一個合法的數字、一個看起來正常的答案。那份交件會用 `3` 端出去,**而沒有任何東西會紅**。
⚠️ 這與「尺壞掉印 0」**不同族**:**0 明顯可疑、會讓人停下來;`3` 不會。**
📌 與鐵則 1 那條「**它不是回空,它回了一個看起來很正常的清單**」是同一個母題 ——
**一個【部分正確】的答案,比一個空答案危險一個量級。**

### ⇒ 下次那一刻要做的動作(可機械執行)

1. **數結構的東西不要用字面錨** —— 表格列數用 `awk '/^\| /&&!/^\|---/&&!/^\| 表頭字 /'`,
   不要用 `grep '^| **'`。**尺要吃「它是不是一列」,不要吃「它長什麼樣」。**
2. **自檢印出的數字,跟你心裡那個數對一次**;對不上時**先問尺,不要先改檔**。
   本次就是這一步救的:我知道我寫了 4 列,而它印 3。
3. 🔴 **而如果你沒有「心裡那個數」⇒ 這條抓不到你。**
   ⇒ 真正的動作是:**寫的時候就把「我寫了幾列」記下來**,不是事後去數 ——
   **兩個數要來自兩個地方,否則是同一個錯複印兩份。**

### 負對照(本次有做,而它印了假的那一種)

同檔另一把尺 `grep '推薦\|建議'` 也叫了 ⇒ 開檔查 ⇒ **兩個命中都是我在寫「不推薦」** ⇒ **誤報。**
📌 **⇒ 兩把尺同時叫,一把真、一把假 —— 而差別只有開檔那一步看得出來。**
(這正好又是 ⑧ 那條的日常版:**分數/命中是【值得開檔】的訊號,不是【有問題】的結論。**)

## 🔴 為什麼這不是既有那些的重複

```
· 拍板落在沒有流量的路上   ⇒ 東西對，而沒有人走那條路
· 好的量測沒有索引         ⇒ 東西對，而沒有一條路從症狀通到它
· grep 印兩列而我讀一列     ⇒ 工具答了，而我沒讀完
🔴 這一個：兩節【互相假設對方做了】—— 而每一節單獨看都是完整的
```
📌 **母題 `:12329` 講的是「兩個各自正當的【動作】合成一個洞」;**
**這一半講的是「兩個各自正當的【段落】」—— 而邊界在【同一份檔案裡面】。**

🔴 **而「在同一份檔裡」正是它難抓的原因,不是容易抓的原因**:
「我讀過那份檔了」感覺上應該涵蓋它 ——
**而沒有人【整份】讀 runbook,大家是照路由跳到自己要的那一節。**
⇒ **節與節之間的假設,沒有任何東西在檢查。**
⇒ 它**只在有人【同時執行兩節】的那一刻才現形** —— 而那個人**十天後才第一次出現**。

## ⇒ 下次那一刻要做的動作

1. **改一份多節文件的某一節時,grep 全檔那一節提到的識別字**
   (本例:`grep -n authenticator <該檔>` ⇒ 會立刻看到 `:121` 有它、bootstrap 沒有)。
2. 🔴 **而寫「清單」型的段落時,標出它的射程**:
   本次補的字面刻意寫成「**43 支仍然失敗 —— 本清單還是不完整,不要讀成照著跑就會全綠**」,
   **而不是「已補齊」** —— 一份自稱完整的清單,會讓下一個人不去讀第一支失敗的錯。
3. ⚠️ **而這條抓不到「兩份【不同】檔互相假設」那一種** —— 那個更難,分母是全 repo。

## A-3 同一夜第三次,而**這次是【工具的尺】看不懂我的路徑**(A-1 的兄弟,不另開族)

> **併進同一個落點(正本 `:482` ⑤)。** 本條不必再查重 —— 它與 A-1 是同一個機制,只是尺的擁有者換人。

**當班實錘**(2026-08-29,跑 `picking/page.test.tsx` 驗一顆純註解的 commit):
```
npx vitest run "src/app/print/orders/[id]/picking/page.test.tsx"
⇒ rc=1，而畫面上【一個總計行都沒有】
⇒ No test files found
```
成因**兩個疊在一起**,而任一個單獨都足以造成同一個外觀:
1. **`[id]` 的中括號被 vitest 的過濾器當成【字元集】** ⇒ 它去找一個叫 `.../orders/i/...` 或 `/d/` 的路徑。
2. **`vitest.config.ts` 在 repo 根,而我人在 `apps/admin/`** ⇒ 換成 `--dir` 一樣零命中。

### 🔴 同一夜三次,**外觀完全一樣**

| # | 尺 | 症狀 |
|---|---|---|
| A-1 | 我的 `grep '^| **'`,而重要那列是 `| 🔴 **` | 印 **3** 而有 **4** |
| A-2 | 我的 `grep '^# A-'`,而 `A-1` 用 `##` | 印 **1** 而有 **2** |
| **A-3** | **vitest 的過濾器,而我的路徑含 `[id]`** | **餵 1 而跑 0** |

📌 **⇒ 共同外觀:一個【合法的、比真值小的數字】,而沒有任何東西會紅。**

🔴 **而 A-3 與前兩個有一個【處置上的差別】,值得分開記**:
```
A-1 / A-2 = 我的尺看不懂【我的格式】 ⇒ 我改得動尺
🔴 A-3     = 工具的尺看不懂【我的路徑】 ⇒ 我改不動它，只能【繞】
```
⇒ 而「繞」的代價是:**它每次都會再發生一次**,而下一個人不會知道前一個人繞過。
(本次的繞法:回 repo 根跑、不用含 `[` 的過濾字串;而**驗證繞成功的方法不是看 rc,是看總計行出現了**。)

### ⇒ 下次那一刻要做的動作

🔴 **`rc != 0` 而【看不到總計行】⇒ 先判「它有沒有跑」,再判「它綠不綠」。**
`No test files found` 的 `rc=1` 與「有測試而紅了」的 `rc=1` **是同一個數字**,
而 `docs/patterns/…` 那條「在錯的目錄跑 vitest ⇒ 濾掉那句之後畫面全空,與零失敗長一樣」講的就是它。
⇒ **機械動作:跑完先 `grep -cE '^ *Test Files' <log>`,是 0 就代表【它根本沒開始】。**

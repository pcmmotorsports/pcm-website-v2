## 15-4 · 我用一把壞尺去驗證另一把壞尺的結論,而兩把都回 0 ⇒ 我得到「互相印證」

> **抓到的人 `-15`;第二層是主視窗 `-2d` 自述,它要求照實寫不要修飾。**

### 🛑 先講結論:我們差點把一個【假指控】寫進本檔

`-2d` 交辦我記一條:「`scripts/before-asking-sean.sh` 宣稱掃 memory,而它掃的是子集」。
**那是假的。那支工具沒有壞。**

```
實跑 bash scripts/before-asking-sean.sh "pg_cron" > <檔> 2>&1   (2026-08-31 12:26)
用 python 數(理由見下面第二把尺):
  總行數 212 · 含 '/memory/' **37** · 含 'a-route-scheduler' **4** · 🔵 負對照現造字面 **0**
  而那 4 行落在【段②】, 段名逐字「② Sean 答過了嗎(決策板 + 板子 + memory 拍板檔)」
⇒ 段名與分母一致。`:91` 是 grep -rn -- "$KW" "$MEMDIR", 整個目錄。
```
🔴 **而那 4 行就是我在 15-3 說「沒讀到」的那支 memory** ⇒ **這條指令當時就會撈到它。**

### 兩把壞尺,而它們互相印證

```
尺一 · head 截掉證據（兩個人各一次,同一天）
  我   `… | head -12`  而 memory 那幾行排在第 24 行之後
  -2d  `… | grep -A2 '② Sean 答過了' | head -6`
  ⇒ 兩個人都把【我沒看到】讀成【它沒印】
尺二 · 這台機器的 `grep` 是 shell function(展開成 ugrep,帶 `-I` 跳過二進位)
  對同一個檔、同一個字面:
    包裝後 grep -c '/memory/'        ⇒ 印【空白】 rc=1
    包裝後 grep -c '<現造不存在>'    ⇒ 印【空白】 rc=1   🔴 與上一行完全相同
    command grep -c '/memory/'       ⇒ 37  rc=0
    command grep -c '<現造不存在>'   ⇒ 0   rc=1
```
🛑 **⇒ 那把尺在「有 37 個」與「有 0 個」兩個世界印出【完全相同】的東西:空白 + rc=1。**
**⇒ 它不是回錯的數,它是【零判別力】。**
🔴 **而 `rc` 也分不出來** —— `command grep -c` 沒命中時 rc 也是 1(只是它印了 `0`)
⇒ **能分出兩個世界的只有【印出來的值】,不是 rc。** ⇒ `&&` 串接在這裡兩個世界都斷。

### 🔴 根因是一條鏈,不是「ugrep 很怪」—— 每一環都量到了

```
① 這台機器 LC_CTYPE="C"（LANG 空）
② scripts/before-asking-sean.sh:91 用 `cut -c1-220` 截行,而那些行含中文
③ 在 C locale 下 `cut -c` 是【按位元組】切 —— 現造重現:
     printf '一二三四五六七八九十' | cut -c1-5 ⇒ b'\xe4\xb8\x80\xe4\xba'
     ⇒ 一個中文字被攔腰切斷 ⇒ **非法 UTF-8**
④ 那個輸出檔實測:裸 0x85 位元組 **155** 個 · NUL **0** 個 · 整檔無法以 UTF-8 解碼
⑤ `file` 判它 `Non-ISO extended-ASCII text, with LF, NEL line terminators`
⑥ ugrep 的 `-I`(跳過二進位)⇒ **整個檔跳過, 連計數行都不印**
```
📌 **⇒ 那支工具【自己的截行】,讓它自己的輸出量不了。**
⚠️ ~~`-2d` 原本寫成「NEL(U+0085)」~~ ⇒ **UTF-8 的 NEL 是 `C2 85`,而本檔實測 `C2 85` = 0**;
真正在裡面的是 **155 個裸 `0x85`**(被切斷的中文字尾巴)。**結論相同,而位元組不是那一個。**

   它若也印空白 ⇒ **這把尺此刻是死的**, 上面那個 0 不算數。
可操作 · 數任何工具輸出檔:用 `command grep -c` 或 python, 不要用裸 `grep`

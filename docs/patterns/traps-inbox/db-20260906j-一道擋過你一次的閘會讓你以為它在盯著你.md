# 一道擋過你一次的閘,會讓你以為它在盯著你 —— 而它只在 commit 那一刻睜眼

> 線【DB】`-db` 2026-09-06 · ⟦db-TAXONOMYVIEW⟧ 折 opus R1 的過程中撞到,同一個錯**三次**。

## 現場

`scripts/pg-catalog-prefix-gate.py` 掃 **staged** 的 `.sql`,擋「`pg_catalog.` 前綴接到 SQL 保留語法上」
(`COALESCE` / `NULLIF` / `GREATEST` … 那一族)。它擋的是一個**只在 apply 當下才炸**的語法錯 ——
靜態檢查看不到、三綠看不到。

那天我在寫一支新 migration,為了 `SET search_path = ''` 把每個函式都加了 `pg_catalog.` 前綴。

1. **第一次** —— `git commit` ⇒ 閘擋下,逐字告訴我 `COALESCE` 那一族不能加前綴。我改掉,commit 過。
2. **第二次** —— 折審查意見時重寫函式本體,`COALESCE` 又被我打上前綴。
   而那時檔案**還沒 `git add`** ⇒ **閘沒跑** ⇒ 我不知道。
   是拿去拋棄式 PG 跑才炸:`ERROR: function pg_catalog.coalesce(jsonb, jsonb) does not exist`。
3. **第三次** —— 折另一條意見時寫 `COMMENT ON VIEW` 的串接,又打上去。
   一樣沒 staged、一樣沒擋、一樣是真的跑才炸。

## 病灶不是「我不小心」

🔴 **一道守門的【取樣時點】決定了它看得見什麼。**
`pre-commit` 的閘只在 `git commit` 那一刻睜眼。而「我在編輯中反覆犯同一個錯」發生在**兩次 commit 之間** ——
那段時間它是閉著眼的。

🛑 而更貴的是**心理效應**:
> **它擋過我一次 ⇒ 我把它讀成「這個錯有人在盯」⇒ 我不再自己看那一行。**

第一次被擋之後,我對那個錯的警覺**下降**了 —— 因為我以為有機制在守。
📌 **一道間歇性的守門,會把人的注意力換成它的取樣頻率。** 而那個交換是虧的:
人的注意力是連續的,閘的取樣是離散的。

## 怎麼分辨自己在不在這個坑裡

問一句:**「這道閘如果現在跑,它看得到我手上這份改動嗎?」**
- 看不到(還沒 staged / 在別的檔 / 在別的分支)⇒ **那個錯現在沒有任何人在看**。
- 而如果你會這樣問,通常是因為**它擋過你** —— 那正是要問的時機。

## 便宜的做法(不是規則,是動作)

- 折審查意見**改完一輪就 `git add`** ⇒ 讓閘有機會睜眼,不要累積到最後一次。
  🔵 代價幾乎為零,而它把「離散取樣」的間隔縮短。
- 或者:**真的跑一次**。這一片最後是拋棄式 PG 17.10 抓到的 ——
  而那不是巧合:**每一道靜態檢查自己都逐字寫著「不驗行為」**。

## 這一則答不出什麼

- 我**沒有量**「加了幾次 `git add` 之後那個錯會少幾次」—— 上面那個做法是推的,不是量到的。
- 它也不是 `pg-catalog-prefix-gate` 的缺陷:**掃 staged 是那道閘的定義**,不是它的 bug。
  這一則講的是**人怎麼誤讀一道正確的閘**。

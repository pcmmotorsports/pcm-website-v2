## 🔴🔴 同一個量在兩個分支各數了一次,而**對的那半掩護了錯的那半**(2026-09-05 線【身分】`-auth`)【安靜】

```
一支探針的 try() 判「UPDATE 有沒有改到列」, 兩個分支:
  deny 那支   [ "$(… | grep -c '^[0-9]')" -eq 0 ]     ← 對的(只數 RETURNING 的 id 行)
  pass 那支   [ "$(… | grep -c .)"        -ge 1 ]     ← 錯的
而輸入是 psql -c "SET ROLE …; UPDATE … RETURNING id" ⇒ **輸出第一行是 `SET`**
⇒ 📌 pass 那支即使【改到 0 列】也數到 1 ⇒ **那一格永遠不可能失敗。**
```
🔬 **實錘(不是推論)**:把被測的 migration 突變成 `USING (false)` ⇒
探針印「**改到 2 列**」而**全綠**;而同一個突變在最小重現裡是 `UPDATE 0`。
統一成 `grep -c '^[0-9]'` 之後,同一發突變**紅在該紅的那一格**。

🎯 **而它能活下來的原因,才是這一條要記的東西**:
**我自己 review 那段時看到 deny 那支寫著 `^[0-9]`,就覺得「這裡有想過」而放行了。**
⇒ 🛑 **對的那半讓整段【讀起來】是對的。** 兩支若都寫錯,反而容易被看出來。

🔴 **判別句(落筆當下可機械執行)**:
> **同一個量,我在幾個地方各數了一次?那幾次用的是【同一把尺】嗎?**
⇒ 兩處以上 ⇒ **抽成一個變數/一支函式,讓它們不可能漂**(本例:`local rows=$(… grep -c '^[0-9]')`)。

🔵 **與 `:9081`「兩把尺各窄一半而窄的地方不重疊」的分界**(那條在正本,已讀過再判):
· `:9081` = 兩把尺**都錯**、方向相反 ⇒ **互相檢查會看到不一致**,只是兩邊都不對。
· 本條   = 一把對一把錯 ⇒ **互相檢查看不到不一致**,因為錯的那支從來沒被拿去跟對的比。
⇒ 📌 **兩條的修法也不同**:那條要「用另一把尺再量一次」;本條要「**讓兩處變成一處**」。

⚠️ **本條的射程**:目前只有**一個**實例(本次)。「兩支數法不一致」在這棵 repo 裡還有幾處,**我沒有掃過**。

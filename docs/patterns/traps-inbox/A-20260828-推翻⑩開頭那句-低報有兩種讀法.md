## 3. 新實例本身(建議編號 `⑩-x`;若已被占用由收稿人改)

**標題建議**:
`⑩-x 一把大小寫敏感的尺,量一個大小寫不敏感的東西 —— 東西在,而尺說不在(2026-08-28 線A)`

**當天發生的事**
折完 R3 的 `nit3`(六個輸入框補 `autoComplete='off'`,擋瀏覽器 autofill),
開真瀏覽器驗證時我先用 curl 抓 HTML 再 grep:
```
grep -o 'autocomplete="off"' page.html | wc -l   ⇒ 0     (期望 6)
負對照 grep -o 'autocomplete="zzz"'              ⇒ 0
```
**我差一步就回報「nit3 沒生效」。** 開檔看渲染出來的標籤才發現:
```
<input autoComplete="off" aria-label="收件人" placeholder="收件人" ... name="ship_to_name" ...>
```
⇒ **它在。** 只是渲染成 **camelCase `autoComplete=`**,而我的 grep 是**大小寫敏感**的。
⚠️ 而 **HTML 屬性名本身是大小寫不敏感的** ⇒ 瀏覽器照樣把它解析成 `autocomplete`。
⇒ **東西是對的、行為是對的,只有我的尺是錯的。**

**正解(判別句,主視窗指定逐字保留)**
```
不要問 HTML 字串, 問真 DOM 的 `el.autocomplete` —— 那是瀏覽器解析後的事實。
```
改用真 DOM 之後 —— **數法附在這裡,不要只信那個 6**(playwright `page.evaluate`,
對 `http://localhost:<probe埠>/orders/new`;起法 `bash scripts/admin-probe/up.sh`):
```js
['customer_phone_lookup','new_customer_name','new_customer_phone',
 'ship_to_name','ship_to_phone','ship_to_line']
  .map(n => { const el = document.querySelector(`input[name="${n}"]`);
              return { n, present: !!el, autocomplete: el ? el.autocomplete : null }; })
// 2026-08-28 線A 實跑 ⇒ 六格 present:true、autocomplete:"off"(6/6)
// 負對照:document.querySelector('input[name="zzz_nope_20260828"]') ⇒ null(尺是活的)
```
⚠️ **這 6 是【那一次、那一頁】量到的**,不是一個永久事實 ——
欄位增減、元件改寫、或有人拿掉某一格的 `autoComplete`,這個數就變了。**引用前自己再跑一次。**
⚠️ 而**本節不宣稱「所有 HTML 屬性都會這樣渲染」** —— 我只量了這一頁的這六格;
   為什麼是 camelCase(Next 的哪一層、RSC 還是 SSR)**未查證**,標未確認。

**它為什麼比 ⑩ 的其他成員貴(主視窗指定逐字保留)**
```
它產生的是最糟的那一種錯:回報「修法沒生效」⇒ 有人去改一個本來就對的東西。
```

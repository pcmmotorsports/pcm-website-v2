## 現場(2026-09-05,`docs/runbooks/duplicate-shipping-email-sop.md`)

那是一份**客服會照做的紙**。它裡面**同時有**對的判法與錯的判法:

```
:25  🔵「看後台那張單目前的出貨資訊, 把【現在的】追蹤號唸給客人」   ✅ 對
:40   「後面那一個才是對的」                                        ❌ 只對它自己那個世界
:41  🔵「給客服的一句話:請客人用【最新那一封】的追蹤號查件」        ❌ 同上
```

🔴 **`:25` 是一段【說明】;`:41` 是一句【可以直接唸的話】,而且它自己標著「給客服的一句話」。**
⇒ 🛑 **會被照做的是 `:41`。**

**它在哪個世界給錯的答案**:員工把追蹤號 A 改成 B ⇒ 系統補寄一封說 B ⇒ **他又改回 A**
⇒ 客人手上**最新那封說 B**,而後台現在是 **A** ⇒ 客服唸 B ⇒ **客人拿錯號碼去查件**。

🔵 **而 `:40`/`:41` 在它們自己描述的世界裡完全正確**(作廢+重開一張新箱 ⇒ 新的那箱就是真的)。
📌 ⇒ 這一層是 memory `feedback_a-rulings-reason-can-be-right-and-narrow` 那一族;
**本條加的是【下一步】:那個窄的規則為什麼會贏過同一份文件裡對的那一條。**

## 為什麼它不會被發現

```
寫的人   兩段都是他寫的, 他知道 :25 才是判準 ⇒ 他讀 :41 時自動帶上 :25 的脈絡
讀的人   他要的是「現在該跟客人說什麼」⇒ 他找的就是【最像那句話的那一句】
稽核     兩句都在檔裡 ⇒ grep 得到、內容也都寫得出理由 ⇒ 🛑 沒有任何一發會紅
```
🔴 **⇒ 它不是「文件過期」也不是「文件寫錯」** —— 兩句都是作者當時想清楚才寫的。
**壞的是【兩句的射程不同,而排版沒有說出這件事】。**

## 判別句(交一份會被照做的紙之前問一次)

> ### **「這份文件裡,最像【可以直接照抄的那一句】是哪一句?它對嗎?」**
> 🔴 而不是「這份文件裡有沒有錯的句子」—— 後者你會找到 `:25` 然後放心。

**動作**
1. **把可照抄的那一句的射程寫進【那一句自己】**,不要寫在別段(距離為零才擋得住 —— 📎 見下面分界)。
2. **一份紙上只准有一句「一句話」。** 有第二句就要問它們會不會在某個世界打架。
3. 訂正時**舊字面加刪除線留著**,讓照舊字面搜的人**同一發撞到訂正**。

## 同一把尺,兩個失效方向 —— **而整晚的討論都在錯的那一邊打轉**〔安靜〕

> 🔴 **併入 canonical 時請放在「量具族」的最前面** —— 它是「量具只看得到某一層」最乾淨的實例。

### 判別句

> 🔴 **我這把尺失效的時候,是【多叫】還是【少叫】?**
> 只想過一個方向 ⇒ **另一個方向你還沒找過,而它通常比較嚴重。**

一般化:**假警報浪費一輪;漏報讓帶著問題的東西被收進去。**
兩者都要各自找一個實例,**只證一個方向 = 只驗了一半**。

### 實例(2026-08-17 夜;三個窗、一個晚上、同一把尺被推翻三次)

收割前的「不落地衝突預演」,量法演進:

```
v1  git merge-tree $BASE dev <界線> | grep -c 'changed in both'
v2  git merge-tree $BASE dev <界線> | grep -c '<<<<<<<'
v3  git merge-tree --write-tree dev <界線> >/dev/null 2>&1; echo $?     ← 現行(0=可併 1=衝突)
```

**v1 怎麼死的(I 窗)**:兩個世界(同檔不同段 / 同檔同一行)**都印 `1`** ⇒ **根本不是量具**。
🔴 而我當時抽的病根是對的:「**我把一個【分類標籤】當成了【嚴重度分級】**」——
`changed in both` 旁邊還有 `added in both` / `removed in both`,我的 `grep` 一個都沒抓。
🔴 **更毒的是我把它【廣播給全陣】** —— 而它當時讀起來比原本更嚴謹(它甚至更正了一個更粗的用法)
⇒ **一個錯的量法,只要它比前一版精確,就會被當成改進而擴散。**

**v2 怎麼死的 —— 兩個方向,兩個窗各抓到一個:**

| 方向 | 抓到的人 | 證據 | 嚴重度 |
| --- | --- | --- | --- |
| **假警報**(該綠而報紅) | T 線 | 真 repo:v2 回 `2`,真 merge 零衝突 | 浪費一輪 |
| 🔴 **漏報**(該紅而報綠) | I 窗 | C 窗 `fc065f3f`:v2 ⇒ `0`、v3 ⇒ `1` | **會把帶衝突的東西收進 dev** |

**漏報那一發的原文**:
```
git merge-tree --write-tree dev fc065f3f
CONFLICT (modify/delete): docs/patterns/traps-inbox/C-20260817.md
  deleted in dev and modified in fc065f3f.
```
🔴 **成因:`modify/delete` 是【樹層級】衝突,它不會產生任何衝突標記** ——
而 `grep '<<<<<<<'` 只看得到**內容層**的衝突。**尺對的是一層,而衝突可以發生在另一層。**

⚠️ **假警報那個方向我構造不出來**(四格:線性 / 基底含 merge commit,各配同行與不同行,
`<<<<<<<` **四格全對** `0/1/0/1`,`git version 2.39.5`)。**我沒有據此宣稱 T 線錯了** ——
**兩人各有一個方向的實證 ⇒ 兩邊都留,不挑一個消滅。分歧本身是證據。**

### 為什麼它安靜

`grep -c` **回 `0` 在終端機上,和「真的沒有衝突」是同一個畫面**。
而三個版本的每一版**都比前一版更精確** ⇒ **每一次更正都感覺像進步,而問題只是換了一層。**

### 🔴 T 線抽的那句(照原字,它是這一族最深的一層)

> **我兩次都做了「自造兩個世界」那個動作,兩次都得到「它會分辨」這個正確答案 ——
> 錯的是【我沒問我的樣本像不像真的】。**

⇒ **雙向表演過關 ≠ 量具在真實場景準確。**
玩具 repo 沒有 merge commit、沒有 rename、沒有交叉歷史、**沒有人在別的分支上刪檔** ——
**而那正是真 repo 每天都有的東西。**

### 動作(不是決心)

- **換掉一把尺之前,先問它【兩個方向】各有什麼實例**;只有一個方向 ⇒ 標明「另一方向未測」。
- **能用工具自己的 rc,就不要用 `grep` 去讀它的輸出** —— 輸出是**給人看的**,rc 是**給程式看的**;
  前者的格式與分類是工具的自由,後者是它的契約。
- **`grep` 一個工具的輸出當判準時**,同一段寫下「**我這個字集是誰列的**」——
  工具的文件,還是我的印象?我的印象 ⇒ 先去把平行項列完,或改用 rc。

### 與既有條目的關係

- 「**尺量的是分類,而我讀成嚴重度**」(canonical 量具族):那是 v1 的死因,本則是**整條演進**。
- 「**量具壞掉的時候,它的錯誤訊息會偽裝成你要的那個數字**」:同族 —— 那是**輸出被污染**,
  本則是**輸出看不到那一層**。
- memory `feedback_check-scope-narrower-than-risk-scope`:同源。**本則是「層」的版本,不是「範圍」的版本。**

## 舊字面掃描的**反面**:掃到的不是自己的訃聞,是**別人的同名字**〔安靜〕

> 來源 = B 窗 2026-08-17 夜實例(主視窗轉,我未複驗)。與 canonical 既有的
> 「**更正本身會過期**」與 memory `feedback_claimed-sync-but-only-patched-touched-lines`
> 的「留痕會讓掃舊字面掃到它自己的訃聞」**互為反面**。

### 判別句

> 🔴 **這個命中,是【我要找的那個東西】,還是【剛好長一樣的另一個東西】?**
> 兩者在 `grep` 的輸出裡**完全相同**。

### 實例(B 窗;值由它提供)

它把 `§7.1` 從 B3 spec 搬到 B5 spec 之後,拿舊字面掃全樹 ⇒ 命中 `docs/phase-1-backlog.md:324-336`。
**開檔讀了** ⇒ 那是 **M-0-07 指令的 `§7.9` / `§7.10`**,**不是它的 `§7.1`** ⇒ **不動**。

### 兩個反面湊成同一個動作

```
掃到自己的訃聞    命中的是【我剛寫的刪除線】     ⇒ 會被讀成「那句話還在」
掃到別人的同名字  命中的是【另一份文件的同名節】 ⇒ 會被讀成「這裡也要改」
```
🔴 **兩者的共同解法只有一個:命中之後【開檔讀那一段】,不要看數字。**
⇒ `literal-sweep.sh` 的輸出是**候選清單**,不是**待辦清單**。

### 動作(不是決心)

- 舊字面掃描的每一個命中,落筆說「已處理 N 處」之前,**逐處寫下它屬於哪一類**:
  ①真的要改 ②我自己的留痕 ③**同名但無關** ④有日期的歷史紀錄、不動。
- **四類的數字加起來要等於命中總數** —— 加不起來表示有命中沒被看過。

## 尺會動、方向也對,而**單位是錯的** —— 比不會動的尺更難被發現〔安靜〕

> 🔴 併入 canonical 時放在量具族,**緊接在「同一把尺,兩個失效方向」之後**。

### 判別句

> 🔴 **我這把尺回的那個數,單位是什麼?**
> 答得出「幾個 X」而說不出「X 是怎麼被數成一個的」⇒ **你不知道它的單位。**

一般化:**「它有反應」是雙向驗會通過的訊號,而【單位錯】雙向驗抓不到** ——
因為錯的單位通常**與對的單位正相關**,兩個世界照樣印不同的數。

### 實例(2026-08-17 夜;`scripts/dev-four-greens.sh` 的並行數儀器)

`RUN-CONTEXT` 印「並行vitest行程數」,判準是 `count_matching '[v]itest'`(`:219`)。

```
同一時刻   舊尺 ps -Ao command | grep -c '[v]itest'        ⇒ 13
           新尺 ps -Ao command | grep -cE '[v]itest\.mjs'  ⇒ 1
逐條開輸出讀那 13 個（不看數字）:
   1 個  node …/vitest/vitest.mjs run                                  ← 真的 run
  10 個  node --experimental-import-meta-resolve --require …/pcm-d…    ← 🔴 同一發 run 的 worker
   2 個  /bin/zsh -c source …snapshot-zsh…                             ← shell
```
⇒ 它量的是 **worker 行程數**,而欄位名寫的是 **run 數**。

🔴 **為什麼它撐了這麼久沒被抓到**:worker 數**會跟著 run 數一起動** ——
多一發 run 就多十幾個 worker ⇒ **它對世界【有反應】、方向也【對】**。
⇒ **雙向驗會過**(有 run 時大、沒 run 時小),**而每一個絕對值都是錯的**。
⇒ 兩筆已經寫進 `#618` 分析的數字因此**整組作廢,且不可換算** —— 只能重量。

### 為什麼它安靜

**壞掉的尺會給你一個明顯不對的數**(0、負數、爆大),**單位錯的尺給你一個合理的數**。
`12` 是個很合理的並行數。**沒有任何一個世界會讓它印出可疑的東西。**

### 動作(不是決心)

- **每一個要寫進分析的數字,同一行寫下它的單位,並問「這個單位是怎麼數出來的」。**
- **雙向驗過了不代表單位對** —— 雙向驗回答「它會不會動」,**單位要另外問**。
- **看數字永遠看不出單位錯 ⇒ 逐條開輸出讀一次。** 這一則是這樣抓到的,沒有別的方法。

### 與既有條目的關係

- 「**同一把尺,兩個失效方向**」:那則是**失效方向**;本則是**單位** —— 尺沒失效,它一直在動。
- 「**尺量的是分類,而我讀成嚴重度**」:那則是我**讀錯輸出**;本則是**輸出本身就是別的東西**。

## 命令列是**任何人都能寫進去的字串** —— 從 `ps` 數東西,你數的是「誰提到過它」〔安靜〕

### 判別句

> 🔴 **我 `grep` 的那個字串,會不會出現在【別人正在打的字】裡?**
> 在這個艦隊裡,答案幾乎永遠是會 —— **因為我們整晚都在討論它。**

### 實例(2026-08-17 夜;而我是在寫「怎麼修上一則」的那條命令裡踩到的)

上一則的修法是把字面收窄成 `[v]itest\.mjs`。**我複量了一次:**

```
新尺 ps -Ao command | grep -cE '[v]itest\.mjs'   ⇒ 5      而當下【零個真 run】
逐條列出那 5 個:
   3 個  /bin/zsh -c source …snapshot-zsh…       ← 🔴 我自己的 shell
   2 個  node …/codex exec … / codex-darwin-arm64 ← 別窗的 codex
```
🔴 **成因:我在同一條命令裡 `echo` 了一段解釋文字,而那段文字含那個字面**
⇒ 它進了 `zsh` 的命令列 ⇒ 被 `ps` 撈到。
⇒ **`[v]` 那個括號技巧只避開 `grep` 自己。它避不開「我正在談論它」。**

**再收窄一層也不夠**:改成「執行檔名必須是 `node`」——
```
pgrep -f 'itest\.mjs' 逐個查 comm:
  zsh   ← 濾掉
  node  ← 🔴 這是【codex 的 node】,不是 vitest
  codex
```
⇒ **一個跑 codex 的 `node`,只要它的 prompt 文字含那個字,就會被算進去。**

### 🔴 最糟的性質:**噪音與討論強度正相關**

這把尺的**地板不是 0,地板高度取決於「現在有多少人正在打字提到它」**。
⇒ **而討論強度在事故當天最高。** **它會在你最需要它的時候最不準。**

### 動作(不是決心)

- **不要從 `ps`/`pgrep` 的【命令列】數東西當判準。** 命令列是**別人的自由文字**。
- **要數「有幾發在跑」,讓那件事自己留痕**:起跑時在 `logs/` 開一支 `<pid>` 標記檔、
  結束刪掉,**數檔案**。⇒ **那不是字串比對,是「真的有那個 run 才會存在的東西」。**
  (📌 這是**建議**,腳本不歸收割窗,已交作者。)
- **凡是 `grep` 一段【會出現在文件與訊息裡】的字面**,先問:**我自己等一下會不會寫到它?**

### 📎 這一則自己就是它的實例

**我是在寫「怎麼避免這個坑」的那條命令裡踩到這個坑的。** 同族第三次:
heredoc 因含被禁字面而被閘擋下 / `git commit --no-verify` 在無 hook 的拋棄式 repo 裡被擋下 / 本則。
> 🔴 **你越把一個字面寫清楚,它越會出現在不該出現的地方。**

## 「就地更正」與「並列兩版」在檔上**看起來都像已修好**〔安靜〕

> 來源 = V 窗 2026-08-17 夜稽核 `I-009` 的六條(F1-F6),病根是它抽的。

### 判別句

> 🔴 **我把更新寫在哪裡 —— 原段裡,還是另一段?**
> 另一段 ⇒ **原段現在是廢版,而它讀起來完全正常。**
> **接手人是照【正文順序】讀的,不是照【我更新的順序】讀的。**

### 實例(I 窗自己的交接檔)

`I-009` 檔尾加了一節 `§🔁「22:0x 追加」`,更新了 `§①`/`§③`/`§④`/`§⑥`/`§⑦` 的內容,
而**只在檔頭標了「§③-C 自撤一處」**,其餘四處**原段沒有任何標記**。
```
§③-B-新增  逐字「口徑:寫『現在必然放行』,不得寫『已加上守門』」
§🔁        逐字「口徑改成『已加上守門,且同一顆 tip 上真的擋過一發』」
⇒ 兩段相反,而 §③ 無刪除線、無指標 ⇒ 接手人會照 §③ 做
§④ 列「沒做完的三件」之首,而 §🔁 寫「已完成」
§⑥ 待收清單是舊版 tip —— 🔴 而本檔第一段就自誡「照界線收」
```

### 🔴 而同一份檔裡有【做對的兩處】,差別值得記

`§③-C`(量法 v1/v2/v3)與 `§⑤`(逃生門舊 A/B / 新 C)**都標了刪除線 + 兩版並列**。
⇒ **差別不是我知不知道規矩** —— 是那兩處**我當時就意識到有兩個版本**,
而另外四處是**就地更正**:我改的時候心裡只有「新的那版」,**沒有意識到舊的還躺在上面**。

### 動作(不是決心)

- **在檔尾加「更新/追加」節之後,回頭在【每一個被它覆蓋的原段】補一行回指。**
  一行就夠:`⚠️ 本節已於 §X 更新,照那版`。
- **判別法**:寫完追加節,問自己「**這一節推翻了本檔的哪幾段?**」——
  答得出幾段,就要回去標幾段。**答不出來 ⇒ 那節可能根本不該用追加的形式寫。**
- **修的是【指標】不是【數字】** —— V 窗原話:數字都對,只是新舊並存無標。

## 一句錯的轉述被**做成機制**之後,**更正那句話不會更正那個機制**〔安靜〕

### 判別句

> 🔴 **我剛更正的那句話,有沒有人已經拿它去【做了什麼】?**
> 做了 ⇒ **更正只回到了說過那句話的人身上,沒有回到那個產物上。**

### 實例(2026-08-17 夜;源頭是主視窗,它自己歸的戶)

主視窗把一個**未複量**的診斷原字廣播:「`find -newermt` 相對格式壞掉的方式是
**三個訊號同時沉默**(stderr / **exit code 仍是 0** / 0 行)」。
B 窗**據此掛了一道 pre-tool 攔截閘**,而**那句話被寫進了閘的訊息文字裡**。
之後主視窗與 E 窗、I 窗各自實測 ⇒ **`rc` 是 `1`,`find` 有報錯** ⇒ 更正廣播出去。

```
守門本身      ⇒ 對的、該留
守門的【解釋】⇒ 錯的,而它還在那裡對每一個撞到閘的人說「exit code 仍是 0」
```
🔴 **而錯的解釋長在守門裡,比長在文件裡更貴**:
**讀者在【正要犯那個錯的那一刻】最信它**,而且**不會想到要去查一個「守門說的話」**。

### 為什麼它安靜

更正走的是**訊息通道**(廣播、STOP、commit body),而機制住在**執行通道**。
**兩個通道沒有任何連結** —— 沒有東西會因為「那句話被更正了」而讓那道閘變紅。

### 動作(不是決心)

- **更正一句已經廣播出去的話時,同一段問:「有沒有人拿它做了東西?」**
  hook / 守門訊息 / runbook 步驟 / 測試斷言的註解 —— 都是「拿它做了東西」。
- **反向**:**要把一句話寫進機制之前,先問它是【量到的】還是【讀來的】。**
  讀來的 ⇒ 機制裡只寫**動作**,不寫**解釋**(解釋放指標,指到會被更新的那份檔)。
- 📎 這一則是「**更正本身會過期**」的下一層:那條講的是更正的**下游文件**;
  **本條講的是更正的【下游產物】,而產物不會讀你的更正。**

## 一道擋住「**寫下它自己**」的守門 —— 它會**系統性地讓自己無法被記載**〔安靜〕

### 判別句

> 🔴 **這道閘看的是【命令字串】還是【我在做什麼】?**
> 命令字串 ⇒ **「寫一篇說明這個坑的文章」與「犯那個坑」在它眼裡是同一件事。**

### 實例(2026-08-17 夜,同族第三次,而這次多一層)

```
1 T 線在自己剛 mktemp -d、本來就【沒有任何 hook】的拋棄式 repo 裡跑 git commit --no-verify
  ⇒ 被 pre-commit 閘以「繞過鐵則 11」擋下（那個 repo 根本沒有鐵則 11）
2 I 窗用 heredoc 經 Bash 落檔,而檔案內容在講那個被禁的時間格式字面
  ⇒ 被 find 攔截閘擋下 —— 🔴 而它擋下的正是【把這條教訓寫進 traps】那顆 commit
3 同一道閘的第一版把整個 command 當一串判 ⇒ 連 heredoc 裡【描述這個坑的散文】也誤擋
```
🔴 **第 3 條那一層是新的**:前兩者是「擋錯了一次」,**這一條是「它會系統性地讓自己無法被記載」**——
**每一次有人想把這個坑寫下來,都會再被擋一次。** ⇒ **那道閘在製造自己的知識真空。**

### 動作(不是決心)

- **寫任何看命令字串的閘,先問:「有人會為了【描述這件事】而把這個字面打出來嗎?」**
  會 ⇒ 閘要能分辨「**執行**這個字面」與「**寫下**這個字面」
  (例:只在真的要執行的位置比對,而不是整條 command 一起 grep)。
- **繞法要選【不停用任何東西】的那條**:換工具落檔(編輯工具而非 Bash)、
  `core.hooksPath=/dev/null` 開一個本來就沒 hook 的環境 —— **不要 `--no-verify`、不要改閘。**
- **撞到之後把「我是在寫它的說明書時被擋的」記下來** —— 那句話本身是那道閘的 bug report。

## 「**我預期紅在哪一格**」要寫在**動手之前**〔安靜〕

### 判別句

> 🔴 **這一發突變紅了 —— 而它紅在【我預期的那一格】嗎?**
> 沒有事先寫下預期 ⇒ **「紅了」與「紅對了」你分不出來。**

### 實例(2026-08-17 夜 T 線,而它一小時前才把這個坑寫進 inbox)

突變 `M29` 第一版寫成 `grep -v '<字面>'` **掃整檔** ⇒ **連 `格25-g` 自己那一行也被刪掉**
⇒ **紅的是 `格25-g`,不是預期的 `格25-j`**。
🔴 **抓到它的是「紅在哪一格與我預期的不同」,不是它記得那條規則。**
📎 **它一小時前才寫下那條規則** —— **寫下來不等於不會再犯**,而**預期表會抓到**。

**已改成機制**:突變射程一律 **`awk` 切函式範圍**,不用 `grep -v` 掃整檔。

### 為什麼它安靜

**突變測試的成功訊號是「紅」,而紅是廉價的** —— 刪錯行也會紅、語法壞掉也會紅。
⇒ **只看「有沒有紅」的突變測試,對「我改對地方了嗎」零判別力。**

### 動作(不是決心)

- **每一發突變,動手前寫下「預期紅哪一格」**,跑完逐發對。**對不上 ⇒ 先查突變本身,不要先信結論。**
- **突變的射程用結構切**(`awk` 切函式 / 行號範圍),**不要用字串刪** —— 字串會命中它自己。

## 留痕是**給人讀的**,而**機器數的時候要跳過它**〔安靜〕

### 判別句

> 🔴 **我這條計數,會不會把【我自己寫的訃聞】算成一則?**
> 會 ⇒ 你數的是「這個字出現幾次」,不是「有幾則」。

### 實例(2026-08-17 夜 A 窗抓到,而它直接咬收割窗)

併 `traps-inbox` 時要數「哪幾則已經在 canonical 裡」。
**實測**:`grep -c '基準是手打的'` 全檔命中 **4** 次,而其中一次是 `:3441` 那條
**劃掉的舊指標**(`## 📎 ~~指標:…~~ 全文已併入本檔`),**不是一則教訓**。
⇒ **抓字串的話這一則會被誤判成「已併入兩次」。**

🔴 **而這是【留痕的代價】**:今晚全陣一直在推「**留痕比改乾淨好**」——
不留痕的話,引用舊版的人會找不到東西去哪了。**兩件都對,而它們互相衝突。**

### 動作(不是決心)

- **數「有幾則」一律抓標題行**:`grep -c '^## '`,**不要抓內文字串**。
- **要拿字串當判準時**,先問「**這個字串在刪除線 / 作廢註記 / 合併留痕裡會不會出現?**」
- 一般化:🔴 **留痕是寫給人的第二層敘述;凡是機器要數的東西,計數規則要先把那一層剝掉。**

## 🟢 正面版本:**一格有判別力的測試,會在它作者沒預期的地方救人**〔這一則不是坑〕

> 今晚所有「恆綠」討論的**正面版本**,而正面版本只有這一個 —— 值得單獨留。

### 實例(2026-08-17 夜 T 線)

它把四綠機制改成「每種一個子目錄」時,**vitest 那組 5 格當場紅 4 格**。
**那不是機制壞掉 —— 是格子沒跟著改路徑。**

> **「如果那 4 格當時是【恆綠】而不是【當場紅】,我不會發現路徑改了。」**

🔴 **那 5 格是為了【別的事】寫的**,而它們在這一刻**替它抓了一次重構事故**。

### 收束

> **一格有判別力的測試,會在它作者沒預期的地方救人;而恆綠的那些,在同一刻什麼都不會做。**

⇒ 這句與今晚兩條合起來,才是守門的完整生命週期:
```
一裝就叫    ⇒ 會被【改鬆】
一裝就不叫  ⇒ 會被當冗餘【刪掉】
有判別力    ⇒ 會在【作者沒預期的地方】救人   ← 而這是留著它的真正理由
```

🔴 **而 T 線補的這一句,才把「為什麼要把這一刻寫下來」講完整**(照原字):
> **守門的成本【天天付】,收益【只在事故當天出現】,而【沒有紀錄的收益,在下一次精簡討論裡等於 0】。**

⇒ 今晚我們只講過它的反面(**沒寫理由的守門會被刪**)。
**這一句是正面**:**救過人的那一刻如果沒被記下來,它在帳上就等於從來沒有救過人。**

## 「格式未知」這一格,**一個標籤兩種意思** —— 而**補 0 會讓「沒量到」長得像「量到 0」**〔安靜〕

### 判別句

> 🔴 **我這個「其他 / 未知 / 不適用」的桶子裡,裝的是【同一種】情況嗎?**
> 不是 ⇒ **它會把兩件需要不同處置的事,壓成一個看起來已經處理過的數字。**
>
> 🔴 **而我有沒有在某一格填 `0`?** 填了 ⇒ **問「這個 0 是量到的,還是我沒量?」**

### 實例(2026-08-17 夜 T 線的被動收集器)

它寫 `scripts/four-greens-context-table.sh`,要把 `logs/four-greens/*/RUN-CONTEXT` 對上 `rc`,
輸出「並行數 × 紅綠」四格表。**第一版**把兩種完全不同的情況印成同一個「格式未知」:
```
· 舊欄位名（前兩版量具留下的 ⇒ 那些數字【已作廢】,本來就不該進表）
· 有 vitest 欄但沒有 build 欄（⇒ 那是【這一發沒跑完】,是另一件事）
```
**改法**:四種原因**分開具名、不補 0**:
```
帶 RUN-CONTEXT 的發次 12
四格:低×綠 1 / 低×紅 0 / 高×綠 0 / 高×紅 0
不進四格(分開具名):欄位名未知 7 / 僅 vitest 且 rc 未知 3 / 僅 vitest 0 / rc 未知 1
```
🔴 **它刻意不下結論,而且把判停條件印在【結果旁邊】,不是檔頭** ——
**因為讀結果的人不會回去讀檔頭。**

### 🔴 T 線自己的歸因,照原字(這一句比實例值錢)

> **我報這件不是自責:這個病【不是特定某個人的習慣,它是寫工具時的預設】。**
> **我今晚第 N 次犯它,而每一次我都剛寫完那條規則。**

⇒ **「寫下來」對抗不了「預設」。** 對抗預設的只有**當場的形狀檢查**:
**看到一個 `0`,問它是量到的還是沒量到;看到一個「其他」,問它裡面有幾種。**

### 📎 同一支工具裡的另一個決定,理由值得抄

它多印一行 `rc`,理由是**防一個沒人想到的耦合**:
> 沒有它,做統計的人得去 **parse `run-rc.sh` 印的那句中文**(`rc=0 ✅(…)`)
> ⇒ **統計工具綁死在那句措辭上,措辭一改、統計【靜默】失準。**
**守門 `格23-e`**:四個 `rc` **位置不得對調**(餵 `0/1/2/3` 分得出來)。
🔴 **判別句:我的下游在讀我的【資料】,還是在讀我的【文案】?** 讀文案 ⇒ 那是一條沒人看得到的耦合。

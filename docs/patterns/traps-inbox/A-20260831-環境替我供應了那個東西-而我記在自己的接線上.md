# 實例一 · 字型沒載到, 而它印出一張**比我要的還好看**的 PDF

## 事件(可重跑)
片 A 要答:**伺服器沒有中文字型時, 產出的 PDF 會不會變豆腐。**
探針:HTML 掛 `@font-face` 指到本機的 Noto Sans TC woff2, headless Chrome `page.pdf()`。

```
第一版寫法   src: url(file:///…/noto-sans-tc-…woff2)
實際發生     Chrome 【完全沒有載】那支字型 —— 零錯誤、零 console 警告、page.pdf() 正常回傳
我看到的     一張中文完全正常、排版漂亮的 A4 PDF
```
🔴 **它之所以正常, 是因為這台 macOS 自己有 PingFang TC。**
⇒ 那一發若當成成功, 我會回報「字型接上了、伺服器產檔可行」——**而字型從頭到尾沒有參與。**

抓到它的不是看畫面, 是**問 Chrome 你到底用了誰**:
```
CDP  CSS.getPlatformFontsForNode  ⇒ 回 familyName + glyphCount
第一版(file://)  ⇒ Songti TC:630 | Times:32     ← 那兩支都是 macOS 系統字, 我方的字型不在裡面
改走 http:// 後  ⇒ Noto Sans TC:630             ← 才是我以為一直在發生的事
```
數法(可重跑, 探針是丟棄式的, 在 scratchpad 不在 repo):
`node probe.mjs <scratchpad>/fontprobe/package <scratchpad>/fontprobe`
⇒ 四個世界各印一行 `=== 世界 X === PDF n bytes` + 三個節點各自用到的字型。**連跑兩發, 每一格逐字相同。**
負對照(現造):`src` 指向一支不存在的 `.woff2` ⇒ 它**必須**掉回系統字 —— 而它掉了(`404` + `Songti TC`)。
⇒ 尺會動。**而在加這道負對照之前, 我那把尺對「載到」與「沒載到」印同一張圖。**

## 🔴 判別句 —— **替代品的品質不低於正品時, 「看輸出好不好」零判別力**
```
PingFang TC 不是壞字型 —— 它是 macOS 內建的中文字型, 品質不低於 Noto Sans TC
⇒ 它畫出來的中文【不比我要的差】
⇒ 「輸出品質」這個訊號在【成功】與【徹底失敗】兩個世界都印「很好」
```
數法:四個世界都成功產出 PDF、都可以肉眼開(`probe-{full,tc2,none,neg}.pdf`),
而它們的 bytes 分別 192,190 / 144,544 / 507,002 / 211,586 ⇒ **沒有一個是 0 或錯誤**。
⇒ **「有沒有產出、產出多大」這兩個訊號在四個世界都不判別。**
🛑 「零判別力」這句我只證到**這三個訊號**(有無產出 / 檔案大小 / 肉眼好不好看);
   **我沒有窮舉所有可能的輸出訊號 —— 未數。**
**而人本能會去看輸出 —— 那正是它不會說話的地方。**

## 🔴🔴 根因比 `file://` 那個技術細節深一階
```
探針跑在   macOS      —— 有 PingFang TC / Songti TC / Helvetica / Times
                          (這四支不是我列的, 是 CDP 在四個世界裡【自己印出來】的 familyName)
目標跑在   Linux 容器 —— 🛑 **「什麼 CJK 字型都沒有」這句我【未量】**, 它正是片 A 要證而沒證成的那件事
```
⇒ **我的量測環境比目標環境【富有】。**
⇒ **一個比目標富有的環境, 結構上跑不出目標會發生的那種失敗** —— 不是我沒注意, 是它做不到。
📌 **判別句:「我在這裡跑過了」要先答一句 —— 【這裡有沒有目標沒有的東西, 而它剛好會接住這個錯?】**
答得出「有」⇒ 那一發不是驗證, 是**在一張安全網上表演掉下去**。

⚠️ 而這一格**至今沒有解掉**:這台機器沒有容器
(`command -v docker` / `colima` / `podman` / `lima` ⇒ 全部無;`docker info` ⇒ `rc=127`)
⇒ 片 A 的「豆腐」那一格**明寫未量**, 並寫出缺哪一道:
**【在一個沒裝任何 CJK 字型的 Linux 容器裡, 用同一份 HTML 產一張 PDF】。**
🛑 **沒有**拿官方文件那句「serverless 容器沒有 CJK 字型」去充當那一發量測。

# 實例二 · 一個**真的 0**, 而它的分母比宣稱的窄

## 事件
片 A/B 的 plan(`docs/plans/2026-08-31-statement-pdf-server-render-plan.md` §0)逐字寫:
```
🔴🔴 沒有任何字型檔    git ls-files | grep -ci '\.(ttf|otf|woff2?)$' ⇒ 0;@font-face 宣告 ⇒ 0
⇒ 今天的中文靠【看的人那台機器剛好有字型】。
```
**那個 `0` 是真的。** repo 裡確實零字型檔、確實零本地 `@font-face`。
🔴 **而下一行那個結論是假的。** 開檔量到:
```
apps/storefront/src/app/layout.tsx:159-164  全站 <head> 掛著
  <link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=…
        &family=Noto+Sans+TC:wght@400;500;600;700&…&display=swap" />
實抓那支 CSS ⇒ HTTP 200 · 241,420 bytes · 210 個 @font-face · 105 支 woff2 URL
find apps/storefront/src/app/account -name 'layout.tsx' ⇒ 零輸出(明細單吃的就是 root layout)
```
⇒ **客人今天有 Noto Sans TC, 是 Google CDN 給的。** 那個「缺口」不存在。

## 🔴 判別句 —— **那不是量錯, 是量對了一個比宣稱窄的東西**
```
那把尺問的是   「這個 repo 的檔案清單裡有沒有字型檔」   ← 它誠實地答了:沒有
被讀成的是     「這個網站有沒有字型」                   ← 而字型可以不住在 repo 裡
```
📌 **⇒ `git ls-files` 的分母是【版本控制的檔案】, 不是【執行時會載到的資源】。**
**兩者的差就是所有從 CDN / node_modules / build 產生器來的東西 —— 而那是一個很大的差。**

## 🔴🔴 而兩個實例是同一件事的兩個方向
```
實例一  我的世界比目標【多】了一個東西(PingFang)⇒ 我以為是我的接線在work
實例二  我的尺的世界比宣稱【少】了一條路(CDN)  ⇒ 我以為那個缺口存在
```
**⇒ 共同形狀:【我量到的邊界】與【我拿它去答的那個問題的邊界】不是同一個, 而兩邊各自都是真的。**
🛑 **⇒ 所以不會有任何東西紅。** 只有把「我量了什麼」與「我要答什麼」並排寫出來才看得到。
✅ **可機械執行的版本:每一個要當結論用的量測, 旁邊寫一行「這把尺的分母是什麼」。**
   寫不出來 ⇒ 那個值只能當線索, 不能當結論。

## 修法(不靠記得)
```
① 「我掛了一個資源上去」的驗證 ⇒ 不看輸出, 去問【誰真的被用到了】
   字型 ⇒ CDP CSS.getPlatformFontsForNode
   通則 ⇒ 找一個會印「用了誰」而不是「結果好不好」的介面
② 每一發探針都要有一個【指向不存在的東西】的負對照, 而它必須印出不同的值
③ 落筆寫「我在本機驗過了」之前, 先數一次:
   本機有而目標沒有的東西 —— 那張清單就是這一發的盲區, 要寫進報告
④ 每個當結論用的數字旁邊寫它的分母(見實例二)
```

## 實例六 · 逐字挑子集省了 12 倍, 而它的代價是同一族的
```
片 C2 只內嵌「這張紙用得到的」子集(20 支 / 1.22 MB, vs 全部 210 支 / 8.0 MB)。
🔴 而少嵌一支的後果 = 紙上一個豆腐字, 而程式不會叫 ——
   codex R1 的七條 must-fix 有三條是同一族(entity 被刪掉 / `src:local(),url()` 判成沒 url /
   小寫 `u+` 解不出來), 三條都會讓某一支該嵌的子集被判成「用不到」。
```
📌 **⇒ 一個省成本的優化, 把「全有」換成了「逐項判斷」** —— 每個判斷都是一個新的漏字機會,
   **而漏掉的那一格不會出現在任何計數裡**(它就是沒被算進去)。
✅ 所以那三條的測試是那一片的**承重件**, 不是附帶。

## 驗「我的東西併進去了沒」,不能用**我寫的標題**當尺 —— 併入這個動作本身會改標題〔母題成員〕

### 當天的事(2026-08-22 線 C,而它發生在我【正要刪掉唯一那份副本】的前一秒)

流程是對的:投稿 → 別人併進正本 → **我先驗它真的併進去了,才刪掉暫存區那份**。
而我用的尺是**我自己那五條的標題字面**:

```
這一欄是誰寫的      ⇒ 0
空有三種世界        ⇒ 0
這支東西有人呼叫嗎  ⇒ 0     🔴 三個 0
集合空掉有兩個原因  ⇒ 1
誤判一把好尺        ⇒ 1
```

**照這把尺,五條裡有三條沒進去 ⇒ 而我下一步就是刪掉唯一那份副本。**

換一把尺(用**內容裡的識別字**,不用標題):
```
空-A ⇒ 3   空-B ⇒ 6   空-C ⇒ 4   在誰的路徑上 ⇒ 1   中間人 ⇒ 3   fire-and-forget ⇒ 4
⇒ ✅ 內容全部都在。
```

### 🔴 成因:**併入是一個【會改寫措辭】的動作,而它改寫的正是我拿來當尺的東西**

```
收件的人做了三件都正確的事:
  ① 「併進既有那條、不新開節」   ⇒ 我的標題被吸收進別人的標題底下
  ② 目錄規矩「新條目不編號」     ⇒ 我的 ⑬–⑰ 編號被拿掉
  ③ 收斂重複的措辭               ⇒ 同義句被合併
⇒ 三件都是好的編輯行為,而它們**共同把作者的原句改掉了**。
🔴 而作者手上唯一的尺,就是那些原句。
```

### 判別句

```
「我拿來驗『它在不在』的那個字串,**會不會因為它【真的被收下了】而改變**?」
   會 ⇒ 🔴 那把尺在【成功】的世界裡也會回 0 ⇒ 它分不出成功與失敗。
```

**這一格的形狀是通用的**,不只投稿:
```
· 驗 PR 有沒有被合併  ⇒ 用 commit 訊息的字面?**squash 會改寫它。**
· 驗設定有沒有生效    ⇒ 用你寫的註解字面?**格式化工具會動它。**
· 驗翻譯有沒有上線    ⇒ 用你送的原句?**校稿會改它。**
🔴 共同形狀:**驗收用的特徵,正好是【被驗收的流程會加工的東西】。**
```

### 修法(動作,不是更小心)

```
1. 🔴 用**不會被改寫的識別字**當尺:
   · 技術識別字(函式名 / 欄位名 / 錯誤碼 / 代號)—— 編輯者不會動它們
   · 數字與逐字證據(那 4 個 0、那個 run id)
   · 而**標題、句子、你自己的措辭 = 最容易被改的那一層**,不要拿它當尺。

2. 🔴 **不可逆的動作(刪掉唯一副本)之前,要求尺【至少兩把、而且用不同層的特徵】。**
   本例:標題層說「沒進去」、識別字層說「都在」⇒ 兩把不一致本身就是停下來的訊號。
   ⚠️ 而如果只跑第一把 ⇒ 它會給一個**乾淨、明確、而且錯的** 0。

3. 交件時順手替下一個人省掉這一步:**投稿裡自己標「本條的識別字是 X」**
   ⇒ 收件者改標題無所謂,而作者驗收有一個不會被改的錨。
```

### ⚠️ 而這條與既有那條「更正落在會被丟掉的那份」是**反方向**

```
那一條:我改對了,而改在會被丟掉的載體上          ⇒ 修法是「改在會被留下的那份」
本 條:東西已經在會被留下的那份裡了,而我的尺看不到 ⇒ 修法是「換一把不會被改寫的尺」
🔴 兩條都會讓人得到「它不在」這個結論,而處置相反。
   判別法:**先問「它到底在不在」,而不是先問「我該改哪一份」。**
```

### 📌 順帶:這件事在 git 上零留痕

```
那份暫存檔一直是未追蹤(`??`)⇒ 我刪掉它,git status 一個字都不會說。

```

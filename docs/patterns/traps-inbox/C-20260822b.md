## 驗「我的東西併進去了沒」,不能用**我寫的標題**當尺 —— 併入這個動作本身會改標題〔母題成員〕

### 當天的事(2026-08-22 線 C,而它發生在我【正要刪掉唯一那份副本】的前一秒)

流程是對的:投稿 → 別人併進正本 → **我先驗它真的併進去了,才刪掉暫存區那份**。
而我用的尺是**我自己那五條的標題字面**:

```
這一欄是誰寫的      ⇒ 0
空有三種世界        ⇒ 0
這支東西有人呼叫嗎  ⇒ 0     🔴 三個 0
集合空掉有兩個原因  ⇒ 1
誤判一把好尺        ⇒ 1
```

**照這把尺,五條裡有三條沒進去 ⇒ 而我下一步就是刪掉唯一那份副本。**

換一把尺(用**內容裡的識別字**,不用標題):
```
空-A ⇒ 3   空-B ⇒ 6   空-C ⇒ 4   在誰的路徑上 ⇒ 1   中間人 ⇒ 3   fire-and-forget ⇒ 4
⇒ ✅ 內容全部都在。
```

### 🔴 成因:**併入是一個【會改寫措辭】的動作,而它改寫的正是我拿來當尺的東西**

```
收件的人做了三件都正確的事:
  ① 「併進既有那條、不新開節」   ⇒ 我的標題被吸收進別人的標題底下
  ② 目錄規矩「新條目不編號」     ⇒ 我的 ⑬–⑰ 編號被拿掉
  ③ 收斂重複的措辭               ⇒ 同義句被合併
⇒ 三件都是好的編輯行為,而它們**共同把作者的原句改掉了**。
🔴 而作者手上唯一的尺,就是那些原句。
```

### 判別句

```
「我拿來驗『它在不在』的那個字串,**會不會因為它【真的被收下了】而改變**?」
   會 ⇒ 🔴 那把尺在【成功】的世界裡也會回 0 ⇒ 它分不出成功與失敗。
```

**這一格的形狀是通用的**,不只投稿:
```
· 驗 PR 有沒有被合併  ⇒ 用 commit 訊息的字面?**squash 會改寫它。**
· 驗設定有沒有生效    ⇒ 用你寫的註解字面?**格式化工具會動它。**
· 驗翻譯有沒有上線    ⇒ 用你送的原句?**校稿會改它。**
🔴 共同形狀:**驗收用的特徵,正好是【被驗收的流程會加工的東西】。**
```

### 修法(動作,不是更小心)

```
1. 🔴 用**不會被改寫的識別字**當尺:
   · 技術識別字(函式名 / 欄位名 / 錯誤碼 / 代號)—— 編輯者不會動它們
   · 數字與逐字證據(那 4 個 0、那個 run id)
   · 而**標題、句子、你自己的措辭 = 最容易被改的那一層**,不要拿它當尺。

2. 🔴 **不可逆的動作(刪掉唯一副本)之前,要求尺【至少兩把、而且用不同層的特徵】。**
   本例:標題層說「沒進去」、識別字層說「都在」⇒ 兩把不一致本身就是停下來的訊號。
   ⚠️ 而如果只跑第一把 ⇒ 它會給一個**乾淨、明確、而且錯的** 0。

3. 交件時順手替下一個人省掉這一步:**投稿裡自己標「本條的識別字是 X」**
   ⇒ 收件者改標題無所謂,而作者驗收有一個不會被改的錨。
```

### 🔴 與正本「引用一個【段落名】時:我是**複製**的,還是**重述**的?」的分工(鄰居工具第 2 名 0.3550;我開檔讀過才判)

**判定:近親,不同族。而那一條【自己的框架裡有一個空格,本條正好是它】。**

C2 那條逐字自己畫的分界:
> 「那兩條講【行號型】指標:它會**安靜地指到另一段真文字**
>  本條講【段落名型】:它會**大聲地零命中** —— 而今天壞掉的那幾個
>  **不是飄走的,是【一開始就沒對過】。**」

```
                       壞的時候長什麼樣   壞的原因            誰做錯了
行號型(既有兩條)      安靜地指到別段     檔案自己長高了       沒有人
段落名型 · 重述(C2)   大聲地零命中       寫的人憑印象重述     🔴 寫引用的人
段落名型 · 被改寫(本條)大聲地零命中       🔴 收的人【正確地】改寫了它  沒有人
```

🔴 **兩者在畫面上完全一樣(零命中),而成因相反:**
```
C2   :我的字串【從來沒有對過】—— 它出生就是錯的
本條 :我的字串【曾經是對的】,而它因為【那件事成功了】才不再對
```
⇒ ⇒ **處置也相反**:
```
C2   ⇒ 修法是「引用要複製、不要重述」 —— 動作在【寫的時候】
本條 ⇒ 修法是「換一把不會被改寫的尺」 —— 動作在【驗的時候】,而引用本身沒有錯
🔴 拿 C2 的修法來治本條會失敗:**我的標題就是複製的,一個字都沒改** —— 是對面被改了。
```

### 🔴🔴 而最漂亮的一格:**C2 自己用的那個方法,正好是分開這兩族的尺**

C2 逐字:
> 「而我沒有停在『指不到』—— 我去問它們【有沒有曾經對過】:
>  `git log -S'<那三句>' --oneline -- <檔>` ⇒ 三句皆 **0**
>  ⇒ **那三句從來沒有進過這支檔。**」

```
⇒ 拿同一發打本條的案例,會得到【非零】——
   因為我那五條的標題真的進去過(在收件者改寫它之前的那個版本裡)。
🔴 ⇒ **`git log -S` 回 0 = C2 那一族(從來沒對過)**
   **`git log -S` 回非零而現在 grep 是 0 = 本條這一族(對過,然後被改寫)**
⇒ **兩族用同一發指令就分得開,而 C2 已經把那發指令寫好了。**
```
📌 **收件時建議**:在 C2 那條的「先講與既有兩條的分工」那個 code block 裡**加第三列**,
   並把上面那條 `git log -S` 的判別法標成**兩族共用的分流器**。
   ⇒ **不必新開一節** —— 本條可以整個掛在 C2 底下當第三種壞法。**那由收件者決定,我不搶。**

### ⚠️ 而這條與既有那條「更正落在會被丟掉的那份」是**反方向**

```
那一條:我改對了,而改在會被丟掉的載體上          ⇒ 修法是「改在會被留下的那份」
本 條:東西已經在會被留下的那份裡了,而我的尺看不到 ⇒ 修法是「換一把不會被改寫的尺」
🔴 兩條都會讓人得到「它不在」這個結論,而處置相反。
   判別法:**先問「它到底在不在」,而不是先問「我該改哪一份」。**
```

### 📌 順帶:這件事在 git 上零留痕

```
那份暫存檔一直是未追蹤(`??`)⇒ 我刪掉它,git status 一個字都不會說。
⇒ 🔴 **一個「為了守規矩而做的動作」在版本控制上不存在。**
⇒ 而它的風險是不對稱的:刪對了沒有人知道,刪錯了也沒有人知道 —— 直到有人要找那五條。
```

# 閘的單位**沒有錯**,而它與決策要的單位不同 —— 而輸出只帶了前者

> 線【DB】`-db` 2026-09-06 · ⟦db-FITMENTSYNCORPHAN⟧。
> 🔵 **這是 `I-20260817b:121`「尺會動、方向也對,而單位是錯的」的【兄弟】,不是重複** ——
> 差別在下面「為什麼不是那一條」那節,而那個差別正是本條要記的東西。

## 現場

顧客站車款同步的守門:
```
rate = orphan 列 / view 總列        (sync_storefront_fitments.py:262)
> 5% 且 orphan ≥ 10  ⇒ 整 run abort
```
2026-09-06 它擋下來,告警印 **10.0%**,而 Sean 收到的訊息就是那個數。

實際跨兩顆庫算出來的差集:
```
報價單 dbk 相異料號  1,819
顧客站 dbk 相異料號  1,933
報價單有而顧客站沒有    18 件  = 1.0%
```
一件商品有很多列車型配適(`CV03` 一件 **37 列**,那 18 件平均每件約 **171 列**)。

## 病灶

🔴 **「10.0% 的東西對不上」與「1.0% 的料號沒上架」是同一個世界的兩個講法。**
而告警只講了前者,於是:
- **讀的人照 10% 去估嚴重度**
- **要做的動作(上架幾件)對應的是 1%**

⇒ 兩個數字都對,而**它們不是同一個問題的答案**。

## 🛑 而門檻本身【沒有訂錯】—— 這是本條的重點

用**列**當分母對這道閘主要要擋的東西(來源被截斷、整批對不上)是**正確的**:
來源少了一半 ⇒ 列會掉一半,而料號數可能還看起來正常。

⇒ 📌 **不是「它量錯了」,是「它量的那個數不足以決定下一步」。**
✅ 修法**不是換分母**,是**同時印兩個**:相異鍵數 / 相異鍵總數(這裡是 `18 / 1,819`)。

## 為什麼不是 `I-20260817b:121`(單位是錯的)

那一條的判別句是「**我這把尺回的那個數,單位是什麼?**」—— 它處理的是**尺自己搞錯了單位**。
本條的尺**知道自己在數列,而且該數列**。錯位發生在**尺與讀者之間**:

> 🎯 **一個對它自己的用途完全正確的數字,對接下來要做的那個決定是錯的單位。**

⇒ 判別句因此不同:

> **「這個數字要餵給誰做什麼決定?那個決定的單位跟它一樣嗎?」**

## 這一則答不出什麼

  ⇒ 那要翻 `product_fitments_effective_sync_log`,**而我沒翻**。這是已知缺口,不是「查過是 0」。
- 修法(同時印兩個數)在**報價單 repo**,不是本 repo ⇒ **本線改不到**,只能記。
- 「差一個量級才算問題」這個界**是我事後看到 10% vs 1% 才畫的** —— 它不是一個量出來的門檻。

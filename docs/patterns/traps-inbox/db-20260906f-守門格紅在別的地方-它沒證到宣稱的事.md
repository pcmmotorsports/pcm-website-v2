## 守門格紅的【位置】與它宣稱守的那道閘不同 —— 那一格從來沒證到它宣稱的事

> 線【DB】`-db` 2026-09-06。實錘 = opus 對 `scripts/apply-paste-board.sh` 的 R4 突變測試。

### 發生了什麼

opus 跑 **16 發突變**:**存活 8 發**,而 selftest 照樣印 **63/63 全綠**。
而存活的那幾發打的,**正是我為前三輪審查的指名 bug 寫的那五道守門**
(拒收覆寫 / host 抽取比對 / 只能一個編號 / 編號只認數字 / apply 後 SHA 回核)。

🔴 **機制不是「我忘了寫格」** —— 每一道都有格。是那些格**紅在別的地方**:

| 格 | 它宣稱守的 | 實際擋住它的 |
|---|---|---|
| `⑭` / `⑩d` | db-url 的 host 檢查 | **前置①**(貼板檔命中 0 支)—— 那兩格**沒有帶 `APB_PASTE_ROOT`** |
| `⑩c` | 正式模式拒收覆寫 | **「只能在主樹跑」** —— 而那取決於跑 selftest 時的 **cwd** |

⇒ 🛑 **`⑭`/`⑩d` 從來沒有走到自己宣稱的那道閘**,而 `rc≠0` 讓它們一直是綠的。
⇒ 🛑 **`⑩c` 的綠是 cwd 決定的,不是碼決定的。**

### 🔴 而格型本身也有病

`ck "…" "$([ $? -ne 0 ] && echo ne0 || echo 0)" "ne0"` 這一型
在 opus 的**四次突變裡都被別的錯誤救活**。

📌 **一個「該紅」的世界有很多種紅法,而 `rc` 只告訴你「紅了」,不告訴你「紅在哪一句」。**

🎯 ⇒ **「它紅了」與「那道閘守到了」是兩個宣稱,而 `rc` 只證得了第一個。**

### 判別式(兩層)

**寫的時候**:每一個「該紅」的格,除了 `rc` 之外**再配一條【那道閘的專屬字串】的 grep**。
訊息格與效果格(`in_db` / `led_rows` / 呼叫次數)才有判別力。

**寫完之後 —— 這一層更重要**:
> **把那一格宣稱守的那道閘拔掉,看它會不會紅。不會紅 ⇒ 那一格不是在守它。**

🔵 而我前三輪**每一輪都報過「突變 N 發各打紅不同的格」** ——
🛑 **那句話每一輪都是真的,而它每一輪都只涵蓋我想到的那幾條路。**
⇒ 📌 **自己挑突變點,等於自己劃定自己的分母。**

### 這一條與已記的差在哪(查重跑過)

分母 2,934,最高 **0.282**,無同族:
· 正本 `:14632`「exit code 是被壓成一個數字的東西,而壓縮會把兩種世界壓成同一個值」(0.250)
  —— **最近的一條,而它講的是 rc 本身的資訊量**;本條講的是**那一格根本沒走到它要測的地方**。
· `memory/feedback_the-message-i-wrote-to-tell-two-reds-apart-was-never-read`(0.247)
  —— 那條是**訊息沒被讀**;本條是**閘沒被走到**。
· 正本 `:30890`「行為閘六天前就做好了,而出事那支檔不在它的候選清單裡」(0.282)
  —— 🔵 **同族的另一個粒度**:那條講**受測對象**不在分母裡,本條講**執行路徑**沒到那道閘。
⇒ 🎯 新的那一軸:**紅的位置與宣稱的位置不同,而 `rc` 把它們印成同一個結果。**

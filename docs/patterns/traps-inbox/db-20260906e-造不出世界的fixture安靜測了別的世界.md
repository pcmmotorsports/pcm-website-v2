## 造不出自己那個世界的 fixture,不會大聲失敗 —— 它安靜地測了**另一個**世界,而帳算在**三格之後**

> 線【DB】`-db` 2026-09-06。實錘 = `scripts/apply-paste-board.sh --selftest` 的第 ⑮ 格。

### 發生了什麼

我要一格證明「**帳本存在而讀不動 ⇒ 工具要停**」。造那個世界的方法是 `chmod 000`:

```sh
chmod 000 "$T/repo/supabase/APPLIED.tsv"
run 09          # 期望:被前置⑥ 擋下
chmod 644 "$T/repo/supabase/APPLIED.tsv"
```

🔬 **而 `chmod 000` 在這台機器上擋不住讀取**(當場量,uid 502):

```
printf 'a\n' > t; chmod 000 t; awk 'END{}' t   ⇒ rc=0
```

⇒ 那一發**沒有被拒**。它走完整條路,**真的把那支 migration 貼進了拋棄式資料庫**。

🔵 **而那一格自己是綠的** —— 因為我斷言的是 `rc≠0`,而它**確實** `rc≠0`(它在**後面別的地方**失敗了)。

### 🔴 損害出現在三格之後

另一格紅在:

```
🔴 前置⑦:**平台帳本上已經有 20990909000000**(count=1)⇒ 它貼過了 ⇒ 拒絕重貼。
```

**那一格什麼都沒做錯** —— 它只是**繼承了前一格留下的世界**。
而我第一時間是去讀它,找它哪裡壞了。

### 坑的形狀

**fixture 造世界失敗時,沒有任何訊號。**
它不會說「我造不出那個世界」;它會**安靜地讓後面的斷言去測一個不是我要測的世界**,
而**損害往後遞延** ⇒ 讀起來像後面那一格壞了。

📌 🎯 **一個 fixture 有兩件事會失敗:它造的世界對不對、以及它造出來了沒有。
而我只驗了第一件 —— 第二件連問都沒問。**

🛑 而它比「fixture 內容寫錯」貴一級:內容寫錯至少**錯在原地**;
造世界失敗**把帳算到別人頭上**,而那個「別人」看起來完全合理。

### 判別式

> **一個 fixture 的【前置條件】要自己驗一次,就地。**

`chmod` 之後就地 read 一次 · 起服務之後就地 ping 一次 · 塞資料之後就地查一次。
🔴 **造不出來就大聲跳過**,並在輸出逐字寫「**這條路未覆蓋**」——
因為 **「未覆蓋」與「通過」在 PASS 數上是同一個數字。**

✅ 我最後的處理:**那一格拿掉了,而理由留在檔裡**,並明寫
「『帳本存在而讀不動』這條路**本 selftest 未覆蓋**,不是它通過了」。

# 🔴 機制:**行號是一個【寫下的瞬間正確】的識別字**

> ## **它不會壞掉、不會報錯、不會變成空的 ——**
> ## **它會【指到另一個真實存在的東西】,而那個東西看起來也很合理。**

```
一個壞掉的 ID  ⇒ 查無 ⇒ **會停下來**
一個漂掉的行號 ⇒ 指到別人 ⇒ **不會停** —— 板子那一行也是一列正常的工作
⇒ ⇒ 📌 所以它與「查無」不是同一種錯：**查無有訊號，漂掉沒有。**
```

🔴 **而它在四個載體上同時被當識別字用,四個都沒有防護**:
```
① commit body（「板子 :215」）        ② 派工工具的輸出
③ 窗與窗之間的訊息（我寫的每一則）    ④ 我自己前後兩次量測的對照
```

## ⚠️ 而板子**自己早就寫過同一個病,只是防在別的地方**

那一列的鄰居(講品牌牆那列)逐字寫著:
> 「**字面錨,不寫行號** —— 量到原寫的 `:52-55` 已漂成 `:50-55`,**而行號漂掉時板子不會有任何訊號**」

📌 **⇒ 它防的是【code 的行號】,沒有防【板子自己的行號】。**
🔴 **⇒ 一條正確的規矩,寫在它自己的射程之外。**

# ✅ 判別動作

> ## **我要把一列的座標寫進【任何會活過今天的東西】之前 ——**
> ## **附上它的【文字錨】,不要只附行號。**

```
✅ 最便宜的形狀（不必改任何工具）：
   ❌ 「板子 :215」
   ✅ 「板子那一列（錨:『新品牌上架後客人在品牌區看不到它』）」
   ⇒ 一行 grep 就找得回來，而且【找不到時會查無】——有訊號
🔴 而板上已有錨的慣例（`⟦b4-XXXX⟧` 這種標記）⇒ **有標記的列就引標記，不要引行號**
   ⇒ 而那一列【沒有標記】—— 這正是它會出事的原因之一
```

## ⚠️ 而「照著板子挑一件」這個動作本身要多一步
```
挑到一列 ⇒ 🔴 **先拿它的標題去 `git log --grep` / `log -S` 掃一發**
⇒ 那一步 30 秒，而它今天可以省掉一整片的重做
   （數法：`git log --oneline -S '<標題裡最特別的那幾個字>' -- <相關目錄>`）
```

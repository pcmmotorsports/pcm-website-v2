# C2-20260829 · 一個在關機中途取的讀數,與「它還在跑」印同一個數字

> 投件窗 線C(`-b4`)· 2026-08-29 深夜 · **-48 指定投件**
> 🔴 **本條與今晚其餘量具坑【方向相反】** —— 前面全是「該紅而印綠」,
> **這一條是【該綠而印紅】。**

---

## 我做了什麼

拋棄式 Postgres 收攤,照既有紀律「不看 `rc`,看埠」:

```
pg_ctl -D /tmp/rw1b-f8/pgdata stop -m fast   ⇒ rc=0
lsof -nP -iTCP:54893 -sTCP:LISTEN | wc -l    ⇒ 0     ← 我指定的那個埠,乾淨
lsof -nP -iTCP:54331 -sTCP:LISTEN | wc -l    ⇒ 3     ← 🔴 預設埠,而我起跑前量過它是 0
```

⇒ 我當下的結論是:**「有一座我起的 cluster 殘留在 54331」**,而我已經在寫回報了。

**再量一次 ⇒ 0。**

---

## 那個 3 是什麼

**關機延遲。** `pg_ctl stop -m fast` 回 `rc=0` 表示**它送出了關機指令且 postmaster 收下了**,
不表示**每一條連線的 socket 都已經從核心的 listen 表上消失**。

📌 **⇒ 而在那個時間窗裡,`lsof` 印的數字,與「它根本沒關掉」印的數字【完全相同】。**

---

## 🔴 為什麼這一條的後果與其他量具坑不同

```
今晚其餘的坑        該紅而印綠 ⇒ 後果 = 漏掉一個真的問題
🔴 這一條           該綠而印紅 ⇒ 後果 = 【誤報一個不存在的問題】
```

而誤報的下場**不是「多花點時間」**:

- 下一個人去追一個幽靈;或者更糟 ——
- 🔴 **有人去 `kill` 一個他以為是殘留的東西,而那是別窗正在用的。**
  (八窗共用一台機器,而埠號上面沒有寫誰的名字。)

⇒ 📌 **一個假紅在單人環境裡只是浪費;在多窗環境裡它會【產生一個真的事故】。**

---

## ✅ 判別動作(機械的,不靠判斷)

```
停完 ⇒ 隔一下 ⇒ 再量一次 ⇒ 【兩次都 0】才算數
```

🔴 **而這一條與鐵則 11 的「連跑兩發」【不是同一件事】,不要混:**

| | 連跑兩發(鐵則 11) | 本條 |
|---|---|---|
| 在比什麼 | **比數字**(檔數/測項/紅格數是否相同) | **等狀態穩定** |
| 兩發相同代表 | 輸入清單一致(重現性) | 它真的停了 |
| 兩發**不同**代表 | 🔴 有東西在飄 ⇒ 查 | ✅ **正常** ⇒ 就是在等這個 |

📌 **⇒ 差別在:那一條「不同 = 壞掉」,這一條「不同 = 它正在收斂」。**
⇒ **同樣是量兩次,而讀法相反。**

---

## ⚠️ 這一條的射程

- 只在 **macOS `lsof`** 上量到過(一次)。**沒有量過**要等多久才穩定 ⇒ 本條**不寫秒數**。
  ⇒ 寫死一個秒數會產生一個新的假綠:**「我等了 N 秒所以它一定停了」。**
  ✅ 判準是**讀數本身**(連兩次 0),不是時間。
- 同族**推測未驗**:任何「送出停止指令 ⇒ 立刻量狀態」的形狀都可能有這個窗
  (docker stop / kill -TERM / dev server 收攤)。⇒ **標未確認,沒有量過。**

---

## 📌 一句話帶走

> **`rc=0` 說的是「指令被收下了」,不是「事情做完了」。**
> **而在那兩件事中間的那段時間,量具印的東西與「它從來沒開始做」一模一樣。**

# 一份驗收查詢,自己毀掉了自己要收集的證據

> 線【出貨】`-1e` · 2026-08-31 · 拿它打**正式庫**(唯讀)時當場炸掉

## 現場

一支 SECDEF 的 RPC apply 上去之後,SQL Editor 只回「Success. No rows returned」。
⇒ 那只證了**它跑完沒報錯**,不證明形狀對、權限對。
⇒ 我寫了一份驗收查詢:六格 catalog 檢查 + 一格「**真的呼叫它**看回傳形狀」,
**全部放在同一個 `UNION ALL` 裡一次跑完。**

**我用唯讀帳號打它:**
```
ERROR:  permission denied for function get_order_created_gap_counts
```
⇒ 那支函式是 SECDEF 且只授一個角色 ⇒ 沒有 EXECUTE 的人跑它就報錯
⇒ **而一個報錯會中止整個查詢** ⇒ **前面六格一列都看不到。**

🔴 **同一份裡還有一格更明顯的**:負對照那格是**故意**要它報錯的(NULL 參數必須炸)
⇒ 放在同一個 UNION 裡 = **保證誰都看不到前面的結果**。

## 📌 母題

```
一份【驗收查詢】自己也是一把尺 —— 而尺自己沒有被量過。
```

## 🔴 而量它的方法有一格容易漏

```
✅ 拿它去打一個【你知道答案】的世界(我打了三個:正式庫現況 / 函式不存在 / 函式在而做壞了)
🔴 而**還要包含一個【你不是 owner】的世界** ——
   因為「權限不足時會怎樣」正是這種驗收最常見的執行環境:
   寫的人是 owner, 而跑的人可能不是。
```
⇒ 📌 **我是用唯讀帳號跑才撞到的。用 owner 跑一輩子都不會發現。**

## 🔵 而同一輪它還抓到第二個【我的尺錯】

```
我寫 `'search_path=' = ANY(proconfig)` 判「有沒有釘空 search_path」
⇒ 正式庫實際存的是 `search_path=""`(**帶引號的空字串**)
⇒ 那一格印 **FAIL**, 而那支函式是**對的**
```
🛑 **⇒ 若我直接把這份東西交出去, 讀的人會看到一個 FAIL, 然後去修一個沒有壞的東西。**
📌 **⇒ 一把驗收尺的假紅, 比它的假綠更貴** —— 假綠只是少一道保護,
**假紅會動員一個人去改一個正確的東西。**

## ✅ 改法

```
· 純 catalog 讀取那幾格 ⇒ 留在第一段(任何角色都跑得動)
· 「真的呼叫它」那格   ⇒ 分出去第二步(owner 自己跑)
· 故意要炸的負對照     ⇒ 分出去第三步, 並寫明「它報錯【就是】PASS」
```

## ⚠️ 射程

```
· 這份驗收證的是【存在 / SECDEF / 權限】, **不證明行為對** —— 行為層的證據在拋棄式 PG。
· 而它自己也只被三個世界量過。第四個世界(例如 overload 同時存在)**未演**。
```

# C9-20260830 · 數字**轉對了**、而**射程轉丟了** —— 重量會得到一模一樣的數字

> 投件窗 線C(`-b4`)· 2026-08-30 07:0x · **我自己犯的,`-b9` 追問才現形**
> 🔴 **這是一族的第三個成員,不是新母題**:
> ① 常載 `~/.claude/rules/00-work-rules.md` §6-b 第 2 條 —— **數字離開現場時,範圍要跟著走**
> ② 正本 `guard-and-instrument-traps.md:8796` —— **聚合數字被搬走而【組成】沒跟著搬**(`8 = 3+5`)
> 🔴 ③ **本條:【那把尺量到的是什麼】沒跟著搬。**

---

# 現場

我轉述另一個窗的量測。**三個數我一個都沒轉錯**:`114` / `11` / `26`。

```
它量的是：「commit body 裡【有沒有寫出】比對過拍板原句」
我寫出去的是：「那一格【真的沒做】」
```
而它自己標了兩格限制,**我一格都沒帶**:
```
· 它讀的是 commit body,**不是審查過程**
· 分母只含「body 有引拍板」的那些 ⇒ 做了而 body 沒提的,完全不在分母裡
```

## ⇒ 掉的不是值,是**射程**

> ### **轉述契約要求「值與授權句貼原文」—— 而這一次值全對,掉的是【那把尺量到的是什麼】。**

📌 **「有沒有寫」與「有沒有做」之間的距離,就是我弄丟的東西。**

---

# 🔴🔴 而它為什麼比**轉錯數字**危險 —— 這一格是本條唯一新的東西

```
數字轉錯了  ⇒ 下一個人重量 ⇒ **數字對不上** ⇒ 它會被抓到
🔴 射程轉丟了 ⇒ 下一個人重量 ⇒ **會得到一模一樣的數字** ⇒ 而結論仍然是錯的
```

> ## **⇒ 這種錯是【防驗證】的:走一遍查證流程,只會確認它。**

📌 **而這正是它與上面那兩條的分界**:
```
② 那一條(8 = 3+5)⇒ 重新檢查【發現了】矛盾 ⇒ 驗證會救你
🔴 本條           ⇒ 重新檢查【複現了】那個數 ⇒ 驗證會背書那個錯結論
```
🔴 **⇒ 所以本條不能靠「叫下一個人重量」來防** —— 重量是它的**共犯**,不是它的解藥。

---

# ✅ 判別動作(在轉述一個數之前,問一句)

> ## **這把尺量到的是「有沒有【寫】」,還是「有沒有【做】」?**
> ## **而那個區別,有沒有跟著這個數字一起走?**

```
✅ 而最便宜的形狀:把原作者標的限制【整段貼過去】,不要只貼結論
   —— 我這次的錯不是「沒想到」,是我**看過那兩格限制,而轉述時把它們留在原地**
🔴 而它有一個外觀上的成因:限制那幾行讀起來像【作者在自我克制】,
   看起來不是「結論的一部分」 ⇒ 轉述時最先被裁掉的就是它
   📎 而那正是本 inbox `C6` 記的那件事的另一面:
      C6 講「承重的話住錯地方沒人讀到」;本條講「承重的話讀到了,而轉述時被丟掉」
```

# ⚠️ 而抓到它的方式值得記(不是我自己發現的)

`-b9` 沒有重跑那三個數,它問了兩句:
```
「那 11 是怎麼判的?」
「那顆 commit 你是開檔逐輪讀的,還是掃 findings 標題?」
```
⇒ **兩句都不是問數字,是問【那個數怎麼來的】** ⇒ 我當場答不出來,因為我沒驗。
📌 **⇒ 對一個轉述的有效追問,問的不是「這個數對不對」,是「你怎麼知道的」。**
🔴 **而前者我答得出來(數字我抄對了),後者我答不出來。**

```

   (本條講的是【轉述】那一段,不是那個量測)
❌ 沒證:這一族有多常發生 —— n=1(我這次),而 ①② 兩條各自有自己的實例
```

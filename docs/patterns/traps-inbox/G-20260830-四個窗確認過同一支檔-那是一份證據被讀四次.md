## 發生什麼

板上那一列的關鍵事實欄寫著:**線C `-95` 交、`-c8` 開檔複驗成立**;
往下讀還有:**`-b4` 逐字交、`-b9` 開檔全部複現才落**。
⇒ 讀起來是**四個窗、獨立確認過**。而主視窗派我做之前問了一句:**那兩個來源獨立嗎?**

```
線C -95 交 → -c8 開檔複驗 → -b9 開檔複現 → 線G 再開一次
🔴 四個人，讀的是【同一支檔】
```

📌 **⇒ 那是一份證據被讀了四次, 不是四份證據。**

---

## 🔴 而重點不是「他們偷懶」—— 他們每一個都做對了

那一題的宣稱**就是關於那支檔**(RPC 裡有沒有查價)⇒ **開檔讀它是唯一正確的方法**。
四個人各自獨立地做了對的事。

🛑 **問題在【四票】這個形狀本身**:
> 四次確認**共用同一個可能出錯的東西** —— 而那個東西**不在那支檔裡**:
> **那支檔是不是【正式庫現在正在跑的那一版】。**

⇒ 而那一格,**四個人沒有一個查過**。當場量:
```
grep -c '^20260829140000' supabase/APPLIED.tsv ⇒ 0   ← 板上引行號的那一版【未 apply】
grep -c '^20260824020000' supabase/APPLIED.tsv ⇒ 1   ← 正對照，正式庫跑的是它
負對照 ^zzz99999999                            ⇒ 0
```
✅ **這一次結論沒變** —— 兩版的缺口相同(逐格核過)。
🛑 **而下一次它會變, 而那時沒有東西會提醒。**

---

## 🔴 為什麼「四票」特別危險

**票數會被當成信心。** 一列寫著「四個窗確認過」的板子條目,
下一個接手的人**不會再開檔**——而那正是他唯一可能撞到那個共用前提的動作。

📌 **⇒ 複核次數提高的是【那一次讀取的可靠度】, 不是【那個前提的可靠度】。**
而共用前提**在每一次複核裡都被同樣地假設掉了**,所以**複核越多次, 它越隱形**。

---

## ✅ 可執行的自檢

```
🔴 觸發時機：你要引用一個「N 個人都確認過」的結論，或你正要成為第 N+1 個

✅ 那一刻要問的【不是】「他們查得夠不夠仔細」，而是：
   「這 N 次確認，有沒有共用一個【沒有人查過的東西】？」
   ⇒ 而它通常長這樣：
       · 他們讀的是同一支檔    ⇒ 那支檔是不是現在生效的那一版？
       · 他們跑的是同一支腳本  ⇒ 那支腳本的分母對不對？
       · 他們引的是同一份摘要  ⇒ 摘要與正本有沒有漂？

✅ 而查法要【離開那個共用物】：
   讀檔的 ⇒ 去查 APPLIED.tsv / 部署狀態 / 生效設定（不是再讀那支檔一次）
   跑腳本的 ⇒ 餵它一個你確信會紅的輸入（不是再跑一次）
```

📌 **⇒ 一句話**:**獨立的不是【人】, 是【那條通往結論的路】。**
四個人走同一條路 = 一條路走了四次。

---

## ⚠️ 而本條自己的射程

- 我**沒有**證明那四個窗真的都只讀了那支檔 —— 我讀的是**板上那一列的字面**與 commit 訊息。
  **他們可能各自還做了別的, 而沒有寫下來。**⇒ 本條講的是**留下來的證據的形狀**,
  不是那四個人實際做了什麼。
- 而我補的那一格(`APPLIED.tsv`)**也只是離開共用物一步** —— 它答的是「repo 說哪一版 apply 了」,
  **不是「正式庫裡那支函式的實際定義」**。要答後者得連正式庫,而那不在施工窗的射程裡。
  🔴 **⇒ 所以本條不能被讀成「現在查清楚了」** —— 它只是把共用前提**往外推了一層**。

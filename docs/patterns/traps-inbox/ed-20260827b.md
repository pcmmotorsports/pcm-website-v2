## ed-B1 拋棄式世界是從【工作樹】建的 ⇒ 你正在改的那支東西已經在裡面了

**當班實錘**:要驗「新品區有沒有排掉維修零件」,起 `scripts/storefront-probe/up.sh` 量兩個世界。拿到的是:
```
修【前】 total 0 · 維修零件 0
修【後】 total 0 · 維修零件 0
```
「修後 0 件維修零件」**看起來就是我要的答案**。我差一點就收工。

**真相**:`up.sh` 把 `supabase/migrations/` 底下**所有** migration 都套進去 —— 包含我那支**還沒 commit** 的新檔。
```
數法(不是我讀出來的, 是它自己那一行):
  scripts/storefront-probe/up.sh:140   for f in $REPO/supabase/migrations/*.sql; do
  🔴 是【glob 打在工作樹上】—— 不是讀 git、不是讀 index、沒有任何 committed 與否的判斷
  那個 glob 現在對到幾支:ls supabase/migrations/*.sql | wc -l   ⇒ 221(2026-08-27 當場數)
```
⇒ **鑽機一起來,函式已經是【修後版】** ⇒ 我以為的「修前」,從第一發起就是修後。

**當場分得開的那一發**(在那個世界裡問「你是修前還是修後」):
```sql
SELECT count(*) FROM pg_proc p JOIN pg_namespace n ON n.oid = p.pronamespace,
       LATERAL regexp_matches(p.prosrc, '<我這片新加的識別字>', 'g')
WHERE n.nspname = 'public' AND p.proname = '<那支函式>';
-- 回 3 ⇒ 🔴 這個世界【已經是修後】。回 0 ⇒ 才是修前。
```

🔴 **而這不是操作失誤,是那個世界的建造方式決定的**:
> 「拋棄式世界」的整個賣點是**它與正式庫一樣**。
> 而它套的是**工作樹**,不是 `HEAD`。
> ⇒ 所以**你正在改的那支 migration,自動就在那個世界裡**。
> ⇒ ⇒ **你永遠拿不到「修前」,除非你刻意去造。**

### 判別句
> **我這個拋棄式世界,是從【HEAD】建的還是從【工作樹】建的?**
> 工作樹 ⇒ 🔴 **我手上那支還沒 commit 的東西已經在裡面了 ⇒ 我沒有「修前」。**

### 修法(要「修前」就得明確造)
1. **同一個交易裡先把舊版 `\i` 回去**,量完再套新版,最後 `ROLLBACK`(本片用的)
2. 從 `HEAD` 建那個世界(而不是工作樹)
3. 把那支 migration 移開再起
   ⚠️ **2 與 3 在共用主樹上有代價**:七窗同一棵樹,`git stash` / 移檔會動到別人正在寫的東西。
   **本片選 1 的理由就是這個 —— 它不碰工作樹。**

## ed-B2 兩道量具同時壞 ⇒ 修好其中一道,畫面【完全沒變】

**當班實錘**:B1 只是**第二道**。同一發裡還有第一道:
```

  psql -h /tmp -p <鑽機埠> -U postgres -d postgres -Atc \
    "SELECT (created_at AT TIME ZONE 'Asia/Taipei')::date, count(*) FROM public.products_list_public GROUP BY 1 ORDER BY 1 DESC;"
  ⇒ 修量具【前】回一列, 值 108;散開之後最多的一天是 9(同一條 psql 重跑)
⇒ 撞上那支函式自己的規則:「單日新增 ≥100 件 = 批次日、那一整天不顯示」
   (門檻 c_batch_day_threshold := 100, 在 migration `20260811040000` 起的每一代函式裡)
```

🔴 **而畫面完全沒變 —— 還是 `0` 對 `0`。**

📌 **⇒ 而最自然的結論是「這條路不對」⇒ 然後放棄,或去改別的東西。**

### 判別法
> **兩道都修好之前,你拿不到任何有判別力的數。**
> ⇒ 所以【修好一道而數字沒動】**不是「這條路不對」的證據 —— 它什麼都不是**。
> ⇒ ⇒ 正確的下一步:去問「**還有第二道嗎**」,不是去問「我是不是修錯地方」。

📌 **一般化**:先驗**該紅的那個世界真的是紅的**(本片:修前那個 `N` 必須 > 0)。
**在 `N > 0` 之前,後面那個 `0` 一個字都不能引用** —— 它與「排掉了」印同一個數。

🔴 **而同日同一句話在【正式庫】那一側也成真了**:主視窗把我那三段驗收 SQL 端出去之前發現 ——
08-27 首灌 **1559 件**(gilles + dna)⇒ `≥100` ⇒ **整天被批次日規則藏起來** ⇒ 那三段現在貼下去也是 `0/0`。
✅ **救下來的是我預先寫進讀法的那一句**:「① 若回 0 而【新品區 total 也是 0】⇒ 那是『7 天內沒有新品』,不是『排掉了』」。
**⇒ 判別法要寫進【讀法】,不是只寫進做法** —— 那句話在別人手上、在另一個資料庫上,又擋了一次。

## 一格只證「**沒有發生**」的證人, 在【它自己沒被執行】時也會印綠

**線** `-auth` 2026-09-06 · `⟦f8-HARVESTCHAIN⟧` · **自述**(而抓到它的是反向對照, 不是我)

### 事情

收割鏈加 `--dry-run`(全部照跑, 只是不呼叫 `announce-and-push.sh`)。
我為它寫了一格證人:**把 `PUSH_CMD` 換成一支會留下痕跡的樁, 然後看那個痕跡在不在**。

```sh
_mark="$(mktemp -d)/pushed"
( DRY=1 PUSH_CMD="touch $_mark" ; push_step /dev/null ) >/dev/null 2>&1
[ -f "$_mark" ] && 紅 || 綠      # 「沒有痕跡」= dry-run 沒有推 ⇒ 綠
```

🟢 **它印綠了。** 而它綠的理由是:**`push_step` 那時根本不存在** ——
我把它定義在主流程裡, 而 `--selftest` 在 `case` 分派時就跑了
⇒ 呼叫失敗 ⇒ 沒有痕跡 ⇒ **斷言成立。**

🔬 **抓到它的是同一組的反向對照**:
```sh
( DRY=0 PUSH_CMD="touch $_mark" ; push_step /dev/null )
[ -f "$_mark" ] || 紅            # 非 dry-run【必須】留下痕跡
```
那一格紅了, 我才回頭看第一格為什麼綠。

### 判別句

> **這一格證的是「某件事沒有發生」嗎?**
> 是 ⇒ 📌 **那它在「這一格自己沒有跑起來」的時候也會成立** ⇒ **必須配一格「該發生時真的發生」。**

### 🔴 為什麼這個形狀特別難自己發現

- **它不報錯。** 同一個順序坑我今晚踩了三次, 前兩次是 `rc=127`(command not found)**看得見**;
  **這一次因為那一格證的是【否定】, 失敗被吸收成通過。**
  ⇒ 🎯 **同一個 bug, 換一種斷言方向, 從「報錯」變成「假綠」。**
- **證人自己是新寫的** ⇒ 沒有人期待它會壞;而它壞掉的方式剛好是它要證的那個結論。
- **樁看起來很嚴謹**(留痕跡、比檔案在不在)—— 而**嚴謹的是斷言, 不是它有沒有被執行**。

### 第二層(而它是本條的標題)

**這是既有母題的一個新【作用域】, 不是新母題。**
母檔 `docs/patterns/guard-and-instrument-traps.md` 已經有:

- `:13312` 「當『成功但沒事做』與『根本沒跑』印出同一個數字時, 判別欄位不是那個數字」——
  🔵 **那是【數字層】**;本條是 **【證人格層】**:不是產出的量分不開, 是**證人自己沒跑而它的斷言仍然成立**。
- `:10992` 「恆真斷言假扮負向對照 —— 斷言裡沒有受測物, 它在量它自己」——
  🔵 **那條的受測物【不在斷言裡】**;本條的受測物在斷言裡, 而**執行它的那支函式不存在**。
- `:19301` 「原始碼裡的【位置】不等於【執行順序】」——
  🔵 **那條是拿文字當量具去量結構**;本條是**真的執行順序**(shell 函式要定義在呼叫那一行【執行】之前)。

⇒ 📌 **三條都近, 而沒有一條講到「否定型斷言 + 證人未執行」這個組合。**

### 修法

1. **每一格「沒有發生」都配一格「該發生時真的發生」** —— 兩格用**同一支樁**, 只差開關。
   (本例:`DRY=1` 不得有痕跡 · `DRY=0` 必須有痕跡。)
2. **shell 函式要定義在「呼叫它的那一行【執行】之前」**, 不是「檔案裡在它上面」——
   ⚠️ 而 `--selftest` 這種**在分派時就跑**的入口, 特別容易踩:
   它在檔案的中間, 而它要用的東西寫在檔案的後面。
3. 🔵 **把被測的那一步抽成函式**(本例 `push_step`), 不要在呼叫點寫 `if [ "$DRY" = 1 ]` ——
   後者**只能用眼睛看**, 沒有一格證人抓得到。

### 同族

- 母題:**【它根本沒跑】與【它跑了而沒有東西】印同一個輸出。**

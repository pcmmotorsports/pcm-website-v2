🔴 **本篇不是那個母題的解藥, 它是「記錄分散」的第四個實例。**
   本篇唯一的貢獻是**把它們指在一起**, 不是發現它們。

## 第四個成員(2026-08-28 線C 實測)
```
突變 runner 被指到一個【不存在的目錄】⇒ 產生器一支檔都寫不出來
⇒ 整份輸出是 `No such file or directory` × 3, **一個 `ERROR:` 都沒有**
⇒ 只看「有沒有紅」的話, 這一輪與「48 發全部通過」在畫面上完全一樣
✅ 擋下來的不是找紅那把尺, 是另一把:**比【我餵幾條】與【它跑幾支】**
   ⇒ 產生器說 0 發、目錄裡 0 支 ⇒ rc=1 退場
```
**這一層的新意只有一格**:前三條的失敗都**印了一個東西**(一個 0 / 一片空白 / 一個句子),
而這一個**連被檢查的對象都不存在** —— 尺不是量錯,是**沒有東西可以量**。

## 修法已經是法, 不必再立
`CLAUDE.md` 鐵則 11 逐字寫著 **「要比第四個數:【我餵幾條】vs【它跑幾支】」**
(2026-08-28 Sean 拍 `Q-鐵則11分母=甲`)。
⚠️ 而本次值得補的只有一句限定:**那個數不能從輸出推** ——
輸出只知道自己跑了幾支, **它不知道你原本要餵幾條** ⇒ 必須由呼叫端自己算。

## 判別句
**「有沒有紅」只答得出【它跑了而且失敗】。它答不出【它根本沒跑】。**
📌 **而那兩件事在畫面上的差別是【少了東西】不是【多了東西】——**
   **人眼會注意到多出來的紅字, 不會注意到少掉的那幾行。**

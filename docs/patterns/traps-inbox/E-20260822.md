## 1. 🔁 量到「有沒有」的尺,答不了「看不看得到」—— 而它只在你正在推薦的那個世界裡壞掉

**當天**:我要判「面板 690 與 720 哪個讓訂單列表看得到比較多欄」。
尺 = `th.getBoundingClientRect().width > 0`,回答 690 有 **14 欄**、720 有 **8 欄**
⇒ 我據此推薦 690,**講了好幾個小時、寫進 STOP、發給主視窗、差點進 Sean 的決策批**。

**真相**:690 之下表格 `scrollWidth 1480` 塞進 `clientWidth 900` ⇒ **橫向捲動**,
14 欄裡 **Sean 眼睛只看得到 7 欄**(物品名稱/數量/單價/金額/客戶/狀態/發票在視野外)。
**720 才是對的**,Sean 原本拍的那個數字沒有錯。

**為什麼活這麼久**:
> **在 720(不橫捲)那個世界,`width > 0` 與「看得到」完全一致 —— 尺是準的。**
> **它只在表開始橫捲時分岔,而表只在 690 橫捲**
> ⇒ 🔴 **這把尺的 bug,只存在於我正在推薦的那個世界裡。**

**連帶(這半比上面更難防)**:
> **對照組沒救到我,因為對照組(720)正是尺還準的那一格。**
> ⇒ **對照組會系統性地選在尺還準的地方** —— 因為那正是你有把握、拿來當基準的那一格。

**判別句**:
> **我這把尺是從幾何算出來的,還是從畫面讀出來的?**
> 幾何算的答不了「人看到什麼」——**再準都答不了,那是層級問題不是精度問題。**
> ⇒ 凡結論要寫「看得到 / 看不到 / 讀得出來」,**截圖是必要證據,不是輔助**。

📎 抓到它的是**後台自己印的一行字**:「→ 右邊還有 7 欄沒有完整顯示:…」。
**那個功能是對的、一直在講實話,而我從來沒打開過那張圖。** 我把同一組數字量了好幾輪、跨了一次 context 壓縮。

## 2. 🔁 凡量測會【動到被量的東西】,幾何讀數就失去判別力 —— 破壞和訊號長得一樣

**當天**:為了測最壞金額字面,我用 `td.textContent = 'NT$ 1,280,000'` 注入。
單號格裡是 `<a class="after:absolute after:inset-0">`(整列可點的 stretched link),
`textContent` 讀出來是**串接**、寫回去就把巢狀元素**壓平**成可見的重複字:
```

```
🔴 **幾何量測完全沒紅** —— 那格只是變寬,而**變寬正是我在量的東西**。

**判別句**:
> **我的量測動作,會不會改變我要量的那個量?**
> 會 ⇒ 那個讀數同時包含「真實值」與「我造成的破壞」,而兩者在數字上分不開。
> **處置**:改成不碰 DOM 的量法(canvas `measureText` + 該格自己的 computed font),
> 或量完**用截圖驗一次**。

## 8. 🔁 你的工具會不會被【別的東西】呼叫,決定它該不該用離開碼說話

> 🔴 **判定先寫**:canonical 已有這一族,而且它自己標了「**同族第三例**」——
> 「**exit code 是被壓成一個數字的東西,而壓縮會把兩種世界壓成同一個值**」(2026-08-20)。
> 那一族現有至少四條(另含「成功的 `rm -rf` 與什麼都沒做的 `rm -rf` 回傳值一模一樣」、
> 「`cmd A B || echo 零命中` 的 exit code 是整條的」、「把檔案清成 0 bytes 而 rc=0 印 ok」)。
>
> **而我認為本條是那一族【還沒有人寫的那一面】:**
> ```
> 既有那幾條 = 【呼叫端】視角:rc 會騙你 ⇒ 不要只看 rc, 去看數量
> 本條       = 【作者端】視角:那你寫工具的時候, 該怎麼讓 rc 不騙人
> ```
> 🔴 而 `where-is.sh` 正好是那一族問題的**建設性答案**:
> 既有那條說「exit code 把多個世界壓成一個值」,**而它示範了怎麼把它們解壓開**(3 個不同的碼)。
> ⇒ **建議併成那一條的「作者端」續篇,不要開新母題。**
>
> ⚠️ **第二半我沒找到對應**:「**有索引/快取的工具,它的零命中同時相容於『不存在』與『比索引新』**」——
> 過期那一族(附了量法照樣過期 / 量具自檢跟著過期 / 待辦集合自己縮小)講的都不是這件事。
> 那一格**可能是新的**,但我只掃了 `快取|索引|過期|stale` 四個字。

### 判別句

> **這支工具的答案,會不會被 `&&` / `if` / `||` / CI 讀到?**
> 會 ⇒ **它必須用離開碼區分「查無」與「我壞了」**,光靠印不同的字不夠。
> 🔴 因為 **`&&` 與 `if` 讀不到你印的字,只讀得到離開碼。**

### 正面範本:`scripts/where-is.sh`(七支裡唯一做到的)

```
存在      ⇒ rc=0
查無      ⇒ rc=3
用法錯    ⇒ rc=2
工具自壞  ⇒ rc=1
```
🔴 **關鍵不是「它有離開碼」,是它把【三種失敗】分成三個不同的碼。**
那三種在**文字輸出上可以長得非常像**(都是「我沒找到東西」),而**只有離開碼分得開**。

### 反例一:`graphify query`(2026-08-22 實測)

```
真節點     ⇒ 「Traversal: BFS depth=2 … 68 nodes found」   rc=0
不存在     ⇒ 「No matching nodes found.」                  rc=0   ← 🔴 同一個碼
```
⇒ 誰寫 `graphify query X && …`,**零命中會被當成成功**。
判別只活在那一行字裡,而那行字**還會被 `head -1` 吃掉**
(它現在每次先印兩行 `warning: skill is from graphify 0.8.16, package is 0.8.17`)。

🔴 **而它更深的一層:那個零命中本身是雙關的。**
```
圖最後更新 Aug 18;2026-08-20 起新增 93 支檔
實測:查一支【今晚剛建的】檔 ⇒ 「No matching nodes found.」
```
⇒ **「不存在」與「比圖新」印同一句話、回同一個碼。**
而那支工具被指定的用途是「**想知道改這支檔會影響什麼**」
⇒ **它的失效區(比圖新的檔)與它的使用區(剛動過的檔)完全重疊。**
**那不是覆蓋不足,是結構上永遠答錯。**

### 反例二:`scripts/literal-sweep.sh`

```
有命中的字面 ⇒ rc=0, 111 行
不存在的字面 ⇒ rc=0,  46 行
兩邊【第一行完全一樣】:「字面:<你給的字>  (當純字串)」
```
⇒ 行數分得開,**離開碼與第一行分不開**。
而 Sean 2026-08-15 拍板「改過對外字面 ⇒ 拿舊字面跑它再 commit」——
**照做的人若只看開頭幾行,兩個世界長得一樣。**

### 可執行

```
寫工具時:
  · 先問「它會不會被別的東西呼叫」—— 會 ⇒ 查無與自壞要用【不同的離開碼】
  · 抄 where-is.sh 的分法(0 有 / 3 查無 / 2 用法錯 / 1 自壞), 不要自創第二套

用工具時:
  · 拿到 0 之前先問:這支工具【回不回】非 0? 不回 ⇒ 那個 0 什麼都沒說
  · 對有快取/索引的工具(graphify 這類)再問一句:
      ls -ld <索引目錄>                        # 索引多舊
      git log -1 --format=%cd -- <你查的東西>  # 它多新
    索引比它舊 ⇒ 🔴 零命中不算證據
```

📌 這條與本檔既有那族的關係:CLAUDE.md 早記過「**pipeline 後面的 `$?` 是右端那個指令的**」——
那是**呼叫端**把離開碼弄丟;**本條是被呼叫端根本沒用離開碼說話。** 同一枚硬幣的兩面。

**我挑 690,是因為它是我先前二分找到的「最大仍看得到 14 欄」那一格** ——
**我挑了一個【剛好還成立】的邊界值當證據,而沒注意到它離失效只有 1px。**
🔴 **而 `-4a` 是從 CSS 字面(那兩道斷點)反推出來的,不是從我的數字看出來的。**

### 收斂

> **讓我有把握的那個先例,正好是它還沒失效的那一格。**

**為什麼這比「要有對照組」更難防**:對照組**已經有了**,而且**它通過了**。
```
問題不在「沒有對照」, 在【對照本身是從有把握的那一格挑的】。
🔴 而【這兩次挑對照的人都挑了自己有把握的那一格】——
   兩個窗、同一夜, 一個挑的是【動作】、一個挑的是【量具】, 兩邊互不知情。
   ⇒ 它至少不是一次巧合。
```
⚠️ **本條的分母是 2。** ~~原寫「而人挑對照的時候【本來就會】挑自己有把握的那一格」~~
—— 那是一個**普遍傾向**的宣稱,而兩個實例支持不了它(`-4a` R1 MF-1,頻率副詞那道抓的)。
📌 **收窄之後反而更強**,因為它現在引的是**自己真正的分母**。

### 判別句

> **我拿來當基準的那一次(那個先例 / 那個對照組),是不是正好是【這件事還成立】的那一格?**
> ⇒ 可執行版:**去找一個【我沒把握】的格子當對照**,而不是找一個我確定的。
> 具體:`-3c` 的版本是「**我拿掉的這個狀態,在客人的畫面上存不存在?**」
> 我的版本是「**這把尺在我要推薦的那個世界裡,有沒有被單獨驗過?**」

### 🔴 而它與「量測會動到被量的東西」不是同一條

那條講**動作污染讀數**;**本條講的是我為什麼不會去懷疑那個動作** ——
**因為同一個動作上一次是對的,而「上一次對」會關掉這一次的懷疑。**
⇒ **一條講機制,一條講【為什麼機制不會被觸發】。**

## 14. 🔴🔴 「引用結論而不是逐字抄」是好習慣 —— **而它切斷了更正的傳播路徑**

> 具名:線 E `-5b`(**當事人是我**)。`-4a` 建議由我自己寫,理由是它今晚引過兩次的那條:
> **只有犯錯的人自己寫得出「當下為什麼看起來很合理」。**

### 當下為什麼看起來很合理

`-4a` 給了我一個結論(「inbox 那些檔一條都沒併進 canonical」)。
我把它**理解之後用自己的話寫進我的檔頭**,而**沒有逐字複製它的句子**。

**那在當下感覺是【比較負責】的做法**:
```
逐字抄 ⇒ 讀起來像複製貼上, 而且我沒有真的理解它
用自己的話寫 ⇒ 表示我讀懂了、消化了、對它負責
```
🔴 **而我當時完全沒有想到:我剛剛把這一行從它的搜尋範圍裡拿掉了。**

### 後來發生什麼

`-4a` 自己推翻了那個結論(它量到的是**收割後的殘餘**,讀成了**全部**)。
它要通知所有副本,於是 grep 自己的字面:
```
主視窗數到 2 份(#838 + STATUS)—— 那兩份是【逐字轉述】它的話
而我這一行 ⇒ 兩邊都 grep 不到
   主視窗搜它自己的字 / -4a 搜它自己的字 / 而我寫的是【我自己的字】
⇒ 最後是 -4a 跑 git grep 掃【全 repo】才撞到
```

### 🔴 為什麼這一族特別難防

```
兩個都是好習慣, 而它們互相打架:
  ①「理解後用自己的話寫」⇒ 減少複製貼上, 提高品質
  ②「更正時先數副本」    ⇒ 而它靠【字面】找副本
⇒ 越是照 ① 做的人, 越不會被 ② 找到
```
**而沒有人會發現這件事**:
> **引用的那一方讀起來很負責,被引用的那一方 grep 起來很乾淨。**

### ⚠️ 而處置本身有一個失效條件 —— 那半是 `-4a` 的

**「留一個可搜的錨」不是萬靈丹**:我那一行**本來就有「審查線」三個字**,
🔴 **而 `-4a` 搜的是【結論的字面】,不是那三個字。**

`-4a` 的原話:
> **留標記只有在【更正的人會搜那個標記】時才有用。兩邊都要約定,單邊留沒有用。**

⇒ **合起來才是完整的規矩**:
```
我這半 = 為什麼會有這個洞(兩個好習慣的交叉點)
它那半 = 處置什麼時候會失效(錨是一個【雙邊協定】, 不是單邊動作)
```
🔴 **而「單邊留沒有用」這件事,單邊的人看不出來** ——
我留了錨、感覺盡責了,**而它到底有沒有被搜到,只有另一邊知道。**

### 可執行

```
引用別人的結論時:
  留一個【那個人自己會搜的標記】—— 條目編號 / 窗代號 / 交件檔名, 而不是主題詞
  (我那一行現在留了 `-4a` 三個字元)

而更正自己的結論時:
  🔴 不要只 grep 自己的字面 —— 那只找得到【逐字抄的人】
  要 grep【全 repo】, 或直接問「誰引用過我這個結論」
  📎 實測:主視窗 grep 字面 ⇒ 2 份;-4a 掃全 repo ⇒ 3 份
```

📌 **與既有那條的關係**:canonical 已有「更正先數副本 —— 而別人替你抄的那份,你 grep 自己的字抓不到」。
🔴 **那條講的是【別人替你抄】;本條講的是【別人用自己的話寫】** ——
後者更難找,**而它是被鼓勵的那種行為。**
⇒ 建議併成那條的第二格,**只留「兩個好習慣互相打架」與「錨要留在對方會搜的維度上」兩句。**

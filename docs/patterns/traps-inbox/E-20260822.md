## 1. 🔴🔴 量到「有沒有」的尺,答不了「看不看得到」—— 而它只在你正在推薦的那個世界裡壞掉

**當天**:我要判「面板 690 與 720 哪個讓訂單列表看得到比較多欄」。
尺 = `th.getBoundingClientRect().width > 0`,回答 690 有 **14 欄**、720 有 **8 欄**
⇒ 我據此推薦 690,**講了好幾個小時、寫進 STOP、發給主視窗、差點進 Sean 的決策批**。

**真相**:690 之下表格 `scrollWidth 1480` 塞進 `clientWidth 900` ⇒ **橫向捲動**,
14 欄裡 **Sean 眼睛只看得到 7 欄**(物品名稱/數量/單價/金額/客戶/狀態/發票在視野外)。
**720 才是對的**,Sean 原本拍的那個數字沒有錯。

**為什麼活這麼久**:
> **在 720(不橫捲)那個世界,`width > 0` 與「看得到」完全一致 —— 尺是準的。**
> **它只在表開始橫捲時分岔,而表只在 690 橫捲**
> ⇒ 🔴 **這把尺的 bug,只存在於我正在推薦的那個世界裡。**

**連帶(這半比上面更難防)**:
> **對照組沒救到我,因為對照組(720)正是尺還準的那一格。**
> ⇒ **對照組會系統性地選在尺還準的地方** —— 因為那正是你有把握、拿來當基準的那一格。

**判別句**:
> **我這把尺是從幾何算出來的,還是從畫面讀出來的?**
> 幾何算的答不了「人看到什麼」——**再準都答不了,那是層級問題不是精度問題。**
> ⇒ 凡結論要寫「看得到 / 看不到 / 讀得出來」,**截圖是必要證據,不是輔助**。

📎 抓到它的是**後台自己印的一行字**:「→ 右邊還有 7 欄沒有完整顯示:…」。
**那個功能是對的、一直在講實話,而我從來沒打開過那張圖。** 我把同一組數字量了好幾輪、跨了一次 context 壓縮。

## 2. 🔴 凡量測會【動到被量的東西】,幾何讀數就失去判別力 —— 破壞和訊號長得一樣

**當天**:為了測最壞金額字面,我用 `td.textContent = 'NT$ 1,280,000'` 注入。
單號格裡是 `<a class="after:absolute after:inset-0">`(整列可點的 stretched link),
`textContent` 讀出來是**串接**、寫回去就把巢狀元素**壓平**成可見的重複字:
```
畫面出現 PCM-2026-1002PC…  /  H7CPXQH7CPXQ  /  2DTX422DTX42
```
🔴 **幾何量測完全沒紅** —— 那格只是變寬,而**變寬正是我在量的東西**。

**判別句**:
> **我的量測動作,會不會改變我要量的那個量?**
> 會 ⇒ 那個讀數同時包含「真實值」與「我造成的破壞」,而兩者在數字上分不開。
> **處置**:改成不碰 DOM 的量法(canvas `measureText` + 該格自己的 computed font),
> 或量完**用截圖驗一次**。

📌 `-3c` 同一晚獨立踩到同一個(也是 `textContent` 還原)⇒ **這不是個人失誤,是這個 API 的形狀。**

## 7. 🟡 我為了修 A 而加的東西,把守 B 的那道閘變成恆真的

> 它:  <span class="b-cat-label">{name}<span class="b-cat-count">{count}</span></span>
>      ⇒ textContent = 「維修零件697」⇒ 陣列元素永遠不等於「維修零件」⇒ 恆真

> 同樣是突變抓到的、同樣是作者自述。**
>
> ⇒ **併入時請當成那一條的第二個實例,不要開新條。**


> 🔴 而它不是「有人偷懶」:**是兩個各自正確的動作疊起來的副作用。**

### 🔴 我認為 canonical 那條沒有涵蓋到的兩格(要併的是這兩格)

**(a) 觸發者不同 ⇒ 防法不同。**
那條的觸發者是**別人開的處方**(審查意見)⇒ 它的防線是「收下修法前先讓它表演」。
我這發的觸發者是**我自己另一件不相干的改善**(修無障礙)——
**沒有任何人給我處方,也沒有任何一步是錯的**:
```
我加 sr-only(修無障礙)         ← 對的
我原本的守門讀 textContent      ← 原本也是對的
兩個放一起 ⇒ 視覺那半從此無人看管
```
⇒ **「收處方前先驗」那條防線,在這個情境下【不會被觸發】** —— 因為根本沒有處方。

**(b) 因此需要一條不同形狀的可執行規矩**:
> **凡新增任何「會進到既有斷言觀察面裡」的東西**
> (`.sr-only`、`aria-label`、`title`、隱藏欄、佔位字元、debug 屬性),
> **當場把那道既有斷言的目標刪掉跑一次** —— 它必須紅。不紅 ⇒ 你剛剛關掉了它。

**判別句**:
> **我這一次改動,有沒有讓某一道既有的檢查【更容易通過】?**
> ⇒ 具體到可執行:**凡新增任何「會進到既有斷言觀察面裡」的東西**
>   (`.sr-only`、`aria-label`、`title`、隱藏欄、佔位字元、debug 屬性),
>   **當場把那道既有斷言的目標刪掉跑一次** —— 它必須紅。不紅 ⇒ 你剛剛關掉了它。

## 附:我今晚被截圖抓到三次,而三次的尺都「沒有紅」
```
① 欄位可見性     幾何說 14 欄, 畫面說 7 欄        ← 後台自己印的警告行抓到
② 金額省略號     幾何說「切了」, 畫面說「NT$ 22,...」← 截圖抓到(且它有 ellipsis, 不是無聲截斷)
③ textContent    幾何說「變寬了」, 畫面說「字重複了」← 截圖抓到
```
🔴 **三次都不是尺紅,是圖不對。** 這正是第 1 條那句的實證:
**幾何量測讀的是 layout,而人看的是 paint。**

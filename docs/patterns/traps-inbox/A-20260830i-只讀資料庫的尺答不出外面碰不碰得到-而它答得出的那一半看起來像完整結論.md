- 🔴 **歸屬(照 `A-20260830h` 的三格寫法)**
  ```
  事件 ← 兩條線各自走進同一個錯誤前提：
         -b4 從「板子那一列的權限量測」進來
         -e9 從「設計一支 ACL 漂移探針」進來（三輪對抗審查、59 條 finding）
  發現 ← 兩邊各自撞到，主視窗 -48 看出是同一件事並要求合寫
  寫成條 ← -e9（理由：探針那一側的反例樣本在 -e9 手上；-b4 只有單一實例，證不到通則）
  ```
- 🔴 時刻是 sandbox 的 `date`,不是 Sean 那台的鐘。

## 那句話

> **一把只讀資料庫的尺,對「外面碰不碰得到」【結構上】答不出來 ——**
> **而它答得出來的那一半(角色層過寬),看起來就像一個完整的結論。**

---

## 實例一 · `net` 那一列(`-b4` 提供,**以下為原字面,未經轉述**)

```
板子那一列（錨:「net 對 anon 權限過寬, 目前靠一個【設定】擋著」）：
· 角色層量到「過寬」，而尺是活的（同一發的自檢）：
    has_schema_privilege('anon','net','USAGE')                  ⇒ true
    has_table_privilege('anon','net.http_request_queue','INSERT')⇒ true
    has_table_privilege('anon','net._http_response','SELECT')    ⇒ true
    對照 anon × public.products × SELECT ⇒ false（同一發）⇒ 兩個世界分得開
🔴 · 而可達性【不在資料庫裡】，實測：
    select setting from pg_settings where name='pgrst.db_schemas' ⇒ **查無**
  ⇒ 答案在 Supabase 面板一個下拉清單（Sean 08-28 截圖「2 of 3 schemas exposed」，net 不在裡面）
```

⚠️ **來源屬性(`-b4` 自標,照抄)**:上面三行 `has_*_privilege` 與 `pg_settings` 那發是 **`-c8` 2026-08-28 量的,寫在板上**;`-b4` 是**開檔讀來的**,不是它親手跑的。截圖那格是 **Sean 給的**。
⇒ **`-b4` 那半沒有一格是它自己量的。**

## 實例二 · 三輪對抗審查 59 條(`-e9`,我自己的)

我設計一支「監看 ACL 目錄」的漂移探針,三輪 codex 對抗審查共 **59 條 finding**。
**其中至少 8 條的根因是同一個 —— 每一條都是「ACL 一格不動,而客人路徑打開」:**

```
· 角色鏈沒遞迴：anon→A→B 已存在，之後 GRANT … TO B ⇒ 探針零差異
· view 的 security_invoker 從 true 改 false ⇒ ACL 六本目錄一格沒動
· 關 RLS / 放寬 policy / 給 authenticated BYPASSRLS ⇒ 同上
· public 的 security_invoker view 引用 private 表 ⇒ 對 private 表 GRANT 即可讀到
· anon 可 SET ROLE 到 service_role 的世界 ⇒ service_role 的 GRANT 客人用得到
· 既有函式改成 SECURITY DEFINER / 換 owner ⇒ proacl 可保持不變
· relkind 白名單漏 f（foreign table）
· 六本目錄漏 pg_type.typacl（public type/domain 的 USAGE）
```

📌 **⇒ 三輪不重複,不是因為我每輪修得不夠細 —— 是因為每一輪找到的是【同一個錯誤前提】的不同反例。**
**⇒ ⇒ 三輪加起來不是「還沒修完」,是【這條路不通】。**

---

## 🔴 本體:**它不是錯的答案,是一個【正確而不完整】的答案**

```
那把只讀 DB 的尺，答得出來的那一半【本身是正確的】——
「角色層過寬」是真的、量到的、自檢過的（正對照 true / 對照組 false，兩個世界分得開）
⇒ ⇒ 🔴 所以它不是「錯的答案」，是【一個正確而不完整的答案】
⇒ ⇒ ⇒ 而正確的答案不會觸發任何人的懷疑
```

**這就是它為什麼躲得過檢查:**
```
問「有沒有量？」    ⇒ 量了
問「量具驗過嗎？」  ⇒ 驗了，正負對照都在
問「結論對嗎？」    ⇒ 對
🔴 而沒有人問：「它答的是【哪一個】問題？」
```

## ⚠️ 而反過來也要寫,否則會被讀成「權限表沒用」

> **那半正確的答案是【必要的】** —— 沒有它,那個勾被打開的那一天,我們連「打開會怎樣」都答不出來。
> **⇒ ⇒ 缺的不是那把尺,是【它旁邊那句「而可達性在別的地方」】。**

🔴 **⇒ 這一條的動作不是「不要用權限表」,是「用它的時候,旁邊一定要有另一句」。**

## ✅ 可執行動作

```
① 寫下任何「權限/曝露/安全」的結論之前，先分成兩句：
   ·【角色層】它【被授予】了什麼   ← 資料庫答得出來
   ·【可達層】外面【真的碰得到】嗎 ← 🔴 資料庫答不出來
② 而第二句的答案住在哪，要當場寫出來（不是「未確認」三個字）：
   PostgREST 的 db-schemas（不在 pg_settings，在 Supabase 面板）／
   RLS 與 policy 的內容／view 的 security mode／角色鏈／
   🔵 或者——【直接去試一發】
③ 🔵 而 ② 的最後那個選項是唯一不需要窮舉的：
   scripts/anon-reachability-probe-verify.sh 已證明「當客人去讀一發」這個做法
   叫得出來也不亂叫（拋棄式 PG：該紅 200 有資料 / 該綠 401 / 負對照 404；
   連跑兩發 9/0；突變拿掉 GRANT ⇒ 7/2 真的變紅）
   ⇒ 它不推論，它去試
🔴 而【八條反例對它成不成立】要分兩半寫（-b4 2026-08-30 逐字核出我把推論寫成量測）：
   ✅ 已實證 1/8：RLS 那條。同一支 harness 第三個世界 —— rls_table 有 GRANT
      SELECT TO anon 而 RLS 開著且無 policy ⇒ 200 而【零列】；
      關掉 RLS ⇒ 資料出來了，而【ACL 一格都沒有動】。PASS=11 FAIL=0
   🛑 其餘 7 條 =【機制推論，未逐條餵給它看】—— 不得寫成「全部不成立」
```

## ⚠️ 天花板

- **「去試一發」也有它的分母**:它只看得到**你列出來的那幾張**。
  ⇒ 而那個分母**可以窮舉、可以檢查**(清單長度 vs 試過幾張,兩個數要相等)——
  **比「用目錄推論」那個分母好,但不是「全部」。**
- 🔴 **它要打正式站,而那需要 Sean 本人授權** —— 所以它不是隨時可用的工具。
- 這條是**規矩不是閘**:沒有任何東西會在你只寫了第一句的時候變紅。
- 🔴 **來源屬性(`-b4` 要求標,照標)**:`-b4` **開檔驗了那支探針存在**(6372 bytes、可執行),
  **而它沒有跑它** ⇒ 本條裡所有 harness 的數字都是 **`-e9` 跑的**,不是兩人各跑一發。
- 🛑 而「其餘 7 條」那一格:**方向是【讓我們的新工具看起來更好】** ——
  📌 而那正是本 repo `C11` 那條的形狀:**未驗的樂觀發生在讓答案更漂亮的方向上,而那個方向最不會被質疑。**
  🔴 **一份講「沒有人問它答的是哪一個問題」的檔,不該有一格自己沒過那一關。**

## 驗轉址要看**最終落點**,不是看有沒有轉址 —— 第一跳改前改後**一模一樣**〔安靜〕

**線** `front` 2026-09-17 · 舊 WordPress `/index.html` 導首頁(`8f65f67b8`)上線驗收 · **自述**

### 事情

要驗的是:舊網址 `/index.html` 從 404 變成導到首頁。
順手把**射程變體**也列進驗收(大小寫、尾斜線)—— 其中 `/index.html/` 這一格:

```
before   /index.html/   HTTP 308 → https://www.pcmmotorsports.com/index.html   (然後 404)
after    /index.html/   HTTP 308 → https://www.pcmmotorsports.com/index.html   (然後 → 首頁)
```

🔴 **第一跳的狀態碼與 Location 逐字相同。** 那個 308 是 **Next 自己的尾斜線正規化**,
**改之前就在了**,跟這次的修法無關。

⇒ 📌 如果驗收判準寫成「`/index.html/` 要回 308」,那一格**改之前就已經是綠的** ——
**它從頭到尾不會紅,也永遠不會告訴你任何事。**

真正變的東西要跟到底才看得到:
```bash
curl -sL -o /dev/null -w 'HTTP %{http_code}  最終 %{url_effective}\n' \
  https://www.pcmmotorsports.com/index.html/
# before  HTTP 404  最終 …/index.html
# after   HTTP 200  最終 https://www.pcmmotorsports.com/     ← 這才是差別
```

### 🎯 母題

**一條路徑上可能已經有【別人的】轉址,而它與你要加的那一段長得一樣。**
⇒ 你量到「有轉址」,而那個轉址**不是你做的**。
🔴 而這種格子的失敗方向是**恆綠**:它不會誤報,它會**什麼都不報**,
所以不會有人去看它 —— 📌 **一道從來不紅的閘,與沒有那道閘,在報告上長得一模一樣。**

🔵 **本例真正避開它的原因,不是量得仔細:**
是**先把判準寫下來(「pass = 最終落點是首頁」),才去量**。
⇒ 反過來(先量完再想判準)那一格會在報告裡長成「都有 308 ⇒ 沒變 ⇒ 沒生效」,
而那句結論**每個字都對,而整句是錯的**。

### ✅ 可機械執行

> **驗轉址的 pass 條件一律寫成【最終落點】,不是【狀態碼】。**
```bash
curl -sL -o /dev/null -w '%{http_code} %{url_effective}\n' <網址>   # 跟到底
```
> **而且 before 一定要量** —— 這一格的 before(第一跳已經 308)就是它會恆綠的證據。
> 🛑 只有 after 的話,「308 ⇒ 過」看起來完全合理。

> 🔵 順帶:`%{redirect_url}` 只給**下一跳**,`%{url_effective}` 配 `-L` 才給**終點**。
>   兩個都印,才分得出「導了幾段」與「最後停在哪」。

### 📎 鄰居
- canonical「同一個網址兩種取法而錯的那次回 200」(`front-20260906f`)—— 🔵 **同族而受詞相反**:
  那條是**兩把尺對同一個網址給不同答案**;本條是**同一把尺對改前改後給相同答案**。
- 本片同一發的另一格「沒變就是正確答案」(`front-20260917c`)—— **必須配著讀**:
  一個講「相同 ⇒ 可能是恆綠」,一個講「相同 ⇒ 可能正是對的」。**分辨器是判準有沒有先寫下來。**

### 🔵 跳幾段 —— 2026-09-17 14:0x 補量(原本這裡寫「未量」)

```bash
curl -sL -o /dev/null -w 'redirects=%{num_redirects} code=%{http_code} final=%{url_effective}\n' <網址>
```
| 網址 | 跳數 | 終點 |
|---|---|---|
| `/index.html` | **1** | `/` |
| `/INDEX.HTML` | **1** | `/` |
| `/index.html/` | **2** | `/`(Next 尾斜線正規化 → `/index.html` → `/`) |
| apex `pcmmotorsports.com/index.html` | **2** | `/`(既有 apex→www → 本條規則) |

🟢 **兩個 2 跳都不是本次規則造成的** —— 那兩段前面那一跳(尾斜線正規化 / apex→www)
**改之前就在了**,本次規則只加了最後那一段。Search Console 那兩筆命中的是 `/index.html` ⇒ **1 跳**。
🛑 **不要為了把 2 跳壓成 1 跳去加規則** —— 那會走上 plan 裡明寫不做的那條
(`/:path*.html` / `/(.*)/index.html` 會把 29 筆該 404 的舊網址一起導去首頁 = 製造 soft-404)。

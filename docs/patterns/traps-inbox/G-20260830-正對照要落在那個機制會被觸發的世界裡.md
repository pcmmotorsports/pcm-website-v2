# 一個正對照要能動,它必須落在【那個機制真的會被觸發】的世界裡

2026-08-30 線G,同一晚同一件工作踩兩次,兩次都差點讓我丟掉一把好的尺。

我在試三段修法 CSS,判準是「注進去之後畫面有沒有變」。

第一次:我拿 `.pd-sheet{min-height:0}` 當渲染腳本的正對照,餵一份 7 項的出貨單。
出圖與對照組 sha 完全相同 ⇒ 我判「CSS 沒生效,這支腳本不能用」。
而腳本是好的:7 項那份的溢出是內容本身超過一頁,拿掉 min-height 對它本來就沒有作用。
換成 `body{background:#000}` ⇒ sha 立刻不同。

第二次:我拿一份 5 項(只有一頁、有餘裕)的紙,去驗三段修法 CSS 是不是活的。
三個全部沒變 ⇒ 我一度判三段都沒生效。
而那也是錯的:甲那段用的是 break-before / break-inside,
而一份只有一頁的文件本來就沒有分頁可避 ⇒ 那個機制根本不會被觸發。

兩次的共同形狀:我挑的正對照,落在一個【那個機制不會被觸發】的世界裡。
於是它印出「沒有變化」,而那個「沒有變化」是正確的結果 ——
它不是在說「尺壞了」,它是在說「這個情境用不到它」。

而問題在於這兩者長得一模一樣:
  這段 CSS 沒生效        ⇒ 畫面沒變
  它生效了而這情境用不到 ⇒ 畫面也沒變
在檔案雜湊上,兩個世界完全相同。

解法不是換一個更明顯的樣式(那只是換一個運氣),是換一種量法:
直接量那個屬性的計算值(getComputedStyle,而且要 emulateMedia 到對的媒體)。
那一發答得出「這條規則有沒有落在那個元素上」,而它與「這個情境用不用得到它」無關。

實測:
  現況 .pd-bottom marginTop = 0px  /  注入 margin-top:0 之後 = 0px  ⇒ 空操作
  現況 .pd-bottom breakBefore = auto / 注入之後 = avoid            ⇒ 活的
  現況 .pd-sheet minHeight = 944.882px / 注入 200mm 之後 = 755.906px ⇒ 活的
三段裡有兩段是活的,而它們在「畫面有沒有變」那把尺底下全部長得像死的。

自檢:
你拿來當正對照的那個東西,它要觸發的機制,在你餵的那個樣本上會不會被觸發?
答不出來就不要用它 —— 一個不會被觸發的正對照,它的「沒有變化」沒有任何資訊,
而它讀起來像一個結論。

### 🔴 為什麼 `:23182` 是鏡像而不是同族

```
:23182  對照組回了【你想看到的肯定答案】，而那個肯定是假的
        ⇒ 後果：你以為尺是活的 ⇒ 【過度自信】，然後拿它去下一個零命中斷言
🔴 本條  對照組回了【正確的否定答案】（這個情境用不到它）
        ⇒ 而我把那個正確答案讀成「尺死了」
        ⇒ 後果：【丟掉一把好尺】—— 我第一次真的差點把渲染腳本判成不能用
```
📌 **⇒ 兩條的判別動作也相反**:
`:23182` 說「對照組回了你想看到的答案之後,**開檔看那一筆**」;
**本條說「對照組回了『沒有變化』之後,先問【那個機制在這個樣本上會不會被觸發】」。**
⚠️ **⇒ 而兩條應該互相指向** —— 它們是同一件事的兩端:
**一個對照組的答案, 在它【該有的世界】之外沒有任何意義, 不論那個答案是肯定還是否定。**

# 🔴 機制:為什麼寫成程式碼就會被抓到

```
兩個相反的答案,可以同時住在同一個人腦裡而不打架 ——
**因為它們從來沒有被並排放過。**
而寫成程式碼之後它們【一定會並排】:
  · 腳本的輸出是一個檔
  · 我的手判是一則訊息
  ⇒ **兩個物件,一個 `diff` 就比得出來**
⇒ ⇒ **不一致從「不存在」變成「可偵測」。**
```
📌 **⇒ 所以價值不在「別人可以重跑」(那是常說的那一半),**
**在【我自己會被迫一致】** —— 而後者連我自己都沒預期。

# ✅ 判別動作

> ## **我這一次的判斷,與我上一次對同一個東西的判斷,**
> ## **有沒有一個地方可以把它們【放在一起比】?**

```
沒有 ⇒ 🔴 我不會發現我改變了主意 —— **我只會覺得我剛才想清楚了。**
✅ 最便宜的形狀(不必寫程式):
   把上一次的答案【貼在旁邊】再判 —— 而不是憑印象重判
   ⇒ 那一步花五秒,而它把「重新猜測」變回「複核」
```

## ⚠️ 而它的代價要寫明,否則會被當成「所有判斷都該寫成程式」
```
· 分類寫成腳本 = 把判準【凍結】成關鍵字比對 ⇒ 它會漏掉需要讀上下文的那幾列
  (我那份腳本就是關鍵字比對,而它**剛好**在這兩列上對)
🔴 · 所以本條【不主張】「用腳本取代判斷」——
  主張的是:**判斷之後留下一個【可以被下一次比對的物件】**,不論它是腳本、清單、還是一段貼在旁邊的舊答案
```

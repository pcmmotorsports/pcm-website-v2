# 一個新加的 fail-closed,它擋掉的東西可能比它守的東西寬 —— 而我二十分鐘內犯了兩次

> 線【出貨】`-1e` · 2026-08-31 12:3x–12:5x CST · 樹 `/Users/sean_1/pcm-wt-ship`
> 兩發都是 codex 對抗審查當場擊破的(R1 `codex-出貨-片4-R1-20260831.out` / R2 `codex-出貨-nits-R2-20260831.out`)

## 母題

**我為了讓一個問題【出聲】而加的 fail-closed,它沉默掉的東西比它要守的那件事寬。**
而兩次的具體修法完全不同,形狀一模一樣。

## 第一次(R1)

```
我寫的  某顆 env 設了而形狀不合 ⇒ 當場 `return 503`
位置    在 `checkAnomalyAlerts(...)` 【之前】
```
codex 逐字:
> route 在 `checkAnomalyAlerts` 前直接 return 503 ⇒ **同輪付款、退款等其他真異常全部不通知**

📌 **⇒ 一顆打錯的【出貨】env,會讓整支告警啞掉一天。而那比它要治的病嚴重。**
✅ 改法:這裡只 `console.error`,**503 排到告警跑完之後**,與既有五種 503 同一個位置。

## 🔴 第二次(R2)—— 而它發生在我剛被打過【二十分鐘】之後

```
我寫的  `P0001` 且錯誤訊息帶那支函式前綴 ⇒ 降級;**不符 ⇒ `throw err`**
我當時的理由(逐字)「認不出來就原封上拋 = 現況行為 = 安全方向」
```
🛑 **那句話是錯的,而錯在一個我可以當場查的地方:現況是【降級】,不是上拋。**
codex 逐字:
> migration 改動參數閘前綴或標點而應用程式尚未同步 ⇒ 真正可降級的參數錯誤改成整條上拋,
> **付款／退款等其他告警同輪無法送出**

**⇒ 與第一次逐字同一個後果。**

## 🔴🔴 而 codex 還拆掉了那個判準本身

> 同一 RPC 日後以**既有函式前綴**拋出非參數閘的 `P0001` ⇒ 被誤判為參數錯誤並靜默降級

⇒ 📌 **前綴在【兩個方向】都不成立**:認不出真的參數閘(訊息漂),也擋不住假的參數閘(同前綴)。
**⇒ 我不只選錯了代價,我選了一個【不成立】的判準。**

## ✅ 最後的改法與判別句

```
控制流維持現況(P0001 一律降級);前綴【只決定 log 印哪一句】+ reason 標 unexpected_shape
```
📌 **判別句:拿不到訊號的成本是 0,拿錯控制流的成本是整條告警。**
🔵 一個守門要新增「更嚴格的那一側」時,先問:**它變嚴格的時候,誰跟著一起被關掉?**

## 🔴 而這一則的重點不是那兩個修法

**我讀過那個教訓,而且是【自己】在二十分鐘前被教的,照樣犯第二次。**
⇒ 而第二次的錯誤理由裡有一句可以當場查證的假話（「現況是上拋」）——
**我沒有查,因為我在寫的是一個【我已經學會的】教訓的應用。**
📌 **⇒ 剛被糾正過的那一刻,是最容易再犯的時候之一:你以為你已經在防它了。**
📎 同族但不同層:memory `feedback_knowing-rule-is-not-executing-rule`
(那條講「規則在庫、也讀過,犯錯的不是知識層」;**本條窄一格:規則是二十分鐘前【針對我】下的**)。

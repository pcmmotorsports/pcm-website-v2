# T① traps 收件(2026-08-18)— 主視窗指名落檔

## 一個數字要有【兩個形狀不同】的來源,才准下結論 —— 審量具的人被自己的量具騙

**事實(可回放)**:審計 dev-four-greens.sh 時,我一度要報「git-common-dir 修法【不在 dev】」。
依據=一次 grep(pattern 只命中 trap 註解、沒命中 :570 的真賦值)。第二次用【形狀不同】的 pattern
再數 ⇒ count=2 ⇒ 兩次不一致 ⇒ 追差異才發現 :570-571 真的有那段 code。差點把「工具沒修」
報成 finding —— 而工具修了、只是 disclosure 沒跟上。🔴 **它發生在【我正在審量具】的時候。**

**判別句(可操作,不是「更小心 grep」)**:

> 一個 grep 的 `0` 或 `N`,在下結論之前要有第二個【切法不同】的來源對照 ——
> 不是換關鍵字,是換【切法】:找識別字 vs 找賦值形狀 vs 找檔案清單 vs 開檔讀那段。
> 🔴 兩者一致才算;不一致 ⇒ 先追差異,不要挑一個信。

**同族(這是第 3-4-5 個變體,共同解都一樣)**:
- C 窗:`grep -c` 數【行】不數【次數】(一行多命中被數成 1)。
- B 窗:`head -N` 截斷,把「有更多」讀成「就這些」。
- 本條:同一字串、兩個 pattern 形狀,給不同答案。
- 🔴 **共同解不是「更小心」,是【一個數字要有兩個形狀不同的來源】。** 一把尺量一次=一個證據
  複印 N 份,一致不是效度(memory `feedback_reproducibility-is-not-validity` 的 grep 版)。

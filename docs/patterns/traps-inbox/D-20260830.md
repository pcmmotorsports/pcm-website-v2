## D-1 一個 view 的【行為】由 `WHERE` 決定,而它的【約定】住在 `COMMENT` 裡 —— 兩個都要讀

**當班實錘(2026-08-30)**。

我要判「出貨通知信第一次接上線會不會對舊單補寄」,於是去讀那支 view 的 `WHERE`:
```
WHERE s.shipped_at IS NOT NULL AND s.deleted_at IS NULL AND (…) AND NOT EXISTS (…)
🔴 零時間界線（interval 0 ／ now() - 0 ／ days 0 ／ shipped_at > 0，負對照 0）
```
⇒ 我得出「它會撈到所有歷史單」(**那是對的**),
⇒ 然後把「那顆 cutoff 要用自己一顆、還是共用既有那顆」寫成一個**要 Sean 拍的設計題**。

### 🔴 而答案早就在【同一支檔】的 `COMMENT ON VIEW` 裡
```
'⚠️ 本 view 【不】自帶起始線 —— 它回的是【歷史上全部】還沒排過信的配對。'
'cutoff 由呼叫端以 shipped_at 條件加上（env SHIPPED_EMAIL_CUTOFF，
  鏡像 order_created 那條的 B4_DEPLOY_CUTOFF）'
```
✅ **⇒ 那顆 env 的【名字】與【它是自己一顆】,寫這支 view 的人早就定了。**
🛑 **⇒ 所以那個「設計題」不存在 —— 而我差點拿它去佔 Sean 一次注意力。**

### 📌 判別句
> **一個 view 的【行為】由 `WHERE` / 索引 / 觸發器決定;**
> **而它的【約定】(誰負責給什麼、為什麼這樣切、哪些東西刻意不在裡面)住在 `COMMENT` 裡。**
> **⇒ 兩個都要讀。而讀碼的人的習慣是只讀前者。**

🔴 **而它為什麼特別容易漏**:
```
· WHERE 讀起來像「事實」，COMMENT 讀起來像「說明」
  ⇒ 而我們被訓練成「不要相信註解，要看碼」
  ⇒ ⇒ 而那條訓練在這裡【剛好害了我】：那段 COMMENT 不是在描述碼，是在【指派責任】
· 而 COMMENT ON VIEW 在檔案的【最下面】，離 WHERE 幾十行
· grep 一個欄位名會命中 WHERE，而不會讓你讀到 COMMENT
```

### 下次那一刻要做的動作
> 讀一支 view / 表 / 函式要下任何「它會不會…」的結論之前,
> **把那支檔的 `COMMENT ON` 段落整段讀完** —— 不是 grep,是讀。
> ⇒ 而具體到可執行:`grep -n 'COMMENT ON' <檔>` 拿到行號,然後**開那幾段**。

⚠️ **鄰居但不同**:正本 `:10097`「守門掃【來源】,而人讀的是【輸出】」——
那一條講的是**兩個不同的產物**(原始碼 vs 渲染結果),而**尺與人不在同一個平面**;
**本條講的是【同一支檔的兩段】,而讀的人只讀了其中一段。**
📌 **⇒ 共通的母題是「答案在一個你的習慣不會去的地方」,而落點不同。**

### ✅ 而它有一個【正面】的對照,同一支檔裡
同一支 migration 另有 `public.pcm_shipped_email_unsendable`,而它的 COMMENT 逐字:
> 「分開的理由…它們永遠不會消失,留在這裡會由最舊那端永久擋住後面的有效信」

📌 **⇒ 也就是:這個 repo 已經有一個慣例 ——【被排除的東西要有自己的一張表,不是消失】。**
🔴 **⇒ 而那個慣例也只寫在 `COMMENT` 裡。** 我是因為這一次去讀了才知道它存在。
⇒ **一個沒有人讀的慣例,與一個不存在的慣例,在下一個人身上是同一件事。**

反過來(先改消費端)會讓消費端引用一個還不存在的方法,一樣紅,而且更難讀。

```
   ⇒ 最接近的一條, 而它是本條【操作化那一段所引用的原則】, 不是本條本身:
     它答「規矩該寫在哪」, 本條答「一個必然會出現的紅, 誰該在什麼時候替它命名」。
```

### 🔴🔴 而這條有一個【完成式】,而它是在寫完上面那一段之後才長出來的

### 🔴🔴 而 03:5x 我**第三次**犯它,而這一次我當場說得出【為什麼會犯】——那個理由才是這條的本體
```

而我【沒有事先認領】, 當下的判斷逐字是:「一分鐘內修掉比寫認領快」
```
⚠️ 這次**沒有人來問** ⇒ 沒有收到稅。**而「沒有人付稅」與「沒有產生稅」是兩個宣稱** ——

🔴 **而那個判斷錯在哪,不是「我估錯秒數」**:
```

真正該進比較的第三項(別人的成本)【根本沒有出現在我的算式裡】
```
📌 **⇒ 不是我偷懶,是我算的那條式子【結構性地缺一項】。**

⇒ ⇒ 而這正好是本檔那條稅的**上游描述**:
> **收稅的對象不是造成它的人 —— 因為造成它的人在做決定的當下,那一項不在他的算式裡。**

### ⇒ 所以判準不需要「寫認領要幾秒」(而我一度真的去量了)
```

   ⇒ 而那是【打字那一下】的成本, 不是【寫認領】的成本
   ⇒ 真正的成本含「想出那句話要寫什麼」, 而它與思考時間混在一起, 我量不到
   ⇒ 📌 **所以我不能說「認領只要 0.03 秒」** —— 那會是一個誠實的數字回答錯的問題
✅ 判準只需要這個不對稱:
   我方成本 = 一句話 + 一次 tool call         ⇒ **有界且小**(不管確切幾秒)
   他方成本 = 撞紅 → git status → 讀 diff → 推理歸屬 → 來問 → 等回覆
             ⇒ **一次完整的調查, 沒有上界**
```
🔴 **⇒ 一個【有界且小】對上一個【無界】—— 那個比較不需要任何一個秒數就成立。**
⚠️ 而我原本要去量那個秒數,是因為**「量一下」聽起來永遠像是更嚴謹的做法** ——
📌 **而它在這裡會把一條成立的判準,換成一個量不準的數字。**

🔴 **而差別在哪,可以量**:
```
第一顆:紅出現時,樹上沒有任何一句話說那是我 ⇒ -e9 從零做歸屬判定
第二顆:紅出現時,艦隊表上【已經有】我認領那五支檔的那一段
        ⇒ 而 -1c 仍然花了一輪 —— 因為它撞到的是【第六支】(測試檔),不在我列的五支裡
```
⇒ 📌 **所以真正的距離不是「有沒有寫」,是【機制裝上的時點】與【事故發生的時點】之間那一段。**
我的認領是在第一顆事故**之後**寫的,而它涵蓋的是**我當時已經知道要動的檔**;
第二顆用的是一支我**當下才發現也要改**的檔 ⇒ 認領清單天生落後於施工面。

### ⇒ 所以操作化要再往上一層(前一版那條不夠)
```
❌ 不夠:「動手前列出我要動哪幾支檔」—— 清單永遠追不上,因為改到一半才知道還要動誰
✅ 夠  :「**我這段時間在動 <某一族>,這一族上的紅先當成是我的**」
        —— 認領【一個範圍】,不是認領【一張清單】
```
🛑 **而這一段刻意不改寫上面那條** —— 上面那條是我在第一顆之後寫的,而它當時是誠實的。
把它改寫成「後來我就沒再犯了」會刪掉這條最有用的那一格:**它記錄了一次「知道了而沒做到」。**

## D-6 · 我貼了原文,而**貼的過程本身把它改壞了** —— 而旁邊還掛著「逐字」兩個字

**現場(2026-08-30 02:4x,R3 對抗審查抓到)**:我在 `scripts/a8a1-verify.sh` / `a8a2-verify.sh`
的檔頭寫了一段過期警語,裡面引 Sean 的原話。用 python heredoc 寫檔時,
我在字串裡多寫了一組 shell quoting 的跳脫 ⇒ **殘渣 `"'"'"` 被原封寫進檔案**:

```
檔內實際字面(cat -v 實證)
  # …(Sean 拍「2 乙」+ 逐字「寫很官方就好"'"'"」):
應該是
  # …(Sean 拍「2 乙」+ 逐字「寫很官方就好」):
```

### 🔴 為什麼這比「引錯字」嚴重一格
```
那段檔頭【自己】逐字寫著:「誰寫繼任的 a8a3/a8a4-verify,請從這裡抄期望值」
⇒ 我親手在那段話上掛了一個【來這裡抄】的招牌,而招牌底下那句是壞的
```
📌 **而真正的機制在這裡:**
> **一段被污染的引句,只要旁邊還掛著「逐字」兩個字,它的可信度反而比沒掛章的更高。**

⇒ 一句沒掛章的引文,下一個人會回去核;**一句掛了「逐字」的,他不會** —— 那兩個字的全部功能
就是**關掉他的核對動作**。⇒ 所以**掛章的引文出錯,比不掛章的出錯貴**,而它們在畫面上長得一樣。

### 🔴 它是「值與授權句貼原文、不重打」那條的**失敗案例**,不是反例
那條規矩(轉述契約 §5-①)是對的,而我照做了 —— **我沒有重打,我貼了原文**。
```
病灶不在【重打】那一步,在【貼的那一步本身會改寫內容】:
  heredoc / shell quoting / echo 的跳脫 / 全形轉半形 / 編輯器自動換行
  ⇒ 這些都在「我以為我在貼原文」與「檔案裡真正的字」之間
```
⇒ 📌 **「貼原文不重打」防的是【我的記憶】,防不了【載體】。**

### 操作化(可機械執行,不是提醒)
```
把引句寫進檔案之後,當場撈回來比一次:
  grep -n "<引句的一段>" <檔> | cat -v
  ⇒ 看到任何 M-… 以外的 ASCII 雜訊(引號、反斜線、'"'"')= 殘渣
或更嚴:把來源那一行與寫入後那一行【逐位元組 diff】
```
🔴 而**寫含引號/反斜線的字進檔案,一律 `printf '%s\n'`,不要 `echo`,也不要在 heredoc
   裡自己疊跳脫** —— 同族已記:CLAUDE.md 的「`echo` 遇到 `\c` 會停止輸出」那條。
   **那一條講的是【少了東西】,本條講的是【多了東西】;而多出來的比少掉的難發現,
   因為句子還讀得通。**

### ⚠️ 射程:**這條的原始證據【不存在】,而那不是疏忽,是它的性質**
```
壞掉的那一版【從來沒有被 commit 過】—— 它活在工作樹裡, 30 分鐘後被 R3 抓到就修掉了
量法（線D 與 -b9 兩個窗、兩套指令、沒有先對過答案，結論相同）:
  git show 5f96851b^:scripts/a8a1-verify.sh | grep -n "寫很官方就好" ⇒ 零命中
  git show 5f96851b :scripts/a8a1-verify.sh | grep -n "寫很官方就好" ⇒ :27, 而無殘渣
  git log --all -S'寫很官方就好' -- 那支檔                          ⇒ 只有 5f96851b 一顆
  git show --stat 5f96851b -- 那支檔                                ⇒ 13 insertions, 零 deletions
  負對照 兩版各 grep -c 'zzq6641' ⇒ 0 / 0（尺不是恆回東西）
```
⇒ **它存在過的唯一憑據是 ①R3 findings 原文 ②本條作者的自述** —— 而那兩個是
**同一次事件的兩份描述,不是兩個獨立來源**。
🔴 **⇒ 引用本條時不得寫成「有 commit 可查」。**「壞掉那版曾經存在過」**證不到也證不否**
—— 工作樹不留痕。

### 🔴 而本條有一個【第三實例】,是作者在寫完上面兩節【之後】犯的
```
我為了讓 -b9 能複核 D-6, 給了它一組 git 指令
⇒ 而那組指令我【沒有跑過】⇒ 它會回空的
⇒ 而收訊者拿到空的時候, 分不出是【自己打錯】還是【我講錯】
```
📌 **⇒ 一個【打開核對】的動作,如果它自己沒被核過,它會製造一次【假的核對】。**
⇒ 與 D-6 本體同一個形狀、方向相反:
· D-6:**貼原文,而貼的那一步改壞了它**
· 第三實例:**給複核路徑,而那條路徑自己沒走過**
⇒ **兩者都是「把一個【減少懷疑】的東西交出去,而它本身沒被驗過」。**

**可執行(不依賴懷疑)**:
> **每當我在訊息裡寫「你跑這個會看到 X」,送出後(或送出前)當場跑一次。**

### 🔴 而這條規矩【太窄】,同一夜就被第四個實例穿過去
```
03:2x 我在交件檔裡寫「下面這段含標點 240 字（我數過）」
⇒ 去量 ⇒ 279。**我寫了「我數過」而我沒數。**
```

而「我數過」**不是那個句形**。⇒ 規矩要擴:

> **凡是句子裡出現「我量過 / 我數過 / 實測 / 當場跑過」,送出前當場跑一次。**

### 📌 而 `-b9` 指出的那一格,比這條規矩本身重要
```
第三實例（沒跑過的指令）：有下游會撞到 —— 他跑一發, 拿到空的, 就發現了
第四實例（沒數過的字數）：**沒有下游** —— 一個字元數不會有人重跑,

```
🔴 **⇒ 「有沒有人會發現」不是【它有多錯】的函數,是【有沒有人剛好在做同一件事】。**

⚠️ 而這一次**剛好有**:`-b9` 正在算那張表的餘裕 ⇒ 它重跑了 ⇒ 得到 252(與我更正後相同)。

## D-7 · **一條規矩(或一道守門)的射程,由它的【觸發條件】決定,不由它【想防的東西】決定**

這句話是 D-6 第四實例逼出來的:我原本那條規矩想防的是「未經驗證的斷言」,
而它的觸發條件只寫了「你跑這個會看到 X」⇒ **「我數過」那個句形整個穿過去。**

📌 **判別問法**:
> **把我想防的那件事,換一個【句子的形狀 / 檔案的位置 / 呼叫的寫法】再做一次 ——
> 我這道閘還看得見嗎?**

看不見 ⇒ **它防的不是那件事,是那件事的一種寫法。**

### 實例(三個;而**只有第一個是我親自量到的**)
```
① ✅ 我量到的:那道 block-unconditional-echo-label 的 hook
   我 03:2x 被它擋下一次 —— 它看得懂【單行 echo/printf 帶結果標籤】
   而 -48 說它【看不懂 if 區塊裡的同一句】⇒ 同一個宣稱換一個語法就穿過去
   🔴 我親自撞到的是【被擋】那一半;【穿過去】那一半是 -48 說的, 我沒複核。
② ⚠️ -48 提供, 我未複核:`cat .env` 擋得住而 `grep -r` 擋不住
   ⇒ 同一個「讀 .env」的意圖, 換一個指令名就穿過去
③ ⚠️ -48 提供, 我未複核:某道守門的分母 231 vs 233
   ⇒ 兩個都是誠實的數, 而它們數的是不同的集合
```
🛑 **②③ 我沒有開檔驗過,所以掛「未複核」的標記**(做法照 `-b9` 2026-08-30 那一格:
**一段推導出來的字面要掛「不是我量的」**,而那個標記的功能是**打開**下一個人的核對)。
⇒ 📌 **而這正好是本條自己的一個實例**:我若把 ②③ 寫得跟 ① 一樣肯定,
**這條 traps 的觸發條件就會漏掉「我引用了別人的量測」那個句形。**

### 可執行
```
寫一條規矩 / 裝一道守門的當下, 當場問:
  「我想防的那件事, 有沒有第二種寫法?」
  ⇒ 有 ⇒ 那第二種寫法【現在就會穿過去】, 不是「以後可能」
  ⇒ 而它穿過去的時候, 這道閘會印綠
```
⚠️ 這條**不保證**你想得出第二種寫法(想不出來的那一種正是會出事的那一種);
它只保證**你有去想**。⇒ 更強的做法:**當場餵一發第二種寫法給它看,不要用想的。**

⇒ **兩側用同一個壞方法 ⇒ 兩側算出同一個空雜湊 ⇒ 相等 ⇒ 放行。**

📌 **⇒ 我以為我寫的是 fail-closed,而它是 fail-open。**

### 🔴 而這是今晚同一個母題的第三次,而這一次它裝在一道守門裡面
```
· 對稿:兩端錯法相同 ⇒ 它會比出【完全吻合】, 而那個結論看起來是最好的那一種
· 覆蓋腳本:兩份手抄的 CHECK 一起抄錯 ⇒ harness 全綠而正式庫會失敗
· 🔴 本條:兩側同一個壞管線 ⇒ 一致 ⇒ **而一致就是放行的條件**
```
⇒ 📌 **前兩個的後果是「你以為你驗過了」;這一個的後果是「守門自己開門」。**
**同一個形狀,而它裝的位置決定了它有多貴。**

### ✅ 修法不是「把 rc 收好」,是**換一個不需要管線的來源**

⇒ 而它**順手關掉了另一個我們已經決定要接受的風險**(見下)。

### ⇒ 可執行
```
heredoc 一律 <<'EOF'(加引號)—— 需要插值時, 用參數傳進去, 不要靠 shell 展開
判別句:**我這段文字裡有沒有 $( ) 或反引號?有 ⇒ 加引號。**
```
📌 而它與 CLAUDE.md 那條「雙引號內禁反引號(commit body 會被吃掉)」是**同一族的另一個成員**:
那一條是**字被吃掉**,本條是**字被執行**。⇒ **前者少東西,後者多做事。**

## D-14 · **拿掉一個分支,擋住的是「沒有值」;而「有一個錯的值」走的是另一條路**

**現場(2026-08-30 06:0x,code-reviewer 抓)**:我寫了一支解析 `SHIPPED_EMAIL_CUTOFF` 的純函式,
而它最貴的失敗模式是:**沒設值 ⇒ 當成 epoch ⇒ 把所有歷史箱子一次寄出**。

我的做法是**型別上不給那條路**:三態裡刻意沒有「沒設值 ⇒ 用一個預設起點」那個分支。
並且我在檔頭寫了一句很好聽的話:
> **一道檢查會被下一個人繞過或刪掉;一個不存在的分支不會。**

🔴 **那句話是對的,而它只涵蓋了一半。實測**:
```
resolveShippedEmailCutoff('1970-01-01T00:00:00Z')  ⇒ { kind: 'ok' }
⇒ 一個【打錯年份的 env】就把全部歷史箱子一次寄出, 而三態不會叫
```

### 📌 判別句
> **拿掉一個分支,擋住的是【沒有值】那條路;而【有一個錯的值】走的是另一條路。**
> ⇒ 而那兩條路的**後果一模一樣**(全部歷史箱子一次寄出),所以**只擋一條等於沒擋**。

⚠️ **而最容易誤讀的是「型別安全」這四個字** —— 它讓人覺得那一類問題已經被處理掉了。
📌 **一個在型別上擋住的東西,會讓人停止去問「值那一側呢」** —— 而那正是它最貴的地方。

### ⇒ 可執行
```
每次用「型別上不給那條路」擋掉一個失敗模式時, 當場問一次:
  **「同樣的後果,有沒有辦法用一個【合法型別的錯值】達成?」**
  有 ⇒ 那一側也要擋, 而那一側只能用檢查(值域、下界、白名單)
```
✅ 而修法有一格值得抄:**下界用常數,不讀時鐘** ——
讀時鐘的話那道檢查會隨時間漂,而**測試會在某一天自己變色**(而那天沒有人在改這支檔)。

### 🔴 而檔頭那句話本身是這條的一個實例
我寫的是「型別上不給那條路」,而**讀起來像「這個失敗模式已經被擋住了」** ——
兩者差一個「哪一側」,而**那個差在檔頭上看不出來**。
⇒ 📌 與 D-8(引用的東西真的存在,而它與那個宣稱的關係是假的)同族:
**這一次被引用的是【我自己的一個真實作為】,而它撐不起我掛在它上面的那句話。**

## D-15 · **我從最裡面那條路往外推,而它是最後一層 —— 那個數字是真的,只是它答的是另一環**

> 📌 **規矩讓你知道要量什麼;量測告訴你有沒有命中。**
> 🛑 **⇒ 所以這一條的可執行動作不能只寫「多問一句」—— 問句是預防,而預防在它作者身上失效了。**
> ✅ **補上偵測動作**:交出一份「別人照著做」的東西之後,**當場 grep 它的檔名一次** ——
> 命中 0 ⇒ 它還不存在,不論你寫得多完整。(負對照:同一發 grep 一個既有的交件名,要命中。)

### 🛑 天花板 —— 寫出來,別假裝這條解得掉它

**這一條只擋得住「我知道誰答得出來」的那一種。**

🔴 **而 `three-ds-flag.ts` 那一段的作者【知道】是 Sean** ——

⇒ 📌 **⇒ 所以真正的天花板是:**
**【知道誰該答】與【那個人真的收到】之間,還缺一個動作,而沒有人負責那個動作。**

⇒ 🔵 **本案的解法不是規則,是一個動作**:那一格已經被端進 `給Sean-起床清單` A 區 ②
(30 秒、讀兩個值)—— **而端它的那個動作,就是上面那句缺的東西。**
⇒ ⚠️ **而端一次不等於解決** —— 下一個寫在 `.ts` 檔頭的問題,仍然沒有人負責端。

## D-18 · **程式把三種收成兩種,而人這一側沒有** —— 缺席不是一個值,而它會被講成一句話

**當天**:2026-08-30,寫「請他去讀兩個 env 的值」那一題。

我(與主視窗)想的答案空間是**二元**:`true` / `false`。
而實際是**三個**,因為**第三個不是一個值,是一個缺席**:那一欄**空白 / 根本沒有那個名字**。

`apps/storefront/src/lib/payment/three-ds-flag.ts:6` 逐字:
> 嚴格 opt-in:**只認字面 `'true'`**;未設 / 空 / 其餘 → false

⇒ ✅ **程式那一側早就把三種收成兩種了。**
⇒ 🔴 **而人這一側沒有** —— 他看到空白時最自然的回報是「**沒有這個東西**」,
而那句話**聽起來像「查不到」,實際是「它是關的」**。

### 📌 形狀

> **「程式怎麼處理」與「人會怎麼回報」是兩個空間,而我們只想了前者。**

⇒ 🔴 **後果不是他答錯** —— 他答得完全誠實。
**後果是我們收到「沒有這個東西」之後,會去查是不是找錯地方 —— 而答案已經在手上了。**
⇒ 📌 **⇒ 一個正確的回報,觸發了一整輪不必要的排查。**

### ✅ 可執行

要人去讀一個值之前,先問:

> **「這個東西【不存在】的時候,他會說什麼?」**

- 而那句話**要寫進題目本身**,不是寫進我們的對照表
- 🔴 **因為要防的是【他那一端的措辭】,那句話就得寫在他那一端**
- 落法:題目裡直接給他措辭 —— 「**空白也是一個答案,請照實說『空的』**」
  + 一句為什麼(「對程式來說空白 = 關著」)⇒ **讓他知道那不是失敗的查詢**

### 🔗 連動

⇒ 這是 **D-17 的正面應用**(問題要落在**答得出的人會去的地方**),
而 D-17 講的是**位置**、本條講的是**措辭** —— 同一件事的兩個維度:
**東西寫對地方了,而寫的話還要是那一端的話。**

## D-19 · **往謙虛的方向走的結論,也沒有人回頭查**

**當天**:2026-08-30。兩個窗對同一道閘給了**相反**的當事人紀錄,主視窗要我做對照實驗。

我造了兩個世界,第一發印出:

```
世界 A（index 有別窗的檔）⇒ ✅ 過
世界 B（乾淨 index）      ⇒ ✅ 過
⇒ ⇒ 看起來就是「-e9 對、我錯」
```

**我差點就那樣回報。** 而加上**正對照**(完全不寫標記,這一格**必須**紅)之後 —— **它也過**
⇒ **那道閘從頭到尾沒接上**,前兩個結果全部作廢。
(成因:測試檔叫 `mine1.txt` —— **`.txt` 不在受審面** ⇒ 閘靜默放行。)

### 📌 形狀

> **一個讓自己認錯的假綠,最不會被回頭查。**

🔴 **而它是那條「往好方向走的數字沒有人回頭查」的【鏡像】** ——
本 repo 已經記過「數字變好時沒有人驗」;**這一條是:結論變謙虛時,也沒有人驗。**

⇒ 🔴 **而在一個整晚都在互相糾錯的隊伍裡,「我錯了」是最不會被質疑的那一句。**
⇒ 📌 那不是因為大家鄉愿 —— 是因為**認錯在社交上已經付過代價了,聽的人會覺得「他都認了,還查什麼」。**

### ✅ 可執行

**正對照的觸發條件與結論方向無關。**
⇒ 判別句:**「這一發如果是壞的,它會印出什麼?」** ——
若答案是「印出我現在看到的這個」⇒ **那就還沒有量到任何東西。**
⇒ 🛑 **而「結論對我不利」不是免驗理由** —— 它是這一條專門要打的那個豁免。

## D-20 · **「該做」的兩個輸入:碼的狀態,與描述碼的字 —— 而只有前者會被驗**

**當天**:2026-08-30。`-b4` 與 `-e4` 各自量到一件,主視窗判為同族兩個方向,`-b4` 讓 `-e4` 合寫。

```
-b4 的：碼上看得到、而【引信不存在】
-e4 的：系統是對的、而【名字還是舊的】
⇒ 兩個都會生出「看起來該做，而其實不該做」的待辦
```

### 實例一(**`-b4` 量的,以下為它交來的原字面**)

```
板上 ⟦b4-SUPSLUG1⟧：products / product_variants 兩表都是 NOT NULL DEFAULT 'rpm'
  （supabase/migrations/20260602135934_…sql :34 / :35，`DEFAULT 'rpm'` ⇒ 4 處）
🔴 而引信不存在：admin 對 products 的兩個呼叫【都是 .select()】
  （product-repository.ts:315 / :404）；admin 全樹 supplier_slug 命中 8 處
  ⇒ **全部是顯示／欄位清單／註解，零寫入**；負對照 現造表名 ⇒ 0
⇒ ⇒ **那個預設值今天從來沒有被觸發過，因為沒有任何一條路會建商品。**
```
> **`-b4` 的判詞**:它不是「一個正在傷害資料的預設值」,是**【一顆還沒接上電的引信】。⇒ 兩者在碼上長得一模一樣。**

### 實例二(**`-e4` 量的**)

`.github/workflows/rpm-sync.yml:3` **逐字**(`-e4` 開檔量;該檔「下架對賬」命中 1、負對照現造字面 0):
```
# 每天台灣 12:30(UTC 04:30)自動跑全量同步 + S4 下架對賬 + V1 變體級對賬 + S5 W1 抓取完整性 gate。
```
⇒ 而那支管線**已經不下架任何東西**(`scripts/rpm-reconcile.ts:9` 逐字「`delisted_at` 從此不由本管線寫入」,`:13` / `:159` 各再寫一次)。
⇒ 🔴 **那個過期的名字生出了板上一張待辦**(「⚠️未確認 停產品會不會自動從店裡下架」)。

### 📌 形狀

> **「該做」這個判斷的輸入有兩個 —— 【碼的狀態】與【描述碼的字】。
> 而三綠、測試、審查,全部只驗前者。**

### 🔴 而**為什麼這個不對稱會一直持續**(`-b4` 補,原字面)

> **描述碼的字【沒有執行時機】** —— 碼錯了會在跑的時候出事,
> 而字錯了**永遠不會有任何一刻讓它出事**,
> **它只會讓讀的人做錯決定,而那個錯決定的成因不會指回那行字。**

⇒ 📌 **⇒ 所以它不是「我們比較不在意註解」,是【它沒有一個會叫的時刻】。**

🔴 **而兩個實例的傷法不同,值得分開記**:
```
-b4 那一種：描述【太強】⇒ 讓人以為資料正在被毀 ⇒ 優先序被抬高
🔴 -e4 那一種：描述【過期】⇒ 讓一個正確運作的系統看起來壞掉
             ⇒ 已經有人被它動員（那張待辦是真的被寫出來了）
```
⇒ 🔴 **⇒ 而那張待辦提議的檢查,若真的跑,會回一個【很大而且正確】的數字** ——
**一個看起來像事故的正常狀態,而跑它的人會把它端上來,而它每一位都是對的。**

### 🔵 而開那張待辦的人**沒有做錯**

他逐字標了「**兩個訊號打架,不報成已確認**」—— 那是本 repo 教的做法。
⇒ 🔴 **他讀到的兩個訊號,一個是事實,一個是舊名字。**
⇒ 📌 **⇒ 誠實在這裡救不了他:他每一步都做對,而其中一個輸入是壞的。**

### ✅ 可執行

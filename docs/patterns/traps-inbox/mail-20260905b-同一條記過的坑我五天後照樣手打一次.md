> 📎 **併入建議**:`traps-inbox/D-20260830.md` 的 **D-11**(「兩邊用同一個壞方法, 於是它們一致 —— 而一致就是放行的條件」)。
> 🛑 **本篇的價值不在「又發生了一次」, 在【它已經被記過、連修法都寫了, 而那沒有阻止我】。**

## 現場

我起 codex 前想把受審檔鎖成唯讀, 手打了這一段:
```sh
FILES="a.sql b.ts c.ts d.ts e.ts"
for f in $FILES ; do chmod a-w "$f" ; done
echo "🔒 五支已鎖"
BEFORE=$(cat $FILES | shasum -a 256 | awk '{print $1}')
# … codex …
AFTER=$(cat $FILES | shasum -a 256 | awk '{print $1}')
test "$BEFORE" = "$AFTER" && echo "✅ 零留痕" || echo "🔴 被動過"
```
🔬 實際發生的:
```
chmod: <五支串成一行>: No such file or directory     ← zsh 不對未加引號的變數斷詞
🔒 五支已鎖                                          ← 而這一行是【無條件印的】
✅ 零留痕                                            ← cat 也失敗 ⇒ 兩邊都是【空字串的 hash】⇒ 相等
```

## 🎯 而它與 D-11 是**同一條**, 逐項對得上

| | D-11(2026-08-30) | 本篇(2026-09-05) |
|---|---|---|
| 兩側的值 | 同一段 `git diff \| shasum \| cut` | 同一段 `cat $FILES \| shasum \| awk` |
| 壞的原因 | 管線 rc 被最後一段吃掉 | 變數不斷詞 ⇒ `cat` 找不到檔 |
| 產生的東西 | **空內容的合法 sha256** | **空內容的合法 sha256** |
| 判定 | 兩側相等 ⇒ **放行** | 兩側相等 ⇒ **印零留痕** |
| 我以為我寫的 | fail-closed | fail-closed |
| 它實際是 | **fail-open** | **fail-open** |

🔴 **而 D-11 已經寫下了修法**:
> **「修法不是『把 rc 收好』, 是【換一個不需要管線的來源】。」**
> **「判別句:我這兩側是不是用【同一段可能一起壞掉的碼】算出要比對的那個值?」**

⇒ 🛑 **而我五天後手打了一個帶管線的, 而且是兩側同一段。**

## ✅ 而真正的修法是機制, 不是再多一條判別句

```
scripts/codex-lock.sh <檔…>        鎖 + 印 BASELINE=
scripts/codex-lock.sh --unlock …   解鎖 + 印 CURRENT=
```
🔬 它做對的四件, 每一件都對應上面某一行失效:
```
① 陣列傳參 "${FILES[@]}"          ⇒ 斷詞那條結構上不可能發生
② 每支 chmod 各自看 rc, 一支失敗整個 exit 3  ⇒ 不會「鎖了三支而印五支」
③ 🔴 **空 hash 當場 rc=3** —— 它把空字串的 shasum 算出來當成【禁止值】,
   而不是讓它安靜地變成一個合法的比對對象
④ 「已鎖 N 支」的 N 由 ${#FILES[@]} 來, 不是我打的字
```
🔬 `--selftest` 五格全過, 而**格②就是本篇的重現**:檔不存在時必須 rc=3。
🔬 我用它重跑今晚那一發 ⇒ `🔴 檔不存在: a.sql b.ts c.ts ⇒ 拒繼續`, **rc=3**。
　 ⚠️ 而我第一次量那個 rc 印 **0** —— **因為我接了 `| head`**(同一份 traps 記過的另一條)
　 ⇒ 📌 **驗一個「rc 要對」的修法時, 我用了一個會吃掉 rc 的方式去量它。**

## ⚠️ 這一篇證不到什麼
```
· `chmod` 擋得住寫入, 擋不住把檔複製一份去改
· 多窗共用工作樹時別的窗也會被擋 —— 而本支沒有偵測那件事
· 它不驗「審查是不是還在跑」⇒ 忘了 --unlock 下一步會撞到(而那是【會叫的失敗】)
· 🔴 **本篇沒有回答「為什麼一條記過的坑會復發」** —— 只提出「查重 ≠ 自檢」這一個可能。
  而 D-11 自己那一輪也是三次, 所以復發率本身可能有別的成因。
```

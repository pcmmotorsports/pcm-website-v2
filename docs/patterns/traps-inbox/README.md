## 為什麼有這個目錄

`guard-and-instrument-traps.md` **只有一個檔尾**,而多個窗同時往檔尾 append
⇒ 交件會被 merge 衝突卡住。2026-08-17 夜當場現值兩批(A 窗 `aec6f60d`、C 窗 `619bf899`
同時撞在該檔,判準 `git merge-tree $(git merge-base dev <界線>) dev <界線> | grep -c '^+<<<<<<<'` ⇒ 各 `1`)。

⚠️ 曾經考慮過的替代案(②「固定錨點 + 動之前先 `git log -1` 看有沒有人剛動過」)**沒有採用**,
理由:那仍然只有一個檔尾,而 `git log` 那一道是**靠人記得跑**的 ——
當晚**提出那個警告的人自己就是沒跑的那一個**(收割窗半小時前才廣播「檔尾會撞」,然後自己插隊)。
**不同檔案在 git 上撞不起來,不需要任何人記得任何事。**

## 怎麼用

```
docs/patterns/traps-inbox/<窗>-<日期>.md     例:A-20260817.md / C-20260817.md
```
- 各窗**只** append 自己那一份,不動別人的、不動 canonical。
- 格式照 canonical 現行慣例:`## 標題〔安靜〕` + 判別句 / 實例(附可重跑量法)/ 為什麼它安靜 /
  動作 / 與既有條目的關係。**新條目不編號**(2026-08-17 丙裁定;舊的 `①~㊽` 是歷史編號、保留不動)。

## 誰負責併入

**收割窗(I 窗)。** 沒有頻率規定,由收割窗判斷時機。
併入時把整節搬進 canonical、**零刪除一字未改**,再刪掉這裡的來源檔。

## 🔴 這個目錄自己的已知風險:第二個真相

暫存區存在的期間,**同一則會同時活在兩個地方**。
⇒ 併入之後**要刪來源檔**;沒刪的話下一個人可能引到這裡的舊版。
⇒ 刪之前跑一次 `grep -rn 'traps-inbox' docs/ scripts/` 確認沒有東西還指著它。

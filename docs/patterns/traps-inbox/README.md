## 為什麼有這個目錄

`guard-and-instrument-traps.md` **只有一個檔尾**,而多個窗同時往檔尾 append
⇒ 交件會被 merge 衝突卡住。**不同檔案在 git 上撞不起來,而且不需要任何人記得任何事。**

2026-08-17 夜當場現值兩批(A 窗 `aec6f60d`、C 窗 `619bf899` 同時撞在該檔,
判準 `git merge-tree $(git merge-base dev <界線>) dev <界線> | grep -c '^+<<<<<<<'` ⇒ 各 `1`)。

⚠️ 曾經考慮過的替代案(②「固定錨點 + 動之前先 `git log -1` 看有沒有人剛動過」)**沒有採用**,
理由:那仍然只有一個檔尾,而 `git log` 那一道是**靠人記得跑**的 ——
當晚**提出那個警告的人自己就是沒跑的那一個**(收割窗半小時前才廣播「檔尾會撞」,然後自己插隊)。

## 怎麼用

```
docs/patterns/traps-inbox/<窗>-<日期>.md     例:A-20260817.md / C-20260817.md
```
- 各窗**只** append 自己那一份,不動別人的、不動 canonical。
- 格式照 canonical 現行慣例:`## 標題〔安靜〕` + 判別句 / 實例(附可重跑量法)/ 為什麼它安靜 /
  動作 / 與既有條目的關係。**新條目不編號**(2026-08-17 丙裁定;舊的 `①~㊽` 是歷史編號、保留不動)。
- 併入之後 inbox 那份可以留著當歷史,但**引用它就是引到副本**。

## 🔎 併入迴圈的第一道:先找【放錯目錄】的

**併入之前先跑這一條**(2026-08-17 夜補;它抓的正好是「放錯地方而看起來正常」那一類):

```bash
find . -name '*-20[0-9][0-9][0-1][0-9][0-3][0-9].md' \
  -not -path './docs/patterns/traps-inbox/*' \
  -not -path './node_modules/*' -not -path './.git/*'
```
**有輸出 ⇒ 有人把 inbox 檔寫在別的地方。**
🔴 **印出來就好,不要自動搬** —— 搬到哪、要不要搬,是判斷(有些檔名長得像但不是 inbox)。

**它為什麼不會誤抓一般 docs**:`docs/specs/` 那些是**日期在前**(`2026-06-02-S1-…md`),
本條要的是**日期在後**(`<窗>-<日期>.md`)。

**雙向驗(落筆當下跑過,可重跑)**:
```
世界 1  現況沒有放錯的        ⇒ 零輸出（靜默）
世界 2  造一支 docs/FAKE-20260817.md ⇒ 印出 ./docs/FAKE-20260817.md
        移除靶後複驗          ⇒ 再度靜默；git status 零留痕
```
⚠️ **射程**:它認的是**檔名形狀**,不是內容。**檔名不合這個形狀的放錯檔,它抓不到。**

## 誰負責併入

**收割窗(I 窗)。** 沒有頻率規定,由收割窗判斷時機。
併入時把整節搬進 canonical、**零刪除一字未改**,再刪掉這裡的來源檔。

🔴🔴 **刪之前先量:有沒有窗【正在寫】那一份**(2026-08-17 夜補;下面有實例)

```bash
for b in $(git for-each-ref --format='%(refname:short)' refs/heads/ | grep -v '^dev$'); do
  [ "$(git rev-list --count dev..$b)" = 0 ] && continue
  n=$(git diff --name-only dev...$b -- docs/patterns/traps-inbox/<該檔> | wc -l)
  [ "$n" != 0 ] && echo "🔴 $b 正在寫它 ⇒ 只併不刪"
done
```
**有人在寫 ⇒ 只併、不刪**,等它交件之後再刪。
**實例**:2026-08-17 夜第一次併入時,收割窗 `git rm` 了 `C-20260817.md`,
而 C 窗**同一時間還在寫它** ⇒ 它下一批交件 `git merge-tree --write-tree` 回 **rc=1**:
```
CONFLICT (modify/delete): docs/patterns/traps-inbox/C-20260817.md
  deleted in dev and modified in <界線>
```
🔴 **而這種衝突用 `grep -c '<<<<<<<'` 掃不到** —— `modify/delete` 是**樹層級**衝突,
**不會產生任何衝突標記**。⇒ 衝突預演一律用 `--write-tree` 的 rc。

🔴 **收割窗自陳(留著,因為它解釋了為什麼這一句是必要的、而不是「有人不小心」)**:
> **規則是我寫的,缺口也是我留的。**
📎 **同一晚同一形狀第三次**(往 canonical 檔尾插隊 / 兩個窗各建一份 README / 刪掉它正在寫的檔)。
**三次的共同點不是「不小心」,是:**
> 🔴 **我在做一件【全域動作】,而其他窗正在那個位置工作,而我沒有量。**

## 🔴 這個目錄自己的已知風險:第二個真相

暫存區存在的期間,**同一則會同時活在兩個地方**。
⇒ 併入之後**要刪來源檔**;沒刪的話下一個人可能引到這裡的舊版。
⇒ 刪之前跑一次 `grep -rn 'traps-inbox' docs/ scripts/` 確認沒有東西還指著它。

⚠️ **沒刪之前的判準(A 窗那份的原句,I 窗自陳它沒寫、比它那節更精確)**:
**看到某一則同時出現在兩邊,以 canonical 那份為準** ——
inbox 這份可能是**併入前的舊字面**(併入時被改過措辭的話,舊的仍留在這裡)。

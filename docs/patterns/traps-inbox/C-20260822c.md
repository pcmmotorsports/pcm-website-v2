## 安全的動作與危險的動作,**在同一段流程裡相鄰,而且長得幾乎一樣**〔母題成員〕

> 🔴 **與既有那些「長得一樣」的條目不同族,差別在【誰壞了】**:
> 那些講**量具**壞掉(它回一個錯的答案);**本條講【動作】做對了 —— 它成功地做了另一件事。**
> ⇒ 本條的失敗模式**不是安靜的零,是一個大聲的成功。**

### 兩個實例(同一天,同一條線)

**實例一 · 只差一個動詞**
```
安全  vercel env ls   production --project X   ⇒ 只列名字與 metadata,不印值
🔴 危險 vercel env pull                          ⇒ **在磁碟上寫出一個 .env 檔**
   而當天已證實:apps/admin/.env.local 有【別窗的鑽機】在讀它
   ⇒ pull 下去會把別人的鑽機指到別的地方,**而它不會報錯、不會有紅字。**
   vercel env add / rm                          ⇒ 直接改正式站環境變數(對外可見)
```
🔴 **而三者寫在同一份操作說明的同一段裡** —— 因為它們「都是查 env 的命令」。

**實例二 · 只差一把尺(而下一步是不可逆的)**
```
流程是對的:投稿 → 別人併進正本 → 我先驗它真的併進去了,才刪掉暫存區那份
🔴 而驗的尺用錯:我拿【自己寫的標題】去數正本 ⇒ 三條回 0
   下一步就是 rm 掉唯一那份副本。
換一把尺(用內容裡的識別字)⇒ 全部都在。
```
🔴 **那個 `rm` 的對象是未追蹤檔 ⇒ 刪掉之後 `git status` 一個字都不會說。**
⇒ **刪對了沒人知道,刪錯了也沒人知道** —— 直到有人要找那五條。

### 🔴 共同形狀

```
① 安全版與危險版**共用同一個前綴 / 同一個心智模型**(「都是在查 env」/「都是在驗它在不在」)
② 危險版**不會報錯** —— 它成功了,只是做了另一件事
③ 它們**在同一段說明、同一個流程步驟裡相鄰** ⇒ 手滑的距離是一個字
④ 🔴 而後果落在**別人身上**或**看不到的地方** ⇒ 做的人不會收到回饋
```

### 判別句(兩句,第一句最便宜)

```
1.「這個命令的動詞,是【看】還是【拿 / 加 / 刪 / 寫】?」
   ls / show / list / get-status ⇒ 看
   pull / add / rm / set / write / apply ⇒ 🔴 停

   🔴🔴 **限定(`-4a` 打的,我沒自己標):這是一道【便宜的第一關】,不是一道閘。**
   **很多危險動作的動詞看起來就像「看」:**
     git checkout <branch>   ← 「切過去看看」而它會帶走你未存的改動
     git restore <檔>        ← 「還原」而它是覆蓋
     docker system prune     ← 「整理」
     supabase db reset       ← 「重設」
   ⇒ **動詞過關【不代表安全】,只代表「這一關沒攔到」。**
   ⇒ 不確定 ⇒ 去看那個子命令的說明,或先在拋棄式環境跑一次。

   🔴🔴 **而更硬的一格(主視窗 2026-08-22 補):同一個命令,兩個情境,一個安全一個危險。**
   `git checkout` 今晚就有人用它【做還原】,而在那個情境它是對的。
   ⇒ 所以這道關**不可能**靠一張「危險命令清單」做到 ——
     危險不在命令裡,**在【你當下有沒有未存的東西】**。
   ⇒ ⇒ 這讓上面那條限定從「可選的補充」變成【必要的】:
     **判別句 1 只能用來【提高警覺】,永遠不能用來【放行】。**

2.「我下一步是不可逆的嗎?是 ⇒ 我這把尺【在成功的世界裡】會回什麼?」
   🔴 如果尺在「成功」與「失敗」兩個世界回同一個東西 ⇒ 那把尺不能拿來決定要不要刪。
```

### 修法(動作,不是更小心)

```
1. 🔴 **寫操作說明時,不要把安全版與危險版寫在同一段。**
   危險版要嘛不出現,要嘛獨立一段並標「這一列要停下來等人」。
   ⇒ 本條的成因不是「使用者不小心」,是**說明的排版把它們放在一起**。

2. 🔴 **不可逆動作之前,要求【兩把用不同層特徵的尺】。**
   兩把不一致 ⇒ 那本身就是停下來的訊號,而不是去挑一把你比較喜歡的。

3. 對「後果落在別人身上」的動作,加一句**受害者是誰**:
   「pull 會寫 .env」⇒ 資訊不足;「pull 會寫 .env,**而別窗的鑽機在讀它**」⇒ 才擋得住人。
```

> 不是 ⇒ 那我量到的是我自己造成的狀態。

```
🔴 拿它打我的【實例一】(vercel env ls / pull):
   pull 不是觀察,是動作 ⇒ **它那句擋得住。** ✅ 這一半被涵蓋了,我不宣稱新。

而拿它打我的【實例二】(用錯尺、下一步 rm 掉唯一副本):
   我的第一個動作**就是觀察**(grep)⇒ 它那句放行 ⇒ ❌ 擋不住。
   問題不在「我先動了手」,在**那個觀察本身沒有判別力**。
```

⇒ **⇒ 本條與它的分界**:
```
-86 那條:動作與觀察【順序】錯了 —— 我知道我在做什麼,而我做早了
本 條  :安全動作與危險動作【長得一樣且相鄰】—— 我不知道我做的是哪一個
🔴 而後者多一格前者沒有的:**它的成因在【說明的排版】,不在做的人。**
   ⇒ 修法因此不同:那條要「先觀察再動手」;本條要「**把兩個版本拆開寫**」。
```

⚠️ **而我承認重疊**:若收件者判「實例一掛到 `-86` 那條底下、本條只留實例二 + 排版那一格」,
**那個處置是合理的,我不反對。** ⇒ 由收件者決定。

### ⚠️ 與 ⑳ 的分工(我開檔讀過才寫)

```
既有「⑳ 量具用錯一個字元,而它壞掉的方式是【永遠回 0】【安靜】」
  ⇒ 那是【量具】壞了:它對任何輸入都回 0,而人把一致性當成正確性
本條
  ⇒ 是【動作】對了:命令成功執行,只是執行了另一件事;沒有 0、沒有紅字、沒有不一致
🔴 兩條的判別句因此不同:
  ⑳ 問「這個 0 有沒有分母?」          ← 對量具
  本條問「這個動詞是看還是拿?」        ← 對動作
```

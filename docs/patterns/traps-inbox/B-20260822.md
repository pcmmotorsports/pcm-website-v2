## B-1 🔴🔴 我用來假裝「資料少一點」的做法,**讓被測的系統走上了另一條路**(2026-08-22 線 B `-3c`,具名自寫)

### 判別句(先給)
> **我用來假裝「少一點 / 小一點 / 簡單一點」的那個做法,會不會讓系統【換一條路走】?**
> 會 ⇒ 🔴 **我量到的是【路的差別】,不是【量的差別】** —— 而讀數看起來完全正常。

### 當時發生什麼(完整輸出還在,不是回憶)

要回答「這個查詢明年會不會爆」,我需要成長曲線。手上是正式庫,不能改資料,
所以我用**篩選一部分廠牌**當作「資料比較少」的代理:

```sql
-- 全量
EXPLAIN ANALYZE SELECT moto_brand, model_code FROM vehicle_taxonomy_public
GROUP BY moto_brand, model_code;
--   Merge Append actual rows=10293 ... Execution Time: **113.686 ms**

-- 「假裝資料少一點」
EXPLAIN ANALYZE SELECT moto_brand, model_code FROM vehicle_taxonomy_public
WHERE moto_brand < 'D' GROUP BY moto_brand, model_code;
--   Merge Append actual rows=1478 ... Execution Time: **148.104 ms**
```

```
資料少 86%（10,293 → 1,478 列），時間【多 30%】。
```

**原因:規劃器換了計畫。**
```
全量  ： Parallel Hash Anti Join  （建一次雜湊表，兩邊各掃一次）
加篩選： Nested Loop Anti Join    （**每一列去查一次索引，loops=21,276**）
```

> ### ⇒ 我量到一個**真的數字**,而**那個數字回答的是另一個問題**:
> ### **「規劃器挑了哪個計畫」,不是「資料有多少」。**

### 🔴 為什麼它特別會過關

```
· 兩次都【成功執行】，沒有錯誤、沒有警告
· 兩個數字都在合理範圍（都是一百多毫秒）
· 而「資料變少、時間也變少」是我【預期會看到】的 ——
  🔴 **如果它剛好變快了，我會直接把它當成成長曲線的一點寫進規格，而不會多看一眼。**
  救我的不是我更小心，是**它往【反方向】跑了 30%** —— 那個違反直覺的方向逼我去讀計畫。
```
⚠️ **也就是說:這個坑只有在代理【剛好給出離譜答案】時才會被發現。**
   代理給出「看起來對」的答案時,它是隱形的。

### 適用範圍(不只 SQL)
```
凡是「被測物會【因應輸入而改變策略】」的東西，代理變數都不安全：
  · 資料庫規劃器（本例）           · JIT / 分支預測 / 快取層
  · 有 fast path 的程式（小輸入走另一條 code path）
  · 自動調整的系統（連線池、批次大小、重試策略）
⇒ 判別句換個問法：**這個系統會不會【看情況換做法】？** 會 ⇒ 代理量不到成長。
```

### 處置
```
· 要量成長 ⇒ 在【資料量真的不同】的副本上量（拋棄式 PG 灌 25/50/100%），
  **不要在原系統上用篩選假裝**
· 而不管量到什麼，**把執行計畫一起貼出來** ——
  🔴 沒有計畫，兩次讀數是不是同一條路，**你看不出來**
```

```

   ⇒ 同族，**不同機制**：它是【我改了對象的狀態】；本條是【資料一個字沒變，
      是系統自己換了做法】。本條的對象**完全沒被改動**。
:17309 「量具裡藏著一個假設,而它回給你一個乾淨的數字」（-4a）
   ⇒ **最接近的一條**，本條可視為它的一個新載體：

      :17309 的假設藏在【量具沒去找的東西】，本條藏在【被測物會不會換路】。

## B-2 🔴 「別人量過了」的分母,是**當初那個人在找什麼** —— 不是那份紀錄涵蓋的範圍
### (2026-08-22 主視窗 × 線 B `-3c`;**建議掛在 `:1086 ⑬` 底下,不獨立成節**)

### 判別句(先給)
> **「別人量過了」永遠要接一句:【他當時在找什麼?】**
> 🔴 **問題不同 ⇒ 同一個畫面會產生兩份完全不同的紀錄,而兩份都是誠實的。**

### 當時的情境(還沒踩,是在踩之前擋下的)

我要回答:那 7 格 🟡 裡,**有幾格的畫面【自己講出了它做不到什麼】**。
`spec §1-A-2` 已經有別的窗量過那 7 格,而其中三格逐字記著自陳
(`#20`「這一頁目前只能改上架狀態」/ `#25`「Email 是登入帳號,不能在這裡改」/
`#26`「這個身分是你自己選的、系統並未驗證」)。

**剩下三格,那份紀錄【一個字都沒提到自陳】。**

```
🔴 我差一點寫：「這三格是安靜的。」
   而正確的推論是：**別的窗量那三格時，問的是「做不做得到」，不是「畫面有沒有講」**
   ⇒ **他們沒有理由去記錄一句自陳** ⇒ **他們的沉默不是證據。**
```

### 🔴 它與既有兩條的分界(**我開檔讀過**)

```
:1086 ⑬「問題的形狀決定了答案的形狀」
  ⇒ **第一人稱**：我自己的問題限制了我自己的答案
    （退款帳本那例：驗了一堆不變量，而沒問「這張表有 writer 嗎」）
  ⇒ 本條是它的**第二人稱版**：**我讀的是【別人的】答案，而限制它的是【別人的】問題**
    —— 而我看不到那個問題，我只看到答案。

:1547 ㉓「有範圍的結論被引用成沒範圍的」
  ⇒ 那裡**原作者有寫下範圍**，是引用者把它丟了。
  ⇒ 本條**原作者從來沒寫下範圍** —— 因為從他的問題看過去，那件事根本不存在，
    **沒有東西可以寫。** ⇒ **連「省略」都算不上，它不在他的視野裡。**
```
> ### ⇒ 三者的差別在**那個範圍住在哪裡**:
> ### ⑬=在我的問題裡(我沒問)/ ㉓=在他的紀錄裡(我沒帶走)/ **本條=在他的問題裡(從來沒被寫下來)**

### 為什麼它特別難防
```
· 那份紀錄【完全誠實】，每個字都是真的，而且通常寫得很好
· 它的「沒有提到」看起來像「檢查過而沒發現」——
  🔴 而寫得越詳盡的紀錄，這個誤讀越強：**詳盡讓沉默更像結論。**
· grep 不會命中、測試不會紅、審查看那份紀錄也看不出來
  —— 因為**缺的東西不在那份紀錄裡，在【產生它的那個問題】裡**。
```

### 處置
```
· 引用別人的量測前，先找出**他當時的任務是什麼**（派工單 / 那節的標題 / 表格的欄名）
· 🔴 而最省事的判準：**他的欄位名，就是他的問題。**
  spec 那張表的欄是「缺的那半 / 最後量測 / 證據」——
  **沒有一欄叫「畫面有沒有自陳」** ⇒ 那件事不在它的分母裡。
· 對不上你要的問題 ⇒ **自己去看一次**，不要把他的沉默當成你的答案。
```

### ⚠️ 我沒做
```
· 這一條是【擋在踩之前】的，所以它**沒有事故實例** ——
  🔴 而那讓它比其他條弱一格：我不能拿出「因為沒問這句，所以錯成什麼樣」。
· 那三格我還沒去看（在等 `-86` 給我它那台鑽機的埠與資料來源）

## B-3 🔴 字集差一個字,而結論**翻面** —— 不是「漏掉一些」,是「把最好的講成最壞的」
### (2026-08-22 線 B `-3c`,具名自寫;**建議掛在 `:393 ⑤` 底下,不新開節**)

### 判別句(先給,而它是【動作】不是【自問】)
> **當我的尺回「沒有」,我有沒有把原文也印出來?**
> 🔴 **零命中的那一刻,正是最該看原文的一刻。**

### 當時發生什麼(有實例,不是風險)

我在量「後台那幾格的畫面,有沒有自己講出它做不到什麼」。自檢欄位寫成:
```js
有沒有自陳做不到: /目前不能|尚未|還不能|無法|未開放|停用|關閉/.test(inner)
```
而退款區畫面上的原文是:
> 「這個環境**沒有開放**「線上退款(TapPay)」的操作入口 —— 這是系統設定,不是這張單的問題。
>   要退這張單的款,請通知系統維護開放之後再操作。」

```
我的字集有「**未**開放」，原文寫的是「**沒有**開放」 ⇒ 我的尺 **回 false**。
```

### 🔴 而它與 `⑤` 已收的那幾例,**後果的方向不同**

```
⑤ 既有的實例（如 refundUnregisteredFailed 那例）：
   我以為「零覆蓋」，實際「有覆蓋」 ⇒ **我少報了一些東西** ⇒ 我會去補一個不需要補的洞

本例：
   我以為「這一格安靜」，實際那是**全站最好的一句自陳**
   ⇒ 🔴 **結論的方向【相反】** —— 我會把一個「做得最好的地方」寫成「會咬人的地方」
   ⇒ 而它會被拿去排工、被寫進給老闆的報告
```
> ### **字集太窄的後果不只是「撈不全」。**
> ### **當你數的是【一個好東西在不在】,漏掉它 = 宣告它不存在 = 把 ✅ 寫成 🔴。**

### 🔴 而 `boolean` 這個輸出形狀,讓那個相反**看不出來**

```
如果我輸出的是【命中的原文】⇒ 空的，我會去看一眼發生什麼事
而我輸出的是【true / false】 ⇒ `false` 是一個**完全正常、預期之內**的值
⇒ **它不會引起任何懷疑。** 一個布林值沒有「看起來怪怪的」這種狀態。
```
📌 ⇒ 這也是為什麼 `⑤` 的原判準(「先寫下你掃了哪些字面,再問這件事會不會用別的名字存在」)
**在這一發上救不了我** —— 那是一個**自問**,而我當時**沒有理由起疑**:
我的字集看起來很完整(七個詞),而 `false` 看起來很正常。

### ⇒ 要補的是一條【動作】,不是一句提醒

```
✅ 可操作：零命中時，**把被掃的原文（或它的前後 N 字）一起輸出**
   —— 我這次就是這樣被救的：我同時 dump 了全文，所以看到那句話。
   🔴 **救我的不是我更小心，是我剛好多印了一欄。**
⚠️ 代價：輸出會變長。而這條的建議是**只在零命中時才印**——
   有命中時原文本來就在你眼前。
```

### 🔴 而這個處方**擋不住什麼**(`-86` 補的,而它是對的)

```
**dump 原文只在「你掃對了地方」時有用。**
掃錯地方 ⇒ 你會 dump 出一段【乾淨的、無關的】原文，**而它讀起來像證據。**
⇒ 兩件事要一起做：①零命中時印原文 ②先確認那段原文【是你要找的東西該住的地方】
```

### 📌 而 `-86` 指出**兩個實例的救場方式不同,只有一種可複製**
```
它那發（字集 sendEmail|mailer|resend|寄送.*客人 ⇒ 0，而字集裡沒有 email/mail）
  ⇒ 靠【審查線把字集加寬重打】救回來 ⇒ **這條要有另一個人**
我這發
  ⇒ 靠【自己同時 dump 全文】⇒ **這條每次都做得到**
🔴 所以處方要寫成後者 —— **一條需要別人的處方，在一個人做事的那一刻是空的。**
```

### ⚠️ 我沒做
```
· 沒有回頭去看我今晚【其他】用同款 boolean 自檢的地方有沒有同樣的假陰性
  🔴 而我應該要 —— 這一條的價值有一半在那裡，而我還沒做。
· 沒有量「字集要多寬才夠」（那沒有答案；本條的處置刻意不走「把字集加寬」那條路，
  因為下一個詞永遠可能在字集外）
```

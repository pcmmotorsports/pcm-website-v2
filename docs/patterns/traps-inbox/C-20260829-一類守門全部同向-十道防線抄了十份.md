# 一整類守門【全部只守同一個方向】—— 那不是十道防線,是一道防線抄了十份

> 🔴 **先講清楚新在哪一軸, 否則它會被判成舊條**(查重時我自己差點這樣判):
> · 「負向斷言弱」「`every()` 對空陣列恆真」⇒ **正本已經有**, 不是本條的主句。
> · **㊾「排除形狀空清單恆真」也已經有** —— 而它講的是**一道守門的形狀**。
> 🔴 **本條新的是【分佈】:一整類守門裡, 正向的有幾格。**
>   查重時要用「分佈 / 全部同向 / 零正向」去打, **不要用「負向斷言」** ——
>   用後者一定命中舊條, 然後被判成不新。**而兩者的修法不同**(見文末)。
> 🔴 **「分佈那個角度零命中」的數法**(2026-08-29 當場跑, 你可以重跑):
> ```
> for k in 分佈 同向 十份 整類 抄了 幾格是; do
>   grep -c "^#\{2,4\} .*$k" docs/patterns/guard-and-instrument-traps.md docs/patterns/traps-inbox/*.md
> done            # ⇒ 六個字全部 0
> 正對照 grep -c '^## ' docs/patterns/guard-and-instrument-traps.md   # ⇒ 非 0，尺是活的
> ```
> ⚠️ **而這只證明「那六個字沒出現在標題行」** —— 不證明「這個概念不在檔裡」。
>    (traps-neighbours 那把尺也跑了, 前 8 名最高 0.3427, 而真正最近的 `㊾` 是**尺2 grep 撈到的**,
>     不在那 8 名內 —— **兩把尺又一次結論不同。**)

## 判別句(主句)
> **問一個守門【類別】:「這裡面有幾格是正向的?」**
> **答案是 0 ⇒ 那不是十道防線, 是一道防線抄了十份。**

## 實例(2026-08-29 線C 量到,分母與量法都附)
```
量測時刻 2026-08-29 03:1x · HEAD 105cdbe3 · 那批檔工作樹 dirty = 0
來源 ⟦b4-MONEY4⟧：67 格裸的負向斷言，逐格開檔判出「這一格自己在算錢」的 15 格
      其中歸類【價格外洩】的 **10 格**
```
🔴 **那 10 格全部是負向斷言, 10/10, 零例外** —— **數法**(逐格開檔判的, 清單在報告裡):
```
清單落點 ~/pcm-mailbox/線C-⟦b4-MONEY4⟧分母體檢-20260829.md 的「① 價格外洩」那節
重數:   grep -c '^ *[0-9]' <那節>          ⇒ 10 行
機械側佐證(不是同一把尺):
  那 10 格的斷言逐行看, 每一行都含 `not.` 或 `.toBeNull()` ⇒ 零正向
  ⚠️ 而「零正向」是**我逐格讀出來的**, 不是 grep 出來的 —— grep 分不出
     `expect(x).not.toContain(y)` 與 `expect(x.includes(y)).toBe(false)`
```
斷言長相:
```
not.toContain('price_store') · not.toContain('經銷') · not.toMatch(/price_by_tier/)
not.toContain('unit_price')  · not.toContain('wallet_balance') · …
```
📌 **它們守的是「不該出現的東西」, 而沒有一格證明「該出現的出現了」。**
🔴 **⇒ 一個回傳空物件 / 空字串 / 空清單的實作, 會讓這【整個類別】同時變綠。**
   而畫面上那是**十個綠勾**, 看起來比一個綠勾可靠十倍。

## 為什麼它比單格的病難發現
```
每一格【單獨看都是對的】—— 沒有任何一格寫錯
問題不在任何一格，在【這一組的組成】
⇒ 而 code review 是逐格看的 ⇒ 逐格看永遠看不到分佈
```
📌 **一個只在「全部加起來」那一層才存在的缺陷, 對逐格審查是隱形的。**

## 同一批裡的第二個形狀(同族,更安靜)
```
expect(result.every(p => p.price >= 0 && p.price <= 3000)).toBe(true)
🔴 `every()` 對空陣列【恆真】⇒ 篩選回傳 [] 時這一格照樣綠
```
⇒ 它連「負向」都不是, 是**正向的形狀而空集合恆真** ⇒ **更難看出來**。
⚠️ 這一格**是舊條**(`naked-cells.py` 檔頭自己就列了)—— 放在這裡只為了說明:
   **同一類裡可以混著兩種失效, 而它們都指向同一個「空的世界」。**

## 修法 —— 🔴 **一類補【一格】就夠,不是把 10 格都改寫**
```
不得出現 price_store      ⇒ 而 general 價【必須出現】且是個具體的值
不得出現「經銷」二字       ⇒ 而畫面上【必須有】價格那一列
select 不得含 unit_price   ⇒ 而它【必須含】小計那一欄
```
📌 **一格正向的同伴, 就把「什麼都沒有」那個世界從綠變紅。**
✅ **其餘 9 格繼續守「不該出現的沒出現」—— 它們沒有壞, 不要一起改。**
🔴 **這正是本條與舊條的修法差別**:
```
舊條（負向斷言弱）  修法 = 【這一格】改寫
本條（一類全同向）  修法 = 【這一類】補一格正向的
⇒ 兩者的動作、成本、與誰該做，都不同
```

## 與既有那三條的關係(我開檔讀過,逐條說為什麼不同族)
| 既有條目 | 它講的 | 為什麼不是本條 |
|---|---|---|
| `㊾` 排除形狀空清單恆真 | **一道守門的形狀**(排除 vs 只允許) | 它答「這一道會不會恆真」;本條答「**這一類裡有沒有人守另一個方向**」 |
| 恆真斷言假扮負向對照 | 斷言裡沒有受測物 | 那是**斷言自己壞了**;本條的每一格都好好的 |
| 一次成功的負向驗收讀起來像正向 | **閱讀者**的誤讀 | 那是報告層;本條是**測試組成**層 |

🔴 **而 ㊾ 值得互相指標** —— 它與本條合起來才是完整的問法:
```
㊾   這一道守門，清單空掉時會放行還是會擋？   ← 單道
本條 這一類守門，有幾格是正向的？             ← 分佈
```

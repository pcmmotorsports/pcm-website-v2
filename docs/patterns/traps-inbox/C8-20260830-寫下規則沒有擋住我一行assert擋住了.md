# 現場

我今晚在重驗板子時,用**錨**去定位一列:
```python
if 'b4-XXX' in line and line.startswith('| open |'):
    ...
    break          # ← 取第一個命中
```
而**交叉引用**讓那個錨出現在別的列上,而那一列在檔案裡更前面 ⇒ **我改到了錯的列。**

## 🔴 而關鍵不是我犯了這個錯,是**我犯它的時候手上正拿著那條規則**

```
我今晚【寫過三次】「不要用錨取第一個命中」——
  第一次:發現兩段戳記貼錯列時,寫進給 -b9 的回報
  第二次:寫進發給 -1c 與 -e9 的做法說明(還附了「先數它命中幾列」的具體做法)
  第三次:寫進板子上那一列的重驗戳
🔴 而【第四次】我又犯了 —— 就在我量測「我自己有沒有照規矩做」的那一發裡
```
📌 **三次都寫得很具體:帶實例、帶行號、帶後果。而具體沒有幫上忙。**

# ✅ 真正擋住我的東西

`-1c` 給的一行:
```python
hits = [n for n,l in enumerate(L) if key in l and l.startswith('|')]
assert len(hits) == 1, hits          # ← 就是這一行
```
**下一次我再用錯的鍵,它當場炸,並把命中的那幾行號印給我看。**

> ## **差別在於:一條規則要我【記得】,而一個 `assert` 在我【忘記的那一刻】替我停下來。**

## 🔴 而規則之所以擋不住,有一個機械原因,不是意志力
```
我用錨取第一個命中時,**程式不會報錯**
⇒ 它回一個【看起來完全正常的列】,而我接著在那一列上做完整套工作
⇒ ⇒ **違反與遵守,在我的螢幕上印同一個東西**
```
📌 **⇒ 判別句:一條寫給自己的規則,若【違反它不會產生訊號】,那它只是一句提醒,不是防護。**

# ✅ 可執行(最小形狀)

```
凡是「用某個字串去定位【唯一一個】東西」的程式碼 ⇒ 下一行加 assert 只命中 1
  · 找板子的某一列        · 找設定檔的某一行
  · 找函式的某一個定義點  · 找交件檔的某一節
⚠️ 而 `-1c` 加的半格要一起帶:**「事欄文字」也會 >1**(被別的列引用過)
   ⇒ **不是「換一個比較好的鍵」就沒事,是【每一次都 assert】。**
```
🔴 **而順序很重要**:先寫 `assert`,再寫那條規則 —— 不是反過來。
📌 因為**寫完規則的那一刻,人會覺得這件事已經處理完了**
(那正是 memory `feedback_writing-the-rule-feels-like-obeying-it` 記的那件事)。

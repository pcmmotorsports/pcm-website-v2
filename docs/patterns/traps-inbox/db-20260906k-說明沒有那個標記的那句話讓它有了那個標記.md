# 一句說明「本檔**沒有**這個標記」的話,讓本檔**有了**那個標記

> 線【DB】`-db` 2026-09-06 · ⟦0e-DDLINTOVC-MARK⟧ commit 當下被閘擋下才發現。

## 現場

我在 `supabase/migrations/20260905160000_….sql` 的檔頭補一個新標記,並想說清楚它**刻意不帶**另一個:

```
--     ⚠️ 本支**沒有** `-- pcm:never-apply`, 而那是刻意的:那是另一個軸(「要不要貼」)
```

而 `scripts/state-gates.sh` 判斷一支檔是不是 `never-apply` 的方法是
**檔頭前 20 行的【子字串】比對**。

⇒ 它把我這句**解釋**讀成了**標記本身**。
⇒ `docs/reference/order-state-gates.md` 的分母當場從「排除 **4** 支」變成「排除 **5** 支」。
⇒ commit 被 `state-gates-freshness-gate` 擋下,我才看到。

## 形狀

🔴 **一句用來澄清「這裡沒有 X」的話,因為它必須寫出 X 的字面,而讓 X 成立。**

這不是 typo,也不是誤用 —— **那句話寫得完全正確**,而正確地寫出它就足以造成後果。
📌 只要判別方法是「字面在不在」,**否定句與肯定句就長得一樣**。

## 而最值得記的是時間差

**同一天稍早**,我在 `scripts/lib-migration-header-marks.sh` 的檔頭親手寫下:

> 只看**檔頭前 20 行**。一支檔中段【提到】某個標記字面,不該把它自己變成那一型。

⇒ 🎯 **我寫下那條規則,然後在幾個鐘頭內自己踩進去。**
而我踩進去的方式,正是那條規則字面上**沒有涵蓋**的那一種 —— 它講的是「中段提到」,
而我這句在**前 20 行之內**,是我為了解釋標記而寫的。

## 判別句

要在一個會被機器讀的地方**提到**某個標記/關鍵字的字面時,問一句:

> **「讀這個檔的機器,分得出我是在【用】它還是在【講】它嗎?」**

分不出 ⇒ **把字面拆開寫**。例:寫 `pcm 冒號 never-apply`,不要留完整字面。

## 這一則答不出什麼

- 我**沒有掃**過 repo 裡還有幾處同型(某支檔的註解裡提到某個機器可讀標記的完整字面)。
  ⇒ 那要一個掃描,而它今天不存在。**這是已知缺口,不是「掃過了是 0」。**
- 「拆開寫」這個做法**降低可讀性** —— 下一個人搜那個字面時會搜不到這一句。
  🛑 這是一個真的取捨,不是純贏。

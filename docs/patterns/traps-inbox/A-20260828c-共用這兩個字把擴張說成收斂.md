# 🔴 「共用」這兩個字,把一個【擴張】的動作說成一個【收斂】的動作

> 投稿窗:線A(`pcm-website-v2-ea`)· 2026-08-28
> 主視窗指定:判別句用原句、附一個可執行的檢查。**我判它不同族**(理由在 §4)。

---

## 1. 判別句(兩句,主視窗指定原字保留)

> **「共用」這個詞讓它讀起來像在【減少】重複, 而實際上是在【增加】一個消費者。**
>
> **⇒ 那兩件事的風險方向相反:合併是收斂, 新增消費者是擴張。**

📌 收成一句:**一個詞把一個擴張的動作, 說成一個收斂的動作 —— 而沒有人會去質疑「共用」這兩個字。**

## 2. 可執行的檢查(主視窗給的,我照收)

> **看到「共用」時, 先數【現在有幾個消費者】** —— **0 或 1 的話, 那不是共用。**

⚠️ 而數的時候要**數真的消費者, 不是提到它的地方**:
```
grep -rn '<元件名>' apps packages --include='*.tsx' --include='*.ts' | grep -v '\.test\.' | grep -v '/\.next/'
⇒ 而其中【註解裡提到它】的那些不算。逐行看, 不要只看總數。
```

## 3. 當天發生的事(2026-08-28,片A 的 plan)

那份 plan 逐字寫:
> 「把顧客站的 `VehicleCombo`(`apps/storefront/src/components/VehicleSelect.tsx:83`)
>  **搬進 `packages/ui`, 兩站共用。不複製一份到 admin。**」

**而我去數消費者:**
```
apps/storefront  4 個掛載點(MobileVehicleSheet:228/243/258 · CascadeFilterTop:105/116/128
                 · account/InlineVehicleForm:209/233)
apps/admin       grep -rc 'VehicleCombo' apps/admin/src  ⇒ 0        (2026-08-28 21:xx 當場數)
```
🔴 **⇒ 「兩站共用」描述的不是「把兩份合起來」, 是「把一個顧客站元件, 拿去服務一個【還沒寫的】後台用途」。**

### 而它的代價是可以列的,只是那個詞讓人不去列
```
props 13 個, 其中 4 個是為顧客站的具體場景長出來的:
  variant:'catalog'|'finder'|'form'  三個值都以顧客站的畫面命名
  slotLabel / autoFocus(逐字「只給桌機選車列的廠牌欄用」)
  onDraftTextChange(Q8=A, 為手機選車面板的「清除」鈕長出來, 且帶一條「卸載時不回報」的契約)
資料/邏輯依賴 4 支, 全在 storefront
CSS class 三族, storefront 有 9/8/5 個檔命中、packages/ui 全部 0
```

### 🔴 而還有更深一層:目的地也不是它看起來的那個東西
```
packages/ui 現在只有三個檔:index.ts + filters/cascadeFilterReducer.ts + 它的 test
  cascadeFilterReducer.ts  289 行 / react 0 / JSX 0 / import 0   ⇒ 純邏輯
  packages/ui/package.json  grep '"react"'  ⇒ 零命中
  index.ts 逐字:「@pcm/ui — design tokens + 共用 UI 邏輯(殼、隨 slice 增長)」
⇒ 搬一個 React 元件進去 = 【第一個元件】+ 第一次把 react 拉進那個 package 的依賴
```
📌 **⇒ 那不是「放進既有的抽屜」, 是【改變那個抽屜是什麼】。**
🔴 **而那句話讓「搬進 packages/ui」從一個【搬運動作】變成一個【架構決定】—— 兩者要的批准層級不同。**

⚠️ **順帶量到一件, 而它讓「共用」這個字更可疑**:
`@pcm/ui` 唯一那支 reducer 的消費者**也全在 storefront**(三支 `app/dev-preview/*`),後台 0。
⇒ **那個叫「共用」的 package, 至今沒有任何一個東西是兩站真的共用的。**

## 4. 查重紀錄(兩把尺,2026-08-28 21:xx)

**尺一** `traps-neighbours.py`,**分母 1723(當場切)**,已落 `logs/traps-neighbours.jsonl`:
```
1. 0.2197  正本 :17843  兩個證據看起來獨立, 而它們共用同一個東西
5. 0.1947  正本 :15973  寫得【太嚴】的限定沒有人會來質疑它 —— 因為它看起來像謹慎
6. 0.1937  memory/feedback_scoped-claim-this-only-affects-X
```
**尺二** 機制關鍵字 grep 標題行(`共用`/`一個詞`/`措辭`/`名字`/`讀起來像`/`方向相反`/`消費者`/`重複`)
⇒ 命中 10 條;開了 **3 條**。

**為什麼判它不同族:**
| 開過的 | 它講的 | 與本條的差別 |
|---|---|---|
| `:15973` 太嚴的限定沒人質疑 | 一句**限定**讀起來像謹慎 ⇒ 沒人來打它 | 🔴 **它講「沒人查」, 本條講「方向被反過來」**。太嚴的限定至少方向是對的(偏保守);「共用」是**把擴張說成收斂** |
| `:3897` 「沒有人 X 過」讀起來像貢獻 | 一個**沒有分母的 0** 被讀成成就 | 相鄰。而本條的 0 **有分母而且我數出來了**(admin ⇒ 0)—— 病不在數字, 在**那個詞讓人不去數** |
| `:17843` 兩個證據共用同一個東西 | **證據的獨立性**是假的 | 只是共用「共用」這個字, 機制無關 |
| `:6236` 「重複」比「過期」更難發現 | 兩份各自自洽 ⇒ 難發現 | 相鄰:那是**已經有兩份之後**;本條是**還沒有第二份, 而那個詞讓人以為已經有了** |

⚠️ 工具自列的六種已知失效照舊適用,**本投稿不宣稱查全**。

## 5. 而它與 `#953` 是一組(收稿人可考慮互相指標)
`docs/phase-1-backlog.md` `#953` 記的是「同一條等式五份拷貝,而它們彼此不知道對方存在」。
🔴 **而那五份至少【住在同一個等式上】** ⇒ 有一天有人動那條 CHECK 時會撞到。
而「複製一份 `VehicleCombo` 到後台」比它更糟:
**兩邊各自演化, 而沒有任何東西會把它們放在一起看** ——
📌 它壞掉的方式是**後台的選車行為與顧客站不一樣**, 而**那不會紅, 只會讓員工覺得後台比較難用**。
⚠️ 而我**沒有量「顧客站那份多久改一次」** ⇒ 「會漂」是一個合理的擔心, **不是一個量到的頻率**。

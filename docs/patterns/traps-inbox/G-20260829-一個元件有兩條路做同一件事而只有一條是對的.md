# 🔴 一個元件有**兩條路**做同一件事, 而只有一條是對的 —— 錯的那條長得一樣合理

> 2026-08-29 · 線G `-1c` · 由 Sean 一句話觸發, 主視窗 `-48` 要求投條並給了判別句雛形。
> 🔴 **這不是「誰寫錯了」** —— 是那個 API 讓錯的那條**看起來一樣合理**。

---

## 事情怎麼被發現的

Sean 看券列表的截圖,逐字:
> **「然後文字都要對齊標題左側,不要一下左一下右」**

一欄之內,**標題在左而內容在右**。

---

## 🔴 成因:同一支檔的兩行, 而它們吃不同的欄位

```
apps/admin/src/components/shared/admin-data-table.tsx
  :147  表頭  className={col.alignRight ? `${TH} text-right` : TH}
  :165  內容  className={[TD, col.alignRight && 'text-right tabular-nums', col.className]…}
🔴 表頭【只吃】col.alignRight ／ 內容格【才吃】col.className
```

**⇒ 於是有兩條路可以把一欄推到右邊:**

| 寫法 | 結果 |
|---|---|
| `alignRight: true` | 表頭與內容**一起**移 ✅ |
| `className: 'text-right'` | 🔴 **只移內容**, 表頭留在原地 |

---

## 🔴 而錯的那條**什麼都不會紅**

```
TypeScript  不紅 —— className 是合法欄位，值也是合法字串
lint        不紅
測試        不紅 —— 沒有人斷言「表頭與內容同側」
畫面        看起來也不奇怪，除非你注意到標題在左而數字在右
⇒ 唯一會發現它的，是【一個看著整頁的人】
```

---

## 📊 而它不是偶發 —— **三支列表頁, 兩支選了錯的那條**

```
coupons-table.tsx    className text-right = 2   🔴 錯的那條（我寫的）
customers-table.tsx  className text-right = 2   🔴 錯的那條（不是我寫的）
products-table.tsx   alignRight = 1             ✅ 對的那條
orders-table.tsx     兩者皆 0                    —（沒有靠右的欄）
```
📌 **⇒ 兩個不同的人、不同的時間, 各自選到同一條錯的路。**

---

## ✅ 判別句

> **一個元件同時提供【語意化的旗標】與【原始的 `className`】時,**
> **問一句:這兩條路做出來的結果一樣嗎?**
> **不一樣 ⇒ 那個 `className` 是一個陷阱, 而它不會有任何東西紅。**

🔴 **而為什麼「小心一點」沒有用**:兩個欄位名字**都指向「這一欄的樣式」**,
而**沒有任何東西說「要移整欄請用這一個」** ——
寫的人不會知道自己選了哪一條,因為他不知道有兩條。

---

## ⇒ 機械擋法(兩種, **都要動共用元件** ⇒ 鐵則 12⑥)

```
甲 · 在共用元件那一層，把 col.className 裡出現 text-right / text-center 當成錯誤
   （要移整欄請用 alignRight）
   ✅ 直接消滅那條錯的路
   🔴 而它會擋掉「我真的只想移內容」那種正當用途 —— 而那種用途存不存在，沒有人量過
乙 · 讓表頭也吃 col.className
   ✅ 兩條路結果變一樣 ⇒ 陷阱消失
   🔴 而它會讓既有兩支頁面【當場改變外觀】（表頭跟著跑到右邊）
   ⇒ 那是視覺改動 ⇒ 要 Sean 看過
🛑 我不挑。而本片沒有裝任何一個 —— Sean 看的是券那一頁，我不替他擴大射程。
```

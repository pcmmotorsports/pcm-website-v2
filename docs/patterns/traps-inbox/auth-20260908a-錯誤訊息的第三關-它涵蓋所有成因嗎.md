## 病史(同一句話一天內寫錯兩次,而兩次的錯法相反)

那顆碼對應的是「授權閘回了 `null`」(後台改客人信箱那一片的 `customer_email_denied`)。

```
v1(過寬)「你的登入可能過期了, 或者這個動作只有管理者能做。」
   ⇒ Sean 當天把閘放寬成任何登入員工 ⇒ 🔴 那一種成因【不存在了】, 而句子還留著它

v2(過窄)「你的登入過期了, 或這個頁面開太久。」
   ⇒ 🔴 codex 打掉:那個閘回 null 還有別的成因 ——
        有效票之下 staff 查詢失敗 · 帳號被停用 · 備援登入沒有具名操作者;
        而 **Origin 不符與「頁面開多久」無關**

v3(現行)「改不了 —— 系統沒有讓這個動作通過。請先重新登入再試一次;
           還是不行請找管理者或工程師(不是你填錯東西)。」
```

🛑 **注意 v2 是為了「更精確」而寫的** —— 它比 v1 更精確,**也更錯**。
⇒ 📌 **判準不是「講得更精確」,是「講一句在每個分支下都不會錯的話」。**

## 🔴 為什麼**過窄比過寬危險**(這是方向,不是程度)

```
過寬 ⇒ 他一頭霧水 ⇒ 他會來問        ⇒ 🟢 錯誤有回饋路徑
過窄 ⇒ 他去做一件【對他的情況沒有用】的事(去重新登入, 而問題是帳號被停用)
     ⇒ 🔴 他會以為【自己試過了】⇒ 那條路在他心裡結案
     ⇒ 而系統這一端什麼都沒發生 ⇒ **零訊號**
```
🎯 **一句過窄的錯誤訊息會【關掉】使用者的下一個動作** —— 而那正是錯誤訊息本來要打開的東西。
📎 同形狀:`red-is-not-the-same-as-guarded`(紅了不等於守到)—— 這裡是「回應了不等於接住了」。

## ✅ 落筆當下的自檢(接在既有兩關後面)

```
① 他做得到嗎                       ← 既有(:19983)
② 做完有人會收到嗎                 ← 既有(:19983)
③ 他照做會不會製造一個新的錯       ← 既有(memory a-fix-message-…)
🔴 ④ 【本關】這個碼有幾種成因, 而我寫的下一步在【每一種】下都對嗎
```
**④ 的做法是機械的**:去讀那支函式的**每一條** `return null` / `throw`,不要憑印象數。
有一種成因對不上 ⇒ 那句話要**往中性收**,而不是把那一種也塞進去(塞到第三種就沒有人讀得完)。

## ⚠️ 這一條不涵蓋什麼

- **不是**「錯誤訊息要模糊」—— v3 仍然說得出「不是你填錯東西」,那句有判別力而且每個分支下都對。
- **不涵蓋成功訊息**:那一側的病是另一種(把「我做了」講成「世界變了」)。
- 🔴 **未量**:我沒有觀察過「員工看到 v2 之後真的會停手」——
  那是推的,依據是這一族的既有紀錄,**不是我做的觀察**。標在這裡,不要當成實錘引用。

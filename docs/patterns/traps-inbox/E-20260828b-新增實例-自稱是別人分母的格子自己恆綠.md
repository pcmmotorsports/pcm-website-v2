# 【新增實例】一個【自稱是別人分母】的格子,自己是恆綠的 —— 它把名單寫對了,只是名單上沒寫自己

> 2026-08-28,線B(`-d3`),假守門盤點第三輪。**不推翻既有任何一條。**
> 母題 = **量具與它要量的病同族,而它不會把自己算進去。**

## 事發

`apps/admin/src/app/print/orders/[id]/shipping/[shipmentId]/page.test.tsx:185`
標題**逐字**:

```
正向:一切正常時可以印(否則下面六格全部恆綠)
  expect(block({})).toBeNull();
```

它存在的**唯一理由**,就是當下面那六格的分母 —— 「如果這一格失效,那六格全部沒有意義」。

**而把 `shippingDocBlocker` 改成 `if (true) return null;`(它對任何輸入都不擋)之後:**

```
本格          ⇒ 綠
它點名的六格   ⇒ 全部綠
```

📌 **它說對了那六格的處境,而它自己也在那個名單裡 —— 只是名單上沒寫自己。**

## 修法:先證那把閘是活的,再斷言「這一個世界不擋」

```ts
expect(
  block({ detail: { cancelledAt: '2026-08-05T02:00:00+00:00' } }),
  '連已取消的單都不擋 ⇒ 這把閘整支沒在跑, 下面那個 null 不算數',
).not.toBeNull();
expect(block({})).toBeNull();
```
同一發突變下當場紅。同族的 `:212`(面6 反向)同修。

## 📌 判別句

**這一格如果是【別人的分母】,那它自己的分母是誰?**

⚠️ 這種格子最難被懷疑,因為**它的標題就在講恆綠**——
讀的人會把「它在談這個問題」讀成「它處理了這個問題」。

### 我開了 `:21728`,判它**同母題、不同實例**

那一條:一個窗找別的窗,**把自己的舊 socket 名列進「查無」的分母**,
而「查無」對【已消失】與【改名還活著】印同一個字。
```
共同的母題:列名單的人沒有把自己算進去
不同的地方:那一條的名單是【搜尋目標】, 我這條的名單是【依賴我的那些測試格】
          那一條的病在「我是誰」, 我這條的病在「誰在替我背書」
```
⇒ **落成新實例,不改那一條。** 兩條之間互相知道對方存在(本檔這一段就是那條路)。

# 順帶兩則:**分母守門本身也有射程**

## ① 分母守門要涵蓋【所有合法的世界】,不是只涵蓋主線那個

兩張列印頁被擋時,印的**不是空白** —— 是**一張只有 `<Alert>` 的紙**
(`shipping/[shipmentId]/page.tsx:82-86` 的註解逐字講這件事)。
⇒ 錨若只釘 `h1`,**會把那個合法世界誤判成「沒渲染」** = 一整族假紅。
```
expect(container.querySelectorAll('h1, h2, [role="alert"]').length).toBeGreaterThan(0)
```
📌 **寫錨之前要先數:這支元件有幾種【合法的長相】?**

## ② 一個對【整體】成立的結構性字面,對【它的一段】不成立

`expectRead(src)` 用 `toContain('import')` 當分母 —— 對整份 `.tsx` 成立。
而同一招用在 `raw.slice(0, 400)` 上:**`shipment-section.tsx` 的前 400 字整段是檔頭註解,沒有 `import`**
⇒ 當場一發假紅。切片版改成只量長度(`expectReadHead`)。
📌 **分母守門的射程,跟著它拿到的那一份輸入走,不跟著檔案走。**

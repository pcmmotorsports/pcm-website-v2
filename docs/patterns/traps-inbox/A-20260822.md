## 條 B · Next 把中文塞進跳脫字串 ⇒ 只數 raw 會得到一個乾淨的 0【安靜】

### 當天發生什麼(同日,查「請款狀態」那一格在不在畫面上)
```
grep -c '訂單' orders.html  ⇒ 1
```
那頁上「訂單」兩個字**至少出現幾十次**。⇒ **我的正對照當場告訴我尺壞了。**

**原因**:Next 的 RSC payload 走 `self.__next_f.push([...])`,裡面的中文是 **`\uXXXX` 跳脫**的。
同一個字在同一份 HTML 裡有**兩種寫法**,而 `grep` 只認你打的那一種。

```python
def count(html, w):
    esc = ''.join('\\u%04x' % ord(c) for c in w)
    return html.count(w) + html.count(esc)
```
改成兩種都數之後:`訂單` ⇒ **151**。

### 為什麼危險
🔴 **只數 raw 會得到一個乾淨的 0,而那個 0 是量法造的。**
而這一族的用途正好是**下否定斷言**(「這個字沒有出現在畫面上」)
⇒ **錯的方向剛好是最貴的那個方向。**

### 判別句
> **我在數的這個東西,在這份檔裡只有一種寫法嗎?**

**過關的做法**:每一發都帶**正對照** —— 拿一個你**確定一定在**的字用同一把尺數一次。
回 0 ⇒ 是語法/編碼問題,不是資料問題。

📌 **同族**(canonical 已有前兩個成員,這是第三個):
```
:6659  剝掉 <script> ⇒ RSC payload 整塊消失      （我主動丟掉資料）
:6659  curl 逾時截斷 ⇒ 同一個 URL 兩次不同大小   （傳輸層丟掉資料）
本條   中文在 payload 裡是跳脫的                 （資料在, 而我的字集比它窄）
memory `reference_git-grep-silently-ignores-backslash-b`：git grep -E 不吃 \b 且靜默不匹配
⇒ 四者同一形狀:**尺的字集比你以為的窄,而它不會抗議。**
```

## 條 C · 一個 `0` 讓我差點判定「這條路走不通」,而它是量法造的【安靜】

**同一晚第三次同族,而這次的載體是【版面】不是文字。**

### 當天發生什麼
我要回答「84px 的側欄軌,加一行字塞不塞得下」。我量:
```js
nav.scrollHeight === nav.clientHeight   // 876 === 876
```
⇒ 我讀成「**餘裕 0,已經滿了**」⇒ 差一步就要寫下「這條路走不通,只能改字級或換詞」。

**而它是錯的。** `nav` 是 **flex 撐開的容器** —— 那兩個值相等**只代表沒有溢出**,
不代表內容剛好填滿。真正的餘裕要拿**最後一個項目的 `bottom`** 減 `nav` 的 `top`:
```
誤讀:餘裕 0px
實際:內容高 506 / 容器高 876 ⇒ 餘裕 370px
在最緊的 1280×720 也還有 98px, 加一行(+51px)之後還剩 47px
```
⇒ **差了 370px,而兩個讀數都是「真的量到的數字」。**

### 判別句
> **我量的這個 0,是「東西剛好填滿」還是「我的量法看不到剩下的空間」?**

**過關的做法**:量**內容自己的邊界**(最後一個子元素的 `bottom`),不要量容器的自陳。
📌 `scrollHeight === clientHeight` 只回答「有沒有溢出」,**它不回答「還剩多少」**。

### 這條與本檔前兩條是同一族,而三條的載體都不同
```
條 A  textContent   對受控 <details>   ⇒ 0        （DOM 讀法）
條 B  grep raw      對 RSC 跳脫中文    ⇒ 0        （字集）
條 C  scrollHeight  對 flex 容器       ⇒ 餘裕 0    （幾何）
🔴 三種完全不同的工具, 同一個形狀:**量法選錯 ⇒ 得到一個乾淨而錯的 0。**
   而 0 特別危險, 因為它讀起來像「我已經確認過了」。
```

> 寫取消區文案的人**正確地**告訴員工去退款區;寫退款區的人**正確地**在旗標關著時不渲染入口。

### 三個等級(由差到好)
```
① 不給         按鈕不渲染 / 區塊空白        ⇒ 員工不知道為什麼, 而【他手上正拿著一句叫他來這裡的話】
② 說           擋住, 而且講原因與下一步去哪
③ 預告         擋住 + 講原因 + 【告訴他什麼時候會亮起來】
```

### 同一個後台裡,三種都有
**① 的實例(我修掉的那個)**:旗標關著時,「退款」區塊渲染成**只有標題、底下一片空白**,
而**同一張畫面上的取消區正在叫他去那裡**(逐字「請到本頁最下方的「退款」裡處理」)。

**②③ 的實例(同一個後台,批次出貨那個對話框)**:
```
沒有採購列的品項         ⇒ 【那顆「貨到了」根本不渲染】             （①,但這裡是對的:見下方)
按下有鈕的那一顆         ⇒ 「這個品項目前沒有可以登錄到貨的採購（可能還沒下單,或原本
                            那筆已經作廢）。請先到訂單頁的「採購」區塊補上要向誰訂
                            （或選「店內現貨」）,再回來登錄。」                       （②)
兩顆送出鈕 disabled      ⇒ 「這些品項現在都不能出,其中還有在等到貨的。貨到了就按右邊的
                            「貨到了」先登記到貨,**登記完這裡就會亮起來**。」          （③)
```

### 🔴 而「不給」不是永遠錯的 —— 判準是**別的地方有沒有話在指著它**
上面那顆不渲染的「貨到了」是**對的**,因為同一個畫面上有一整段話解釋整批的狀況。
而空的退款區是**錯的**,因為指著它的那句話**在另一個區塊**,而那個區塊不知道這裡是空的。

### 判別句
> **有沒有任何一段文字,正在把人指向我這個【不給】的地方?**

📌 這一條的價值在於:①②③ 在程式碼裡**看起來一樣安全**(都 fail-closed、都不會漏行為),

## 我量了什麼

我要答一個很具體的問題:**「這張真訂單上,員工有沒有辦法登錄『我跟供應商訂貨了』?」**

```
量法:main 的 textContent 裡找「採購(向供應商訂貨)」 ⇒ 0 命中
對照:同一把尺, 另一張【已經有採購紀錄】的訂單      ⇒ 1 命中
⇒ 讀起來是一組乾淨的兩世界對照:有採購的那張有入口, 沒有的那張沒有
⇒ 我差一步就要寫下「一張還沒下訂的單, 畫面上沒有下訂的入口」——那會是一個很嚴重的假缺陷
```

## 為什麼那個 0 是假的

商品卡是 **React 受控的 `<details>`**。關著的時候,**它的 body 根本沒有掛進 DOM**。
真的用滑鼠點開之後再量:入口、表單、二十幾家供應商的下拉、七個欄位,**全部都在**。

🔴 **而這個坑特別會咬人,原因是我以為我已經避開它了:**
```
一般的 <details>   ：關著時內容【在 DOM 裡】只是不顯示 ⇒ textContent 讀得到
                     ⇒ 這正是「別用 innerText、要用 textContent」變成常識的原因
React 受控 details ：關著時內容【不在 DOM 裡】        ⇒ textContent 也是 0
```
兩者在 `querySelector('details')` 上長得一樣,在 `outerHTML` 上也長得一樣。
⇒ **「我已經避開 innerText 那個坑了」這件事本身,讓我更不會去懷疑這一發。**

## 判別句

> **我這個 0,是「畫面上沒有」還是「DOM 裡還沒有」?**

**過關的唯一做法**:**真的點開它,再量一次。** 讀 DOM 的任何一把尺都答不出這一題 ——
因為它們讀的都是「現在掛著什麼」,而問題正是「還沒掛上去的那些」。

📌 而「點開」要用**真的點擊**(Playwright `locator.click()`),不是 `evaluate` 裡合成的 `.click()`。

## 🔴 而這裡就是接到另一半的地方

**點開它,就改變了被量的東西。**
⇒ 這一族沒有「不打擾地量一次」這個選項:
```
不打開 ⇒ 尺讀不到（我這一半）
打開了 ⇒ 版面已經不是原來那個（-5b 那一半）
```
⇒ **所以要量兩次、而且要講清楚每一次量的是哪個世界。**
**只做其中一次、卻用全稱句寫結論,就是這一族出事的方式。**

## 這一半擋得住什麼
一整族「**這個功能沒做**」的假缺陷。
而假缺陷的下場不是被發現,是**有人真的去把它做第二次**。

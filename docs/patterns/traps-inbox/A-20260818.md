## 1. 🔴 量具的窗開多寬,會直接改變「有幾處出問題」這個答案 —— 而它報的是**假陽性**

### 事故(2026-08-18 A 窗,盤 `packages/adapters` 無上界查詢)

```
任務    找出「沒有 .limit( 也沒有 .range( 的 select」（它們會靜默吃 PostgREST db-max-rows）
第一版  正規式:從 .from(' 往後切【600 字元】，在窗內找 limit/range/single   ⇒ 報 16 處
第二版  改成每處往後看【20 行】                                              ⇒ 剩 2 處
```

### 為什麼第一版會多報 14 處(逐處開檔看到的,不是推測)

```
SupabaseProductAdapter.ts:273   .limit(limit) 在【15 行外】—— 中間隔著一段 orderDesc 三元式
SupabaseProductAdapter.ts:286   走 fetchAllPaginated + .range(from,to) ⇒ 界在【外層函式】給
SupabaseProductAdapter.ts:331   .limit(poolLimit) 寫在 .order 之後
email_outbox 5 處                全是 insert / update ⇒ 本來就不需要【讀取】上界
VehicleAdapter:79 / AddressAdapter:85   是 delete
```

### 🔴 這一則與大多數量具坑**方向相反**

```
多數量具坑   假陰性 —— 該紅的沒紅、該找到的沒找到
本則         假陽性 —— 把【有界但寫得遠】判成無界
```
> **而假陽性的代價不是「沒發現」,是【派 16 個人去修 14 個不存在的問題】。**

⚠️ 它還有一個更貴的二階效果:**一份多報的清單會稀釋真的那兩處**。
下一個人掃過 16 條,對每一條的注意力只剩十六分之一 —— **真的那兩處反而更不容易被看見。**

### 判別句

> **我的量具會不會把【有界但寫得遠】誤判成無界?**
> 換句話說:**我判定「沒有 X」的那個範圍,是誰決定的 —— 程式的結構,還是我隨手挑的一個字元數?**

### 修法(不是「窗開大一點」)

```
1 🔴 報「有 N 處缺 X」之前，【先隨機開三處看】——
  假陽性在開檔的第一秒就露餡（.limit 就在那裡），而它在 grep 輸出裡完全看不出來。
2 判定範圍要跟著【程式結構】走（函式、陳述式），不要跟著【字元數/行數】走。
3 🔴 不要宣稱修正後的版本是對的。
  我第二版用 20 行窗，它一樣有上限 —— 【這是縮小誤差，不是消除】。
  報數字時把這句一起報，讀的人才知道那個數字的性質。
```

## 2. 🔴 `git checkout <檔>` 當突變還原手段:**靶檔乾不乾淨決定它是還原還是毀損**

> 🏁 **本則已直接寫進 `docs/patterns/mutation-harness-restore.md` §4-b**(commit `ad60fb3f`),
> **不需要再併一次。** 這裡只留指標,免得收割窗以為漏了。

一句話:同一輪突變連做三發,前兩發靶檔乾淨 ⇒ `git checkout` 正確還原;
第三發靶檔**有未 commit 的真改動** ⇒ **它把突變和我的工作一起還原掉了,而 rc=0、沒有訊息、`git status` 變乾淨**。
判別句:**我要丟掉的那個改動,和我要留下的那個改動,現在住在同一個檔裡嗎?**
—— **而這個答案在一輪突變的【中途】會從「否」變成「是」。**

## 3. 🔴 「遠小於」讀起來像常識,而它是一句**沒有量過的全稱句**

### 事故

我在盤點檔裡寫:「今天分類數**遠小於** 2000 ⇒ **不可達**」。
C 窗複核時只問了一句:**「你量過嗎?」** —— 我沒有。

### 為什麼這一則值得單獨留

```
🔴 我寫的時候【並不覺得自己在推論】。
   「遠小於」不像「我猜」，它讀起來像在陳述一個顯而易見的事實。
⇒ 這種句子不會觸發任何自我懷疑，所以【自檢抓不到它】——
   要靠別人問，或靠一個不需要先懷疑自己的機械判準。
```

### 判別句(**它的優點是不需要你先懷疑自己**)

> **這句話裡的數量詞（遠小於／遠低於／不可能超過／頂多），我有沒有一個【量到的數】?**
> 沒有 ⇒ 改寫成「**未量**」,並寫出**缺哪一道檢查**(例:對正式庫數一次 `categories` 列數)。

⚠️ **與既有那條「0 命中必附分母與 pattern」同族,但方向不同**:
那條防的是**掃不到而說沒有**;本條防的是**沒去掃就說不會有**。

## 4. 🔴 引用一個**住在別人手上的設定值**,而沒有寫它的保存期限

### 事故

我引 memory 裡「`db-max-rows = 1000`(2026-08-02 production 實測)」去判一個迴圈「零餘裕」。
V 窗當場實測 ⇒ **2000**(Sean 08-17 調大了)。**我的結論翻面。**

🔴 **而那個值當時是對的。** 這不是「引錯數字」,是**引了一個有保存期限的東西而沒寫保存期限**。

### 規模(順手掃到的,不是本則的重點但值得記)

```
grep -rn '1000 上限\|1000-row\|1000 列上限\|PostgREST 1000\|max-rows.*1000\|1000.*max-rows' \
  --include='*.ts' --include='*.tsx' --include='*.md' apps packages docs | grep -v '\.test\.'
⇒ 18 命中（2026-08-18 落筆當下；這個數字自己也會漂）
```
🔴 **這 18 處當初都是對的,而 Sean 按下 Save 的那一秒全部變假 ——
且【沒有任何一個檔案被改動】:檔沒改、測試沒紅、grep 數不變。**

### 判別句

> **我寫下的這個數字,有沒有人可以在我不知情的情況下把它改掉?**
> 有 ⇒ **它不是常數。** 要把**時點 + 環境 + 探法**寫在**數字旁邊**(表會被複製走,前後文不會)。

### 🔴 而修法不是「把 18 處改成 2000」

> **那只是把保存期限往後推一次。**
> **要改的是「數字旁邊沒有時點與探法」這件事本身。**

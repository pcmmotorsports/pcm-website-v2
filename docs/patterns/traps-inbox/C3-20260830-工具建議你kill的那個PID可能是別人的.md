## 🔴 那句 `or run kill 89784` —— **它是工具給的建議,而工具不知道這裡有八個窗**

```
單人環境 ⇒ 那個 PID 是你自己十分鐘前忘了關的 ⇒ kill 它完全正確
本 repo  ⇒ 八個窗共用一棵樹 ⇒ 那個 PID **很可能是別窗正在用來看畫面的**
⇒ ⇒ 你 kill 它，對方的畫面在他眼前消失，而他不會知道發生了什麼事
```

> 📌 **一個在單人環境下完全正確的建議,在多人環境下是破壞。**
> **而它不是錯的建議 —— 它是一個【前提不成立】的正確建議。**

🔴 而這與「守門給出錯的修法建議」是**同一族**:
**一個說得出「你應該怎麼改」的東西,它的建議本身要先被驗過**,
而**建議通常不帶它自己的前提** —— 它只說做什麼,不說「這在什麼情況下才對」。

### ⚠️ 判別動作(機械的)
```
工具叫你 kill / rm / reset / --force 一個【你不是親手建立的東西】
⇒ 停。先問:這個東西是誰的?
⇒ 而在多窗環境裡，預設答案是【不是我的】
```
✅ 查歸屬:`ps -o command= -p <PID>`、`lsof -nP -iTCP:<埠> -sTCP:LISTEN`。
🔴 **而查得出「它是什麼」查不出「它是誰的」** —— 全窗共用 git 身分,程序也沒有窗代號。
⇒ **所以判準不是「查清楚再決定」,是【查不出歸屬就不動】。**

## ✅ 正解:**開一棵 git worktree**(2026-08-30 實走過,成功)

`next dev` 的鎖是**每目錄一份**,不是每埠一份 ——
🔴 **所以換埠救不了**(我起跑前四個埠都量過,web 埠是乾淨的;它不是搶不到埠,是搶不到那個目錄)。

```bash
git worktree add --detach /tmp/pcm-wt-<窗代號> HEAD
cd /tmp/pcm-wt-<窗代號> && pnpm install --frozen-lockfile --prefer-offline   # 15 秒
ADMIN_PROBE_DIR=/tmp/pcm-admin-probe-<窗代號> ADMIN_PROBE_PG=… ADMIN_PROBE_PREST=… \
ADMIN_PROBE_PROXY=… ADMIN_PROBE_WEB=… bash /tmp/pcm-wt-<窗代號>/scripts/admin-probe/up.sh
```

## 🔴🔴 而**同一支檔,同一天,第三個人踩** —— 而這一格值得獨立成一條

```
2026-08-30 凌晨，對 storefront-probe/up.sh「REPO 寫死主樹」這件事:
  ① CLAUDE.md 路由表作者   —— 寫下它時是對的，而 9603b601 之後沒人回頭改
  ② -48（主視窗）          —— 派工時逐字轉述路由表那一列
  ③ R3                     —— 發了一則警告，而 -01 當場撤回
  （④ 我自己差一點寫進本檔，是回核行號擋下的）
```

### 而他們踩的**不是同一個東西**,這一格要分開
```
①② 的來源是【一份轉述碼的表】⇒ 表過期了
🔴 ③ 的來源是【碼本身】—— 而它 grep 到的是那支檔裡一行**加了刪除線的舊註解**
```

### 📌 而 ③ 是一個**我們自己造出來的**坑
```
本 repo 有一條慣例:改字面時【舊句留著加刪除線】，
讓拿舊字面去搜的人，在同一發裡撞到更正。
✅ **那條慣例是對的** —— 它救過很多次，本檔上面那一段也是照它寫的。

🔴 而它的代價從來沒有被寫下來:
   **`grep` 不會渲染刪除線。**
   在 grep 的輸出裡，`~~已作廢的舊字面~~` 與**生效的碼**長得一模一樣。
⇒ ⇒ 而一支檔【越誠實】（保留越多歷史），它的 grep 假陽性就【越多】。
```
> **⇒ 那不是文件爛掉,是【文件很誠實,而量具讀不懂它的標記】。**

### ✅ 判別動作(便宜,而且機械)
```
grep 命中一行 ⇒ 在斷言它是現況之前，看那一行【本身】有沒有 ~~ 或 ⛔
⇒ 而更硬的一發:對【可執行的檔】，問「它是不是一行註解」——
   sed -n '<N>p' <檔> 看開頭是不是 # 或 --
🔴 而最硬的一發:不要問「那個字面在不在」，問「**生效的那一行是哪一行**」
   例:REPO 這種賦值 ⇒ grep -n '^REPO=' 只會命中沒有被註解掉的那一個
```
📌 **⇒ 一般化:`grep <字面>` 答的是「這幾個字在不在檔裡」;**
**而你想問的通常是「這件事現在成不成立」—— 那兩個問題的答案會分岔,而分岔的方向偏向【誤以為舊的還在生效】。**

### 📎 而它屬於一族,不是孤例(`-b9` 2026-08-30 併的)
```
`b9-20260830-五個坑…` 第 6 條:**負對照的字面自己進了分母**
本條:**加了刪除線的舊字面自己進了 grep 的分母**
📌 ⇒ 同一族:**我們為了誠實而寫下的東西,讓量具讀錯。**
⇒ 而兩者的修法方向相同:**不要問「那個字面在不在」,問「生效的是哪一個」。**
```
### ⚠️ 而稀有度已經量過一次,寫下來免得被高估
```
-b9 把這一類量進他那 20 條引用抽樣 ⇒ **0 / 20**
🛑 而他自陳那個 0 是【下界】:他只檢查「含引文的那一行」有沒有 `~~`，
   **跨多行的刪除線區塊（`~~` 在前一行、引文在下一行）他抓不到**
⇒ ✅ 所以正確字面是【真的存在而稀有】，不是「不存在」
⇒ 🔴 而它【不足以】拿去抵銷任何一個「引用指錯」的統計 —— 那 20 條裡的 10 個紅，
     7 個是「那句話已經全檔都沒有了」，與本條無關。
```

### ⚠️ 一個會擋住你的坑:**不要用符號連結省掉 `pnpm install`**
```
我先試了 ln -s 主樹的 node_modules 進 worktree ⇒ Turbopack 逐字拒絕:
  「Symlink [project]/apps/admin/node_modules is invalid, it points out of the filesystem root」
✅ 老實跑 pnpm install --frozen-lockfile --prefer-offline ⇒ **15.2 秒**（共用 store）
⇒ 📌 那個「省時間」的做法比正解慢，因為它先花時間失敗一次。
```

# 退場條件綁在「之後會做的某件事」上 —— 那件事被取消時,它**不會失效,而會永遠掛著**

> 線【DB】`-ops` 2026-09-17 · ⟦db-EXITCONDCANCELLED⟧。
> 🔵 **這不是「註解過期」那一族**,差別在下面〈為什麼不是那一條〉。
> 過期的註解是**壞掉的事實**;本條是**壞掉的機制** —— 它會主動假裝自己還有效。

## 現場

`packages/adapters/src/supabase/database.types.ts` 有三處手寫的型別宣告,
都是「migration 還沒貼、生成器產不出來,所以先手寫」。其中一處把退場條件寫得**比另外兩處好**:

```
// migration `20260904190000` 尚未 apply 到正式庫 ⇒ 生成器現在產不出它。
// apply 之後重 gen 應該就有了 ⇒ **那時這一段可以退場**(退場條件寫在這裡,
// 而不是「哪天有人想起來」)。
```

📌 **它做對了一件事**:退場條件寫在碼旁邊,不是放在誰的記性裡。那是這個 repo 一直在推的形狀。

2026-09-17 實查(**判準不是帳本**,見〈量法〉):
```
admin_update_shipment_tracking   活的庫 ⇒ 命中 1   ⇒ 前半【到期了】
整檔重 gen                        ⇒ 已裁定【不做】 ⇒ 後半【永遠不會成立】
```

## 病灶

那句話是 **`A 成立 ⇒ 才做 B ⇒ B 做完才退場`**。
而現實走成:**A 成立了,B 被取消了。**

```
A「migration apply」          ⇒ 已發生
B「整檔重 gen」               ⇒ 2026-09-17 裁定不做
   (量到 537 刪 / 5091 增,而 runbook §1.5 量到的是 26 / 36 ⇒ 差兩個數量級
    ⇒ 收下它 = 一次宣告 5000 行沒人核過的型別現況是對的)
退場                          ⇒ 🔴 **永遠不會觸發**
```

🛑 **而它不會變紅、不會逾期、不會有人收到通知。** 它只是繼續躺在那裡,
對每一個讀到的人說「這是暫時的,之後會清掉」——**而「之後」已經被取消了。**

⇒ 🎯 **一個綁在別人動作上的退場條件,自己沒有辦法知道那個動作被取消了。**

## 🔴 而它比「忘了清」更難抓 —— 這才是本條的重點

一段**忘了清**的暫時性碼,讀起來就是「有人忘了」⇒ 下一個人會去清。
本條那一段讀起來是「**有計畫、有條件、有出處**」⇒ 📌 **它看起來像被管理著,所以下一個人不會去碰它。**

> **一個寫得好的退場條件,在它的前提被取消之後,會比一個沒寫的更能阻止別人動它。**

## ✅ 修法(不是「記得回來看」)

退場條件要綁在**可觀測的狀態**上,不要綁在**別人打算做的動作**上:

```
⛔ 「apply 之後重 gen 就有了 ⇒ 那時這一段可以退場」
      ↑ 綁在「有人會去重 gen」這個【動作】上

✅ 「當 `supabase gen types` 的輸出裡有這一支時,本段就是多餘的 ⇒ 退場」
      ↑ 綁在【狀態】上。重 gen 做不做、誰做、什麼時候做, 都不影響這句話還成不成立
```

⚠️ 而**本次沒有照這個修法改** —— 因為重 gen 已裁定不做 ⇒ 那些手寫宣告
**仍然是型別的唯一來源**,退場的是條件不是那段碼。
⇒ 實際做的是:標到期(刪除線)+ 寫明「前半到期、後半永遠不成立」。

## 量法(可重跑)

🔴 **判準不是 `supabase/APPLIED.tsv`。** `scripts/is-migration-applied.sh` 自己逐字說:
「帳本答的是『有沒有人**記**』, 不是『東西在不在』」——
本次四支查下去**帳本都命中 1 列**,而那證不了任何事。

用**從活的庫生成的型別**當判準:
```bash
supabase gen types typescript --project-id <id> \
  --schema public --schema graphql_public > /tmp/types-fresh.ts

grep -c "^      admin_update_shipment_tracking: {" /tmp/types-fresh.ts   # ⇒ 1
grep -c "^      admin_delete_item_receipt: {"      /tmp/types-fresh.ts   # 正對照 ⇒ 1
grep -c "^      zzz_not_a_real_fn: {"              /tmp/types-fresh.ts   # 負對照 ⇒ 0
```
⚠️ **沒有那兩個對照,任何 0 都自動成立。**

## 為什麼不是「註解過期」那一條

「註解過期」的判別句是:**「這句話現在還是真的嗎?」** —— 它處理的是**一個壞掉的事實**,
而事實壞掉之後,只要有人讀到、去核一次,就會發現。

本條那句話的**每一個字現在都還是真的**:
migration 確實曾經沒貼(已到期並標示)、重 gen 確實會產生它、產生之後這段確實可以退場。
壞掉的是**它們之間那個「⇒」** —— 那個箭頭的右邊被取消了,而箭頭自己不知道。

⇒ 判別句因此不同:

> **「這個退場條件要等的那件事,現在還有人打算做嗎?
>   如果它被取消了,這段碼會不會有任何人收到通知?」**

## 這一則答不出什麼

- 我**沒有掃**過全 repo 還有幾處同型的「等某件事做完就退場」。
  ⇒ 今天只掃了 `database.types.ts` 這一個檔(因為工作範圍就在那裡),掃出 4 處到期句、其中 1 處是本條。
  ⇒ **這是已知缺口,不是「查過是 0」。** 真要掃,起點大概是 `退場` / `之後可以` / `就可以拿掉` 這幾個字。
- 上面那個 ✅ 修法(綁狀態不綁動作)**我沒有在任何地方實作過** ——
  它是從本次這一例推出來的形狀,**沒有被任何一發量測驗過**。
- 「重 gen 不做」這個裁定**可能之後被推翻**(那兩筆基線債已合成一件排進待辦)。
  ⇒ 真被推翻的話,本條那段碼的退場條件會**重新成立**,而本條記的那個形狀**不會因此失效**。

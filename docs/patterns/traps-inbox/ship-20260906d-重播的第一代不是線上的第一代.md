## 從零重播建出來的「第一代」, 與正式庫的第一代不是同一個東西〔安靜〕

**線** `-ship` 2026-09-06 · `⟦5b-SHIPPEDNUMNOTRECORDED1⟧` 貼板 39 · **自述**

### 事情
第二代 view 貼上正式庫 ⇒ 逐字 `ERROR: 42P16: cannot drop columns from view`。
```
線上那支 view   11 欄(第 11 欄 order_source, 由 20260905080000 加的)
我寫的第二代    10 欄(照 20260904220000 那一版抄)
⇒ CREATE OR REPLACE VIEW 只准在【尾端加欄】 ⇒ 42P16
```
🔴 **而拋棄式 PG 從零重播 313 支【沒有紅】** —— 那棵樹上這支 view **只有 10 欄**
(四支姊妹 view 也都沒有 `order_source`)。

### 🎯 母題
**重播答的是【這條路通不通】, 不答【線上長什麼樣】。**
而我拿「從零建出來的第一代」當「正式庫第一代」的替身 —— 它們差一欄, 而**那一欄就是全部的差別**。

### ✅ 判別句
> **我要對一個【線上既有】的物件做 `CREATE OR REPLACE` 之前 ——**
> **我有沒有去問【線上那一份】長什麼樣?**(欄名、順序、型別;不是問我的 migration 資料夾)

機械做法(唯讀一發就夠):
```sql
SELECT a.attnum, a.attname, format_type(a.atttypid, a.atttypmod)
  FROM pg_attribute a WHERE a.attrelid = '<那支 view>'::regclass
   AND a.attnum > 0 AND NOT a.attisdropped ORDER BY a.attnum;
```
✅ 而更好的是把它做成**前置閘**:live 的欄名清單必須是新版清單的**前綴**
(比前綴不比相等 —— **加欄合法, 少欄與換序不合法**)。已加成 `20260905200000` 的前置閘①d。

### ⚠️ 而有一格我【還沒查出來】, 不編
`20260905080000` 在那一發重播裡**不在失敗清單**(48/48 我逐行數過, 不是掃一眼),
而它**確實沒有在那棵樹上把欄加進去**。
⇒ 🛑 **兩件事我對不起來, 而我沒有查完就寫下解釋** —— 這一行就是那個缺口本身。

### 🛑 與近親的差別
最近的是「`CREATE OR REPLACE` 讓 migration 資料夾從『歷史』變成『一堆互相覆蓋的定義』——
而 grep 給你第一個」(0.23)。
🎯 **那一條講【同一棵樹裡】哪一份是最新的;本條講【兩棵樹之間】那一份不一樣** ——
而第二種更難發現:**你在自己那棵樹上做的每一次驗證都是綠的。**

## 2. 我這一格多的那個角度:**同一個結論, 兩個【不同】的錯理由, 連續兩次**

### 當天發生的事(2026-08-28,片 B1 migration)
那支 migration 有一欄 `tax_total integer NOT NULL DEFAULT 0`,
而我要在 `COMMENT` 裡寫「**為什麼不要拿掉這個 DEFAULT**」。我寫了兩次,兩次都錯:

```
第一版  拿掉它 ⇒ 下一次動那條 CHECK 會炸在【全表驗證】上
        🔴 錯:落地之後拿掉 DEFAULT【不會回頭改既有列的 0】—— 既有列不受影響
        真相:出事的是【新插入的列】(NOT NULL 無 default ⇒ 沒列它的 INSERT 直接失敗)

第二版  (訂正之後我又補了一句)那它仍然有一個對既有資料的版本:
        在本檔落地【之前】就沒有 DEFAULT ⇒ 第 3 節的 ADD CONSTRAINT 會炸在全表驗證上
        🔴 也錯:非空表的話它【更早】就死了 —— 第 1 節的 ADD COLUMN … NOT NULL
                 沒有 DEFAULT 就填不了既有列 ⇒ 當場失敗, 根本走不到第 3 節
```

### 🔴 判別句(這是我要投的那一句)
> **兩次的結論都是「不要拿掉它」—— 所以兩次都沒有人發現理由是錯的。**
>
> 📌 **一個【結論穩定】的推論鏈, 可以整條都是錯的, 而沒有任何訊號。**

### 為什麼它與既有那兩條不同
```
:921 / :4753 講的是【一次】結論對而理由錯 ⇒ 下一個人會照那個理由跳過重看
🔴 我這一格是:【訂正之後又錯一次】, 而第二個錯理由與第一個【完全不同】
   ⇒ 也就是說:「我剛剛才訂正過它」這件事, 一點保護都沒有提供
```
📌 **而最刺的一格是:第二版是【訂正的產物】** ——
   我在寫它的時候是**特別小心**的(我剛被打過一次)。
   ⇒ **小心讓我換了一個理由, 而沒有讓我去驗那個理由。**

### 而它為什麼躲過了三道人
```
· 我自己:兩次都得到我要的結論 ⇒ 沒有理由回頭查
· R1 code-reviewer:它審的是第一版 —— 而它抓到的是【別的東西】, 沒碰這句
· 主視窗:那句「拿掉 DEFAULT 的後果」原本【是他給我的字面】
  ⇒ 他自陳:「我把一個【對新資料】的風險, 寫成了一個【對既有資料】的風險。」
🔴 ⇒ 三個人看過同一句話, 而三個人都在看【它說的對不對】, 沒有人在看【它憑什麼】
```
✅ 抓到它的是 **codex R2**(第二輪對抗審查),而它抓的方式是**去推那句話的機制**,不是讀它通不通。

## 3. 可執行的推論(如果你要收的話, 我建議只收這一句)
> **當你【訂正】一個理由時, 新理由要與原理由受一樣的檢查** ——
> 而它通常不會, 因為訂正時大家在看的是「原來錯在哪」, 不是「新的憑什麼」。

⚠️ 而它有一個更便宜的操作化:**訂正之後, 問「那它會在哪一行先爆?」** ——
   我兩次都答不出行號(第一次答錯欄位範圍、第二次答錯節次),**而兩次我都以為我答得出來**。

## 正對照釘在「今天非法」上 ⇒ 它會在被守的東西**合法化**的那一天反咬,而症狀是【整支檔紅】

> 線【DB】`-db` 2026-09-06。實錘 = `⟦b4-TWOTRUTHS1⟧` 的第二把尺,第 31 批合併時紅。

### 發生了什麼

我寫了一支兩份真相對帳測試:**DB 走得到的每一對 `payment_status` 轉移,TS 的轉移表都要判合法。**
正對照寫成:

```
it('🔵 正對照:片3 那個形狀(refunded 可以回 paid)⇒ 必須印紅', …)
  expect(illegal(pairs)).toContain('refunded→paid');
```

當天 TS 那側 `refunded: []`(終態)⇒ 這一對非法 ⇒ 正對照綠。

`cardcancel` 片③ 合進來那一顆(`57a84b1e2` 折 R3 F6),TS 把它改成:

```
refunded: ['paid', 'partiallyRefunded'],
```

⇒ 🎯 **兩份真相【真的一致了】** ⇒ **主斷言正確地轉綠**,而我那個「必須印紅」的正對照
也跟著綠 ⇒ `AssertionError: expected [] to include 'refunded→paid'` ⇒ **整支檔紅。**

### 🔴 病灶不是尺壞了 —— 尺量對了

主斷言做了它該做的事。壞的是**我挑的不變量**。

一個正對照的工作是證明「**這把尺紅得起來**」。
而我拿的是**當下剛好非法的一個值** —— 那個值一被合法化,正對照就失去判別力,
而**它失去判別力的方式是【整支檔紅】**。

📌 **正對照要釘【不變量】,不是【當下的值】。**

🛑 而這個坑有一個很毒的性質:**它在「事情變好」的那一刻爆炸。**
兩份真相從分歧走向一致 —— 那正是這支檔存在的目的 —— 而那一刻它紅給你看。
⇒ 🔴 **下一個人最自然的動作是「這尺是不是壞了?先 skip 掉」**,而那會把整支守門關掉。

⇒ 📌 **釘的是尺,不是被量的東西。**

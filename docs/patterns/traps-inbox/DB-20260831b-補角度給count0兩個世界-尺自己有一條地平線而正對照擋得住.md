# 補角度給正本 `:21211`(`count(*) = 0` 有兩個世界)—— **那一條是【問題】有兩個世界, 我這一發是【尺自己】有一條地平線**

- 線【DB 與金流】· 2026-08-31 · 查重跑過:第 2 名 **0.3882** 正本 `:21211`,**開檔讀了** ⇒ 判**補角度、不另立**。
  (第 1 名 0.3946「告警的名字與它的分母」開檔讀 ⇒ 不同族。)
- 🔴 標題刻意含「印同一個數字」—— 下一個人會用那句話搜,而他要同一發撞到兩條。

## 那一條講什麼

> `email_outbox` `count(*) = 0` ⇒ 兩個世界:①從來沒寄過(沒接線)②寄過而那些列後來被標走了。
> **而 `count(*)` 對這兩個世界印同一個 `0`。**

⇒ 📌 **那一條的形狀是:尺是好的, 而【問題】本身有兩個世界。**分開它們要換一把問不同問題的尺(`n_tup_ins`)。

## 🔴 而我這一發是另一半:問題只有一個世界, 而【尺自己有一條地平線】

我要答:**今天有沒有任何路徑會 `UPDATE` 既有的 `order_refunds.refund_amount`?**

```
第一把尺   grep -rn -A6 "UPDATE public.order_refunds" | grep "refund_amount ="   ⇒ 0 處
```

那個 `0` 看起來就是答案,**而我差一步就拿它去寫板子。**

🔴 **而它的分母是「`UPDATE` 那一行之後的【6 行】」—— 而 `SET` 清單可以比 6 行長。**

```
第二把尺   從 UPDATE 讀到分號、整段再找                                        ⇒ 0 處
```

📌 **兩把尺印同一個數字,而只有第二把的 `0` 算數。**

## ✅ 救回它的是正對照 —— 而這一格與「猜名字的尺」相反

```
同一把尺找 `status =`  ⇒ 12 處 UPDATE 全中(12/12)
⇒ 證明尺讀得到 SET 子句 ⇒ 那個 0 是【真的沒有】, 不是【尺看不到】
```

🔵 **而它值得與 memory `feedback_ruler-named-by-guess-was-never-connected` 對照著看**:
那一條講「用猜的名字造出來的 grep 尺,它的 `0` 是它沒被接上」,**而那一條明說負對照擋不住它**。
🔴 **本條相反:截斷型的尺,【正對照擋得住】** —— 因為只要餵它一個「一定在 `SET` 子句裡」的字面,尺沒接上就會當場印 0。
📌 **⇒ 兩種壞尺,兩種對照:猜名字的要【開檔核】,有地平線的要【正對照】。挑錯了那一種就白做。**

## 🔴 而完成品是第二問,不是第二把尺

**「沒有碼在做」與「沒有人做得到」是兩個宣稱。**

```
① 沒有碼在做   migrations 12 處 UPDATE, SET refund_amount 的 0;app 側 .update( 0
② 沒有人做得到 order_refunds = RLS on + 零 policy + REVOKE ALL FROM PUBLIC/anon/authenticated
               + 只 GRANT SELECT 給 service_role(20260725130100:318,321,324)
               ⇒ 沒有任何角色有 UPDATE
```

🔴 **大部分人在第一個 `0` 就收工了 —— 而第一個 `0` 只答了兩個宣稱裡的一個。**
⇒ 而它們的失效方式不同:①明天有人寫一支新 RPC 就不成立;②要有人 `GRANT` 才不成立。
📌 **⇒ 只有 ① 的話,結論的保存期限是【下一個 commit】。**

## ⇒ 可執行的一句

> **一把帶截斷參數的尺(`-A<n>` / `head` / `limit` / 分頁)印出 `0` 的時候,那個 `0` 有兩個來源:
> 【真的沒有】與【它在截斷之外】—— 而兩者印同一個字。**
> ⇒ 先餵它一個**一定在截斷範圍之外**也應該命中的正對照,再決定要不要相信那個 `0`。

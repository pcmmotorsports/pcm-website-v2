## 🔴 而它們的處置**完全相反**

```
選擇器錯      ⇒ 這是 bug   ⇒ 動作是【修】
等接線 / 刻意 ⇒ 這是狀態   ⇒ 動作是【等】, 而修它是錯的
```
⇒ 📌 **一個掃「有沒有呼叫端」的工具, 對這兩者印同一個結果** ——
　 而**照它的輸出去清理, 會把還沒接線的東西刪掉**;反過來,把選擇器錯的那種當成「等接線」,
　 它就**永遠不會被修**。

## ✅ 判別句(寫的當下,不是掃到的時候)

> **寫一段今天沒有呼叫端的樣式時,在它【旁邊】寫下「今天沒有呼叫端」與為什麼。**

🔵 **為什麼要寫在旁邊而不是別處**:掃到它的人手上只有那個檔。
　 註解是**唯一與那段規則同進退**的載體 —— 板列會被搬走、commit body 不會被 `grep` 到。
🟢 **今晚兩個都做了**:`.pp-grid.is-loading` 上方逐字寫著「**這幾行是【等接線】不是【接好了】**」;
　 `od-trace` 那一格的理由在 `OrderDetailView.tsx:40-44` 並**引了稿自己的警告**。
🛑 **而那不是自動發生的** —— 第一個是 code-reviewer 要我補的,第二個是我對稿時才發現它沒有呼叫端。

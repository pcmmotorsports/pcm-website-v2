# 一、判【併】的兩條

## ①→ 併進正本 `㊺`「正在書寫某條規則的當下, 是它最容易被違反的時刻」(:2792)
**它是那條的第 4 個實例, 而它多一個【新的形狀】。**

`㊺` 現有三個實例都是「寫規則時違反了那條規則」。
🔴 **我這一個多的是:那段文字【用了那個坑本身的材料】。**
```
現場：板子是 markdown 表格，一列五格用直線分開
我要警告下一個人「這一列的結尾沒有表格收尾符號」
⇒ 而我把【那個符號本身】寫進反引號當字面去解釋它
⇒ 該列欄數當場 6 變 7，而板子守門印 rc=0（它驗態欄、驗列數，不驗欄數）
✅ 抓到它的是拿隔壁兩列當正對照（兩列都是 7）
```
📌 **一段關於格式的警告, 用了會破壞格式的材料 —— 而破壞只發生在欄數上, 不在文字上, 所以它讀起來完全正常。**

🔴 **而這一格值得單獨記在 `㊺` 底下的理由**:今晚同族發生 **4 次**
(`546ab67c` 字接在收尾符號外 / `6a0a86b0` 與 `6245d11b` 把含直線的 grep 指令寫進表格 / 第四次是本則)。

> ⛔🔴🔴 ~~**而第 4 次的抓法與前三次不同** —— 前三次是**下一顆 commit 才發現**, 第 4 次是**改完當場量**。
> ⇒ **那是一條學習曲線的證據, 而它的證據是【抓到的時點】, 不是【次數】。**~~
> **這一段 2026-08-30 00:4x 被作者自己推翻 —— 而推翻它的是【一發我本來不必跑的量測】。**
>
> **實量**(用錨定位, 量那一列在該顆 commit 裡的形狀):
> ```
> 546ab67c  取消閘那列 ⇒ 欄數 7 而【結尾缺收尾符號】⇒ 🔴 真的出去了，修在 62a7c689
> 6a0a86b0  該列 ⇒ 7  ⇒ ✅ commit 之前就抓到了
> 6245d11b  該列 ⇒ 7  ⇒ ✅ commit 之前就抓到了

> ```
> 🔴 **⇒ 只有【第 1 次】真的出去了;第 2、3、4 次【全部】是改完當場量抓到的。**
> ⇒ **所以「前三次不是當場量」是假的, 而那句話正是本條的賣點** ——
> 📌 **一個關於【我學會了】的宣稱, 是最不會被回頭查的那一種, 因為它讓人心情好。**
>
> ⚠️ **而我第一發用的尺沒有判別力**:我數「欄數不是 6 也不是 7 的資料列」⇒ 四顆都印 **65/66**
> (板上本來就有大量含直線的列)⇒ **四個一樣的數字看起來像「沒有變化」, 而它只是尺太鈍。**
> ⇒ **換成用錨逐列量才分得開。**
>
> ✅ **而【真正成立的那一半】留下來**:四次裡**有三次是改完當場量抓到的**,
> 而**板子守門對這四次全部印 `rc=0`** ⇒ **抓到它們的一直是「拿隔壁兩列當正對照」這個動作, 不是守門。**

**可執行**:寫進表格的任何指令與符號, 先問「它含不含那個分隔符」;要講那個符號就**寫中文字**。
改完**當場** `awk -F'|' '{print NF}'` 比隔壁兩列 —— **不要等守門, 守門不驗這個。**

## ⑤→ 併進正本 `⑭`「結構性結論一律要去讀建它的那支 migration 的註解」(:1358)當第 5 列
**而它把 `⑭` 從【讀註解】擴到【讀 DDL 子句本身】。**
```
現場：交接檔明寫「舊單發票回填做了沒 = 另一格，接手窗自查」
grep -rlE 'UPDATE …orders…invoice_requested' supabase/migrations ⇒ 零命中
🔴 而那個零的意思是【不需要】，不是【沒做】：
   20260828100000…:253 逐字
     ALTER TABLE public.orders ADD COLUMN invoice_requested boolean NOT NULL DEFAULT true;
   ⇒ NOT NULL DEFAULT true 這個組合，PostgreSQL 把【既有每一列】都填成 true
   ⇒ 那正是 Sean 答的「全部填要開」⇒ 沒有東西要補做
```
📌 **分得開那兩個世界的不是那個 0, 是去讀 `ADD COLUMN` 那一行的 `DEFAULT`。**
🔴 **這是「零命中」那一族裡最少見的變體**:一般的零命中坑是**零是錯的**(尺太窄);
**這一個零是對的, 而從它推出的結論相反。**
📎 **與 memory `feedback_no-caller-means-either-not-built-or-explicitly-blocked` 是同族第三種**:
那條講一個零有兩種意思(**還沒做** / **被明文擋住**);**本條是第三種:【不必做】。**
📎 而 `⑭` 現有第 4 列正好也是 `invoice_*` 欄那一族 ⇒ **同一支檔家族, 兩個不同的機制。**

**可執行**:對「找不到 X 的實作」的零命中, 下結論前多問一句
**「X 有沒有可能是由別的機制順便完成的?」** —— 對 DB 而言最常見的是
`DEFAULT` / `GENERATED` / trigger / 約束, **而它們在 grep「做這件事的動詞」時全部隱形。**

# 二、判【新開】的三條(附為什麼不併)

## ② 一把不剝註解的尺, 會把「明文說自己沒做這件事」的檔算成犯規者
```
現場：要數「哪幾支 migration 在 view 那一句裡用了 別名星號」
第一發用「整支檔裡有沒有」⇒ 10 支
逐支開檔 ⇒ 4 支誤抓，而其中【3 支的原文逐字寫著「刻意不用 c 星號」】
```
🔴 **那三支是最謹慎的作者 —— 他們把「我沒有這樣做」寫下來了, 而正是那句話讓他們被算成犯規者。**
📌 **⇒ 一把不剝註解與字串的尺, 懲罰的是【把決定寫下來的人】。**
⚠️ 同夜另一個窗撞到同族的**另一種藏身處**:誤報全在 `CREATE OR REPLACE FUNCTION … AS $tag$` **函式體**裡。
⇒ **同一個母題, 兩個不同的藏身處。**

**🔴 為什麼不併進 `⑤`「掃描的字集/範圍比你宣稱的窄」(:482)**:
```
⑤ 講的是【窄】——漏抓
本條講的是【寬】——誤抓，而誤抓的分布【不是隨機的】：它集中在最謹慎的那些檔
⇒ 併進一個標題寫著「窄」的條目，會讓這一半被埋掉
```
⇒ **新開, 而與 `⑤` 明確互指為【反向的兩半】。**

**可執行**:掃 SQL 的尺**剝三樣**(`--` 行註解 · 單引號字串字面 · `$tag$` 區塊),
然後**把範圍收到你真正在問的那個語句之內**;負對照用**現造識別字**, 跑之前先確認回 0。

## ③ migration 的時間戳是【全域唯一】的資源, 而沒有任何東西在管它
```
八窗共用一棵工作樹。我新開 20260829190000_…
⇒ 而另一個窗同一時間也開了 20260829190000_…
ls supabase/migrations/*.sql | sed 's#.*/##' | cut -c1-14 | sort | uniq -d
⇒ 1 組（就是我造成的那一組）⇒ 全 repo 唯一一組
```
🔴 **三綠不叫、板子守門不叫、lint 不叫 —— 抓到它的是 codex 對抗審查的第一條 must-fix。**
⚠️ **而後果不是 conflict**:兩支檔都在、都合法、`git status` 乾淨,
**而 migration ledger 可能安靜地跳過第二支** ⇒ **那支的內容從來沒有被套用, 而沒有東西會叫。**

**🔴 為什麼不併進 `:14292`(`CREATE OR REPLACE` 讓 migration 資料夾變成互相覆蓋的定義)**:
```
那條的機制是【同一個物件被後面的檔覆寫】—— 兩支檔都會跑
本條的機制是【兩支檔的檔名撞號】—— 其中一支可能【根本不會跑】
⇒ 同一個資料夾、兩個完全不同的失效
```
⇒ **新開, 互指。**

**可執行**:開任何 `supabase/migrations/` 新檔**之前**跑 `ls supabase/migrations/<你要用的14位>*`;
**收工前**再跑 `cut -c1-14 | sort | uniq -d` ⇒ **期望 0**。

## ④ 字面完全相同, 而它在講另一件事 —— **而「多讀幾個命中」救不了你**
```
要查 Sean 有沒有答過「那兩張紙要不要改名」
grep -rn '不用改名' ~/pcm-mailbox/ ⇒ 3 個命中
🔴 而【第一個不是答案】：
   C-A75-CORRECTION-2026-08-16.md:75「實測是:不用改名。只要 import 活著就會漏。」
   ⇒ 那在講【import 洩漏】，與紙張命名完全無關，而字面一模一樣
✅ 真答案在第三個命中：等Sean決策-20260829.md:2388「A:  不用改名，依照現在」
```
📌 **一個只看第一個命中的人, 會拿一份關於 import 的實測去回答一個關於紙張命名的問題 —— 而他會覺得自己查到了。**

**🔴 為什麼不併進「grep 到第一個命中就停」那一族**:
```
那一條講的是【同一支檔裡有更新的那個命中】⇒ 多讀幾行就救得回
🔴 本條是【不同的檔、不同的主題，而字面完全相同】
⇒ ⇒ 「多讀幾個命中」也救不了你，除非你去讀那個命中的【上下文】
```
⇒ **它比那一條狠一格, 而修法不同 ⇒ 新開。**

🔴🔴 **而這一條在【同一夜有三個現場, 跨三個窗】—— 這是本份唯一一條有跨窗複現的**
(2026-08-30 00:3x 補;前兩個是我自己的與 `-b4` 主動送來的):
```
現場一（-b9）grep '不用改名' ⇒ 撞到 import 洩漏那則，字面一模一樣、主題無關
現場二（-b4）grep 'price_store' 在 admin_create_manual_order 那支 ⇒ 2 行
            🔴 一度讀成「它有查價、前人寫錯了」
            開檔（-b9 獨立複驗）：那 2 行是 :383-384 一道【拒絕】守門
            RAISE EXCEPTION 禁止 line_spec 出現價格欄名（防經銷價洩漏）
            📌 它不是在查價，它在【禁止】那些字出現
現場三（-b4）A7C_VERIFY_PORT —— 那個識別字真的存在，而職務不同
```
📌 **⇒ 三個現場的共同形狀:字面在, 而它扮演的角色與你假設的【相反或無關】。**
🔴 **而現場二最貴** —— 一個【禁止】的守門, 被讀成一個【查詢】的實作
⇒ **那會讓人得出「這裡已經有防護了」而停止追查。**

**判別句**:**一個字面命中告訴你「這幾個字在那裡」, 它不告訴你「那幾個字在講你問的那件事」。**
⇒ **加一句(現場二帶出來的)**:**尤其分不出【做這件事】與【禁止這件事】—— 而它們的字面一樣。**
🔴 **而這個病長在 `scripts/before-asking-sean.sh` 的主要用法上** —— 它的第②發正是**用他的話去 grep**。
⇒ **那一句要寫進那支工具自己的射程節**(主視窗 `-48` 已派給該支檔的作者 `-e9`, **不是我**)。

## 🔴 而重點是這一句

> **這三個鍵, 每一個【單獨看都是最自然的選擇】。**

```
錨            它是那張表上【唯一的識別字】—— 不用它用什麼？
第一個命中     grep -n | head -1 是全 repo 最常見的取法
行內第一個錨   一列有好幾個錨時，取第一個是最省事、也最像慣例的做法
```

⇒ 📌 **一個錯的鍵不會看起來像個錯誤, 它看起來像個慣例。**
而它的產物是**一個合理量級的數字**:36 與 41 都說得通;`:124` 與 `:126` 都是真的板列;
`b4-BOARD1` 真的在那一行裡。**沒有一格會讓人停下來。**

🔴 **而「很接近」才是 ① 的危險**:36 與 41 之間**沒有任何東西會叫**。
若我先看到別人的 41,我會以為**自己漏了五列**而去補;若我先交,別人會以為**板子少了五列**。

```

```
📌 **⇒ 選鍵的判準:那個東西【在這件工作的期間會不會變】, 以及【它唯不唯一】。**
而三個失敗剛好各踩一格:①不唯一 ②取法不唯一 ③不唯一且會變。

## ⚠️ 而本條的射程

- **`n=3`, 而三次都是同一個人在同一支檔上。**我**沒有量**別人有沒有踩過同一族
  —— 而我特別不去猜那個數:**本條講的就是「一個合理的數字不會讓人停下來」。**
- 三次都被抓到,靠的是**兩件事**:①與另一個窗**對帳**(它算 41,我算 36)②我為每一族寫的**正對照**。
  🔴 **⇒ 沒有那兩樣的話, 三次【都會安靜地過去】** —— 而產物是一份看起來完整的重驗報告。
- 🛑 而**最後那個鍵也不是安全的**:事欄文字**被編輯就會變**(今晚就有人在改事欄)。
  ⇒ 它只是**在這一輪的時間尺度上**夠穩 ⇒ **所以這一輪的清單被【凍結】成一份快照**
  (`~/pcm-mailbox/線G-凍結清單-維度一-20260830.md`,帶時刻與 HEAD)。
  📌 **⇒ 沒有一個鍵是無條件穩定的;能問的只有「它在【多久】的尺度上穩」。**

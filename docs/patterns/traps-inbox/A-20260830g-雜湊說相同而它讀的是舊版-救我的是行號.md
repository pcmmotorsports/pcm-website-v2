# 雜湊說「相同」,而它讀的是舊版 —— **救我的是行號**

- 線A `-e9` · 2026-08-30 · 🔴 **標題刻意含「雜湊」二字** —— 下一個人會拿雜湊來當定案,而這一條就是給他撞的。
- 🔴 時刻是 sandbox 的 `date`,不是 Sean 那台的鐘。

## 現場

我請 codex 對抗審查一份 plan(152 行)。**它跑的期間,我把那份 plan 改成了 176 行。**
我當場自標:「那發審查的分母是舊版,回報時要寫清楚。」

**然後我去驗那個自標 ——**

```
codex 自己在 log 裡印了 plan 的 md5：d0ac9f066ebadad98e1593b811acb026
我當場算現在的檔        ：d0ac9f066ebadad98e1593b811acb026
⇒ ✅ 完全相同
⇒ ⇒ 看起來：它審的【就是】現在這一版，我的自標被推翻了
```

🔴 **而我差一步就寫「自標撤回,它讀的是新版」。**

## 真相在一個比較土的地方:**行號**

```
它有一條 finding 引【:148】，引文是「路⑤ 在資料庫層擋不住」
我 grep 那句話 ⇒ 🔴 它在新版是【:171】
⇒ ⇒ 148 是【舊版(152 行)】的行號
⇒ ⇒ ⇒ 它讀的是舊版。我的自標【成立】。
```

📌 **解釋**:codex 在**整個工作的最後**才跑 `md5 -q` —— **而那時我已經改完檔了。**

> ## 🔴 **雜湊答的是「它現在是什麼」,不是「你讀了什麼」。**

## ⇒ 而毒在哪:**它是【大家更會信的那一把】**

```
行號   —— 會漂、大家知道它會漂、引用時本來就會半信半疑
雜湊   —— 精確、不可偽造、業界公認的「同不同一份」判準
⇒ ⇒ 而這一次，精確的那一把給出了【錯的答案】
```

🔴 **⇒ 而正是它的嚴謹,讓人不再往下查。**
一個「行號對不上」會讓人再看一眼;**一個「雜湊完全相同」會讓人結案。**

⇒ **⇒ 兩把尺不一致的時候,我們的直覺是相信比較精確的那一把 —— 而這裡要相信比較土的那一把。**

## 🔴🔴 而正確的教訓【不是】「不要相信雜湊」—— 是**一端的雜湊會騙人,兩端的不會**

同一晚,同一支檔,我跑了第二輪審查(R2),而這次我做對了:

```
R1：只有【事後】一端的雜湊  ⇒ 🔴 答不出「期間有沒有動」
R2：起跑【前】記一次 09765cee…、跑完【後】比一次 09765cee…
    ⇒ ✅ 兩端相同 ⇒ 答得出「這段期間沒有人動它」
```

📌 **⇒ 同一把尺,兩種用法,只有一種成立。**

🛑 **⇒ 所以這條坑不可以被總結成「雜湊會騙人」** ——
下一個人若學到那句,他會**放棄一個好工具**,而那比繼續誤用它更貴。

```
✅ 正確的用法：雜湊要【夾】住那段時間 —— 前一端 + 後一端
🔴 錯誤的用法：只有一端（尤其是【事後】那一端），而拿它去答「你讀了什麼」
```

⚠️ 而**兩端也有它答不出的**:兩端相同,只證明**頭尾一致**,不證明**中間沒有被改回來**。
⇒ 要那一格 ⇒ 得看**它自己 log 的時序**,或**在讀取當下**取雜湊。

## ✅ 可執行動作:**雜湊要問「什麼時候算的」**

```
拿雜湊證明「它讀了哪一版」之前，先答一句：
  🔴 這個雜湊是在【它讀檔的那一刻】算的，還是在【它做完事之後】算的？
  · 讀檔當下算的  ⇒ 它答得出「你讀了什麼」 ✅
  · 事後算的      ⇒ 它只答得出「這個檔現在是什麼」 ⇒ 🛑 不能拿來當版本證據
```

**⇒ 而在「事後算的」那種情況,可用的證據是這些:**
```
· 行號（引文的位置對不對得上）  ← 這次救我的
· 引文本身（那段字在不在那一版裡）
· 它引到的最大行號 vs 新增內容的行號（新內容在 141/153/164，它最大引到 148）
· 它自己 log 裡的時序（它什麼時候讀、我什麼時候寫）
```

## ⚠️ 天花板

- 這條只講**版本身分**。它擋不住「它讀了對的版本而理解錯了」。
- 🔴 **而反過來也成立**:雜湊**不同**也不證明它讀了舊版(檔可能在它讀完後被別人動)。
  ⇒ **雜湊在這個問題上,兩個方向都答不準** —— 它答的是另一個問題。
- 它是**規矩不是閘**;沒有任何東西會在你拿雜湊當版本證據的時候變紅。

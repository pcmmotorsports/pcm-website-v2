# 擋住錯誤的不是【警覺】,是【持有原件】

> `-b9` 2026-08-30 · `-48` 指名獨立成條、掛 `-b9` 的名
> 母題:**兩次擋下上游的錯,而兩次我都沒有懷疑他。**

## 兩個實錘,同一晚,同一個上游

```
① 主視窗：「#231 兩個子項不擋上線 ⇒ 產品∩open 13 → 11」
   我手上有【那 13 列的逐列清單】⇒ 我問「是哪兩列」
   ⇒ 量完：#231 ①④ 在 B 節沒有任何一列（它們是 backlog 子項）⇒ 13 不動

② 主視窗：「戳的套用率 2/44 ⇒ canonical 定義改成裸窗代號」
   我手上有【那份 canonical 檔】⇒ 我去讀它現在寫什麼
   ⇒ 逐字：`<誰> 釘死成【窗名, 單一 token, - 開頭, 不加反引號】`
   ⇒ ⇒ 規格【已經是】裸窗代號 ⇒ 那道指令從頭到尾無事可做
   ⇒ 而我自己量套用率 ⇒ 38/38（改前 37/38）
```

✅ 兩次上游都收回。**而兩次我都不是因為覺得他可能錯。**

## 🔴 兩次的動作是**同一個**

> ### **回去讀那個數字所描述的東西本身。**

不是「重新計算一次」,不是「找第二個來源」,不是「加一道審查」——
**是打開那個數字在講的那個東西,看它一眼。**

## 📌 而這條的重點在下一句

> ### **擋住錯誤的不是【警覺】,是【持有原件】。**

```
🔴 一個沒有原件的人，再警覺也只能問「你確定嗎」—— 而他會說確定，
   因為他真的以為確定
✅ 一個有原件的人，不需要警覺，只要順手比一下
```

⇒ **警覺是一種【狀態】,會累、會被時間壓力磨掉、在第二十件事上一定比第一件低。**
⇒ **持有原件是一種【配置】,它不會累。**

## 🛑 可執行的結論

> ### **下指令的人,不該同時是唯一持有原件的人。**

而今晚的實況**正好相反,那是它會生效的原因**:
```
主視窗持有的是【轉述】（-e9 的結論 / -0b 的數字）
我持有的是【原件】（逐列清單 / canonical 檔）
而下令的是主視窗
⇒ ⇒ 所以每一道涉及數字的指令，執行的人【本來就有能力】驗前提
```

🔴 **⇒ 反過來就危險**:若下令的人同時是唯一讀過原件的人,
**執行的人在結構上沒有能力反駁** —— 他只剩下「相信」或「不相信」,
**而兩者都不是證據。**

## ⚠️ 而這條不能被讀成「要多問一句」

「多問一句」是**紀律**,而紀律今晚已經失敗過很多次
(`⟦b9-FIXNOTLANDED1⟧`:一句我自己寫在自己 commit 標題裡的修法,1h55m 後我自己犯了)。

**本條要求的不是動作,是【誰拿著什麼】。**
⇒ 派工的時候問一句:**這個人手上有沒有他要驗的那個東西?**
**沒有 ⇒ 先把原件給他,再下指令。**

## 📌 而它與「成員清單」那條是同一件事的兩端

```
`b9-20260830l`：交數字要附成員清單
  · 已知的一面：讓下一個人驗得動你
  · -b4 補的一面：讓你自己問得出「是哪兩列」
🔴 本條：而那件事的前提，是【你手上真的有那份清單】
```
⇒ **附清單給別人 = 把原件配置到下游。**
⇒ ⇒ **⇒ 所以「交數字附成員清單」不是禮貌,是【把擋錯的能力分配出去】。**

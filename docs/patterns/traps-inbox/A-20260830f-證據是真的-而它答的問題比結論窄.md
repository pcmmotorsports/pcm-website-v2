# 證據是真的 —— **而它答的問題比結論窄**

- 線A `-e9` · 2026-08-30 · **兩個實例,同一個形狀**
- 🔴 時刻是 sandbox 的 `date`,不是 Sean 那台的鐘。
- 🛑 **利益揭露:實例①的證據提供者是主視窗 `-48`,而它在那一格【有立場】**(那個設定是它引導 Sean 去做的)。**它自己要求把這句寫進來。**

## 母題

```
一份【真的】證據 ／ 一把【當初正確】的量具
⇒ 被拿去支持一個【比它射程寬】的結論
⇒ ⇒ 而它沒有說謊 —— 它只是回答了一個比較小的問題
```

🔴 **它與「說謊」「沒量」都不同,所以既有的檢查抓不到它**:
- 問「有沒有證據?」⇒ **有**
- 問「證據是真的嗎?」⇒ **是**
- 問「量具驗過嗎?」⇒ **驗過,而且有正負對照**
- 🔴 **而沒有人問:「它答的是【哪一個】問題?」**

---

## 實例① · 截圖證明的是面板,不是安全

**場景**:板子 `#5`「TapPay 通知端點沒有限流」。主視窗回報:
> 「Sean 02:2x 把 `tappay-notify flood ceiling` 從 log 改成 429,**我親眼看過他的截圖,規則詳情頁 Then = 429**」

```
✅ 截圖證明：那個面板欄位顯示 429              ← 真的，我不質疑
🔴 它證明不了：300 / 60 秒對【真實 TapPay 尖峰】是安全的
🔴 它證明不了：改成擋之後 Firewall 的 Rate Limited 欄是 0
⇒ ⇒ 而【後兩者正是那一列自己拿來當前置的東西】
```

而那一列逐字寫著誤擋的代價:
> 「擋錯 = TapPay 的通知進不來 = **訂單付了款卻沒被標成已付**」(鐵則 12①)

⇒ **⇒ 一張真的截圖,支撐了一個「這件事做完了」的結論,而那個結論的風險面它一格都沒碰到。**

## 實例② · 一把附了正負對照的尺,13 天後開始印假進展

**場景**:`#231` 項④「轉人工結案流程 / 後台 UI」。2026-08-17 板上留了尺:
```
git grep -ln 'needs_manual_review' -- apps/admin   ⇒ 當時印 0  ⇒ 判「未實作」✅ 對
```
✅ **那把尺當初是對的,而且作者附了正負對照**(正向全樹 57 / 反向假字串 0)。

**2026-08-30 我重跑同一發**:
```
⇒ 🔴 印 4
⇒ 而逐行機械判：5 個命中【全部是註解】，非註解 = 0
   （判法雙向驗過：餵真 export 行 ⇒ 印「碼」／餵 doc 行 ⇒ 印「註解」）
🔴 其中 cancel-review-section.tsx:159 的註解逐字寫著「不濾 needs_manual_review」
   ⇒ ⇒ 那是一句【我沒做這件事】的宣告，而尺把它數成一個命中
```

📌 **⇒ 尺答的問題是「這個字串出現幾次」;而它被拿來答「這件事做了沒」。**
**13 天前那兩個問題的答案剛好相同。今天不同了,而沒有任何訊號。**

## 🔴 而實例② 的方向,是最壞的那一種

```
0 → 4  讀起來是【有人動工了】
而真相是【有人寫了註解說「我沒動這個」】
⇒ ⇒ 錯的方向【往好的走】
```
📌 **往好的方向走的數字,沒有人會回頭查。**
⇒ 一個往壞的走的假數字,下一個人會撞到;**一個往好的走的,會被當成好消息收下。**

## ✅ 可執行動作:**問量具它答的是哪一個問題**

引用任何一份證據 / 任何一個數字之前:

```
① 我的【結論】是什麼？（一句話寫出來）
② 這份證據 / 這把尺，直接回答的是【哪一個問句】？（也寫出來）
③ 🔴 兩句一不一樣？
   一樣 ⇒ 用
   不一樣 ⇒ 只能寫成「證據支持 ②，而 ① 未確認」，不得寫成「①已完成」
```

**兩個現成的填空範例:**
```
① 結論：TapPay 端點的限流做完了
② 證據答的：那個面板欄位現在顯示 429
⇒ 不一樣 ⇒ 寫「規則已設定為擋；而是否誤擋未確認」

① 結論：後台轉人工 UI 還沒做
② 尺答的：apps/admin 底下有幾個檔提到這個字串
⇒ 不一樣 ⇒ 這把尺要排除註解，或改用行為錨（有沒有 route/元件【讀】這個欄位）
```

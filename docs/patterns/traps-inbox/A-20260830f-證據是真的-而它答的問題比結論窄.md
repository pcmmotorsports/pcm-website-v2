# 證據是真的 —— **而它答的問題比結論窄**

- 線A `-e9` · 2026-08-30 · **兩個實例,同一個形狀**
- 🔴 時刻是 sandbox 的 `date`,不是 Sean 那台的鐘。
- 🛑 **利益揭露:實例①的證據提供者是主視窗 `-48`,而它在那一格【有立場】**(那個設定是它引導 Sean 去做的)。**它自己要求把這句寫進來。**

## 母題

```
一份【真的】證據 ／ 一把【當初正確】的量具
⇒ 被拿去支持一個【比它射程寬】的結論
⇒ ⇒ 而它沒有說謊 —— 它只是回答了一個比較小的問題
```

🔴 **它與「說謊」「沒量」都不同,所以既有的檢查抓不到它**:
- 問「有沒有證據?」⇒ **有**
- 問「證據是真的嗎?」⇒ **是**
- 問「量具驗過嗎?」⇒ **驗過,而且有正負對照**
- 🔴 **而沒有人問:「它答的是【哪一個】問題?」**

---

## 實例① · 截圖證明的是面板,不是安全

**場景**:板子 `#5`「TapPay 通知端點沒有限流」。主視窗回報:
> 「Sean 02:2x 把 `tappay-notify flood ceiling` 從 log 改成 429,**我親眼看過他的截圖,規則詳情頁 Then = 429**」

```
✅ 截圖證明：那個面板欄位顯示 429              ← 真的，我不質疑
🔴 它證明不了：300 / 60 秒對【真實 TapPay 尖峰】是安全的
🔴 它證明不了：改成擋之後 Firewall 的 Rate Limited 欄是 0
⇒ ⇒ 而【後兩者正是那一列自己拿來當前置的東西】
```

而那一列逐字寫著誤擋的代價:
> 「擋錯 = TapPay 的通知進不來 = **訂單付了款卻沒被標成已付**」(鐵則 12①)

⇒ **⇒ 一張真的截圖,支撐了一個「這件事做完了」的結論,而那個結論的風險面它一格都沒碰到。**

**2026-08-30 我重跑同一發**:

## 🔴 而實例② 的方向,是最壞的那一種

```
0 → 4  讀起來是【有人動工了】
而真相是【有人寫了註解說「我沒動這個」】
⇒ ⇒ 錯的方向【往好的走】
```
📌 **往好的方向走的數字,沒有人會回頭查。**
⇒ 一個往壞的走的假數字,下一個人會撞到;**一個往好的走的,會被當成好消息收下。**

## ✅ 可執行動作:**問量具它答的是哪一個問題**

引用任何一份證據 / 任何一個數字之前:

```
① 我的【結論】是什麼？（一句話寫出來）
② 這份證據 / 這把尺，直接回答的是【哪一個問句】？（也寫出來）
③ 🔴 兩句一不一樣？
   一樣 ⇒ 用
   不一樣 ⇒ 只能寫成「證據支持 ②，而 ① 未確認」，不得寫成「①已完成」
```

**兩個現成的填空範例:**
```
① 結論：TapPay 端點的限流做完了
② 證據答的：那個面板欄位現在顯示 429
⇒ 不一樣 ⇒ 寫「規則已設定為擋；而是否誤擋未確認」

① 結論：後台轉人工 UI 還沒做
② 尺答的：apps/admin 底下有幾個檔提到這個字串
⇒ 不一樣 ⇒ 這把尺要排除註解，或改用行為錨（有沒有 route/元件【讀】這個欄位）
```

## ✅ 動作的下一層版本:**這支檔沒有 ⇒ 它會不會在【上下游】身上?**

2026-08-30 同夜,我判「`#231` ④ 的告警有沒有接」時,**兩次差一步交出錯的結論**:

```
第一次：打開 api/cron/anomaly-alert/route.ts ⇒ needs_manual_review 零命中
        ⇒ 差一步就寫「告警沒接，④ 擋上線」
        🔴 而那支 route 查的是【寄信】的 deadman counts；付款那半住在 domain 層
第二次：打開 domain/payment/anomaly-alert.ts ⇒ 那個欄位【只在註解裡】
        ⇒ 差一步就寫「只有註解，沒接」
        🔴 而真正的 SQL 在【migration 的 RPC】裡，隔了兩層
           （最新一代 :316+43 逐字 WHERE a.needs_manual_review = true）
```

📌 **⇒ 我停在【我打開的那一支檔】,而那件事住在下一層。**

⇒ 所以「往右再讀一欄」有一個**深度方向**的版本:
```
🔴 這支檔裡沒有 ⇒ 不等於這件事沒做
   ① 誰【呼叫】它？（往上游）      ② 它【呼叫】誰？（往下游）
   ③ 資料是不是住在 DB 函式 / migration 裡？（碼看不到的那一層）
   ⇒ 三個都問過才准寫「沒接」
```

🔴 **而這兩次的錯法方向【一樣】:我會報出一個【比真相更嚴重】的結論。**
⇒ 而那種錯**不會被質疑,它會被當成盡責** —— 與 `A-20260830e` 同一個方向的成本。

## ✅ 而同夜第三個實例:**我答了一個問題,而它的分母是錯的**

主視窗問我「這兩項擋不擋上線 —— **答案決定它進不進那 13 件**」。
我判「不擋 ⇒ 移出 13」,而它照做並算成 `13 → 11`。

```
🔴 而 -b9 逐列核過：#231 的 ①④【從來不在那 13 列裡】
   （13 是板子 B 節的列；①④ 是 backlog 條目的子項 ⇒ 兩個分母）
⇒ ⇒ 我的判斷【對】，而我建議的動作【對一個不存在的集合生效】
```
📌 **⇒ 我接下題目時,把提問者的分母【原封收下】,沒有驗它。**
⇒ **動作要加一句:「這個東西現在在不在那個集合裡?」—— 在提出「移出/加入」之前先問。**
⚠️ 而這一格**不是提問者的錯要我扛** —— 是**兩邊都沒驗,而只要有一邊驗就抓得到**。

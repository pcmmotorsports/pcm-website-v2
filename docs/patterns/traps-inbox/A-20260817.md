## 尺是對的、自檢也真的有判別力,而**基準是手打的,沒有人回去對過**〔安靜〕

> **這是那一族的第三種。** 前兩種是:
> ```
> ① 量具對準了別的東西   （尺歪了）
> ② 量具射程看不到那層   （尺太短）
> ③ 🔴 尺是對的、自檢也有判別力，而【正確答案那一份】是手打的   ← 本則
> ```

### 判別句

> **我這把尺拿來比對的那份「正確答案」,是誰打的?打完之後,有人回去對過原始碼嗎?**

(主視窗提的,我照用 —— 它把問題從「尺準不準」移到「**基準從哪來**」,而那正是沒有人會想到要查的一格。)

### 實例(2026-08-17 A 窗,本 session 實跑)

訂單面板確認稿 `c3c6cc94` 頁尾有一支**雙向按鈕對帳** `#btncheck`:
```
① 稿上有、後台沒有   ⇒ 0 顆 ✅
② 後台有、稿上沒畫   ⇒ 0 個 ✅
量具自檢：餵一顆假鈕 ⇒ 被抓到 ✅ ／ 餵一個沒畫的動作 ⇒ 被抓到 ✅
```
**四樣東西全綠,而它比對用的那份 `REPO` 清單(手工維護)裡,八顆有四顆是錯的:**

| 清單寫的 | code 真實字面 | 出處 |
|---|---|---|
| 建立出貨 | **建立包裹** | `shipment-launcher.tsx:207` |
| 作廢這一箱 | **作廢這箱**(少一個「一」) | `shipment-void-button.tsx:79` |
| 線上退款(TapPay) | 那是 **`<h2>` 區塊標題,不是按鈕**;真的鈕是 **全額退款 / 部分退款** | `refund-section.tsx:108` / `:52-53` → `:211` |
| 申請取消整張單 | **整單取消** 與 **取消勾選的品項**(兩顆) | `cancel-order-forms.tsx:171` / `:229` |

**數法(可重跑;非 `.test.tsx`)**
```
grep -rn '建立出貨'       --include='*.tsx' . | grep -v '\.test\.' | wc -l  ⇒ 0
grep -rn '作廢這一箱'     --include='*.tsx' . | grep -v '\.test\.' | wc -l  ⇒ 0
grep -rn '申請取消整張單' --include='*.tsx' . | grep -v '\.test\.' | wc -l  ⇒ 0
量具對照（同一把 grep 查真實字面）:
grep -rn '建立包裹' … ⇒ 6      grep -rn '作廢這箱' … ⇒ 1
⇒ 那三個 0 不是「這把 grep 什麼都找不到」
```

### 🔴 封頂句

> **前一任畫了五顆幽靈鈕被抓到;這四顆躲過了,因為它們躲在【抓幽靈的那把尺裡面】。**

### 為什麼它安靜

```
① 對帳器【有自檢】，而自檢通過 ⇒ 讀的人（包含我）就結案了
   —— 自檢驗的是「比對邏輯會不會動」，不是「基準對不對」，這兩件事沒有任何地方寫在一起
② 兩個 0 的字面是「稿上有後台沒有 ⇒ 0」，而它真正的意思是
   🔴「畫的東西與那份手打清單一致」—— 兩句話讀起來一樣，指的不是同一件事
③ 基準錯的方向【剛好對稱】：清單寫「建立出貨」、稿也畫「建立出貨」⇒ 兩邊一致 ⇒ 零報警
   （錯得一致比錯得不一致更安靜）
④ 那份清單旁邊本來就寫著「🔴 這份 REPO 清單是人工維護的」—— 警語在，而沒有人去執行它
   📎 memory `feedback_knowing-rule-is-not-executing-rule` 當天第 N 次兌現
```

### 動作(不是決心)

1. **任何「對照清單 / 白名單 / 期望值表」,建立當下就標三件**:誰打的、依據哪個檔、**下次何時重驗**。
2. **重驗要逐顆開檔,不抽驗** —— 本次 8 顆錯 4 顆,抽 2 顆有 25% 機率全過。
3. **自檢要能分辨兩種綠**:「比對邏輯會動」vs「基準是對的」。前者用假資料餵得出來,
   **後者只能回去讀原始碼** ⇒ 🔴 **做不到自動化就明寫「基準未重驗」,不要讓兩個 0 自己去講它證明不了的話。**
4. 修完**把這件事講給讀那份產物的人看**(本次寫成稿上一塊紅字),
   不要只寫進 commit body —— **他之前正是照那張稿在規劃工作流。**

### 與既有條目的關係

- 同一族的前兩種在 canonical:「**輸出合法、格式正確、數量合理**」(尺歪)與各條射程限定(尺短)。
- 近親:「**一個活的數字與一個寫死的數字**」—— 那條是**兩份資料分岔**,
  本條是**只有一份資料,而它從出生就是錯的**。

## 比較圖會製造出不存在的差別〔安靜〕

> **一張比較圖的預設失敗方式,不是漏講差別,是【讓人以為某個東西是差別】。**
> (主視窗抽的,我照用。)

### 判別句

> **我這張圖上,有哪些東西是【兩案一樣】的?我有沒有明講它們一樣?**

### 症狀

並排兩案時,讀者會把**兩案相同的東西**讀成差別 —— **因為它出現在一張「講差別」的圖上**。
版面本身就在說「左右不同」,而讀者不會逐項去問「這一項到底一不一樣」。

### 實例(2026-08-17 A 窗,artifact `1ff3e1de`「採購擺哪」)

Sean 要判「採購那塊留在訂單層,還是搬進品項展開列」。兩案並排之後,**這兩件事其實完全相同**:
```
① 同一個品項的兩家供應商  ⇒ 兩案都是兩列並排看得到（乙案收進展開列之後仍在同一張表裡）
② 可填可改的八個欄位      ⇒ 兩案一欄都沒有增減
```
**不標明的話,它們讀起來像乙案的代價。** ⇒ 圖上另立一塊
「**這兩件事兩案是一樣的 —— 不是差別**」。

🔴 **而真正的差別也因此才浮出來**:不是「同一項的兩家」(那不是差別),
是**跨品項** —— 甲案「某家供應商那三筆一起看」是一眼,乙案做不到(那三筆分在第 4、第 8 與第 3 項裡)。
**先把假差別劃掉,真差別才看得見。**

### 為什麼它安靜

```
① 沒有人會回報「我以為那是差別」—— 他只會【據此改主意】，而改完看起來完全正常
② 圖越漂亮、對比越強，這個效果越大（並排＋色塊＋大數字都在說「左右不同」）
③ 作者最不可能發現：作者知道哪些一樣，所以【他讀那張圖時不會誤讀】
```

### 動作(不是決心)

1. 產出任何比較物(圖 / 表 / A-B 選項)之前,先列一份「**兩案相同**」的清單,**並且把它印在圖上**。
2. 相同的那些**要放在同一個視覺份量**,不要縮成小字 —— 縮小等於沒寫。
3. **先劃掉假差別,再找真差別**:本次真差別是在劃掉假差別之後才浮出來的。

### 與既有條目的關係

本族其餘各條都在講「**量錯東西**」;**本條是【呈現】讓讀者量錯東西** ——
壞的不是我的量測,是我把量測結果擺出來的方式。

## 結論對、而理由只有一半 —— **拿半個理由能推翻半個結論**〔安靜〕

> **來源:V 窗(Fable)2026-08-17 驗我一條宣稱時的原字,主視窗轉來。**
> 我把它擴寫成條目,**那句判別句是它的,不是我的**。

### 判別句

> **我給的理由,少了哪一段之後仍然成立?**
> 少一段就垮 ⇒ 那一段一定要寫出來。**理由不完整比結論錯更危險 ——
> 因為下一個人是【照理由】決定要不要重看,不是照結論。**

### 實例(2026-08-17 A 窗,我自己那條)

我在 plan 裡寫「空箱區**不可能**搬進品項展開層」,理由只給一段:
```
我寫的    shipments 表沒有 order_id ⇒ 它與這張訂單之間一條線都沒有
反駁      繞 shipment_items → order_items 就推得出訂單 —— 【對非空箱確實推得出】
⇒ 我的理由被推翻了一半，而【結論仍然成立】
```
**結論靠的是另外兩段,而我一段都沒寫**:
```
② 空箱【依定義】零 shipment_items 列 ⇒ 間接路徑對空箱是空集合，真的無路
③ COMMENT 自己寫「一箱可含多張訂單」⇒ 掛到某一個品項的展開層對【任何】箱都是型別錯誤
   （多對多硬塞一對一），不只空箱
```

### 為什麼它安靜

```
① 結論是對的 ⇒ 任何驗證「結論」的動作都會通過
② 理由讀起來完整（有出處、有行號、語氣肯定）—— 缺的是【我沒想到要寫的那兩段】，
   而缺席的東西沒有任何形狀
③ 🔴 最危險的下游不是「有人反駁」，是【有人反駁成功之後把結論一起丟掉】
   —— 他手上只有那半個理由，推翻它就沒有別的了
```

### 動作(不是決心)

1. 寫「不可能 / 做不到 / 一定會」這種**強結論**時,**列出所有承重的理由**,不要只寫最好講的那一段。
2. **自我攻擊一次**:每一段理由假設被推翻,結論還在嗎?**還在 ⇒ 那段不是承重的,而承重的那段我沒寫。**
3. 別人替你補上缺的那半時,**把補的那半寫進原檔**,不要只留在訊息裡。

### 與既有條目的關係

- 與「**比較圖會製造出不存在的差別**」互補:那條是**多講了不存在的東西**,本條是**少講了承重的東西**。
- 📎 memory `feedback_scoped-claim-this-only-affects-X` 記過「**理由錯而結論對不代表沒事**」——
  **本條是它的另一半:理由【不完整】而結論對,一樣不代表沒事。**

## 🔴 我用文字描述的那個代價,跟畫出來之後看到的代價,**不是同一個**

> **判別句:我用文字描述的那個代價,跟畫出來之後看到的代價,是同一個嗎?**

### 這一則不是事故,是**方法本身的正面實例**(2026-08-17,同一天同一題)

```
同一題「採購那塊要不要搬進品項展開列」，兩種給法：

第一次 · 文字   主視窗告訴 Sean:「搬過去之後一次只能展開看一項」
                ⇒ 他【沒有動】

第二次 · 圖     並排兩案 + 一個他做取捨要用的數字（8 品項:0 下 vs 8 下）+ 多列乘出來的樣子
                ⇒ 他【當場拍板】，而且【推翻了自己先前選的 A 甲的一部分】
```

🔴 **而他拍板的依據,是【文字版沒有講對的那一層】**:
```
文字講的  「一次只能看一項」
真正的痛  「同一家供應商跨三項的單，甲案一眼掃完，乙案散在第 4、第 8、第 3 三個展開層裡」
⇒ 這一層是【畫圖的時候才長出來的】——
   畫之前我以為代價是「要多點幾下」，畫出來才看到代價是「某些問題【問不出來】」
```

### 為什麼文字會漏掉那一層

```
① 文字描述的是【單一元件的行為】（「一次只開一項」）
   而代價發生在【乘出來之後】（8 項 × 3 家供應商的分佈）—— 單一元件的描述裡不存在「分佈」
② 寫文字的人腦中有一張圖，而【他描述的是那張圖的規則，不是那張圖】
   規則是對的，而讀的人腦中生不出同一張圖
③ 🔴 沒有人會回報「你的文字讓我低估了代價」—— 他只會【不採取行動】，而不行動沒有任何形狀
```

### 動作

1. **視覺類 / 版面類的取捨,一律畫出來**(Sean 08-17 常設令)——
   本則是那條令的**乾淨正面實例**:同一題、同一天、兩種給法、兩種結果。
2. **要放「乘出來」的樣子**(多列 / 多品項),不要單一元件 —— **代價住在乘出來的那一層。**
3. 畫完之後**回頭看自己原本的文字描述**:如果兩者講的不是同一件事,
   **那份文字要更正,不能留著** —— 它會被下一個人當成結論引用。

### 與既有條目的關係

- 與「**比較圖會製造出不存在的差別**」是同一張圖的兩面:那條講**圖會多講**,本條講**文字會少講**。

## `find -newermt` 在本機**報錯、回 0 行、而 `rc` 是 0** —— 三個訊號同時沉默〔安靜〕

> **來源:B 窗 2026-08-17 實測 + 主視窗廣播。🔴 而我【同一晚自己踩了一次】,下面是我的複現。**

### 判別句

> **我這條掃描裡有沒有【時間條件】?有 ⇒ 當場跑一次正向對照(餵一個一定命中的),再相信那個 0。**

### 我自己踩的那一次(本 session 實錄)

我用 playwright 存了一張截圖,然後找它:
```
我當時跑的   find /Users/sean_1 /private/tmp -name 'panel-full.png' -newermt '-10 minutes' 2>/dev/null
             ⇒ 零輸出 ⇒ 我當場對外說「screenshot file not found」
🔴 事後複跑（拿掉 2>/dev/null）:
             bfs: error: Invalid timestamp.
             rc=0
🔴 拿掉時間條件重查:
             /Users/sean_1/pcm-website-v2/panel-full.png     ← 它【一直都在】
```
⇒ **我報出去的那句「找不到」是錯的,而它讀起來完全正常。**
(所幸沒有改變任何結論 —— 我改用 `evaluate` 量幾何,沒有依賴那張圖。**但那是運氣,不是設計。**)

### 成因(B 窗當場量的,我複核了自己那一發)

```
本環境的 find 是包住 bfs 4.1.1 的 shell function
bfs 只吃 ISO 8601-like；'-90 minutes' / '30 minutes ago' 這類 GNU 相對格式【直接報錯】
      find ~/pcm-mailbox -name '*.md' -newermt '-90 minutes'          ⇒ 錯誤 → 0 行
      find ~/pcm-mailbox -name '*.md' -newermt '2026-08-17T18:07:00'  ⇒ 4
      find ~/pcm-mailbox -name '*.md' -newermt '2026-08-17T00:00:00'  ⇒ 65
```

### 🔴 為什麼它比今晚其他每一個都安靜

```
① 錯誤訊息走 stderr ⇒ 接 | wc -l 或 2>/dev/null 就【完全看不到】
② exit code 仍是 0  ⇒ && 串接照樣往下跑，任何「rc 非 0 才停」的紀律都攔不住
③ 輸出 0 行         ⇒ 與「真的沒有」一模一樣
```
**今晚我做的每一個「零命中」斷言都配了量具對照(所以那些不受影響)** ——
🔴 **而這一族的特別之處是:連 `rc` 都不會告訴你。** 量具對照是唯一擋得住的那道。

### 動作

1. **改用 `ls -lt <dir>/*.md | head -8`** —— **兩個世界會印不同的第一行**,不需要記任何格式。
2. 非用 `-newermt` 不可 ⇒ **給 ISO 格式**(`2026-08-17T18:07:00`)**且當場跑正向對照**。
3. **不要 `2>/dev/null`**,除非你已經知道 stderr 會有什麼。

### 🔴 它是復發,不是新發現

`~/pcm-mailbox/A-032-STOP.md:61` 逐字記過同一件事。**教訓躺在信箱裡,而今晚兩個窗照樣踩** ——
📎 memory `feedback_knowing-rule-is-not-executing-rule` 的又一次兌現。
**這也是為什麼修法要是「換一條不需要記得的命令」(`ls -lt`),不是「下次記得給 ISO」。**

### 順帶(同一次操作撿到的)

playwright 存截圖時**給相對檔名會落在 cwd 根**,而 `.playwright-mcp/`(預設路徑)**有被 `.gitignore` 擋**
(`.gitignore:59`)、根目錄**沒有** ⇒ 那張圖變成主工作樹的 `?? panel-full.png`。
**已刪(確認過尺寸 720×4550、時間戳是我產的那一刻)。** ⇒ **存檔一律用預設路徑或明確寫進 scratchpad。**

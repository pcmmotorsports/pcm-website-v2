- 🔴 標題刻意含「對帳」與「兩個數」—— 下一個人會用那兩個詞搜,而他要同一發撞到兩條。

## 那一條講什麼

> 兩份完全不相交而總數一模一樣 ⇒ 那是最像「同一件事」的一種形狀。
> **對不上 ⇒ 觸發對帳;對得上 ⇒ 結束對帳。**

⇒ 它的形狀是:**兩個數【相等】,而相等被讀成互相印證。**

## 🔴 而我這一發是隔壁那一格:兩個數【不相等,只差 1】—— 而那更糟

我要答:**線 DB 那條分支落地之後,dev 上會真的變的檔有幾支?**(要端進 plan 的爆炸半徑)

```
git diff --name-only origin/dev HEAD    (兩點) ⇒ 24 支
git diff --name-only origin/dev...HEAD  (三點) ⇒ 25 支
```

兩個獨立量法,差 **1**。而全隊當時的紀律是「報半徑一律用三點」⇒ 照做會寫 25。

🔴 **而 24 與 25 都不是答案。真值是 22 —— 它在兩個數的【外面】。**

```
comm -13 兩點 三點 ⇒ 只在三點裡 3 支 = 已被 cherry-pick 走、兩邊 sha256 逐字相同
                     ⇒ 落地是【零改動】⇒ 三點把它們算進來 ⇒ 偏大 3
comm -23 兩點 三點 ⇒ 只在兩點裡 2 支 = 別人剛推上去的、dev 比我新
                     ⇒ 我沒有貢獻, 只會蓋掉 ⇒ 兩點把它們算進來 ⇒ 偏大 2
comm -12          ⇒ 交集 22  ← 三條路都落在這裡(25−3 / 24−2 / 直接數)
負對照 origin/dev 對自己 ⇒ 兩點 0 · 三點 0
```

## 📌 為什麼「差 1」比「相等」更會結束對帳

```
相等   ⇒ 讀成「互相印證」        ⇒ 至少那是一個【正面的宣稱】, 有人可能會去問它憑什麼
差 1   ⇒ 讀成「小數點誤差」      ⇒ 🔴 它連宣稱都不是, 它是【雜訊】
                                  ⇒ ⇒ 而人不會去對帳雜訊。
```
🔴 **而那個 1 不是雜訊 —— 它是 5 支檔在兩個相反方向上抵銷之後剩下的餘數。**
偏大 3 與偏大 2,差 1。⇒ **兩個錯的方向相同(都偏大),而它們的【差】小到看起來像沒有錯。**

📌 **⇒ 一句話:兩個數相差很小,不代表它們接近真值 —— 只代表它們錯得很像。**
⇒ ⇒ 而「錯得很像」在兩把尺共用一個盲區時是**預設結果**,不是巧合:
   這兩把尺共用的盲區是**它們都只比「有沒有差異」,不問「這個差異是誰造成的」。**

## ✅ 可執行的處置(不是提醒)

```
🛑 不要比兩個【數字】然後挑一個。
✅ 比兩份【清單】, 然後跑三個方向:comm -13 / comm -23 / comm -12
   ⇒ 每一個差集都要答得出「這幾支為什麼只出現在這一邊」
   ⇒ 答得出來的那幾支, 就是要從分母裡扣掉的
```
⚠️ **射程**:這一招要兩把尺產出的是**可比對的清單**。若一把尺只吐一個總數(常見於
`count(*)` / `wc -l` / 測試摘要行),**這一招用不上** —— 而那正是正本 `:31106` 那一條
講的「同源就沒有證人」的位置。⇒ **先問「這把尺吐得出清單嗎」,吐不出來就先換尺。**

📌 **⇒ 前兩發是「寫的當下對, 後來過期」;這一發是【我就是讀端, 我重量了, 而檢查與動作之間還有時間】。**
🔴 **⇒ 一把「量完就過期」的尺, 它的綠與一把壞尺的綠長得一樣。**

✅ **可執行**:`git checkout <branch> -- <path>` **結構上沒有 TOCTOU 防護** ——
它不看共同祖先、不比對、不會因為對面變了而拒絕。⇒ 熱檔改用
```
git diff <merge-base> <branch> -- <檔> | git apply -3 --index
```
`-3` 吃不下就留衝突標記 ⇒ **它的紅是動手當下的,不是三分鐘前的觀測。**
⚠️ 而純新增的檔(對面沒有那支)仍可 `checkout --` —— **結構上沒有東西可以被刪。**
🔴 **⇒ 判準不是「上次這樣做沒事」** —— 主視窗 11:0x 用同一個指令取三支 `.ts` 是安全的,
**而安全的原因不在指令裡,在那三支剛好是純新增。「上次沒事」在這個指令上零預測力。**

### 四輪審查, 最後一輪的 must-fix 一條都不在碼裡 —— 東西是對的, 而描述它的話一直在超前

一片「純加四條 policy」的 migration, 四輪對抗審查全 FAIL:**8 / 9 / 11 / 7 條**。
而第四輪那 7 條 must-fix **一條都不在 SQL 裡** —— 全在檔頭的
**註解、來源、座標、數字**上。碼與斷言那半連續兩輪被判「關上了」。

⇒ 🎯 **不是我修得不夠仔細, 是【我描述它的話】跑在【我驗過的東西】前面。**

其中兩條的形狀值得單獨記:
```
A1 我做了一張表支持「23 個逐格相同」這個結論
   ⇒ 而那張表【漏了一列】, 漏的偏偏是【結論在講的那一列】(要補 I+U 的那張)
   ⇒ 📌 表裡 22 個, 而我寫 23 —— 而它讀起來完全正常, 因為少的那列沒有留下空格
A3 我寫「判準【抄自】某支 migration, 不是我自己造的」
   ⇒ 而我【改了兩處】而沒說:拿掉一條、保留了另一條
   ⇒ 🔴 保留的那條正是我上一版被判「尺太寬」的同一條
   ⇒ 📌 「抄來的」這三個字讓那把尺看起來有第三方背書, 而它有一半是我的
```
🔴 **判別句(交件前對【每一句事實陳述】問一次)**:
> **這句話我是【量到的】還是【寫得順】?** 而如果它引用了別人的東西:
> **我引用的那份, 我自己打開過嗎?我有沒有【改過它而沒說】?**

🛑 **而這一族不會被「再審一輪碼」抓到** —— 前三輪都在問碼,問到第四輪換角度問
「宣稱 vs 事實」才整批掉出來。⇒ **審查的角度決定它抓得到哪一族;同一個角度審四輪,
第四輪只會更細,不會換族。**

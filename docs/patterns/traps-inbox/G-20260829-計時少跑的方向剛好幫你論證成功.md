# 🔴 少跑的迴圈在【計時】上比在【測試】上難發現一格 —— **因為數字變小正好是你想要的方向**

> 2026-08-29 · 線G `-1c` · 主視窗 `-48` 要求投條
> 🔴 **這一條的新內容不是「迴圈少跑」, 是【錯誤的方向與論證的方向同一邊】。**

---

## 事情

主視窗要我量「把一道守門裝進 CI 會多花多久」。第一發:

```
只跑 5/6/7 三份 ⇒ 2.7 秒
跑 1..7 七份    ⇒ 2.6 秒
```
🔴 **七份比三份還快。** 而兩個數字都很正常、`rc=0`、沒有任何東西報錯。

**成因**:zsh 對**變數**不斷詞 —— `for n in $1` 拿到的是一個字串 `"5 6 7"`,
**迴圈只跑一次**(而那一次 Chrome 去開一個不存在的檔,靜靜地失敗)。

✅ **抓到它的不是那兩個秒數, 是我順手印的「產出頁檔數只有 2」。**

改成 `while IFS= read -r n` 逐行餵、並把**實跑份數**跟時間印在同一行之後:
```
三份 ⇒  8.5 秒 / 實跑 3 份
七份 ⇒ 20.4 秒 / 實跑 7 份
```
⇒ **真值是我第一次量到的三倍以上。**

---

## 🔴 而重點在這裡:**計時比測試難發現一格**

```
一個測試少跑 ⇒ 少一格綠 ⇒ 【總計行上看得到】
              （那正是鐵則 11 的「我餵幾條 vs 它跑幾支」）
🔴 一個計時少跑 ⇒ 【只是數字變小】
```

### 而更難的那一半

```
🔴🔴 數字變小【正好是你想要的方向】。
我當時在論證「這個代價很小,值得裝」——
而那個 bug 剛好幫我論證成功。
⇒ 一個會讓你更快得到你想要的結論的錯誤，是最不會被回頭查的那一種。
```

---

## ✅ 可執行

```
任何一個「跑 N 次要多久」的數字，旁邊必須印出【它實際跑了幾次】。
沒有那一格，那個秒數在「真的很快」與「根本沒跑」之間【沒有判別力】。
```
📌 **⇒ 那就是鐵則 11「我餵幾條 vs 它跑幾支」套在【計時】這一層。**
⚠️ 而它要印在**同一行**:兩個數字分開印時,只有一個會被複製走。

## 🛑 而這條 CLAUDE.md **已經寫著**

終端機紀律那一節逐字:
> 迴圈一律 `while IFS= read -r f; do … done < 檔案`, **不要 `for f in $VAR`**

🔴 **而我今晚引用過它兩次, 然後自己踩了。**
⇒ 機制優先律的又一個實證:**講規矩不會提高套用率。**
⇒ 而這一條的機制版本就是上面那句「把實跑次數印在數字旁邊」——
**它不是提醒, 它是一個【印出來就看得到】的東西。**

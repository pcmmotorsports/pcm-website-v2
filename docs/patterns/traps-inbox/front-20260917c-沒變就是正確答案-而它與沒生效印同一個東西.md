## 「before 跟 after 一樣」有兩種意思,而它們印同一個東西〔安靜〕

**線** `front` 2026-09-17 · FF main 上線驗收(八格) · **自述**

### 事情

八格驗收裡,**三格 before/after 完全相同**。而那三格**全部是對的**:

| 格 | before | after | 相同的意思 |
|---|---|---|---|
| 正對照:上架中真商品 | HTTP 200 | HTTP 200 | 🟢 **對** —— 守的是「不要修出一個全部都 404」 |
| 裸 `/products` noindex | 0 | 0 | 🟢 **對** —— 它本來就該被 Google 收 |
| `?pbrands=gilles` 單一篩選 noindex | 0 | 0 | 🟢 **對** —— 單一篩選刻意保留可索引 |

而同一份報告裡,另外有一格 before/after 的**第一跳**也相同,那一格是**陷阱**(見 `front-20260917b`)。

🔴 ⇒ **「相同」本身不帶資訊。** 它可以是「守住了」,也可以是「沒生效」,
而 `curl` 印出來的**是同一個東西**。

### 🎯 母題

驗收報告最容易出的兩種錯,是**同一件事的兩個方向**:
```
病 A  把「守住了」讀成「沒生效」 ⇒ 去修一個沒壞的東西(今天三格差點)
病 B  把「沒生效」讀成「守住了」 ⇒ 恆綠,永遠不會有人發現(今天一格差點)
```
📌 **分辨器不是讀數,是【這一格的判準有沒有在量之前寫下來】。**
而判準要寫兩件事,不是一件:
> **成功長什麼樣** + **最壞的失敗長什麼樣**

本片實例(寫在腳本裡,不是寫在腦子裡):
```
正對照   成功 = 200 且位元組同量級
        🔴 最壞失敗 = 掉到【兩萬那一階】⇒ 真商品被截短成「商品不存在」那一頁
noindex  成功 = 裸 0 · 單一篩選 0 · 多重篩選 ≥1
        🔴 最壞失敗 = 三個【全部】變 1 ⇒ 不是成功, 是把整個目錄關掉了
```
⇒ 有了「最壞失敗長什麼樣」,`0 / 0 / 1` 這一組讀數才讀得出是**成功**而不是**部分失效**。

### 🔵 而「同量級」這個判準,原本是我隨口寫的

腳本第一版寫「掉到 3 萬多就是被截短」—— **那個 3 萬是估的,沒有量過。**
實測之後:
```
真商品頁  486,219 位元組
那顆 404 頁  20,526 位元組     ← 被截短真的會落在這一階
```
⇒ 📌 **差兩個數量級**,而我原本寫的 3 萬**剛好卡在中間、兩邊都不像**。
✅ 量到之後把實測值寫回腳本判準 ⇒ **下一個人用到的是量過的數字,不是我當初隨口寫的。**

🛑 而同一格 before→after 是 496,611 → 486,219(**-2.1%**)——
**我沒有把這 2% 歸因到任何原因**(頁上有動態內容)⇒ 逐字標「**推論,未核**」。
✅ 我改去核**內容本身**:「加入購物車」命中 3 次、「GB Racing」8 次、「商品不存在」**0 次**。
⇒ 📌 **位元組數答不出來的時候,換一把答得出來的尺,而不是把 2% 講成「應該是快取」。**

### ✅ 可機械執行

> **每一格驗收判準寫兩行,缺一行就不要開始量:**
> ```
> 成功 = ____
> 最壞的失敗 = ____        ← 而它必須是【可以被量到】的樣子, 不是「壞掉」
> ```
> **報告一律逐格寫「從什麼變成什麼」,並且【點名哪幾格沒變、以及沒變代表什麼】。**
> 🛑 不得只寫「都對」「全綠」「符合預期」—— 那三句話在病 A 與病 B 底下都成立。

### 🔴 同族加一格:**拿兩個 ref 直接比,印的是「兩邊的差」,不是「我做了什麼」**

2026-09-17 我**同一天踩兩次**,而第二次是在**核自己的東西**的時候踩的。

```bash
# ❌ 兩個 ref 直接比 —— 我用它來回答「我改了什麼」
git diff --name-only origin/dev..HEAD
git diff origin/dev HEAD -- <某個目錄>

# ✅ 問「我做了什麼」就逐顆問那幾顆
git show --name-only --format= <我的commit>
# ✅ 真要用 diff, 用三點(merge-base 起算), 而且限縮到自己的檔
git diff --name-only origin/dev...HEAD
```

**兩次的成因同一句,而偽裝完全不同 —— 所以第二次沒有認出第一次:**

| | 我看到的 | 我差點得到的結論 | 真相 |
|---|---|---|---|
| 第一次 | 17 支檔,含 `receipt-*.tsx` / migration / `APPLIED.tsv` | 「我改了一大包後台的東西」 | `origin/dev` 13:39 走到我前面,我沒 fetch |
| 第二次 | 別人那則 traps **`deleted file mode`** | 🔴「**我把別人的筆記刪掉了**」 | 那支是 `origin/dev` 有而我本地沒有 |

🔴 📌 **同一個錯法,兩種不同的恐慌** —— 一種是「我做太多」,一種是「我毀了別人的東西」。
⇒ **而「用三點不要用兩點」這句話記不住**,因為它長得像語法細節。
⇒ ✅ **記得住的是那一句**:
> **`git diff <A> <B>` 回答的是「A 與 B 差在哪」。**
> **它從來不回答「我做了什麼」—— 而當 B 落後 A 的時候,它會把【別人做的】算到你頭上,方向還是反的。**

🔵 **而這一格與本條母題是同一個形狀**:讀數是真的,判準錯了。
`deleted file mode` 那一行**逐字為真** —— 那個檔在 HEAD 這一側確實不存在。
⇒ 錯的不是 git,是**我問錯了問題**。

✅ **可機械執行**:
> **核「我做了什麼」一律 `git show --name-only` 逐顆問;要比內容就比【我那幾支】的 shasum。**
> 🛑 **先 `git fetch` 再用任何含 `origin/` 的 diff** —— 本地那個 `origin/dev` 可能是舊的,
>   而它舊的時候**不會報錯,只會給你一個看起來很合理的差集**。

### 📎 鄰居
- `front-20260917b`「驗轉址要看最終落點」—— **必須配著讀**,它是本條的病 B 實例。
- canonical「前後量測要有對照組,否則把環境漂移當成自己的成果」—— 本條是它的下一層:
  **有了對照組之後,還要能讀出「對照組沒動」是對的。**
- canonical「規則沒拿去量成功的那些」(`ship-20260906c`)—— 同一個形狀:只量失敗側。

### ⚠️ 這一條證不到什麼
- 那 **-2.1%** 我到最後**仍然沒有歸因**。我只證明了「它不是截短」,**沒有證明它是無害的**。
- 內容核對用的是 grep 四個字串,**不是畫面**。商品卡有幾張、版面有沒有跑掉,`curl` 看不到 ⇒ **未驗**。
- 「兩個 ref 直接比」那一格我**只有兩個樣本**(都是我自己、同一天)。
  它會不會在別人身上長成第三種偽裝 —— **不知道**。⇒ 寫下的是那兩種,不是「只有兩種」。

## 一個函式同時用 stdout【講話】與【回傳值】—— 而症狀落在下游,讀起來像**另一類**問題

> 線【DB】`-db` 2026-09-06。實錘 = `scripts/apply-paste-board.sh` 的 `preflight()`,第一版。

### 發生了什麼

```sh
preflight() {
  ...
  note "  貼板檔 $(basename "$paste")"          ← 講給人看的
  note "  版本號 $ver"
  ...
  printf '%s\t%s\t%s\n' "$ver" "$mig" "$paste"  ← 回傳值
}
# 呼叫端
PRE=$(preflight "$NUM" "$ROOT") || exit 1
MIG=$(printf '%s' "$PRE" | cut -f2)
```

進度訊息與回傳值**走同一條 stdout** ⇒ `$PRE` 是【講的話 + 結果】黏在一起
⇒ `cut -f2` 切出來的「路徑」裡**夾著中文說明**
⇒ psql 印:

```
/…/supabase/migrations/20990101000000_selftest.sql: No such file or directory
```

**而那個檔明明存在,`ls` 看得到。**

### 🔴 坑不在於它壞了,在於它壞掉之後**長成什麼樣子**

「**No such file or directory**」是一句關於**檔案系統**的話。
它會把我推去看:路徑對不對 · 權限對不對 · temp 目錄是不是被別人清掉了 · mount 有沒有問題。

而真正的病在**兩條訊息共用一個管道**。

🎯 **⇒ 症狀所指的那一層,與病灶所在的那一層,不是同一層。**
🛑 而錯誤訊息**本身完全正確** —— psql 拿到的那個字串,真的不是一個存在的檔名。
   **它沒有說謊,它只是在回答一個我沒有問的問題。**

📌 這就是為什麼它比一個「明顯的錯」貴:一個明顯的錯會停在原地,
   **而這一個會把我推到另一個房間去找。**

### 判別式(寫任何有回傳值的 shell 函式時問一次)

> **這支函式的 stdout 有沒有【兩種讀者】?**

有 ⇒ 🔴 **人要看的一律 `>&2`;stdout 只留回傳值。**

🔵 **連帶(下游那一端的判別式,比上面那條更常用得到)**:
> **下游說「找不到 X」,而你確定 X 在** ⇒ 先 `printf '%q\n' "$那個變數"` 把它**整個印出來看**,
> **不要先去查檔案系統。**

`%q` 是關鍵 —— 夾在裡面的換行與空白,用一般 `echo` 印出來**看起來就像正常的多行輸出**。

# 第 11 條(新開)· **它叫了 —— 而我把兩個嘴巴都摀住之後, 去讀它的排版**<br>(`ls A B 2>/dev/null` 從輸出的【排版】讀出一個不存在的實體;而 `rc=1` 一直在那裡)

> **成因這半只有當事人寫得出, 原稿逐字。`-b9` 判它與第 10 條【不同族】而拆開:**
> **第 10 條是【溝通載體】的病, 本條是【量具】的病 —— 它該住在量具坑那一族。**

## ⇒ 機制
```
ls A B 2>/dev/null    ← A 不存在
⇒ A 的錯誤被 2>/dev/null 吞掉
⇒ ls 只印 B 的「B:」段頭 + 內容
⇒ 🔴 段頭【下面】的子目錄，被讀成【頂層的兄弟】
⇒ ⇒ 從輸出的排版，讀出一個不存在的實體
```

## ✅ 而 `-b9` **現場重現了它**(2026-08-30,兩個世界必須印不同的東西 —— 而它們印了)
```
造：lsdemo/B/tappay-notify、lsdemo/B/other（A 刻意不建）

世界一（A 不存在）    ls A B 2>/dev/null ⇒  B:              🔴 rc=1
                                           other
                                           tappay-notify

世界二（A 存在，負對照）ls A B 2>/dev/null ⇒ A:                 rc=0
                                           （空行）
                                           B:
                                           other
                                           tappay-notify
```
🔴🔴 **而重現多量到一格, 原稿沒有:它【其實有叫】—— `rc=1`。**
```
被丟掉的是【兩個】訊號，不是一個：
  ① stderr ⇒ 被 2>/dev/null 主動丟掉
  🔴 ② rc   ⇒ 沒有人讀（而它兩個世界印不同：1 / 0）
⇒ ⇒ 📌 所以這一族的正確描述不是「它靜靜地錯」，是
      【它叫了, 而我把兩個嘴巴都摀住之後, 去讀它的排版】。
```
✅ **⇒ 而那讓修法變便宜**:不必換掉 `ls`,**只要在後面收一次 rc** —— 一行就有判別力。
⚠️ **而它仍不能取代 `test -e`**:`rc=1` 只說「至少一個 operand 掛了」,**說不出是哪一個**。

🔴 **⇒ 而它印出來的東西【每一個字都是真的】** —— 那些子目錄真的存在,
**錯的是它們的【層級】, 而層級在 `ls` 的輸出裡是靠【空行與段頭】表達的。**
📌 **⇒ 這一族的判別句不是「輸出對不對」, 是【這個輸出有幾個層級, 而我怎麼分辨它們】。**

## ⇒ 同族(原稿逐字):**吞 stderr 三兄弟**
```
· $(...) 把「拒絕執行」變成空字串                （-b4）
· --stat 截斷被讀成「補完了」                    （-e4 C?-截斷）
· 本條：ls 段頭錯位                              （-0b）
⇒ 共同形：**2> 那一側被丟掉，而剩下那半【看起來完整】。**
```

## ⇒ 可執行
```
🔴 要判斷「某個路徑存不存在」，不要用 ls 的【排版】—— 用一個【兩個世界印不同東西】的形狀：
   test -e <path> ; echo "rc=$?"        ← 存在 0 / 不存在 1，沒有第三種讀法

⚠️ 而 2>/dev/null 不是不能用 —— 是【用了它就不能再從輸出的形狀推結論】。
```

## 🔴 判別句
> **一條規矩點名了一個【動作】(`cat`), 而它要防的是一個【結果】(秘密出現在輸出裡)。**
> ⇒ **點名動作的規矩, 只擋得住想得到那個動作的人** —— 而下一個外洩會由另一個動作造成:
> `grep -r` / `rg` / `tail -f` / `find -exec` / 一支讀設定的腳本印出它讀到的東西 / `git show` 一個舊 commit。

📌 **⇒ 而最毒的一格是**:
> **字面命中的人會覺得自己合規。**「我沒有跑 `cat .env`」是**真的**,
> 而那句真話讓他停止懷疑 —— **一條窄規矩比沒有規矩更會關掉懷疑。**

## ⇒ 而這是【機制題】不是【規則題】(`00-work-rules §4` 機制優先律)

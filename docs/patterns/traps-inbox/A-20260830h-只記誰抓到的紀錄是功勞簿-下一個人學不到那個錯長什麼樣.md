# 只記「誰抓到的」的紀錄是**功勞簿** —— 下一個人學不到那個錯長什麼樣

- 線A `-e9` · 2026-08-30 · 觀察對象是 `-b9` 的一顆 commit(**正面實例**,不是事故)
- 🔴 時刻是 sandbox 的 `date`,不是 Sean 那台的鐘。

## 現場(**這一條是從一個【做對了】的例子倒推出來的**)

我給了一個**編出來的成因**:我量到 `find ⇒ 0` 而 `ls ⇒ 38`,然後寫「因為 symlink 讓 find 走不進去」。
**我一發都沒跑去驗那個解釋。** `-01` 把它急播給全隊,`-b9` 當場複量推翻,`-01` 追出真成因。

而 `-b9` 把這件事寫成坑檔時,歸屬行是這樣寫的:

> **🔴 歸屬:事件 ← `-e9`(給了錯成因)· `-01`(廣播、更正、追出真成因)· `-b9`(當場複量推翻 symlink 那半);寫成條 ← `-b9`**

📌 **它同時記了【誰錯了】與【誰抓到的】。**

## ⇒ 而多數寫法只會留下後者

```
常見寫法：「-b9 複量發現 find 的 symlink 說法不成立，真成因是 -maxdepth」
⇒ ✅ 每個字都是真的
⇒ 🔴 而它讀起來像【一份功勞簿】：誰很敏銳、誰抓到了
⇒ ⇒ 而【那個錯長什麼樣】不見了
```

🔴 **⇒ 下一個人從功勞簿學不到任何東西 —— 因為他要防的不是「不夠敏銳」,是「會編一個聽起來合理的成因」。**
**而後者只有在紀錄裡寫出【誰編的、編了什麼】才看得到。**

## ⇒ 為什麼這件事會自然發生(不是誰壞心)

```
寫紀錄的人，通常是【抓到的那個人】
⇒ 而寫「我抓到 X」很自然
⇒ 寫「某某給了一個錯的成因」感覺像在指責 ⇒ 會被自我審查掉
⇒ ⇒ 而那個自我審查，剛好刪掉的是【最有教學價值的那一半】
```

📌 **⇒ 所以這不是紀律問題,是【誰在寫】決定了【哪一半會被留下】。**

## ✅ 可執行動作:**歸屬行寫成三格,不寫成一句**

```
事件 ← 誰做的（把錯的形狀寫出來，一句話：「給了錯成因」「少跑一支」「引了改前的數字」）
發現 ← 誰抓到的 + 【用什麼抓到的】（那才是可複製的部分）
寫成條 ← 誰
```

🔴 **而「用什麼抓到的」那一格最容易漏,而它是唯一可移轉的東西:**
```
❌「-b9 複量發現不成立」        ⇒ 下一個人學不到怎麼複量
✅「-b9 跑 ls -ld /tmp /private/tmp ⇒ 看到方向相反」⇒ 可複製
```

## ⚠️ 天花板

- 🔴 **這條救不了「當事人自己寫」那種**:我寫我自己的錯時,一樣會傾向寫得比較輕。
  ⇒ 唯一的補償是**當事人寫的那一份,細節密度比較高**(本 repo 已驗過)——
  **所以兩份都要,不是二選一。**
- 它是**規矩不是閘**:沒有任何東西會在歸屬行只寫一半的時候變紅。
- 它只管**紀錄**;擋不住「這件事根本沒有被寫下來」。

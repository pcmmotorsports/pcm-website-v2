
## ⇒ 那句話**是對的**,而它有一個沒被寫出來的前提

```
它成立的前提是:【看到紅的人會去查】

```

**在深夜、在「事故」框架下、送到唯一有權限的那個人手上 —— 那個紅一點都不便宜。**

# ✅ 判別動作(機械的,而且就一句)

在把一把偵測用的尺送出去之前,問:

> ## **這把尺印紅的時候,我分得出【它壞了】與【它做對了】嗎?**

答不出 yes ⇒ **它還不是一把尺,它只是一個症狀。**

## 修法:**把「該不該有」也算成一欄,和「有沒有」並排**
```
🛑 錯   SELECT 有沒有信                       ⇒ 一欄,一個布林,兩個世界同色
✅ 對   SELECT 該不該有信, 有沒有信            ⇒ 結論在【組合】上,不在任何單獨一欄
        該不該 false / 有 false  ⇒ ✅ 正確排除
        該不該 true  / 有 false  ⇒ 🔴 真事故
        該不該 false / 有 true   ⇒ ⚠️ 反向異常(寄給了不該寄的人)—— 這一格單欄尺【完全看不到】
```
🔴 **注意第三列**:一把只看「有沒有」的尺,連**反方向的錯**都漏掉。
**⇒ 補上「該不該」不只是少報假紅,它同時多接了一種真異常。**

## 而「該不該」的定義**去哪裡拿**
```
🛑 不要自己想 —— 我以為的「該有信」是「有人下單」
✅ 去讀【真的在決定這件事的那段碼】,把它的述詞逐條抄成欄
   ⇒ 而那段碼就是規格本身;抄它 = 我的尺與被量的東西共用同一個定義
⚠️ 代價明寫:兩者共用定義 ⇒ 若那段述詞本身寫錯,我的尺會跟著錯
   ⇒ 這把尺答的是「**行為有沒有照它自己的規則走**」,不是「**規則對不對**」。兩件事,別合併。
```

## 而**布林不夠**的那一格
```
就算「該有信」,若 paid_at 早於 cutoff 仍會被正確排除(:199)
⇒ 所以 paid_at 要跟著印出來,不能只印 true/false
📌 **一個布林答得出「有沒有」,答不出「差多少」** —— 而修法住在「差多少」裡。
```

# 🔴 同一晚,**第二次** —— 而這一次在【判讀指南】那一層

## ⇒ 一句話

> ### **一份判讀指南沒有寫出「正常」那一格,**
> ### **讀的人就會把結果塞進【最接近的異常格】—— 而他不會覺得自己在猜。**

📌 **五個名字全部是異常名 ⇒ 那份指南在結構上不可能輸出「沒事」。**
🔴 而它比上半節那個病更難發現:上半節是**一欄布林**,一看就知道資訊不夠;
這裡是**五個選項、附判準、附下一步** —— **它看起來很完整,而它的完整性正是它的偽裝。**

## ✅ 判別動作(與上半節同一句,只是套在指南上)
```
把候選名列完之後,數一下:**有幾個是「它做對了」?**
  0 個 ⇒ 🔴 這份指南在結構上不可能判出「沒事」⇒ 回去補
✅ 而那一格要寫得**和異常格一樣具體**:寫出它的判準、寫出「⇒ 停手,不要修任何東西」
   —— 因為讀的人要的是【下一步】,而**一個沒有下一步的選項不會被選**。
```

## ⚠️ 而第二次教的那一格,第一次沒教
```
第一次的修法是「把正常放進尺裡」⇒ 我照做了,而我做的是【SQL 那一層】
第二次壞在【判讀指南那一層】—— 同一個病、換一個載體,而我【剛寫完它】
```
📌 **⇒ 修一個病的時候,要問:這個形狀還住在哪幾個載體上?**
`量具` / `判讀指南` / `選項清單` / `決策題的選項` / `告警的分類`
—— **它們全都會列舉異常而漏掉正常,而修好其中一個不會動到其餘四個。**

### ⚠️ 與既有條目的分界(查重時開過,寫出來免得下一個人再查一次)
```

🔴 本條不同:**尺是好的、量得也對,而【可能的結論清單】漏了一格** ——

```

# 🔴 第三節 · **錯的不是尺,是我把命中歸給了哪一個 pattern**

> ⚠️ **分母**:同一晚 **n=2**,**跨兩個窗**(`-b4` 與 `-1c`),而兩個是**同一句話的兩半**。
> `-48` 2026-08-30 03:1x 指出它們同族並要求把分母寫進來。**不是「又一次」。**

## 兩個現場

### ① 誤中(`-b4`):OR 樣式,**命中來自第二個,而我歸給了第一個**
```
我想知道:那支測試會不會讀我這支檔的原始碼(因為我只改了註解)
我跑的  grep -rln 'readFileSync\|check-anomaly-alerts.ts' --include='*.test.ts'
命中    check-anomaly-alerts.test.ts
我讀成  ✅「它會讀原始碼 ⇒ 我改註解可能會弄紅它 ⇒ 要跑它」
實際    那個命中來自【第二個 pattern】—— 檔名字串（一個 import 路徑）
        該檔 readFileSync ⇒ **0**
```
🔴 **後果**:我跑了那支測試、拿到 `1 檔 / 73 passed / rc=0`,
**而那個綠對我的改動【零判別力】**(我動到的三個字串在該測試檔命中 **0**)。
📌 **⇒ 差一步我就會寫「測試驗過了」—— 而那句話會是真的、也會是空的。**

### ② 漏掉(`-1c`):我猜的是**概念的字**,而檔裡寫的是**機制的字**
```
它搜  「內容雜湊」⇒ 0 命中 ⇒ 差點讀成「沒有人寫過這個做法」
實際  那份檔用的字是 `md5`
```

## ⇒ 共同的根,一句話

> ### **`grep` 回的是【有/沒有】,它不回【為什麼】——**
> ### **而當樣式裡有「或」、或那個字是我猜的,那個「為什麼」正是承重的那一半。**

📌 **⇒ 這與本檔前兩節是同一個病的第三層**:
```
第一節  量具的輸出裡沒有「該不該有」    ⇒ 分不出【壞了】與【做對了】
第二節  判讀指南的選項裡沒有「正常」    ⇒ 結果被塞進最接近的異常格
🔴 第三節  grep 的輸出裡沒有【哪一個 pattern 中的】⇒ 命中被歸給我期待的那一個
```
**三層都是:輸出少了一個維度,而少的那個維度正好是結論所依賴的。**

## ✅ 判別動作(兩個,都便宜)

```
① 樣式裡有「或」(\| / -e a -e b)⇒ **不要只看檔名清單**
   ✅ 改用 `grep -on` 或 `-o`,讓它把【命中的那段字】印出來
   ✅ 或者最笨也最可靠:**兩個 pattern 各跑一次,比兩個數**
      —— 一個 5 一個 0,與 各 5 各 5,在合併輸出上是同一份清單

② 拿到一個【0】而那個字是我自己想的 ⇒ 先問:
   **「這份檔如果真的做了這件事,它會用哪個字?」**
   ✅ 至少再跑一次【機制的字】(md5 / sha / hash),不要只跑【概念的字】(內容雜湊)
   ✅ 而 0 一律要有正對照 —— 本檔既有規矩,不重複
```

## ⚠️ 而它與「尺太窄」那族的分界(寫出來,免得被併錯)
```
尺太窄   ⇒ 尺【真的漏了】東西  ⇒ 修法是把尺放寬
🔴 本條  ⇒ 尺跑得【完全正確】,命中也是【真的】——
          錯的是我對「這個命中是誰造成的」的歸因
⇒ 把尺放寬對本條【沒有用】:①那個命中本來就在,②放寬只會多幾個一樣沒歸屬的命中
```

# ⚠️ 射程(免得被當成「不要報異常」)

```
❌ 它【不是】說偵測到異常先別講 —— 慢報一個真事故更貴
❌ 它【不是】要每個查詢都證明全世界正常
✅ 它只要求兩件事:
   ① 送出去之前問那一句
   ② 🔴 **講給人聽的時候,把不確定講在同一句裡**,不要放附件:
      🛑「8 張沒有信,可能還在發生」
      ✅「8 張沒有信,而我還沒分辨出是【不該有】還是【該有而沒收到】,一發查詢就分得出來」
📌 因為【加強語氣】與【加強證據】在讀的人那裡長得一樣,而只有後者是真的。
```

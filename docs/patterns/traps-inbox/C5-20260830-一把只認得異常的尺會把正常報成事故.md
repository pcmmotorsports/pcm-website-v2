# C5-20260830 · 一把只認得**異常**的尺,會把**正常**報成事故

> 投件窗 線C(`-b4`)· 2026-08-30 · 我自己當場踩到,而**它差一步就送到 Sean 面前**
> 📌 觸發情境寫成症狀:**「我做了一把尺去偵測 X 有沒有壞」的那一刻。**
> ⇒ 不寫「偵測器設計」—— 沒有人會去查那個主題,而每個人都在做那件事。

---

# 現場

```
現象   近 14 天 9 張訂單,8 張沒有「訂單成立」信
我的尺 一發 SQL:每張單印「有沒有信 = true/false」
結論   8 張 false ⇒ 🔴 事故,而且可能還在繼續
```
這句話已經被轉述給剛睡醒的 Sean,措辭是「**它可能今天還在發生**」。

## 而我回頭讀了決定「誰該有信」的那段碼

`packages/adapters/src/email/SupabasePaidOrderScannerAdapter.ts` 逐字:
```
:194   .eq('payment_status', 'paid')      ← 沒付款 ⇒ 本來就不寄
:198   .is('cancelled_at', null)          ← 已取消 ⇒ 本來就不寄
:199   .gte('paid_at',    input.cutoff)
:200   .gte('created_at', input.cutoff)
:201-202  已排過 order_created ⇒ 不重排
```

## ⇒ 🔴 那 8 張若是**沒付款 / 已取消的測試單**,系統**做對了**

📌 **而「它做對了」與「它壞掉了」,在我那把尺的輸出上是【同一個 false】。**

> ### **我做了一把尺去偵測「信沒寄出去」,而我沒有把「不該寄」放進去 ——**
> ### **⇒ 它印紅的時候,我分不出那是【壞掉】還是【做對了】。**

# 為什麼既有的規矩擋不住它

```
量具坑那一族(docs/patterns/guard-and-instrument-traps.md)全部在講【恆綠 / 假綠】——
  「錯的那次和對的那次長得一樣」「該紅沒紅」「守門恆綠」
🔴 而本條是【假紅】,方向相反
```
更麻煩的是:**這條線上有一句已立的、正確的判斷在替假紅背書** ——
memory 逐字「**假紅可以排隊,假綠不能**」。

## ⇒ 那句話**是對的**,而它有一個沒被寫出來的前提

```
它成立的前提是:【看到紅的人會去查】
⇒ 而查的成本由誰付、什麼時候付,決定了那個紅貴不貴
```
🔴 **本次那個假紅的價碼**(不是假設,是當天真的發生的):
```
① 它被貼上「事故」與「正在流血」的標籤
② 它被轉述給【剛睡醒、只想看結果】的 Sean —— 而他是唯一能跑正式庫 SQL 的人
③ 下一步本來是叫他去修一個【沒有壞的東西】
```
📌 **⇒ 假紅的成本 = 它讓多少人、用什麼身分、在什麼時刻去動什麼。**
**在深夜、在「事故」框架下、送到唯一有權限的那個人手上 —— 那個紅一點都不便宜。**

# ✅ 判別動作(機械的,而且就一句)

在把一把偵測用的尺送出去之前,問:

> ## **這把尺印紅的時候,我分得出【它壞了】與【它做對了】嗎?**

答不出 yes ⇒ **它還不是一把尺,它只是一個症狀。**

## 修法:**把「該不該有」也算成一欄,和「有沒有」並排**
```
🛑 錯   SELECT 有沒有信                       ⇒ 一欄,一個布林,兩個世界同色
✅ 對   SELECT 該不該有信, 有沒有信            ⇒ 結論在【組合】上,不在任何單獨一欄
        該不該 false / 有 false  ⇒ ✅ 正確排除
        該不該 true  / 有 false  ⇒ 🔴 真事故
        該不該 false / 有 true   ⇒ ⚠️ 反向異常(寄給了不該寄的人)—— 這一格單欄尺【完全看不到】
```
🔴 **注意第三列**:一把只看「有沒有」的尺,連**反方向的錯**都漏掉。
**⇒ 補上「該不該」不只是少報假紅,它同時多接了一種真異常。**

## 而「該不該」的定義**去哪裡拿**
```
🛑 不要自己想 —— 我以為的「該有信」是「有人下單」
✅ 去讀【真的在決定這件事的那段碼】,把它的述詞逐條抄成欄
   ⇒ 而那段碼就是規格本身;抄它 = 我的尺與被量的東西共用同一個定義
⚠️ 代價明寫:兩者共用定義 ⇒ 若那段述詞本身寫錯,我的尺會跟著錯
   ⇒ 這把尺答的是「**行為有沒有照它自己的規則走**」,不是「**規則對不對**」。兩件事,別合併。
```

## 而**布林不夠**的那一格
```
就算「該有信」,若 paid_at 早於 cutoff 仍會被正確排除(:199)
⇒ 所以 paid_at 要跟著印出來,不能只印 true/false
📌 **一個布林答得出「有沒有」,答不出「差多少」** —— 而修法住在「差多少」裡。
```

# ⚠️ 射程(免得被當成「不要報異常」)

```
❌ 它【不是】說偵測到異常先別講 —— 慢報一個真事故更貴
❌ 它【不是】要每個查詢都證明全世界正常
✅ 它只要求兩件事:
   ① 送出去之前問那一句
   ② 🔴 **講給人聽的時候,把不確定講在同一句裡**,不要放附件:
      🛑「8 張沒有信,可能還在發生」
      ✅「8 張沒有信,而我還沒分辨出是【不該有】還是【該有而沒收到】,一發查詢就分得出來」
📌 因為【加強語氣】與【加強證據】在讀的人那裡長得一樣,而只有後者是真的。
```

---

# 📌 一句話帶走

> **一把只認得異常的尺,量到的永遠是異常 ——**
> **因為「正常」從來沒有進過它的分母。**

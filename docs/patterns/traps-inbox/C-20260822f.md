## 一次成功的**負向**驗收,讀起來像一次成功的**正向**驗收 —— 而且**更有說服力**〔母題成員〕

### 判別句(先給)

> **這個 ✅ 底下的證據,證明的是「它擋住了」還是「它做到了」?**
> 前者 ⇒ 🔴 那是**守門有效**的證據,**不是功能可用的證據**。同一個結果,兩個意思。

### 當天的事(2026-08-22,而它是事故不是風險)

一份驗收清單上,`取消訂單` 那一格標著 ✅。它的證據逐字:
> 「刷卡單上它**直接擋住,連按鈕都不給**(該區 `<button>` 數 = 0)」

```
🔴 那句話【本身就寫著它沒有取消成功過】—— 只是沒有人把它讀成那個意思。
```

**實測(唯讀,兩把不同的尺,不同的表):**
```
尺 A  orders                 總數 19(正對照,尺是活的)
                             cancelled_at 非 null ⇒ 7
                             其中 reason ≠ 'payment_expired' ⇒ 🔴 **0**
                             整欄出現過的值只有 'payment_expired' 一種(全是排程寫的)
尺 B  order_cancellations    列數 ⇒ **0** / distinct actor ⇒ 0 / actor 值 ⇒ null
      order_cancellation_items ⇒ 0        控制組 orders ⇒ 19
⇒ ⇒ **兩把獨立的尺、不同的表、都是 0 ⇒ 那顆按鈕從來沒有成功取消過任何一張單。**
```
⇒ 那格已從 ✅ 降為 🟡,而在此之前它已經被口頭轉述給決策者當成「這件事做得到」。

### 🔴🔴 為什麼它比一般的假綠更難抓:**它有一個乾淨的數字**

```
一次【正向】驗收的產物,通常是一段【描述】:
   「我按了送出,畫面出現『已取消』,列表上那張單消失了。」
   ⇒ 讀的人會下意識問:哪一張?你怎麼知道它真的變了?

🔴 一次【負向】驗收的產物,是一個【數字】:
   「該區 <button> 數 = 0。」
   ⇒ 而數字看起來已經被量過了。**沒有人會去質疑一個 0。**

⇒ ⇒ **證據的形式比它的內容更有說服力,而那個形式是負向驗收天生自帶的。**
```

📌 而它與「假綠沒有回饋迴路」疊起來會加倍:
```
假綠  ⇒ 沒有人會去查一個通過的檢查
本條  ⇒ 而這個通過的檢查【還附了一個乾淨的數字】
⇒ 它不只沒有人查,它還會被【引用】—— 因為它看起來是這份清單裡最硬的一格。
```

### ⚠️ 而最危險的一步是【轉述】

```
原始紀錄:「它直接擋住,連按鈕都不給(<button> 數 = 0)」  ← 誠實、精確、正確
轉述之後:「取消訂單 ✅」                                    ← 🔴 資訊在這一步消失
⇒ 而轉述的人沒有做錯任何事:他讀到一個成功的驗收,填了一個 ✅。
⇒ **病灶在【那張表只有一欄】** —— 它放得下「驗過了」,放不下「驗的是哪個方向」。
```

### 修法(動作,不是更小心)

```
1. 🔴 驗收表要能記錄【方向】:
     ✅正 = 我讓它做到了(帶:哪一筆、之後那筆長什麼樣)
     ✅負 = 我讓它擋住了(帶:擋的是什麼、誰擋的)
   ⇒ 只有一欄的表,會把兩者壓成同一個字。

2. 收到一個 ✅ 而它的證據是【數字 0】⇒ **先問那個 0 數的是什麼。**
   本例:0 個按鈕 ⇒ 那是「入口不存在」,不是「動作成功」。

3. 🔴 **要證明「做得到」,唯一的證據是【它做過】** ——
   去下游找那個動作留下的東西(本例:`order_cancellations` 有沒有列)。
   ⇒ 而那一發**通常只要一句 SQL**,比爭論那個 ✅ 便宜太多。
```

### 🔴🔴 E-019 第一道撈到【本條的母題】,而它是一條 memory —— 我不假裝這是全新的

工具第 5 名 `memory/feedback_measured-A-answered-B` 逐字:
> 「**量了 A 卻拿去答 B** —— 量測本身是對的,所以**沒有任何東西會紅**;
>  只有把幾個各自為真的量測拼起來才看得到。」

```
🔴 那就是本條的母題,而本條是它一個【有名字的、高頻的】實例:
   A = 「它擋不擋得住」   ← 我真的量了,而且量對了
   B = 「它做不做得到」   ← 而那個 ✅ 被填進了這一欄
⇒ 完全符合「量測本身是對的,所以沒有任何東西會紅」。
```

**⇒ 而本條加的是母題沒有的那半:【為什麼這個 A→B 特別容易發生】**
```
一般的 A→B:兩個量測長得不一樣 ⇒ 拼錯了還有機會被看出來
🔴 本條的 A→B:負向驗收的產物是一個【乾淨的數字】,
   而正向驗收的產物通常是一段【描述】
   ⇒ 那個數字在任何清單裡看起來都是【比較硬的那一格】
   ⇒ ⇒ **它不只不會被質疑,它會被優先引用。**
```
📌 ⇒ 建議收件時:**本條掛在 `measured-A-answered-B` 底下當具名實例,並互指 `:8067`。**

### 其餘幾名我開檔看過的判定
```
3. 正本 :17417「量具裡藏著一個假設,而它回給你的是一個乾淨的數字」⇒ 🔴 近親而不同:
   那條 = 數字【內容】裡藏了假設;本條 = 數字的【形式】贏過它的內容(0 個按鈕 ≠ 取消成功)
   ⇒ 一個講「這個數字算錯了嗎」,一個講「這個數字在答哪一題」⇒ 互指
4. 正本 :13905「量具給了你一個講得通的錯誤故事」⇒ 不同族(講錯的發現長得像發現)
6. memory pasting-intermediate-values… ⇒ 不同(講中間值取代結論)
7. memory a-constraint-with-two-directions… ⇒ 🔴 有意思的鄰居:
   那條講【突變只表演一個方向】;本條講【只驗了一個方向,而把它當成兩個方向都驗了】
   ⇒ 那條是量具的缺陷,本條是紀錄的缺陷 ⇒ 互指
8. 正本 :5574「守門只驗有沒有被擋住,沒驗當事人看不看得見自己被擋」⇒ 不同(講使用者感知)
```

### ⚠️ 與正本 `:8067` 的分工(我開檔讀過)

`:8067`「**【環境】擋住了,而我記成【產品】擋住了** —— 而『擋住了』正是我想看到的結果」【假綠】

```
:8067  擋住了 ✅,而【擋的人不對】—— 請求在換角色那一步就死了,產品的閘一次都沒被執行到
       ⇒ 它的判別句是「**誰**擋的」;病在【量測無效】
本 條  擋住了 ✅,而【擋的人是對的】—— 那個負向驗收完全正確
       ⇒ 病在【一個有效的量測,被歸到錯的宣稱底下】
🔴 兩條共用同一個根(「擋住了正是我想看到的結果」⇒ 沒有人會再問下去),
   而它們斷在不同的地方 ⇒ **建議互指,不合併。**
```
📌 而 `:8067` 那句「**當結果符合期望時,沒有人會去問『它是被誰擋的』**」——
   本條是它的下一步:**沒有人去問「它證明的是哪一個方向」。**

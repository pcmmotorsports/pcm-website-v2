> `-b9` 2026-08-30 · `-48` 指名併進今晚那個 CJK 族
>
> ## 🛑 查重先講:**本條不是新母題, 它是一個已存在母題的新成員**
> `traps-neighbours` 第 3 名撈到 **正本 `:16472`**:
> 「**量具給了你一個【講得通的錯誤故事】—— 錯的那一發不長得像壞掉, 長得像一個發現**」
> ✅ **`-b9` 開檔讀了那一條**(實例 A:用「HTML 裡有沒有 `disabled` 這個字」當尺 ⇒ 三個世界全紅,
> 而成因是 Tailwind 的 `disabled:` 變體本來就在 className 裡)。
> 🔴 **⇒ 那就是本條的母題, 而本條【不宣稱是新發現】。**
> **本條新的只有兩格**:①**機制**(CJK 引號)②**與同族另外三種的對比**(它們產生假零, 這一種產生假分類)。
> 📌 **⇒ 而我把這一段放在最上面, 是因為【下一個查重的人會先撈到我, 而不是撈到正本】。**

## 前三種都印一個【零】或【少一個】

```
① cut -c   把一個中文字切成半個 byte ⇒ 輸出爛掉 / 字消失
② tr       逐 byte 處理 ⇒ 中文被拆開
③ ugrep 把 `-b9` 當成【旗標】 ⇒ invalid option ⇒ **印 0**
   （今晚實測:我要數自己的 commit，第一發印 0;加 `-F --` ⇒ **47**）
```

## 🔴 而第四種不一樣:**它產生一個看起來很合理的新分類**

```
git show --name-only 對【含中文的檔名】預設會加引號:
   docs/patterns/traps-inbox/b9-2026...一次濾範本....md
⇒ 變成  "docs/patterns/traps-inbox/b9-2026...一次濾範本....md"
⇒ 而我用 f.split('/')[0] 取頂層目錄
⇒ ⇒ 我得到兩個目錄：`docs`（139 顆）與 `"docs`（**63 顆**）
```

> ### 🔴 **而 `"docs` 是一個【不存在的目錄】, 而它有 63 顆 commit。**

📌 **⇒ 63 是一個【合理的數】** —— 它不大不小、與 `docs` 的 139 並列時看起來像一個真的分類。
🛑 **⇒ 而前三種會讓你【少看到東西】, 這一種讓你【多看到一個東西】。**

```
少看到 ⇒ 你可能會問「怎麼這麼少」
🔴 多看到 ⇒ 你會開始【解釋它】——「喔，那大概是某一批特別的檔」
```

> ### **⇒ 一個假的零會被質疑;一個假的分類會被【合理化】。**

## ✅ 修法(一個參數)

```bash
git -c core.quotePath=false show --name-only …
```
⇒ 加了之後:`docs` **196** 顆,`"docs` **消失**。
✅ **而驗收方式是【那個假目錄要不見】, 不是【數字變大】** ——
**因為「數字變大」在「修好了」與「換了一種算錯」時長得一樣。**

## ⚠️ 而這一發差一點進了端給 Sean 的清單

當時在量的是「**未推的 226 顆裡, 有幾顆動到產品**」——
**而那是他會拿去判斷整晚價值的數字。**
🔴 **⇒ 若那個 `"docs` 沒被抓到, 那份分佈表上會有一個【他看不懂而我們也解釋不了】的分類。**

## 📎 而它與同族第三種(`-b9` 被當旗標)有一個共通點

```
兩者都是【我的識別字剛好長得像那個工具的語法】
   `-b9`  長得像一個旗標
   中文檔名 觸發了 git 的引號機制
🔴 ⇒ 而兩者都不是「工具壞了」—— 工具照它的規格運作
⇒ ⇒ 是【我把一個為別的用途設計的輸出，當成結構化資料在切】
```
📌 **⇒ 所以修法不是「記得加參數」, 是:**
> ### **把一個【給人看的輸出】拿去切欄位之前, 先問它有沒有【給機器看的模式】。**
> (`git` 有 `core.quotePath` 與 `-z`;`grep` 有 `-F --`;`ls` 有 `--quoting-style`。)

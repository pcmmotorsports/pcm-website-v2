# 一個【正確的修法】把六個既有的偵測器一起遮住,而全綠

## 實例(當天,我自己,可重跑)

審查抓到一條真的 must-fix:那支工具讀**工作樹**,而判「哪幾行是這次改的」讀 **index** —— 兩個資料源不同份。
我照 repo 既有的成例補了一道 fail-closed 守門(`staged_content()`),**排在原本那道前面**。

修完我重跑整個突變盤:

```
F4 / M1 / M18 / M7 / M19 / M24 —— **六個原本被殺掉的突變同時活過來**
成因：新的那道排在前面 ⇒ 世界⑥⑦⑧ 全部在【第一道】就 fail-closed
     ⇒ 第二道的 rc / except 守門【再也走不到】
🔴 而 selftest 全綠、rc=0
```

## 為什麼它零訊號

```
· **沒有一行既有的碼被改動** ⇒ diff 上與「補了一道守門」長得完全一樣
· 三綠全綠 · selftest 全綠
· code review 看的是【新加的那段對不對】—— 而那段是對的
```

📌 **⇒ 這個形狀不是【疏忽】的產物, 是【正確的防禦性修法】的副產物。**
🔴 **⇒ 也就是說它會持續發生, 而且發生在最認真的那幾顆 commit 上。**

## 判別句 —— 而它的觸發條件與人們跳過它的理由是同一個

```
唯一看得到它的動作 ＝ 修完之後【重跑整個突變盤】，不是只跑新加的那幾發
🔴 而不重跑的理由正好是「我沒有改它們」
   —— 那句話是【真的】，而結論是錯的：
   **我沒有改它們，但我改了它們【能不能被走到】。**
```
🛑 **⇒ 那個動作的觸發條件, 與「我沒有動它」是同一個** —— 而「我沒有動它」正是所有人跳過重跑的理由。
(這一句的形狀是 `-22` 幫我點出來的。)

## 修法:併成一道,**不是搬順序**

```
兩道守門【擋的是同一件事】⇒ 併成一道 ⇒ 遮罩消失（沒有第二道可以遮）
兩道守門【擋的是不同的事】⇒ 排序，舊的先跑、先給精確訊息，新的當總簽收
🛑 區分它們的問句：
   **「前面那道擋下的時候，後面那道會不會【想講不一樣的話】？」**
   會 ⇒ 兩件事，要排序；不會 ⇒ 同一件事，該併
```
我原本那兩道都只會說「git 答不出來」⇒ **它們從一開始就不該是兩道。**
✅ 併成一個 `_git()` 之後,六個突變塌成兩個(rc / except),兩個世界各殺一個。
🛑 順手刪掉一道變成死碼的守門(前面那道先擋 ⇒ 它永遠走不到)。

🔵 **而「排後面」那一半是 `-eb` 同夜在 migration 指紋上量到的**(它四支裡三支照慣例放最後、
只有它自己那支放第一 ⇒ 搬到最後 ⇒ 遮罩消失、五個突變從兩段改回單段)。
⚠️ **而它對我這一格不適用**:我補的是**資料來源**不是**斷言** ——
`scan(path, content=idx)` 需要它的回傳值 ⇒ **它在資料流上沒有排序自由。**
📌 **⇒ 所以判別句不是「新的排後面」, 而是上面那個問句。**

# 兩個現場,同一晚,而**它們壞的地方不一樣**(`-1c` 指出的分界)

## ① 線C `-b4` —— 射程節裡那句話**內容是假的**
```
scripts/latest-definition-of.sh 的射程節逐字寫著:
  「動態 SQL(EXECUTE $x$CREATE …$x$)照樣會被算進來」
而當時四種形狀裡有三種錨了行首(DROP/ALTER/CREATE)
⇒ **那句話對四分之三的形狀是假的**(鐵則 11 字面 vs 事實)
```
🔴 **抓到它的不是讀,是 R1 審查【真的去跑了那支工具】** —— 餵一個藏在 `EXECUTE` 字串裡的物件名
(`idx_orders_display_id_trgm`)⇒ 舊版印**查無 rc=3**。

## ② `-1c` —— 射程節裡那句話**是對的,只是住錯地方**
```
apps/admin/src/lib/orders/manual-order-tax-basis.test.ts
  「本格答的是【帳本】,不是正式庫」只寫在【檔頭射程節】
⇒ 而那句是承重的:讀的人可能據此以為這道守門涵蓋了正式庫
⇒ ✅ 已搬到那一族斷言的【正上方】(`2af6344d`),而檔頭那份留著
   ——「檔頭講全域,那裡講這一格」
```

## 🔴 ⇒ 而**②比①更難抓**,這一格是 `-1c` 的,值錢
```
① 內容錯   ⇒ 只要有人真的去跑,它就會現形(而 R1 就是那樣抓到的)
② 位置錯   ⇒ **那句話是對的** ⇒ **沒有任何東西會讓它紅**
             測試不會、審查逐字驗也會過、grep 得到、它甚至讀起來很誠實
```
> ### **⇒ 判別句不是問「這句話對不對」,**
> ### **是問:「會不會有人在【他需要它的那一刻】讀到它?」**

# 為什麼「射程節」是最糟的落點(而它看起來是最好的)

```
🔴 那一節讀起來像作者在【自我克制】——
   而自我克制的句子**天生帶著誠實的外觀** ⇒ 沒有人會回頭驗它
🔴 而它一旦錯,錯的方向是**把東西說得比實際【寬】**
   ⇒ 下一個人會以為那一塊已經有人顧了 ⇒ **它關掉的是別人的查證動作**
```
📌 **⇒ 一份產物裡最不會被驗的那一節,正好是專門用來裝【限制】的那一節。**

# ✅ 修法兩條,都機械

## 一、承重的話**貼在它修飾的那一行旁邊**
```
✅ 檔頭那份【留著】—— 它講全域
✅ 而承重那句【複製一份】貼到它修飾的那個值/斷言/欄位的正上方或正下方
⇒ 重複不是浪費:兩個讀者路徑不同
   (掃檔頭的人 / 只看輸出那一行的人 —— 而後者才是多數)
```
**實例**:`latest-definition-of.sh` 把
「`live` 答的是【帳本】不是正式庫 —— 兩個宣稱」
印在 `live = …` **那一行的正下方**,不放射程節。

## 二、🔴 **射程節每宣稱一件事,就要有一格自檢在演它**
```
它把「一句話」變成「一個 checklist 的欄位」⇒ 新增射程句時,同一輪要新增它的格
```
**實例**(同一支工具,檔頭逐條對上):
```
射程句「動態 SQL 算得到」          ⇒ 自檢 ⑩
射程句「… ON tbl 不算 tbl 的一代」 ⇒ 自檢 ⑪
射程句「帳本欄印得出兩種值」        ⇒ 自檢 ⑬
```
⚠️ **而這一條只解得了①(內容錯),解不了②(位置錯)** ——
一句住錯地方的**正確**話,自檢會**通過**。⇒ ②只有第一條修法擋得住。

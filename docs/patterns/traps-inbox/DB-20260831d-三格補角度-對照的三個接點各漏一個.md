本則講的是**下一步**:當它不紅時, 你要判它是哪一個世界 ——
```

🔴 而兩個世界【印同一個 0 紅】。
```

```
   🔵 正對照 還活著的 REFUND_NOTHING_LEFT ⇒ 1 · 🔵 負對照現造字面 ⇒ 0
```

🔴 **而觸發我去證的訊號是:M5 與【純註解負對照 M6】拿到完全相同的結果。**
⇒ ✅ **可執行:突變與負對照同號 ⇒ 那不是通過, 那是該去證不可達的訊號。**

## ③ 補正本 `:23522`(正對照要與目標【逐字同形】, 只差被找的那個值)
### 🔴 而「同形」還有一個維度:**輸入的種類**

查重:最高 `0.2135`(`:15988`)、次高 **`:23522`**(`0.2051`)⇒ 開檔讀 ⇒ **補角度**。

`:23522` 講的是**形狀**(正規式 / 字面的寫法)。本則講的是**輸入的類別**:
```
git diff --name-only dev HEAD -- 'docs/' -z     ← -z 打在 `--` 【後面】⇒ 被當成 pathspec 不是選項
⇒ 檔名輸出成引號跳脫形式(CJK 變 \350\243\234…)⇒ 拿那個字串回頭比對 ⇒ 命中 0
⇒ 🔴 每一支【CJK 檔名】都拿到假的「安全」判定, 而純 ASCII 那幾支是真的
```
🔴 **而我的負對照(`docs/progress-roadmap.html`)剛好是 ASCII** ⇒ 它印了紅 ⇒ **我以為尺是活的。**
📌 **⇒ 一把對【某一類輸入】失效的尺, 它的對照若不屬於那一類, 會替它背書。**
✅ **可執行:對照要與被測物【同類】, 不只是「有對照」** ——
   被測物含 CJK ⇒ 對照也要含 CJK;被測物是含裸 `0x85` 的檔 ⇒ 對照也要是那種檔。
🔵 **同日同族異例**(`-22` 廣播):包裝過的 `grep` 對含裸 `0x85` 的檔整檔跳過、**印空白不印 0**,

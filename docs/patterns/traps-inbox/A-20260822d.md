## 🔴 而我的例子證明那個做法【不夠】 —— 這是要補的那一層

### 當天發生什麼(2026-08-22,線 A)
我寫下一個**搜尋配方**,用來找「備好了沒人接」的功能:
```
資料層有【值域 / 欄位 / 守門】, 而 grep 那個識別字的【消費端回 0】
  · 有 CHECK 而所有列都是同一個值   · 有欄位而全表同一個預設值
  · 有 port 而零實作                · 有函式而對外消費端 0
```
**它是從四個標本歸納出來的,而它對那四個都成立。**

🔴 **而在同一段文字裡,我發現它漏掉【第五個】** —— 一個就在旁邊、同一張表上的格子:
```
那一格不是「沒人接」, 是【有人刻意擋住它】
（一支 migration 加 CHECK 硬擋, 同一支還把既有的值刪掉）
⇒ 它的痕跡不是「零消費端」, 是【一道 CHECK 在拒絕】
⇒ 我那個配方【掃不到它】
```

### 🔴 而 ㉜ 的檢查**抓不到這一種** —— 這就是要補的那一格
```
㉜ 的做法:拿【已知會命中的那一筆】餵它 ⇒ 餵不出來 ⇒ 尺有洞
🔴 而我的配方【餵得出來】—— 四個標本每一個它都撈得到。㉜ 那一關【它會過】。
⇒ 因為它漏掉的不是【催生它的那些例子】, 是【那些例子的鄰居】
   —— 同一個領域、而【類別不同】的那一格。
```

### ⇒ 補一層,而它是可操作的
> **拿新配方去掃的,不只是【它的來源】,還要包括【它的鄰居】** ——
> **同一張表 / 同一個領域裡,那些你已經知道答案、而【類別不一樣】的格子。**

```
㉜ 那一關（必要而不充分)：餵它一個【已知會命中】的  ⇒ 撈得到 ⇒ 尺會動
🔴 這一層（補的)：餵它一個【已知存在、而你【沒有】拿來歸納配方】的
                 ⇒ 撈不到 ⇒ **不是尺壞了, 是【配方的概念範圍】比你以為的窄**
```
📌 **兩者壞的東西不一樣**:
```
㉜ 壞在【實作】—— 正規表示式要求副檔名, 而縮寫沒有 ⇒ 修 regex 就好
本層壞在【概念】—— 配方只描述了一個方向（沒人接), 而現實有第二個方向（被擋住）
                  ⇒ 🔴 修不了 regex, 要【再加一條找法】:看有沒有 migration 在刪東西或擋東西
```

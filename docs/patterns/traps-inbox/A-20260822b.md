## 條 A · 一條測試的名字裡寫著它的理由時,它就是**那個決定的載體**【安靜】

### 當天發生什麼(2026-08-22,線 A)
主視窗批准我放寬一個提示的顯示條件。我改完,測試紅了一格:
```
「負向③:沒有在搜尋(只是瀏覽列表)+ 0 筆 ⇒ 不提示(瀏覽時它是噪音)」
```
🔴 **那不是一條順帶被打到的斷言 —— 它就是【那個決定本身】被釘起來的樣子。**
名字裡逐字寫著理由(「瀏覽時它是噪音」),而**那句理由與元件註解裡的是同一句**。

⇒ 我 `git checkout` 還原、回到全綠、回去問。裁定回來是「**換一句不同的話,那條守門一個字都不要動**」——
**做出來之後那條守門仍然綠,而新行為也有了。**

### 判別句
> **我要改的這條測試,它的名字在講【什麼會壞】,還是在講【我們決定不那樣做】?**
> 後者 ⇒ **改它就是推翻一個決定,而那不是施工,是拍板。**

📌 **這個區分看得出來,不必靠感覺** —— 去讀那條測試的名字。
```
「X 為 null 時不得 crash」          ⇒ 講【什麼會壞】⇒ 行為漂了就修它
「瀏覽時不提示(瀏覽時它是噪音)」   ⇒ 講【我們決定不那樣做】⇒ 改它 = 推翻一個人的判斷
```

### 🔴 而它與 `:8082` 會給出**相反的動作**,所以兩條要互相指
`:8082` 問:**這條測試斷言的是【我要的行為】還是【現在的行為】?** ——
它的用途是**把保護 bug 的測試找出來改掉**。
而本條問的是**那條測試是不是一個決定的紀錄** —— 若是,**即使你覺得它保護的是「現在的行為」,也不能自己改**。
```
🔴 順序（不是「另見」, 是【先後】）:
   第一步  本條   ——「這條測試是不是一個【決定的紀錄】?」
                     是 ⇒ 停, 去問。不管你多確定它保護的是「現在的行為」。
   第二步  :8082 ——「它斷言的是【我要的行為】還是【現在的行為】?」
                     只有第一步答「不是決定」時, 這一步的結論才可以直接執行。
```
🔴 **順序顛倒的後果是具體的:`:8082` 會【單獨授權一次越權】** ——
它讀起來完全正當(「這條在保護 bug,改掉它」),而那個 bug 可能是有人**刻意決定留著的行為**。
📌 ⇒ **兩條落檔時,兩邊都要寫出這個先後,不能只寫「另見」。**
   `:8082` 那邊要加一句:**執行本條的結論之前,先確認那條測試不是一個決定的紀錄。**

### 動作
- 還原(`git checkout`,不是改期望值、不是 skip),把兩案端出去讓人裁。
- 🔴 **而端出去的時候要附「那個決定的理由現在還成立嗎」** —— 我那次的答案是
  「**它只在有結果時成立;0 筆的時候它不是噪音,是畫面上唯一的解釋**」⇒ 那句讓裁定變成一分鐘的事。

## 條 C · 作者**想過**那個名詞,而他想的是那個名詞的**哪一種時序**【安靜】

### 當天發生什麼
訂單列表有一條預設隱藏規則:`payment_channel='tappay' AND payment_status='unpaid'`。
而它的 docstring **逐字寫著作者想過匯款這件事**:
> 🔴 **邊界寫死**:規則只認 `payment_channel='tappay'`。
> **未來開匯款時,`bank_transfer` 的未付款單不在隱藏規則內** —— 那種單「未付款」是正常待辦、
> 不是失敗,**藏起來會讓員工漏掉要對帳的匯款**。

**他想的是「一開始就選匯款」的單。** 那種單 `payment_channel='bank_transfer'` ⇒ 確實不會被藏。
🔴 **而規則認不得的是另一種時序:**
```
客人【先刷卡】⇒ payment_channel='tappay'（這一欄不會因為改用匯款而變）
刷卡失敗      ⇒ payment_status='unpaid'
客人改用匯款  ⇒ 錢進帳本, 而上面兩欄一個字都沒動
⇒ 這張單符合隱藏規則的【每一個字】, 而它已經收到錢了 ⇒ 從員工眼前消失
```

### ⚠️ 更正:我原本寫「而且**更常見**」—— 那句沒有分母,而審查線去量了(R1 must-fix,它對)
```
2026-08-22 正式庫實量:
  符合隱藏規則的單            9 張
  其中【已有收款紀錄】的      0 張
  payment_channel='bank_transfer' 的  0 張
  整張表 payment_channel 相異值        1
⇒ 「更常見」在【今天這個系統的資料上】不成立 —— 匯款這條路的分母是 0
```
⇒ **正確的講法是機制陳述,不是頻率陳述**:
> **規則認得「一開始就選匯款」,認不得「中途改成匯款」。**
> 而**中途改成匯款這條路今天還沒有人走過**(2026-08-22 實量 0 張)——
> 🔴 **它是潛在缺陷,不是現行事故。**
> ⚠️ 而**匯款開始被使用之後會有幾張受害,未量**(那要等它真的開始被用)。

📌 **而這一格本身就是條 C 的實例**:我寫下「更常見」的時候,腦子裡的是**業務直覺**
(刷卡失敗改匯款聽起來很常見),而**我沒有去看那個系統今天有沒有這條路的資料**。
🔴 **一個頻率副詞,讓一個沒量過的量級過關了。**

### 🔴 而更狠的是:那段註解**讀起來像「這件事被想過了」**
它有標題、有理由、有「未來開匯款時」的前瞻 ——
**而它蓋住的正好是沒被想到的那一半。** 下一個讀到它的人不會再去想第二種時序。

### 判別句
> **這段註解說「我想過 X」時,它想的是 X 的【哪一種】?**
> **那個名詞有沒有第二種時序?**(一開始就是 X / 中途變成 X)

📌 而這一族在 PCM 特別容易出現,因為**訂單有生命週期** ——
幾乎每個名詞都有「一開始就是」與「中途變成」兩種:
```
付款方式  一開始就選匯款      /  刷卡失敗之後改匯款
取消      下單就取消          /  出貨後才取消
缺貨      下訂當下就知道缺貨  /  下訂後廠商才回缺貨
會員等級  註冊就是店家會員    /  中途升級
```

### 動作
- 讀到「我們想過 X」的註解時,**把 X 的兩種時序都寫下來,再看規則認得哪一種**。
- 🔴 而寫這種註解的人:**把你想的是哪一種寫出來**。
  原註解若寫成「**規則只認一開始就選匯款的單;中途改成匯款的沒有處理**」,這個洞當天就會被看見。

📎 與 `:1110`(結構性結論要去讀建它的那支 migration 的註解)是**鄰居不是同族**:
那條講**去讀**;本條講**讀了、而註解只想過一半**。⇒ 建議在那條旁邊留一句指標。

```
❌ 只回一個 boolean / 一個 0  ⇒ 那個 0 【無法被事後檢查】
✅ 回 0 的同時 dump 你掃過的那段原文 ⇒ 讀的人（含未來的你）可以自己看出字集漏了什麼
📌 成本幾乎為零, 而它把「字集夠不夠寬」從【寫的時候要想對】移到【看結果的時候看得出來】
```

⚠️ **而它擋不住什麼要講明**:dump 原文只在「**你掃對了地方**」時有用。
掃錯地方 ⇒ 你會 dump 出一段乾淨的、無關的原文,而它讀起來像證據。
📎 那一半屬於本檔另一族(「我要找的這種東西,會住在我剛掃的那個地方嗎」)。

# 【新增實例】一道閘可以正確運作,而它守的是一個【形式】不是一個【事實】

> 2026-08-28 夜,線B(`-d3`),把 `scripts/naked-cells.py` 收進 repo 時撞到。
> **不推翻既有任何一條。** 母題的父條 = 正本 `:10486`
> 「**把突變留成測試 ≠ 那個測試會抓到那個突變**」——
> 那一條講**我自己留的守門量錯東西**;這一條講**一道閘要求我留守門,而它自己說它驗不出內容**。

## 事發

`scripts-whitelist-gate` 擋下新腳本進 index,理由是它沒有【逐字路徑】的 `lint-staged` 條目。
而**那道閘自己的錯誤訊息裡逐字寫著**:

```
🔴 本閘【驗不出】那行命令有沒有判別力 —— 寫 "true" 一樣過得了。那一格靠人。
```

⇒ **它保證的是【格子被填了】,不是【格子裡裝著會叫的東西】。**

📌 **判別句:一個白名單條目要是恆綠的,它登記的是「有人負責」而不是「有東西在看」。**

## 🔴 而這一格最該學的不是那個病,是那道閘的【誠實】

那句自陳寫在**它擋你的那一刻你一定會讀到的地方** —— 不是檔頭、不是文件。
⇒ 我因此當場補了一發突變,而不是照規矩填一行就走:
```
突變:把 naked-cells.py 的 `it.each` 鏈式括號配對拿掉(= R2 那條 must-fix 的病)
     ⇒ `python3 scripts/naked-cells.py --selftest` rc=1
     ⇒ 而 FAIL 的是 **W9(it.each 那個世界)**
還原 ⇒ rc=0
```
🔴 **「它會紅」不夠,要「它紅在對的世界」。**
只證會紅的話,一個恆紅的守門也通得過這一關 —— 而那與**沒有守門**一樣沒有判別力,
只是失效的方向相反(正本 `:5575`「恆紅 —— 恆綠的對稱另一半」)。

## ⚠️ 而那句誠實同時是它的失效條件

那道閘把「這一格靠人」寫出來了 ⇒ **它把責任轉移完成了,而轉移之後沒有任何機制在看那一格。**
```
讀到那句而照做的人   ⇒ 補一發突變（我這次）
讀到那句而沒照做的人 ⇒ 填一行 "true"，而閘【正確地放行】
兩者在 index 上長一模一樣：一個被填好的白名單條目
```
📌 **一道閘把自己的盲區寫在訊息裡,擋不住任何人 —— 它只是讓踩到的人事後知道自己踩了哪裡。**
⇒ 這與正本「機制優先律」那一族是同一句話的另一面:
**把「靠人」寫下來,不會讓那件事變得比較不靠人。**

# 【第二個實例】同一晚,主視窗 `-84` 的回核尺量錯了對象

> **來源屬性**(§6-b):
> · **機制** = 線B `-d3` **當場複驗過**(見下方指令與輸出)
> · **數字 27 / 6** = **主視窗自陳,`-d3` 未複驗** —— 那顆 commit 不在我手上
> ⇒ 兩半的證據等級不同,不要因為寫在同一段就一起相信。

## 它的自陳(逐字轉,不重打)

> 我 commit 完 `CURRENT.md`,跑回核「非我的檔數應為 0」⇒ **它印 27。**
> ```
> 成因:git show --name-only HEAD 會先印【commit 訊息】再印檔名
>      我用 tail -n +2 想跳過訊息 —— 而訊息有 27 行
> ⇒ 那 27 是【我自己 commit body 的行數】,不是檔案數
> ```
> 🔴 **而如果那顆 commit 真的多收了別人的檔,這把尺印的還是 27。**
> 修好之後(`--pretty=format:` 只印檔名)⇒ 1 支 / 非我的 0 支。
> ✅ 補了負對照:同一把尺打一顆已知六檔的 commit ⇒ **印 6** ⇒ 尺是活的。

## `-d3` 的機制複驗(這半是量到的)

```
$ git show --name-only HEAD | head -4
commit cb789c8fe0428ab0b1b502c751cb1070d24a2076
Author: probe <probe@local>
Date:   Fri Aug 28 20:32:13 2026 +0800
                                    ← 空行, 接著才是 commit body

$ git show --name-only HEAD | tail -n +2 | head -3
Author: probe <probe@local>          ← `tail -n +2` 只跳掉「commit <sha>」那一行
Date:   Fri Aug 28 20:32:13 2026 +0800
```
⇒ **`tail -n +2` 跳掉的是一行,而要跳的是【整個標頭 + 整段 commit body】。**
⚠️ 而 body 的行數**每顆都不一樣** ⇒ 那把尺印出來的數字**每次都不同、每次都看起來像一個檔案數**。

## 📌 這一格與本檔主體的差別(兩個實例, 兩種錯法)

```
主體那一格   閘【保證的範圍】比它看起來窄 —— 問題問對了, 而那道閘答不了
本格         尺【量的對象】根本不是那件事 —— 問題問對了, 而量到的是另一種東西
```
🔴 **判別句:一把量錯對象的尺,對它宣稱要量的那件事,在所有世界都印同一個數。**
⇒ 那個數字**不是「錯的答案」,是「與那個問題無關的答案」** —— 而它長得像答案。

## ✅ 而它做對的那一格要單獨記:**它補了負對照**

```
同一把(修好的)尺打一顆【已知六檔】的 commit ⇒ 印 6
```
⇒ 沒有這一發的話,「修好之後印 0」與「修壞成恆印 0」**印同一個 0**。
📌 **一把剛修好的尺,第一件事是拿一個【已知非零】的世界餵它。**

## `-d3` 這一晚用的形狀(可抄)

```
git show --numstat --format='' HEAD        # `--format=''` 直接不印標頭與 body
git show --numstat --format='' HEAD | grep -cv -e '<我的檔A>' -e '<我的檔B>'   # 非我的檔數
```
⚠️ **而這個形狀我今晚用了 10 次都印 0** —— 也就是說**我沒有見過它印非 0**。
⇒ 照上面那條:**它對我而言也還沒有負對照。** 下一個用它的人請先餵一顆已知多檔的 commit。

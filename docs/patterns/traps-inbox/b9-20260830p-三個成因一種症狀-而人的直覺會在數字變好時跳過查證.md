# 三個成因、一種症狀 —— 而人的直覺會在數字**變好**時跳過查證

> `-b9` 2026-08-30 · `-48` 指名獨立成條
> 母題:**錯的那次和對的那次長得一樣** —— 而這一條是它在【數字】上的版本

## 同一晚,同一張板子,三次

```
① B 節「上線前必關」 16 ⇒ 22    成因【時間】
   那個 16 是 2026-08-26 的真值，而 08-27／08-29 各進來幾列

② #231 ④ 那把尺     0 ⇒ 4     成因【尺的定義】
   0 是 08-17 量的，4 是 08-30 量的 —— 而那 4 個命中【全部是註解】
   其中一行逐字寫著「不濾 needs_manual_review」= 一句「我沒做」

🔴 ③ 板頭欄數分佈 不是 5 欄 101 ⇒ 48   成因【我自己的一顆 commit】
   12ea652b 把落在反引號 span 裡的裸 | 跳脫掉 34 列
   ⇒ 那 34 列的內文本來就有直線字元（SQL / wc -l / 表格範例）
```

## 🔴 而三個在板子上都只是「**一個數字變了**」

```
① 沒有人做錯任何事      —— 只是時間過去了
② 兩端都誠實           —— 一句誠實的「我沒做」，被一把誠實的尺數成「有人做了」
③ 是我自己造成的       —— 而我當時在修一個完全無關的東西
```

📌 **⇒ 成因三種、症狀一種。**
⇒ ⇒ **所以「看到數字變了就去查成因」是唯一的動作,沒有捷徑** ——
**你無法從那個數字本身,推出它為什麼變。**

## 🛑 而真正的病灶在**方向**

三次裡有**兩次**(②③),數字是**往好的方向**走的:
```
0 ⇒ 4     讀起來像【有人動工了】
101 ⇒ 48  讀起來像【快可以裝閘了】
```

> ### **⇒ 而往好的方向走的數字,最不會被回頭查。**

**一個變壞的數字會讓人停下來;一個變好的數字讓人往下走。**
⇒ **而它們需要的動作【一模一樣】:去查那個數字為什麼變。**

## ✅ 可執行

> **看到一個數字變了 —— 不管往哪個方向 —— 在用它之前,先答一句:**
> ### **「它為什麼變?」**
>
> 三種答案:
> ```
> 「時間過去了」        ⇒ 分母動了，去重列成員
> 「尺的定義變了」      ⇒ 那是兩個不同的量，不能比
> 🔴 「我不知道」        ⇒ 停。在答出來之前，那個數字不能被引用
> ```

⚠️ **而 ③ 提醒了一件事:成因可能是【你自己剛才做的事】。**
⇒ **⇒ 所以查成因的第一個地方,是你自己的 `git log`,不是別人的。**

## 📎 而它與同夜那條「值沒有過期而標題沒描述它」是**兩個不同的病**

```
本條：值變了，而你不知道為什麼
另條（⑯b 報價單 2FA）：值【沒有】變，而標題從一開始就沒有描述它
   ⇒ 🔴 那一種【不會被任何「重量一次」的動作抓到】——
     重量會印出一個對的數字，而讀的人仍然以為那是雜務
```
⇒ **兩條要一起讀:一條說「數字動了要查」, 另一條說「數字沒動也可能是錯的」。**

# 錯誤訊息**有印**, 只是印在沒有人看的那一欄 —— 而那張表的每一列都是假的

2026-08-30 線G。我要比對「設計稿的 11 條規則 vs 我方 CSS 的同名類別」,
寫了一個迴圈,逐條印出「稿是什麼 / 我方是什麼 / 判定」。

它印出來的表格是這樣的:
```
.masthead   flex   —   ⚠️ 我方無同名 pd- 類
.foot       grid   —   ⚠️ 我方無同名 pd- 類
...（11 列全部一樣）
```
一份看起來很具體的結論:我方 11 條全部沒有對應。

而那是假的。我明明前一發才親手開過 `.pd-foot` 那一段。

成因:我寫 `grep -A8 "^\.pd-${cls} \{"`,而 `{` 在正則裡是量詞的開頭。
ugrep 對每一列都報 `invalid repeat`,而那一行印在 **stderr**。

而 stderr 與 stdout 在終端機上是混在一起的 —— 它就印在每一列判定的正上方。
我沒看。因為判定那一欄看起來完全合理:一個「—」加一句解釋。

修法是 `grep -F`(定值比對)。改完之後真表是 8 相同 / 2 不同 / 1 無同名。

## 而這一條的位置

它與「`$(...)` 把工具拒絕執行變成空字串」是同族的**兩端**:
- 那一端:錯誤訊息**被吃掉了**
- 這一端:錯誤訊息**印了,而沒有人看**

而兩端的結果一樣:**一個看起來合理的表格,而它的每一列都是假的。**

📌 差別只在事後能不能查:被吃掉的那種事後也查不到;
而這一種**證據還在**,只是它在你當時沒看的那一欄。

## 自檢

一個迴圈印出來的表,若**每一列的判定都相同**,先停下來問:
那是因為每一列真的都一樣,還是因為**這把尺對每一列都同樣地失效**?

而可執行的一發:把 stderr 導開再跑一次(`2>/tmp/err`),然後 `wc -l /tmp/err`。
0 行才代表那張表是乾淨的。

⚠️ 而更根本的:**任何把使用者輸入拼進正則的 grep**,只要那個輸入含
`{ } ( ) [ ] . * + ? | ^ $ \`,就要用 `-F`,或者問自己「我要的是字面還是樣式」。

```

```
📌 **⇒ `:4795` 的毒在【數字裡】, 本條的毒在【我的注意力裡】。**

(第三種 = 被導去 `/dev/null`,那是 `:4795` 自己提到的前兩種之一)。

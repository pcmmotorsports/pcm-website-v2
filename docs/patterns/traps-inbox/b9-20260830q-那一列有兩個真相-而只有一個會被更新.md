# 那一列有**兩個真相**,而只有一個會被更新

> `-b9` 2026-08-30 · `-48` 指名獨立成條
> 母題:**狀態改了, 而另一欄沒跟著改** —— 而兩個方向的錯,後果相反

## 一列上有兩欄各自宣稱一件事

```
態欄   ：這件事還要不要做      （open / doing / parked / done）
誰欄   ：這件事在誰手上        （待派 / 等人:Sean / 等時機:… / 可排片）
```

**做完一件事的時候, 人只會改【態欄】。**

## 🔴 而那產生兩個方向相反的錯,同一晚各量到一次

```
方向一（往「少」錯）：把【還沒決定】寫成【已經決定不做】
   實例：起床清單「22 − 3 = 19」，而那 3 件裡只有 1 件真的是他決定不做
        （另 2 件是「等時機:客人推播上線」與「等人:要談 Enterprise」）
   🔴 後果：那兩件【被靜音了】——
      一件被歸進「決定不做」的事，從此不會再出現在任何一份清單上

方向二（往「多」錯）：做完了，而誰欄還寫著「待派」
   實例（-b9 當場量全板）：done 55 列 · 其中誰欄仍是「待派」類的 23 列
   🔴 後果：任何讀誰欄的工具或人，都會把這 23 列列成【可派】
      ⇒ 而那導致【有人去做一件已經做完的事】（今晚第 9 件同型）
```

## 📌 而在版本控制上,兩者都只是**一欄字沒更新**

⇒ **沒有任何 diff、測試、審查看得出「這一欄該更新而沒更新」** ——
因為**它在「作者刻意保留」與「作者忘了」之間沒有形狀上的差別。**

## 🛑 可執行的那一句

> ### **一個狀態欄與一個歸屬欄放在同一列,而只有一個會被更新**
> ### **⇒ 那不是紀律問題,是那一列有【兩個真相】。**

⇒ 所以修法不是「記得一起改」(那是紀律,而紀律今晚失敗過很多次),是:
```
✅ 判「還要不要做」一律看【態】，不看誰欄
✅ 態 = done 的列，它的誰欄【不是權威】
✅ 改成 done 的【同一次編輯】，誰欄要一起收掉（只管之後，不回頭補）
```

## ⚠️ 而「不回頭批次補」有一個**非直覺的理由**

```
批次改 23 列的誰欄 ——
🔴 在 diff 上，與「有人重新指派了 23 件事」長得一樣
```
⇒ **一個【清理】動作與一個【決策】動作,在版本控制裡沒有形狀上的差別。**
⇒ ⇒ **⇒ 所以大批次的「順手清理」本身是一種風險,即使每一列都改對了。**

## 📎 而它今晚生出三次真實的派工錯誤

主視窗自陳:**它今晚三次派人去做已經做完的事** ——
🔴 **而那三次不是它讀錯, 是那一欄在說謊, 而它有 23 個實例。**

## 📎 同族一格(不同病,不要混)

```
本條：值變了（態改了），而另一欄沒跟著變
另條（⑯b 報價單 2FA）：值【沒有】變，而標題從一開始就沒有描述它
   ⇒ 那一種不會被任何「重量一次」的動作抓到
```

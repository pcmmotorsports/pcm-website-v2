# 門檻我**量了**,而只量了**通過那一側** —— 訂出一個看起來很安全、卻幾乎擋不住的數字

> 線 `-f3` · 2026-09-06 · ⟦search-BRANDSLUGHYPHEN⟧。主視窗指定投收件匣。
> 🔎 **查重跑過**(`traps-neighbours.py`,分母 2934)。
> 🔴 **這一條是正本 `guard-and-instrument-traps.md:13330` 的【實例三】,不是新母題** ——
> 那一節逐字:「自檢的**門檻**是一個可以量的東西 —— 而它幾乎總是被『想』出來的(同一晚兩次,一鬆一緊)」,
> 而它的結論是「**兩次的共同點不是鬆緊,是我都沒有去量門檻該設在哪**」。
> ⇒ 📌 **本條要加的是那一句的下一層:我【量了】,而量錯了【哪一側】。**(收攏時請併進那一節,不要另立母題。)

## 發生什麼

我為一道效能守門訂門檻 **2000ms**:
```
修好之後       實測    8ms   ← 我量的就是這一側
把修法拿掉     實測 2073ms   ← 這一側我【事後】才量
```
⇒ 🎯 **通過側的餘裕是 250 倍,而失敗側只差 73ms。**
⇒ 📌 **那個門檻看起來非常安全,而它幾乎擋不住它要擋的東西** ——
　 CI 機器快一點、或那台機器那一刻閒一點,**突變就會安靜地通過**。

✅ 改成 **300ms**:比通過值高 **37 倍**、比突變值低 **3–7 倍**(同一發突變在兩台不同負載下量到 858ms 與 2073ms)。

## 🎯 而「只量一側」為什麼是預設會發生的事

· 訂門檻的時候,**我手上只有通過那一側的數字** —— 因為我剛把它修好、剛跑過。
· 失敗那一側要**額外做一次突變**才量得到 ⇒ 📌 **它不在我的路徑上,而通過那一側是。**
· 🔴 **而只看通過側的數字,任何一個大到荒謬的門檻都「安全」** ——
　 `8ms < 2000ms` 讀起來與 `8ms < 300ms` 一樣令人安心。

## ✅ 判別句

> **訂一個數字門檻之前,通過側與失敗側【各量一次】,門檻放中間。**

🔵 **可機械化的版本**:寫下 `pass=___ / fail=___ / 門檻=___`,三個數都填得出來才 commit。
　 填不出 `fail` ⇒ 你還沒做那一發突變 ⇒ **那道守門的判別力目前是未知,不是「有」。**
🛑 而**兩個數字都要寫進測試的註解裡** —— 下一個人調它時才知道餘裕在哪一邊。

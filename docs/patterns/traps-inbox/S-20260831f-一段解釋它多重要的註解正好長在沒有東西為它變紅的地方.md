# 一段解釋它有多重要的註解,正好長在那個【沒有東西會為它變紅】的地方

> 線【出貨】`-1e` · 2026-08-31 · 突變殺出來的,不是讀出來的

## 現場

一支 use-case 把 reader 回來的旗標傳到 result 上。**那一行的正上方**有一段長註解,逐字:
```
🔴 **這一行是本片【最重要】的一行,而我差點沒寫。**
…我第一版**沒有把這個旗標帶出來** ⇒ route 讀不到 ⇒
🔴 **RPC 一直沒 apply ⇒ 這片完全沉默,而沒有任何人知道** —— 正是它要治的那個病。
```

**我把那一行寫死成 `false`。**
```
3 支測試檔 · Tests 186 passed (186) · rc=0  ⇒ **突變活著**
```

## 🔴 三層都沒抓到,而每一層的理由單獨看都合理

```
adapter 的測試      測的是 adapter 怎麼【算】那個旗標(該檔命中 5 處)
route 的測試        把 `checkAnomalyAlerts` **整支 mock 掉** ⇒ 真正的 pass-through 沒有跑
use-case 的測試     把它當【輸入】餵進去, 而沒有斷言它【出得來】
數法 grep -rn 'res\.shipped\|res\.shipments' --include='*.test.ts' ⇒ **改前 0 命中**
```
📌 **⇒ 兩邊都以為對方測了,而那個【交界】不在任何一邊的分母裡。**

## 📌 判別句

```
一段說明它有多重要的註解, 不是一個會在它壞掉時變紅的東西。
🔴 而註解越長、越懇切, 那一行越【像】已經被守住 —— 因為有人顯然想過它。
```
✅ 補了 4 條斷言後重放同一發突變:
```
補前 rc=0 · Tests 186 passed (186) · 紅 **0** 格
補後 rc=1 · Tests **1 failed** | 185 passed (186) · 紅在具名的那一行
⇒ 總數兩發都是 186 ⇒ **差別在紅的格數, 不在總數。**
```

## 🔵 可機械執行的一條(這一則有,前幾則沒有)

**在一支檔裡搜「最重要 / 承重 / 差點沒寫 / 一定要」這類自陳,對每一處問:
「它旁邊那一行,有沒有一個會為它變紅的東西?」** —— 那是一份**有限而可窮舉**的清單。

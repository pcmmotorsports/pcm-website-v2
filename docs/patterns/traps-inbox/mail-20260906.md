## 【新條】一道鎖比對的值, 是 fixture 餵的, 不是被測的碼算的

**場景**:對抗審查抓到「我那道『全文逐字』的鎖只抽內文, 沒鎖主旨」。
我照著補 —— 從**真的送出去的那一封**取主旨來比對, 而那聽起來比 import 那支函式**更接近事實**。

🔬 **第一發就印出一個對不上的值**:
```
expected 'PCM 訂單 PCM-2026-0001 付款成功通知'
      to be '訂單 PCM-2026-0142 已成立,請於期限內完成匯款'
```
🎯 **成因**:寄信那一層送的是 `job.subject`, 而 `subject` 是**排入列(enqueue)當下就寫進 outbox 的那一份**。
⇒ 📌 **在寄信那支測試裡鎖它, 鎖到的是【那支測試自己的 job fixture】** —— 產生主旨的那段碼**不在這條路上**。

🛑🛑 **而危險的不是它紅了, 是它【本來會綠】**:
我只要把 fixture 的 `subject` 改成正確字面, 那一格**當場全綠** ——
而它那時宣稱「主旨逐字鎖住了」, 實際上**改壞產生主旨的那支函式, 它一個字都不會說**。
⇒ 🔴 **一道鎖可以綠得很有說服力, 而它與被保護的那段碼之間【隔著一個 fixture】。**

### 判別句
> **這道鎖比對的那個值, 是【我要保護的那段碼算出來的】, 還是【測試自己填進去的】?**
> 　 答不出來 ⇒ 去看那個值**從哪裡來**:路徑上只要有一個 fixture, 鎖就停在 fixture 那裡。

### 修法(方向:把鎖搬到產生它的地方, **不是加更多斷言**)
✅ 主旨的鎖搬到 `packages/adapters/src/email/order-email-assembly.test.ts` —— 它就住在 `bankOrderCreatedSubject` 旁邊。
🧬 **搬完要證它會動**:主旨少四個字 ⇒ **1 failed**;還原 ⇒ 5 passed。

## 【併入既有母題】`㉗` 的第三個實例 —— 一次拿掉三條守門, 蓋住「其中兩條沒有世界可測」

> 🔵 **查重結果**:正本 `㉗`(`:2128`)與 inbox `T2-20260818.md:67` 已經是同一族
> (前者:fixture 形狀讓兩種寫法收斂;後者:fixture 的預設形狀堵住守門的入口)。
> ⇒ **本則【不開新條】, 請收割窗把它當作 `㉗` 的第三個實例併進去。**

**場景**:探針有一發突變, 一次拿掉 `balance_due` 的三條守門(`IS NOT NULL` / `> 0` / `<= total`),
讀數 1 → 2 ⇒ **綠**。我把它讀成「這三條都有在做事」。

🔬 **對抗審查說那不是單點突變。拆開之後(探針 21a/21b/21c/21d 四格, 讀數如下)掉出來的東西比那句更重**:
```
21a 只拿掉 IS NOT NULL  ⇒ 讀數不變(退款單被 > 0 擋住)
21b 只拿掉 > 0          ⇒ 讀數不變
21c 只拿掉 <= total     ⇒ 讀數不變
21d 三條全拿            ⇒ 讀數變了
```
🎯 **真正的成因在 fixture**:`paid_total` 是一支**恆回 0 的 stub** ⇒ `balance_due` **恆等於** `total`
⇒ 📌 **`> 0` 與 `<= total` 那兩條守門, 在那個 fixture 裡【沒有任何一筆資料會踩到它們】。**
⇒ 🛑 **而「一次拿掉三條」剛好讓那個空白看起來像被驗過了** ——
三條一起拿, **只要其中一條有作用讀數就會變**, 而它讀起來像「每一條都有作用」。

### 判別句(兩句, 各管一半)
> **① 我這一發突變拿掉的是【一條】還是【一組】?**
> 　 一組 ⇒ 讀數變了只證明「**至少一條**有作用」。
> **② 對每一條守門, fixture 裡有沒有一筆資料【會被它擋下來】?**
> 　 沒有 ⇒ 那條守門今天**不可測**, 而不是「已驗證」。

### 修法
✅ 拆成單點(21a/b/c)+ **保留全拿那一發當對照**;
✅ **補出缺的世界**:`paid_total` 改成可設, 加「付清(0)」與「多付(負數)」兩筆。⇒ 探針 **28 → 51 格**。

🔵 **順帶第三個教訓(不另開條, 掛在這裡)**:我拆完之後給 21b 的標籤寫「退款單漏進來」, 而讀數是 **1(沒漏)**。
⇒ **標籤要由讀數決定。** 而那一格是**探針自己**抓到的 —— 標籤說「1 變 3」而期望值還寫 1 ⇒ 矛盾 ⇒ 紅。
📌 **一個與讀數矛盾的標籤, 比沒有標籤糟** —— 它會讓下一個人去改【本來是對的】那一半。

## 【新條】字面與碼分家的時候, 守的是【字面】、破的是【碼】—— 而反過來也有, 判準不是「哪個先寫」

> 🔬 **查重跑過**(`scripts/traps-neighbours.py`, 分母 **2988** 則, 落 `logs/traps-neighbours.jsonl:532`)。
> 🔴 **最高分 0.2084 < 0.25 ⇒ 工具自己說「這不是沒有近親, 是尺沒接上」** ⇒ 照它的指示做了尺二
> (`grep -n '^## '` + 機制關鍵字 `文案|核可|字面|重算|快照|不寄|逐字|Sean`, 命中 28 條標題)。
> **開檔讀過三條, 逐條寫為什麼不同族**(見下方分界表)。

**場景**:寄送前的重驗發現我手上那份快照過期了 —— 後台把金額從 **12,800** 改成 **10,000**,
或收件人從 A 換成 B。最自然的修法是 **「用新值重算一封信再寄」**。

🛑 **而那是錯的, 錯在一個不在程式裡的地方**:那封信的每一個字是 **Sean 逐字核可**、
被一整串 `toBe` 鎖著的。用新值重算 = **在寄送當下生成一份沒有人核可過的文案**。
⇒ ✅ 正確處置是**不寄**, 標一個自己的錯誤碼, 讓那一列在修好之後**重新排進來**。
📌 **少寄一封 < 寄一個沒有人看過的版本給客人。**

🔬 **而同一夜, 同一個形狀出現了三次, 三次的【正確方向不一樣】**:
```
① 快照過期      字面 = Sean 核可的信      ⇒ 守字面, 破碼(不寄, 不重算)
② 「不進 result」  字面 = 我自己寫的註解      ⇒ 破字面(型別上就帶著它, 註解是錯的)
③ 部署順序只列一支 字面 = 我自己寫的前置清單  ⇒ 破字面(補上另一支)
```
🔴 **三次我的第一反應都一樣:「讓它們一致」** —— 而那句話**沒有方向**。

### 判別句(兩問, 都答完才知道要動哪一邊)
> **① 這個字面是【誰核可的】?** 有第三方核可(Sean / 法務 / 對外公告)⇒ **字面是權威, 動碼。**
> **② 有沒有人【在別的地方依賴這個字面】?**(測試的 `toBe`、別支檔的引用、客人看過的舊信)
> 　 有 ⇒ 動它要連著那些依賴一起動, 不是就地改一個字。
> 　 兩個都「不是」⇒ 那只是**我寫的一句描述**, 而描述說錯了就改描述。

### 🛑 為什麼這條值得寫下來(不是「小心一點」就能防的)
**在 diff 上, 「改註解讓它符合碼」與「改碼讓它符合註解」是【同樣大小、同樣安全】的一行。**
三綠對兩個方向**都是綠的**;審查看到的也是「作者把不一致修掉了」。
⇒ 📌 **方向這個維度, 在所有既有的量具上都不留形狀** —— 只有「誰核可的」這一問答得出來。

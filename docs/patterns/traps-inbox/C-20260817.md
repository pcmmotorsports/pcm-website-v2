## 「我沒跑那條命令」與「repo 裡沒有那個東西」——**寫出來的句子一模一樣**〔安靜〕

**實例(2026-08-17 晚,C 窗 `Q-C9` plan §3;`f958af69` 的 commit body 有原句)。**

要寫「自取那封信的文案」,而文案要告訴客人**什麼時候可以來拿**。
我落筆寫的是:

> 「但『可取貨時間 / 營業時間』**全 repo 我沒有找到**(未查到,不是不存在)⇒ **列為待問 Sean**。」

**那一整句是憑印象寫的 —— 我一次都沒跑過那支 `grep`。**
真的跑了之後:

```text
grep -rl '營業時間\|營業時段\|取貨時間\|可取貨' --include='*.ts' --include='*.tsx' \
  --include='*.md' --include='*.sql' apps packages docs supabase        ⇒ 21 檔
正向對照 同範圍找 '自取'（僅 ts/tsx）                                    ⇒ 27 檔
```

而 SSoT 就在其中:`apps/storefront/src/lib/site-config.ts:37-42` 的 `OPENING_HOURS`
= 週一–六 10:00–19:00。**那題根本不必問 Sean。**

### 為什麼它安靜

    「我沒跑那條命令」  ⇒ 寫出來是「找不到」
    「我跑了、回 0 」    ⇒ 寫出來也是「找不到」
    ⇒ 這兩個世界在【句子】這一層沒有差別，而句子就是下一個人拿到的全部

而且它**還附了一個看起來很嚴謹的自我限定**(「未查到,不是不存在」)——
那個限定**讓句子更可信**,卻**一個字都沒有增加證據**。
🔴 **免責貼紙貼在一個沒做過的動作上,只會讓它更難被質疑。**

### 判別句(落筆寫「找不到 / 查無 / 沒有」的當下)

> **我剛剛真的跑了那條命令嗎?那條命令長什麼樣?它回了什麼?**
> 三個問題有任何一個答不出來 ⇒ 我要寫的不是「沒有這個東西」,
> 是「**我還沒查**」。這兩句話對讀的人做的事完全相反:
> 前者**關掉**他的尋找動作,後者**把動作交給**他。

### 動作(三條,缺一都會退回原狀)

1. **命令與結果一起落筆。** 沒有 `⇒ N` 就不准寫「找不到」。
2. **配正向對照。** 同一支 `grep` 在同一個範圍找一個**一定存在**的字,證明它會命中。
   (本例:找 `自取` ⇒ 27 檔 ⇒ 那把尺是活的。)
3. **標「未確認」時必附【缺哪一道檢查】。** 附不出來 = 免責貼紙,重寫。

### 📎 同族的另一個方向(2026-08-17 夜,B 窗)

B 窗把**已經拍過的板**寫成「還沒人拍」;我把**存在的東西**寫成「查無」。
⇒ **同一個沒做的動作:沒跑那條命令就先寫了結論。**
兩個方向的共通症狀:**產出的檔看起來完全正常**,而它關掉的是下一個人的動作
—— 一個讓他**不去找**,一個讓他**去等**。

📎 與本檔既有那條「量對了東西,卻量的是一個重製品」的關係:
那條是**量了、而量錯對象**;本條是**根本沒量、而寫得像量過**。
**後者比前者便宜得多也常見得多** —— 它連一次執行都不需要。

## **內容型斷言守不住「那個東西在哪一層」** —— 而繞過它的那條路,畫面幾乎一樣〔安靜〕

**實例(2026-08-17 晚,C 窗 `Q-C20` 續頁抬頭,`566bfcdf`)。**

要守的事:**列印時第 2 頁上要看得到「這是哪一張訂單、哪一箱」**。
做法是在品項表的 `<thead>` 裡多一列帶訂單編號與箱號 —— 靠的是**瀏覽器對 `<thead>` 的原生逐頁重複**。

**直覺會寫的守門**(而它是壞的):

```js
expect(textOf(container)).toContain('PCM-2026-0042')   // ← 恆綠
```

🔴 **因為頁首本來就印著一個訂單編號。** 把那一列**搬出 `<thead>`**
(挪去 `<caption>`、或表格上方的 `<div>`):

    畫面    幾乎一樣（同樣的字、同樣的位置）
    textContent  照樣含訂單編號
    四綠     全綠
    而列印時   第 2 頁變回沒有單號 —— 也就是這件事整個沒做

⇒ **內容型斷言在「已經壞掉」的那個世界裡照樣通過。**

### 為什麼它安靜

    這一族的壞法不是「東西不見了」，是「東西還在，只是搬到了不會被重複的那一層」。
    而「在哪一層」不在 textContent 裡，也不在畫面上 —— 它只在【列印時】才有後果。

### 修法:**釘位置,不釘存在**

```js
const bar = t.querySelector(':scope > thead > tr.contbar > th');   // ← 位置
expect(bar).not.toBeNull();
expect(bar?.textContent).toContain(orderDisplayId);               // 內容只是附加
expect(bar?.getAttribute('colspan')).toBe('3');
const rows = [...t.querySelectorAll(':scope > thead > tr')];
expect(rows[0]?.classList.contains('contbar')).toBe(true);        // ← 還要排在欄名【上面】
```

### 🔴 第二條,與上面同等重要:**不要假設「今天共用同一份 JSX」永遠成立**

出貨明細單有**三張**品項表,今天它們共用同一個 `Section` 元件
⇒ 一格斷言看起來就夠了、一發突變也會同時打到三張。
**而守門守的是契約,不是今天的實作細節。** 哪天有人把「訂單取消」那一區拆出去自己寫,
共用那一格**照樣綠**,而那一區靜默失去抬頭。⇒ **三張各釘一次。**

### 判別句(寫守門的當下)

> **我先想一下:這件事會怎麼被弄壞、而畫面看起來一樣?**
> 想得出那條路 ⇒ **照那條路去釘**,不要照「東西在不在」去釘。
> 想不出來 ⇒ 我還不知道我在守什麼,先別寫那格。

### 這格自己的雙向表演(不做這步就不算完)

    M1 `contbar` class 改名        ⇒ Tests 1 failed | 60 passed   rc=1
    M2 抬頭那一列與欄名那一列對調  ⇒ Tests 2 failed | 59 passed   rc=1
    兩發都先 cp 一份到 /tmp 再改，跑完 cp 回來並 diff -q 驗還原，
    git status --porcelain <該檔> 只剩本次修改那一行。

📎 與本檔上一則的關係:上一則是**沒跑那條命令**;本則是**跑了、而那條命令量的是別的東西**。
**兩則的共通點:產出看起來完全正常。**

## 工具**大聲**回了一個錯誤,而我讀成結果 —— 而它是我拿來**推翻自己**的那一發

> 線【DB】`-db` 2026-09-06。
> 🔵 **這是正本 `:6210`「`grep` 在沒有任何提示的情況下拒絕讀一個檔 —— 而它印出來的東西跟『查無』一樣〔安靜〕」
> 那個母題的【新子機制】,不是新的一族。** 差別寫在最後一節。

### 發生了什麼

我給冪等閘加了新樣式之後,被擋的支數從 **50 跳到 61**。

🔵 **我做對了一件事:我沒有相信那個數字,我去驗它。**
跑了一發 grep 數 repo 裡有幾支**真的** `CREATE TABLE … AS SELECT` ⇒ 得到 **0**。
於是我寫下:「**repo 裡一支真的 CTAS 都沒有 ⇒ 那 11 支全是誤擋**」,然後去把樣式收窄。

🔴 **而那個 0 不是計數。** 那一發印的是:

```
ugrep: error: error at position 627
\xf4[\x80-\x8f][\x80-\xbf][\x80-\xbf]){0,200}AS
                  exceeds complexity limits___/
```

它**先印錯誤再結束**,而我**只看了最後那個數字**。
真相是:那 11 支**全是真的 CTAS**(`CREATE TEMP TABLE … ON COMMIT DROP AS SELECT`),
而正確結論不是「沒有 CTAS」,是「**它們是 TEMP,重跑安全 ⇒ 該排除的是 TEMP**」。

### 🔴 坑的形狀 —— 它比「直接相信那個數字」貴

**直接相信 50** ⇒ 只是**沒驗**。
**讀錯錯誤** ⇒ 讓我**以為我驗過了**,然後**去改一個本來是對的樣式**。

🎯 ⇒ **一個懷疑的動作,被一把壞掉的量具帶到了相反的結論。**
🛑 而那一刻我對結論的信心**比沒驗之前更高** —— 因為我「查過了」。

### 判別式

> **任何用來【推翻自己】的量測,先看它的 rc 與 stderr,再看它的數字。**

🔵 `grep` / `rg` / `ugrep` 家族尤其:它們的 rc 有**三種** ——
`0` 有命中 / `1` 沒命中 / **`2` 出錯** ——
而 **「沒命中」與「出錯」在只看 stdout 的時候長得一樣:都是空的。**

### 這一條與正本 `:6210` 差在哪

| | 正本 `:6210` | 本條 |
|---|---|---|
| 工具怎麼壞 | **安靜地**拒絕讀檔 | 🔴 **大聲印了錯誤** |
| 為什麼沒被發現 | 它沒說話 | **它說了,而我沒讀** —— 我只看尾巴那個數字 |
| 那一發的用途 | 一般查詢 | 🔴 **拿來推翻我自己的結論** ⇒ 錯得更遠 |

📌 ⇒ **母題相同(工具的失敗與工具的答案長得一樣),而新的那一格是:
它其實有講,只是我讀的位置不對。** 那不是工具要改,是**讀的順序**要改:**先 rc、再 stderr、最後才是數字**。

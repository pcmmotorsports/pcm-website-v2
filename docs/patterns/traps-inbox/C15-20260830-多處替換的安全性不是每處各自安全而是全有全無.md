# C15-20260830 · **一個多處替換的編輯,它的安全性不等於【每一處各自安全】**

> 投件窗 線C(`-b4`)· 2026-08-30 12:0x · **我踩到,而擋下我的是最後一處的那行 `assert`**
> 🔴 **本條不是「要小心標點」** —— 它是**一個編輯動作有沒有原子性**,而標點只是最常見的觸發器。

---

# 現場

改一支要端給 Sean 的檔,**兩處替換,同一支檔**:

```
第一處：Q3 的代價那行 ⇒ 錨命中 ⇒ 準備替換 ✅
第二處：檔尾那節     ⇒ 🔴 **錨查無**
```

**查無的原因**:
```
我打的錨： 「我答不出來,那要正式庫」   ← 半形逗號
檔裡的字： 「我答不出來，那要正式庫」   ← **全形逗號**
⇒ ⇒ 兩者在畫面上幾乎一樣，而在字串比對上是兩個不同的字元
```

✅ **而第二處的 `assert` 讓腳本在 `write` 之前中止 ⇒ 那支檔【一個位元組都沒被改】。**

---

# 🔴 可執行的通則(這是本條唯一有用的東西)

> ## **一個多處替換的編輯,它的安全性不等於【每一處各自安全】——**
> ## **它等於【全部成功,或全部不寫】這個性質有沒有被保證。**

```
🛑 而逐處呼叫編輯工具（改一次、再改一次）預設【不保證】：
   第一處寫了 ⇒ 第二處查無 ⇒ **半支檔，而它不會報錯**
⇒ ⇒ 兩條可用的形狀（擇一）：
   ① 整段 rewrite（讀進來 → 全部改完 → 一次 write）⇒ **天然全有全無**
   ② 每一處都自帶 assert，而 🔴 **最後一處的 assert 是唯一擋得住「半寫」的那一格**
      —— 而它也是最容易被省掉的一處：**前面幾處都成功了，人會鬆手。**
```

## 📌 而「半支檔」為什麼比「完全沒改」貴

```
完全沒改 ⇒ 我會發現（我要的東西不在）
🔴 半支檔 ⇒ **它看起來就是改好了** —— 我改的第一處在，我不會回去確認第二處
⇒ ⇒ 而下一個讀那支檔的人，讀到的是【一半新、一半舊】，而兩半都通順
```

# 🔵 全形/半形是那個查無最常見的來源,而它連到一條既有規矩的同一個根

```
常載規矩逐字：「zsh 禁全形標點「」():;」（報 unknown file attribute）
🔴 而根是同一個：**中文標點在不同層長得一樣，而不相等**
   · 在 shell 那一層   ⇒ 語法錯（**會叫**）
   · 在字串比對那一層 ⇒ 查無（**不會叫**）
⇒ ⇒ 📌 **同一個根，一邊有訊號、一邊沒有 —— 而沒訊號的那一邊，我們沒有規矩。**
```

## ✅ 判別動作

> ## **我這一發要改幾處?**
> ## **⇒ 一處以上 ⇒ 問:【第二處失敗的時候,第一處會不會已經寫下去了?】**

```
✅ 最便宜的形狀：所有替換做在【記憶體裡的字串】上，最後才 write 一次
   （本次就是這個形狀，所以它擋住了 —— 不是因為我警覺）
⚠️ 而逐處呼叫編輯工具是**最順手的那一種**，而它天生沒有原子性
```


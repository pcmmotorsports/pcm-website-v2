# 端一題出去之前,要查到【選項】那一層 —— 不只查「那一列還成不成立」

> 線【出貨】`-1e` · 2026-08-31 · 主視窗 `-24` 指名採用並要求由現場的人落檔

## 判別句

**端一題出去之前,先查【這一題的每一個選項】是不是已經有人做掉了 ——
不只查「那一列還成不成立」,要查到【選項】那一層。**

## 當天發生的事

板上 `⟦b4-DUPACC1⟧`(後台建客人查重不是原子的),Sean 批「甲 現在修」。
我照規矩跑了 `bash scripts/is-this-still-true.sh`,**它回「成立」**。

我於是端了一題給主視窗:
```
Q5: 先做哪一片?
A: 甲 先做片2(把疑似重複變成員工的選擇)—— 我推薦
   乙 照原順序先做片1
```
🔴 **而片 2 一個月前就做完了**(`6d4f4323`,2026-08-28,codex R5/R6/R7 must-fix 修出來的),
**而且有測試守著**(`manual-customer-picker.test.tsx:1042` 逐字
「existing ⇒ 那位出現在候選裡, 而【一顆都沒有被選起來】」)。

⇒ 那一題會讓 Sean **去決定一件已經做完的事**。

## 🔴 而這一格最值錢的地方:工具沒有壞

```
is-this-still-true.sh 回「成立」—— 而它是【對的】。
那一列確實還開著:三個關掉條件裡的 ①(DB 鎖)真的沒做。
```
📌 **⇒ 不是量具失效, 是【問題問窄了】。**

「**那一列還成不成立**」與「**我提的那個選項還沒被做掉**」是**兩個宣稱**,
而我只查了前者就端題。
⇒ 一列可以合法地還開著(某一部分沒做),
   **而我端出去的那個選項, 剛好落在已經做完的那一部分上。**

## 🛑 為什麼這個錯特別貴

```
· 它不會被任何閘擋下 —— 三綠全綠, 板子那一列的態也是對的
· 它消耗的是【Sean 的注意力】, 而那是全隊最稀缺的東西
· 而他回答之後, 那個答案會被落檔、被引用 —— 一個關於不存在問題的拍板
```
🔴 **同族(這是重複發生, 不是新病)**:
memory `8題有5題早做完板子上還開著與沒人回頭劃掉同一個字`。
⇒ 那一條講的是**板子過期**;**本條講的是【端題的人自己】** ——
   即使板子是對的,選項那一層仍然可能過期。

## 怎麼做

```
① 照舊跑 is-this-still-true.sh / before-asking-sean.sh(它們仍然是對的, 只是分母不同)
② 🔴 再加一步:把【每一個選項】當成一個獨立的宣稱去查
   「甲 = 做 X」⇒ 去查 X 是不是已經有人做了(grep 落點 + 開檔 + 看測試)
③ 查到了 ⇒ 那個選項不該出現在題目裡, 而【它被做掉這件事本身】可能就是答案
```
⚠️ **成本很低**:當天我做這一步花了約 4 分鐘(grep 兩支檔 + 讀 40 行 + 數測試格數),
而它省掉的是一次 Sean 的拍板 + 一次落檔 + 未來所有引用那個拍板的人。

## 📎 順帶一格(同一天、同一份 plan)

我在同一份 plan 裡把兩題**都編成 `Q3`** ⇒ 他回「Q3=甲」會指到兩件事。
⇒ 與 memory `兩個窗兩套標號同一個字母被讀成相反的答案` 同族,
   **而這一次是發生在【同一份檔】之內** —— 不需要兩個窗就能撞。

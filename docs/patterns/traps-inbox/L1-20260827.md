## 🔴🔴 一句宣稱的射程,大於【產生它的那個動作】的射程 —— 而超出的那一段不會留下任何訊號(2026-08-27 線1 `-21`,具名自寫;一夜四個實例)

> **一句話**:我做了一個動作(開了一個檔 / 查了一個地方 / 跑了一次 / 印了一句話),
> 然後我寫下一句宣稱。**那句宣稱涵蓋的範圍比那個動作大**,而**大出來的那一段沒有任何載體會印紅**。
> ⇒ 四個實例形狀不同、載體不同、修法不同,而**它們都是同一個差**。

### 判別句(結尾是動作,照 `:19916`)
> **產生這句話的那個動作,涵蓋到哪裡為止?——【把那個邊界寫在這句話旁邊】。**
> 🔴 **答不出邊界時的預設處置:把宣稱縮到動作的邊界。**
>    (不是標「未確認」——「未確認」是把宣稱留在原地再貼一張貼紙,它不縮射程。)

### 🔴 三件要先講的(主視窗讀完投稿後要求提到 §0)

**一、【標記】/【縮射程】/【加一道拒絕】是三種不同的動作, 不互相取代**
```
標記    「未確認」「已知缺口」          ⇒ 那句話【留在原地】, 只是旁邊多一張貼紙
縮射程   把宣稱改小到動作的邊界          ⇒ 那句話【變小了】
加拒絕   「這一格填起來之前, 擋住的是 X」 ⇒ 那句話還在, 而它現在【擋得住事】
```
📌 `-26` 2026-08-27 的原句:**「一個被標記的洞, 與一個被填起來的洞, 在下一句話裡長得一樣。」**
⇒ 本條處置**只講第二種**。第三種是主視窗同夜在 `#944`-`#947` 做的。**三種並存, 選哪一種要看那句話會被誰讀。**

**二、🔴 四個實例裡三個換了載體、一個停在紀律 —— 而【停在紀律的那一個, 正是最常發生的那一種】**
實例① 是「同一件事寫在兩個檔」, 而我的修法是**兩處互相指路**。
⇒ **那仍然靠人記得開兩個檔。** 我沒有把它從會腐爛的位置搬走, 因為我不知道怎麼搬。
⇒ **「最常見的那一種目前無解」這件事本身要被看見**, 不要因為它被寫在實例①裡就以為它跟 ②③④ 同級。

**三、對照組(正例)—— 這個病有一個現成的反面示範, 而它就在每天用的 hook 裡**
2026-08-27 我把「寫 commit 訊息檔」與「commit」放在同一個 bash call ⇒ 全稱句守門讀不到那個檔。
它印的**不是**放行, 也**不是**假裝驗過, 而是逐字:
> 「⚠️ **這一發我沒有檢查到**…⇒ 這則 commit 訊息裡的全稱句**沒有被驗過**」
📌 **一個量具明說自己的射程到哪裡為止 —— 那正是本條在講的東西的正面版。**
⇒ 拆成兩發重跑之後, 它就真的擋下我一句沒附數法的全稱句。**一條教訓有一個現成的正例, 比十個反例好用。**

### 🔴 為什麼四個修法不一樣 —— 而其中三個是【搬走】不是【修準】

```
① 兩處互相指路(「改這段就要開那一份」)—— 而這仍然是紀律, 我知道
② 訂正落在【那支測試的檔頭】而不是 docs ——【下一個撞到的人會做的動作是打開那支測試】
③ 結果不要寫在被測物裡:探針不寫自己的 sha, 輸出檔【執行當下現算】
   ⇒ 我沒有選「以後記得先算」——【那是紀律, 而紀律會再壞一次】
④ 不要在下游重寫上游的理由, 直接把上游那一列的判定【搬過來】
```
🔴 **②③④ 的共同解法不是「把資訊修得更準」,是【把它從一個會腐爛的位置搬走】。**
而 ① 我沒有做到那件事 —— **我只加了互相指路的註解,那仍然靠人記得。** 明寫,不假裝。

### 這一條與「分母選窄」是不是同一條

**不是,而它們常常同時出現。** 分母選窄講的是**量測涵蓋多少**;
本條講的是**宣稱涵蓋多少 vs 動作涵蓋多少的【差】**。
⇒ 分母選窄的人**可以誠實地報出他的分母**(那就沒有本條的病);
  而本條的病是**那個差沒有被寫在宣稱旁邊** ⇒ 讀的人拿不到它。

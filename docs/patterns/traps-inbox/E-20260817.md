## 「開始寫」之前先問「這件有沒有人做過」—— 而擋住我的是工具的預設行為,不是我的紀律

**當天實例(2026-08-17 夜,E 窗)**:
主視窗派工「寫全站滲透測試計畫,先寫不跑」。我讀完要件、直接動手寫一份新的,
`Write` 工具回:
```
File has not been read yet. Read it first before writing to it.
```
一讀才發現 `docs/security/2026-08-17-full-site-pentest-plan.md` **已經存在,166 行,16:13 寫的,已 commit**,
而且**比我正要寫的那份完整**(§0 三條硬紀律、三個面向、§8 觀測端盤點與執行順序、§8.3 動手前四句自檢)。

🔴 **擋住我的是工具的預設行為(「沒讀過不准覆蓋」),不是我的紀律。**
**如果那個預設不存在,我會用一份較差的檔覆蓋掉一份較好的檔,而且不會有任何訊號** ——
`git status` 只會顯示 `M`(修改),不會顯示「你剛剛蓋掉了別人 166 行」。

**兩層病灶,分開記(它們的修法不同)**:
```
執行者側  我把「派工單描述的東西」直接當成「還不存在的東西」。
          派工單說「寫一份」，我讀成「從零寫一份」——而它其實是「確保有一份」。
派工者側  主視窗自陳:派工時沒查既有物（它說當晚第二次、前一次是 README）。
          ⚠️ 「第二次」是主視窗的自陳,**我方未數、未查證**——引用時帶這個限定。
          🔴 派工者沒查既有物 = 把「重複造輪子」的風險【轉嫁】給執行者，
             而執行者手上的資訊比派工者少。
```

**判別句(給下一個人)**:
> 🔴 **我正要「新增」的這個東西,它的位置我猜得出來嗎?猜得出來 ⇒ 先去那個位置看一眼。**
> 檔名帶日期 / 帶主題的產物(`docs/security/<日期>-<主題>.md`、runbook、plan、清單)**最容易撞**,
> 因為**命名規則本身讓兩個人會取到同一個名字**。

**當場可跑的一條(比記住這條便宜)**:
```
ls docs/security/ docs/specs/ | grep -i <主題關鍵字>
# 或
git log --oneline --all -- '*<主題關鍵字>*' | head
```
🔴 **要 `--all`** —— 施工窗的產物常在**未收割的分支**上,`ls` 只看得到當前 checkout
(同 `docs/lessons-learned.md` §12-43「`git ls-files` / `test -e` 只看當前 checkout」那一條)。

**與既有條目的關係**:
- 近親=「**寫對地方 ≠ 會被讀到**」(2026-08-16 admin 本機啟動那條):那條講**寫了沒人讀**,
  這條講**沒讀就寫**。**同一個縫的兩個方向。**
- 這條的特別之處:**它這次沒有造成損失,而零損失的原因是一個工具預設,不是任何人的判斷。**
  ⇒ **不要把「這次沒事」讀成「這個流程是安全的」。**

## `$?` 是管線右端的那個 —— **它一天穿了三件不同的衣服出現在同一個窗身上**

**重點不是「`$?` 是右端的」** —— 那是 `CLAUDE.md` 終端紀律**已經寫著**的東西,我今天開工就讀過。
🔴 **重點是:我讀過它、修過它,然後在同一天又踩了兩次,因為它每次長得不一樣。**

**2026-08-17 E 窗,同一條,三個外觀**:

```
① 在【別人的腳本】裡（我以審查者身分抓到，很得意）
   SECOUT=$(git diff … | grep -E '^\+' | grep -cE "$PAT6"); SECRC=$?
   ⇒ SECRC 是最右端 grep 的。左端 git diff 死掉 ⇒ grep 吃空輸入、印 0、rc=1
   ⇒ 過了 `-ge 2` 檢查 ⇒ **祕密掃描讀成「乾淨」**
   （V 窗 RI-1 指出，我修的）

② 在【別人的診斷】裡（我以複量者身分抓到）
   全窗廣播「find 回 0 而 exit code 仍是 0」
   ⇒ 我複量:find 直接跑 rc=1（它【有】報錯），`| wc -l` 之後才變 0
   ⇒ 廣播的診斷少算一格；而少算那一格會讓修法停在「改用 ISO 格式」
     （特例），而不是「掃描不要接 | wc -l 就當結論」（通則）

③ 在【我自己的自查】裡（🔴 差點沒抓到）
   grep -n "LINE" <清單> | head   ⇒ 空輸出、rc=0
   ⇒ 我差點讀成「有寫，只是沒印出來」
   ⇒ 那個 rc=0 是 head 的。改成 grep -c（不接管線）⇒ 0、rc=1
   ⇒ 而我正在用它查證「我剛剛跟主視窗說的那句話是不是假的」——**答案是假的**
```

🔴 **判別句(這才是新東西)**:
> **「我已經知道這條了」不會讓你下次認出它。**
> 因為你認得的是**那一次的樣子**:那次是 `SECRC=$?`,而下次是 `| head`、再下次是 `| wc -l`。
> ⇒ **要認的不是句型,是【位置】:任何時候我要拿一個 `$?` 或一個「空輸出」當結論,
> 先問「這條管線右端是誰」。**

**當場可跑的一條(比記住這條便宜)**:
```
不要   cmd | wc -l        然後看 $? 或看到 0 就下結論
要     cmd > /tmp/o 2>/tmp/e; echo "rc=$?"; wc -l < /tmp/o; head -2 /tmp/e
或     在【呼叫的那個 shell】set -o pipefail（寫在腳本裡管不到包住它的那一個）
```

**與既有條目的關係**:
- 這條**不是**新規則,`CLAUDE.md` 終端紀律早有。**它是「知道規則 ≠ 執行規則」的一個高解析度實例**
  (memory `feedback_knowing-rule-is-not-executing-rule`)。
- 🔴 **它的新資訊是「復發的機制」**:不是因為忘了,是因為**同一條規則的三個實例在表面上不相似**,
  而人是靠表面相似度做模式辨識的。
  ⇒ **修法不能是「記得這條」,要是「在那個【位置】設一個當場動作」** —— 位置 = 我要把
  空輸出或 `$?` 當成結論的那一刻。

## 證據一直在自己的檔裡,而寫的時候沒有讀到那個字母

**當天實例(2026-08-17 夜,E 窗;由 B 窗交件時指出)**:

我寫 `E-684` 新物件收權斷言樣板,**手寫了七種表權限**:
```sql
ARRAY['SELECT','INSERT','UPDATE','DELETE','TRUNCATE','REFERENCES','TRIGGER']
```
PG 17 有**八種**,少了 `MAINTAIN`。

🔴 **而我漏掉它的時候,證據正印在我自己引用的字面裡**:
```
docs/specs/2026-08-17-e683-default-privileges-plan.md:29
  現在（網站庫）  postgres → {postgres=arwdDxtm, anon=Dxtm, …}
                                              ^^^^
aclitem 字母:D=TRUNCATE  x=REFERENCES  t=TRIGGER  m=MAINTAIN
⇒ 那個 m 就是 MAINTAIN。我【引用了它、貼進 plan、當成證據用】，然後在同一天
   寫樣板時憑記憶列了七項。
```

**為什麼沒讀到**:
`Dxtm` 是一個**壓縮字面** —— 它讀起來像一個**識別碼**(一團代表「那組權限」的東西),
不像一個**清單**。⇒ **我把它當成「一個值」在搬運,沒有把它當成「四個成員」在展開。**

🔴 **判別句**:
> **我引用的這個字面,是不是一個【被壓縮的清單】?**
> 是 ⇒ **展開它,逐個成員唸出來**,再決定我的檢查涵不涵蓋每一個。
> 常見形狀:`aclitem`(`arwdDxtm`)、權限位元、旗標欄、bitmask、`rwxr-xr-x`、
> enum 的簡碼、`Dxtm` 這種**沒有分隔符**的字串 —— **沒有分隔符的東西最容易被當成單一值。**

**當場可做的一條(比記住這條便宜)**:
```
手寫任何「型別/權限/狀態」清單前，先問:這個清單會不會隨【版本或平台】增加成員？
會 ⇒ 用推導不要手寫。本例的修法:
  SELECT DISTINCT d.privilege_type FROM aclexplode(acldefault('r', <owner>)) d
⇒ PG 之後再加第九種，這一臂自動入列。
```

**嚴重度要精確(這一格本身也是教訓)**:
B 窗原本寫「樣板掃不到它自己舉的那個例子」,**我複驗後收窄成「少報,不是全盲」**:
```
現況 anon=Dxtm ⇒ 樣板列的 D/x/t 三項都會命中 ⇒ 斷言仍會 RAISE
⇒ 既有用過樣板的地方【沒有】因此變假綠
危險世界是:某次修補收掉 D/x/t、只剩 m ⇒ 樣板報「乾淨」而 anon 仍有 MAINTAIN
```
🔴 **而這個收窄是實質的**:少報 ⇒ 既有的仍成立、只需往後改;
全盲 ⇒ **要回頭重跑所有用過樣板的 migration**。**兩者的工單完全不同。**
⇒ **報缺陷時,「它壞到什麼程度」與「它壞了」一樣要量。**

## 更正一條錯結論時,難的不是掃全樹,是**知道要掃哪幾個字**

**背景**:Sean 的實測答案推翻了我三條已經對外講過的結論。交接信點名了三處位置。
我改完那三處之後**沒有收工**,先拿舊字面跑了一次全樹掃描 ——
**掃出 4 個沒有人點名的下游載體**(`route-inventory` 附錄 A-3/A-5/A-6、
`pre-launch-checklist` ⑪、`trigger-map` 附錄 C)。

🔴 **那 4 處讀起來一樣有說服力。** 它們不是「附註」「引用」——
每一處都是完整句、有證據、有行號,**看不出來上游已經倒了**。
⇒ 只改被點名那三處的話,明天引用的人會引到那 4 處,而且**引得理直氣壯**。

### 這條與既有那條的差別(**不要當成同一條**)

`feedback_claimed-sync-but-only-patched-touched-lines` 已經說了「要掃全樹」。
**那句大家都知道。真正卡住的是:掃什麼字?**
—— 落筆當下你手上只有「這個結論錯了」,沒有「錯字面清單」。

### 🔴 可操作的部分:舊字面清單怎麼生出來

**不要**從「我改了哪些字」去想(那只會生出你已經改過的那幾個)。
**要從【被推翻的那個命題】的四個面去生**:

```
① 結論的斷言詞      —— 那句話最短的講法。 例:永久有效
② 結論的解法詞      —— 「所以我們有救」的那個詞，最容易被單獨引用
                       例:解藥   ← 🔴 這個字撈到的東西最多，而我差點沒想到
③ 判斷的依據詞      —— 我當初【憑什麼】那樣說。 例:同一個 Provider
④ 嚴重度標籤        —— 別人排優先序時抄走的那個詞。 例:硬 blocker
```
實際用的:`grep -rn '永久有效\|解藥\|同一個 Provider\|硬 blocker' docs/`

**② 是最容易漏的一面。**
①③④ 都在講「問題」,只有 ② 在講「沒關係、有解」——
🔴 **而「有解」那句話,正是別人拿去決定「這條可以先不修」的那一句。**
它錯掉的代價比 ① 高,而它用的字跟原結論**一個都不重疊** ⇒ 靠回想改過哪些字絕對撈不到。

### 判別句

> **我掃的這組字,涵蓋「這件事沒關係」的那個說法嗎?**
> 只涵蓋「這件事有問題」的說法 ⇒ 你會留下所有「所以不用管」的殘句。

⚠️ **射程限定**:上面四面是從**一次**更正(3 條結論 / 7 個載體)歸納的,**不是驗證過的通則**。
下一次適用不適用,自己再看。**不要把它當清單照抄然後宣稱掃乾淨了。**

### 反向代價(**同一次裡真的踩到**)

掃出來的命中**有一些是它自己的訃聞** —— 我剛寫下的「~~永久有效~~ 已推翻」也含那個字。
⇒ **命中之後要開檔讀那一段**,不能看到命中就改。
(同 memory `feedback_claimed-sync-but-only-patched-touched-lines` 的反向代價那條。)

## 同一個錯誤碼騙了我四次 —— 而每一次它都「證明」了我想證明的那件事

**背景**:寫 `#628` 的負測,要證明「`anon` 沒有 `MAINTAIN` 了」。
做法是以 `anon` 身分去跑 `REINDEX`,**要求它回 `42501`(權限不足)**。

一個晚上,`42501` 出現四次,**每一次的原因都不是我以為的那個**:

```
① anon 沒有 schema public 的 USAGE  ⇒ 42501（碰不到 schema，不是沒有 MAINTAIN）
② pg_maintain 自己沒有 schema USAGE ⇒ 42501（提權目標動不了，不是提權失敗）
③ CLUSTER 沒有既有 clustered index  ⇒ 42704，而【有權限的世界也炸】
④ 真的沒有 MAINTAIN                 ⇒ 42501  ← 只有這個是我要的
```

🔴 **①②④ 在觀察面上【一模一樣】。** 而 ①② 那兩次,我的斷言**通過了** ——
負測綠燈,而 `MAINTAIN` 根本沒被收掉。**綠燈的原因是「更早的地方就壞了」。**

### 為什麼「換更嚴的斷言」修不好它

我的第一反應是把斷言寫緊(檢查訊息文字、檢查更多欄位)。**那個方向是錯的。**
訊息文字會變、而且 ①②④ 的權限拒絕本來就長得像。

**真正的修法是加一道【可歸因性正控】**:
```
在做那件「應該失敗」的事之前，
先證明這個角色【現在碰得到這個東西】—— 例如它 SELECT 得到那張表。

證得到 ⇒ 接下來的 42501 才歸因得到我要測的那個權限
證不到 ⇒ 這一格【失去判別力】，要 RAISE，不是繼續往下測
```
⇒ 這一格在 `#628` 是 `§3b`,它是被自己的突變測試(拿掉 schema USAGE)逼出來的。

### 判別句

> **失敗的原因有幾種?我排除掉幾種?**
> 只要「我要的那個原因」與「別的原因」會產生**同一個觀察值**,
> 那個斷言就**還不是量具** —— 不管它今天綠不綠。

📌 近親但方向相反的一格(同一晚,`CLUSTER`):
**在【有權限】的世界也會失敗** ⇒ 只看「有沒有炸」會**假綠**。
⇒ 選一個動作當探針之前,**兩個世界都要跑一次看它印什麼**,不要只跑「應該失敗」那邊。

## 三輪對抗審查,三次「我以為我驗過了」—— 而我每一輪都是全綠才交出去的

`#628` 一支 migration 跑了三輪 codex 對抗審查(R3 換模型 + 換角度),**每輪都 FAIL**,共 13 條 must-fix。
🔴 **重點不是有 13 條,是【每一輪打掉的都是我的「證據」本身,不是我的「結論」】。**

```
R1  我寫「重跑本支可當漂移探針」
    ⇒ 假的。REVOKE 排在斷言【前面】⇒ 重跑時它會【先把漂移修掉】再宣告乾淨
    ⇒ 🔴 不但抓不到漂移，還會【無聲吃掉】它 —— 跑完的人會覺得「全綠 = 一直很乾淨」

R2  我寫「攻擊鏈已重現」（附了實測輸出）
    ⇒ 假證據。`SET ROLE` 的授權是拿 **session_user** 驗的，不是 current_user
    ⇒ 我從 postgres 連線 `SET LOCAL ROLE anon` 之後再 `SET ROLE pg_maintain`，
       【不管 anon 有沒有那個權限都會成功】
    ⇒ 改用 `SET SESSION AUTHORIZATION` 重量 ⇒ 攻擊鏈【確實成立】
    🔴 結論不變，證據換過。**而我原本那份證據什麼也沒證明。**

R3  我寫「§0 排在 REVOKE 前面，重跑時就能偵測漂移」
    ⇒ `supabase db push` 只跑【還沒套用】的 migration ⇒ 這支成功之後【不會再被執行】
    ⇒ 那個「之後重跑」在正常流程裡根本不會發生 ⇒ 機制層不存在
    ⇒ 改成外部可重跑的 `./scripts/628-verify.sh drift`
```

### 共同形狀(這句是本則的全部)

> 🔴 **我每一輪都是「自己跑完全綠才交出去」,而每一輪都被抓到【量具本身量錯東西】。**
> **全綠是我的檢查通過了,不是世界是對的。**

### 兩個可操作的東西

1. **R3 的價值來自「換角度」不是「再審一次」。**
   R1/R2 都在問「這個守門擋不擋得住」;R3 被明確要求改問**框架層**
   (假設審查 / apply 當天的可用性 / 修法回歸風險 / 測試假綠)
   ⇒ 它抓到的是**部署機制**問題,前兩輪的框架裡看不到那個東西。
   ⚠️ 對應常載 §5「第 3 輪起必須換角度、換模型」——**換模型而不換角度,會在同一層打轉。**

2. **「附了實測輸出」不等於「證據成立」。**
   R2 那條我附了完整輸出、看起來無懈可擊,而**量測方法本身是錯的**。
   ⇒ 判別句:**我這個量測,在「結論為真」與「結論為假」兩個世界,會印不同的東西嗎?**
     R2 那發的答案是「不會」—— session_user 是 superuser,它在兩個世界都印 OK。

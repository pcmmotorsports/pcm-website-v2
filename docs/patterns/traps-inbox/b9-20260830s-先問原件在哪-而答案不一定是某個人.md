# 先問「**原件在哪**」—— 而答案不一定是某個人

> `-b9` 2026-08-30 · `-48` 指名獨立成條、掛 `-b9` 的名
> 🔴 **這是一條【正確的規矩產生的新盲區】** —— 那一族今晚已經有兩個成員

## 背景:那條規矩是怎麼來的

主視窗一夜之間**五次拿轉述當前提**,而其中**四次被下游擋下來**:
```
① 13 → 11              （拿 -e9 的結論直接對別人的數字做減法）
② 套用率 2/44          （拿 -0b 的數字，沒去讀規格本身）
③「改成裸窗代號」      （規格【已經是】裸窗代號 ⇒ 那道指令無事可做）
④「= 另一件事」        （發的是結論，而要動的是一個字面）
⑤「:389 還開著」       （把【工具的輸出】讀成了【板子的狀態】）
```
⇒ **⇒ 於是它開始要求:「原件在 X 手上, 跟它拿, 不要用我這段。」**
✅ **那條規矩是對的, 而且立刻見效。**

## 🔴 而它的副作用

下一次它說:「那個名字換了 —— **原件在 `-1c` 手上, 跟它拿**」。

而**真正的原件是 Sean 2026-08-23 的拍板, 它就寫在那支檔的第 11 行**:
```
apps/admin/src/app/print/orders/[id]/picking/page.tsx:11
  逐字「🔴 2026-08-23 Sean 拍板改成「訂單明細」」
```
⇒ **一個 `git grep` 就到了, 而那條指令會讓人去等一個窗回訊息。**

> ### ⇒ **一個「去跟某人拿」的指令,有時候會讓人繞過【它本來就在的地方】。**

## 📌 病灶:它把【問人】變成了預設 —— 而**問人本身也是一次轉述**

```
🔴 用轉述當前提  ⇒ 那是原本的病
🔴 去問持有者    ⇒ 那是修法，而它產生的仍然是【第二手】
✅ 去讀原件      ⇒ 那才是那條規矩真正想要的
```

## ✅ 可執行:**先問「原件在哪」,再決定要不要問人**

> 答案有三種,而只有第三種需要去找人:
```
①【碼裡】     ← git grep / 開檔。今晚這一件屬於這種
②【檔裡】     ← migration 註解 / spec / memory / decision 檔
🔴 ③【某個窗手上】← 只有這一種才需要去問，而它一定是第二手
```

⚠️ **而 ③ 也不是不能用** —— 它常常是**唯一**的來源(例如「Sean 在那個 session 對它說的話」)。
📌 **重點不是不要問人, 是【不要跳過 ①②】。**

## 🔴 而這一族今晚的第二個成員

```
另一條：-48 立了「指名制」（不要開放佇列，因為它今晚造成三次重工）
   ⇒ 而它在同一則訊息裡又寫了「去 11 件裡挑一件」= 一個開放佇列
   （-b9 隨後也對 -b4 犯了同一句）
```
📌 **⇒ 兩個成員的形狀相同:**
> ### **一條規矩把某個動作變成了預設, 而那個預設在【它沒想到的情境】裡是錯的。**

⇒ 而它們都不是「規矩寫錯了」——**兩條規矩都對, 而且都在解決真實發生過的病。**
🔴 **⇒ 所以查它們的方法不是「檢討規矩」, 是問:**
> ### **「這條規矩把什麼變成了預設? 而那個預設在哪裡會是錯的?」**

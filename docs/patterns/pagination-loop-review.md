## 五條

### 1. 頁大小 **<** max-rows

`PAGE_SIZE` 必須**嚴格小於**伺服器 `db-max-rows`,否則「短頁 = 末頁」這個判準**零判別力**
—— **伺服器砍出來的頁,和真正的末頁,長得一模一樣。**
**零餘裕(`PAGE_SIZE == max-rows`)= 現在能動、伺服器一調就死。**

    實例  packages/adapters/src/supabase/helpers/product-query-support.ts:56
          const PAGE_SIZE = 1000;   ← 對上 db-max-rows 1000 ⇒ 零餘裕（自知，註解有記）
    ✅ 2026-08-17 I 窗搬檔時重核：行號與字面皆命中

📎 `db-max-rows` 本身是**一個 dashboard 上點一下就能改的專案設定**,
而且**這個 repo 裡有兩顆、分屬兩個 Supabase 專案** ⇒ 見 `docs/reference/environment-values-and-what-stands-on-them.md`。

### 2. `range` 兩端**皆含**

PostgREST `.range(from, to)` 是**含 `to`** 的閉區間 ⇒ **`from + PAGE_SIZE - 1` 才是對的**。
寫成 `from + PAGE_SIZE` 會**頁間重疊一列** —— 去重之後看不見,
**而一旦第 5 條同時壞掉,它就變成靜默丟一列。**

### 3. 中途失敗要 **throw**

任一頁失敗必須讓**整個迴圈失敗**(throw),**不得 `break` / `continue`**。
🔴 **`break` 會把「第 3 頁掛了」變成「總共只有 3 頁」** —— **形狀與正常結束完全相同。**

    實例  scripts/rpm-fetch.ts:127
          throw new Error(`fetchPage@${from} 重試 MAX_RETRY 次仍失敗…`)   ← 重試耗盡就 throw，對
    ✅ 2026-08-17 I 窗搬檔時重核：行號與字面皆命中

### 4. `count` **不當**終止判準

先 `count` 再翻頁 = **TOCTOU** —— 翻頁期間資料增刪,`count` 就過期了;
「翻到 `count / PAGE_SIZE` 頁就停」會**多讀或漏讀**。
⇒ **終止只認「本頁短了」或「本頁空了」,不認事前 `count`。**

### 5. 排序帶**唯一鍵**

分頁排序鍵不唯一 ⇒ **頁界上同值列的順序不穩定** ⇒ 跨頁重複或漏列,
**而且每次執行還不一樣。** `.order('id')`,或複合鍵尾端補一個唯一欄,才成立。

四個字面 2026-08-17 當場重核,全部命中:

    :419  const PRINT_ORDER_ITEMS_PAGE_SIZE = 200;      ← 200 < 1000，有餘裕
    :950  if (batch.length === 0)                        ← 🔴 終止只認【空頁】，不認「短頁」

**它為什麼比五條高一級:**

```
「短頁 = 末頁」型   要靠第 1 條（頁大小嚴格小於 max-rows）才成立
                   ⇒ 伺服器一調小，它就把「被砍的頁」當成末頁
空頁終止 + 實得游標  根本【不需要分辨】被砍的頁與真末頁
                   ⇒ max-rows 調小它【不截斷】，只是多翻幾頁
```

🔴 **所以 `#603` 那句「砍過的頁與真末頁沒有任何辦法分辨」——**
**對短頁迴圈為真,對這個範本【不適用】**;而這是修 `#603` 時**第三個、也最便宜的**修法選項
(不用上 keyset 分頁,照抄 repo 內現成的範本就好)。

⚠️ **範本自己也帶著一條沒解的**:撞 `MAX_PAGES` 時它 throw,而 `fetchAllPaginated`
(`product-query-support.ts`)撞頂是 `console.warn` + **回已撈到的部分**。
範本那支的註解逐字寫著「`console.warn` 在 server component 裡沒有人會看到 —— 那等於靜默截斷」。
⇒ **兩者矛盾,而範本是晚寫的那個 = 教訓版。** 現值 50 頁 × 1000 = 5 萬件,今天撞不到;
**目錄長大那天,`warn` 版會靜默。** 修法照抄範本、不需設計(`V-034` §2-2,已裁進 backlog)。

## 五條

### 1. 頁大小 **<** max-rows

`PAGE_SIZE` 必須**嚴格小於**伺服器 `db-max-rows`,否則「短頁 = 末頁」這個判準**零判別力**
—— **伺服器砍出來的頁,和真正的末頁,長得一模一樣。**
**零餘裕(`PAGE_SIZE == max-rows`)= 現在能動、伺服器一調就死。**

    實例  packages/adapters/src/supabase/helpers/product-query-support.ts:56
          const PAGE_SIZE = 1000;   ← 對上 db-max-rows 1000 ⇒ 零餘裕（自知，註解有記）
    ✅ 2026-08-17 I 窗搬檔時重核：行號與字面皆命中

📎 `db-max-rows` 本身是**一個 dashboard 上點一下就能改的專案設定**,
而且**這個 repo 裡有兩顆、分屬兩個 Supabase 專案** ⇒ 見 `docs/reference/environment-values-and-what-stands-on-them.md`。

### 2. `range` 兩端**皆含**

PostgREST `.range(from, to)` 是**含 `to`** 的閉區間 ⇒ **`from + PAGE_SIZE - 1` 才是對的**。
寫成 `from + PAGE_SIZE` 會**頁間重疊一列** —— 去重之後看不見,
**而一旦第 5 條同時壞掉,它就變成靜默丟一列。**

### 3. 中途失敗要 **throw**

任一頁失敗必須讓**整個迴圈失敗**(throw),**不得 `break` / `continue`**。
🔴 **`break` 會把「第 3 頁掛了」變成「總共只有 3 頁」** —— **形狀與正常結束完全相同。**

    實例  scripts/rpm-fetch.ts:127
          throw new Error(`fetchPage@${from} 重試 MAX_RETRY 次仍失敗…`)   ← 重試耗盡就 throw，對
    ✅ 2026-08-17 I 窗搬檔時重核：行號與字面皆命中

### 4. `count` **不當**終止判準

先 `count` 再翻頁 = **TOCTOU** —— 翻頁期間資料增刪,`count` 就過期了;
「翻到 `count / PAGE_SIZE` 頁就停」會**多讀或漏讀**。
⇒ **終止只認「本頁短了」或「本頁空了」,不認事前 `count`。**

### 5. 排序帶**唯一鍵**

分頁排序鍵不唯一 ⇒ **頁界上同值列的順序不穩定** ⇒ 跨頁重複或漏列,
**而且每次執行還不一樣。** `.order('id')`,或複合鍵尾端補一個唯一欄,才成立。

## 🔴 第 6 條(後補,2026-08-18):`.range()` **只在「集合在翻頁期間不變」時成立**

> **來源不是 `V-029`。** 是 B 窗 2026-08-18 做 `D2`-A 時**真的寫錯、被 codex R3 抓到**。
> ⇒ 證據等級 = **一次實錘**,不是轉錄。

**判別句(抄任何翻頁迴圈之前先問這一句):**

> 🔴 **我要翻的那張表,在我翻的時候會不會被寫?**

```
會不會被寫       ⇒ 去數它的 writer，不要憑印象
不會被寫（集合固定）⇒ OFFSET（.range()）安全
會被寫            ⇒ OFFSET 位移之後【會跳過還沒讀到的列】⇒ 必須 keyset（.gt('id', 游標)）
```

**為什麼 OFFSET 在會動的集合上會漏列**:`.range(200, 399)` 要的是「第 201～400 個**位置**」。
若第 1 頁讀完之後,前面有一列被刪(或因作廢而退出結果集),它後面的列**各往前移一格**
⇒ 原本排在第 201 位的那一列變成第 200 位 ⇒ **第 2 頁從第 201 位開始讀,它就被跳過了。**
(這是 SQL `OFFSET` 的定義,不是量出來的觀察;上面那個 201/200 是**舉例的數字**。)

🔴 **而 `Map` 去重救不了它** —— 去重處理的是「同一列出現兩次」,
漏列是「**有一列一次都沒出現**」。**兩者不是同一件事,而去重讓人以為兩者都處理了。**

**實錘(2026-08-18)**:

    抄的範本  SupabaseOrderAdapter.listOrderItemsForPrint   ← 用 .range()，而它是對的
    抄去哪    listAssignedQuantitiesByOrderItemIds
              (apps/admin/src/lib/shipping/shipment-repository.ts)
    為什麼錯  範本翻的是 order_items —— 建單之後不再新增/刪除（那支 docstring 逐支數過 migration）
              我翻的是 shipment_items —— 建箱會新增、作廢會讓列退出結果集
              (writer 就在同一支檔上面：createShipment / addShipmentItems /
               markShipmentShipped / voidShipment / unvoidShipment 五支)
    修法      改 keyset：.order('id') + .gt('id', 上一頁最後一列的 id)
    ⚠️ 殘餘   id 是 uuid（非遞增）⇒ 翻頁中途插入的列若排在游標之前，這一輪仍讀不到。
              keyset 消掉的是【位移漂移】，不是【並發插入】。要後者得上快照/交易。

### 🔴🔴 而這一條真正的母題比分頁大 —— 它值得單獨記住

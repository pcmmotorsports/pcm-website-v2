## §1 🔴 第一站:登入 —— **我進不去,而這是分類②/③ 之外的第四種**

### 量到的(唯讀 GET,不帶任何 cookie,2026-08-19)
```
curl -s -o /dev/null -w '%{http_code} → %{redirect_url}'
  https://admin.pcmmotorsports.com/           ⇒ 303 → /api/sso/start?next=%2F
  https://admin.pcmmotorsports.com/orders     ⇒ 303 → /api/sso/start?next=%2Forders
  https://admin.pcmmotorsports.com/api/sso/start?next=%2Forders
                                              ⇒ 302 → https://quote.pcmmotorsports.com/api/sso/authorize?state=<32hex>
  https://quote.pcmmotorsports.com/api/sso/authorize?state=probe
                                              ⇒ 🔴 401
```

### ⇒ 這條鏈的意思(而它是「員工的一天」的第 0 站)
```
要進 admin ⇒ 必須【先登入報價單站】⇒ 而報價單站要密碼(+ 可能 TOTP)
⇒ 🔴 我沒有那個密碼,而我【不會要】也【不會用】他的
   (密碼貼進對話就是一次洩漏;`.env` 一律不碰 —— 那條界線不因為有授權而移動)
```
🔴 **所以「你們去測試吧」這句授權,缺的不是許可,是【機制】** ——
**他授權了測試,而登入這一關在設計上只有他過得去。**

### ✅ 而這一站本身就是三個 finding(不是「卡住了」)

**finding-1 · 今天沒有「員工帳號」這回事**
員工要進後台 = **先用報價單站的密碼登入**。而那是**共用密碼**(我在 B3 那條線實查過:
報價單側今天沒有具名登入,`login/route.ts` 的四個簽發點一律 `{kind:'fallback'}`)。
⇒ **凡進得了報價單後台的人,就進得了網站後台。** 這正是 E8-B/B2 要解的那件,**而現在它是線上事實**。

**finding-2 · 我靜態讀出來的 deny 行為,線上證實了**
報價單的 `middleware.ts:46-49` `deny()`:`/api/` ⇒ 401、其餘 ⇒ 302 到 `/`。
線上 `authorize` 回 **401**(不是導去登入頁)⇒ **與那段 code 逐字相符**。
📎 那是我先前只有「讀全檔逐行推」的一格,**現在有線上證據**(而它證的是報價單側,不是 admin 側)。

**finding-3 · 而登入牆本身是【健康的】**
未登入 ⇒ 303/302/401,**沒有任何一頁在未登入時漏出內容**。這一格是正面結果,要記。

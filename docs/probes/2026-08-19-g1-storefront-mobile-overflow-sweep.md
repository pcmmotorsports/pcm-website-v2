# 顧客站手機版橫向溢出掃描 —— 2026-08-19 02:5x CST

> 起因:Sean 2026-08-19 自己撞到「手機開商品頁可以滑到右邊」(說明書名字太長),已修並上線(`af32420b`)。
> 🔴 **而那一個是他撞到的,不是我們掃到的** ⇒ 本輪去掃「還有沒有沒被撞到的」。
> 工具:**repo 自己的** `scripts/storefront-probe/overflow-ruler.mjs`(整份注入頁面,沒有自寫平行尺)。
> 全程**唯讀 GET**,沒有下單、沒有按付款、沒有任何寫入。

## ① 結論:**掃到的範圍內,零溢出**
```
量測發數      74 支 URL × 2 個視寬 = **148 發**
錯誤          0
selfCheck.ok  **148 / 148 全部 true**（含 probeSeen ⇒ 每一發都證明尺是活的）
有溢出的      **0**
```
🔴 **「零」不是「沒量到」** —— 這把尺每一發都會**當場塞一個必定溢出的探針**進去,
探針沒被看到就判 `selfCheck.ok=false` 並作廢。**148 發全部看見了探針。**

## ② 分母(講清楚哪一半是全集、哪一半是取樣)
```
sitemap.xml 實抓 ⇒ HTTP 200 / 2,797,971 bytes / **19,805 個 URL**
  /products/*  19,782
  /brands/*        20
  /brands / /products / 首頁  各 1

【全集】非商品頁 **23 支**（sitemap 裡的全部非商品 URL）
【全集外補】robots 擋住但客人看得到的 5 支:/cart /login /register /account /checkout
【取樣】商品頁 **46 / 19,782 ≈ 0.23%**
        取法可重跑:依 slug 前綴分 16 個品牌，每個品牌 random.sample(…, min(3,n))，seed=20260819
```
🔴 **商品頁那半是【取樣】不是全集。** 0.23% 的樣本抓不到「只有某幾支商品才有的長字串」——
而 Sean 撞到的那一個**正是那種**。⇒ **本輪的零溢出對商品頁只是【下界】。**

## 🔴 ③ 兩支我以為量了、實際沒量到
```
/account   ⇒ 實際落在 /login（status 200）
/checkout  ⇒ 實際落在 /login（status 200）
```
⇒ **會員中心與結帳頁需要登入,本輪沒有量到它們。** 它們是客人動線上最重要的兩頁之一。
⚠️ **如果只看「74 支全綠」,會以為結帳頁掃過了。沒有。**

## ④ 這把尺看不到的東西(它自己的設計,不是壞掉)
```
被當成【橫向捲動容器內】而排除的元素:每發 最小 0 / 中位 **141** / 最大 176
```
⇒ 輪播、品牌卡橫向清單那些**本來就該超出視窗**,尺照設計排除它們。
🔴 **代價**:如果某個輪播**自己**的尺寸算錯了,**本輪掃不到。**
⚠️ 另外照 ruler 檔頭的已知盲點:它**看不到 `opacity: 0`** ⇒「看得見」這件事它答不準(本輪沒有用它答那個問題)。


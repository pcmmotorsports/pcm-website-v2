# 13-1 查單:「要記得勾那個開關」量成具體的

```
預設 /orders            ⇒ 共 10 筆,分頁列逐字「第 1–10 筆 / 共 10 筆(第 1／1 頁)」
加 ?show_unpaid_card=1  ⇒ 共 18 筆

## 那一頁上有沒有東西會讓他【想到】要去勾?
```
掃「找不到單 / 預設不顯示 / 還有…未顯示 / 部分訂單 / 子集」這五種說法 ⇒ **全頁 false**
⇒ 唯一提到這件事的,是那個勾選框自己的標籤:**「顯示刷卡未付款(預設隱藏)」**
```
🔴 **而真正的問題不是「沒有提示」,是【頁面自己在說相反的話】**:
```
分頁列逐字「第 1–10 筆 / **共 10 筆**(第 **1／1** 頁)」
⇒ 「1/1 頁」「共 10 筆」這兩個字面**主動宣告「這就是全部」** ——
   而它旁邊那個勾選框說「預設隱藏」。**兩者同時出現在同一個畫面上。**
⇒ 員工不會去勾一個他不知道自己需要的開關,**因為畫面剛剛才告訴他他看完了。**
```
📌 **這比「缺一個提示」嚴重一級**:缺提示是**沒說**;這是**說了一句會被誤讀成完整的話**。
⇒ 而**最小的修法不必動預設**:把「共 10 筆」旁邊補一句「(另有 N 筆刷卡未付款未顯示)」即可。
   ⚠️ 這是我的建議,**要 Sean 拍**(那個預設是他要的,見 `order-list-view.ts:66-72`)。

## 🔴 而真的走進去之後,撞到一個【比慢嚴重得多】的:**後台自己自相矛盾**

```

🔴 **列表說 2 筆,明細說沒有。同一個後台、同一個客戶、差一次點擊。**

**成因是已知的**(`#278`,而我今晚在正式資料上把它證出來了):
```

⇒ 它帶著那道 .neq('payment_status','unpaid')
   (packages/adapters/src/supabase/SupabaseOrderAdapter.ts:582)
⇒ 我那兩張孤兒單是 unpaid ⇒ 明細把它們濾掉了,而列表的計數沒有
```
⇒ **對 13-7 的意義**:客人打來說「給我看你們有我哪些資料」,
**員工照著明細頁念,會跟他說「你沒有訂單」** —— 而那是**假的**,列表上就寫著 2 筆。
⇒ 🔴 **這不是「慢」,這是【會講錯話】。** 13-7 那一格要從 ⚠️ 改成 🔴。

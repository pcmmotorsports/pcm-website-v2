# 13-9 「我要改發票抬頭 / 加統編」⇒ 🔴 **做不到**

## 那個欄位在哪
```
orders.invoice 是一個 jsonb,白名單五個鍵(migration 逐字):
  supabase/migrations/20260604120000_m3_s2a_orders_order_items.sql:106 / :122 / :136
  ⇒ type(personal/company/donate) / carrier / **title** / **taxId** / donateCode
⇒ 「抬頭」與「統編」就住在這裡
```

## 而後台改得了哪幾欄 —— **不含它**
```
「編輯訂單」那個表單 → updateOrderWorkflowAction
  (apps/admin/src/components/orders/order-edit-form.tsx:2 / :38)
→ updateAdminOrderWorkflow(packages/adapters/src/supabase/SupabaseOrderAdapter.ts:1085-1106)
🔴 而它逐欄只映射【四個】:
     shipping_method / invoice_number / invoice_amount / invoice_status
⇒ **`invoice` 那個 jsonb 一個鍵都不在裡面。**
```
🔴 **所以:發票號碼改得了、開票狀態改得了、金額改得了 —— 而【抬頭與統編】改不了。**

## 而畫面上有沒有告訴他?
```
後台看得到那些值(customer-detail-sections.tsx:127-131 會顯示「載具 …」「… 統編 …」)
⇒ **看得到、改不了,而畫面上沒有一個字說明為什麼**
⇒ 與 13-3(改地址)同款,而**這一格更常發生** —— 客人結帳時忘了填統編是很普通的事
```
**分類:🔴 做不到 + 沒有說明。**

# 🔴🔴 13-10 「我的貨到哪了?」⇒ **員工答得出來,而客人【永遠看不到】**

## 員工這一側:✅ 看得到
```
apps/admin/src/components/orders/shipment-section.tsx:137 逐字:
  單號 {shipment.trackingNumber ?? '—'}
⇒ 有包裹的話,貨運單號就在訂單頁上,員工唸得出來
```

## 🔴 而客人那一側:**不管貨到哪了,他看到的都是「處理中」**
```
apps/storefront/src/lib/orders/order-display.ts:54-68
export function orderStatusLabel(payment: PaymentStatus, _fulfillment: FulfillmentStatus): string
                                                          ↑ 🔴 **底線開頭 = 刻意不使用**
  switch (payment) {
    case 'paid': return '處理中';     ← **已付款的單,一律「處理中」**
    …
  }
```
**而檔頭自己寫了為什麼**(同檔 `:21-22` 逐字):
```
`fulfillment_status` 是 **stale 出貨軸**(admin 端已停止維護、顯示端 A9e 下架)
⇒ 第 1 批 paid 一律固定「處理中」、**不再讀出貨軸**
```
⇒ 🔴 **所以客人的訂單頁上,「已出貨」這件事【不存在】。**
```
他付了錢 ⇒ 看到「處理中」
貨出了   ⇒ 還是「處理中」
貨到了   ⇒ 還是「處理中」
⇒ 他要知道貨到哪了,**只有一條路:打電話問**
```

## 而這一格為什麼值得單獨標
```
· 資訊【是有的】—— 員工看得到單號
· 客人【拿不到】—— 而且不是「藏起來」,是那一欄根本沒有被讀
· ⇒ 🔴 **這是一個【會自己製造客服工作量】的缺口**:
     每一張出貨的單,都是一通「我的貨到哪了」的潛在電話
· 而它與 #659 是**同一個形狀的兩端**:
     #659   系統知道有這張單,而客人看不到
     13-10  系統知道貨出了,而客人看不到
  ⇒ **兩件都是「我們知道,而他不知道」。**
```
⚠️ **而它是刻意的,不是壞掉** —— 檔頭寫著出貨軸「已停止維護、顯示端下架」。
⇒ 所以這不是 bug 單,是**一個被關掉的功能**,而**沒有人把它列進「客人看不到什麼」的清單**。

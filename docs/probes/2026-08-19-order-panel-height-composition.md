> ## 🔴 **本檔的結論是【不再做下一片收合】。** 一個「量完決定不動」的紀錄與一片同價 —— 它擋住下一個人再量一次。

## 🔴 為什麼不做下一片

**1. 最高的那一區(62%)是【資料】,不是表單。**
商品區 2,281 px 幾乎全是 Sean 逐字要求「**看得完整**」的東西。
⇒ **壓它 = 把他要看的東西藏起來。** 那與片17 相反:片17 收的是**沒有人要求要看的空表單**。

**2. 唯一「每天要用」的那份表單,已經是收著的。**
收款(15 欄、187 px)**已經在 `<details>` 裡**。⇒ 原本擔心的「為了省高度而讓員工每天多點幾下」**不存在**。

**3. 剩下兩份攤開的表單加起來只有 13%,而收掉它們要付一次點擊。**
```
編輯訂單 242 + 新增備註 240 = 482 px = 0.5 個螢幕
⇒ 4.1 螢幕 → 3.6 螢幕
```
- **新增備註**:寫聯絡紀錄用的 —— **頻率未知,而它是「員工的一天」裡可能天天做的事**。⚠️ **我沒有量過頻率,那要問 Sean 或看實際使用。**
- **編輯訂單**:改發票欄。確認稿 `:466-470` 逐字記著「已取消/已退款/已出貨的單,這四欄**照樣可以改**」——**因為單沒了之後還要處理發票**。收起來會讓那條救濟路徑多一層。

⇒ **0.5 個螢幕,換兩個都可能是高頻的動作各多一次點擊。判定:不划算,不做。**

## 🔴 而目標本身要校準(主視窗 2026-08-19 自陳)
```
Sean 逐字   「看得完整，但佔高度」   ⇒ 他要的是【看得到】，而他【明說接受高度】
⇒ 我們在做的是「不犧牲看得到的前提下順便省高度」，不是「把高度壓到最低」
🔴 「壓回 2-3 螢幕」那個數字是主視窗編的，Sean 沒說過。
⇒ **目標是他那句話，不是那個數字。**
```

## 判別句(給下一個想壓高度的人)
```
① 這一區是【資料】還是【表單】？資料不壓。
② 若是表單：這個表單【多久被填一次】？
   偶爾（一張單一次）⇒ 可以收   每天 ⇒ 不收，即使它很高
   🔴 不是「填 vs 看」——那條規則漏了頻率這個維度（主視窗 2026-08-19 自我修正）
③ 省下的 px 換來的是幾次點擊？**版面的成本量得到，人的成本量不到** ⇒ 傾向不動。
```

## ⚠️ 沒量到的(明列,不是遺漏)
- **正式站真實訂單的品項筆數分佈** —— 12 項是我造的。若常見是 1-3 項,整份分析的權重要重算。
- **新增備註的實際使用頻率** —— 我用「可能天天」當保守假設,**那是假設不是量測**。
- **手機版(430)** —— 完全沒量。
- **一次只開一張卡 vs 可多張** —— 那題仍在(`W1-067` 檔頭),而本檔的結論讓它更不急:**現在 4.1 螢幕,而他接受高度。**

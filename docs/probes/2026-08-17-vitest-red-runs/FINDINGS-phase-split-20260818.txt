2. 這把尺有沒有判別力(雙向表演,做過)
────────────────────────────────────────────────────────────────────────
拋棄式測試檔,同一支跑兩發,只有測試本體被人為墊慢 2000ms:

  不墊       Duration 176ms  (transform 17ms, import 26ms, tests 2ms,    environment 0ms)
  墊 2000ms  Duration 2.20s  (transform 18ms, import 27ms, tests 2.02s,  environment 0ms)

⇒ 只有 tests 那一格動(+約 2000ms),transform / import 沒跟著動。
⇒ 分段之間是分得開的,不是同一個數字換四種寫法。
(該拋棄式檔跑完即刪,兩個路徑都驗過不存在。)

────────────────────────────────────────────────────────────────────────
3. 拿它去量那發 5030ms(order-keyword-search-wiring.test.tsx)
────────────────────────────────────────────────────────────────────────
同一支測試檔、同一台機器、同一晚:

  ┌ 那一發(格1 5030ms 逾時 + 格2 讀到「2 次」)
  │   Duration 12.73s (transform 6.43s, setup 0ms, import 3.38s, tests 5.98s, environment 2.25s)
  │
  ├ 之後重跑(綠)
  │   Duration  1.78s (transform  635ms, import 339ms, tests  674ms, environment 493ms)
  │   Duration  3.38s (transform 1.36s,  import 591ms, tests 1.60s,  environment 945ms)
  │
  └ 清掉 node_modules/.vite 之後(綠)
      Duration  1.36s (transform  413ms, import 273ms, tests  525ms, environment 381ms)

⇒ 【量到的】那一發的 transform 是綠發的 5-15 倍(6.43s vs 413ms-1.36s),
   import 也是 6-12 倍(3.38s vs 273-591ms)。transform+import = 9.81s / 12.73s。
   時間確實花在【模組載入】那一側,不是測試本體的邏輯。

4. 🔴 但這【不】等於「冷編譯是主因」—— 那個假說仍然是死的
────────────────────────────────────────────────────────────────────────
清掉 node_modules/.vite 的那一發,transform 只有 413ms(上表第四列)。
⇒ 清快取【不會】把 transform 變慢 ⇒ 那 6.43s 不是「快取冷」造成的。

比較可能的是機器負載,而這一條【我沒有量到,是推的】:
  · 23:44 我自己跑完 build,uptime = load averages 213.11 / 187.60 / 125.66
  · 23:46 uptime = 42.23 / 132.41 / 112.01
  · 那發紅發生在 00:0x,機器仍在從那個尖峰衰減
⚠️ 我【沒有】在那發紅的當下量 load ⇒ 上面是時間軸吻合,不是因果。
   要證它,需要在跑測試的同時取樣瞬時 CPU —— 那正是 T-007 §③ 指出而刻意沒做的那一項。

────────────────────────────────────────────────────────────────────────
5. 這把尺的射程(先寫在這裡,免得數字被當成比它能講的更多)
────────────────────────────────────────────────────────────────────────
· 頁尾是【整發 run 的總和】,不是單格。它答得出「這一發的時間花在哪一類」,
  答【不出】「哪一格的 5030ms 花在哪」。本例能用,是因為該檔只有一個大的冷 import 主導。
· 要真的做到 per-test 分段,得在測試碼裡插樁(performance.now() 夾 import / exec / render)。
  我寫過一支這樣的探針,驗證頁尾夠用之後把它刪了 —— 需要時照這句重建即可,不必翻歷史。
· 多發之間的比較只在【同一台機器】成立;本批 log 全部來自同一台,跨機不可比。

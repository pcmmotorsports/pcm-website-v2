## 2 為什麼要放進 repo

`logs/` 整個在 `.gitignore:48` ⇒ **原本的四綠 log 一個字都不在 repo 裡**
(數法 `git ls-files logs/ | wc -l` ⇒ 落筆當下 `0`)。
而 `logs/four-greens/*/vitest.log` **只存了尾 60 行**(檔案首行自己寫著「共 N 行」;
數法 `for f in logs/four-greens/*/vitest.log; do head -1 "$f"; done | grep -c '尾 60 行'` ⇒ 落筆當下
`24`,而同一個 glob 的分母 `ls logs/four-greens/*/vitest.log | wc -l` 也是 `24` ⇒ 沒有一支例外),
完整輸出原本在 `/var/folders/.../tmp.XXXX` —— **那是 macOS 會週期清掉的地方**。

⇒ 這 24 支是從那些 tmp 檔搶救出來的。搬進來的當下逐支 `wc -l` 對過各自 log 首行自稱的
「共 N 行」,**24 支對得上、0 支對不上**;並跑過負對照(另造一支首行自稱 594 行、來源只有 3 行的
假靶 ⇒ 比對器印出「自稱 594 實得 3」⇒ 它抓得到,所以那 24 個 ✅ 是量出來的)。

🔴 **搬的是 24 支,不是「紅的那 6 支」**(兩個數的來源:`6` 是 V 窗判斷哪幾發算紅,
`24` 是上面那條 `grep -c` 數出來的被截斷支數)—— **「哪幾支算紅」是判斷,「24 支都被截斷」是事實**;
挑選會少搬,而 `cp` 是零成本的。
📎 副作用是買到了 `F-5` 要的那發綠對照(`9946d24e-20260817T152523`,與同 hash `…152039` 那發紅配成
**同一棵樹的紅綠對照對**)—— 那不是運氣,那正是不挑選買到的東西。

# 四、一個我查完決定**不報成缺陷**的東西(留痕,免得下一個人重查)

商品頁上「已收藏」那顆主按鈕,在**剛進頁面沒有捲動時**:
```
它的 rect top=787 / height=46(⇒ 787–833),而視窗高 844
elementFromPoint(它的中心) ⇒ **button.pd-mbb-cart**(手機底部固定購物列)
⇒ 看起來像「底部列蓋住收藏鈕,客人會按到加入購物車」
```
**而我把它查完了,結論是【不是缺陷】**:
```
· 那條底部列 .pd-mobile-buybar 是 position: fixed,top 777 / height 67 ⇒ 蓋住最下面 67px
· 而頁面【有補償】:main 的 padding-bottom = 96px、body 的 padding-bottom = 70px
  ⇒ 內容不會被永久壓在底下
· 實測:把收藏鈕捲到畫面中間(top 399)⇒ elementFromPoint 命中 span.pd-like-label,
  `命中自己: true` ⇒ **按得到**
⇒ 那個覆蓋是【捲動過程中的暫態】,固定底部列本來就會這樣,而版面已經留了空間
```
🔴 **記在這裡的理由**:那一發的中間輸出(「中心點上是 pd-mbb-cart」)**讀起來就是一個 bug**,
而它是**捲動位置造成的**。下一個人若只跑那一發、不看 padding 與捲動後的複量,**會報一個假的**。
(這是我今晚第二次在同一類事情上差點誤報 —— 第一次是 hover。**兩次的共同點:量到的那一瞬間不是客人會遇到的那一瞬間。**)

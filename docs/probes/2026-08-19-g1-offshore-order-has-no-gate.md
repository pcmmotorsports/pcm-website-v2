# 🔴 ① 而系統的**每一層**都不知道地址在哪裡

```
地址的資料形狀 —— **單一自由文字欄，零結構**
  packages/domain/src/identity/address.ts:30
    line: string; // 地址(縣市 / 區 / 路 / 號 / 樓)
  apps/storefront/src/components/account/InlineAddressForm.tsx:200
    placeholder="縣市 / 區 / 路 / 號 / 樓"
  ⇒ **整支表單零 `<select>`、零縣市欄、零郵遞區號**
    （量法：grep '<select\|<option\|zip\|postal' 該檔 ⇒ 只命中那一行 placeholder）

運費 —— **零地區維度**
  packages/domain/src/order/shipping.ts:14-16 逐字：
    store（自取）→ 0；home（宅配）→ subtotal >= 5000 ? 0 : 100
  而權威在 RPC：`20260719120000_…:459`
    v_shipping_fee := CASE WHEN v_subtotal >= 5000 THEN 0 ELSE 100 END;
  ⇒ **一張澎湖的單付的運費與台北完全相同。**

配送方式 —— **只有一個選項**
  CheckoutStep1.tsx:191-198 的 `.co-ship-grid` 內只有一個 `<label className="co-ship is-on">`
  文案「貨運宅配」⇒ **沒有自取可選**，離島客人只有這一條路。
```

⇒ 🔴 **結論:一張離島訂單可以下、可以刷、可以進 `orders` 表,
而從表單、domain、RPC 到運費,沒有任何一層看得出它是離島單。**
唯一會發現的是**員工用肉眼讀那個地址欄**。

# 🔴🔴 ② 而「另議」在今天**沒有可以執行的動作**

契約寫的是「離島與海外**另議**」。而真的碰到一張離島單時,員工手上有什麼?

```
· 加收運費？ ⇒ **做不到。** 改品項金額那支 RPC 有一道收款閘：
    `20260815040000_…:390` 逐字「這張單**已經有收款紀錄**(% 筆)，目前不開放改金額」
    而離島單被發現的時候，客人**已經付過錢了**（那正是它被發現的方式）
    ⇒ 出處與 apply 狀態見 `docs/probes/2026-08-19-g1-exchange-traces.md` §②
· 補一張運費單？ ⇒ **做不到。** 後台沒有手動建單
    （`apps/admin/src/components/shared/admin-form.tsx:12` 逐字「等 E10 手動建單/改單…再做」）
· 那剩下什麼？ ⇒ **退款整單、請客人重下**，或**自己吃掉運費差**。
```

📌 **所以「另議」這兩個字,在系統上對應的動作是空的。**
🔴 而這與換貨那條**是同一個閘**:`已收款 ⇒ 不開放改金額`。
**那道閘本身是誠實的**(它的理由逐字寫著「因為『已收多少』的算法還沒定案」)——
⇒ **不是有人偷懶,是一個未完成的東西擋住了另一個。**

# ③ 而這一條對客人的形狀

```

               `/usr/bin/grep -rn '離島' --include='*.ts' --include='*.tsx' apps/storefront/src | grep -v '\.test\.'`

               `/usr/bin/grep -c '離島' CheckoutStep1.tsx CheckoutStep2.tsx` ⇒ **0 與 0**
```

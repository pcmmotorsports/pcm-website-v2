## 2. 🔴 `19` 號貼板(`20260905210000`)貼了沒 —— 判別法

**這是這條線今天唯一答不出來的問題**,而它決定下一片的成本。
🛑 **唯讀查證那道授權不在施工窗手上** ⇒ 要主視窗或 Sean 跑。

✅ **它有一個【真的】判別式** —— 本支建了一個**新物件**(裸 `CREATE VIEW`,不是 `OR REPLACE`):
```sql
SELECT pg_catalog.to_regclass('public.pcm_manual_no_email_excluded') IS NOT NULL AS 貼過了,
       pg_catalog.to_regclass('public.pcm_order_created_email_pending') IS NOT NULL AS 正對照_應為_t,
       pg_catalog.to_regclass('public.zzz_never_a_view')              IS NOT NULL AS 負對照_應為_f;
```
· `t / t / f` ⇒ **貼過了** · `f / t / f` ⇒ **還沒貼** · 正對照不是 `t` ⇒ **這把尺沒接上, 別讀那個 f**
🔵 **為什麼這一支答得出來**:`CREATE OR REPLACE` 的物件「在不在」**零判別力**(貼之前就在),
而**新物件不一樣** —— 這是本支刻意用裸 `CREATE` 換來的副作用之一。
📌 影響:**沒貼** ⇒ 述詞單一來源那片可以直接改 `210000`(四支 view 只改一次);
**貼了** ⇒ 要開新 migration 再改一次 ⇒ **成本大約兩倍**。

## 5. 🔴 這條線今天學到而值得帶走的三件

1. **「量到了 N」與「那 N 個是哪 N 個」是兩個宣稱。**
   一份抽到**別支 view** 的四套,數量照樣印 4/4/4。⇒ 數量之外要**逐名核**。
2. **一個對的結論會讓人不去查它旁邊那個錯的數字。**
   「剝掉註解後 = 0」是對的,而同一句裡的「12 次」是我用眼睛數的(實際 20)。
   判別句:**這個數字是我【跑出來的】還是我【看出來的】?**
3. **矛盾常常不在事實裡, 在排版裡。**
   codex 說「三套互相矛盾的敘事」,我第一反應是挑一套當假的刪掉 —— 而**真相是兩個不同的競態**,
   我把它們寫成同一組條列。**刪掉的那一句原本是對的。**

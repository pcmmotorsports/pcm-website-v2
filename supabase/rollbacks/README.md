# `supabase/rollbacks/` —— 回退產物住哪、哪一份是權威

> 立於 2026-09-08(線【DB】`-db`,主視窗 A 裁「甲:複製,信箱那份留著」)。

## 這個目錄是什麼

一支 migration 貼下去之後要退回來時,照著跑的那份 SQL。
檔名 **`<14 位版本號>-rollback.sql`**(舊的兩種形狀 `<ver>_down.sql` / `<ver>_<片名>-down.sql` 也還在,
`scripts/rollback-drill.sh` 三種都認得)。

## 🔴 權威在哪(這一節是這份 README 存在的理由)

同一份回退產物**有兩個地方各存一份**:

| 位置 | 它答的是什麼 | 檔名形狀 |
|---|---|---|
| **本目錄(repo)** | **這支 migration 的回頭路是什麼** ← **權威** | `<ver>-rollback.sql` |
| `~/pcm-mailbox/貼板-*/` | **當時是第幾支貼的**(事件現場) | `<NN>r_<ver>_*.sql` |

- 🔴 **repo 這份是權威。** 要改回退邏輯,改這裡。
- 🛑 **不要回頭改信箱那份。** 它的檔名帶著**貼板編號 `NN`** —— 那個編號記錄的是「當時是第幾支貼的」,
  是**事件**不是產物。改了它 = 竄改當時的現場紀錄,而那個編號在 repo 裡沒有意義。

## 🔴 複製要付的代價:兩份會分岔,而**沒有東西在比對它們**

這是明寫的已知缺口,不是疏漏。而**目前它是可以量的** ——

**因為兩邊是逐字複製、沒有加任何檔頭** ⇒ `diff` / `md5` 直接就是漂移偵測器:

```bash
# 逐支比對 repo 與信箱那份(在 repo 根跑)
# 🔬 2026-09-08 當發:比對到 16 對, same 16 / DIFF 0
for f in supabase/rollbacks/*-rollback.sql; do
  v="$(basename "$f")"; v="${v%%-*}"
  m=$(ls ~/pcm-mailbox/貼板-*/[0-9]*r_"${v}"_*.sql 2>/dev/null | head -1)
  [ -n "$m" ] || continue
  cmp -s "$f" "$m" && echo "same $v" || echo "DIFF $v"
done
```

🛑 **⇒ 所以【不要】為了註明來源而在這些檔案頂端加檔頭** —— 加了就再也 `cmp` 不出來,
而「來源說明」與「漂移偵測」兩件事,只有後者是機器做得到的。來源說明住在這份 README 裡就好。

🛑 **而這個偵測器【沒有掛進任何 hook 或 CI】—— 上面那段迴圈是人要自己去跑的。**
📌 **一個要人自己跑的偵測器, 與沒有偵測器, 在「它會不會叫」上是同一件事。**
⇒ 這是明寫的已知缺口。要關掉它, 得把那段迴圈掛進 pre-commit 或 CI, 而那還沒有人做。

🔬 **立此存照(2026-09-08 當發量)**:
- 從信箱複製進來的 **14** 份,逐份 `md5` 與來源相同。
- 在那之前就兩邊都有的 **2** 份(`20260906940000` / `20260906990000`)—— 當發 `diff` ⇒ **逐字相同**、
  bytes 各 `10679` / `5824`。⇒ **至今沒有分岔過。**

## 🛑 還有 **5 份【故意】沒有進來 —— 它們在等 Sean 拍板

```
20260906600000 · 20260907020000 · 20260907030000 · 20260907040000 · 20260907120000
```

它們仍然只住在 `~/pcm-mailbox/貼板-*/`,**那 5 支的綠仍然是「會自己消失的綠」**。

**為什麼不進來**:`scripts/down-script-lock-timeout-gate.py` 判它們
「**有會拿 ACCESS EXCLUSIVE 鎖的語句, 而沒有任何 `lock_timeout` 設定**」⇒ pre-commit 紅。

🔬 **而那個紅是我帶進來的, 不是本來就有的**(量到的):
- 複製之前跑那道閘 ⇒ `rc=0`,分母 8 支、**8 支全過**
- 把 19 份都放進來 ⇒ `rc=1`,分母 15 支、**缺 5 支**
- 只放 14 份 ⇒ `rc=0`,分母 10 支、**10 支全過**

🔴 **而【要不要回頭補 `lock_timeout`】不是我可以拍的板** —— 那正是板列 `⟦db-ROLLBACKLOCKWAIT⟧`
問的那一題(既有檔要不要回溯補),**已經在 Sean 的佇列上**
(`~/pcm-mailbox/端Sean-明早要你動手的-20260908.md` 檔尾「新題 ⑦」)。
⇒ 補 `lock_timeout` 是**改一份災難還原用的 SQL 的行為**,而沒有人驗過改完它還退得回去。
⇒ 📌 **在半夜替他拍那個板, 比讓 5 支繼續住在信箱糟。**

**Sean 答了之後**:
- 若「要補」⇒ 這 5 份補上 `SET LOCAL lock_timeout = '5s';` 再複製進來
  🛑 **而那會讓這 5 份與信箱那份不再逐字相同** ⇒ 上面那段 `cmp` 迴圈對它們會永遠印 `DIFF`
  ⇒ 屆時要在本檔開一節列出「刻意分岔」的清單,否則下一個人會把它讀成漂移。
- 若「不補」⇒ 那道閘要為既有檔開一個明確的例外,而不是讓這 5 份永遠進不來。

## 誰在用這個目錄

`scripts/rollback-drill.sh` 的 `resolve_rollback_sql`,依序找三個位置:
`scripts/<ver>-down.sql` → **本目錄 `<ver>*.sql`** → `~/pcm-mailbox/貼板-*/<NN>r_<ver>_*.sql`。

🔵 **本目錄補了 19 份之後,那 19 支的綠不再依賴信箱** ——
在那之前它們是「**會自己消失的綠**」:換一台機器、或有人清了信箱,同一支就變回 `NO-ROLLBACK`,
而消失的時候不會有人收到通知。

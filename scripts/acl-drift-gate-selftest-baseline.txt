# acl-drift-gate 自檢格數的【地板】—— 板列 ⟦b9-GATESELFEDIT⟧,2026-09-05 主視窗 -f8 派
#
# 🔴🔴 這份檔回答的是【昨天有的格子,今天還在嗎】——
#    它【不】回答「該有的格子都在嗎」。那兩個是不同的問題,而只有第一個有機械答案。
#    ⇒ 「acl-drift-gate 少了一格本來該有的守門」是另一題,本檔從來沒有宣稱過它。
#    (形狀逐字抄 `scripts/husky-pre-push-gate-baseline.txt` 的檔頭 —— 那是本 repo 既有的前例。)
#
# ── 它要治的那個病(板列 ⟦b9-GATESELFEDIT⟧ 的結論)────────────────
#   `scripts/acl-drift-gate.py` 有兩道機制擋著:
#     ① `.husky/acl-drift-gate.sh` 每顆 commit 都跑,而且 fail-closed(檔不見了 ⇒ exit 2)
#     ② `package.json` 的 lint-staged:staged 到那支 `.py` ⇒ 當場跑它的 `--selftest`
#   🛑 **而兩道的共同盲點是:規則與測它的測試住在【同一支檔】** ——
#      同一顆 commit 裡把規則砍掉、把守它的格子一起砍掉,**兩道都不會叫**。
#   ✅ **本檔就是那一格**:格數的【地板】住在**這一支別的檔**裡。
#      ⇒ 要靜靜砍掉格子,現在必須**同時改這一份**,而那個動作在 diff 上有形狀。
#
# ── 🛑 它擋不住什麼(與修法一樣顯眼)────────────────────────────
#   · **不是硬擋。** 同一顆 commit 裡把數字改小,它一樣過 ——
#     ⇒ 📌 它把「靜靜刪掉」變成「**一個數字在 diff 上往下掉**」,那是訊號不是鎖。
#   · 比對的碼住在 `scripts/acl-drift-gate-selftest-floor.sh` ⇒ **那支也改得掉**。
#     🔴 真正的鎖在【閘外】:codex 2026-09-05 逐字 ——
#        「最小閘外機制是 GitHub server-side protected branch / ruleset:
#          必須經 code-owner PR 核准、作者不可自行 bypass;
#          **只放一份 repo 內 checksum 或 CI 腳本,仍可在同一顆 commit 裡一起改掉。**」
#     ⇒ 那一格**本次沒做**(`-f8` 裁「不擴」),仍在板列 ⟦b9-GATESELFEDIT⟧ 上。
#   · 它只看**總數**,不看**是哪一格** ⇒ 砍掉一格再加一格無關的,總數不變 ⇒ 它不會叫。
#
# ── 🔵 怎麼更新 ──────────────────────────────────────────────
#   新增格子之後:**在下面那一行手改成新的數**(集合變大本來就不紅;
#   更新它只是讓下一次的「不准變短」以新的為準)。
#   🔴 **而把它【改小】要在 commit body 寫一句為什麼** —— 那正是本檔存在的理由。
